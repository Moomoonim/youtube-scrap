## 스크립트

안녕하세요, 저는 Pine Cone의 Zach입니다. 이번 영상에서는 Palumi를 사용하여 새로 배포한 AWS 레퍼런스 아키텍처에 점프 호스트를 배포하는 방법을 살펴보겠습니다. 이전 소개 영상에서 언급했듯이, 점프 호스트의 목적은 사용자 정의 DPC의 프라이빗 서브넷에서 실행되는 RDS PostgreSQL 데이터베이스를 포함한 리소스와 상호 작용할 수 있도록 하는 것입니다. 따라서 먼저 퍼블릭 서브넷에서 실행되는 새로운 EC2 인스턴스를 프로비저닝하고, 해당 인스턴스에 SSH로 접속하여 보안 그룹 규칙을 통해 PostgreSQL 데이터베이스에 대한 접근 권한을 부여할 것입니다. 이렇게 하면 점프 호스트에 SSH로 접속할 수 있고, 점프 호스트에서 PostgreSQL 클라이언트를 설치하여 psql 명령줄 인터페이스를 사용할 수 있게 됩니다. 그리고 PostgreSQL 데이터베이스에 직접 접근할 수 있게 됩니다. 이제 개발자 컴퓨터에서 점프 호스트를 통해 PostgreSQL 데이터베이스에 임의의 SQL 쿼리를 실행하고, 카운트를 확인하고, 데이터베이스에 대한 정보를 조회하고, 필요에 따라 SQL 쿼리를 수정할 수 있습니다. 이는 데이터베이스의 특정 부분을 변경하는 등의 작업을 수행하는 데 매우 유용합니다. 데이터베이스 구조를 조사하고 살펴보는 것, 또는 아마도 별도의 비디오에서 보여드릴 것처럼 추가 테스트 레코드를 로드하여 시스템에 상당한 부하를 발생시키는 방법을 살펴보겠습니다. 시작하기 전에, AWS 참조 아키텍처 저장소(Palumi 사용)의 문서 섹션에 있는 목차에서 링크를 클릭하면 일반적인 작업 링크가 있습니다. 첫 번째 일반적인 작업 중 하나는 점프 포스트 사용에 대한 내용입니다. 여기에는 자세한 지침이 포함되어 있으며, 우리가 무엇을 할 것인지 정확하게 설명하는 흐름도가 있습니다. 방금 설명한 것처럼 개발자의 집 컴퓨터에서 점프 포스트를 통해 RDS PostgreSQL 프라이빗 인스턴스로 이동하고, 임의의 SQL 쿼리를 실행할 수 있는 방법을 알아보겠습니다. 이 비디오에서 함께 이 과정을 완료할 것이지만, 언제든지 여기에서 일반적인 작업 가이드의 지침을 따를 수 있다는 점도 알아두시기 바랍니다. 그럼 시작으로 AWS 계정에 로그인해 보겠습니다. 이전 비디오에서 참조 아키텍처를 완전히 배포했습니다. 이제 먼저 EC2 대시보드에서 새 인스턴스를 생성해야 합니다. 인스턴스 인터페이스로 이동하여 인스턴스 이름을 지정하세요. 저는 점프 호스트 또는 배스천 호스트라고 이름을 지정하여 나중에 삭제할 때 어떤 역할을 하는지 쉽게 알 수 있도록 합니다. 기본값인 Amazon Linux AMI를 그대로 사용해도 됩니다. T2 마이크로 인스턴스도 무료 티어에 해당하므로 괜찮습니다. 키 페어 로그인은 필수입니다. 기존 키 페어를 선택하거나 새 키 페어를 생성해야 합니다. 이 과정을 통해 시스템에 SSH 키 페어가 설정됩니다. 브라우저 인터페이스를 통해 개인 키를 강제로 다운로드하고, 인스턴스 자체에도 인증된 SSH 키를 설정하여 해당 개인 키를 사용하여 인스턴스에 인증할 수 있게 됩니다. 만약 기존에 다운로드하고 올바르게 설정한 키 페어가 없다면 새 키 페어를 생성하세요. 저는 이미 키 페어를 가지고 있습니다. 키 페어를 선택하지 않으면 인스턴스에 SSH로 접속할 수 없습니다. 그리고 가장 중요한 것은 키 페어를 생성하는 것입니다. 설정 관점에서 보면 여기에는 몇 가지 설정이 있습니다. 하나는 공용 IP 자동 할당인데, 이는 인스턴스가 시작될 때 트래픽을 수신할 수 있는 공용 IPv4 주소가 할당될지 여부를 지정합니다. 우리가 직접 SSH로 접속할 수 있도록 이 설정이 활성화되어 있는지 확인하십시오. 또 다른 중요한 고려 사항은 참조 아키텍처에 배포된 다양한 서브넷입니다. 사용자 지정 VPC에는 공용 서브넷과 개인 서브넷이 모두 의도적으로 포함되어 있으므로 어느 서브넷을 선택하든 상관없지만, 인스턴스는 반드시 공용 서브넷에 시작해야 합니다. 개인 서브넷 에 인스턴스를 시작하면 SSH 연결 시도가 아무런 메시지 없이 계속 대기하게 됩니다. 따라서 여기에서 다시 한번 두 가지를 변경해야 합니다. 첫째, 공용 IPv4 주소 자동 할당을 활성화하고, 둘째, 인스턴스가 공용 서브넷 중 하나에 시작되도록 해야 합니다. 나머지는 시작 마법사 2를 그대로 사용해도 됩니다. 이제 이 인스턴스를 위한 새로운 보안 그룹을 생성할 수 있습니다. 프로비저닝이 완료되었으니 이제 RDS 보안 그룹을 수정하여 이 보안 그룹에서 오는 트래픽도 허용하도록 하겠습니다. 나머지는 괜찮아 보이지만, 포트 22에 대한 SSH 인바운드 보안 그룹 규칙을 추가해야 합니다. 모든 곳 에서 허용하는 대신(즉, 공용 인터넷 전체에서 허용하는 대신) 제 IP 주소로 설정하면 인터페이스가 자동으로 제 IP 주소를 감지하여 사용하게 됩니다. 이렇게 하면 저만 이 인스턴스에 접근할 수 있고, 공용 인터넷에 노출되어 공격받을 위험을 방지할 수 있습니다. 새 인스턴스 프로비저닝은 매우 빠르므로 오래 기다릴 필요는 없습니다. 하지만 인스턴스에 연결하기 전에 인스턴스가 완전히 실행 중이어야 합니다. 현재 인스턴스는 대기 상태이며, 공용 IPv4 주소도 여기에 표시됩니다. 이 주소를 복사해서 붙여넣을 수 있습니다. 그리고 또 하나 알아둘 점은 개인 키를 다운로드했다면(저는 아직 SSH 폴더로 옮기지 않았습니다) 여기에 있다는 것입니다. 이미 제 사용자만 읽을 수 있도록 권한을 설정해 두었습니다. 키 권한이 너무 개방적이면 오류가 발생하는데, 그럴 때는 ` chod` 명령어를 사용하고 실제 파일 경로를 지정하면 됩니다. 하지만 이미 설정을 마쳤기 때문에 실제 SSH 명령어는 ` s-i`입니다. 여기서 ID 파일과 해당 ID 파일의 경로를 지정하면 됩니다. 이 경우에는 개인 키 파일이고, Amazon 머신 이미지( EC2)를 사용했으므로 해당 머신의 사용자 이름과 IP 주소를 입력하면 됩니다. 이제 다시 확인해 보면, 새로 고침을 통해 인스턴스가 사용 가능한지 알 수 있습니다. 현재 실행 중입니다. 이제 SSH를 통해 연결을 시도하고 새 지문을 수락하면 점프 호스트에 로그인됩니다. 점프 호스트는 공용 서브넷에서 실행 중이지만, RDS가 자체 프라이빗 보안 그룹에서 실행되고 있기 때문에 점프 호스트는 아직 RDS에 접근할 수 없습니다. 이를 해결하려면 여기에 있는 특정 보안 그룹 이름을 기록하거나 복사해 두세요. 이제 인스턴스를 클릭해 보겠습니다. 보안 그룹에서 보안을 설정하려면 Launch Wizard 2를 사용해야 합니다. 이 점을 기억해 두세요. 이제 보안 그룹으로 이동하면 참조 아키텍처에서 프로비저닝한 RDS 보안 그룹을 찾을 수 있습니다. 기본적으로 Palumi 코드에 명시된 대로 RDS에 액세스할 수 있는 보안 그룹은 두 개뿐입니다. 첫 번째는 Pelican입니다. Pelican은 Postgress에서 직접 읽고 변경 레코드를 수신해야 하기 때문입니다. 두 번째는 프런트엔드 UI입니다. UI는 데이터베이스에 SQL 쿼리를 실행하고 테이블 뷰에 사용하기 때문입니다. 이제 여기에서 인바운드 규칙을 편집하고 규칙을 추가합니다. 이것은 표준 Postgress TCP 규칙이며 기본적으로 포트 543-2를 사용합니다. 이는 참조 아키텍처에서도 사용하도록 구성된 포트입니다. 이제 어떤 그룹에서 규칙을 추가할지 묻습니다. 방금 살펴본 Launch Wizard 2 그룹을 선택합니다. Jump Post가 실행되는 그룹이기 때문입니다. 이 규칙을 저장하면 EC2 Jump Post가 RDS Postgress 인스턴스까지 네트워크 연결을 확보합니다. 하지만 실제로 RDS Postgress 인스턴스에 연결하기 전에 몇 가지 추가 작업이 필요합니다. 이 머신에서 해야 할 정리 작업이 하나 있는데, 먼저 다양한 패키지를 검색하는 것입니다. 이 비디오를 시청하는 시점에 따라 업데이트나 변경 사항이 있을 수 있습니다. 저는 PostgreSQL 15를 사용하고 있습니다. 이렇게 하는 이유는 psql 클라이언트를 설치하기 위해서입니다. 이제 이 점프 호스트에서 CLI가 설치되었으므로 psql 명령을 실행하여 RDS 데이터베이스에 직접 연결할 수 있습니다. 이를 위해 RDS에 접속하여 참조 아키텍처를 통해 프로비저닝된 인스턴스를 찾습니다. 연결 및 보안 패널에서 호스트 이름을 가져옵니다. 여기 있는 엔드포인트에 데이터베이스 이름과 rs가 있습니다. Amazon aws.com C를 복사 하고 명령어는 psql입니다. 호스트 이름은 여기에 붙여넣으세요. RDS 호스트 이름을 입력하고 연결할 사용자는 postgress입니다. 이제 RDS 클라이언트, 즉 RDS 인스턴스 자체에서 암호를 묻는 메시지가 나타납니다. 좋습니다. 여기에 공유 암호가 있습니다. 이 암호를 터미널에 입력하면 됩니다. 이제 postgress 인스턴스에 직접 연결되었으므로 임의의 SQL 쿼리를 실행할 수 있습니다. 예를 들어 기본 데이터베이스의 레코드 수를 계산하거나, 기타 작업을 수행할 수 있습니다. 이제 postgress를 수정하거나 조사하고 스키마를 변경하는 데 필요한 모든 것을 갖추었습니다. 예를 들어 ` describe table on products with increment` 명령을 실행하면 구성된 트리거와 스키마를 확인할 수 있습니다. products 테이블 에서 삭제, 삽입 또는 업데이트가 발생할 때마다 여기에 구성된 `notifi change` 함수가 실행됩니다. 이것이 점프 호스트를 통해 RDS postgress 데이터베이스에 직접 연결하는 방법입니다.
