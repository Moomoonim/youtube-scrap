## 스크립트

저는 예전에 실시간 알림 서비스를 담당하는 엔지니어 팀을 이끌었던 적이 있습니다. 5명의 개발자가 3주 동안 750 줄의 인프라스트럭처 코드를 작성해서야 알림 서비스를 가동할 수 있었는데, 결국 제가 한 일은 메시지를 보내는 것뿐이었죠. 안녕하세요, 저는 AWS 서버리스 영웅 앨런 헬튼입니다. 이 영상에서는 푸시 알림을 쉽게 구축하는 방법을 보여드리겠습니다. EventBridge API 대상과 Momento 토픽을 사용하는 방법, StepFunctions를 사용하여 워크플로를 오케스트레이션하는 방법을 단계별로 설명해 드리고, 다람쥐 잡기 게임을 통해 이 모든 것을 보여드리겠습니다. 자, 시작해 볼까요? 먼저 게임을 살펴보죠. 화면에 작은 다람쥐가 뛰어다니고 있고, 오른쪽에는 레벨 1의 털복숭이 곰이 있습니다. 이제 다람쥐를 클릭해서 움직이는 모습을 지켜볼 겁니다. 계속 클릭해 보면 " 꽤 간단한 데모네"라고 생각하실 수도 있겠네요. 맞아요, 아름다움과 단순함이 있죠. 제가 몇 번 클릭했더니 레벨이 1에서 2로, 그리고 방금 2에서 3으로 바뀌는 걸 보셨을 거예요. 이건 백그라운드에서 뭔가 작업이 진행되고 있다는 뜻이에요. 스크롤이 움직이는 동안 특별히 기다린 게 아니라, 계속 클릭하니까 레벨이 올라가는 게 자연스럽게 일어난 거죠. 그럼 이런 현상이 어떻게 구현되는지 알아내려면 아키텍처 다이어그램을 살펴봐야 해요. 이 아키텍처 다이어그램은 여러 단계로 구성되어 있어요. 앞서 말했듯이 아름다움과 단순함이 핵심이지만, 모든 게 단순하다는 건 아니에요. 사용자 경험은 단순하지만, 백그라운드에서는 많은 작업이 진행되고 있죠. 방금 보신 게임은 Lambda 에서 렌더링되어 브라우저로 전송되는 간단한 웹 폼이었어요. Lambda는 중요한 정보를 담은 HTML을 생성해서 브라우저로 보내고, 브라우저는 HTML을 렌더링하면서 사용자 정보를 로드해서 레벨을 보여주는 거죠. 그리고 인터랙티브 기능을 구현하기 위해 구독도 처리하고요. 자, 이제 게임 내부를 살펴볼까요? 게임 화면을 조금 확대해 보니 두 가지가 보였습니다. 하나는 화면에서 움직이는 다람쥐였고, 다른 하나는 제 사용자 이름과 레벨이 바뀌는 것이었습니다. 어떻게 된 걸까요? 저는 그저 다람쥐를 클릭했을 뿐인데 다른 것들이 바뀌고 있었습니다. 그 이유는 바로 게임 내에서 실시간 알림을 받기 위해 모멘토 토픽을 구독하고 있었기 때문입니다. 서버 측에서는 다람쥐가 이동하면 새로운 위치 정보를 브라우저로 전송해야 합니다. 즉, 모멘토 토픽을 통해 " 다람쥐의 새로운 위치입니다. 화면에 표시해 주세요."라고 알리는 것입니다. 사용자 레벨에 대해서도 마찬가지로, 특정 사용자에 대한 업데이트가 있을 때마다 알림을 받도록 구독합니다. 다람쥐를 클릭해도 아무런 반응이 없는 것처럼 보였던 것도 의도된 설계입니다. 비동기 워크플로가 실행되고, 그 안에서 API 게이트웨이에 연결하여 특정 단계를 비동기적으로 실행하는 것입니다. Step Functions 워크플로는 API Gateway에서 Step Functions로 직접 연결되어 비동기 적으로 작업을 시작합니다. 즉, 프로세스를 기다리지 않고 바로 작업을 시작할 수 있습니다. Step Functions 내부에서 마법 같은 일이 벌어지는데, EventBridge API 대상을 사용하여 Momento 토픽과 네이티브로 통신합니다. Momento는 브라우저와의 통신을 처리하는 타사 서비스입니다. 먼저 Momento 캐시를 확인하여 플레이어 데이터가 이미 있는지, 그리고 플레이어가 다람쥐의 활성 위치를 클릭하려고 하는지 확인합니다. 이 부분에서는 EventBridge API 대상을 사용하는 대신 Step Functions 자체의 기능을 사용하여 HTTP API와 직접 통신합니다. 이번에는 Momento 캐시를 동기적으로 호출하여 최신 데이터가 있는지 확인합니다. 최신 데이터가 있으면 해당 위치로 이동하여 약간의 처리를 수행합니다. 이것은 Step Functions 워크플로 스튜디오 자체에서 렌더링한 결과이며, 여기에서 확인할 수 있습니다. 제가 그린 건 아니지만, 이렇게 멋진 다이어그램을 그릴 수 있었으면 좋았을 텐데요. 어, 이건 AWS 콘솔에서 바로 제공하는 기능입니다. 여기서 우리는 올바른 스쿼럴을 클릭했는지 확인하고, 맞다면 분기 로직을 ​​통해 해당 사용자에게 경험치를 부여합니다. 경험치를 부여하면 DynamoDB에 저장합니다. Vage API 대상을 사용하면 정말 멋진 기능을 활용할 수 있습니다. 캐시에 항상 최신 정보가 유지되도록 캐시를 무효화하는 동시에, 추가 작업을 최소화하는 것이 목표입니다. 이를 위해 EventBridge 파이프 에서 DynamoDB 스트림을 사용하여 DynamoDB의 변경 사항을 캐시에 직접 푸시합니다. 다이어그램에서 볼 수 있듯이 DynamoDB에서 스트림, 파이프를 거쳐 EventBridge로 바로 전달됩니다. 이렇게 하면 데이터가 변환되어 캐시에 저장됩니다. DynamoDB에서 데이터를 가져와 캐시에 저장하면 사용자가 이제 경험치 10점을 획득하고 레벨 4가 되었다고 알 수 있습니다. 이렇게 하면 다른 스크롤을 클릭할 때 캐시에 해당 정보가 이미 저장되어 있어 바로 사용할 수 있습니다. 코드는 전혀 필요하지 않습니다. 이 모든 것은 비동기 이벤트로 처리되므로 지연 없이 게임을 플레이할 수 있습니다. 이것이 EventBridge API 대상을 사용하는 한 가지 방법입니다. 비동기 스트림에서 파이프를 통해 데이터를 가져오는 것이죠. EventBridge API 대상을 사용하는 또 다른 방법은 다람쥐의 새로운 위치를 설정하는 것입니다. 다람쥐를 클릭한 후 화면의 원하는 위치로 이동시켜야 합니다. 원하는 위치에 다람쥐를 무작위로 배치하고 EventBridge API 대상을 사용하여 간단히 이벤트 호출을 하면 됩니다. EventBridge는 규칙을 통해 Momento 토픽에 직접 연결하고, API 대상은 해당 규칙의 대상이 되어 HTTP API 및 서비스와 직접 통신할 수 있습니다. 따라서 코드는 전혀 필요하지 않습니다. 이것 또한 EventBridge API 대상을 활용하는 방법입니다. 한 번 설정하면 EventBridge에 타사 서비스 와 연결하고 통신하는 방법을 알려줍니다. 그 후에는 화면에 이벤트를 추가하는 것만 남습니다. 워크플로에서는 PUT 이벤트를 기본적으로 호출하기만 하면 됩니다. 그러면 다람쥐의 새로운 위치나 레벨업한 경우 새로운 레벨이 백엔드에서 브라우저로 직접 전송됩니다. 따라서 어떤 연결이 어떤 사용자에게 속하는지 파악하는 등의 연결 관리에 대해 걱정할 필요가 없습니다. 모든 것이 PUT 이벤트와 EventBridge의 기본 기능을 통해 처리됩니다. 정말 멋지죠? 이제 AWS 콘솔로 넘어가서 실제로 어떻게 보이는지 살펴보겠습니다. 모두 다이어그램 보는 것을 좋아 하지만, 실제 모습을 보는 것을 더 좋아할 거라고 생각합니다. 여기가 AWS 내의 StepFunctions 콘솔입니다. 여기서는 다람쥐를 클릭할 때마다 새로운 실행이 이루어지는 것을 볼 수 있습니다. 가장 최근 항목을 클릭해 보겠습니다. Step Functions의 장점은 특정 실행 과정에서 수행된 모든 단계를 보여준다는 것입니다. 이 특정 실행에서는 제가 활성 다람쥐를 클릭하지 않았다는 의미입니다. 즉, 다른 사람이 이미 그 자리에 있었 거나, 화면 표시가 지연되어 다람쥐가 이미 움직였을 수도 있습니다. 따라서 아무런 작업도 수행되지 않았을 수 있습니다. 저는 한 사람 또는 특정 점수 위치에만 점수와 크레딧을 주고 싶기 때문입니다. 이제 제대로 작동한 실행을 살펴보겠습니다. Step Functions 내부에서 무슨 일이 일어났는지 어떻게 알 수 있을까요? 초록색 부분을 따라가면 됩니다. 위쪽에는 캐시에서 데이터를 가져오기 위해 Momento에 동기적으로 연결하는 부분이 있습니다. 아래쪽에는 항목 유효성 검사를 통과했다는 내용이 있는데, 이는 활성 다람쥐가 맞다는 것을 의미합니다. 아래쪽에는 캐시에서 정보를 불러오는 부분이 있습니다. DynamoDB에서 데이터를 가져와 사용자의 XP를 업데이트합니다. 이 작업은 새로운 XP를 기록하는 것입니다. 이 코드는 Dynamo DB 내부에 새로운 레벨을 기록하고, Dynamo DB 스트림을 트리거하여 HPE를 실행합니다. 그러면 코드를 작성하지 않고도 캐시가 자동으로 업데이트됩니다. 레벨업이 완료되었는지 확인하고, 완료되면 이벤트 브리지의 ` put events` 호출을 한 번 더 수행합니다. 이 호출은 이벤트 브리지 규칙을 트리거하고, 해당 규칙은 API 대상을 호출하여 브라우저로 알림을 푸시합니다. 이 모든 과정이 코드 작성이나 연결 관리 없이 이루어집니다. 이것이 바로 실시간 푸시 알림의 전부입니다. Momento 토픽과 같은 서비스를 Event Bridge라는 강력한 서비스에 연결할 때, 이벤트 브리지를 사용하면 단 하나의 이벤트만으로 수백, 수천 개의 활성 연결을 동시에 관리할 수 있습니다. 단 네 줄 의 설정만으로 가능합니다. 이 모든 것을 단 200줄의 코드로 구현했습니다. 5명의 개발자가 3주 동안 작업한 것과 같은 결과물을 얻었습니다. 코드를 확인하고 싶다면 링크를 참조하세요. 실시간 알림에 대해 더 자세히 알고 싶으시다면 제 웹사이트에서 관련 내용을 많이 다루고 있으니 참고해 주세요. 웹사이트 설명란에 링크를 통해 더 많은 자료를 찾으실 수 있습니다. 이 영상이 도움이 되셨다면 좋아요를 누르고 AWS Developers YouTube 채널을 구독해 주세요. 시청해 주셔서 감사합니다!
