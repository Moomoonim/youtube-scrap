## 스크립트

스택형 PRS를 사용하는 경우 GitHub CLI 용 확장 프로그램을 확인해야 합니다 . 제가 방금 어떻게 사용했는지 보여드리겠습니다. 방금 일을 좀 마무리했어요. 원래는 스택에 세 개의 레이어가 있었는데 , 나중에 보니 그중 하나의 레이어가 단독으로는 의미가 없다는 것을 알게 되었습니다. 그리고 이것이 바로 스택형 PRS를 다룰 때 핵심입니다. 변경 사항이 해당 레이어의 컨텍스트 내에서 의미 있는 레이어에 존재하도록 해야 합니다. 자, 이제 GH 스택 수정 명령어를 사용해서 변경 사항들을 다른 레이어로 통합하고 이름을 바꾸는 작업을 할 거예요. 그런 다음 GH 스택 제출 명령어를 사용해서 모든 변경 사항을 GitHub 풀 리퀘스트에 추가하고 , 마지막으로 하나씩 병합해 나갈 겁니다. GitHub 스택 뷰에 입력하겠습니다. 여기서 우리는 스택에 있는 모든 레이어를 살펴볼 수 있습니다. F 키를 누르면 파일들이 보이는 거죠 ? C 버전을 달성했습니다. 커밋 내역을 확인하실 수 있습니다. 이 스택에서는 제 Learn to Cloud 웹사이트를 위한 커뮤니티 페이지를 만들었습니다. 사용자 인터페이스와 여기에 표시되는 지표를 변경했고, 커리큘럼도 일부 업데이트했습니다. 하지만 검토 관점에서 몇 가지 수정하고 싶은 부분이 있습니다. 지금 GH 스택 수정이라고 입력할게요. 제일 먼저 하고 싶은 건 접는 거예요. 그래서 저는 이 데이터 모델 계층을 페이지 계층에 통합하고 싶습니다. 그래서 제가 꼭 그 일정에 참여하도록 하겠습니다. 위아래 화살표를 사용하시면 됩니다. 그다음에 U 키를 누르겠습니다. 그리고 지금 우리는 '한 번 접는 중'이라고 표시되는 것을 봅니다. 이것은 접을 수 있습니다. 그래서 제가 여기서 했던 모든 작업은 여기서 마무리될 겁니다. 또한, 이 레이어의 이름을 바꾸고 싶습니다. 페이지 UI 업데이트 내용을 입력하겠습니다. 환상적이에요. 이제 이 모든 변경 사항을 저장하려면 Ctrl+S를 누르기만 하면 됩니다. 이제 GH 스택 뷰를 살펴보겠습니다. 그리고 우리는 그러한 수정 사항들이 적용된 것을 확인할 수 있습니다 . 이 내용을 제출하려면 GH 스택 제출을 입력하겠습니다. 그리고 저는 자동 열기 기능을 사용하겠습니다. 그러면 PR이 생성되고 초안 상태가 아닌 열린 상태로 설정됩니다. 그럼 엔터 키를 누르겠습니다. 엄청난. 그래서 우리는 모든 것이 그곳에서 창조되었다는 것을 알 수 있습니다. github.com으로 가서 복습해 봅시다. 제 풀 리퀘스트 탭에 두 개의 PR이 모두 보이고 스택 아이콘도 표시되어 있습니다. 저는 684를 클릭하겠습니다. 원하시면 여기 있는 스택 맵 아이콘을 클릭하여 레이어 사이를 이동할 수 있습니다. 하지만 여기 아래쪽을 한번 살펴보겠습니다. main을 대상으로 하는 작업이 있을 때마다 실행되는 CI가 현재 실행 중입니다. 잠시만 기다려 주시면 완료하겠습니다. 엄청난. 모든 검사가 통과되었습니다. 스크롤을 아래로 내리면 스택에 있는 두 레이어를 모두 볼 수 있습니다. 물론 아래부터 차근차근 하나씩 해나갈 거예요. 그럼 이 부분을 병합해 보겠습니다. 그리고 이제 자동으로 다음 레이어가 메인을 대상으로 지정하게 될 것입니다. 그럼 다시 타겟팅을 하겠다는 거죠? 자, 그럼 이제 여기를 클릭해 보겠습니다. 이제 메인 브랜치를 대상으로 리타겟팅되므로 모든 CI 검사도 여기서 실행되어야 합니다 . 그러니 이 작업들이 완료될 때 까지 기다려야 병합할 수 있겠네요. 훌륭합니다. 이 레이어에 대한 모든 검사 도 통과했습니다. 제가 바로 압축하고 병합할 수 있습니다. 자, 이렇게 됐네요 . 제가 작업한 모든 내용이 메인 코드에 병합되었습니다. 그러므로 GitHub CLI에서 스택 PR용 확장 프로그램을 사용하고 있는지 확인하십시오 . 그리고 병합 방식이나 누적된 PR에 적용할 수 있는 수정 사항에 있어서 매우 다양한 유연성이 있다는 점을 기억하세요. 활용할 수 있는 요원 기술이 있고, 그 외에도 할 일이 많습니다 . 바로 시작하실 수 있도록 관련 문서 링크를 어딘가에 남겨두겠습니다.
