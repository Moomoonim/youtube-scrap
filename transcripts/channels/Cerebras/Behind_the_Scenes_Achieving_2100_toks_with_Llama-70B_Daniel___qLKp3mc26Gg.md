## 스크립트

[음악] 안녕하세요, 제 이름은 다니엘입니다. 저는 세레브러스에서 Bulba 관계 담당 책임자로 일하고 있습니다. 제 업무는 기본적으로 이와 같은 멋진 이벤트를 기획하고 개발자들에게 세레브러스가 얼마나 훌륭한 플랫폼이고, 그 기반이 되는 기술이 얼마나 뛰어난지 알리는 것입니다. 애플리케이션이나 스타트업에 초고속 추론이 필요하다면 발표 후에 저에게 말씀해 주세요. 저희가 어떻게 도움을 드릴 수 있는지, 그리고 차세대 AI 애플리케이션을 어떻게 지원할 수 있는지 논의하고 싶습니다. 오늘은 세레브러스 기술로 어떻게 이러한 놀라운 속도를 달성하는지에 대해 이야기하고 싶습니다. 얼마나 빠른지 보여드리기 위해 현재 오픈 소스 Llama 모델을 제공하는 모든 제공업체의 그래프를 보여드리겠습니다. 저희는 NVIDIA GPU에서 실행되는 가장 빠른 추론 제공업체보다 15.5배 빠릅니다. 저희 속도가 얼마나 빠른지 감을 잡으실 수 있을 겁니다. 발표에서는 이러한 놀라운 속도를 달성하기 위해 하드웨어와 소프트웨어 측면에서 적용하는 몇 가지 최적화 기술을 자세히 설명드리겠습니다. 그전에 간단히 몇 가지 이야기를 나누겠습니다. LLM이 무엇이고 어떻게 작동하는지, 그리고 GPU가 직면한 속도상의 근본적인 한계를 이해하기 위해 기본적인 내용부터 살펴보겠습니다. 먼저 LLM이란 무엇일까요? LLM은 Large Language Model의 약자로, 인간의 언어를 이해하고 생성하는 매우 복잡한 소프트웨어라고 생각하면 됩니다. 여러분이 사용하는 모든 AI 앱, 예를 들어 Chat, GBT 등은 모두 LLM을 기반으로 작동합니다. LLM의 내부 구조를 살펴보면, 각 레이어는 수학적 계산을 수행하여 입력을 출력으로 변환하는 여러 레이어로 구성되어 있습니다. LLM의 각 레이어는 일련의 매개 변수(가중치라고도 함)를 통해 입력 데이터를 처리합니다. 이 매개변수는 학습 과정에서 계산되며, 각 단계에서 모델의 입력 이해도를 향상시킵니다. 최종 레이어에서는 학습 과정에서 얻은 모든 매개변수를 기반으로 계산된 확률 분포를 바탕으로 가장 가능성이 높은 출력 단어를 선택합니다. 그렇다면 Chat에 질문을 하고 출력을 생성하는 과정은 어떻게 이루어질까요? LLM은 한 번에 한 단어 또는 한 토큰씩 텍스트를 생성합니다. 첫 번째 토큰을 생성하기 위해 모델은 모든 레이어를 통해 입력을 처리하고 각 레이어와 관련된 복잡한 수학 연산을 순차적으로 수행하여 첫 번째 단어를 생성합니다. 그런 다음 마지막으로 생성된 단어를 맨 위에 삽입하고 이 과정을 반복합니다. 여기서 중요한 점은 토큰 생성 과정을 중단할 수 없다는 것입니다. 다음 토큰을 계산하려면 이전 토큰이 필요하며, 이것이 LLM 의 근본적인 한계 중 하나입니다. LLM의 각 레이어에서는 칩 내의 여러 컴퓨팅 코어가 함께 작동하여 입력에 대한 수학 연산을 수행합니다. 각 코어는 다음 레이어의 출력을 생성하기 위해 메모리에 저장된 가중치에 접근해야 합니다. 따라서 모든 가중치에 접근하는 메모리 속도는 모델의 텍스트 생성 속도에 직접적인 영향을 미칩니다. Chach PT가 로딩되면서 한 번에 한 단어씩 생성하는 데 시간이 오래 걸리는 것을 보면 이러한 현상을 이해할 수 있습니다. 다음으로 자주 받는 질문은 첫 번째 토큰을 생성하는 데 왜 항상 다른 토큰보다 시간이 훨씬 오래 걸리는가 하는 것입니다. 이는 첫 번째 레이어가 처리된 후 모델이 모든 데이터를 버리지 않기 때문입니다. 계산 과정에서 얻은 모든 중간 출력값을 캐시에 저장합니다. 즉, 모델은 다음 토큰을 생성할 때 이전 토큰의 중간 계산값을 재사용하고 이를 기반으로 계산을 진행할 수 있어 계산 부하를 줄일 수 있습니다. 이러한 캐싱 전략은 방대한 양의 텍스트를 생성할 때 매우 중요합니다. 모델이 동일한 계산을 반복적으로 수행하는 것을 방지하고, 가능한 한 많은 부분을 재사용하여 백그라운드에서 이루어지는 모든 계산 속도를 높일 수 있기 때문입니다. 이전 토큰의 캐시된 계산값을 재사용하고 새로운 정보만 계산함으로써, 첫 번째 토큰 이후의 토큰 생성 속도가 매우 빨라집니다. 많은 컨텍스트 정보가 재사용되어 다음 토큰을 생성하는 데 도움이 되기 때문입니다. 따라서 텍스트 생성량이 증가하고 모델의 크기가 커질수록 메모리 제약에 부딪히게 됩니다. 모델은 방대한 양의 데이터를 저장하고 읽어야 하기 때문입니다. 원시 데이터 처리와 캐시 연산을 모두 처리해야 하므로 사용 가능한 메모리가 빠르게 가득 찰 수 있습니다. 이는 모델이 때때로 매우 느린 이유에 대해 이야기할 때 다루는 문제와 유사합니다. 그렇다면 세레브라가 왜 그렇게 빠른 걸까요? 첫 번째 비결은 세레브라 칩에 메모리 대역폭 문제가 없다는 것입니다. 처음부터 AI에서 발생하는 매우 메모리 집약적인 워크로드를 실행하도록 칩을 설계했기 때문입니다. 이것은 저희 칩 사진입니다. 행사가 끝나면 사진 작가가 행사장을 돌아다니며 실제 칩을 보여줄 예정이니 그때 크기를 직접 확인하실 수 있습니다. 이 사진은 저희 칩의 아름다운 모습입니다. 4조 개의 트랜지스터, 90만 개의 코어, 그리고 44GB의 온칩 메모리를 갖추고 있습니다. 이를 엔비디아 H100S와 비교해 보면 크기 차이가 확연히 드러납니다. H100S 와 세레브라의 크기 차이를 보여주는 실제 비교 사진입니다. 저희 세레브러스 WC3 칩과 비교해 보시면 크기 차이를 확연히 알 수 있습니다. 왜 이 차이가 중요하고, 어떻게 빠른 모델 처리가 가능한지 간단히 설명드리겠습니다. 이 그림은 엔비디아 H100 칩의 아키텍처 다이어그램입니다. 빨간색으로 표시된 부분은 특정 코어, 즉 H100 에서 연산을 수행하는 부분입니다. H100 칩에는 약 17,000개의 코어가 있습니다. 문제는 메모리가 칩 외부에 있다는 것입니다. 즉, 177,000개의 코어 중 하나라도 모델 가중치나 계산 결과에 접근할 때마다 외부 메모리에서 해당 가중치를 가져와야 합니다. 이는 여러 단계의 스위치를 거쳐야 하고, 또 다른 경우에는 칩 외부로 나가야 한다는 것을 의미합니다. 따라서 외부 메모리와 코어를 연결하는 메모리 채널이 매우 빠르게 병목 현상을 일으킵니다. 세레브러스는 완전히 다른 칩 설계를 채택했습니다. 모든 코어가 고속 메모리에 직접 접근할 수 있도록 설계되어 있어 칩 외부에서 가중치를 반복적으로 가져올 필요가 없습니다. 결과적으로 전체 메모리 대역폭 요구 사항과 이러한 시스템을 실행하는 데 필요한 전력을 줄일 수 있습니다. 프로덕션 환경에서 머신러닝 모델의 각 레이어 가중치는 특정 코어 와 직접 연결된 메모리에 저장됩니다. 따라서 가중치는 이동하지 않고 코어가 연산을 수행할 필요한 위치에 고정됩니다. 이것이 바로 WSC 3 칩에서 모델을 실행할 때 메모리 대역폭 문제를 걱정할 필요가 없는 이유 중 하나입니다. 두 번째 비결은 서버 칩이 대형 모델에서 선형적으로 확장된다는 것입니다. 대형 자유의 여신상 라마 모델을 보세요. 정말 크죠? [ 웃음] GPU의 경우 왜 선형적으로 확장되는지 자세히 설명하기 전에, Meta에서 새로운 오픈소스 모델을 출시할 때 어떤 모습인지 보여드리겠습니다. Meta 웹사이트( hugging face)에서 Meta가 모델 학습을 완료한 후 Melan 팀이 공개하는 내용을 확인할 수 있습니다. 예를 들어, 라마 3.18 모델은 16GB 용량에 40개의 레이어로 구성되어 있습니다. Meta는 이 모델을 출시할 때 몇 가지 구성 요소를 공개하는데, 그중 하나가 원시 모델 가중치입니다. 안전한 텐서 형식을 사용하고, 전체 모델의 아키텍처를 보여주는 구성 파일도 제공하며, 마지막으로 모델이 워크로드를 처리할 수 있도록 모든 데이터를 전처리하는 방법을 알려주는 토크나이저도 제공합니다. 멜란 팀과 메타 팀이 새로운 모델을 출시하면, 세레브러스는 컴파일러를 사용하여 모든 레이어와 가중치를 CH가 모든 계산을 수행할 수 있는 명령어로 변환합니다. 하지만 GPU와는 매우 다른 방식으로 작동합니다. GPU에서는 데이터가 컴퓨터와 메모리 사이를 끊임없이 오가는 것과 달리, 세레브러스는 파이프라인 아키텍처라는 것을 구현했습니다. 이 설계에서는 데이터 FL이 칩을 통해 흐르는 동안 가중치는 고정된 상태를 유지합니다. 즉, LLM의 레이어를 칩의 물리적 코어에 직접 매핑합니다. 따라서 각 코어 그룹은 모델의 특정 레이어에 대한 계산을 담당합니다. 입력을 처리하면 데이터는 코어 파이프라인을 통해 이동하고, 각 코어는 로컬 가중치를 사용하여 할당된 레이어에 대한 계산을 수행합니다. 이 아키텍처를 통해 매우 큰 모델도 효율적으로 확장할 수 있습니다. 웨이퍼 상의 더 많은 코어에 더 많은 레이어를 직접 매핑하는 방식으로 구현했습니다. 그렇다면 추론 앱에 접속해서 50개의 썰렁한 아재 개그를 요청하면 어떻게 될까요? 실제로 어떤 일이 벌어지는지 궁금하시죠? 쿼리를 보내면 일반적인 서버, 즉 Dell 서버에 접속하여 입력값을 전처리합니다. 텍스트를 머신러닝 모델이 이해할 수 있는 토큰으로 변환하는 것이죠. 그런 다음, 칩의 각 부분에 매핑된 모든 레이어를 거치는데, 이 데이터는 캘리포니아, 댈러스 또는 다른 데이터 센터에 있는 Cerebra 시스템에 저장됩니다. 각 레이어를 거친 후 최종 출력으로 이어집니다. 다행히 16GB 용량의 Llama 3.1 AP는 하나의 시스템에 무리 없이 탑재할 수 있습니다. 따라서 Llama 3.1 AP를 서비스하는 데에는 하나의 시스템만 있으면 됩니다. 하지만 44GB 메모리만 가진 CRA 시스템에 3.1 70b와 같은 더 큰 모델을 호스팅하려면 어떻게 해야 할까요? 어떻게 해결할까요? 더 큰 모델을 수용하기 위해 우리는 다른 방식으로 처리합니다. 대규모 모델의 여러 레이어를 서로 다른 세레브러스 시스템에서 처리하여 병목 현상이 발생하지 않도록 합니다. 각 머신 에서 모든 레이어를 처리하는 데 걸리는 시간이 거의 동일하도록 하여 입력에서 출력까지 완전한 파이프라인 시스템을 구축하고, 매우 큰 머신 러닝 모델을 통해 토큰을 처리합니다. 세레브러스가 GPU보다 훨씬 빠른 속도 이점을 제공하는 이유는 모델이 커질수록 물리적인 원리가 작용하기 때문입니다. 오른쪽에 보이는 상용 솔루션인 DGX H100은 8개의 GPU를 하나로 묶어 대규모 머신 러닝 모델을 처리합니다. 하지만 활성화 값, 가중치 업데이트, 기울기 등 다양한 데이터의 빈번한 교환 으로 인해 모델 크기가 커질수록 지연 시간이 기하급수적으로 증가하는 문제가 있습니다. 세레브러스는 머신 러닝 모델의 개별 레이어를 여러 GPU에 분산 처리하기 때문에, 대규모 머신 러닝 모델을 여러 GPU에 걸쳐 확장할 때 GPU 개수가 많아질수록 문제가 더욱 심각해집니다. 반면 세레브러스 아키텍처는 성능 저하 없이 선형적으로 확장됩니다. 웨이퍼 간 활성화 값만 통신하기 때문에 문제가 발생하지 않습니다. 텐서나 중간 계산과 같은 것은 통신하지 않기 때문에 GPU가 통신해야 하는 것들에 비해 대역폭이 매우 낮습니다. 모델의 단일 레이어를 분할하지 않기 때문에 시스템 간 통신량이 훨씬 적습니다. 따라서 더 많은 모델을 단일 칩에 탑재할 수 있습니다. 칩이 매우 크고 메모리 용량이 크기 때문입니다. 이것이 바로 대규모 머신러닝 모델을 처리할 때 속도가 훨씬 빠른 이유에 대한 요약입니다. 세 번째 비결은 최근 공개된 소프트웨어 최적화 기술입니다. 하드웨어 최적화 외에도 추론 속도를 향상시키기 위해 소프트웨어 최적화를 적용했습니다. 그중 하나가 투기 적 디코딩입니다. 먼저 표준 디코딩을 살펴보겠습니다. 일반적인 머신러닝 모델을 실행하면 한 번에 한 단어씩 생성합니다. 따라서 9개의 단어를 생성하려면 모델을 9 번 거쳐야 합니다. 하지만 이 혁신적인 신기술을 사용하면 투기적 디코딩을 통해 속도를 크게 향상시킬 수 있습니다. 추측 디코딩은 두 개의 모델을 사용합니다. 하나는 일반적으로 더 빠르고 작은 모델(예: Llama 3B)이고, 다른 하나는 더 크고 정확한 모델(예: Llama 70B)입니다. 여기서 핵심은 작은 모델이 단어 시퀀스를 빠르게 생성하면, 큰 모델이 개입하여 " 이것이 맞는가?", " 정확한가?"를 확인하는 것입니다. 정확하지 않으면 작은 모델이 생성한 내용을 수정하고, 정확하면 다음 단어 세트로 넘어갑니다. 이 예시에서 Llama 3B 모델은 " The Quick Brown Fox Jumps Over the Lazy Dog"와 같은 여러 단어를 생성합니다. 세 개 정도의 단어를 생성한 후, 더 큰 Llama 70B 모델이 시퀀스의 정확성을 검증합니다. 정확하면 다음으로 넘어가고, 그렇지 않으면 필요에 따라 단어를 수정하거나 다시 생성합니다. 이 기술은 효율성을 크게 향상시킵니다. 일반적인 모델 하나를 실행하여 모든 단어에 대해 반복 처리하는 대신, 추측 디코딩을 사용하면 작은 모델의 속도를 활용 하면서 큰 모델의 정확도를 유지할 수 있습니다. Llama 70B는 모든 단어를 처리하는 대신 키 간격에서만 검증 작업을 수행하므로, 올바르게 구현될 경우 정확도나 품질에 영향을 미치지 않습니다. 이것이 가장 중요한 점입니다. 따라서 D 농담과 같은 특정 프롬프트의 경우 Llama 3B 와 70B 정렬 결과를 출력하여 초당 수백 개의 토큰을 처리하는 매우 빠른 속도를 달성할 수 있습니다. 하지만 더 복잡한 프롬프트의 경우, 더 큰 모델이 더 작은 모델의 출력을 더 자주 수정해야 하므로 평균적으로 초당 2148개의 토큰을 처리합니다. 그러나 추측 디코딩을 기반으로 프롬프트에 따라 초당 최대 20,000개의 토큰까지 훨씬 빠른 추론 속도를 달성할 수도 있습니다. 이것이 바로 Cerebrus 추론의 핵심 기술입니다. 첫째, 칩의 기본 아키텍처 덕분에 메모리 밴들릿 문제가 없습니다. 둘째, 모델 크기가 커질수록 선형적으로 확장됩니다. 셋째, 추측 디코딩과 같은 뛰어난 소프트웨어 최적화를 통해 매우 빠른 속도를 구현합니다. 이것으로 제 발표를 마치겠습니다.
