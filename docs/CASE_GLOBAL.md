   > AI로 자동화 가능한 비율을 계산하고 — **그건 어느 직군에서나 항상 평균 30%입니다** —
   > 그 30%를 손익에 떨구고, 나머지 70%로 팀을 재편하면 명확한 ROI가 나온다는 것입니다.
   > **그런 식으로 일어나고 있지 않습니다.**"
4. **★ AI의 더 큰 가치는 자동화가 아니라 'Capability Add'다.** — 지지
   > 내부감사팀 사례 — "AI 덕분에 **이제 모든 내부감사가 선제적 리스크 식별을 제공합니다.
   > 그건 인간이 하던 일이 아니었습니다.** AI가 프로세스에 주입한 새 역량입니다"
5. **Capability Add를 인정하면 ROI 측정은 더 어려워진다.** — 지지
   > "성장·혁신·고객경험·직원경험은 측정하기 더 어렵고 ROI를 계산할 단순 인과 모델을 만들기 어렵습니다.

6. **측정은 도입 → 행동 변화 → 사업 성과의 사슬로 매핑해야 한다.** — 실험 단계로 진술됨

## B. 문제 상황

  포트폴리오"
- 질문: **"처음 몇 개의 에이전트를 쓸 때 어떻게 사용량을 측정할 수 있을까? 누가 쓰고 있나?
  무엇에 쓰이고 있나?"**
- 신뢰: **"직원이 상담원에게 무슨 말을 하는지, 상담원이 뭐라고 답하는지 어떻게 알 수 있을까?"**
- 사용자 유형이 갈린다 — **경영진**(사업 가치), **PM**(무엇을 만들까), **에이전트 빌더**(진단)
- 예상 밖 수요: "영업 사원용 에이전트를 만들었더니 판매자들이 곧바로 **우리가 예상하지 못했던
  질문들**을 하기 시작했습니다 — 어떻게 하면 거래 승인을 받을 수 있나요?"

## C. 개입의 메커니즘 — 측정 4대 핵심 요소와 3계층 아키텍처

```
[측정 4대 핵심 요소]
① 참여도(Engagement) — 직원이 에이전트와 어떻게, 얼마나 깊이 상호작용하는가
   MAU · 주간 신규 사용자 확보율 · ★참여 심도율(표면에 머무는가, 심층까지 파고드는가) · 유지율
② 효능(Efficacy) — 응답 품질과 작업 성공률
   ★부정적 반응률 · ★재촉율(reprompt rate) · 간결성 점수 · 결단력 · 도움 정도 · 교육 여부
③ 성능(Performance) — 응답 속도
④ 만족도(Satisfaction) — 사용자 경험과 감정
   → "이 넷을 제대로 구현하면 자연스럽게 비즈니스 가치로 이어진다"
   → 비즈니스 가치 = 시간 절약 + 운영 효율

[★ 재촉율의 구현] 이 코퍼스에서 가장 정교한 품질 신호
   "특정 유사도 점수를 충족하는 프롬프트가 세션 내에서 연속으로 나타날 때 신호를 보내는
    모델을 구축했습니다. 그것을 상담원의 응답 품질 신호로 간주합니다.
    다시 안내를 요청한다는 것은 첫 응답이 원하던 것이 아니었을 가능성이 높기 때문입니다"

[3계층 아키텍처]
① 데이터 기반 — Agentforce의 모든 관찰 데이터, 원시 로그, 대화 녹취록
   → 처리 → 민감정보 제거 → 데이터 기반에 통합
② ★측정 인텔리전스 레이어 — "작지만 강력한 분석팀"이 LLM 기법으로 대규모 포트폴리오에 확장
   ★ LLM as judge + AI 기반 평가 도구로 에이전트를 평가
③ 경험 레이어 — Tableau 임베딩 API로 자체 웹앱에 시각화 삽입
   ★ Tableau MCP로 주간 보고서와 맞춤 시각화를 자동 생성

[AI 성과 분석 자동화]
   측정 프레임워크에 맞춰 특별히 훈련된 에이전트가 매주 모든 인증 데이터 소스를 조회·분석
   → 포트폴리오의 모든 에이전트에 대해 간결한 성과 분석 생성
   → 한 문장: 이번 주 잘한 점 / 또 한 문장: 주의가 필요하거나 악화되는 지표
   → 호버하면 지표의 출처 표시, 스크롤하면 출력 검증 가능
   ★ 즉 에이전트를 평가하는 일 자체가 에이전트에게 위임된다

[비교 장치] 산점도
   x축 = 선택 지표, y축 = 주간 변화율, 포트폴리오의 모든 에이전트를 플롯
   선택 에이전트는 굵게 → 다른 에이전트와 즉시 비교
   ★ 음영 영역이 '개선 방향'을 표시 — 참여도는 위쪽이 녹색,
     부정적 반응률 같은 효능 지표는 감소가 개선

[분해] 사용량 데이터 × 직원 인구통계(산업·직무군·조직 단위) 필터
```

**⚠️ 화자 스스로 밝히는 문제**: **"저희는 비즈니스에 있어 매우 새로운 지표들을 많이 다루고 있습니다.
이전에는 접해보지 못한 지표들이죠. 따라서 사용자에게 명확한 정의를 제공하는 것이 매우 중요합니다"**
— 대시보드에 **지표 정의를 화면에 직접 붙여 놓는다**. 새 분모는 설명 없이는 읽히지 않는다.

- 2021년 Rise 출시 → Signavio·LeanIX·WalkMe를 포트폴리오에 추가하며 **가치 창출**에 집중
- ⚠️ **"우리가 다소 간과했던 부분은 이러한 변화 각각에 수반되는 비용과 복잡성이라는 주제입니다"**
- ⚠️ **"고객들이 변화를 원할수록, 그리고 최종적으로 그 변화에서 벗어나고 싶어 할수록,
  고객 측의 초기 투자 비용은 더욱 높아진다는 점입니다"**
- 실제 공수 요인: **상태 관리, 데이터 품질, 클린 코어 변환, 테스트**

## C. 개입의 메커니즘 — 7개 마이그레이션 어시스턴트

```
[기반] 시스템 분석 어시스턴트
   데이터 · 맞춤설정 · 사용자정의 코드 3축으로 시스템을 완전 분석
   ★ "이 세 가지를 이해하는 것이 변환 프로젝트의 범위를 정하는 데 필수"

[1] 데이터 관리 어시스턴트
   ★ 로드·마이그레이션 자체가 아니다("이미 상당 부분 자동화")
   → 데이터 품질과 준비에 집중: 불일치 파악 → 근본 원인 분석 → 해결 지침 →
     ★ 시스템에서 데이터를 직접 수정하는 담당자 배치

[2] 사용자 지정 코드 어시스턴트 — 두 차원
   (a) 기존 ECC 커스텀 코드가 S/4HANA에서 실행 가능하도록(개발자용 도구)
   (b) ★클린 코어 변환 — 커스텀 코드를 **의미론적으로 이해**해
       표준 기능과 비교하고 **표준이 커스텀을 대체할 수 있는 부분을 식별**
       확장이 필요한 부분은 코어를 준수하는 방식의 기술 사양 제공
   ★ 즉 에이전트가 고객의 고유 로직을 표준으로 회수한다

[3] 구성 어시스턴트
   스코핑 항목 + SAP의 기업 지식으로 중앙 비즈니스 구성 도구와 함께
   ★ 고객 시스템을 **사전 구성** — "이제 실제 설정에 많은 시간을 쓸 필요가 없다"

[4] 테스트 관리 어시스턴트
   테스트 준비·범위 설정에 집중(테스트 데이터·케이스 생성이 큰 문제점)
   근거: 기업 전문지식 + Signavio의 고객 프로세스 + 고객 정의 요구사항·유저스토리
   Tricentis는 테스트 자동화 담당(기존 파트너십)

[5] 롤아웃 어시스턴트
   초기 구현 템플릿을 여러 국가·시장 단위·공장으로 확장할 때
   차이점 파악과 필요한 변경 사항 식별

[6~7] (스크립트 후반, 추가 정독 필요)
```

**이 메커니즘의 함의**: 마이그레이션 에이전트가 **커스텀 코드를 표준으로 되돌린다**. 고객의 고유
로직이 줄어들수록 다음 마이그레이션은 쉬워지고, 동시에 **벤더 표준에 대한 의존은 깊어진다.**
C5(거버넌스 락인)가 코드 수준에서 관찰되는 드문 사례다.
