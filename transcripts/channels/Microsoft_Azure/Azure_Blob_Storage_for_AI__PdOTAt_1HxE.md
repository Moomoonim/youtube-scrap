Azure Blob Storage를 통해 고객은 수백 페타바이트 규모의 엔터프라이즈 데이터를 저장하고 관리할 뿐만 아니라, 에이전트 기반 추론 시나리오에 필수적인 보안 및 최신성을 유지하면서 지연 시간이 짧은 검색을 구현할 수 있습니다 . 좋습니다, 그럼 AI 학습 및 미세 조정부터 시작해 보겠습니다. AI 학습 및 미세 조정 파이프라인은 Microsoft AI, OpenAI 또는 자체 학습 워크로드를 사용하든 관계없이 대략 동일한 패턴을 따릅니다. 확장성 요구 사항만 약간 다를 수 있습니다. 슬라이드에서 왼쪽에서 오른쪽으로 보시는 것처럼 , 이 과정은 원시 데이터를 Azure Blob Storage로 가져오는 것부터 시작합니다 . 이 데이터는 테라바이트 또는 수백 페타바이트에 달할 수도 있습니다. 이 데이터가 Azure에 수집되면 일반적으로 오픈 소스 Spark 또는 Databricks 엔진을 사용하여 데이터의 유효성을 검사하고, 정제하고, 주석을 추가합니다 . 훈련 데이터와 기본 모델 가중치가 준비되면 모델은 훈련 단계에 진입하는데, 이 단계는 상당한 연산 및 저장 공간을 필요로 합니다. 훈련 데이터를 로드하려면 초당 테라비트급 읽기 대역폭이 필요하고, 훈련 과정을 체크포인트 하려면 테라비트급 쓰기 대역폭이 필요합니다 . 체크포인트는 GPU 클러스터의 전체 상태를 캡처하여 영구 저장소에 저장함으로써 장애 발생 후 재시작을 가능하게 합니다 . 또한 추적성과 모델 계보를 위해 해당 데이터를 보관해야 합니다. 대규모로 운영될 경우, 체크포인트는 엑사바이트 규모의 데이터를 생성할 수 있습니다. 학습 과정이 완료되면 마지막 단계는 AI 추론이 이루어지는 환경에 모델을 배포하는 것입니다 . AI 학습을 제대로 지원하려면 스토리지 시스템은 엑사바이트 규모의 데이터를 저장할 수 있어야 하며, 대규모 분산 CPU 및 GPU 클러스터에서 활용도를 극대화하기 위해 수십 테라비트의 처리량을 제공해야 합니다. 오늘 이 영상에서 보시게 될 모든 내용은 공개적으로 이용 가능합니다. 하지만 이는 수년에 걸쳐 반복적인 개발과 대규모 운영에서 얻은 실질적인 교훈을 통해 확립된 것입니다 . 고객이 새로운 규모 및 성능 요구 사항을 충족할 수 있도록 지원하는 기능 중 하나를 살펴보겠습니다. 확장된 계정. 확장형 계정은 학습 및 추론과 같은 고강도 워크로드에 적합합니다 . 확장형 계정은 일반 스토리지 계정에 추가적인 성능과 확장성이 필요하다고 판단될 때 내부적으로 작동하는 기능입니다. 저희는 단일 클러스터가 아닌 전체 Azure 리전에 걸쳐 계정을 확장하므로 용량은 리전 자체의 규모에 의해서만 제한됩니다 . 확장 가능한 계정은 필요할 때마다 자동으로 제공되는 기능입니다. 계정 변경도 없고, API 변경도 없으며, API 사용료 추가도 없습니다. AI 워크로드에 유용한 또 다른 기능은 애플리케이션과 도구가 POSIX 기반 파일 시스템을 사용하도록 구축된 경우 BlobFuse를 활용하는 것입니다. BlobFuse를 사용하면 블롭 컨테이너를 VM의 파일 시스템에 마운트하여 교육 코드 및 기타 애플리케이션이 지능형 스트리밍 기능을 갖춘 로컬 파일 시스템처럼 블롭 스토리지에 액세스할 수 있습니다 . 가상 머신 및 로컬 NVMe 드라이브와 함께 사용하면 데이터를 미리 로드 하거나 체크포인트를 푸시하여 GPU가 필요 이상으로 오랫동안 차단되는 것을 방지할 수 있습니다. BlobFuse는 오픈 소스 소프트웨어이며, 사용하기 쉽도록 설계되었고, 유용한 기본 설정이 제공되지만, 물론 사용자의 고유한 시나리오에 맞게 수정할 수도 있습니다. 그렇다면 규모가 커진 계정을 실제로 테스트해 보면 어떤 일이 벌어질까요? 미국 지역의 표준 블롭 스토리지 계정을 사용한 간단한 데모를 보여드리겠습니다 . 저희는 10만 개의 vCPU를 갖춘 컴퓨팅 클러스터를 구축하고 BlobFuse를 사용하여 1.5페비바이트의 데이터를 확장된 계정에 기록하여 체크포인트 쓰기를 시뮬레이션했습니다. 그런 다음 별도의 10만 코어 컴퓨팅 클러스터를 구성하여 확장된 계정 에서 1.5페비바이트의 데이터 세트를 읽어 대규모 데이터 세트 또는 학습용 체크포인트 로드를 시뮬레이션했습니다. 캐싱 효과를 방지하기 위해 별도의 컴퓨팅 클러스터를 사용합니다. 보시는 바와 같이, 첫 번째 컴퓨팅 클러스터가 초당 22테라비트, 즉 거의 초당 3테라바이트의 속도로 계정에 데이터를 기록하고 있습니다. 읽기 성능의 경우, 초당 51테라비트 이상의 읽기 대역폭, 즉 초당 6테라바이트 이상의 속도를 보여줍니다 . 이 데모는 현재 가장 규모가 큰 AI 고객 및 파트너들이 사용하고 있는 Azure Blob 스토리지의 확장성과 성능을 보여줍니다. 학습에 대해 알아봤으니 이제 추론에 대해 이야기해 보겠습니다. 수조 개의 매개변수를 가진 모델을 학습시키는 단계에서 실제 운영 환경에서 실행하는 단계로 넘어가면 초점이 바뀝니다. 엑사바이트 규모의 원시 데이터나 체크포인트 데이터 대신, 테라바이트 규모의 엔터프라이즈 도메인 데이터를 다루게 됩니다. 하지만 AI 에이전트의 응답성을 유지하려면 여전히 초당 수백 기가비트의 처리량과 10 밀리초 미만의 지연 시간이 필요합니다 . Azure Blob Storage는 바로 그러한 기능을 제공합니다 . 엔터프라이즈 데이터에 대한 에이전트 기반 추론 및 논리 연산을 가능하게 하는 파이프라인의 스토리지 중심적 관점을 살펴보겠습니다 . 우리는 다양한 형태의 비정형 기업 데이터를 수집하고, 정제하고, 분할한 다음 임베딩을 생성하고, 이를 벡터 데이터베이스에 인덱싱하여 에이전트 기반 애플리케이션이 향후 검색할 수 있도록 합니다. Blob 스토리지는 Azure AI 검색 및 기타 타사 벡터 데이터베이스와 통합되어 해당 인덱스가 최신 상태로 유지됩니다. 사용자의 쿼리가 에이전트 기반 앱에 도달하면 에이전트는 벡터 유사성 검색을 실행하여 올바른 컨텍스트를 즉시 검색합니다. 여기서는 한 자릿수 밀리초의 지연 시간이 중요합니다. 여러 에이전트 루프에 걸쳐 절약되는 모든 밀리초는 에이전트 추론 속도 향상과 더 나은 엔드투엔드 사용자 경험으로 이어지기 때문입니다. 만약 기업 데이터가 이미 블롭 스토리지에 저장되어 있지 않다면, 이 파이프라인을 활성화하기 위해 다양한 유형의 기업 데이터를 Azure로 일괄 이동해야 합니다. 이제 Azure 스토리지는 Azure DataBox와 같은 오프라인 솔루션과 Azure Storage Mover와 같은 온라인 솔루션을 모두 제공하여 페타바이트 규모의 데이터를 Azure Blob 스토리지에 빠르게 수집할 수 있도록 지원합니다. Azure 스토리지 이동 서비스는 완전 관리형입니다. 에이전트도, 스크립트도 필요 없습니다. 온프레미스 환경에서 클라우드 환경으로 수십억 개의 객체를 고속 병렬 전송으로 이동시킬 수 있습니다 . 내장된 암호화 및 증분 동기화 기능을 갖춘 페타바이트 규모의 마이그레이션을 통해 다운타임 없이 AI 워크로드에 필요한 데이터를 준비할 수 있습니다. 데이터가 Azure에 저장되면 프리미엄 Blob 스토리지를 통해 성능을 한 단계 더 끌어올릴 수 있습니다. 일반 스토리지와 달리 프리미엄 스토리지는 AI 추론과 같은 고도의 상호작용 워크로드를 위해 설계된 SSD 기반 객체 스토리지입니다 . 표준 블롭 스토리지 대비 최대 40배 빠른 성능과 최대 65%의 트랜잭션 비용 절감 효과를 누릴 수 있습니다. 더욱 중요한 것은, 한 자릿수 밀리초 범위의 일관된 저지연 I/O 처리 속도입니다. 즉, 모델 로딩 속도가 빠르고, 기업의 데이터 검색이 신속하며, GPU가 대기하지 않고 계속 활용된다는 의미입니다. 기업 데이터를 이용한 추론에서 중요한 것은 저장 속도와 데이터 피드뿐만이 아닙니다. 이는 AI 서비스 및 도구와의 통합을 통해 대규모 환경에서 효과적으로 작동하는 것입니다. Blob 스토리지는 Microsoft Foundry IQ, Azure AI Search, Azure Open AI 및 Azure Machine Learning을 위한 페타바이트 규모의 데이터 및 지식 소스 역할을 합니다. 저희는 또한 많은 분들이 에이전트 기반 애플리케이션을 구축하기 위해 PyTorch 및 LangChain과 같은 타사 오픈 소스 도구 및 프레임워크를 사용하고 있다는 사실을 알고 있습니다 . Blob 스토리지는 개발자의 편의성을 위해 이러한 도구와 통합될 뿐만 아니라, 가장 많이 사용되는 통합 기능을 고처리량 파이프라인에 최적화하여 앱이 병목 현상 없이 엔터프라이즈 데이터 환경을 포괄하도록 확장할 수 있도록 지원합니다 . 이제 파이썬을 사용하여 기업용 AI를 개발하는 우리 커뮤니티에 유용한 몇 가지 기능을 자세히 살펴보겠습니다 . 파이썬을 사용하여 데이터를 개발하는 전문가들은 끊임없는 도전에 직면합니다. 규모에 관계없이 에이전트 애플리케이션 코드와 클라우드 스토리지를 연결합니다. Python의 파일 시스템 사양 표준은 범용 파일 어댑터이며, ADLFS( Azure Data Lake File System)는 Azure의 블롭 및 데이터 레이크 스토리지에 대한 고성능 게이트웨이입니다. 최신 ADLFS 개선 사항을 통해 병렬 업로드와 더욱 빠르고 안정적인 블록 수준 쓰기를 제공하여 대용량 파일의 타임아웃 시간을 줄입니다. ADLFS에서 Azure 스토리지의 속도와 안정성을 향상시킴으로써 PyTorch, Pandas, Ray 등 FS 사양을 사용하는 모든 도구가 Azure에서 크게 성능 향상을 경험할 수 있습니다. 가장 좋은 점은 별도의 사용자 정의 통합이 필요 없다는 것입니다. 로컬 파일이나 다른 클라우드 파일에서 Azure로 전환하는 것은 이 슬라이드의 예시에서 볼 수 있듯이 파일 경로를 지정하는 것만큼 간단한 경우가 많습니다. 에이전트 오케스트레이션 프레임워크로 한 단계 더 나아가 , LangChain 에서 Azure Blob Storage 로더를 공식적으로 지원하게 되어 매우 기쁩니다 .
