## 스크립트

안녕하세요 여러분, GitHub Copilot CLI 초보자 시리즈에 다시 오신 것을 환영합니다. 오늘은 Copilot CLI만을 사용하여 새로운 기능을 기획하고, 구축하고, 코드를 검토해 보겠습니다. 자, 그럼 가봅시다. 이전 영상에서는 워크플로 전반에서 사용할 수 있는 다양한 슬래시 명령어를 살펴보았습니다 . 이제, 기능 기획, Copilot을 이용한 빌드, 그리고 마지막으로 계획, 위임, 검토라는 세 가지 강력한 기능을 순차적으로 사용하여 검토하는 방법을 살펴보겠습니다. 계획 모드( 또는 슬래시 플랜)는 요구 사항을 미리 정의하여 Copilot이 원하는 것을 정확하게 구축하도록 하는 데 매우 유용합니다. Copilot은 명확한 질문을 하고 코드를 작성하기 전에 단계별 계획을 제시합니다. 저희 앱을 한번 살펴보겠습니다. 게임을 선택하고 '이 게임 지원하기'를 클릭해도 아무런 반응이 없는 것 같습니다. 개별 게임 보기 화면과 메인 페이지 모두에서 해당 기능을 지원했음을 보여줌으로써 이 기능이 제대로 작동하도록 하고 싶습니다. Copilot의 계획 모드를 사용하여 이것을 어떻게 구축할지 계획해 봅시다. Shift + Tab 키를 누르면 계획 모드로 들어갑니다. 슬래시 플랜(/plan)이라고 입력할 수도 있습니다. 예를 들어 , 이 게임을 지원하는 버튼을 구현해 봅시다. 상태가 '지원됨'으로 변경되고 메인 페이지의 해당 게임에 아이콘이 표시되어야 합니다. 과제를 제출하면 Copilot이 프로젝트 구조를 분석하고 계획 수립을 시작합니다. 계획 모드의 장점은 Copilot이 사용자가 미처 생각하지 못했거나 명시하지 못한 부분에 대해 명확한 질문을 해준다는 점입니다. 여기서 Copilot은 지원 상태를 어떻게 저장하는지, 어떤 아이콘을 사용할지, 그리고 사용자가 지원 상태를 전환할 수 있도록 할지 여부에 대해 질문했습니다. 프로젝트 저장소로는 로컬 스토리지를 사용할 예정이므로 백엔드를 구현할 필요가 없습니다. 아이콘은 기존에 사용 하던 하트 아이콘을 그대로 사용하고 싶고, 토글 기능은 기존 기능을 지원하는 것이 좋을 것 같습니다 . 이제 Copilot이 단계별 계획을 제시할 것이고, 우리는 Copilot에게 그 계획을 실행하도록 요청할 수 있습니다. 우리는 이를 로컬에서 구현하거나 Copilot이 클라우드에서 구축하도록 선택할 수 있습니다 . 다음으로, 이 계획을 Copilot CLI에서 클라우드로 위임하여 GitHub 코딩 에이전트가 빌드하도록 하겠습니다. 위임(또는 대리자)은 작업을 원격 Copilot 코딩 에이전트에게 넘겨 임시 PR을 생성하게 하는데, 이는 실시간으로 처리하고 싶지 않은 작업에 적합합니다. 방금 세운 계획을 Copilot CLI를 통해 GitHub Copilot 코딩 에이전트에 위임해 보겠습니다 . 위임하려면 `/delegate`를 입력한 다음 프롬프트를 포함할 수 있습니다. 이를 위해 우리는 이 계획을 실행한다고 말하겠습니다. Copilot은 대화의 맥락을 요약하는 것으로 시작할 것입니다. 그런 다음, PR 초안을 생성하고 해당 구현을 추가합니다 . Copilot CLI는 에이전트가 원격으로 수행하는 작업에 대한 스트리밍 로그도 제공합니다 . 이 작업이 진행되는 동안, Copilot이 백그라운드에서 처리되고 있으므로 Ctrl+N을 눌러 새 세션을 시작하고 다른 작업을 시작할 수 있습니다 . 이 제품이 어떤 홍보 효과를 냈는지 살펴보겠습니다. 작업이 진행되는 동안 ' 세션 보기' 버튼을 클릭하여 어떤 단계를 거치고 있는지 확인하고 필요한 경우 조치를 취할 수 있습니다 . 자 , 이제 좀 빨리 감기를 해볼까요? 자세한 홍보 자료가 남겨져 있는 것을 확인할 수 있고 , 담당자가 작업을 마쳤으니 이제 파일을 살펴볼 수 있습니다. 여기서 다시 Copilot으로 돌아가서 ` slash resume` 명령어를 실행하여 이 브랜치를 테스트해 볼 수 있습니다. 슬래시/재개 메뉴를 보고 있는 동안 탭 키를 누르면 원격 브랜치로 이동할 수 있습니다 . 이것은 22분 전에 생성된 것으로, 방금 만들어진 것입니다. 이제 원격으로 작업을 계속하거나 로컬로 다운로드할 수 있습니다 . 오늘은 이 문제를 지역 차원에서 해결하고 싶습니다. 터미널에서 GitHub Copilot 코딩 에이전트에 직접 작업을 위임하는 방법은 다음과 같습니다 . 이제 이 PR을 Copilot을 사용하여 검토해 보겠습니다. Copilot CLI는 터미널에서 바로 코드를 검토할 수 있으며, 이는 커밋되지 않은 변경 사항이나 PR에 포함된 변경 사항 모두에 적용됩니다. 이번 PR의 목표는 게임 지원 버튼을 작동시키는 것이었는데, 이제 클릭했을 때 상태가 바뀌는 것을 확인할 수 있으니 좋은 징조입니다. 홈페이지에 아이콘이 표시되기를 원했는데 , 이제 그렇게 된 것 같습니다. 코드 리뷰를 시작하려면 슬래시 `review`를 입력하면 되고, 추가 프롬프트를 추가하여 살펴볼 사항을 더 자세히 지정할 수 있습니다 . 일단은 단순한 리뷰로 진행하겠습니다. 그러면 코드 검토를 전문으로 하는 하위 담당자에게 검토 작업이 위임됩니다 . 현재 원격 회의를 통해 PR을 검토하고 있지만, 이 방식은 로컬 회의에서도 동일하게 적용됩니다. 이는 버그나 취약점을 찾는 데 도움이 됩니다 . 그리고 한 가지 팁은 코드를 작성한 모델과 다른 모델을 리뷰에 사용하는 것입니다. Copilot은 코드 검토 중에 문제를 발견하면 수정 사항을 적용하고 사용자의 의견을 묻습니다. 리뷰 말미에 Copilot이 변경한 내용에 대한 요약을 확인할 수 있습니다 . 이렇게 하면 Copilot을 사용하여 검토 과정에서 발견된 항목을 수정하는 작업을 계속 반복할 수 있으며, 최종적으로 병합할 기능 관련 PR에 대한 신뢰도를 높일 수 있습니다 . Copilot CLI를 사용하면 기능 기획부터 원격으로 기능을 구현 하고 터미널에서 결과물을 검토하는 것까지 완전한 코딩 과정을 수행할 수 있습니다 .
