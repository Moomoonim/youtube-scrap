## 스크립트

아키텍처 다이어그램을 쉽게 만들 수 있는 도구를 찾고 계신가요? 그렇다면 이 영상이 도움이 될 것입니다. 안녕하세요, 저는 AWS 개발자 어드보케이트인 로히니 가에르입니다. 이 영상에서는 멋진 아키텍처 다이어그램을 만드는 데 도움이 되는 세 가지 도구를 살펴보겠습니다. 아키텍처는 머릿속 생각을 종이에 옮겨 적어 다른 사람들이 같은 내용을 이해할 수 있도록 하는 좋은 방법입니다. AWS 개발자 어드보케이트가 되기 전, 저는 AWS에서 솔루션 아키텍트로 약 5년간 근무하면서 다양한 아키텍처 다이어그램을 구축하고 고객들이 구축하는 것을 도왔습니다. 아키텍처 다이어그램을 만드는 과정은 시간이 지남에 따라 확실히 발전해 왔습니다. 마커로 화이트보드에 그리 거나 종이에 적던 것에서 PowerPoint 프레젠테이션에 추가하는 단계, 그리고 이제는 온라인 도구를 사용하는 단계까지 이르렀습니다. 오늘날의 도구는 단순히 아이콘을 캔버스에 드래그 앤 드롭하는 것 이상의 훨씬 더 많은 기능을 제공합니다. 시작하기 전에 이 영상에 좋아요, 댓글, 공유를 남겨주시고, 더 많은 유용한 실습 콘텐츠를 위해 채널 구독도 부탁드립니다. 먼저, AWS 웹사이트의 한 페이지에서 필요한 아이콘과 도구를 모두 찾을 수 있습니다. 여기에서 AWS 아이콘을 다운로드할 수 있습니다. 툴킷, 에셋, 그리고 타사 도구에서 제공하는 기존 라이브러리까지 선택할 수 있는 도구가 정말 많습니다. 하지만 오늘은 아름다운 아키텍처를 만들 뿐만 아니라 추가 기능까지 제공하는 아키텍처 다이어그램 도구를 살펴보겠습니다. 이 비디오에서는 Lucid Chart, Cloudcraft, 그리고 새로운 서비스 지원 도구인 Application Comperer 세 가지 도구를 살펴보겠습니다. 각 도구의 무료 버전을 사용하여 AWS 리소스인 API Gateway, Lambda, DynamoDB를 활용한 간단한 서버리스 패턴을 만들어 보겠습니다. 먼저 널리 알려진 Lucid Chart부터 시작해 보겠습니다. 저는 이 도구가 간단하고 사용하기 쉽다고 생각합니다. 로그인 후 제공되는 다양한 템플릿 중에서 선택하거나, 기존에 다른 도구를 사용하고 있다면 기존 다이어그램을 Lucid Chart로 가져올 수도 있습니다. 하지만 이 비디오 에서는 빈 문서를 만들어 보겠습니다. 이제 Lucid Chart에 특정 AWS 아키텍처 아이콘 세트를 사용하도록 알려줘야 합니다. 최신 2021 아키텍처 세트를 선택하겠습니다. " 이 세트를 사용하세요"라고 말하면 됩니다. 보시다시피 모든 아이콘이 도형 섹션에 가져와지거나 삽입되었네요. 이제 스크롤하면서 살펴볼 수 있지만, 다른 도구들을 검색해 보겠습니다. Amazon API Gateway를 검색해 보면 어떤 결과가 나오는지 볼까요? 네, Amazon API Gateway가 보이네요. 클릭해 보니 캔버스에 이미 나타나 있어서 원하는 위치로 드래그 앤 드롭하면 됩니다. 다음으로 Lambda가 필요하니 AWS Lambda를 검색해서 아이콘을 가져오겠습니다. 마지막으로 DynamoDB가 필요하니 DynamoDB를 검색해서 찾았습니다. 이제 필요한 세 가지 아이콘을 모두 가져왔으니, 다시 도형 섹션으로 돌아가서 API Gateway에서 DynamoDB로 연결되는 선을 그려보겠습니다. 복사해서 붙여넣고 연결하면 되겠네요. 화살표를 좀 더 굵게 하고 싶다면 그렇게 할 수도 있습니다. 이름의 표기법을 바꾸거나 색상을 변경하고 싶다면 캔버스에서 바로 할 수 있죠. 정말 쉽고 간단하지 않나요? 이제 이 아키텍처 다이어그램을 팀원들과 공유할 수 있습니다. 이메일을 통해 공동 작업자를 추가하거나 간단한 참여 ID를 제공하여 팀원들이 이 아키텍처 다이어그램에 접근하고 저와 함께 협업하여 다이어그램을 만들 수 있습니다. 애플리케이션이 발전함에 따라 다이어그램도 계속해서 발전시킬 수 있습니다. 또한 Lucid Chart의 프레젠테이션 모드를 사용하면 PNG 파일로 다운로드하거나 PowerPoint 템플릿을 수정할 필요 없이 Lucid Chart에서 바로 프레젠테이션을 할 수 있습니다. 프리미엄 버전에서는 비디오 옵션도 제공되며, 다양한 형식으로 내보낼 수도 있습니다. 아키텍처 다이어그램을 만드는 것이 목적이라면 Lucid Chart가 제격입니다. 간단하고 사용하기 쉬우며 가볍고 브라우저에서 바로 사용할 수 있습니다. 아무것도 설치할 필요가 없으며 팀원들과 협업할 수 있다는 점도 큰 장점입니다. 자, 이제 두 번째 도구인 Cloudcraft를 살펴보겠습니다. Cloudcraft에 로그인하면 자신만의 블루프린트를 만들거나 참조 아키텍처 라이브러리에서 복사할 수 있습니다. 재밌는 점은 참조 라이브러리에도 밝은 모드와 어두운 모드가 있다는 거예요. 3D 캔버스와 2D 캔버스 중에서 선택할 수도 있고요. 저는 3D를 좋아하는데, 흥미롭고 색다른 느낌을 준다고 생각해요. 3D 모드로 아키텍처 다이어그램을 만들면 사람들이 " 어떻게 만들었어?"라고 더 관심을 보이더라고요. 정말 멋진 기능이에요. 밝은 모드와 어두운 모드를 선택할 수 있는 것도 좋고, 레이어 기능도 있어요. 예를 들어, 제가 참조 아키텍처를 사용해서 만든 블루프린트를 보여드릴게요. 이건 라이브러리 에서 가져온 간단한 참조 아키텍처 다이어그램인데, 여기에 VPC와 보안 그룹에 대한 정보를 추가했어요. 레이어를 클릭하면 VPC와 보안 그룹을 볼 수 있죠. 여러 레이어를 만들어서 필요에 따라 각 레이어의 정보를 표시하거나 숨길 수 있어요. 정말 멋진 기능이라고 생각해요. 모든 이미지와 텍스트를 숨길 수도 있어요. 네, 텍스트를 모두 숨기면 실제로 모든 텍스트가 숨겨져요. 다이어그램을 보여드릴게요. 레이어를 사용하는 멋진 기능 중 하나였는데, 여러분 도 흥미롭게 생각하셨는지 댓글로 알려주세요! 자, 이제 다시 블루프린트로 돌아가 보겠습니다. 이 영상의 설명을 위해 이미 제 서버 아키텍처 참조에 몇 가지 구성 요소를 추가해 두었습니다. API 게이트웨이, 람다 함수, 그리고 다이나모 DB 테이블이 있죠. 더 많은 리소스를 추가하려면 이름을 클릭하거나 검색하면 캔버스에 나타납니다. API 게이트웨이를 람다 함수에 연결한다고 가정해 보겠습니다. 연결 방법은 두 가지가 있는데, 화살표를 선택해서 클릭해 보겠습니다. 클릭하면 어디로 연결할지 묻는 창이 뜹니다. 마찬가지로 람다 함수를 다이나모 DB 테이블에 연결해 보겠습니다. 보시다시피, 각 리소스를 클릭하면 몇 가지 설정을 할 수 있습니다. 예를 들어 API 게이트웨이의 경우, 어떤 AWS 리전을 사용할지 선택할 수 있습니다. 제가 보유한 AWS 리전 중 하나를 선택하거나, 다른 리전을 추가할 수도 있습니다. SCT AP 요청 유형과 관련하여 추가 정보를 입력하거나 링크를 추가할 수 있습니다. 마찬가지로 Lambda 함수에서도 리전을 선택할 수 있습니다. 앞서 논의한 것처럼 VPC, 보안 그룹, 서브넷과 같은 추가 정보를 입력할 수 있습니다. 아키텍처, 메모리(기본값은 128MB), 월별 요청 수 등도 지정할 수 있습니다. 추가 정보도 입력할 수 있습니다. 선택한 값에 따라 비용 견적도 제공됩니다. 비용 견적을 클릭하면 예산 탭으로 이동하여 특정 아키텍처 참조 다이어그램에 대해 월별 비용을 확인할 수 있습니다. 예를 들어 Lambda 함수에서 256으로 변경하면 빠르게 재평가하여 해당 아키텍처 참조에 대한 비용을 보여줍니다. 참고로 데이터베이스의 경우 ping $0.0으로 표시되면 DynamoDB DP에 대한 비용이 전혀 발생하지 않는다는 의미입니다. 여기서 무슨 일이 일어나고 있는지 클릭해 보시면 월 535달러를 지불하고 있다는 것을 알 수 있습니다. 하지만 DynamoDB의 경우 항상 무료 체험 기간에 해당하기 때문에 무료입니다. 대부분의 AWS 리소스는 AWS 무료 티어에 속하지만, 일부 AWS 리소스는 초기 12개월 무료 체험 기간이 끝난 후에도 항상 무료로 제공되는 '항상 무료' 티어가 있습니다. DynamoDB가 이 범주에 해당한다면 무료로 사용할 수 있습니다. 이 도구가 DynamoDB를 무료 티어에 속한다고 인식하는 것은 정말 좋은 점입니다. 덕분에 다이어그램을 만들 때 비용을 예상할 수 있고, 이 정보를 팀과 공유하여 어떤 선택을 할지 함께 논의할 수 있습니다. 또한, 이 도구의 또 다른 장점은 AWS 계정과 연결할 수 있다는 것입니다. 유료 버전에서는 CloudCraft를 AWS 계정 및 리전에 연결하면 사용 중인 서비스를 자동으로 파악해 줍니다. 사용 중인 리소스 간의 관계를 파악하면 아키텍처 다이어그램과 레이아웃을 자동으로 생성해 줍니다. 솔직히 말해서, 많은 고객에게 이 기능이 있었다면 정말 좋았을 겁니다. 자동으로 생성된 다이어그램을 바탕으로 고객과 심도 있는 아키텍처 설계 세션을 진행할 수 있었을 테니까요. 어쨌든 정말 훌륭한 기능입니다. 혹시 이 기능을 사용해 보신 적이 있다면 어떠셨는지, 추가하고 싶은 기능이 있는지, 아니면 비슷한 기능을 제공하는 다른 도구가 있는지 댓글로 알려주세요. 마지막으로 최근 출시된 AWS 서비스인 Application Composer를 살펴보겠습니다. Application Composer를 사용하면 서버리스 애플리케이션의 가상 표현을 생성 하고 클라우드 포메이션 또는 SAM 템플릿을 함께 생성할 수 있습니다. AWS Management Console을 통해 이 서비스에 액세스할 수 있습니다. AWS Management Console에 로그인하고 Application Composer를 검색하세요. 대시 보드는 다음과 같습니다. 대시보드에서 "프로젝트 생성"을 클릭하세요. 여기에서 새 빈 프로젝트를 생성하거나, 클라우드 포메이션 템플릿 또는 SAM 템플릿이 있는 기존 서버리스 애플리케이션이 있는 경우 해당 프로젝트를 불러올 수도 있습니다. 이 비디오에서는 기존 프로젝트를 사용하겠습니다. 이제 새로운 Black 프로젝트를 생성해 보겠습니다. 두 가지 옵션이 있습니다. AWS Application Composer는 브라우저에서 작동하며, 생성한 내용을 저장하지 않습니다. 저장해야 할 모든 파일은 로컬 컴퓨터에 저장해야 합니다. 연결 모드와 연결되지 않은 모드, 이렇게 두 가지 모드가 있습니다. 연결 모드에서는 AWS가 로컬 폴더 중 하나에 대한 권한을 부여할지 묻습니다. 권한을 부여하면 필요한 변경 사항을 로컬 폴더에 자동으로 저장할 수 있습니다. 이 기능을 원하지 않으면 연결되지 않은 모드를 선택할 수 있습니다. 연결되지 않은 모드에서는 AWS가 자동으로 아무것도 저장하지 않으므로 변경 사항이 발생할 때마다 수동으로 로컬 폴더에 가져와야 합니다. 이 프로젝트에서는 연결 모드를 선택하겠습니다. 로컬 폴더에 대한 액세스 권한을 부여하겠습니다. 이 폴더는 'My First Serverless App'이라는 빈 폴더입니다. 이 폴더를 선택하면 Application Composer 또는 브라우저가 이 파일을 볼 수 있도록 허용할지 묻습니다. '예'를 선택하면 '예'라는 메시지가 나타납니다. 이제 생성을 진행해 보겠습니다. 다시 한번 여쭤보겠습니다. 이 폴더에 있는 파일들의 변경 사항을 자동으로 저장하시겠습니까? 네, 저장하겠습니다. 변경 작업을 진행하시면 이제 이 폴더에 템플릿이 저장된 것을 보실 수 있습니다 . F 로컬 폴더를 보여드리면 비주얼 스튜디오에서 이렇게 보입니다. 즉, 빈 템플릿이 생성된 것입니다. 제가 접근 권한을 부여한 로컬 폴더에 yam 파일이 있습니다. 여기에는 두 가지 주목할 점이 있습니다. 모든 아키텍처 다이어그램 도구와 마찬가지로 캔버스에 아이콘이나 리소스를 드래그하여 그릴 수 있습니다. 이렇게 하면 템플릿으로 이동하여 필요한 코드, 즉 CloudFormation 또는 S 코드가 자동으로 추가된 것을 볼 수 있습니다. API Gateway를 드래그 앤 드롭하는 순간 yaml 코드가 자동으로 추가된 것을 확인할 수 있습니다. 이제 다른 것을 추가해 보겠습니다.
