## 스크립트

이 강의는 모델 관리에 관한 것이지만, 모델을 관리하려면 먼저 모델을 학습시켜야 합니다. 이번 강의에서는 학습 스크립트를 실행할 것입니다. 이 스크립트는 강의 저장소에서 확인할 수 있으며, 링크는 이 영상 아래에 공유하겠습니다. 자, 그럼 여기서 무슨 일이 일어나고 있는지 살펴볼까요? 이번 학습에서는 알파카라는 데이터셋을 사용할 것입니다. 이 데이터셋은 명령 실행에 따른 고유한 언어 모델을 찾는 데 사용됩니다. 데이터셋을 살펴보겠습니다. 저는 모델을 학습시키기 전에 데이터를 먼저 보는 것을 좋아합니다. 데이터셋을 살펴보겠습니다. 이미 보셨겠지만, 아티팩트 뷰를 통해 데이터셋과 모델의 버전 관리를 위해 가중치와 편향을 아티팩트 뷰로 관리하고 있습니다. 이 경우, 데이터셋을 살펴보겠습니다. 파일들을 보면 평가 데이터와 학습 데이터에 대한 두 개의 JSON 파일이 있습니다. 하지만 데이터를 시각화하고 탐색하기는 어렵습니다. 그래서 계보 뷰를 살펴보겠습니다. 계보 뷰는 이미 보셨을 겁니다. 보시는 것처럼 저희 데이터 세트, 특히 이 버전 4의 데이터 세트는 여러 번의 학습 실행에 사용되었습니다. 저는 이 데이터 세트를 생성하는 데 사용된 실행 과정을 살펴보고 싶습니다. 이 데이터를 기록한 사람이 직접 확인해 볼 수 있기를 바랍니다. 네, 이 데이터 세트를 기록한 사람은 토마스입니다. 토마스가 기록하는 동안 데이터를 어떻게 시각화했는지 살펴보겠습니다. 예상대로 거래 데이터 세트가 담긴 표가 보입니다. 이 표를 사용하여 데이터를 좀 더 자세히 살펴보고 실제로 무엇을 사용하고 있는지 파악할 수 있습니다. 데이터 세트에는 세 개의 열이 있습니다. 하나는 명령이고, 다른 하나는 입력 열인데, 입력 열은 비어 있거나 텍스트가 포함되어 있습니다. 그리고 이것은 출력입니다. 예를 들어, 이 명령 중 하나를 보면 피보나치 수열을 출력하는 스크립트를 작성하라고 되어 있습니다. 여기에는 입력이 없습니다. 출력은 다음과 같습니다. 출력은 실제로 피보나치 수열을 출력하는 파이썬 스크립트입니다. 마크다운으로 보면 더 잘 표시될 것 같네요. 네, 분석은 필요 없을 것 같습니다. 아마 맞을 거라고 생각해요. 입력이 포함된 예제를 하나 살펴볼까요? 여기서는 다음 게시물을 개인적인 게시물인지 전문적인 게시물인지 분류하라는 지시가 있습니다. 입력은 " 직장 동료들과 최고의 저녁 식사를 했어요"이고, 출력은 " 직장 동료들을 언급하고 있으므로 전문적인 게시물"입니다. 이 결과에 동의하는지는 잘 모르겠지만, 어쨌든 이것이 우리가 사용할 데이터 세트입니다. 이 데이터 세트에 어떤 내용이 포함되어 있는지 잘 파악하는 것이 중요하죠. 평가 예제를 살펴볼까요? 구조는 비슷합니다. 예를 들어 "이 텍스트를 스페인어로 번역하세요"라는 예제가 있습니다. 입력은 " 이 프로젝트에서 당신과 함께 일하게 되어 기쁩니다"이고, 출력은 " 이 텍스트의 스페인어 번역"입니다. 자, 이제 학습 스크립트로 돌아가 보겠습니다. 이 데이터가 모델 의 입력으로 어떻게 변환되는지 힌트를 드리자면, mini 폴더에 있는 데이터 dop 파일입니다. llm 라이브러리는 코스 저장소 내에 있으며, 입력값 유무에 따라 행을 변환하는 것을 볼 수 있습니다. 입력이 없으면 접두사를 붙이고, 그 아래에는 작업을 설명하는 명령어와 요청을 적절하게 완료하는 응답을 입력합니다. 입력이 있는 경우, 이 명령어를 프롬프트에 추가하고, 마지막 단계에서는 명령어와 출력( llm의 완료 응답)을 결합합니다. 이 결과를 사용하여 llm 모델을 학습시킬 것입니다. 이 스크립트는 실행 시 수정할 수 있는 설정 파일로 시작하며, 학습률을 조정할 수 있습니다. 또한, 단일 GPU에 맞추기 위해 일부 레이어를 고정하여 모델을 학습시킬 수도 있습니다. Laura를 사용하여 단일 GPU에서 모델을 학습시키는 대안으로, 레이어 수를 제한하는 방법도 고려할 수 있습니다. 디버깅만 하고 싶다면 평가 샘플 수를 조정할 수 있습니다. 이 스크립트는 Hugging Facet Trainer를 사용하고 있는데, Hugging Facet Trainer를 사용하기 때문에 ` report to 1B`라는 줄을 추가해야 합니다. 이렇게 하면 학습이 어떻게 진행되는지, 가중치와 편향이 어떻게 개선되는지 확인할 수 있습니다. 스크립트에 대한 자세한 설명은 생략하겠습니다. 학습에 대해 더 자세히 알고 싶으시다면, FindUnique LMS에서 제공하는 훌륭한 교육 과정을 1DB에서 확인해 보세요 . 저는 이 과정을 적극 추천합니다. 이 경우에는 모델을 교환한다고 가정하고 스크립트의 모든 요소를 ​​자세히 살펴보지는 않겠습니다. 마지막으로 강조하고 싶은 한 가지는 평가를 위해 샘플링 콜백을 추가한다는 것입니다. 일반적으로 모델을 학습시키면 손실에 접근할 수 있습니다. 학습 손실과 평가 손실을 볼 수 있지만, 평가 손실만으로는 언어 모델의 품질을 평가하기에 충분하지 않은 경우가 많습니다. 따라서 특정 시점에서 모델에서 샘플링하여 주어진 입력에 대한 출력을 생성하고 시각화하거나 자동으로 평가해야 할 수 있습니다. 이것이 바로 모델의 품질을 관리하기 위해 우리가 할 일입니다. 학습이 끝나면 저장해 둔 모델 체크포인트를 사용하여 평가 데이터 세트에 대한 출력을 생성하는 샘플링 콜백을 추가합니다. 자, 이제 이 학습 스크립트를 시작해 보겠습니다. 콘솔에서 ` train`을 입력하겠습니다. PI, 디버깅 목적으로 20단계 정도로 제한해 보겠습니다. 스크립트가 제대로 실행되는지 확인해 보면, 스크립트가 weight와 bies를 호출하고 있고, 제 리뷰 엔티티에서 실행이 시작되는 것을 볼 수 있습니다. 한 가지 팁을 드리자면, 학습이 시작되었고, 20단계 디버깅 단계이기 때문에 금방 완료될 겁니다. 스크립트를 실행하는 동안 프로젝트 이름, 특히 weight와 bies 엔티티 이름을 조정해야 한다는 점을 강조하고 싶습니다. 리뷰 엔티티에는 접근 권한이 없으므로 개인 엔티티 또는 팀 엔티티로 변경하는 것이 좋습니다. weight 와 bies의 세금도 조정할 수 있고, 입력 모델도 변경할 수 있습니다. 여기서는 11억 개의 파라미터를 가진 tiny lava라는 사전 학습된 백본을 사용하고 있습니다. 이러한 요소들을 실행하면서 조정하여 더 나은 명령을 따르는 모델을 만들 수 있습니다. 자, 스크립트가 학습을 완료했고 이제 데이터 세트를 생성하고 있습니다. 데이터 평가 세트입니다. 음, 완료될 때까지 잠시 기다려 보겠습니다. 다음 영상에서 이어서 이 모델을 어떻게 평가할지 살펴보겠습니다.
