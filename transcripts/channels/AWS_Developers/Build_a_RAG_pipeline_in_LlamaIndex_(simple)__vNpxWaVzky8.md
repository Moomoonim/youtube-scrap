## 스크립트

RAG(Retrieval Argumentation Generation)는 대규모 언어 모델과의 상호 작용 방식을 혁신하고 있습니다. 안녕하세요, 저는 스튜어트입니다. Lama Index를 사용하여 기본 및 고급 RAG 파이프라인을 보여드리겠습니다. RAG는 외부 데이터 소스 와 언어 모델을 결합하여 정보에 기반한 응답을 생성합니다. 이러한 접근 방식은 AI 출력을 실제 지식에 기반하여 정확성과 관련성을 향상시킵니다. 다음 다이어그램을 살펴보겠습니다. 이 다이어그램은 오늘 사용하는 데모를 통해 워크플로를 설명합니다. RAG의 작동 방식을 더 자세히 살펴보겠습니다. 먼저 문서 처리 단계가 있습니다. 구성된 지식 기반에서 문서를 전처리하는 것으로 시작합니다. 이러한 문서는 청크로 분할 되고 특정 임베딩 모델을 사용하여 벡터에 내장됩니다. 다음으로 인덱싱 단계가 있습니다. 이러한 문서 벡터는 효율적인 검색을 위해 벡터 데이터베이스에 인덱싱됩니다. 다음은 사용자 쿼리 처리 단계입니다. 사용자가 쿼리를 제출하면 동일한 임베딩 모델 이 쿼리 텍스트를 벡터 표현으로 변환합니다. 이 작업을 완료한 후 컨텍스트 검색 단계로 넘어갑니다. 시스템은 쿼리 벡터와 인덱스 문서 벡터를 비교합니다. 이 비교를 통해 의미적으로 가장 유사한 항목을 식별합니다. 지식 기반에서 데이터를 추출한 후, 프롬프트 논증으로 넘어갑니다. 여기서 추출된 데이터는 사용자의 쿼리와 관련된 추가 컨텍스트와 함께 제공되며, 원래 사용자 프롬프트에 추가됩니다. 다음 단계는 응답 생성입니다. 이렇게 증강된 프롬프트는 기초 모델(FM)로 전달되어 지식 기반의 관련 데이터를 통합하여 응답을 생성합니다. 모델의 출력은 해당 기관의 독점 정보를 기반으로 합니다. 다음으로 선택적인 시스템인 에이전트 오케스트레이션이 있습니다. 고급 설정에서는 이 RAG 프로세스를 에이전트로 오케스트레이션할 수 있습니다. 이러한 에이전트는 FM을 사용하여 쿼리가 지식 기반과 관련이 있는지 여부와 추출된 컨텍스트를 워크플로에 통합하는 방법을 결정합니다. 이 워크플로는 RAG 시스템이 기관의 지식 기반에서 가져온 최신 정보를 기반으로 응답을 생성할 수 있도록 합니다. 대규모 언어 모델의 광범위한 기능과 관련 정보(종종 독점 정보)를 정확하게 검색하는 기능을 결합하여 사용자의 원래 프롬프트를 지식 기반의 텍스트로 논증합니다. 이를 통해 모델은 사용자의 쿼리와 관련성이 높고 정확한 응답을 제공할 수 있습니다. 조직의 최신 정보를 처리하는 데 매우 강력한 모델입니다. 최근 이벤트, 회사별 데이터 또는 모델의 일반 학습에 포함되지 않는 정보와 같은 질의를 처리하는 데 적합합니다. Llama Index를 사용한 간소화된 RAG 파이프라인을 살펴보겠습니다. 다음 코드를 예시로 사용하겠습니다. 먼저 Llama Index에서 Simple Directory Reader와 Vector Store Index를 가져옵니다. 이 두 도구는 데이터를 로드하고 검색 가능한 인덱스를 생성하는 데 필수적입니다. 이 작업을 완료한 후 Simple Directory Reader를 사용하여 데이터 SL 디렉터리에서 문서를 로드합니다. 이 디렉터리에는 텍스트 또는 PDF와 같은 다양한 파일 형식이 포함될 수 있습니다. 다음으로 이러한 문서에서 Vector Store 인덱스를 생성합니다. 이 단계는 문서를 효율적인 의미 검색을 위한 벡터 표현으로 변환하는 데 매우 중요합니다. 이제 "인공지능이 인간 지능을 능가할 가능성에 대한 철학적 함의를 분석하세요"와 같은 간단한 질문으로 인덱스를 쿼리할 수 있습니다. 인덱스는 이 쿼리에 대한 가장 관련성이 높은 문서를 찾습니다. 마지막으로 복잡한 쿼리를 사용하여 컨텍스트를 검색한 후 언어 모델이 생성한 응답을 출력합니다. 여기에서 언어 모델이 다양한 정보 모음에서 미묘한 뉘앙스를 처리하고 이해하는 능력을 보여줍니다. 벡터 저장소 인덱스를 통해 제공된 문서는 이 시나리오에서 더욱 가치가 높아집니다. 복잡한 쿼리에 답하기 위해 문서에서 관련 정보를 효과적으로 검색할 수 있기 때문입니다. 이 간단한 R 파이프라인은 지식 기반의 관련 정보를 사용하여 언어 모델의 응답을 결정하는 Rags의 핵심 개념을 보여줍니다. 간단한 Rags 파트 플랜은 강력하지만, 추가적인 고급 기술을 통해 더욱 향상시킬 수 있습니다. 그러한 기술 중 하나는 라우터 쿼리입니다. 쿼리 엔진의 루트를 사용하면 쿼리의 특성에 따라 쿼리를 다른 인덱스 또는 쿼리 엔진으로 라우팅할 수 있습니다. 이는 다양한 유형의 정보를 처리하거나 서로 다른 쿼리에 대해 서로 다른 처리 방식이 필요한 경우 특히 유용합니다. 이제 라우터 쿼리를 구현하는 방법을 예시로 살펴보겠습니다. 다음 코드를 보면 먼저 IM 요약 인덱스 와 라우터 쿼리 엔진을 포함한 llama 인덱스의 추가 클래스를 가져옵니다. 이제 요약 인덱스와 벡터 저장소 인덱스라는 두 가지 유형의 인덱스를 생성합니다. 각각 다른 유형 의 쿼리에 적합합니다. 각 인덱스에서 쿼리 엔진을 생성할 수 있습니다. 이제 이러한 엔진은 해당 인덱스 유형을 검색하는 방법을 알고 있습니다. 다음으로 쿼리의 특성에 따라 사용할 쿼리 엔진을 결정하는 라우터 쿼리 엔진을 생성합니다. 이 예제에서는 미리 간단한 코드를 작성해 두었습니다. 여기서 `rotor query` 함수를 사용하여 입력 쿼리를 문자열로 받아 사용할 쿼리 엔진을 나타내는 정수를 반환할 수 있습니다. 루트 지정 로직은 매우 간단합니다. 쿼리가 10 자 미만이면 요약 쿼리 엔진을 사용하고, 그렇지 않으면 벡터 쿼리 엔진을 사용합니다. 이제 다시 메인 코드로 돌아가서, 쿼리 엔진 루트 지정 설정에서 쿼리 루트 지정 로직을 정의합니다. 이는 키워드, 쿼리 길이 또는 더 복잡한 기준에 기반할 수 있습니다. 쿼리 루트 지정 방식을 사용하면 다양한 유형의 쿼리를 효율적으로 처리할 수 있습니다. 예를 들어, 일반적인 질문은 빠른 수준 높은 답변을 위해 요약 인덱스로 보내고, 상세하거나 구체적인 질문은 보다 정확한 정보 검색을 위해 벡터 인덱스로 보낼 수 있습니다. 이 고급 기술은 RAG 파이프라인의 유연성과 성능을 향상시켜 다양한 쿼리 유형과 정보 요구 사항에 적응할 수 있도록 합니다. 쿼리 루트 지정과 같은 고급 RAG 기술을 구현함으로써 몇 가지 주요 이점을 얻을 수 있습니다. 예를 들어, 타겟팅 인덱싱을 통해 정확도를 향상시킬 수 있습니다. " 무엇이..."와 같은 질문을 할 수 있습니다. 2004년 3분기 매출 성장률과 같은 질문에 대해 라우터는 재무 보고서 인덱스로 쿼리를 전달하여 정확한 답변을 제공합니다. 특수 인덱스를 사용하면 효율성이 향상됩니다. 예를 들어, 제품 라인업 요약과 같은 질문에 대해서는 요약 인덱스를 사용하여 자세한 제품 정보를 생략하고 신속하게 답변할 수 있습니다. 또한 다양한 쿼리를 처리할 수 있도록 유연하게 설계되어 있습니다. 예를 들어, 시스템은 반품 정책을 단계별로 설명하거나 지속 가능성 이니셔티브 개요를 제공하는 등 두 가지 유형의 쿼리를 효율적으로 관리할 수 있습니다. 이러한 미묘한 차이를 고려한 응답 방식은 복잡한 질문을 훨씬 간단하게 만들어 줍니다. 또 다른 예로, 4분기 실적을 경쟁사와 비교하고 개선 방안을 제시하는 경우, 여러 인덱스를 활용하여 포괄적인 답변을 제공할 수 있습니다. 이러한 개선 사항을 통해 당사의 래깅 시스템은 실제 엔터프라이즈 급 작업을 처리할 수 있습니다. 개발자와 고객은 광범위한 정책과 구체적인 세부 정보에 모두 접근할 수 있는 서비스를 구축할 수 있으며, 연구원은 개요 와 상세 결과를 모두 얻어 Oran 조직의 다양한 요구 사항에 걸쳐 의사 결정을 향상시킬 수 있습니다. 파이프라인과 프로젝트에 이러한 래깅 구현을 적용해 보세요. 설명에 있는 노트북에서 예제를 찾아 직접 모든 단계를 실행해 보고 결과를 확인해 보세요. 이 설명에서 언급한 예시들을 통해 다양한 문서 유형 과 쿼리를 실험해 보고 AI 애플리케이션이 어떻게 향상되는지 직접 확인해 보세요. 이 영상이 도움이 되셨다면, 더 많은 실용적인 기술 콘텐츠를 보시려면 이 영상에 좋아요를 누르고 AW Developers YouTube 채널을 구독해 주세요. 시청해 주셔서 감사합니다!
