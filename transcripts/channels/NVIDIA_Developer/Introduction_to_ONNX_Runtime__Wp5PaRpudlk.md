## 스크립트

안녕하세요 여러분, 저는 Vide Tech 마케팅 팀의 피터입니다. 오늘은 Onyx, Onyx 런타임, DML(Direct ML), Onyx 런타임 Gen에 대한 소개를 드리겠습니다. 각 프레임워크 또는 라이브러리가 무엇인지, 서로 어떻게 상호 작용하는지, 그리고 서로 어떻게 다른지 설명해 드리겠습니다. 이 개념들에 대한 사전 지식은 필요 없지만, LLM이나 AI 모델에 대한 기본적인 이해는 있으면 좋습니다. 먼저 Onyx가 무엇인지부터 시작해 보겠습니다. Onyx는 Open Neural Network Exchange의 약자입니다. 이 프로젝트의 핵심 아이디어는 연구자가 모델을 만들 때 다양한 프레임워크를 사용하여 모델을 구현하고 학습시킬 수 있다는 것입니다. 현재 scikit-learn, TensorFlow, Torch 등이 있습니다. 사용 사례와 원하는 모델 기능에 맞는 프레임워크를 선택할 수 있습니다. 학습이 완료되면, CPU, GPU 등 특정 하드웨어에 배포하여 추론을 수행해야 합니다. 모바일 기기, NPU 등 다양한 하드웨어 옵션이 존재하는데, 모델 학습 중에는 이러한 요소들을 고려하고 싶지 않을 것입니다. 학습이 완료된 모델을 배포 단계로 넘어가고 싶을 것입니다. Onyx는 모델 개발자들이 학습과 배포를 분리할 수 있도록 설계된 표준입니다. Onyx는 추론에 초점을 맞춘 모든 머신러닝 모델을 표현하는 표준으로, 원하는 프레임워크에서 학습한 후 변환 도구를 사용하여 Onyx 모델로 변환하고 배포 단계로 넘어갈 수 있도록 합니다. Onyx 표준은 실행 그래프 형태로 표현되며, 각 노드는 행렬 곱셈, 덧셈, 뺄셈과 같은 기본 연산을 나타냅니다. 그래프의 정점은 각 연산의 종속성 구조를 나타냅니다. 이제 Onyx가 무엇인지, Onyx 모델이 어떻게 생겼는지, 그리고 이 표준이 존재하는 이유에 대해 이해했으니, Onyx 런타임에 대해 알아보겠습니다. Onyx 런타임은 Onyx 모델의 실행을 관리하는 라이브러리입니다. 오닉스 그래프는 실제로 이러한 연산, 즉 노드와 정점을 중간의 실행 가능한 코드에 연결합니다. 여기 오닉스 모델의 예시가 있습니다. 오닉스 런타임 프레임워크는 이 실행 그래프를 가져와 오른쪽의 일련의 연산으로 변환합니다. 여기서 오른쪽에는 수행해야 할 연산, 해당 연산에 대한 인수 , 출력이 저장될 위치가 표시됩니다. 오닉스 런타임은 이러한 모든 연산을 거쳐 최종적으로 모델의 출력을 얻을 때까지 진행합니다. 오닉스 런타임의 핵심 개념은 실행 공급자입니다. 실행 공급자란 무엇일까요? 오닉스 런타임은 이전 슬라이드에서 보여드린 것처럼 그래프를 일련의 연산으로 구성한 후, 실행해야 할 연산, 해당 연산에 필요한 입력, 출력을 저장할 위치를 정확히 파악했다고 판단합니다. 하지만 이 시점에서 오닉스 런타임은 실제로 이러한 연산을 실행할 수 있는 기능을 가지고 있지 않습니다. 행렬 곱셈을 실행해야 한다는 것은 알지만, 어떻게 실행해야 하는지는 모르는 것입니다. 음, 바로 여기서 실행 공급자(Execution Provider, EP)가 등장합니다. EP는 Onyx 런타임에서 실행하려는 Onyx 모델에 있는 모든 Onyx 연산자에 대한 실행 세부 정보를 제공합니다. 일반적인 흐름은 다음과 같습니다. Onyx 런타임은 이 테이블을 순회하며 실행하려는 연산과 입력값을 확인합니다. 현재 실행 중인 EP로 요청을 전달하고, EP가 해당 연산에 대해 가지고 있는 코드를 실행합니다. 결과를 다시 Onyx 런타임으로 전달하여 출력에 저장합니다. 그리고 이 과정을 연산 테이블의 모든 행에 대해 반복합니다. Onyx 런타임에서 지원하는 다양한 실행 공급자가 있으며, 각 공급자는 Onyx 연산자 정의를 구성하는 기본 코드, 해당 코드가 실행되는 위치, 최적화 정도 등 이 모두 다릅니다. 오늘은 DML(Direct ML) EP에 초점을 맞추겠습니다. 매우 유연하고 성능이 뛰어난 옵션이며, NVIDIA GPU 또는 직접 실행을 지원하는 모든 하드웨어에서 코드를 실행하는 데 적합합니다. 이제 Onyx가 무엇인지, Onyx 모델, Onyx 런타임, 실행 공급자에 대한 기본적인 이해를 바탕으로 마지막 단계인 Onyx 런타임 생성에 대해 자세히 살펴보겠습니다. 이 프로젝트의 핵심 아이디어는 생성형 모델을 사용할 때 사용자나 개발자에게 완벽한 엔드투엔드 경험을 제공하기 위해 핵심 모델 추론 외에도 많은 작업이 필요하다는 것입니다. 예를 들어, Llama 3 또는 다른 일반적인 LLM 모델을 추론하는 과정을 보여주는 간단한 다이어그램이 있습니다. 프랑스의 수도가 무엇인지 입력하면, 앞서 설명한 것처럼 Onyx 런타임을 사용하여 Llama 3 모델을 추론합니다. 그러면 결과적으로 어휘집에 있는 많은 토큰에 대한 확률 분포를 얻게 됩니다. 이 시점에서 Onyx 런타임을 사용하여 Llama 3 모델을 추론했지만, 이제 래퍼 코드를 작성해야 합니다. 원하는 토큰을 샘플링하고, 원하지 않는 토큰은 지울 수 있습니다. 어휘 마스크가 있고 이러한 토큰을 제거하고 싶다면 확률 분포에서 해당 토큰을 제거할 수 있습니다. 여기서 토큰을 샘플링하여 지금까지의 입력에 추가하고 필요한 값 캐싱을 처리한 다음, 입력을 다시 Llama 3에 통과시켜 다른 확률 분포 샘플을 얻는 과정을 반복합니다. 이 과정을 종료 조건에 도달할 때까지 반복합니다. Onyx Runtime Gen의 핵심 아이디어는 Onyx Runtime을 사용하여 LLM을 추론하는 것이지만, 이러한 모든 래퍼 코드는 이 라이브러리를 통해 자동으로 처리됩니다. 궁극적으로 이 설명은 Onyx Runtime Gen 과 Onyx Runtime 간의 관계를 나타냅니다. 즉, Onyx Runtime Gen 라이브러리는 Onyx Runtime을 사용하여 생성형 Onyx 모델을 반복적으로 실행하여 사용자에게 엔드 투 엔드 흐름을 제공합니다. 이 스크린샷은 Microsoft 공식 GitHub 페이지에서 가져온 것으로, 몇 가지 내용을 간략하게 설명합니다. 제가 여기서 말하는 디코딩 루프, 논리 처리, 검색, 샘플링, 캐시 관리와 같은 구체적인 단계들은 모두 이 라이브러리에서 처리됩니다. 다시 말해, 이 간단한 다이어그램으로 설명할 수 있습니다. Onyx 런타임 Geni는 Onyx 런타임의 반복 실행을 처리하는 생성 프레임워크이며, 실행 공급자를 사용하여 Onyx 모델의 추론을 조율합니다. 이제 이러한 개념들과 그 상호 작용 방식, 그리고 각 개념의 차이점이 모두 이해되셨기를 바랍니다. 이제 실제로 코드로 구현하는 방법을 살펴보겠습니다.
