Sweepy Embedded, 14일 무료 샌드박스를 제공하는 WCS, 그리고 Docker를 사용하여 로컬에서 실행하는 방법 등 Review를 실행하고 Weavate와 Llama Index를 함께 사용하여 애플리케이션을 시작하는 데 도움이 되는 몇 가지 옵션을 소개합니다. Review 레시피에 대한 링크는 설명란에 남겨두겠습니다. 이 영상에서는 Weavate의 몇 가지 기능과 통합 파트너사의 기능을 활용한 전체 과정을 보여주는 노트북을 공유합니다. 그럼 바로 시작해 볼까요? 이것이 바로 그 노트북입니다. Wii V8 레시피 저장소에서 공유할 예정이니, 꼭 따라오셔서 통합( Integrations) &gt; Llama Index 에피소드 1로 이동하시면 됩니다. 이미 설명드린 개요는 여기까지이고, 이제 Llama Index가 무엇인지 자세히 알아보겠습니다. Llama Index는 다른 LMS와 스토리지 제공업체를 연결할 수 있도록 해주는 프레임워크입니다. 여기서 스토리지 제공업체는 오픈 소스 Vector 데이터베이스를 의미합니다. Llama Index와 VV8을 함께 사용하면 최고의 검색 증강 생성 스택을 만들 수 있습니다. 기존 LMS는 사용자의 특정 데이터에 직접 접근할 수 없었지만, Llama Index와 LLM을 함께 사용하면 데이터베이스에 저장된 데이터를 LLM에 제공할 수 있기 때문입니다. 이를 통해 회사에 특화된 쿼리를 수행할 수 있습니다. 예를 들어, "회사에 사직서를 제출할 수 있는 기한은 언제인가요?"와 같은 쿼리를 작성할 수 있습니다. (좀 끔찍한 예시일 수도 있지만, 요점은 이해하셨을 겁니다.) Llama Index의 멋진 기능 중 하나는 Llama Hub입니다. Llama Hub는 여러 LMS와 스토리지 제공업체를 연결하는 허브입니다. Slack, PDF 문서, YouTube, PowerPoint 등 다양한 데이터 로더를 사용하여 Vector 데이터베이스에 데이터를 입력할 수 있습니다. 이 데모에서 보여드리는 것처럼 모든 데이터 소스는 Vector 데이터베이스에 입력할 수 있습니다. 첫 번째 데모에서는 Llama Index를 사용하여 Vector에 데이터를 로드하는 방법과 그 반대의 방법을 보여드리겠습니다. 그럼 데모를 시작하겠습니다. 기존에 Vector Database 인스턴스가 실행 중인 경우가 없는 분들을 위해 세 가지 시작 옵션이 있습니다. 첫 번째는 WeBeEmbedded를 사용하는 것입니다. 이 옵션을 사용하면 애플리케이션에서 직접 실행할 수 있습니다. 유일한 요구 사항은 Python 클라이언트가 최신 버전이어야 한다는 것입니다. 최소 3.21 버전인지 확인하면 WeBeEmbedded를 실행할 수 있습니다. 그렇지 않은 경우 다른 옵션도 있습니다. 두 번째 옵션은 BB 클라우드 서비스를 사용하는 것입니다. 계정을 생성한 다음 BB 인스턴스를 생성할 수 있습니다. 특히 좋은 점은 14일 무료 샌드박스를 제공하여 Vector를 사용하여 봇을 테스트하고 빠르게 시작할 수 있다는 것입니다. 데이터베이스, 음, 그게 한 가지 옵션이에요. 완전히 무료로 실행할 수도 있고, Docker에 내장해서 무료로 실행할 수도 있어요. 어떤 방법이든, 가장 편한 방법을 사용하시면 돼요. 콘솔에서 BB 인스턴스를 생성하면 여기에 URL을 입력해야 해요. 저는 Llama Index Episode One을 사용하고 있어요. 그리고 여기에 OpenAI 키를 입력하는데, 보안 및 재정적인 이유로 숨겨 놨어요. 샌드박스를 생성하고 인증 기능을 활성화했다면 여기에 키를 입력할 수도 있어요. 하지만 이 데모에서는 인증 기능을 사용하지 않았어요. 마지막으로 Docker를 사용해서 리뷰를 실행할 수도 있어요. 이 Llama Index 폴더 안에 gamble 파일이 있는데, 그걸 가져와서 실행하면 localhost 8080에서 실행될 거예요. 이렇게 세 가지 방법으로 Weave를 실행할 수 있어요. Weave 인스턴스가 아직 실행 중이 아니라면, Weave를 설정하기 위한 또 다른 요구 사항은 스키마를 구축하는 거예요. 이 셀에서 저는 블로그 게시물 클래스를 만들고 content 속성을 전달하고 있어요. content 속성은 그냥... 각 블로그 게시물 안에 있는 텍스트인데, 제가 전에 명확히 설명하지 못했던 것 같지만, 저는 BB8 블로그를 데이터 세트로 사용하고 있습니다. 네, 그것도 꼭 확인해 보세요. Llama Index를 사용하여 WebVA에 데이터를 추가하는 것은 다양한 데이터 로더를 사용하면 정말 쉽습니다. 이 비디오에서는 Simple Directory Reader, Web Page Reader, Notion에서 문서를 불러오는 세 가지 방법을 다룹니다. Slack, PDF 또는 YouTube 동영상을 사용하려면 Llama Hub를 방문하는 것이 좋습니다. 다양한 데이터 로더 사용 방법을 확인할 수 있습니다. 자, 먼저 Simple Directory Reader부터 시작해 보겠습니다. 이 프로그램은 파일 시스템에서 파일을 읽어옵니다. 제 데이터 폴더에는 Rev8 블로그 게시물이 모두 있는데, 이것을 불러오면 됩니다. 아주 간단하죠. 다음 방법은 Simple Web Page Reader를 사용하는 것입니다. 이것은 HTML을 텍스트로 변환하는 웹 스크래퍼입니다. 어떻게 하는지 보여드리기 위해 Wii Vape를 보여드리겠습니다. 블로그, Llama 인덱스, Weave 블로그 게시물 등을 이용하면 웹사이트에서 데이터를 쉽게 불러올 수 있습니다. 또 다른 방법은 Notion 페이지 리더를 사용하는 것입니다. Notion 페이지 리더는 Notion에서 문서를 불러오는데, Notion 문서를 마크다운으로 변환할 수 있다는 점이 정말 좋습니다. 이게 새로운 기능인지 아니면 제가 몰랐던 건지는 모르겠지만, 정말 유용한 기능입니다. 이제 Google이나 Notion에 있는 블로그 게시물을 일일이 마크다운 으로 변환하는 수고를 덜 수 있으니까요. 한번 사용해 보시면 좋을 것 같습니다. Notion 페이지 리더는 통합 토큰을 사용합니다. 워크스페이스 소유자 또는 관리자라면 통합을 생성하고 여기에 비밀 키를 입력하면 됩니다. 다음으로 페이지 ID를 입력해야 하는데, notion.so에 접속해서 불러오려는 문서로 이동하면 URL 끝에 숫자와 문자가 섞인 코드가 있습니다. 이 코드를 여기에 붙여넣으면 Notion에서 문서를 불러오는 것이 아주 간단해집니다. 이제 데이터를 확보했으니 토큰 길이 제한 문제를 방지하기 위해 데이터를 청크 단위로 나누어야 합니다. LamaIndex에는 간단한 노드 파서가 있으며, 이 파서는 데이터를 청크 단위로 나누어 줍니다. 이 데모에서는 블로그 게시물을 노드로 나누어 처리합니다. 다음으로, 이러한 메모를 가져와 업로드하여 문제를 해결해야 합니다. 이를 위해서는 벡터 저장소를 구축해야 합니다. 여기에 Weave 클라이언트가 있으며, 이를 `client`로 설정합니다. Weave 클라이언트는 WCS 인스턴스에 내장하여 실행하거나 로컬에서 실행할 수 있습니다. Weave 인스턴스를 연결하여 벡터 저장소를 구축합니다. `index`는 우리가 만든 클래스 이름입니다. 이 예시에서는 스키마에 정의한 `blog post`를 사용하고 있으며, 텍스트 키는 스키마에 정의한 속성인 `content`입니다. 이제 ARM 베팅을 위한 저장소를 설정해야 합니다. 이를 위해 벡터 저장소를 전달하기만 하면 됩니다. 여기서 정의한 이유는 WeVieate 데이터베이스를 사용하기 때문입니다. 다음으로 인덱스를 설정해야 하므로 노드를 가져와 방금 정의한 것과 동일한 스토리지를 설정합니다. 이것이 Llama 인덱스를 사용하여 Alleviate에 데이터를 업로드하는 데 필요한 마지막 단계입니다. 이제 WeVieate 인스턴스에 데이터가 있으므로 간단한 쿼리 엔진을 구축해 보겠습니다. 방금 구축한 인덱스를 사용하여 쿼리를 전달합니다. 쿼리는 " Lumps와 Search의 교집합은 무엇인가?"를 묻고, 이 정보를 WeVieate 데이터베이스에서 가져오도록 합니다. 좀 더 구체적으로 말하면, 제가 Lumps와 Search에 대해 이야기하는 블로그 게시물을 가져오도록 하고 싶습니다. Conor와 저는 몇 주 전에 이 블로그 게시물을 작성했습니다. 이 질문에 대한 답변이 어떻게 나오는지 보는 것이 흥미로울 것입니다. 답변은 "Arms와 Search의 교집합은 Alums를 사용하여 검색 기능을 향상시키는 기능입니다. 예를 들어 조각 쿼리, 인덱스 구성 이해, 렌즈 및 재구성 등이 있습니다."라고 합니다. 블로그 게시글을 실제로 읽어보시는 걸 추천드려요. Llama 인덱스를 사용해서 이렇게 간단한 검색 엔진을 구축하는 방법이 정말 멋지거든요. 다른 방법은 VBA 콘솔을 사용해서 쿼리하는 거예요. 여기서는 Weevid 인스턴스에 연결해서 간단한 하이브리드 검색을 실행하고 있어요. 하이브리드 검색이 뭔지 잘 모르시는 분들을 위해 설명드리자면, 키워드 검색인 BM25와 벡터 검색을 결합하는 거예요. 이 결합은 알파(Alpha) 매개변수를 사용해서 이루어지는데, 알파를 0으로 설정하면 순수 BM25 검색이고, 1로 설정하면 순수 벡터 검색이에요. 0.75로 설정하면 벡터 검색 비중이 더 높아지 는데, 이건 그냥 여러분의 애플리케이션에 맞게 조정해 볼 수 있는 값이에요. 저는 여기서는 0.75로 설정했어요. 자, 이제 검색 결과가 나올 거예요. 블로그 게시글에 있는 텍스트, 즉 콘텐츠를 반환하는 거죠. 제 쿼리는 렌즈 와 검색의 교집합을 찾는 거라서, 이 주제에 대해 이야기하는 블로그 게시글들을 가져오고 싶었어요. 결과는 이렇게 나와요. 바로 여기, 음, 그래서 검색 블로그 게시물의 요소를 전달하거나 출력하는 것입니다. 아주 좋습니다. 또 하나 알아둘 점은 OpenAI 키와 헤더를 여기에 전달할 수 있다는 것입니다. 쿼리를 벡터화해야 하기 때문입니다. 네, 이게 전부입니다. Llama Index에서 쿼리하는 한 가지 방법입니다. 아, 죄송합니다. Weave 인스턴스가 이미 실행 중이고 Llama Index를 추가하려는 경우 이 방법을 사용하면 됩니다. 웹 리더를 사용하면 되는데, 관련 문서는 Llama Hub에서 확인할 수 있습니다. 아니면 이 노트북을 따라가셔도 됩니다. WCS에 연결 하거나 Docker를 사용하는 경우 localhost 8080을 전달해야 합니다. 사용자 이름과 비밀번호로 로그인한 다음 리베이트 인스턴스의 URL을 전달합니다. 여기서 문서화하는 것은 스키마입니다. 저는 블로그 게시물 클래스를 사용하고 AI 콘텐츠 속성을 전달했습니다. 이제 실행했으니 쿼리하거나 업로드하고 쿼리할 수 있습니다. 이미 설정된 기존 클래스를 사용해서 URL을 다시 전달합니다. 그러면 WeBeat 리더가 어떤 인스턴스에 연결해야 하는지 알 수 있습니다. 그런 다음 쿼리를 구성합니다. RefTebec이 무엇인지 설명하는 블로그 게시물을 찾고 싶고, 콘텐츠 속성을 기준으로 두 개로 제한하여 콘텐츠만 출력하도록 하고 싶습니다. 자, 이제 문서가 준비되었으니 인덱스를 구축해야 합니다. 그런 다음 쿼리 엔진을 실행합니다. 다시 RefTebec이 무엇인지 묻자, "RefTebec은 NLP를 사용하여 텍스트 참조의 벡터 표현을 생성하는 머신 러닝 알고리즘입니다."라는 답변이 나옵니다. 약간 논란의 여지가 있지만 어쨌든 답변은 나왔습니다. 이것이 Llama 인덱스에서 쿼리하는 한 가지 방법입니다. 콘솔에서도 쿼리할 수 있습니다. 콘솔에서 텍스트를 사용하여 OpenAI 키를 전달하면서 "RoughTebec이 무엇입니까?"라고 물으면(벡터화해야 하기 때문입니다), RefTebec에 대한 블로그 게시물과 추천 시스템에 왜 필요한지에 대한 내용이 출력되는 것을 볼 수 있습니다. RefTebec에 대해 더 자세히 알고 싶으시면 관련 자료를 참고하세요. tibec에 대해서는 저희 문서를 확인해 보시길 추천드립니다.
