## 스크립트

AWS에 서버리스 웹 애플리케이션을 빠르게 배포하고 싶으신가요? 안녕하세요, 저는 스튜어트입니다. Amazon Q Developer를 AWS CDK와 함께 사용하여 이 작업을 수행하는 방법을 보여드리겠습니다 . 먼저 프레젠테이션 레이어부터 살펴보겠습니다. 여기서 핵심적인 고려 사항은 이미지, CSS, 자바스크립트 파일과 같은 정적 자산을 효율적이고 안전하게 제공하는 방법입니다 . 최적의 방법은 아마존 S3 버킷을 원본 서버로 사용하고, 아마존 클라우드프론트를 통해 전 세계에 콘텐츠를 전송하는 것입니다. 이를 설정하려면 Amazon Q Developer에게 CloudFront S3 정적 자산 용 S3 버킷을 생성하고 오리진 액세스 제어를 통해 보안이 유지되도록 Python을 사용하여 CDK 스택을 생성하도록 요청할 수 있습니다. 이 CDK 코드는 공개 액세스 비활성화 및 오리진 제어 설정과 같은 필요한 보안 제어를 사용하여 S3 버킷을 프로비저닝합니다. CloudFront가 버킷에 안전하게 액세스할 수 있도록 하기 위해 이제 정적 콘텐츠에 대한 더 나은 감사 및 모니터링을 위해 CloudTrail 로깅을 이 S3 버킷에 추가하겠습니다 . 다음으로는 Amazon AWS Lambda와 Amazon API Gateway를 사용하여 애플리케이션 계층을 설정하겠습니다. 이를 통해 웹 애플리케이션에서 동적 콘텐츠와 API 요청을 처리할 수 있게 됩니다 . Amazon Q Developer에게 Amazon API Gateway에서 호출되는 AWS Lambda 함수를 생성하는 CDK 스택을 만들어 달라고 요청할 것입니다 . 이 CDK 코드는 Lambda 함수와 API Gateway 엔드포인트를 포함한 필요한 AWS 리소스를 프로비저닝합니다. 이 모든 것이 우리 애플리케이션의 서버리스 백엔드를 구동합니다. 이제 데이터 계층에서는 아마존 데이터베이스를 사용하여 애플리케이션의 모든 데이터를 저장할 것입니다. Amazon DB는 빠르고 예측 가능한 성능과 원활한 확장성을 제공하는 완전 관리형 NoSQL 데이터베이스 서비스입니다. 자 , 그럼 Amazon Q Developer에게 읽기 용량 100단위, 쓰기 용량 100단위를 가진 DynamoDB 테이블로 구성된 CDK 스택을 생성해 달라고 요청해 보겠습니다. 이 CDK 코드는 애플리케이션의 모든 요구 사항을 충족하기 위해 적절한 성능 특성을 갖도록 DynamoDB 테이블을 설정합니다 . 아시다시피, 모니터링은 매우 중요합니다. 이는 서버리스 애플리케이션의 안정성과 신뢰성에 매우 중요합니다 . 여기서는 주요 지표를 추적하고 알림을 설정하기 위해 Amazon CloudWatch를 사용하겠습니다. 이를 위해 Amazon Q Developer에게 매일 오후 3시에 EC2 인스턴스의 웹 인스턴스를 중지하는 CloudWatch 이벤트 규칙의 CDK 스택을 생성하도록 요청하겠습니다. UTC 기준입니다. 이 기능은 CDK 코드가 CloudWatch 이벤트 규칙을 설정하여 업무 시간 외에는 모든 서버 인스턴스를 자동으로 중지하도록 합니다. 이는 비용 절감에 도움이 됩니다. 이제 마지막으로 서버리스 애플리케이션 인프라 전체의 배포를 자동화하는 CI/CD 파이프라인을 구축하겠습니다 . 다시 말해, 이를 위해 Amazon Q Developer에게 Python을 사용하여 3계층 서버리스 애플리케이션을 배포하는 CDK 파이프라인을 생성하도록 요청할 것입니다. 이 CDK 파이프라인 코드는 완전 자동화된 배포 프로세스를 설정하여 애플리케이션 개발 과정에서 일관성과 안정성을 보장합니다 . 보시다시피, Amazon Q Developer는 CDK를 사용하여 AWS에 서버리스 애플리케이션을 배포하는 속도를 크게 향상시킬 수 있습니다 . 한번 시도해 보시고 생산성 향상 효과를 경험해 보세요 .
