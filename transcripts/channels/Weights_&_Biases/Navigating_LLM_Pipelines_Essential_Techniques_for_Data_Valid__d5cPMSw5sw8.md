## 스크립트

안녕하세요 여러분, 저는 Shrea입니다. 머신러닝 파이프라인 데이터 유효성 검사 과정을 담당하고 있습니다. LLM(Large Language Model) 파이프라인은 기본적으로 머신러닝 파이프라인의 하위 집합입니다. 이러한 파이프라인의 입력은 프롬프트라고 생각할 수 있습니다. 이는 머신러닝 세계의 특징(feature)과 유사합니다. 프롬프트는 런타임에 데이터로 포맷됩니다. 예를 들어 이메일을 작성하라는 프롬프트가 있다면 사용자 정보, 수신자 정보와 같은 런타임 변수를 사용할 수 있습니다. LLM의 응답은 출력 또는 예측이라고 생각할 수 있습니다. 머신러닝 파이프라인 비유를 사용하자면, LLM 파이프 라인의 입력과 출력은 완전히 비정형적인 자유 형식 데이터라는 점이 유일한 차이점입니다. 따라서 LLM 파이프라인도 머신러닝 파이프라인 의 한 종류이지만, 여전히 프롬프트 와 응답을 모니터링하고 이러한 입력과 출력에 대한 데이터 유효성 검사를 수행해야 합니다. 구조화된 데이터 유효성 검사 기법은 LLM 환경에도 적용됩니다. 예를 들어 LLM에게 이메일을 작성하도록 요청하는 프롬프트가 있는 파이프라인이 있다고 가정해 보겠습니다. 런타임에 일부 정보를 입력할 수 있지만, 이러한 값은 런타임에 채워지기 때문에 LLM 파이프라인의 입력과 출력에 대한 유효성 검사를 수행해야 합니다. 아직 모든 값이 완전히 정확하고 타당한지 확인해야 합니다. 예를 들어 변수가 null이면 안 됩니다. 그렇지 않으면 llm이 어떤 값을 반환할지 알 수 없기 때문입니다. 더 고급 설정에서는 이러한 각 값의 임베딩이 이전 실행 결과나 [음악] 실행의 파티션 또는 그룹과 유사해야 합니다.
