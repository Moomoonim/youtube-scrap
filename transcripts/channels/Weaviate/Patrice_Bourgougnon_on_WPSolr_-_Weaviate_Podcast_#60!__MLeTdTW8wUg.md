AI 검색을 비롯한 이러한 사업을 운영하는 데 있어 어떤 점과 미묘한 차이가 있는지 좀 더 자세히 말씀해 주시겠어요? 코딩이 필요 없는 방식이라 흥미로운 것 같은데, AI를 워드프레스에 구축하는 경험에 대해 좀 더 자세히 설명해 주시겠어요? 워드프레스 같은 거 말이죠. 네, 워드 프레스는 헤드리스 솔루션이나 노코드 솔루션 등과 비교했을 때 좀 더 특수한 면이 있어요. 완전히 새로운 방식으로 개발할 수도 있고, 오픈소스라서 서버나 호스팅 서비스에 설치해서 전체 코드에 접근하고 수정할 수도 있거든요. 물론 워드프레스 코어는 수정하면 안 되겠죠. 코어를 업데이트하면 데이터가 날아가니까요. 하지만 플러그인이나 확장 프로그램을 만들어서 서버에 업로드하고 원하는 기능을 구현할 수 있어요. 제가 개발자로서 워드프레스를 좋아하는 이유가 바로 이 점이에요. 노코드 방식도 가능하고, 코드를 전부 사용해서 완전히 맞춤형으로 개발할 수도 있으니까요. 특히 소규모 사업체들은 기성 플러그인을 최소한의 설정으로 사용하는 경향이 있는데, 플러그인 중독은 정말 심각해요. 웹사이트에 플러그인을 수백 개씩 설치하다 보면 문제가 생길 수도 있거든요. 플러그인 간의 호환성 문제, 즉 하나를 설치하면 다른 하나가 작동하지 않게 되는 문제, 워드프레스 버전과의 호환성 문제 등이 있습니다. 필요한 플러그인만 설치하는 것이 좋지만, 수천 개의 플러그인이 존재하기 때문에 쉽지 않습니다. 특히 검색 플러그인의 경우, 워드프레스 내에서만 작동하는 플러그인, 즉 워드프레스 기능을 확장하지만 워드프레스 내에서만 작동하고 특정 기능을 판매하지 않는 플러그인이 있습니다. 예 를 들어, MySQL을 검색 엔진으로 계속 사용하는 플러그인도 있고, 마이너(Minimum)와 같은 외부 솔루션을 사용하는 플러그인도 있습니다. 이러한 외부 솔루션은 자체적으로 호스팅되거나 SAS 서비스에 호스팅될 수도 있습니다. 제가 처음 워드프레스 플러그인을 봤을 때는 PHP와 같은 언어를 사용하여 Weviate 와 워드프레스를 연결하는 방식이었는데, 이는 일종의 한계였습니다. 오늘날 AI 시장은 피자 닉(Pizza Nick)처럼 빠르게 성장하고 있으며, 모든 것이 파이썬으로 이루어지고 있습니다. 이것이 제가 2년 전 시장과 기능, 성능 등을 평가하기 시작했을 때 파이썬을 선택한 이유 중 하나일 것입니다. 만약 벡터 데이터베이스 에 벡터화 도구가 내장되어 있지 않다면, WordPress WooCommerce에 있는 데이터를 기반으로 직접 벡터를 생성해야 합니다. 즉, 제목, 설명, 가격, 색상, 크기 등의 속성을 WooCommerce에 전송하여 벡터를 생성하고, 생성된 벡터를 다시 벡터 데이터베이스에 저장해야 합니다. 벡터화는 거의 100% Python 클라이언트를 통해 이루어지는데, WordPress에서 Python을 사용하는 것은 사실상 불가능하다고 생각합니다. 따라서 두 가지 해결책이 있습니다. 하나는 PHP 클라이언트를 사용하는 것이지만 위젯에는 존재하지 않습니다. 다른 하나는 개발자가 될 수 있는 경우 직접 개발하는 것입니다. WordPress는 두 가지 API를 제공하는데, 하나는 위젯 관리, 데이터 업로드, 벡터화 등 모든 기능을 수행하는 REST API이고, 다른 하나는 검색, 필터링, 집계 등을 위한 GraphQL API입니다. 이 또한 일종의 REST API입니다. 따라서 저는 자체 PHP 클라이언트를 개발해야 했습니다. WordPress가 Viet의 REST API를 호출하는 것은 깔끔한 PHP 클라이언트가 아니기 때문에 오픈 소스로 개발될 수 있습니다. 왜냐하면 제대로 된 PHP 클라이언트를 만들고 유지 관리하는 책임을 지는 것이 매우 어렵기 때문입니다. 일종의 PHP 클라이언트의 축소판이라고 할 수 있겠죠. 음, 그 주제는 항상 저를 매료시켜 왔습니다. 다양한 클라이언트들이 있는데, 최근 팟캐스트에서 Andre라는 분이 Lang Chain Ruby를 개발하고 있었습니다. Ruby에 특화된 도구들을 만드는 거죠. 예를 들어, Microsoft Symantec 커널과 통합할 때 C#이나 TypeScript용으로 개발했던 것처럼요. [웃음] 파이썬스러운 API 인터페이스를 유지하면서도, Rust처럼 더 빠른 언어로 백그라운드에서 작동하는 도구를 사용하는 것은 큰 주제입니다. REST API 같은 도구가 그런 역할을 한다고 생각합니다. 그리고 다국어 지원은 큰 주제인데, 보통 오픈 소스 클라이언트 빌더를 사용해서 구현합니다. API, YAML 파일 등등... 하지만 제가 아는 한 현재 Viviet은 파이썬 기반입니다. 그래서 크게 문제될 건 없어요. 사실 REST API를 구현할 필요가 없다면 몇 가지 기능에만 집중하면 충분합니다. 사실 PHP는 요즘 대부분 WordPress나 Drupal CMS에서 사용되고, Symphony나 Laravel처럼 PHP로 풀스택을 개발하는 대기업 프로젝트는 예외입니다. 아마 미래에는 PHP 클라이언트가 줄어들 것 같아요. 지금보다 많이 늘어나지는 않을 것 같습니다. 그런데 V8을 어떻게 활용하시는지, 좀 더 심도 있는 주제로 넘어가기 전에 기술적인 질문 하나 드릴게요. Weavier 같은 추론 컨테이너나 클립의 텍스트 등을 어떻게 관리하시는지 궁금합니다. 저 두 가지 서비스, 그러니까 데이터베이스랑 추론 컨테이너 말인데요, 중요한 건 제가 아직 제대로 이해하지 못했다는 거예요. 위젯에는 스테이트 리스와 스테이트풀 부분이 있는데, 스테이트풀은 제 수준에서는 그냥 블랙박스처럼 단순하고, 어떻게 작동하는지도 잘 모르겠어요. 벡터 저장 알고리즘 같은 거 말이죠. 음, 예를 들어 지금 워드프레스 관리자 페이지에서 검색 엔진 유형이나 위젯을 선택했다고 가정해 볼게요. 그러면 몇 가지 선택지가 나오는데, 벡터라이저 드롭다운 목록이 있어요. 모두 선택할 수 있는데, 현재는 모든 벡터라이저를 사용할 수 있는 것 같아요. 전부 다 가능한 건 아니지만, 나중에 자세히 얘기해 볼게요. 저는 지금 이미지 유사도 분석은 안 하고, 텍스트- 이미지 변환만 해요. 이미지-텍스트 변환이나 이미지-이미지 변환은 안 하죠. 그래서 텍스트-텍스트 변환, 클립, 오픈 AI, 코레아, 그리고 구글 펜까지 있다고 가정해 볼게요. 플러그인의 PHP 코드는 실제로 REST API를 호출하여 위젯에 새 클래스를 생성합니다. 이 클래스는 MySQL의 테이블과 유사하며, 클래스 생성 시 전달되는 매개변수에는 기본 필드 유형, 벡터라이저, 그리고 선택한 벡터라이저에 따라 달라지는 몇 가지 추가 매개변수가 있습니다. 예를 들어, 클립 벡터라이저를 선택하면 텍스트 또는 이미지 검색 비율과 같은 설정을 지정해야 합니다. 하이브리드 벡터라이저를 선택하면(하이브리드는 GraphQL 기반인데, 이는 또 다른 문제입니다) 매개변수가 달라집니다. Docker 파일을 다운로드하고 필요에 따라 수정한 다음 실행하면 됩니다. 완벽하지는 않지만, 사실상 더 이상 진행할 방법이 없습니다. 올바른 벡터라이저를 사용하여 올바른 Docker를 실행한 다음 WP Sera에서 동일한 벡터를 선택하면 클래스 정의에서 모든 작업이 자동으로 수행됩니다. Kubernetes는 정말 좋습니다. 우선, 저는 클라우드 전문가가 아니라는 점을 말씀드리고 싶습니다. 저는 이 분야에 종사하면서 이러한 것들을 조금은 알고 있습니다. 다행히 오늘 Patrice가 함께해 주셔서 감사합니다. 제가 초창기에 컨설팅을 했을 때 웹사이트가 하나 있었던 기억이 납니다. GoDaddy에서 호스팅하고 있어서 Stripe 결제 정보를 웹사이트의 JavaScript에 바로 연결했어요.
