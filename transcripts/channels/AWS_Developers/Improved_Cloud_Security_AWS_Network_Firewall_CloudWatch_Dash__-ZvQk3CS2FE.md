## 스크립트

안녕하세요, AWS 네트워크 방화벽 CloudWatch 대시보드 데모에 오신 것을 환영합니다. 이 대시보드는 AWS 클라우드 환경에서 가시성과 보안을 강화하도록 설계된 포괄적인 도구입니다. 강력한 기능을 제공하는 이 대시보드는 다양한 CloudWatch 기능을 통합하여 방화벽 운영 및 보안 상태에 대한 실시간 정보를 제공합니다. 시작하기 전에, 이 영상이 유용했다면 좋아요 버튼을 눌러주시고, 클라우드 인프라 보안 관련 콘텐츠를 더 보시려면 채널을 구독해주세요. 오늘은 AWS 네트워크 방화벽 CloudWatch 대시보드 설정 과정을 안내하고, 트래픽 추적, 잠재적 위협 식별, 규정 준수 보장 등 네트워크를 사전에 관리하고 보호하는 데 이 대시보드를 사용하는 방법을 보여드리겠습니다. 이 대시 보드는 AWS 네트워크 방화벽 모니터링과 관련된 모든 것을 위한 중앙 허브 역할을 합니다. 대시 보드 설정을 위해 CloudFormation 템플릿을 사용하겠습니다. 템플릿 링크는 이 영상 아래에서 찾으실 수 있습니다. CloudFormation 템플릿은 VPC 내에 활성 AWS 네트워크 방화벽이 배포되어 있고, 방화벽이 흐름 및 경고 로그를 특정 CloudWatch 로그 그룹에 게시하도록 구성되어 있다고 가정합니다. AWS 네트워크 방화벽이 아직 설정되어 있지 않다면 AWS 네트워크 방화벽 배포 아키텍처 템플릿 중 하나를 사용하여 시작할 수 있습니다. 아래 링크에서 관련 정보를 찾을 수 있습니다. 설정이 완료되면 방화벽의 흐름 및 경고 로그에 대한 CloudWatch 로그 그룹을 구성하고 방화벽을 통한 최적의 트래픽 라우팅을 위해 방화벽 정책을 미세 조정하세요. 이러한 사전 요구 사항을 충족하면 이제 AWS 네트워크 방화벽 CloudWatch 대시 보드를 활용하여 실시간 네트워크 모니터링 및 보안의 모든 기능을 사용할 준비가 되었습니다. 시작해 보겠습니다. 대시보드를 설정하는 CloudFormation 템플릿이 필요합니다. 이 템플릿은 GitHub 리포지토리에서 찾을 수 있으며, 이 비디오 아래에 링크가 있습니다. 리포지토리에서 파일을 다운로드하세요. 이 파일은 CloudFormation이 대시보드를 구축하는 데 사용할 청사진입니다. 이제 AWS 콘솔로 이동해 보겠습니다. AWS 네트워크 방화벽이 배포된 동일한 리전에 있는지 확인하고 CloudFormation 서비스로 이동하여 스택 생성을 클릭합니다. 새 스택 설정을 시작하려면 새 리소스 표준을 선택합니다. 템플릿 준비에서 템플릿 소스로 템플릿 준비됨이 선택되어 있는지 확인합니다. 파일을 업로드할 것입니다. 파일 선택을 클릭하고 GitHub에서 다운로드한 파일을 업로드합니다. 다음 화면에서 스택 이름에 대한 몇 가지 세부 정보를 입력해야 합니다. 스택 이름을 지정하세요. 방화벽 이름에는 '내 방화벽 대시보드'와 같이 설명적인 이름을 입력하세요. 방화벽 이름은 네트워크 방화벽 콘솔에서 확인할 수 있습니다. 다음으로 방화벽 엔드포인트가 있는 서브넷 ID를 입력합니다. 이제 방화벽 흐름 로그를 위한 CloudWatch 로그 그룹 이름을 입력해야 합니다. 마찬가지로 방화벽 경고 로그를 위한 로그 그룹 이름도 입력해야 합니다. 다음 옵션은 '기여자 인사이트' 규칙 상태입니다. '기여자 인사이트'를 사용하면 로그 데이터를 분석하고 시계열 시각화를 생성하여 네트워크 방화벽에 영향을 미치는 주요 기여 요소를 확인할 수 있습니다. ' 기여자 인사이트' 규칙을 활성화 또는 비활성화할 수 있습니다. 활성화하면 규칙이 로그 데이터를 스캔하고 ' 기여자 인사이트' 대시보드 위젯에 결과를 표시합니다. 이 옵션을 활성화하지 않으면 모든 규칙이 비활성화되므로 대시보드에 데이터가 표시되도록 하려면 어떤 규칙을 활성화할지 선택해야 합니다. 여기서는 모든 데이터 시각화를 대시보드에 표시하기 위해 활성화하겠습니다. 모든 매개변수를 입력했으면 CloudFormation 마법사를 진행하여 스택 생성을 시작합니다. 스택이 '생성 완료' 상태에 도달하면 화면이 나타납니다. 여기 출력 탭에서 방화벽 대시보드 URI를 찾을 수 있습니다. 이 링크를 클릭하면 새 CloudWatch 대시보드로 이동합니다. 위젯, 특히 로그 인사이트 및 기여자 인사이트에 의존하는 위젯이 데이터로 채워지는 데 몇 분 정도 걸릴 수 있습니다. 일치하는 로그 이벤트가 아직 없는 경우 일부 위젯은 즉시 데이터가 표시되지 않을 수 있습니다. 하지만 걱정하지 마세요. 방화벽이 트래픽 처리를 시작하면 대시 보드에 유용한 데이터가 표시될 것입니다. 이로써 AWS 네트워크 방화벽 CloudWatch 대시보드 배포가 시작되었습니다. 이제 대시보드의 위젯에 데이터가 채워졌으므로 이러한 위젯이 네트워크 및 보안에 대해 어떤 정보를 제공하는지 살펴보겠습니다. 보시다시피 이 대시보드는 AWS 네트워크 방화벽의 작동 현황을 포괄적으로 보여주는 풍부한 정보를 제공합니다. 먼저 방화벽 엔드포인트 및 방화벽 엔진 섹션을 살펴보겠습니다. 방화벽 엔드포인트 섹션에서는 방화벽 엔드포인트 사용률, 연결 메트릭 및 처리된 트래픽에 대한 메트릭 기반 데이터를 볼 수 있습니다. 방화벽 엔진 섹션으로 이동하면 스테이트리스 및 스테이트풀 엔진의 패킷 검사에 대한 더 많은 메트릭 기반 데이터를 볼 수 있습니다. 여기서는 과거 패킷 수와 드롭된 패킷 수를 빠르게 확인할 수 있습니다. 또한 방화벽 정책 스트림 예외 설정은 네트워크 연결이 중간에 끊어졌을 때 네트워크 방화벽이 트래픽을 처리하는 방식을 결정합니다. 대시보드에서는 정책이 적용된 패킷에 대한 몇 가지 지표를 볼 수 있습니다. 아래로 조금 스크롤하면 상위 트래픽 발생원 및 상위 프로토콜 섹션이 나오는데, 여기서는 좀 더 흥미로운 정보를 확인할 수 있습니다. 대시보드는 Surot에서 검사한 상위 트래픽 흐름을 보여줍니다. 실제로 이 두 섹션은 일반적으로 NMS에서 볼 수 있는 내용입니다. 예를 들어 바이트 단위로 표시되는 상위 소스 및 대상 IP는 두 IP 주소 쌍 간의 처리량을 보여줍니다. 특정 IP 주소 쌍을 클릭하면 해당 IP 주소 쌍의 패킷 수도 확인할 수 있습니다. 그 바로 아래에는 바이트 단위로 표시되는 상위 TCP 흐름이 있어 특정 레이어 4 연결을 집중적으로 분석할 수 있습니다. 대시보드를 더 아래로 스크롤하면 경고 로그 분석 섹션이 나오는데, 여기에는 규칙 활동과 SyraCotta에서 적용한 조치가 요약되어 있습니다. 예를 들어 드롭 거부 규칙이 가장 많이 적용된 상위 패킷, 차단된 소스 IP, 차단된 TCP 흐름 등이 표시됩니다. 웹 프로토콜이 널리 사용됨에 따라 HTTP 및 TLS 섹션에서는 레이어 7 세부 정보도 확인할 수 있습니다. 예를 들어, 경고 로그 이벤트에서 이 섹션을 검토하여 어떤 도메인이 차단되거나 경고되는지 더 잘 이해할 수 있습니다. 그런 다음 이 정보를 사용하여 도메인 목록 규칙 그룹을 구현하거나 사용자 지정 COTA 규칙을 구성할 수 있습니다. 자, 이제 AWS 네트워크 방화벽 CloudWatch 대시보드에 데이터를 성공적으로 채우고 다양한 위젯을 살펴보았습니다. 이를 통해 네트워크 보안 및 성능에 대한 중요한 통찰력을 얻을 수 있습니다. 이 대시보드는 AWS 네트워크 방화벽을 모니터링하는 데 매우 유용한 도구이며, 보안 위협과 네트워크 효율성을 파악하는 데 도움이 됩니다. 이제 여러분도 이 강력한 모니터링 기능을 환경에 도입할 차례입니다. 아래 링크된 GitHub 저장소에서 CloudFormation 템플릿을 다운로드하고 AWS 설정에 이 대시보드를 배포하세요. 이번 데모에 참여해 주셔서 감사합니다. 질문이 있거나 AWS 네트워크 방화벽 CloudWatch 대시보드 사용 경험을 공유하고 싶으시면 아래에 댓글을 남겨주세요. 더 많은 데모와 AWS 서비스에 대한 심층 분석을 위해 좋아요, 공유, 구독 부탁드립니다. 항상 안전하고 유익한 정보를 얻으시길 바라며, 다음 시간에 뵙겠습니다. 즐거운
