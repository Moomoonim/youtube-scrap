## 스크립트

안녕하세요 여러분, 유튜브 채널 Weave It을 시청해 주셔서 정말 감사합니다. 오늘은 SQL Palm의 향상된 대규모 언어 모델 적응(텍스트, TestQL용)에 대해 자세히 알아보겠습니다. 본론으로 들어가기 전에 이 논문을 살펴볼 만한 세 가지 이유를 말씀드리겠습니다. 첫째, 이 논문은 데이터베이스 사용의 진입 장벽을 크게 낮출 수 있습니다. 예를 들어 SQL 구문을 배우는 대신 "컨트리 음악 가수의 평균 나이는 몇 살일까요?"와 같은 자연어 질문을 작성할 수 있게 되므로 더 많은 사람들이 데이터베이스에 접근할 수 있게 됩니다. 여기서 "사람들"이란 대규모 언어 모델을 포함한 이러한 도구의 활용을 의미합니다. 둘째, 이 논문은 대규모 언어 모델의 제로샷 및 퓨샷 학습 능력을 더 깊이 이해할 수 있도록 해줍니다. 연구진은 퓨샷으로 학습된 Palm 대규모 언어 모델을 Spider 텍스트 SQL 데이터셋 에서 미세 조정된 모델들과 비교했습니다. 그 결과, 이 모델이 지도 학습 으로 훈련된 기존 모델들을 즉시 능가하는 성능을 보였습니다. 셋째, 특히 딥러닝 연구에 관심이 있다면 이 Spider 데이터셋이 매우 유용할 것입니다. 학습을 위해 166개의 서로 다른 데이터베이스 테이블에서 000개의 쿼리를 실행하고, 테스트를 위해 22개의 데이터베이스에서 000개의 쿼리를 실행했습니다. 텍스트 SQL 성능을 측정하는 데 매우 흥미로운 데이터 세트입니다. 또한 스파이더, 동의어 대체, 스파이더 현실적, 스파이더 도메인 지식의 세 가지 변형을 사용하여 모델이 SQL 쿼리를 얼마나 잘 작성할 수 있는지 벤치마킹합니다. 이는 Wevia에게 매우 흥미로운 부분입니다. Weave에는 집계 API가 내장되어 있어 Weave를 사용해서도 이러한 유형의 쿼리를 실행할 수 있습니다. 저는 Wevia의 집계 구문을 사용하여 몇 가지 간단한 프롬프트를 테스트해 보았습니다. 이 영상에서는 이러한 부분과 기타 여러 가지 흥미로운 세부 사항을 자세히 살펴보겠습니다. 시청해 주셔서 감사합니다. 이 논문 요약 영상이 도움이 되셨기를 바랍니다. 이 영상에서는 텍스트를 SQL로 변환하는 매우 흥미로운 최신 논문인 SQL Palm Improved Large Language Model Adaptation for Text to SQL에 대해 간략하게 설명하겠습니다. 논문에 들어가기 전에, 이와 같은 논문 요약 영상이 마음에 드셨다면 좋아요와 구독 부탁드립니다. 여러분의 응원은 더 많은 콘텐츠를 제작하는 데 큰 힘이 됩니다. 그럼 2분 요약부터 시작해 보겠습니다. 텍스트를 SQL로 변환하는 작업은 자연어 질문을 SQL 구조화 쿼리 언어 질문 또는 구문으로 변환하는 것입니다. 예를 들어 " 가장 어린 가수의 모든 노래 제목과 발매 연도는 무엇입니까?"와 같은 질문이 있다고 가정해 보겠습니다. 그러면 해당 질문을 테이블의 속성을 기반으로 SQL 쿼리로 변환합니다. 즉, "select song name song release year from table singer"와 같이 변환하고, 결과를 나이 순으로 오름차순 정렬하고, 가장 어린 가수에 대한 결과만 하나만 표시하도록 제한합니다. 이것이 바로 데이터베이스에 매우 자연스러운 방식으로 질문할 수 있도록 하는 고수준 아이디어입니다. 내부적으로는 대규모 언어 모델이 자연어 질문을 구조화 쿼리 언어로 변환합니다. 이 논문의 핵심 연구 중 하나는 Palm 모델의 성능을 몇 번의 시도만으로 비교하는 것입니다. Palm은 5천억 개의 매개변수 없이 학습된 거대한 사전 학습된 대규모 언어 모델 중 하나입니다. 따라서 몇 번의 시도만으로 Palm 모델의 성능을 스파이더 데이터셋에서 미세 조정했을 때와 비교하고, 기존의 미세 조정 및 배포된 다양한 학습 기법을 적용한 최첨단 모델들과 비교할 것입니다. 텍스트 SQL 변환 작업을 매우 빠르게 수행하기 위한 추론 기법은 다음과 같습니다. 입력에 몇 개의 예시를 제공하는 방식입니다. 데이터베이스 스키마 예시와 자연어 질문 예시, 그리고 해당 SQL 변환 예시를 제공합니다. 이 다이어그램에서는 입력에 두 가지 예시만 나와 있는데, 이것이 질문 중 하나입니다. 몇 개의 예시를 제공하는 방식은 예시의 개수를 정하고, 이러한 예시들을 후속 추론에 더 적합하게 조정해야 하는지 여부를 결정하는 데 사용됩니다. 이렇게 하면 세 번째 예시와 세 번째 예시를 기반으로 새로운 추론 스키마가 생성되고, 새로운 SQL 변환이 만들어집니다. 몇 개의 예시를 제공하는 방식은 입력 창에 작업에 대한 참조를 제공하고 학습할 수 있도록 합니다. 이는 대규모 언어 모델이 기존의 추론 방식( 새로운 입력만 제공받고 바로 출력을 생성하는 방식)과 비교했을 때 보여주는 매우 흥미로운 새로운 기능 중 하나입니다. A는 몇 개의 예시를 제공하는 방식을 살펴보고, B는 텍스트 SQL 변환 데이터셋인 스파이더 데이터셋에서 Palm을 미세 조정하는 방식을 살펴봅니다. 이렇게 하면 단일 추론, 단일 출력이라는 설정을 확인할 수 있습니다. 스키마를 제공할 때 어떤 모습일지 간단히 추가 살펴보겠습니다. 이런 식으로 표현을 압축하여 텍스트로 변환해 모델에 입력하는 방식입니다. 예를 들어 ' singer'라는 테이블을 굵게 표시하고, 그 테이블에 가수 ID, 이름, 국가, 노래 제목 등의 키가 있다고 가정해 보겠습니다. 흥미롭게도 외래 키가 있다고 하셨는데, 콘서트 데이터를 볼 때 콘서트 ID와 경기장, 콘서트에 속한 가수를 조인해야 하는 경우를 생각해 보세요. 이처럼 이 기능을 확장할 수 있는 다양한 아이디어가 있습니다. 또한, 이것은 데이터 저장 방식의 최적화가 아닌 표면적인 SQL 인터페이스에 관한 것이며, 자연어로 이러한 인터페이스를 제공하는 것입니다. 즉, 이러한 질문을 받아들이고 테이블 정보를 입력으로 제공하면 SQL로 변환하는 방식입니다. 이 논문에서 또 하나 흥미로운 점은 이 스파이더를 평가하는 데 사용된 데이터 세트가 약 7,000개의 학습 쿼리와 166개의 데이터베이스 스키마에 걸쳐 있는 1,000개의 테스트 쿼리, 그리고 22개의 테스트 스키마로 구성되어 있다는 것입니다. 이러한 스파이더 데이터 세트의 변형은 텍스트를 SQL로 변환하는 연구 커뮤니티에서 반복적으로 학습하고 발전시켜 온 것입니다. 스파이더의 동의어 기능은 자연어 질문을 동의어로 대체하여 수동으로 수정하는 것입니다. 예를 들어 " 가수가 몇 명입니까?"와 같이 데이터베이스 스키마와 직접적으로 일치하는 "가수는 두 명 정도"와 같은 질문 대신 " 보컬리스트는 몇 명입니까?"와 같이 질문하는 것입니다. 이러한 아이디어는 자연어 질문이 데이터베이스 스키마와 밀접하게 연관되지 않은 형태로 변할 때 모델의 성능이 얼마나 안정적인지 테스트하기 위한 것입니다. 스파이더는 열 이름을 언급하지 않도록 하여 " 2014년 또는 2015년에 콘서트가 몇 개 있었습니까?"와 같은 질문을 " 2014년 또는 2015년에 콘서트가 몇 개 있었습니까?"와 같이 더 자연스럽게 만듭니다. 스파이더의 도메인 지식 기능은 도메인 지식을 추가하는 것입니다. 예를 들어 평균 연령 이상의 가수가 부른 모든 노래 제목을 나열하는 것과 같이, 생일 열만으로는 답하기 어려운 나이 관련 질문에 답할 수 있도록 테이블에서 생일을 추출하는 것입니다. SQL Palm 실험의 세부 사항으로 넘어가기 전에, Weviate의 집계 API를 사용하여 이러한 기호 집계 쿼리를 직접 수행할 수 있다는 점을 빠르게 알려드리고 싶습니다. Weviate에서 ' singer' 클래스가 있다고 가정해 보겠습니다. 이 클래스에는 Joe Sham과 같은 텍스트 속성, age와 같은 문자열 속성, Ismail과 같은 부울 속성이 있습니다. Weviate의 집계 구문을 사용하면 이러한 기호 집계에 접근할 수 있습니다. 예를 들어 데이터 세트에서 가장 많이 나타나는 가수를 확인하려면 name과 top occurrences를 사용하면 됩니다. 평균 연령을 확인하려면 age를 사용하면 되고, 부울 값인 total(참/거짓)도 확인할 수 있습니다. 또한 가수와 공연 아티스트를 조인하려면 performed in concert와 같이 사용하면 됩니다. 콘서트 클래스에 속하게 되었으니 이제 이런 구문을 계속 사용할 수 있습니다. 이것이 WeGate에서 이 작업을 수행하는 방법입니다. 이제 WeAveate에서도 이와 같은 방식이 어떻게 작동하는지 몇 가지 예시를 통해 살펴보겠습니다. WeAveate는 메타 데이터의 심볼릭 조인 쿼리 및 집계를 수행할 수 있다는 점에서 매우 흥미롭습니다. WeAveate와 관련된 또 다른 매우 흥미로운 연결점이 있는데, 이 비디오의 마지막 부분에서 핵심 내용을 다루면서 자세히 살펴보겠습니다.
