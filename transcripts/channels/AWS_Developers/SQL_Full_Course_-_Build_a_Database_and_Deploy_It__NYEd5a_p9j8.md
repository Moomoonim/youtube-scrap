SQL 연결이 성공적으로 이루어졌습니다. 이제 ' 확인'을 선택하신 다음, 방금 연결하신 새로운 연결을 선택하세요 . 계속 진행하세요. 그리고 이제 정말 좋은 점은, 만약 제가 새로운 데이터베이스를 만들고 싶다면, 여기서 바로 만들 수 있고 이전에 했던 것과 동일한 쿼리를 실행할 수 있다는 것입니다 . 그러니까, 만약 제가 이 SQL 쿼리를 실행해서 ' my app'이라는 데이터베이스 테이블을 생성한다면 , 즉 'my app'이라는 데이터베이스를 생성하고 실행한다면 말이죠. 이제 이 데이터베이스는 로컬 컴퓨터가 아닌 Amazon RDS에 생성됩니다 . 그리고 실제로 이 데모에서 실행했던 모든 SQL 쿼리를 실행해 볼 수 있는데, 모든 데이터는 로컬 컴퓨터가 아닌 클라우드의 실제 데이터베이스에 저장됩니다. 자, 이제 아시겠죠? 이렇게 연결하면 됩니다. 자, 이제 다 됐습니다 . 이것이 바로 클라우드 데이터베이스에 연결하는 방법입니다. 자, 마지막으로 한 가지 더 말씀드릴 게 있습니다. 이 영상에서 보여드린 SQL 쿼리를 실행해 보시면 모든 데이터가 Amazon RDS 데이터베이스에 저장되지만, 사용이 끝나면 모든 리소스를 정리하는 것이 매우 중요합니다. 자, 그럼 콘솔로 돌아가서 데이터베이스를 선택 하고 방금 생성한 데이터베이스를 선택하겠습니다 . 작업에서 삭제를 선택하고, 최종 스냅샷 및 자동 백업 유지 옵션을 해제한 다음, " 삭제"를 입력하여 삭제를 확인하고 삭제를 선택합니다 . 자, 이제 아시겠죠? 이것으로 데모가 끝났습니다. RDS는 특정 데이터베이스 엔진에 종속되지 않습니다. 이 소프트웨어는 MySQL, PostgreSQL, MariaDB, Oracle, SQL Server 및 Amazon 자체의 Aurora를 지원합니다. 오늘 우리가 MySQL로 구축한 모든 것은 RDS를 통해 이러한 모든 서버에서 실행할 수 있습니다. SQL 개념은 동일하지만 내부 엔진은 다릅니다. 가지고 있는 스택에 맞는 것을 고르세요. 하하, 이제 시야를 넓혀볼까요? 이 영상을 시작할 때 당신은 데이터베이스가 무엇인지 몰랐을 겁니다 . 이제 데이터베이스를 기반으로 테이블을 설계하고, 데이터를 정규화하고, 일대일, 일대다 , 다대다 관계에 걸쳐 조인을 작성하고, 프로필이나 선호도와 같은 실제 기능을 구축할 수 있습니다 . 그리고 아마존 RDS를 사용해서 모든 걸 실제 운영 환경에 배포하는 방법도 알고 계시죠. 우리가 다룬 모든 내용은 관계형 데이터베이스, 테이블, 행, 외래 키, SQL에 관한 것이었습니다. 하지만, 그런 개념들을 완전히 무시하는 또 다른 데이터베이스의 세계가 존재합니다 . 테이블도 없고, 행도 없고, SQL도 없습니다. 이러한 데이터베이스는 비관계형 데이터베이스 또는 SQL을 사용하지 않는 데이터베이스라고 하며, 완전히 다른 문제를 해결합니다. 좋아요를 위해 만들었던 연결 테이블 기억나세요? 관계를 데이터 구조로 사용하는 데이터베이스, 즉 그래프 데이터베이스가 있습니다. 연결 테이블이 필요하지 않습니다. 연결 기능은 이미 내장되어 있습니다. 관계형, 비관계형, 그래프 데이터베이스가 있는데, 나머지 두 가지는 나중에 다루도록 하겠습니다. 이 글이 관계형 데이터베이스를 이해하는 데 도움이 되었다면 좋아요를 눌러주세요. 좋아요는 더 많은 사람들이 이와 같은 콘텐츠를 찾는 데 도움이 됩니다. 감사합니다.
