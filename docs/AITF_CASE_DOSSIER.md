아래 21건은 모두 원문 대조를 마쳤고, 인용문은 자막 전문에서 그대로 옮긴 것이다.

## 읽는 법

- **점수 표기**: `자동화 10 (L2/S1/I4/F3)` = 자동화 축 총점 10/16, 하위항목 Level 2 · Scope 1 · Impact 4 · Future 3.
  논문 Table 1의 4개 하위항목(수준·범위·영향·전략)에 대응한다.
- **셀**: 세 축의 low/high 조합(코퍼스 상대 절단점 기준: 자동화 ≥5, 증강 ≥3, 데이터 ≥4).
  논문 절단점(≥9)을 쓰면 대부분 low가 되므로, 셀은 **담론의 상대적 강조점**으로 읽어야 한다.
- **발화 주체**가 사례 신뢰도를 좌우한다. 세 층위를 구분해 표기한다.
  - `도입기업 자기서술` — 도입한 조직의 임원이 직접 말함 (가장 강한 사례)
  - `벤더 매개` — 공급업체 채널에 도입기업이 출연하거나, 공급업체가 고객 사례를 요약
  - `제3자 해설` — 미디어·학계·컨설팅이 외부에서 관찰
- 🔴 **자막 번역 주의**: 영어 원본 영상 상당수가 유튜브 자동번역(ko) 상태다. 아래 한국어 인용문은
  **번역문**이므로, 논문에 직접인용(따옴표+페이지)으로 쓸 때는 원본 음성/영어 자막을 다시 확인해야 한다.
  영어 그대로 인용한 건(SAP)은 원문이 영어다.

## 사례 5. H&M — 고객서비스 자동화가 매출 지표로 번역된 사례

| 항목 | 내용 |
|---|---|
| 출처 | *Analythics Architecture: Promising AI Use Cases for the Enterprise in 2026*, DATAVERSITY 채널 |
| URL | https://www.youtube.com/watch?v=JhbsIutTwXM |
| 파일 | `transcripts/2026-08-03/Analythics_Architecture_Promising_AI_Use_Cases_for_the_Enter__JhbsIutTwXM.md` |
| 수집 | 키워드 검색(`enterprise AI ROI case study`), 2026-08-03 / 자막 ko(번역) / 6,611단어 |
| 발화 주체 | **제3자 해설** — 데이터 아키텍처 전문 미디어의 웨비나. H&M 관계자 발언이 아님 |
| 점수 | 자동화 9 (L3/S0/I4/F2) · 증강 7 (L2/S0/I3/F2) · 데이터 8 (L2/S0/I3/F3) |

**무엇을 했나**
- 대화형 AI 챗봇으로 고객 문의를 자동 처리·해결
- 단순 챗봇 → **통합 에이전트 전달 플랫폼/에이전트 허브**로 이행 (텍스트박스 대체)
- 과금이 좌석 라이선스 → **사용량 기반**으로 바뀌며 예산 구조 재검토 촉발

**원문 근거**
> "H&M은 고객 서비스를 제공하는데, 대화형 AI 챗봇을 활용하죠? 이 시스템은 대량의 고객 문의를 자동으로 처리하고
> 해결하여 **전환율을 25% 향상**시켜 직접적인 매출 증대를 가져옵니다."
> "운영적인 측면에서 볼 때, 이 기술은 값비싼 인적 개입을 대체하여 **고객 문의의 70%를 자율적으로 해결**하는 동시에
> 응답 속도와 해결 시간을 **3배** 더 빠르게 만들어줍니다."
> "기업들은 자동화된 에이전트가 일상적인 문의에 대해 **토큰을 과도하게 할당하는 것을 방지**하는 방법을 알아내는 데 한 해를 보냈습니다."

**프레임워크 해석**
- 자동화(문의 70% 자율해결)와 증강(에이전트 허브가 상담 흐름을 보조), 데이터(대화 로그·인텐트)가 동시에 언급되는
  드문 문서라 H-H-H로 떨어졌다. Impact 항목이 세 축 모두 3~4점이라는 점이 특징이다.
- 다만 Scope는 세 축 모두 0 — **전사 확산 서술이 없다**. 논문 기준으로는 "한 기능(고객서비스)에서만 high"인 셈으로,
  integrated intelligence의 조건인 조직 전반 통합과는 구분해서 써야 한다.

**인용 시 주의**: H&M 자체 발표가 아니라 제3자 요약이다. 25%·70%·3배 수치의 원출처가 영상에 명시되지 않는다.
논문에 쓴다면 "업계 해설에서 인용되는 수치"로 한정하거나, H&M IR 자료로 교차 확인해야 한다.

# 전반 인용 주의사항

1. **자막 번역 문제.** 사례 1~5·7·10·12·14·16·18·20은 영어 원본의 유튜브 자동번역이다. 위 인용문은 번역문이므로,
   직접인용에는 원본 확인이 필요하다. 원문 언어 표기는 각 사례의 "자막" 항목에 명시했다.
2. **자막 오인식.** 한국어 원문 영상도 고유명사가 자주 깨진다(예: "채치비T"=ChatGPT, "LM 스위트"=LLM Suite,
   "카스텐 에드가루스"=Carsten Egeriis 추정). 인명·제품명은 원본 확인 없이 쓰지 말 것.
3. **수치의 성격.** 모든 수치는 **발화자의 주장**이며 감사·검증된 값이 아니다. 투자자 대상 발표(사례 1·2)는
   공시 규율이 걸리므로 상대적으로 신뢰도가 높고, 벤더 고객증언(사례 4)과 제3자 요약(사례 5·15)은 낮다.
4. **채널 ≠ 발화 주체.** 사례 7(Danske Bank/Infosys 채널), 사례 9(Accenture CTO/Intel 채널), 사례 10(PMI/Intel 채널), 사례 3(NEC/SAP 채널),
   사례 14(고객사/Palantir 채널)처럼 **채널 소유자와 발화 조직이 다른 경우**가 많다. 자동 생성 목록은
   채널명으로 표기하므로 반드시 원문에서 발화자를 확인해야 한다.
5. **점수는 담론 강조도**다. 사례 14(Palantir)처럼 도메인 특수 어휘(유지보수 티켓·보증상태)를 규칙 기반 사전이
   놓쳐 데이터 축이 과소평가되는 경우가 있다. 점수는 사례 선별의 도구이지 사례의 평가가 아니다.
