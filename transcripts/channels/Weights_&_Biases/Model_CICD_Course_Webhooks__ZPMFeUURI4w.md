안녕하세요. 다음 섹션에서는 웹훅에 대해 이야기해 보겠습니다. 웹훅의 기본 개념 과 작동 원리를 이해하고 직관적으로 파악할 수 있도록 처음부터 웹훅을 직접 만들어 보겠습니다. 웹훅은 소프트웨어 엔지니어링에서 매우 중요한 요소이며, 구글에서 ' 웹훅'을 검색하면 다양한 관련 자료를 찾아볼 수 있습니다. 특히, 많은 개발 도구에서 웹훅이 사용되는 것을 볼 수 있습니다. GitHub, Zapier, Twio, Stripe, Srid 등에서 웹훅을 통합하는 방법을 확인할 수 있습니다. 웹훅은 다양한 개발 도구와 인프라에서 흔히 사용되는 메커니즘입니다. 즉, 여러 인프라 제공업체가 서로 통신하는 데 사용하는 유연한 방식이며, Weights and Bias와 같은 도구와 다른 도구 간의 통신을 패키지화하는 데 유용합니다. 그렇다면 웹훅이란 무엇일까요? 구글에서 검색하거나 관련 내용을 읽어보면 다소 혼란스러울 수 있습니다. 예를 들어 위키피디아의 웹훅 페이지에서는 웹훅을 다음과 같이 정의합니다. 웹 개발에서 훅(Hook)은 웹 개발 방법 중 하나입니다. 기본적으로 웹 애플리케이션에서 사용자 지정 콜백을 사용하는 방식입니다. 콜백이 무엇인지 모르시더라도 괜찮습니다. 콜백은 나중에 실행될 함수 또는 코드 조각일 뿐입니다. 하지만 이 모든 용어가 웹 훅을 이해하는 데 필요한 것보다 더 복잡하게 느껴질 수 있습니다. 웹 훅을 이해하는 가장 좋은 방법은 직접 만들어 보는 것입니다. 파이썬을 사용하여 웹 훅을 만들 수 있습니다. 지금 바로 코드를 열어보겠습니다. 웹 훅은 두 가지 구성 요소로 이루어져 있습니다. 하나는 웹 훅을 수신하는 웹 서버이고, 다른 하나는 웹 훅을 보내는 클라이언트입니다. 이 저장소(WB modal web hook)에 코드가 있습니다. 제가 살펴볼 코드를 열어보겠습니다. 먼저 웹 훅 서버를 만들 것입니다. Fast API를 사용할 것입니다. Fast API는 웹 서버를 구축하는 데 매우 인기 있는 파이썬 라이브러리입니다. 기본적으로 Fast API를 사용하면 서버를 설정할 수 있습니다. 이 클래스는 데이터 클래스인데, Pantic 모델이라고 합니다. Pantic 에 익숙하지 않으신 분들을 위해 설명드리자면, 웹 서버가 클라이언트로부터 어떤 종류의 정보(예: 이벤트 유형, 이벤트 작성자, 별칭, 아티팩트 버전 등)를 수신할지 지정하는 데이터 클래스입니다. 제가 이 특정 유형 의 데이터를 만든 데에는 특별한 이유가 있습니다. 이것은 Weights and Bias가 웹 서버로 보내는 데이터의 모형입니다. 지금은 자세히 설명할 필요는 없지만, 솔직히 말해서 이 데이터가 무엇인지는 중요하지 않습니다. 이 데이터는 특정 웹 서버가 기대하는 데이터이며, 서버는 이 데이터가 특정 스키마에 맞는지 검증합니다. 밑줄(_)과 밑줄(_)은 정보가 출력되는 방식을 사용자 지정하는 데 사용됩니다. DunderStr에 대해 잘 모르시는 분들을 위해 설명드리자면, 이것은 파이썬에서 오버라이드할 수 있는 특별한 메서드로, 출력 방식을 제어할 수 있게 해줍니다. 이 경우에는 여러 변수를 특정한 방식으로 출력하고 있습니다. 마지막으로 웹 서버가 있습니다. 웹 서버는 여러 엔드포인트를 가지고 있는데, 여기가 루트 엔드포인트입니다. 이 루트 엔드포인트는 두 가지 다른 엔드포인트를 통해 이벤트를 수신합니다. 하나는 이러한 스키마를 가진 JSON 형식의 이벤트이고, 다른 하나는 토큰을 수신하는 것입니다. 토큰은 헤더에서 가져오는데, 잠시 후에 보여드리겠습니다. 토큰을 가져와서 무작위로 생성된 비밀 토큰인지 확인합니다. 참고로, 이것은 보안이 취약한 부분입니다. 이것은 단지 매우 기본적인 워크플로와 웹훅을 보여드리는 것입니다. 그리고 토큰이 올바르지 않으면 예외를 발생시키는 코드를 추가했습니다. 이 코드는 필수는 아니지만, 기본적인 작동 방식을 설명하기 위한 예시입니다. 토큰이 올바르면 웹 서버는 이 메시지를 반환하는 것이 전부입니다. 제대로 처리하는 방법은 이렇습니다. 그럼 콜백이란 무엇일까요? 콜백은 이벤트를 수신했을 때 실행되는 모든 함수를 말합니다. 이 경우에는 단순히 문자열을 반환하지만, 예를 들어 모델을 가져오는 함수와 같은 다른 함수가 있을 수도 있습니다. 예를 들어, 여기서 해당 함수를 실행할 수도 있습니다. 이것이 바로 콜백의 예시입니다. 웹 서버는 정보를 수신한 후, 그 정보를 검증하고 특정 코드를 실행합니다. 자세한 내용은 생략하겠습니다. 여러분을 혼란스럽게 하고 싶지 않기 때문입니다. 웹훅의 가장 기본적인 기능, 즉 무엇을 의미하는지 보여드리는 것이 목적입니다. 자, 이제 웹 애플리케이션을 시작해 보겠습니다. 터미널을 열고 화면을 확대하겠습니다. 화면이 약간 분할되어 있으니 잘 보이실 겁니다. 확대해 보겠습니다. 쭉 크게 만들어 볼게요. 여기도 정말 크게 만들어 볼게요. 이쪽도 마찬가지로 정말 크게 만들어 볼게요. 자, 그럼 먼저 웹 서버를 시작해 볼까요? 이 명령어를 입력할게요. 음, 잠시만요. 아, 됐네요. uorn은 웹 서버를 실행하는 도구이고, 이 파일 이름은 fast API server.py입니다. 그러니까 fastapi server.py인 거죠. 그리고 이건 앱이에요. 애플리케이션 이름이 app이라서 uorn fast API server app인 거예요. 이렇게 하면 웹 서버가 시작되고, 이쪽을 보면 웹 서버 로그가 표시돼요. 이제 웹 서버에 어떤 요청 같은 페이로드를 보내려고 하는데요. 그래서 이 파일에 curl 명령어를 입력하면 됩니다. sh는 기본적으로 최소한의 요청을 합니다. 우리가 할 수 있는 것은 다음과 같습니다. 어, 이 curl 명령어가 있습니다. 좀 더 확대해 보겠습니다. 이 curl 명령어는 다시 말해 en curl입니다. sh um에는 다음과 같은 헤더가 있습니다. 헤더에는 인증 헤더가 있는데, 이 be 단어를 여기에 넣어야 합니다. 그렇지 않으면 작동하지 않습니다. 그리고 콘텐츠 유형은 JSON으로 설정해야 합니다. EV에서 본 것과 정확히 같은 스키마를 보낼 것입니다. 기본 모델에는 이벤트 유형, 이벤트 작성자, 별칭, 아티팩트 버전 등이 있습니다. 보시다시피 이것이 우리가 보내는 정보이며, 예상하는 정보입니다. 여기서 토큰이 비밀 랜덤 토큰과 일치하는지 확인합니다. 실제로 일치합니다. 확인하는 부분입니다. 그리고 이 위의 내용은 신경 쓸 필요가 없습니다. 제가 달리 말하지 않는 한 로컬 호스트를 사용하라는 의미입니다. 다시 돌아가서 셸 스크립트를 실행하면 이벤트가 성공적으로 처리되었다는 메시지가 표시되고 다음과 같은 로그가 출력됩니다. 이러한 로그가 이렇게 출력되는 것은 특정 Dunder Str의 결과입니다. Str 정의는 이것이 출력되기 때문입니다. 여기 이쪽에 '출력 이벤트'라고 표시된 부분을 보세요. 이 출력 이벤트가 바로 이런 식으로 이벤트가 출력되는 원인입니다. 나중에 다시 설명하겠지만, 이 웹 서버를 실제 운영 환경에 배포하면 이런 로그를 확인하게 될 겁니다. 이 정보는 Weights and Bias에서 보내는 정보와 비슷한 유형입니다. 지금은 이해가 안 될 수도 있지만, 이 정보가 무엇을 의미하는지, 이벤트 유형은 무엇인지, 별칭은 무엇인지 등을 설명하면 더 쉽게 이해할 수 있을 겁니다. 웹 서버가 무엇인지 기본적인 개념을 알려드리고 싶었습니다. 직접 사용해 보면서 테스트해 보세요. 예를 들어, 이 부분을 빼고 요청을 보내면 어떻게 될까요?
