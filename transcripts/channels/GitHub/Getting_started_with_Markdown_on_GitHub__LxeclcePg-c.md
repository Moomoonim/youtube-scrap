## 스크립트

오늘은 마크다운을 시작하는 데 필요한 모든 것을 알려드리겠습니다 . [음악] 마크다운은 글쓰기 방식을 혁신적으로 바꿔줄 필수적인 기술입니다 . 이 비디오를 끝까지 시청하시면 훌륭한 README를 작성하고, 이슈와 풀 리퀘스트를 형식화하고, 다른 사람들이 프로젝트를 더 쉽게 탐색할 수 있도록 만드는 데 필요한 모든 필수 마크다운 개념을 이해하게 될 것입니다. 안녕하세요, [음악] 저는 카데샤이고 오늘 이렇게 함께해 주셔서 정말 기쁩니다. 오늘은 제 친구 에밀리가 함께 마크다운을 배우는 것이 왜 가치 있는지 , 특히 깃허브를 처음 시작하는 분들에게 왜 유용한지에 대해 이야기해 줄 거예요. 마크다운은 일반 텍스트 서식 지정을 위한 경량 언어입니다. GitHub에서는 저장소 README 파일이나 풀 리퀘스트 및 이슈에 대한 댓글 등에서 Markdown 구문과 몇 가지 추가 HTML 태그를 사용하여 글을 서식화할 수 있습니다. 마크다운을 사용하면 명확하고 읽기 쉬운 문서를 작성할 수 있습니다. 프로젝트에 깔끔한 README 파일이 있거나 잘 정리된 이슈가 있다면, 누군가가 처음 콘텐츠를 접했을 때 큰 차이를 만들어낼 수 있습니다 . 그리고 가장 좋은 점은, 일단 구문을 익히고 나면 거의 모든 프로젝트에서 사용하게 될 거라는 겁니다 . 마크다운을 가장 흔하게 접하게 되는 곳은 저장소의 README 파일이지만, 마크다운은 그보다 훨씬 더 다양한 용도로 활용될 수 있습니다. 이슈, 풀 리퀘스트, 토론, 심지어 위키에서도 마크다운을 사용하게 될 겁니다. GitHub에서 글을 쓰거나 소통할 때마다 Markdown이 백그라운드에서 작동하여 텍스트를 깔끔하고 일관성 있게 표시해 줍니다. 마크다운은 깃허브를 넘어 최신 메모 작성 앱, 블로그 플랫폼, 문서 작성 도구에까지 널리 사용되고 있습니다. 그럼, 여러분이 가장 많이 사용하게 될 마크다운의 핵심 기능들을 살펴보겠습니다. [음악] 텍스트 서식부터 시작해 봅시다. 먼저 헤더부터 살펴보겠습니다. 이것들은 여러분의 직책과 섹션 이름입니다. 텍스트 앞에 해시 기호(#)를 추가하면 생성됩니다. 메인 헤더용 하나, 서브 헤더용 두 개, 이런 식으로 계속됩니다. 텍스트를 강조하고 싶다면 별표 기호(*)를 사용하여 기울임꼴이나 굵은 글씨를 만들 수 있습니다. 별표 하나는 기울임체, 별표 두 개는 굵은 글씨, 별표 세 개는 기울임체와 굵은 글씨를 모두 나타냅니다. 문자열 내의 특정 문자 또는 한 줄 내의 여러 문자열을 강조 표시할 수 있습니다. 좋아하는 GitHub 콘텐츠 제작자의 글처럼 중요한 내용을 인용하고 싶을 때가 있을 수 있습니다. 이렇게 하려면 텍스트 줄의 첫 번째 문자로 '&gt;' 기호를 추가하세요. 여러 줄에 걸쳐 있는 내용을 인용하려면 각 줄의 시작 부분에 '&gt;' 기호를 추가해야 합니다. 자, 이제 좀 더 심화된 주제인 목록에 대해 이야기해 보겠습니다. 목록은 단계와 절차를 순서대로 또는 순서 없이 표현하는 일반적인 방법입니다. 정렬된 목록을 만들려면 목록의 각 요소에 1, 2, 3 등과 같이 번호를 매기고 각 번호 뒤에 마침표를 찍습니다. 이 내용은 읽기 쉽지만, 두 번째 항목과 세 번째 항목 사이에 요소를 추가하고 싶다면 어떻게 해야 할까요 ? 마크다운 인터프리터를 사용하면 항목을 임의의 숫자로 정렬할 수 있으며, 자동으로 첫 번째 항목부터 마지막 ​​항목까지 순서대로 정렬된 목록으로 해석합니다. 순서 없는 목록의 경우, 각 줄의 시작 부분에 하이픈(-), 별표(*), 또는 더하기 기호(+)를 붙이세요. 마크다운은 이러한 문자들을 모두 순서 없는 목록의 시작으로 렌더링합니다 . 순서 가 없는 목록이든 순서가 있는 목록이든 새로운 중첩 목록을 만들려면 네 칸 들여쓰기를 하여 새 들여쓰기 목록을 시작하세요. 목록 작성이 끝나면 엔터 키를 두 번 눌러 일반 텍스트로 돌아가세요. GitHub 문서에서 Markdown 서식 지정에 대한 요약 정보를 확인하세요 . 이 저장소를 방문하여 오늘부터 마크다운 기술을 연습해 볼 수도 있습니다 . [음악] 마크다운을 사용하여 GitHub 댓글이나 텍스트 파일에 목록, 이미지 및 링크를 추가하는 방법을 배웁니다 . gh.io/github-markdown에서 [음악] 자세히 알아보세요. 이제 마크다운을 사용하여 코드 조각을 포맷하는 방법을 살펴보겠습니다. 때때로 예제, 절차 단계 또는 프로젝트 설치 과정의 일부와 같이 코드 조각을 마크다운에 표시하고 싶을 수 있습니다. 많은 마크다운 인터프리터는 코드 조각을 서식 및 구문 강조 표시와 함께 렌더링합니다. 마크다운에서는 백틱(`) 문자로 코드를 감싸서 나타낼 수 있습니다 . 코드가 여러 줄에 걸쳐 있는 경우 백틱 문자 세 개를 사용하여 코드 블록을 만들 수 있습니다. 이 세 개의 백틱(```) 사이에 있는 모든 문자(공백 및 줄 바꿈 포함)는 코드로 렌더링됩니다. 마지막으로, 마크다운 파일을 더욱 보기 좋게 꾸미는 방법을 배워봅시다. 링크를 사용하면 사람들이 프로젝트 내의 유용한 자료, 문서 또는 다른 페이지로 이동할 수 있도록 안내할 수 있습니다 . 대괄호와 괄호를 사용하여 작성됩니다 . 표시하려는 텍스트를 대괄호 안에 넣고, 그 바로 뒤에 괄호 안에 URL을 넣으세요 . 이렇게 하면 글이 깔끔하고 읽기 쉬워집니다. 이미지도 거의 같은 방식으로 작동하지만, 한 가지 작은 차이점이 있습니다. 맨 앞에 느낌표를 추가하세요 . 이 기능은 README 파일에 스크린샷, 다이어그램 또는 프로젝트 로고를 추가하는 데 매우 유용합니다. 그리고 좋은 점은 GitHub에서는 이미지를 이슈나 풀 리퀘스트에 드래그 앤 드롭하기만 하면 자동으로 적절한 마크다운 코드가 생성된다는 것입니다. 그러므로 튜토리얼 링크를 걸 거나 스크린샷을 보여주려는 경우, 링크와 이미지는 마크다운 에 개성과 명확성을 더하는 데 도움이 됩니다 . 그게 다입니다. 이제 마크다운의 기본 사항, 즉 마크다운이 무엇 인지, 왜 중요한지, 어디에 사용할 수 있는지, 그리고 자신감을 가지고 마크다운을 작성하는 방법을 알게 되었습니다 . 에밀리, 마크다운을 효과적으로 사용하는 방법을 알려주셔서 정말 감사합니다. 몇 가지 간단한 기법만 사용하면 GitHub 프로젝트를 돋보이게 하는 깔끔하고 읽기 쉬운 문서를 만들 수 있습니다 . README 파일을 작성하든, 문제를 제기하든, 프로젝트 노트를 작성하든, 마크다운은 가장 많이 사용하게 될 도구 중 하나가 될 것입니다. 이 영상이 도움이 되었기를 바랍니다.
