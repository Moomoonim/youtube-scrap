## 스크립트

[음악] 감사합니다 [음악] 안녕하세요, 네이버 클라우드입니다. 오늘은 네이버 클라우드 플랫폼에서 제공하는 스토리지 서비스에 대해 살펴보겠습니다. 네이버 클라우드 플랫폼의 스토리지 서비스에는 블록 스토리지 외에도 Nez 백업 객체 스토리지와 아카이브 스토리지가 제공됩니다. 앞서 컴퓨팅 제품 그룹에서 설명했던 블록 스토리지부터 살펴보겠습니다. 블록 스토리지는 서버에 마운트되어 사용되는 스토리지 유형으로, 데이터는 파일 시스템에 의해 계층 구조로 저장됩니다. 네이버 클라우드 플랫폼의 블록 스토리지는 HDD와 SSD 유형으로 제공됩니다. 일반적으로 Linux 기반 서버 의 OS 영역에는 50GB, Windows 서버의 OS 영역에는 100GB의 블록 스토리지가 할당됩니다. OS 영역 외부에 추가 블록 스토리지를 추가할 수 있으며, 최소 10GB에서 최대 2TB까지 생성 가능합니다. 단일 볼륨에 2TB 이상의 블록 스토리지를 사용하려면 여러 블록 스토리지 볼륨을 LVM을 통해 바인딩하여 단일 볼륨으로 인식하도록 설정할 수 있습니다. Linux 또는 Windows의 동적 디스크 할당을 통해 각 서버에 최대 16개의 블록 스토리지 단위를 할당할 수 있으며, 여기에는 OS 영역의 블록 스토리지 하나가 포함됩니다. 추가 블록 스토리지를 위한 분리 기능이 제공되어 ' day'라는 서버에 할당된 추가 블록 스토리지를 분리하여 ' B'라는 다른 서버에 연결할 수 있습니다. 또한 스토리지 용량 확장을 지원하여 초기 할당 용량보다 더 큰 용량을 할당할 수 있지만, 각 볼륨당 최대 2TB까지만 확장할 수 있습니다. 추가 블록 스토리지에 대한 스냅샷 기능도 제공되므로 스냅샷을 기반으로 새 블록 스토리지를 생성하고 관리할 수 있습니다. 이제 블록 스토리지 의 분리 기능을 자세히 살펴보겠습니다. 블록 스토리지의 분리 기능은 서버가 종료되었거나 볼륨이 마운트 해제된 경우에만 사용할 수 있습니다. 서버가 실행 중인 경우 볼륨 크기 확장 기능을 사용하여 초기 할당된 볼륨보다 더 큰 용량을 설정할 수 있지만 OS 영역의 스토리지 용량 확장은 제공되지 않습니다. 실행 중인 서버에 마운트된 스토리지의 크기는 변경할 수 없습니다. 스토리지가 마운트된 서버를 중지하거나 스토리지를 마운트 해제한 후에 변경할 수 있습니다. 스냅샷 기능을 사용하여 저장된 데이터의 이미지를 생성할 수 있습니다. 현재 시점의 블록 스토리지를 살펴보면, 서버 이미지는 서버의 현재 데이터 이미지를 생성할 뿐만 아니라, 추가 블록 스토리지 스냅샷은 블록 스토리지에 대한 이미지만 생성합니다. 스냅샷 기능을 통해 새로운 블록 스토리지를 생성할 수도 있습니다. 그렇다면 이 스냅샷 기능은 언제 사용할 수 있을까요? 스냅샷을 다른 리전으로 복제하거나, HDD로 생성된 블록 스토리지의 스냅샷을 사용하여 SSD 유형의 블록 스토리지를 생성하거나, OS 영역의 볼륨이 손상되어 더 이상 사용할 수 없을 때 스냅샷을 사용하여 새로운 블록 스토리지를 생성하여 데이터를 복원할 수 있습니다. 다음으로 네이버 클라우드 플랫폼의 객체 스토리지에 대해 살펴보겠습니다. 객체 스토리지는 AWS S3 서비스처럼 대용량 데이터를 저장할 수 있는 스토리지 유형입니다. 네이버 클라우드 플랫폼 콘솔, API, SBK 및 CLI를 통해 쉽게 관리할 수 있으며, 저장된 파일에는 고유한 URL이 생성되어 여러 사용자가 인터넷에서 쉽게 액세스할 수 있습니다. 객체 스토리지는 특히 CDN 서비스 및 클라우드 로그 분석과 같은 다양한 네이버 클라우드 플랫폼 서비스의 기본 스토리지로 사용됩니다. 객체 스토리지에 업로드된 객체 및 버킷에 대한 권한을 관리할 수 있으며, 네이버 클라우드 플랫폼의 서브 계정 기능을 통해 객체 스토리지에 대한 권한 분리가 가능합니다. 스토리지 서비스 중 Nez는 다음과 같습니다. Nez는 여러 서버에서 공유할 수 있는 스토리지 유형으로, 최소 500기가바이트에서 최대 10테라바이트까지 구성할 수 있으며 100기가바이트 단위로 확장 가능합니다. Nez는 CIFS 및 NFS 프로토콜을 지원하며, Linux 서버와 공유되는 경우 CIFS 프로토콜을 지원하는 유형을 선택하고, Windows 서버와 공유되는 경우 NFS 프로토콜을 지원하는 유형을 선택할 수 있습니다. Nez는 스냅샷 기능과 MS 볼륨 사용량 모니터링 기능을 제공합니다. NESDET는 NFS 프로토콜을 지원하며 서버 의 IP 주소를 기반으로 액세스 제어를 수행하고, CIFS 프로토콜을 지원하는 NAS는 ID와 암호를 기반으로 액세스 제어를 수행합니다. Nez에서 지원하는 스냅샷은 생성된 MS 볼륨 내에 저장됩니다. 기본 설정에는 스냅샷 설정이 포함되어 있지 않으므로 스냅샷 기능을 사용하려면 스냅샷 설정을 수행해야 합니다. 최대 7개의 스냅샷이 저장되며, 7개 이상의 스냅샷이 생성되면 가장 오래된 스냅샷이 삭제됩니다. 스냅샷은 즉시 생성하거나 매일 또는 매주와 같이 정기적으로 자동 생성하도록 설정할 수 있습니다. 다음은 아카이브 스토리지로, 다양한 용도에 적합한 스토리지 서비스입니다. AWS Glacier 서비스와 유사한 아카이빙 서비스는 사용 빈도가 낮은 콜드 데이터나 아카이브 데이터를 저장하는 데 적합합니다. 스토리지 비용은 객체 스토리지보다 저렴하지만 API 호출 비용은 더 높습니다. 콘솔, API, CLI 및 SDK를 통해 관리할 수 있으며 최소 저장 기간이 없습니다. 하위 계정을 통한 관리가 가능하여 역할 기반 접근 제어 방식으로 권한 분리가 가능합니다. 마지막으로 살펴볼 스토리지 서비스는 백업 서비스입니다. 백업 서비스는 서버 데이터를 주기적으로 복제하고 아카이빙합니다. 네이버 클라우드 플랫폼에서 제공하는 모든 OS 플랫폼 파일 시스템 백업은 물론 DBMS 온라인 백업도 제공합니다. 이를 통해 데이터를 안전하게 보호하고 백업 복구를 지원합니다. 파일 시스템의 경우 파일 단위에서 폴더 단위로, DBMS의 경우 테이블 단위에서 DBS 단위로 백업 복구가 가능합니다. 일회성 백업 및 하루 전체 백업을 포함하여 총 8가지 백업 실행 주기 옵션을 제공합니다. 백업 파일은 최소 1주일에서 최대 52주까지 보관할 수 있습니다. 백업 결과는 요청자의 이메일로 주요 일일 항목과 함께 전송되어 확인할 수 있습니다. 이상입니다. Neighbor Cloud 플랫폼에서 제공하는 스토리지 제품군 서비스의 주요 특징을 살펴보겠습니다. 감사합니다.
