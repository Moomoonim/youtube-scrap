## 스크립트

안녕하세요 여러분! 오늘은 Weights and Biases의 BYOB 기능을 제대로 활용하는 방법을 보여드리는 간단한 영상을 준비했습니다. Terraform을 사용하여 S3 버킷을 생성하고, 모든 실험 결과와 데이터를 버킷에 저장한 후 직접 관리해 보겠습니다. 멋지죠? 자, 그럼 시작해 볼까요? 먼저 ' test bucket'이라는 디렉토리를 만들고, 그 안에 'main.cf'라는 파일을 생성합니다. Terraform의 기본 파일 이름이니만큼, 이제 Weights and Biases GitHub 저장소로 이동하겠습니다. ' terraform AWS 1db'라는 저장소가 있는데요, 이 페이지( Security Storage Connection 모델 모듈)에 접근하려면 gab.com/1db &gt; terraform aws-1DB &gt; train tree &gt; Main을 차례로 클릭해야 합니다. 그리고 Secure Storage 커넥터로 들어가면 됩니다. 이 모듈을 사용하시면 됩니다. 여기 복사해서 붙여넣으시면 첫 번째 단계가 완료되었습니다. 이제 AWS 리전을 설정하고 입력하시면 됩니다. 동쪽 리전을 선택하겠습니다. 좋습니다. 저장해 두겠습니다. 태그 섹션에서는 생성하는 버킷에 태그를 편집할 수 있습니다. 예를 들어 '환경'이라는 태그를 만들고 싶다고 가정해 보겠습니다. 이미 ' 환경'이 제안되어 있네요. 좋은 생각입니다. ' 환경'으로 입력하겠습니다. Dev님, 이 경우에는 입력으로 딕셔너리를 받겠습니다. 완벽하네요. 아니면 JSON이라고 해도 되겠네요. 모듈 부분으로 들어가면 소스는 그대로 유지됩니다. 네임스페이스는 버킷에 원하는 이름을 지정하면 되는데, ' test bucket all'로 하겠습니다. 네임스페이스를 사용하면 해당 네임스페이스가 사용되고, 버킷 이름이 고유하도록 끝에 임의의 단어를 몇 개 추가하겠습니다. 그런 다음 AWS 보안 정보를 입력해야 합니다. 이 부분은 중요하며, AWS 문서 의 'BYOB(Bring Your Own Bucket)' 부분에서 확인할 수 있습니다. 아래로 스크롤하면 이 부분을 사용하게 됩니다. 하나의 데이터베이스에 설정하는 경우입니다. 퍼블릭 클라우드에서 AI를 구현하려고 하는데, 전용 클라우드 인스턴스 에 설정하는 경우 이 aun을 사용하겠습니다. 전용 클라우드 인스턴스의 경우, 무게는 Andes입니다. 좋습니다. 이제 이 aun을 여기에 붙여넣겠습니다. 좋습니다. 다음 단계는 Terraform을 실행하는 것입니다. 좋습니다. 실행이 완료되면 ` terraform plan`을 실행하겠습니다. 필수는 아니지만, 실행하면 WS 내부에서 수행할 모든 작업을 출력해 주기 때문에 실행하는 것이 좋습니다. 좋습니다. 실행이 완료되면 " 유효한 자격 증명 소스를 찾을 수 없습니다"라는 오류가 발생합니다. 이 오류가 발생하는 이유는 AWS 자격 증명이 만료되었기 때문입니다. AWS에 접속하여 자격 증명을 가져와야 합니다. AWS 액세스 포털에 있습니다. 버킷을 생성하려는 AWS 계정으로 이동하여 액세스 키로 이동합니다. 옵션 1에서 액세스 키를 복사하여 붙여넣습니다. 여기 키가 딱 있네요. 완벽합니다. 이걸 복사해서 CLIA에 붙여넣겠습니다. 좋습니다. 이제 Terraform plan을 한 번 더 실행해 보겠습니다. 멋지네요! 성공했습니다. 여기 보이는 게 전부입니다. 내용이 많긴 하지만 버킷에 무엇이 생성될지, 어떤 규칙이 설정될지 등을 보여줍니다. 좋습니다. 이제 Terraform apply를 실행하고 소문자로 입력하겠습니다. 좋습니다. 실행이 완료되었으니 1db로 이동해 보겠습니다 . 완벽해요! 1단계에서 새 팀을 만들려면 '공동 작업을 위한 새 팀 만들기'를 누릅니다. 개인 계정으로는 만들 수 없고, 조직 계정으로 만들어야 합니다. 개인 팀이 아닌 조직 계정으로 팀을 만들려면 조직이 있어야 하죠. 이 경우에는 ' RTM test'라는 조직을 선택하고 '공동 작업을 위한 새 팀 만들기'를 누릅니다. 팀 이름은 원하는 대로 지정할 수 있습니다. 좋아요! ' 팀 테스트'라고 입력해 볼게요. 멋지네요! 이제 외부 스토리지를 선택해 보겠습니다. ' 새 버킷 추가'를 누르면 Google 또는 AWS 두 가지 옵션이 있습니다. Google 버킷을 설정하는 데 관심이 있다면 GCP 버킷을 사용해도 됩니다. 과정은 거의 비슷합니다. 이제 이름, 경로, KMS 키가 필요합니다. 좋습니다! AWS로 이동해서 S3에 들어가 보겠습니다. 12월 6일에 생성된 새 버킷이 보이네요. 클릭해 보겠습니다. 아시다시피 버킷 이름은 'test'입니다. 파일 스토리지는 이미 설정되어 있습니다. 여기서 완벽한 경로를 추가하는 것은 필수는 아니지만, 버킷 내부에 경로를 추가하여 가중치, BIES 실험 및 아티팩트가 저장될 위치를 지정하고 싶다면 여기에 추가하면 됩니다. KMS 키는 권한이 아닌 속성에서 가져올 수 있습니다. 좋습니다. 여기 AON CERAS 키가 있습니다. 이 키를 붙여넣으면 성공적으로 연결되어 작동하는 것을 보여줍니다. 이제 팀 생성 버튼을 누르면 멋진 팀 테스트가 생성됩니다. 좋습니다. AWS에서 수동으로 설정하는 대신 Terraform을 사용하는 이유는 버킷 정책과 코스 정책을 자동으로 설정해 주기 때문입니다. 버킷에 직접 들어가서 설정할 필요 없이 Terraform이 모든 것을 처리해 줍니다. 이제 멋진 팀 테스트가 생성되었으니 로깅 및 시각화 실험을 시작할 수 있습니다. 감사합니다. [음악]
