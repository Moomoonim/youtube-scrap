네, 맞습니다. 새로운 시스템 아키텍처 측면에서 어떻게 생각해야 할까요? 제가 지금 이야기하려는 부분이 바로 이겁니다. 자, 그럼 더블 클릭해 보겠습니다. 제가 흥미롭게 생각하는 점 중 하나는 모델이 상태 비저장(stateless)이라는 점입니다. 즉, 특정 시점의 스냅샷을 찍는다는 거죠. 예를 들어 데이터셋 X를 사용해서 모델을 학습시키고, 그 시점의 스냅샷을 저장하는 겁니다. 이런 생성형 모델(예: jgpt)을 사용해 보면, " 2021년에 학습되었지만, 정답은 모르겠습니다." 또는 "이 정보에 접근할 수 없습니다."와 같은 메시지가 표시되는 경우가 있습니다. 왜냐하면 그 정보는 원래 학습 데이터셋에 있었기 때문입니다. 우리가 여기서 목표로 하는 것은 상태 저장(state fullness)입니다. 즉, 모델 상태를 변경할 수 있도록 하는 것이죠. 데이터베이스 용어로 설명하자면, 모델에 CRO(Crot Resource) 지원을 추가하고 싶다고 가정해 보겠습니다. 모델에서 무언가를 생성하려면, 생성된 데이터를 검색 하거나 읽고, 업데이트하거나 삭제할 수 있어야 합니다. 제가 흥미롭게 생각하는 점은, 생성 과정, 즉 CR의 C가 일종의 미세 조정이라고 할 수 있다는 것입니다. 이는 사람들이 Novel Rag 접근 방식에서 사용하는 방식과 유사할 수도 있고, 아니면 우리가 직접 미세 조정을 하지 않고 모델 내에서 더 많이 수행한다고 할 수도 있겠습니다. 그렇게 되면 두 번째 단계인 읽기 기능이 생겨서 데이터를 읽고 검색할 수 있게 됩니다. 왜냐하면 이제 데이터가 가중치에 저장되었기 때문입니다. 하지만 데이터를 업데이트하고 삭제하는 방법은 아직 잘 모르겠습니다. 예를 들어, 새로운 지식을 기반으로 모델을 미세 조정한다고 가정해 보겠습니다. 그렇다면 이 두 가지 기능을 사용하여 모델이 가진 지식을 어떻게 업데이트하고 삭제할 수 있을까요?
