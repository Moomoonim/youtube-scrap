## 스크립트

자, 코드를 다시 한번 보여드리겠습니다. 이렇게 해서 아티팩트를 생성했습니다. 다음으로 할 일은 모델을 연결하는 것입니다. 모델을 연결하여 아티팩트를 생성하려면 모델 레지스트리 링크를 클릭한 다음 등록된 모델을 선택합니다. 여기서 용어 몇 가지를 좀 명확히 하고 싶은데요, 노아, 모델 레지스트리 와 등록된 모델의 정확한 차이점과 이 경우 등록된 모델이란 무엇인지 설명해 주시겠어요? 네, 모델 레지스트리는 모든 모델의 전체 저장소라고 생각하시면 됩니다. 모든 모델 체크포인트가 저장되는 큰 저장소와 같습니다. 등록된 모델은 모델 레지스트리 내에 여러 개의 등록된 모델이 있을 수 있는데, 일반적으로 팀에서 작업 중인 특정 머신 러닝 작업을 나타냅니다. 여러 프로젝트의 담당자들이 해당 프로젝트에 대한 최상의 체크포인트를 게시하는 것입니다. 예를 들어, 한 팀이 특정 고객 프로젝트를 진행하고 있다고 가정해 보겠습니다. 저희가 함께 작업해 온 모델 레지스트리에는 깊이 추정, 지하 구조, 제조 등 다양한 분야에 맞는 모델들이 있습니다. 예를 들어, 등록된 모델 하나가 깊이 추정을 나타낸다고 생각하시면 됩니다. 앙상블 모델을 사용하는 경우, 앙상블 모델 내의 각기 다른 작업마다 등록된 모델이 있습니다. 따라서 등록된 모델은 머신러닝 작업과 동의어라고 생각하시면 됩니다. 팀 내 여러 프로젝트의 담당자들이 각자의 프로젝트에서 이러한 작업을 수행하지만, 이 팀 레지스트리에 연결되어 있습니다. 레지스트리에는 모든 프로젝트에서 해당 머신러닝 작업에 대한 최상의 모델 체크포인트 모음이 있습니다. 이는 기본적으로 고정되거나 북마크되거나 연결된 모델들을 특정 폴더, 즉 동일한 머신러닝 작업을 위해 작동하는 버전 폴더로 정리하는 추가적인 계층 구조입니다. 정말 유용하죠. 다시 한번 말씀드리지만, 등록된 모델은 작업입니다. 따라서 여기 레지스트리 링크를 클릭하면 해당 작업에 대한 정보를 얻을 수 있습니다. 이 드롭 다운 메뉴에는 이 아티팩트를 연결할 수 있는 등록된 모델이나 작업 목록이 표시됩니다. 이 경우에는 두 개가 있는데, 새 모델을 만들어 보겠습니다. 이전 프로젝트에서 사용하던 모델들이 있지만, 새 모델을 만들고 싶습니다. 여기에서 만들 수 있고, 예를 들어 'ML 작업'이라고 이름을 지정하겠습니다. 유형은 ' 모델'이고, '데모'와 같이 태그를 지정하겠습니다. 태그 상자는 설명하지 않겠습니다. 그냥 넘어가겠습니다. 아주 편리하게 방금 만든 모델 아티팩트를 이 작업에 연결하겠습니다. 이렇게 하면 이 작업이 ' ML 작업'이 됩니다. 필요에 따라 다른 별칭도 만들 수 있습니다. 예를 들어, 이 시점에서 ' 개발자 별칭'을 추가했는데, 다른 유형의 별칭을 추가하고 싶다고 가정해 보겠습니다. 별칭을 스테이징하는 건 일종의 마지막 기회라고 할 수 있어요. 나중에 별칭을 추가할 수도 있지만, 이 단계에서 원한다면 다른 별칭을 추가할 수 있는 방법이죠. 그런 다음 레지스트리에 연결하면 등록된 모델이 생성되고, 레지스트리 보기로 이동하면 레지스트리 에 등록된 모델을 볼 수 있어요. 그러면 다양한 별칭을 확인할 수 있죠. 예를 들어, 여기 있는 건 모델이고, 이건 포인터예요. 그러니까 이건 등록된 모델이고, 이건 아티팩트를 가리키는 거죠. 보기를 클릭하면 모든 정보를 볼 수 있어요. 다음 섹션에서 UI를 자세히 살펴볼 건데, 일단 어떻게 보이는지 보여드리고 싶었어요. 이렇게 모델을 레지스트리에 연결하는 거예요. 방금 보여드린 것처럼 코드로도 똑같이 할 수 있어요. 코드로 레지스트리에 연결하려면 이 셀에 있는 코드를 실행하면 돼요. 그래서 제일 먼저 해야 할 일은 아티팩트 이름을 가져오는 것입니다. 이 콜론(:)에 주목하세요. 노아, 이 특정 상황에서 콜론이 무엇을 의미하는지 설명해 주시겠어요? 네, 이것은 아티팩트를 참조하기 위해 별칭을 사용하는 아주 좋은 예입니다. 레지스트리에서 아티팩트를 가져오거나 프로젝트에서 직접 가져올 때, 버전 번호(예: v27)를 사용하여 원하는 버전을 참조하는 대신, 예를 들어 항상 최신 버전이나 가장 성능이 좋은 모델 버전을 연결하고 싶다면 콜론 뒤에 별칭을 붙이는 것이 좋습니다. 이렇게 하면 팀 전체에서 표준화된 용어를 사용하여 의미 론적으로 친숙한 참조를 사용할 수 있습니다. 그리고 한 가지 더 알아둘 점은, 해밀이 언급했듯이 아티팩트 또는 모델 아티팩트를 레지스트리에 연결할 때 별칭을 추가하는 것이 좋다는 것입니다. 모델의 생명주기 단계를 나타내는 의미론적으로 친숙한 키워드를 추가하는 것이 좋습니다. 예를 들어, 모델을 레지스트리에 처음 연결할 때 QA, 검토, 평가 필요와 같은 별칭을 추가하여 스테이징 파이프라인에 진입했음을 표시하는 경우가 있습니다. 테스트를 거친 후에는 형식이 양자화되었음을 반영하여 별칭이 변경될 수 있습니다. 일부 고객은 ' 양자화'와 같은 별칭을 추가하여 파이프라인 의 해당 단계에 있으며 프로덕션 에 가까워지고 있음을 나타내기도 합니다. 또는 모델이 테스트를 통과하지 못한 경우 '보관됨'과 같은 별칭을 추가할 수도 있습니다. 이렇게 하면 팀은 등록된 모델 이나 작업에서 해당 별칭을 삭제할 수 있습니다. 따라서 별칭은 프로그램적으로 아티팩트를 참조하는 매우 유용한 방법입니다. 버전 번호를 외우는 것보다 좀 더 친숙한 용어를 사용하는 방법을 찾고 있었는데, 노아, 정말 도움이 많이 됐어요. 감사합니다. 별칭에 대해 말씀드리자면, 특정 모델 레지스트리나 등록된 모델 컬렉션에서는 하나의 모델만 동일한 별칭을 가질 수 있습니다. 예를 들어, 최신 모델이 두 개 이상 별칭을 가질 수는 없죠. 이렇게 하면 별칭을 고유하게 사용할 수 있고, 모델의 수명 주기를 관리하는 데에도 도움이 됩니다. 별칭을 추가하고 이런 작업을 하는 게 조금 번거롭게 느껴질 수도 있지만, 나중에 보여드릴 것처럼 이 기능을 기반으로 자동화를 구축하고 다른 시스템과 연동하는 방법을 알려드리겠습니다. API와 몇 가지 다른 기능을 활용하면 모델을 레지스트리의 여러 부분으로 이동시키는 작업을 자동화할 수 있습니다. 워크플로는 사람이 직접 참여하는 방식이라 전혀 복잡하지 않고 매우 편리하며 사용하기 쉽습니다. 그리고 이것은 매우 간단하고 최소한의 예시일 뿐이라는 점도 말씀드리고 싶습니다. 나중에 강의 후반부에서 실제 머신러닝 사용 사례를 통해 이 전체 프로세스를 처음부터 끝까지 살펴보는 예제를 다룰 예정입니다. 이를 통해 실제 머신러닝 프로젝트에서 어떻게 작동하는지 더 잘 이해하고 직관적으로 파악할 수 있을 것입니다. 결론적으로, 이것이 모델을 연결하는 방법입니다. 제가 UI에서 한 것처럼, 해당 모델을 가져와 등록된 모델로 연결했습니다. 제가 모델에 지정한 이름과 동일하며, 기억하시겠지만 스테이징 태그를 추가했습니다. 레지스트리에 모델을 연결하는 데 필요한 모든 작업은 바로 이것입니다.
