## 스크립트

오늘은 VS Code에서 Git과 GitHub를 사용하는 방법을 살펴보겠습니다. VS Code에서 GitHub를 사용하면 컨텍스트 전환이 줄어들고 워크플로가 간소화되며 생산성이 향상됩니다. [음악] 이 비디오를 끝까지 시청하시면 에디터를 벗어나지 않고 GitHub에서 저장소를 초기화하고, 브랜치를 전환하고, 스테이징하고, 커밋하고, 변경 사항을 푸시하는 방법을 모두 이해하게 될 것입니다. 안녕하세요, 저는 카디샤입니다. 오늘 이렇게 함께해 주셔서 정말 기뻐요. VS Code 팀의 제 친구 레이놀드가 VS Code에서 Git [음악]과 GitHub를 사용하는 방법을 보여주기 위해 이 자리에 함께했습니다. 레이놀드, 시작해 줘 . 고마워, 카디샤. 소스 코드 관리, 버전 관리, 백업 등 어떤 이름으로 부르든, 결국 모든 것은 시간이 지남에 따라 코드와 파일을 추적하는 것에 관한 것입니다 . Git은 소스 코드를 관리하는 프로그램이고 , GitHub는 해당 코드의 사본을 온라인 저장소에 호스팅하는 역할을 합니다. Visual Studio Code는 Git과 GitHub를 쉽게 사용할 수 있도록 해줍니다. 이번 시연에서는 그 방법을 보여드리겠습니다. 시작하기 전에, 이 비디오는 여러분이 이미 Git을 설치했다고 가정합니다. Git은 이 사이트에서 다운로드할 수 있습니다. VS Code에서 Git을 사용하기 위한 첫 번째 단계는 저장소를 반영하는 폴더를 초기화하는 것입니다. 자, 그럼 제가 파일이 들어 있는 폴더를 열어볼게요. 이 폴더 안에는 이 웹사이트가 포함된 간단한 프로젝트 파일이 있습니다. 자, 이제 소스 제어 아이콘으로 이동한 다음 ' 리포지토리 초기화'를 클릭해야 합니다. 이제 왼쪽 하단에 있는 브랜치 이름이 main인 것을 확인할 수 있습니다. 만약 이 항목의 이름을 바꾸고 싶다면, 맥에서는 Shift + Command + P를 눌러 명령 팔레트를 열고 '이름 바꾸기'를 입력한 다음 '분기 이름 바꾸기'를 선택하면 됩니다. 그런 다음 이 부분을 테스트 브랜치와 같은 것으로 변경하면 하단에 반영되는 것을 볼 수 있습니다 . 하지만 이제 원래 이름인 '메인'으로 되돌려 봅시다. 그리고 이제 거기에 그 이름이 반영되어 있습니다 . 초기화가 완료되면 소스 제어판에서 파일 이름 옆에 'U'가 표시된 것을 확인할 수 있습니다 . U는 추적되지 않음을 의미하며, 파일이 새로 생성되었거나 변경되었지만 저장소에 추가되지 않았음을 나타냅니다. 이를 추적하려면 옆에 있는 더하기 기호를 클릭하거나, ' 변경 사항'이라는 단어 바로 옆에 있는 맨 위의 더하기 기호를 클릭하여 모든 변경 사항을 스테이징할 수 있습니다. 이제 커밋하려면 여기 위로 올라가서 " 첫 번째 커밋"과 같은 메시지를 입력할 수도 있고, 더 좋은 방법은 여기 있는 아이콘을 클릭해서 커밋 메시지를 생성하는 것입니다 . 상세한 결과물이 나왔는데, 괜찮아 보이네요. 이제 '커밋'을 클릭하겠습니다. 지금 우리는 메인 브랜치에 있습니다. 그리고 만약 이것이 대규모 앱이고 새로운 코드나 기능을 추가해야 한다면, 새로운 브랜치를 생성합니다. 그렇게 하려면 명령 팔레트로 이동하여 간단히 " 분기 생성"을 입력하고 선택하면 됩니다. 그런 다음 예를 들어 '새로운 기능'이라고 입력하기만 하면 됩니다. 왼쪽 하단 모서리에 새로운 지점이 표시되어 있습니다. 이제 14번째 줄 바로 아래에 새로운 기능을 시뮬레이션하는 코드를 추가하겠습니다. 코드를 추가하면 왼쪽 타일의 여백에 녹색 선이 나타나는 것을 확인할 수 있습니다. 이는 새로운 노선을 반영합니다. 하지만 13번째 줄처럼 코드를 수정하고 느낌표를 추가하면 코드가 수정되었음을 나타내는 파란색 줄이 표시됩니다 . 소스 제어 보기에서 몇 가지 버튼도 볼 수 있습니다 . 여기에 마우스를 올리면 파일을 열거나, 변경 내용을 버리거나, 변경 내용을 스테이징하는 버튼이 나타납니다. 파일이 여러 개인 경우, 위에서 모든 변경 사항을 스테이징하거나 모든 변경 사항을 폐기할 수 있습니다. 또한 변경 사항을 열거나 스테이징되지 않은 변경 사항을 검토할 수 있는 옵션도 있습니다. VS Code는 별도의 도구 없이도 두 파일의 내용을 나란히 비교하여 차이점을 확인할 수 있습니다 . 변경 사항을 확인하려면 소스 제어에서 해당 파일을 클릭하기만 하면 됩니다. 여기서 변화를 확인하고 차이점을 비교할 수 있습니다. 하지만 제가 여러분께 보여드리고 싶은 또 다른 점은 모든 변경 사항을 한눈에 볼 수 있는 인라인 보기로 전환할 수 있다는 것입니다 . 이 안에서 차이점 보기 화면을 편집할 수도 있습니다. 예를 들어 , 제목에 " now"라는 단어를 추가하고, " learning"을 "learn"으로 바꾸고, 완료되면 더하기 기호를 클릭하여 변경 사항을 저장할 수 있습니다. 확정하기 전에 제목을 변경하거나, 어떤 결과가 나오는지 다시 한번 확인해 볼 수도 있습니다 . 이것도 좋아 보이네요. 참고로 저희는 아직 새로운 기능 개발 브랜치를 사용하고 있습니다. 메인은 아직 바뀌지 않았습니다 . 자, 메인 브랜치를 보고 싶다면 여기 왼쪽 하단 모서리를 클릭하면 몇 가지 옵션이 나타납니다. 맨 위에서 '메인 브랜치'를 클릭하면 원래 코드를 볼 수 있습니다. 그러니까 병합하려면 이 세 개의 점을 클릭하고, 분기를 선택한 다음, 병합을 선택하면 어디 에서 병합할지 묻는 메시지가 나타납니다. 저는 새로운 기능 브랜치를 선택하겠습니다. 이제 메인 브랜치에 변경 사항이 반영되었습니다. 자, 이제 이 코드를 GitHub에 게시하고 싶다고 가정해 봅시다 . 우리가 할 일은 '브랜치 게시' 버튼을 누르는 것뿐이며, 그러면 비공개 저장소 또는 공개 저장소를 선택할 수 있는 옵션이 나타납니다. 저는 그것이 공개되는 것에 대해 아무런 문제가 없습니다 . 그러면 게시 프로세스가 시작됩니다. 오른쪽 하단 모서리에 GitHub를 열어 새 저장소를 확인할 수 있는 옵션이 있습니다. 이제 이 저장소는 공개되어 전 세계 사람들이 볼 수 있습니다. VS Code에서 Git과 GitHub를 사용하는 방법에 대한 자세한 내용은 gh.io/gfbvscode에서 확인할 수 있습니다. 좋아요, [음악] 이제 레이놀드 이야기로 돌아가 보죠. 자 , 이제 저장소를 복제하고 싶다고 가정해 봅시다 . 우리가 해야 할 일은 관심 있는 저장소로 이동하는 것뿐입니다. 예를 들어, 여기 있는 simple/card-app 저장소를 클론하고 싶다고 가정해 보겠습니다. 코드라고 표시된 부분으로 가서 드롭다운 메뉴를 클릭하고 URL을 복사하기만 하면 됩니다. 이제 VS Code로 이동하여 명령 팔레트에 ' clone'을 입력하고 선택한 다음, URL을 붙여넣고 'URL에서 복제'를 선택합니다. 저장소를 저장할 위치를 묻고 저장소를 열라는 메시지가 표시되면, 그렇게 하면 됩니다. VS Code의 소스 코드 관리 섹션에서 할 수 있는 일들은 충분히 이해하지만, 모든 것을 항상 수동으로 할 필요는 없습니다 . 예를 들어, MCP( 모델 컨텍스트 프로토콜)라고 하는 것을 활용할 수 있는데, 이를 통해 AI 도구는 외부 도구와 데이터에 안전하게 접근할 수 있습니다. 예를 들어, ' 도구 구성'을 클릭하면 기본적으로 내장된 몇 가지 도구를 볼 수 있습니다. 하지만 확장 프로그램 마켓플레이스에 가서 @mcp를 입력하면 GitHub에서 제공하는 MCP 서버를 찾아서 설치할 수 있으며, 이를 통해 추가 기능을 사용할 수 있습니다. 그래서 엔터 키를 눌러 MCP 서버 인증 권한을 승인했습니다. 제 GitHub 계정을 알려드리겠습니다. 자, 이제 아래쪽을 보면 GitHub MCP 서버가 설치된 것을 확인할 수 있습니다. 그리고 구성 도구로 돌아가면 이제 GitHub MCP 서버가 표시됩니다. 자, 그럼 방금 복제한 앱을 간단히 살펴볼까요? 이제 실행에 필요한 종속성을 설치했고, 모습은 다음과 같습니다 . 이 앱은 간단한 플래시카드 앱으로, 학습 세션을 진행할 수 있습니다. 질문을 하고, 답을 추측해보고 , 맞는지 확인해 보세요. 하지만 디자인은 더 나아질 수 있고, 새로운 기능들을 추가하면 더 좋을 것 같습니다. VS Code 내에서 Chat에게 이 프로젝트에 대한 새로운 기능 두 가지와 UX 개선 사항 두 가지를 요청하고 관련 이슈를 열 수 있습니다. 해당 개발자는 업무에 착수하여, 이상적으로는 기능 및 사용자 경험 개선 사항을 구상한 후 GitHub MCP를 사용하여 이슈를 생성할 수 있다는 것을 알고 있어야 합니다 . 지금 그 작업이 진행되는 동안 , 현재 아무런 문제가 없다는 것을 보여드릴 수 있습니다. 그리고 지금 당장 허락하겠습니다. 보시는 바와 같이, 저희가 설치한 GitHub MCP 서버를 사용하고 있습니다 . 다음은 사용자 경험 개선 사항 외에도 저희가 제안하는 새로운 기능들입니다 . GitHub에 접속해서 새로고침하면 다음과 같은 문제가 표시됩니다. 그게 다입니다 . 개발자들이 Git을 사용하는 가장 일반적인 방법들을 살펴보았습니다. 저장소 생성, 브랜치 생성 및 전환 , 변경 사항 스테이징 및 커밋 , 브랜치 병합, GitHub에 게시 , 기존 저장소 복제 등을 비롯하여 약간의 AI 기능까지 활용합니다 . 더 고급 주제들도 있지만, 이것들이 여러분이 가장 자주 사용하게 될 주제들입니다. 이번 시연을 통해 유익한 정보를 얻으셨기를 바라며, 이제 다시 카디샤 이야기로 돌아가 보겠습니다. 이 영상이 도움이 되었기를 바랍니다.
