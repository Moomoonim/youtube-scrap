LLM 자체에 드는 비용은 이러한 시스템을 구축하는 데 필요한 다른 모든 작업을 수행하는 비용을 포함하지 않기 때문에 비용이 큰 문제가 됩니다. 마지막으로, 복잡한 시스템을 구축해 본 경험이 있다면 이해하시겠지만, 가장 중요한 것은 속도입니다. 인공지능 분석(Artificial Analysis)이라는 회사가 대규모 언어 모델 벤치마킹을 위해 제공한 이 차트가 좋은 예입니다. 인기 있는 소규모 언어 모델 중 하나인 Mistol 7B는 주요 공급업체의 대규모 모델보다 훨씬 빠르게 실행됩니다. 대규모 모델의 문제는 여러 LLM 호출, 복잡한 워크플로 또는 특정 애플리케이션에서 에이전트 및 리뷰를 사용하는 경우 매우 느려질 수 있다는 것입니다. 쿼리 실행에 몇 분이 걸린다면 개발 과정이 매우 힘들 뿐만 아니라, 너무 느려서 사용자가 채택하지 않는 경우가 많습니다. 이러한 모델과 대규모 데이터 세트를 사용하여 실험을 시도할 때, 데이터 과학자가 작업을 실행하고 GP4를 통해 모든 데이터를 처리하는 데 9시간이 걸린다면 개발 속도가 극도로 느려지게 됩니다. 프로젝트에 대한 ROI 영향, 즉 실제 현장에서 직면하는 과제들을 살펴보겠습니다. 일반적인 통념은 인공지능 분석에서 나온 것으로, 미스트로 7B 모델에 대한 분석입니다. 저는 이 차트가 정말 마음에 드는데, 사람들이 이러한 기술들에 대해 갖고 있는 반사적인 생각을 잘 보여준다고 생각하기 때문입니다. 작은 모델은 저렴하고 빠르지만 품질은 떨어진다는 것이죠. 이 차트를 잠깐만 봐도 누구나 생각하는 바를 알 수 있습니다. " 28 대 100이라니, 이건 정말 안 좋을 거야. 제대로 작동하지 않을 거야." 즉, 최고의 성능을 내려면 가장 크고 효과적인 모델을 사용해야 한다는 것이 일반적인 통념입니다. 하지만 곧 살펴보겠지만, 이러한 통념은 사실이 아닙니다. 그럼 네이선에게 마이크를 넘기겠습니다. 감사합니다, 케빈. 네, 저는 네이선 코르도 이고 파인콘의 제품 관리자입니다. 오늘은 파인 콘 연구 및 머신러닝 팀에서 진행한 연구에 대해 이야기해 드리겠습니다. 다음 슬라이드로 넘어가 주세요. 네, 저희는 다음과 같은 연구를 시작했습니다. 모델 규모와 학습된 지식( 모델이 자체적으로 통합하는 지식) 과 검색되지 않은 지식(즉, 외부 소스를 통해 통합되는 지능) 간의 관계를 이해하는 것이 중요했습니다. 특히, RAG 솔루션은 개인 지식 이나 도메인별 지식, 즉 모델이 이전에 데이터를 접하지 못한 사용 사례에서 매우 효과적이라는 것을 이미 알고 있었습니다. 하지만 우리가 테스트하고 싶었던 것은 모델이 훈련받았거나 알아야 할 일반 지식에 대한 성능을 외부 지식 기반을 제공함으로써 향상시킬 수 있는지 여부였습니다. 또한 이러한 대규모 언어 모델을 크기와 훈련 데이터 측면에서 확장하는 것이 지식 집약적인 작업을 해결하는 가장 좋은 방법인지에 대한 질문에 대한 답을 찾고자 했습니다. 다음 슬라이드에서 우리가 실행한 실험을 설명하겠습니다. 우리는 Falcon 대규모 언어 모델 제작사인 TII에서 공개한 데이터 세트인 Refined Web으로 시작했습니다. Refined Web은 주로 Common Crawl에서 가져온 데이터와 품질 및 중복 제거를 위해 정제된 다른 소스의 데이터를 포함하는 크롤링된 웹의 필터링된 버전입니다. 우리는 데이터 세트를 추출했습니다.
