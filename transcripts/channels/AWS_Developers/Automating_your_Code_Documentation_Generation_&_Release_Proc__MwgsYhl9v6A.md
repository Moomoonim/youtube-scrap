AWS에서 HTML 문서를 생성하고 호스팅할 수 있습니다. 이 비디오에서 디자인을 살펴보겠습니다. 아마존에서 저희 팀은 생산성 향상 애플리케이션 제품군을 개발하고 있으며, 그중 하나가 마켓플레이스입니다. 마켓플레이스를 통해 개발자 커뮤니티는 자동화 SDK를 게시, 검색 및 재사용할 수 있습니다. 오늘 소개하는 디자인은 저희 팀이 개발자 커뮤니티에서 관련 SDK를 더 쉽게 찾고 재사용할 수 있도록 도와주었습니다. 론, 왜 팀에서 지속적으로 업데이트된 문서를 보유하는 것이 그렇게 중요한가요? 좋은 질문입니다. 프랑스: 앞서 말씀드렸듯이 저희 팀에는 개발자 커뮤니티가 있으며, 문서가 필요한 다양한 사용 사례가 있습니다. 첫 번째는 팀에 새로운 사람이 합류할 때입니다. 예를 들어, 팀에서 누군가가 떠나더라도 지식 이전과 적응이 매우 쉬워집니다. 두 번째는, 저희는 특정 마켓플레이스를 운영하고 있는데, 유지보수 단계에서 문제가 발생하면 특정 코드 조각을 쉽게 검색하고 유지보수 티켓을 해결할 수 있다는 점입니다. 마지막으로, 많은 외부 개발자들이 이 코드베이스에 기여하고 있기 때문에, 그들이 자신의 기능을 다른 사람들이 재사용할 수 있도록 하려는 경우, 해당 기능을 쉽게 찾고 재사용할 수 있습니다. 따라서 이는 팀 생산성 향상에 도움이 됩니다. 자, 그럼 코드 문서 생성기 의 구성 요소는 무엇인가요? 전체 코드 문서 생성 설계는 세 부분으로 나눌 수 있습니다. 첫 번째는 실제 문서 생성, 두 번째는 생성된 문서의 파일 저장, 세 번째는 사용자가 쉽게 볼 수 있도록 게시하는 부분입니다. 그렇다면 첫 번째 부분, 즉 문서 생성을 직접 처리하시나요, 아니면 문서 생성을 직접 처리하시나요? 문서 생성은 블랙박스처럼 작동하는데, XML 기반 태그나 기타 여러 입력값을 받을 수 있습니다. Swagger JSON 파일은 문서 생성 도구를 통해 HTML, YAML, PDF 또는 JSON 파일로 변환될 수 있습니다. 문서 생성 과정을 좀 더 자세히 살펴보자면, 저희는 Doc Effect라는 도구를 사용하고 있습니다. Doc Effect는 코드 파일 과 XML 태그를 문서 문자열에 전달하고, 이를 사용하여 풍부한 HTML 문서를 생성합니다. 이렇게 생성된 풍부한 HTML 문서는 사용자에게 배포하는 데 사용됩니다. 문서가 생성되면 어디에 저장되고 어떻게 작동하는지 궁금하시죠? 이 문서는 제가 앞서 언급했듯이 Doc Effect를 수동으로 실행하여 생성하는 것과는 달리, 모든 코드 빌드 시에 필요하기 때문에 CICD 파이프라인의 핵심 구성 요소로 만들었습니다. 설계에 대해 말씀드리자면, 저희는 AWS 네이티브 환경을 사용하고 있으며, 그 안에서 코드 파이프라인을 활용합니다. 코드 파이프라인 내부에는 코드 저장소 역할을 하는 코드 커밋이 있습니다. 모든 코드가 여기에 저장되고, 빌드를 수행하는 Windows 서버인 코드 빌드가 있습니다. 코드를 컴파일하고, 코드 빌드 측면으로 좀 더 자세히 살펴보면, 빌드 빌드는 사전 빌드, 실제 빌드, 사후 빌드의 세 부분으로 나뉩니다. 사전 빌드 단계에서는 빌드 머신(Windows 서버)에 DocFX를 설치하고 SDK 코드를 컴파일합니다. 사후 빌드 단계에서는 코드 컴파일이 성공하면 DocFX를 사용하여 해당 빌드 또는 코드에서 HTML 문서를 생성합니다. 생성된 문서는 S3 버킷에 저장됩니다. 이제 두 번째 설계 부분인 파일 저장소에 대해 설명하겠습니다. 생성된 모든 문서는 S3 버킷에 저장됩니다. 여기에는 몇 가지 세부 사항이 있습니다. 저희의 경우 특정 패키지의 버전 업데이트가 있을 때만 HTML 문서를 저장하려고 했습니다. 그래서 설계에서 볼 수 있는 Lambda 함수를 사용했는데, 이 함수는 먼저 컴파일된 코드의 버전이 업데이트되었는지 확인합니다. 해당 코드 조각과 S3에 저장된 버전이 컴파일된 코드 보다 최신 버전인지 확인하는 것입니다. 만약 최신 버전이라면 해당 HTML 파일을 S3에 복사할 수 있습니다. 또 다른 Lambda 함수도 있습니다. 이 Lambda 함수는 모든 HTML 파일이 S3에 복사될 때마다 메인 인덱스 파일, 즉 목차 파일을 생성합니다. 이 Lambda 함수는 복사된 모든 파일을 이 목차에 병합하여 사용자가 웹사이트에 접속했을 때 랜딩 페이지에서 전체 내용을 볼 수 있도록 합니다. 이러한 파일에 어떻게 접근할 수 있도록 할까요? S3 정적 웹사이트 호스팅과 같은 서비스를 사용할까요? S3는 정적 웹사이트를 호스팅하는 데 사용할 수 있지만, 가장 큰 문제점 중 하나는 보안이 취약하다는 것입니다. S3는 HTTP만 지원하고 HTTPS는 지원하지 않기 때문입니다. 따라서 더 안전한 솔루션이 필요했습니다. 또 다른 문제는 저희 고객이 전 세계에 분포되어 있다는 점입니다. 전 세계 여러 지역에 개발자들이 있는데, S3가 특정 지역에만 있다면 웹사이트를 운영하는 데 어려움이 있을 수 있습니다. S3가 있는 동일한 위치에 있는 사용자에 비해 문서에 실제로 접근하는 데 걸리는 시간이 다소 길어질 수 있습니다. 그래서 저희는 클라우드프론트를 설계에 추가했습니다. 클라우드프론트는 콘텐츠 전송 서비스이므로 지연 시간을 줄이는 데 도움이 됩니다. 전 세계 사용자를 위한 글로벌 서비스입니다. 또 다른 중요한 이점은 HTTPS를 지원한다는 것입니다. 이제 전체적인 설계가 더욱 안전해졌습니다. 그리고 S3에 파일을 저장할 때 서버 측 암호화를 사용하여 보안을 강화했습니다. 클라우드프론트를 통해 파일에 접근할 수 있지만, 누구나 문서 웹사이트에 접근할 수 있도록 하고 싶지는 않을 것입니다. 따라서 사용자 인증 및 권한 부여가 필요합니다. 누구나 접근할 수 있도록 공개하는 것은 안전하지 않다는 점이 매우 중요합니다. 따라서 저희는 요구 사항에 따라 아마존 내부 개발자만 접근할 수 있도록 제한하는 간단한 메커니즘을 설계에 적용했습니다. 특정 IP 주소를 사용하는 경우에만 접근이 허용됩니다. 주소는 해당 문서에 접근할 수 있지만, 고객은 이를 Cognito와 연결하여 인증 및 권한 부여 계층을 추가함으로써 문서에 접근할 권한이 있는 사람만 접근할 수 있도록 할 수 있습니다. 이 솔루션에서 강조하고 싶은 다른 장점이 있나요? 블로그에는 다루지 않았지만 몇 가지 더 강조하고 싶은 점이 있습니다. 독자나 시청자가 활용할 수 있는 기능으로는, 예를 들어 시맨틱 검색을 구축하려는 경우 이 문서를 기반으로 OpenSearch와 SageMaker를 사용하여 벡터 데이터베이스와 같은 시스템을 구축하고 그 위에 시맨틱 검색 서비스를 만들 수 있습니다. 또한 확장성을 고려할 때, 이 블로그 게시물에서는 단일 CICD 파이프라인에 대한 문서 생성 방법을 다뤘지만, 더 많은 기능을 구현하려면 SNS와 SQS를 사용하여 모든 문서를 목차 파일로 병합하는 특정 Lambda 함수를 트리거할 수 있습니다. 여러 CICD 파이프라인이 동일한 S3 버킷에 문서를 전송할 수 있습니다. 요약하자면, 문서를 최신 상태로 유지하려면 프로그래밍 언어에 적합하고 여러 입력 형식을 지원하는 문서 생성 도구를 선택하고, CICD 파이프라인에 코드 문서 생성 기능을 포함시켜 팀 에서 코드 문서에 쉽게 접근할 수 있도록 하세요. 이 솔루션에 대해 더 자세히 알아보려면 이 영상 설명란에 있는 Ron의 블로그(LinkedIn 링크)를 참조하세요. 이 영상이 도움이 되셨다면 좋아요를 누르고 AWS Developers YouTube 채널을 구독해주세요. 다음 영상에서 뵙겠습니다. 안녕히 계세요.
