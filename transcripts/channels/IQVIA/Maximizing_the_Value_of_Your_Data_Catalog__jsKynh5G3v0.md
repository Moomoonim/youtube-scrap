## 스크립트

안녕하세요 여러분, 저는 Ivia의 Jay's Will입니다. 오늘은 데이터 카탈로그의 가치 와 그 가치를 극대화하는 방법에 대해 이야기하고 싶었습니다. 핵심은 접근 방식에 있습니다. 대부분의 조직이 하나 이상의 카탈로그 솔루션을 도입했지만, 도입 및 가치 입증에 어려움을 겪는 경우가 많습니다. 데이터 카탈로그 의 목표는 데이터를 쉽게 찾고, 데이터의 의미를 이해하고, 사용처를 파악하고, 거버넌스 프로세스를 통해 데이터 사용을 보호하고, 계약 및 규정 준수를 보장하는 것입니다. 일반적으로 데이터 마켓플레이스 방식도 비즈니스 또는 기술 사용자가 원하는 방식으로 정보를 얻을 수 있도록 지원합니다. 카탈로그 구현은 종종 통합 프로젝트로 간주됩니다. 데이터 레이크나 비즈니스 인텔리전스 도구와 같은 기술 데이터 소스가 카탈로그에 연결되고, 메타데이터와 데이터 계보가 수집됩니다. 원하는 모든 통합이 설정되면 카탈로그 구축이 완료되어 조직에 배포됩니다. 이때 사용된 데이터 소스의 수와 카탈로그에 포함된 수만 개의 데이터 자산에 대한 대대적인 홍보가 이루어집니다. 하지만 호기심 많은 비즈니스 사용자가 이 카탈로그에 로그인하면 다음과 같은 문제에 직면하게 됩니다. 비즈니스 맥락이 거의 또는 전혀 없는 테이블과 열들의 나열만 있고, 사용자가 무엇을 보고 있는지 이해하는 데 도움이 되는 정보가 전혀 없다면, 데이터 카탈로그는 그들에게 그저 쓸모없는 도구일 뿐이며 다시는 사용하지 않게 됩니다. 설상가상으로 거버넌스가 부족하고 데이터 품질이 의심스럽다면 잠재적 사용자는 더욱 멀어지게 됩니다. 대부분의 사용자가 비즈니스 기능 담당자이기 때문에, 그들이 비전문적인 용어로 이해할 수 있는 방식으로 최상의 데이터를 제공하는 데 세심한 주의를 기울여야 합니다. 카탈로그의 가치에 대한 의문은 비즈니스 맥락 부족, 메타데이터 품질, 데이터 소유권의 모호성 또는 카탈로그가 비즈니스 사용자의 기대치를 충족하지 못하는 등의 문제에서 비롯됩니다. 이러한 단점은 데이터 전문가의 참여 부족 이나 비즈니스에서 쉽게 구할 수 있는 정보의 부족에서 발생하는 경향이 있습니다. 비즈니스 맥락 수집이 시간 소모적이라는 이유로 회피되는 경우도 드물지 않으며, 구현 팀은 이를 구현 후 비즈니스에서 수행할 수 있는 작업으로 간주합니다. 바로 이러한 사고방식이 데이터 카탈로그의 성숙도를 저해합니다. 데이터 카탈로그 소프트웨어는 발전된 기술 도구이지만, 거버넌스 프로세스가 전혀 없는 곳에 프로세스를 구축하거나 데이터 자산에 대한 책임을 질 사람을 자동으로 찾아주는 것은 아닙니다. 성공적인 데이터 카탈로그 구축을 위해서는 해결해야 할 사용 사례와 그 대상을 파악하는 데 시간이 필요합니다. 팀은 목표 고객과 소통하여 데이터 카탈로그와의 상호 작용 방식, 원하는 데이터 종류, 원하는 데이터 형식을 정확히 이해해야 합니다. 또한, 다양한 사용자 페르소나에 따라 각기 다른 프레젠테이션 요구 사항이 있을 수 있다는 점을 고려해야 합니다. 자산이나 프로세스가 추가, 변경 또는 사용 중단될 경우, 정보를 최신 상태로 정확하고 관련성 있게 유지하기 위한 지속적인 관리가 매우 중요하며, 이러한 업데이트는 적시에 이루어져야 합니다. 데이터 소유자 및 데이터 관리자와 같은 핵심 역할을 정의하고 자산에 맞춰 조정하는 것이 무엇보다 중요합니다. 고품질 데이터 카탈로그 구축은 일회성 프로젝트가 아닌 지속적인 프로세스입니다. 준비가 되셨다면, 저희는 서비스 템플릿과 비즈니스 컨텍스트를 제공하여 카탈로그를 더욱 빠르게 관련성 있게 만들 수 있는 솔루션을 제시해 드릴 수 있습니다.
