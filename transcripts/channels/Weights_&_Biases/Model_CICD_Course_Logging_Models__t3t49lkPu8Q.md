## 스크립트

안녕하세요. 다음으로 모델 레지스트리 에 모델을 등록 하고 실행 결과를 모델 레지스트리에 연결하는 방법에 대해 이야기해 보겠습니다. 코드를 살펴보고 여러 구성 요소를 설명하기 전에, 문서의 중요성을 다시 한번 말씀드리고 싶습니다. 제가 설명하는 내용이 이해되지 않거나 더 자세한 정보가 필요할 때, Weights and Biases 문서를 참고하시면 좋습니다. 제가 사용하는 여러 도구 중에서 Weights and Biases는 문서 업데이트를 가장 잘하는 편입니다. 저는 Mac에서 Command + K를 눌러 검색하는 방식을 선호합니다. 예를 들어, "모델 레지스트리"를 검색하면 됩니다. ( Caps Lock이 켜져 있어서 죄송합니다.) 저는 튜토리얼부터 시작하는 것을 좋아하는데, "모델 등록" 튜토리얼이 아주 좋습니다. 모델 등록, 아티팩트 생성 등 제가 오늘 보여드릴 모든 작업을 처음부터 끝까지 자세하게 설명하는 훌륭한 예제가 있습니다. 특히, 다음 튜토리얼도 참고하시면 좋습니다. 제가 보여드릴 예제와 거의 똑같은 내용을 다루는 문서가 있는데, API 관점에서 코드가 어떻게 작동하는지 설명해 줍니다. 최소한 이 로그 모델 관련 문서를 읽어보시는 걸 강력히 추천합니다. 가이드에 튜토리얼과 가이드가 있는데, 이 문서는 '로그 모델'이라는 가이드 아래에 있습니다. 꼭 한번 살펴보세요. 자, 이제 코드로 넘어가 보겠습니다. 이 코드는 모델을 레지스트리에 연결하는 데 사용할 코드입니다. 먼저 Weights and Bias를 설치해야 합니다. 최신 버전을 설치해야 하므로 `pip install -` 명령어를 사용하세요. 다음으로 몇 가지 설정을 해야 합니다. 기존 프로젝트에 연결 하거나 새 프로젝트를 생성해야 합니다. 이 `wbit` 명령어가 바로 그 작업을 수행합니다. 그다음 아티팩트를 생성합니다. 이 경우에는 더미 아티팩트, 즉 텍스트 파일을 생성합니다. 아티팩트란 무엇일까요? 아티팩트는 다음과 같은 내용을 담고 있는 파일입니다. 모델에 대한 상태를 저장하여 다운스트림에서 추가 학습이나 추론에 사용할 수 있습니다. 이 예에서는 단순히 텍스트 파일인 더미 파일을 생성 하지만, 이는 중요하지 않습니다. 이 예제를 최소화하여 모델 로깅 및 레지스트리 연결 방법을 이해하는 데 집중할 수 있도록 하기 위한 것입니다. 자산이 무엇인지 또는 어디에 있는지 파악한 후 다음 단계는 실제로 아티팩트를 생성하는 것입니다. 따라서 이 API는 사용하기 좋은 API입니다. WB 로그 모델은 모델 유형 의 아티팩트를 로깅하기 위한 단축 표현입니다. 따라서 여기서는 아티팩트 이름인 model-wb를 전달합니다. 실행 ID에는 아티팩트 경로를 지정해야 하는데, 이 경우에는 이 텍스트 파일입니다. 그다음 별칭(alias)을 지정합니다. 별칭은 아티팩트에 첨부할 수 있는 메타데이터로, 아티팩트의 수명 주기를 나타내는 데 사용할 수 있습니다. 원하는 방식으로 사용할 수 있지만, 모델이 수명 주기에서 어느 단계에 있는지 알 수 있도록 별칭을 만드는 것이 좋습니다. 제가 선호하는 태그의 예로는 Dev, staging, Review, production 등이 있습니다. 이러한 다양한 별칭은 모두 유용합니다. 이제 이 코드를 실행해 보겠습니다. 이 코드는 실행에 아티팩트를 업로드하고 링크를 생성합니다. 이 링크를 클릭해 보겠습니다. 이 실행에는 아티팩트 외에는 아무것도 기록되지 않았습니다. 이 보기에서 해당 실행의 개요를 살펴보겠습니다. 이 실행에서는 특별한 일이 발생하지 않았지만 아티팩트가 있습니다. 이 경우 모델 유형의 아티팩트가 기록되었습니다. 이 아티팩트를 클릭하면 다음으로 눈에 띄는 것이 있습니다. 이제 이 아티팩트를 레지스트리에 연결할 수 있습니다. 레지스트리에 연결하는 방법은 여러 가지가 있지만, 크게 UI를 사용하는 방법과 코드를 사용하는 방법 두 가지로 나눌 수 있습니다. 먼저 UI를 사용하는 방법을 보여드리겠습니다. 그래야 작동 방식을 쉽게 이해할 수 있을 겁니다. UI 사용법을 익히신 후에는 코드를 사용하셔도 됩니다. 여기에서 코드에서 사용한 여러 별칭과 몇 가지 기본 별칭을 보실 수 있습니다. weights and biases는 자동으로 최신 버전을 추가하고 의미론적 버전 관리를 수행합니다. 별칭이 이미 추가되어 있습니다. 노아, weights and biases에서 기본적으로 추가하는 이 두 태그에 대해 설명해 주시겠습니까? 어떻게 작동하는지 궁금합니다. 네, 좋습니다. 해밀이 언급했듯이, 별칭을 사용하는 방식, 또는 모델 버전 에 별칭을 연결하는 아이디어는 특정 모델 버전을 나타내는 의미론적으로 친숙한 식별자 역할을 하도록 하는 것입니다. 따라서 모델 버전을 일일이 기억할 필요가 없습니다. 이것은 제가 작업 중인 이 아티팩트의 세 번째 버전입니다. 이 특정 경우에는 아티팩트에 버전이 하나만 있지만, 하이퍼파라미터를 조정하거나 체크포인트 마다 모델을 로깅하는 등 여러 버전을 사용하는 경우를 생각해 보세요. 그러면 체크포인트가 100개나 있는 아티팩트가 생길 수 있습니다. 별칭은 의미론적으로 친숙한 식별자를 사용하여 코드에서 나중에 아티팩트를 참조할 수 있도록 하는 방법입니다. 특정 버전 번호를 기억하는 대신 말이죠. ' latest'는 기본 별칭 중 하나이며, 저희는 별칭을 추가하여 항상 'latest' 별칭을 가리키는 포인터를 유지합니다. ' latest' 별칭은 아티팩트에 추가된 가장 최근 모델 버전을 가리키는 포인터 역할을 합니다. 따라서 코드에서 이 모델을 참조하거나 사용할 때 'latest' 별칭을 사용하면 모델이 버전 관리되는 동안에도 항상 최신 버전을 참조할 수 있습니다. 항상 최신 버전을 가리키고 있는지 확인하는 방법이 있습니다. 다른 별칭도 추가했는데, 기본적으로 v0과 같은 버전이 표시됩니다. 버전 수를 늘리면 자동으로 카운트를 유지하고, 아티팩트의 파일이 변경될 때마다 다음 버전으로 증가합니다.
