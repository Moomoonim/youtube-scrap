## 스크립트

안녕하세요. 이 짧은 비디오에서는 클라이언트 측 관점에서 인증에 대해 알아보겠습니다. 다양한 인증 설정을 통해 WebIate에 액세스하는 방법을 보여드리겠습니다. 이를 위해 Vv8 클라우드 서비스(WCS라고도 함)의 VVA 인스턴스와 함께 Python 클라이언트를 사용하겠습니다. 하지만 다른 클라이언트에서도 원리는 동일하며, Docker나 Kubernetes와 같은 다른 방식으로 인스턴스를 실행할 수도 있습니다. 자, 시작해 볼까요? 먼저 사용할 WCS 인스턴스를 살펴보겠습니다. 여기 제 WCS 대시보드가 ​​있습니다. 표준 클러스터 하나와 샌드박스 인스턴스 두 개를 포함하여 총 세 개의 Wavy8 인스턴스가 있는 것을 볼 수 있습니다. WCS 클러스터는 유형에 따라 다양한 인증 옵션을 제공합니다. 클러스터 세부 정보를 보려면 여기 있는 세부 정보 버튼을 클릭해 보겠습니다. URL과 WebIate 버전을 포함하여 유용한 정보가 많이 표시됩니다. 우리가 필요한 것은 인증 정보입니다. 여기 있는 버튼을 클릭하면 API 키를 볼 수 있습니다. 이 키는 나중에 로그인하는 데 사용됩니다. 여기에 숨겨진 키가 있는 것을 볼 수 있는데, 이것은 API 키는 해당 vv8 클러스터 에 접근하는 데 사용될 수 있으므로 비밀번호처럼 취급해야 합니다. 이 클러스터는 관리자 키와 읽기 전용 키, 두 가지 키를 제공합니다. 두 키의 차이점은 쉽게 짐작할 수 있지만, 나중에 자세히 설명하겠습니다. 한편, 이 샌드박스 인스턴스는 인증이 필요하지 않도록 설정되어 있습니다. 이는 보안에 취약하며, 간편한 실험을 위한 옵션으로만 제공됩니다. 마지막으로 다른 샌드박스 인스턴스를 살펴보겠습니다. 이 인스턴스는 인증이 설정되어 있으며, 샌드박스를 생성할 때 기본 옵션입니다. API 키를 보면 관리자 키만 포함되어 있는 것을 알 수 있습니다. 읽기 전용 키는 프로덕션 클러스터에서만 제공됩니다. 이제 인증 정보를 얻었으니, Waviate 클라이언트를 사용하여 Waviate 서버와 상호 작용하는 방법을 살펴보겠습니다. 앞서 살펴본 Wii V8 서버 두 곳에 다양한 인증 방법을 사용하여 연결하는 방법을 보여주는 Jupyter Notebook을 준비했습니다. 공개 샌드박스 인스턴스와 인증이 필요한 프로덕션 인스턴스를 사용하겠습니다. URL은 다음과 같이 정의합니다. 익명 액세스부터 시작해 보겠습니다. 공개 인스턴스는 사용자 자격 증명이 필요하지 않으므로 이전에 정의한 URL만 있으면 액세스할 수 있습니다. 클라이언트는 이제 바로 사용할 수 있습니다. 좋습니다. 이제 비공개 인스턴스에서 같은 작업을 시도하면 어떻게 될까요? 클라이언트가 서버에 액세스할 수 없다는 오류를 발생시키는 것을 볼 수 있습니다. 오류 메시지를 살펴보면 로그인 자격 증명이 부족하기 때문임을 알 수 있습니다. 이제 이러한 자격 증명을 제공하는 방법을 살펴보겠습니다. 여러 클라이언트 인스턴스를 생성하여 비교해 보겠습니다. 첫 번째 옵션은 API 키를 사용하는 것입니다. 로그인 자격 증명을 전달할 때 API 키에 대한 추가 인수를 ` auth client secret` 매개변수를 통해 전달해야 합니다. 여기에 표시된 것처럼 `auth API key` 클래스를 사용하고 키는 문자열로 지정합니다. 저는 환경 변수에 저장했지만 다른 방법으로 전달할 수도 있습니다. 일반적으로 스크립트에서 키나 암호를 이런 식으로 또는 파일에서 읽어오는 것이 더 안전합니다. 이렇게 하면 공유될 수 있는 스크립트나 노트북에 노출되지 않습니다. 이제 모든 준비가 완료되었습니다. 이전에는 예외가 발생했지만, 이번에는 사용자 이름과 비밀번호를 사용하여 인스턴스에 액세스해 보겠습니다. 이 과정은 OIDC(Open ID Connect)라는 표준 프로토콜을 사용하는데, 내부적으로는 조금 더 복잡합니다. IE 인스턴스와 WCS는 WCS 자격 증명을 기반으로 사용자를 인증하도록 구성되어 있으므로, 다음과 같이 자격 증명을 전달할 수 있습니다. 여기서는 ` authclientpassword`라는 다른 클래스를 사용하고 WCS 사용자 이름과 비밀번호를 전달하고 있습니다. 이러한 자격 증명은 모든 WCS 인스턴스에서 사용할 수 있지만, 각 API 키는 특정 웹 인스턴스에만 고유합니다. 마지막으로, 읽기 전용 키를 사용하여 클라이언트 인스턴스를 생성해 보겠습니다. 앞서 살펴본 것처럼 프로덕션 인스턴스에는 읽기 전용 키가 제공되므로, 이 예제에서는 해당 키를 사용합니다. 이전과 마찬가지로 클라이언트가 준비되었으므로, 이제 제대로 작동하는지 테스트해 보겠습니다. 먼저 간단한 쿼리를 실행하여 정의한 클라이언트 인스턴스 목록을 딕셔너리로 ​​만들고, 루프를 돌면서 각 클라이언트 인스턴스에 대한 객체를 하나씩 가져오겠습니다. 각 객체가 제대로 작동하는 것을 확인할 수 있습니다. 이제 Waviate에서 데이터를 가져올 수 있습니다. 같은 과정을 사용하여 Waviate에 데이터를 써보겠습니다. 클래스를 생성하고 추가되었는지 확인하는 헬퍼 함수를 ​​정의했습니다. 성공적으로 추가되면 다시 삭제합니다. 이 함수를 루프에서 실행합니다. 또한 발생할 수 있는 예외를 처리하도록 설정했습니다. 셀을 실행하면 생성된 4개의 인스턴스 중 3개는 정상적으로 작동하지만, 하나는 예외를 발생시킵니다. 예상대로 읽기 거부 예외가 발생하는데, 이름에서 알 수 있듯이 Aviate 서버를 수정하는 것이 허용되지 않기 때문입니다. 이것으로 Python 클라이언트를 사용하여 Waviate에 로그인하거나 인증하는 방법을 보여주는 데모가 끝났습니다. 보시다시피 서버 설정과 일치하는 올바른 인증 구성을 사용하는 것이 중요합니다. 올바른 구성 클래스를 사용해야 하며, 각 ID는 서로 다른 수준의 권한을 가질 수 있으므로 적절한 자격 증명으로 인증해야 합니다. 더 자세한 내용은 문서를 참조하십시오. 인증에 다양한 클라이언트를 사용할 수 있다는 것을 확인하거나 WCS에서 인스턴스를 생성하는 방법을 배우기 위해 시청해 주셔서 감사합니다. 다음에 또 뵙겠습니다.
