## 스크립트

안녕하세요, 반갑습니다! 방금 출시된 W 1.22 버전을 소개하게 되어 매우 기쁩니다. 이번 버전에는 사용성과 성능을 더욱 향상시키는 여러 가지 흥미로운 기능이 포함되어 있습니다. 함께 살펴보겠습니다. 1.22 버전에서는 중첩 객체 정렬 기능과 비동기 Spector 인덱싱이 추가되었습니다. 또한 gRPC 지원이 공식적으로 제공되고, 완전히 새로운 V4 파이썬 클라이언트 베타 버전이 출시되었습니다. 정말 기대되는 소식입니다! 이번 업데이트에는 훌륭한 기능들이 많이 포함되어 있으니, 자세히 살펴보겠습니다. 먼저 중첩 객체 저장 기능부터 시작해 보겠습니다. 이 변경 사항은 개별 객체와 객체 배열을 저장할 수 있는 두 가지 새로운 데이터 유형을 도입했습니다. 왜 이것이 중요한지 설명해 드리겠습니다. 중첩 객체를 사용하지 않으면 모든 속성이 같은 레벨에 있는 다음과 같은 평면 구조가 됩니다. 즉, 모든 키가 같은 레벨에 있어야 한다는 의미입니다. 하지만 실제 데이터는 종종 다음과 같은 형태를 띱니다. 여기에서 도시와 거리 이름이 모두 ' 주소'라는 키 아래 두 번째 레벨에 저장되어 있습니다. 이러한 데이터 구조는 수정 없이는 평면 구조로 저장할 수 없습니다. 따라서 각 속성을 중첩할 수 있는 속성 데이터 유형을 도입했습니다. 객체 데이터 유형은 자체적으로 중첩 속성을 가질 수 있으며, 이러한 중첩 속성은 어떤 데이터 유형이든 가능합니다. 또한 자동 스키마 기능을 사용하여 중첩 속성을 추론할 수 있어 편리하지만, 항상 그렇듯이 수동으로 정의하는 것이 가장 큰 제어 권한을 제공합니다. 이 기능은 현재 1.22 버전에서 처음 구현되었기 때문에 몇 가지 제한 사항이 있습니다. 이러한 객체 데이터 유형에 저장된 데이터는 벡터에 영향을 미치지 않으며, 아직 인덱싱되지 않아 필터링에 사용할 수 없습니다. 이 기능을 추가할 예정이므로, 이 기능이 중요한 경우 GitHub 이슈에 해당 기능을 업로드해 주세요. 다음은 비동기 벡터 인덱싱입니다. 비동기 인덱싱이란 무엇일까요? 먼저 동기 벡터 인덱싱을 살펴보겠습니다. 동기 인덱싱에서 요청된 각 데이터는 다음과 같습니다. Wave8의 경우 요청을 수신하고, 데이터 객체를 생성하고, 벡터 인덱스에 추가한 다음 클라이언트로 응답을 보냅니다. 이 프로세스의 어려움은 Wave8이 처리해야 할 작업이 많다는 것입니다. Wave8은 매우 빠르지만, 수천만 개의 객체를 처리하거나 특정 배치에 많은 데이터를 전송하는 경우 처리 시간이 오래 걸릴 수 있습니다. 새로운 비동기 인덱싱으로 인해 타임아웃이 발생할 수도 있습니다. Weia는 응답을 보내기 전에 데이터 객체를 생성하고 벡터 인덱싱 프로세스는 이제 백그라운드에서 실행됩니다. 이러한 기능은 데이터베이스 준비 속도를 높이고 개별 타임아웃 발생 가능성을 줄여줍니다. 이 기능은 실험적인 기능이므로 아직 프로덕션 환경에 바로 적용할 수는 없지만, 사용해보고 싶다면 비동기 인덱싱을 true로 설정하여 활성화할 수 있습니다. 검색은 이미 인덱싱된 객체와 최대 10만 개의 객체를 무차별 대입 방식으로 검색하여 처리됩니다. 122 버전에서는 gRPC 지원도 공식적으로 추가되었는데, 이는 속도 향상에 특히 도움이 됩니다. 즉, 배치 가져오기 및 GET 쿼리 속도가 빨라집니다. 어떻게 가능할까요? 그 비결은 gRPC가 내부적으로 HTTP2를 사용한다는 점입니다. HTTP2는 1.1보다 빠른 프로토콜이며, 바이너리 페이로드를 사용하기 때문에 JingJon보다 효율적입니다. gRPC를 사용하려면 GitHub 의 W 저장소에서 프로토콜 버퍼를 확인하거나 새로운 V4 Python 클라이언트를 사용할 수 있습니다. gRPC 지원이 내장되어 있으며, 앞으로 다른 클라이언트에도 지원을 추가할 예정입니다. 이제 V4 파이썬 클라이언트에 대해 말씀드리겠습니다. 여기에는 많은 변경 사항이 있으며, 주요 변경 사항으로는 개발자 경험 개선과 속도 향상이 있습니다. V4 클라이언트 개발의 가장 큰 동기는 API 검토였으며, 새롭고 더욱 파이썬스러운 API를 통해 이를 달성했다고 생각합니다. 다음은 클래스를 정의하는 기존 구문의 예입니다. 기존 구문에서는 다음과 같이 딕셔너리를 사용했습니다. 새로운 구문을 사용한 동일한 코드는 다음과 같습니다. 최신 IDE에서 더 많은 도움을 제공하는 파이썬 클래스와 함수가 많이 사용되었으며, 더 이상 원시 딕셔너리를 사용하지 않습니다. 쿼리도 더 간편해졌습니다. 다음은 V3 클라이언트를 사용한 거의 텍스트 쿼리 이고, 다음은 새 클라이언트를 사용한 동일한 쿼리입니다. 훨씬 깔끔해 보이며, 경험상 사용하기가 훨씬 쉽습니다. 베타 버전이므로 여러분의 의견을 기다립니다. 포럼에 피드백 스레드가 있으니 크고 작은 문제 또는 개인적인 의견 등 무엇이든 남겨주세요. 얼마나 마음에 드셨는지 알려주시면 감사하겠습니다. we8 1.22는 오픈 소스 소프트웨어로 제공되므로 직접 실행하거나 다양한 클라우드 배포 옵션을 통해 이용하실 수 있습니다. 시청해 주셔서 감사합니다. 곧 다시 뵙겠습니다.
