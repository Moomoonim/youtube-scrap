## 스크립트

안녕하세요 여러분, 저는 스벤 미들버그입니다. CUDA 개발자 도구 비디오 시리즈에 다시 오신 것을 환영합니다. 시리즈의 첫 번째 에피소드에서 로비는 Insight 도구 생태계를 소개하고, Insight가 제공하는 도구와 일반적인 프로파일링 워크플로에 대해 설명했습니다. 이번 비디오에서는 시스템 내부 분석에 초점을 맞추겠습니다. 이는 모든 프로파일링 여정의 시작점이 되는 경우가 많습니다. 로비가 설명했듯이 Insight 시스템을 사용하면 모든 NVIDIA GPU 가속 애플리케이션을 추적하여 사용 가능한 모든 하드웨어 리소스와 활성 프로세스를 포함한 전체 시스템의 전체 모습을 이해하기 쉽고 시각적으로 보기 좋은 타임라인으로 확인할 수 있습니다. 이를 통해 성능 문제를 정확히 파악 하고 최적화 기회를 식별할 수 있습니다. 성능 저하의 원인은 다양할 수 있습니다. GPU에서 실행되는 일부 커널이 너무 오래 걸리거나 CPU의 특정 처리 단계가 병목 현상을 일으킬 수 있습니다. 마찬가지로 디스크 I/O 또는 PCIe 버스를 통한 CPU-GPU 복사 작업도 최적화할 수 있습니다. 성능 조사 외에도 Insight 시스템은 비동기 GPU 컴퓨팅을 위한 EDL 디버깅 도구입니다. 오늘은 Insight 시스템을 시작하는 데 도움을 드리고자 합니다. Insight 시스템을 어디에서 다운로드하고, NVIDIA GPU 가속 애플리케이션을 추적하고, 워크플로를 살펴보겠습니다. 추적 대상을 사용자 지정할 수 있는 다양한 설정을 모두 안내해 드립니다. 최신 Insight Systems 버전은 Insight Systems 학습 페이지에서 다운로드할 수 있습니다. 여기에서 다양한 프로파일링 대상용 설치 프로그램을 찾을 수 있습니다. Linux 워크스테이션 및 서버용 설치 프로그램, Windows 워크스테이션 및 게임용 PC용 설치 프로그램이 있습니다. 또한 임베디드 컴퓨팅 및 엣지 AI를 위한 Jetson 및 IGX 플랫폼용 설치 프로그램과 자율 주행 차량 플랫폼인 Drive 제품용 설치 프로그램도 있습니다. 대상 시스템을 원격으로 프로파일링하는 옵션도 있으며, 호환성 지표를 통해 특정 호스트 시스템 에서 어떤 대상 시스템을 프로파일링할 수 있는지 확인할 수 있습니다. Mac 시스템에서는 NVIDIA 하드웨어 프로파일링을 지원하지 않지만, Mac에서 설정된 시스템을 사용하여 원격 Windows 또는 Linux 대상 시스템을 프로파일링할 수 있습니다. 해당 설치 프로그램을 실행하면 설치 과정이 안내됩니다. 제 Windows 컴퓨터에는 이 비디오를 녹화할 당시 최신 Insight Systems 버전 2023.2가 이미 설치되어 있습니다. Insight Systems를 열고 NVIDIA GPU를 추적하는 방법을 보여드리겠습니다. 처음 실행 시 NSAID 시스템에서 첫 번째 프로젝트가 이미 생성되어 있습니다. 창 왼쪽에는 프로젝트 탐색기가 있는데, 이를 통해 필요에 따라 추적 데이터를 여러 프로젝트로 정리할 수 있습니다. 이 프로젝트 이름을 ' 프로젝트 1'보다 더 설명적인 이름으로 변경해 보겠습니다. ' Hello Insight'로 변경하면 오른쪽에 현재 열려 있는 프로젝트의 프로젝트 창이 표시됩니다. 먼저 프로파일링 대상을 지정해야 합니다. 프로파일링 대상은 관심 있는 애플리케이션을 추적할 시스템입니다. 원격 시스템에서 추적하려면 SSH 또는 USB 연결을 통해 프로파일링 대상을 선택할 수 있습니다. SSH는 Docker 및 원격 Linux 인스턴스에 적합하고, USB는 주로 Jetson 및 드라이브 플랫폼을 대상으로 합니다. 저는 로컬에서 추적하려고 하므로 대상 시스템은 호스트 시스템과 동일하며, 추적 대상으로 'localhost'를 선택하겠습니다. 이제 추적 대상을 사용자 지정할 수 있는 여러 옵션이 나타납니다. 유일한 설정은 추적할 실행 파일인 대상 애플리케이션입니다. 데모를 위해 Nvidia GitHub에서 제공되는 ' Vector at Cooler' 샘플을 추적해 보겠습니다. 이 샘플은 두 입력 배열을 GPU 메모리에 복사하고 CUDA 커널을 실행하여 계산한 후 결과를 다시 CPU 메모리에 복사하는 방식으로 두 배열의 요소 y의 합을 계산합니다. 샘플에는 명령줄 옵션이 없지만, 필요한 경우 여기에 지정할 수 있습니다. 보시다시피, Inside Systems는 추적할 실행 파일이 있는 디렉터리로 환경의 작업 디렉터리를 자동으로 설정합니다. 물론 필요에 따라 사용자 지정할 수도 있습니다. 명령줄 작업 디렉터리는 필수 설정이지만, 추적 오버 헤드를 최소화하기 위해 관심 있는 이벤트와 메트릭만 캡처하도록 다른 설정도 조정하는 것이 좋습니다. 캡처되는 모든 이벤트 또는 메트릭은 오버헤드를 발생시키는데, 이 오버헤드는 이벤트 또는 메트릭 자체뿐만 아니라 추적 대상 실행 파일에도 따라 달라집니다. 따라서 오버헤드를 최소화하기 위해 여러 번 실행하여 서로 다른 이벤트와 메트릭을 추적하는 것이 효과적일 수 있습니다. Inside Systems에서 추적할 모든 이벤트 및 메트릭 과 샘플링 빈도는 대상 애플리케이션 탭에서 구성할 수 있습니다. 다양한 사용자 지정 옵션이 있지만 일반적으로 이러한 옵션 중 일부만 활성화하는 것이 좋습니다. 각 설정을 자세히 설명하는 것은 이 페이지의 범위를 벗어납니다. 이 비디오의 범위를 벗어나지 만, 자세한 설명은 Insight Systems 사용자 가이드를 참조하세요. 간단히 말해서, 이러한 기능들은 QDF, Vulkan, OpenGL, DirectX와 같은 다양한 컴퓨팅 그래픽 API와 관련된 메트릭 수집을 활성화 또는 비활성화합니다. 이를 통해 모든 종류의 CPU 및 GPU 활동을 추적하여 애플리케이션 내부에서 발생하는 상황을 더 잘 이해하고 성능 병목 현상을 식별할 수 있습니다. 특히 언급할 가치가 있는 것은 NVIDIA에서 제공하는 라이브러리인 NBTX입니다. 이 라이브러리를 애플리케이션에서 사용하여 소스 코드 내의 특정 이벤트 및 섹션을 표시 하고 Insight Systems에서 볼 수 있도록 할 수 있습니다. NBTX에 대해서는 시리즈 후반부에서 자세히 다룰 예정입니다. 벡터 추적 예제를 위해 CUDA API와 관련된 샘플 수집만 활성화해 보겠습니다. 보시다시피 제 경우에는 CUDA 샘플 수집이 이미 활성화되어 있으므로 해당 항목은 그대로 두고 나머지는 모두 비활성화합니다. 오른쪽에는 추적 범위 또는 시간 범위를 제한하는 다양한 옵션이 있습니다. Apple의 데이터 수집 분석에는 시간이 걸릴 수 있으므로, 특정 기간 동안만 추적하고 애플리케이션 시작 및 종료 시간 전체를 샘플링하지 않으려는 경우에 유용합니다. 샘플 추적 시 벡터는 매우 최소화되어 있으므로 프로세스의 전체 수명 주기를 추적하는 것으로 충분하며 이러한 옵션은 선택하지 않아도 됩니다. 이제 남은 작업은 시작 버튼을 클릭하는 것뿐입니다. 그러면 Insight Systems가 지정된 명령 줄을 실행하여 구성된 모든 샘플을 수집 하고 처리하여 내부 시스템 보고서를 생성합니다. 이 과정에서 명령줄 실행을 기다리는 동안 Insight Systems가 모든 샘플을 수집하고 처리하는 동안 이 모든 작업을 수행할 수 있습니다. 이 모든 작업은 Insight Systems 명령줄 인터페이스를 사용하여 GUI 없이도 구성하고 완료할 수 있습니다. 자세한 방법은 사용자 가이드를 참조하십시오. Insight Systems 보고서는 ANSYS 명령줄 유틸리티를 사용하여 수집된 샘플과 파생된 메트릭의 데이터베이스입니다. 이 데이터베이스는 SQLite, 오류, JSON 등 다양한 형식으로 내보낼 수 있습니다. 이는 숙련된 사용자를 위한 기능입니다. 내보내기 기능을 통해 사용자의 필요에 따라 수집된 데이터를 사용자 지정으로 분석하고 시각화할 수 있습니다. 하지만 Insight Systems GUI에는 보고서 타임라인 보기라는 편리하고 탐색하기 쉬운 시각화 기능이 이미 내장되어 있습니다. 타임라인 보기는 시스템에서 발생하는 상황을 시간 순서대로 시각화한 것입니다. 추적 기간 동안 가로축은 시간에 따라 진행되고 세로축은 수집된 데이터가 쌓여 표시되는 타임라인 은 시각적으로 보기 좋고 시스템의 어느 부분에서 무슨 일이 일어나고 있는지 쉽게 파악할 수 있도록 해줍니다. 타임라인 보기와 탐색 방법에 대한 자세한 내용은 별도의 비디오를 통해 설명드리겠습니다. 지금 바로 확대해서 이 간단한 Vector at 샘플의 타임라인을 보여드리겠습니다. 스레드 탭에서 애플리케이션이 실행되는 단일 CPU 스레드와 모든 CUDA API 호출을 볼 수 있습니다. 먼저 CUDA malloc을 사용하여 입력 및 출력 데이터를 위한 GPU 메모리를 할당합니다. 그런 다음 CUDA mem copy를 사용하여 입력 데이터를 CPU에서 GPU 메모리로 복사합니다. 이어서 Vector at CUDA 커널을 실행하여 입력 데이터의 일부를 사용하여 요소를 계산하고 결과를 GPU 메모리의 출력 배열에 기록합니다. 이 출력 배열은 또 다른 CUDA mem copy 호출을 통해 CPU 메모리로 다시 복사됩니다. 마지막으로 freeze 호출을 통해 이전에 할당된 모든 GPU 리소스를 정리합니다. 이 모든 것은 CPU 스레드에서 실행되는 런타임 API 호출입니다. PCIe 버스에서도 입력 및 출력 데이터의 실제 복사본을 확인할 수 있습니다. GPU에서 실행되는 쿨러 커널을 확인하려면 타임라인 상단의 CUDA 하드웨어 탭을 열어야 합니다. 좀 더 확대해 보면 CPU 에서 GPU 메모리로 복사되는 두 개의 입력 벡터를 볼 수 있습니다. 파란색 블록은 GPU에서 실행되는 CUDA 커널에 해당하고, 여기는 출력 버퍼가 CPU로 복사되는 것을 보여줍니다. 각 블록 위에 마우스를 올리면 더 자세한 정보를 확인할 수 있습니다. 예를 들어, CPU에서 GPU 메모리로의 첫 번째 메모리 복사 위로 마우스 커서를 이동하면 복사 시간, 달성된 PCIe 처리량과 같은 유용한 정보를 제공하는 툴팁이 표시됩니다. 커널의 경우 실행 시간, 공유 메모리 사용량, 점유율 등의 데이터도 얻을 수 있습니다. CUDA 화면 녹화기가 실행된 시간도 확인할 수 있습니다. 앞서 언급했듯이 타임라인 보기에 대한 자세한 내용은 별도의 비디오에서 다룰 예정이므로 여기서는 자세히 설명하지 않겠습니다. 타임라인 보기는 가장 많은 시간을 보내게 되는 보기 방식이지만, 시스템 설정에는 필요에 따라 살펴볼 수 있는 세 가지 보고서 탭이 더 있습니다. 분석 요약 탭은 보고서의 개략적인 요약을 제공합니다. 이 경우 프로파일링 세션, 추적된 시스템, 추적 설정에 대한 정보를 확인할 수 있습니다. 내부 시스템 버전과 디버그 정보가 표시됩니다. 진단 요약 탭에는 추적 중에 문제가 발생했을 때 시스템에서 보고된 중요한 메시지가 표시됩니다. 경고 및 오류 메시지도 여기에 나타납니다. 마지막으로 파일 단계는 몇 가지 구성 및 로그 파일을 가리킵니다. 예를 들어 표준 출력 및 오류 스트림에 기록된 로그 파일 등이 있습니다. 오늘은 여기까지입니다. 이 영상이 유용했기를 바랍니다. 지금까지 안드로이드 시스템의 기능 중 극히 일부만 다뤘으니, 다음 영상도 기대해 주세요. 시청해 주셔서 감사합니다.
