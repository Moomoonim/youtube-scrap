## 스크립트

ADK? A2A? MCP? 에이전트를 구축하려고 하다 보면 이러한 약어들을 접하게 될 것입니다. 자 , 그럼 불필요한 소음을 제거하고 핵심만 짚어봅시다. 다음 15분 동안 우리는 세 가지 일을 할 것입니다. MCP 도구를 생성하고 서버로 배포합니다 . ADK를 사용하여 에이전트를 생성합니다. 그리고 A2A를 통해 에이전트를 노출시키고 테스트해 보세요 . 이 영상의 모든 단계를 따라하면 이러한 개념을 이해하고 튜토리얼이 끝날 때쯤에는 작동하는 AI 에이전트를 만들 수 있을 것입니다. 먼저 MCP, 즉 모델 컨텍스트 프로토콜에 대해 살펴보겠습니다. 이것은 역방향 프록시 또는 API 서버를 위한 API 서버라고 생각할 수 있습니다. 이는 AI 모델을 특정 리소스, 프롬프트 및 도구에 연결하여 작업을 완료하는 표준적인 방법입니다. 다음으로 에이전트 개발 키트(ADK)를 사용하겠습니다 . 이것은 에이전트를 실제로 구축하고 배포하기 위한 프레임워크입니다. 이 시스템은 복잡한 에이전트를 소프트웨어 개발처럼 간단하게 만들 수 있도록 설계되었습니다. 마지막으로, 에이전트 간 프로토콜(A2A)을 사용하겠습니다. A2A는 에이전트 구축이 완료되면, 누가 구축했는지, 어디에 호스팅되어 있는지, 어떤 프레임워크 나 프로그래밍 언어를 사용하는지에 관계없이 다른 에이전트와 통신하고 협업할 수 있도록 공통 언어를 제공합니다. 이 튜토리얼을 마치면 로컬 MCP 서버를 설정하고 클라우드에 배포하는 실습 경험을 쌓게 될 것입니다 . ADK를 사용하여 자체 에이전트를 구축한 다음 A2A 프로토콜을 사용하여 테스트합니다 . 이 과정을 따라하려면 브라우저와 결제가 활성화된 Google Cloud 프로젝트가 필요합니다. 준비가 된? 자, 시작해 볼까요? 먼저 구글 클라우드 환경을 설정해야 합니다. 아직 Google Cloud 프로젝트가 없다면 새 프로젝트를 만들고 결제가 사용 설정되어 있는지 확인하세요. 오늘 우리는 모든 작업을 클라우드 셸 내에서 진행할 것입니다. Cloud Shell을 열려면 콘솔에서 활성화 아이콘을 클릭하기만 하면 됩니다. 일단 창이 열리면 명령어를 실행할 터미널과 코드를 살펴볼 편집기 사이를 쉽게 전환할 수 있습니다. 이 튜토리얼에서는 두 가지 모두를 사용할 것입니다 . 자 , 이제 터미널에서 첫 번째 명령어를 실행하여 인증이 제대로 되었는지 확인해 보겠습니다. 자, 이 부분이 중요합니다. 우리가 생성하는 모든 리소스가 프로젝트와 연결되도록 프로젝트 ID를 설정해야 합니다. 콘솔에서 프로젝트 ID를 찾고 다음 명령을 실행하세요. 단, 프로젝트 ID는 실제 ID로 바꿔야 합니다. 먼저 환경 변수로 내보내면 다음 명령어가 좀 더 깔끔해집니다. 프로젝트 설정이 완료되었으므로 이제 에이전트가 사용할 특정 API를 활성화해야 합니다 . 여기에는 Cloud Run, Cloud Build, Artifact Registry 및 Vertex AI용 API가 포함됩니다. 이 명령 하나만으로 모든 기능을 활성화할 수 있습니다 . 이 단계는 완료하는 데 몇 분 정도 소요될 수 있습니다. 마지막으로 한 번 더 확인하겠습니다. 이 프로젝트를 실행하려면 Python 3.10 이상 버전이 필요합니다 . 이는 클라우드 셸 환경의 기본값이어야 하지만, ` python3 version` 명령을 실행하여 빠르게 확인할 수 있습니다 . 좋아요. 저희 프로젝트와 API는 이제 모두 준비되었습니다. 같은 클라우드 셸 터미널에서 프로젝트 소스 코드를 다운로드해야 합니다. 같은 세션에서 계속 진행하는 것이 중요합니다 . 따라서 우리는 이전 단계 에서 설정했던 프로젝트 ID 변수에 계속 접근할 수 있습니다 . 먼저 GitHub에서 프로젝트 저장소를 복제해 보겠습니다. 다운로드가 완료되면 새 프로젝트 디렉토리로 이동하겠습니다. 이 프로젝트는 UV라는 도구를 사용하여 파이썬 종속성을 관리합니다. 여기에 나와 있는 curl 명령어를 실행하여 설치하겠습니다. 간단히 알려드릴 사항이 있습니다. 다음 단계에서 UV를 찾을 수 없다는 오류가 발생하는 경우, UV 설치가 인식되도록 새 터미널 탭을 열어야 할 수 있습니다. 만약 그렇게 하셨다면, 잊지 말고 다시 환전 대리점 디렉토리로 돌아가세요. 이제 애플리케이션의 환경 변수를 구성해야 합니다. 다음 명령은 env 파일을 생성하고 이전 단계에서 얻은 프로젝트 ID 변수를 사용하여 해당 파일에 내용을 채웁니다. 파일이 제대로 생성되었는지 확인하기 위해 파일 내용을 빠르게 살펴보겠습니다. 프로젝트 ID가 채워진 세 개의 변수가 출력되는 것을 확인할 수 있습니다. 코드 다운로드와 환경 설정이 완료되었으므로 이제 MCP 서버를 설정할 수 있습니다. 이제 시스템의 첫 번째 주요 구성 요소인 MCP 서버를 구축할 차례입니다. 서버의 역할은 우리 에이전트가 사용할 수 있는 도구를 제공하는 것입니다. 저희의 경우, 환율 정보를 가져올 수 있는 도구가 필요합니다. 우리는 Fast MCP라는 파이썬 패키지를 사용하여 서버를 구축할 것입니다. Fast MCP는 간단한 데코레이터와 파이썬 함수를 사용 하여 MCP용 서버와 클라이언트를 빠르고 직관적으로 구축할 수 있도록 지원하는 파이썬 프레임워크입니다 . 클라우드 셸 편집기를 사용하여 MCP 서버의 server.py 파일에 있는 코드를 살펴보겠습니다 . 이 파일의 핵심 부분은 환율을 가져오는 함수입니다. 위에 있는 MCP 툴 데코레이터는 이 함수를 서버에서 노출할 도구로 등록하는 역할을 합니다. 해당 함수 자체는 환율을 가져오기 위해 외부 API를 호출합니다. 자, 이제 클라우드 셸 터미널에서 이 서버를 실행해 보겠습니다 . 이렇게 하면 8080 포트에서 서버가 시작됩니다. 서버가 실행되면 테스트해야 합니다. 서버를 중지하지 않으려면 새 Cloud Shell 탭에서 이 작업을 수행하는 것이 중요합니다. 새 탭에서 통화 에이전트 디렉터리에 있는지 확인 하고 테스트 스크립트를 실행하십시오. 테스트 스크립트는 로컬호스트 클라이언트에 연결하여 도구를 호출하는 간단한 작업만 수행합니다. 출력 결과에 미국 달러와 유로화의 현재 환율을 보여주는 성공 메시지가 표시될 것입니다. 이는 MCP 서버가 정상적으로 작동 중임을 확인시켜 줍니다 . 완벽한. 첫 번째 터미널 탭에서 Ctrl C를 눌러 서버를 중지하세요 . 다음 단계에서는 이 서버를 클라우드에 배포하겠습니다. 저희 MCP 서버는 작동 하지만, 대화형 클라우드 셸 세션에서만 실행되므로 일시적인 것입니다. 이를 상담원에게 영구적이고 안정적인 도구로 만들기 위해서는 독립형 서비스로 배포해야 합니다. 이를 위해 자동 확장 및 내장 보안과 같은 이점을 제공하는 Cloud Run을 사용할 것입니다. 먼저 서버 디렉토리로 이동해 보겠습니다 . 이제 G Cloud 명령어 하나로 배포해 보겠습니다. 인증 되지 않은 사용자를 허용하지 않는다는 플래그에 주의하세요. 이는 보안에 매우 중요하며, 승인된 계정만 서버에 접근할 수 있도록 보장합니다. 그 작업이 완료되면 서버가 가동될 것입니다. 하지만 보안을 강화했기 때문에 테스트 호출을 인증할 방법이 필요합니다. 클라우드 런 프록시를 사용하여 클라우드 셸 환경에서 실제 서비스로 안전하고 인증된 터널을 생성합니다. 프록시를 아직 설치하지 않았다면 설치하라는 메시지가 나타날 수 있습니다. 이제 이 프록시를 계속 실행 상태로 두세요. 이를 테스트하려면 새 클라우드 셸 터미널을 열어야 합니다. 새 탭에서 프로젝트의 루트 디렉토리로 돌아갑니다. 자 , 이제 아까 실행했던 것과 동일한 테스트 스크립트를 실행해 보세요 . 이번에는 프록시를 통해 클라우드 런 서버로 라우팅됩니다. 이전과 동일한 성공 메시지가 표시될 것입니다. 실제로 제대로 작동하는지 확인하기 위해 명령줄에서 배포된 서비스의 로그를 바로 확인할 수도 있습니다. 자, 이제 Cloud Run에서 안전하게 실행되는 MCP 서버를 확인하실 수 있습니다. 이제 우리는 이를 사용할 수 있는 에이전트를 구축할 준비가 되었습니다 . 이를 위해 에이전트 개발 키트(ADK)를 사용하겠습니다. 클라우드 셸 편집기를 사용하여 currency-agent-agent.py 파일에 있는 에이전트 코드를 살펴보겠습니다. 두 가지 핵심 부분을 보실 수 있을 겁니다. 첫째, 에이전트에게 그 목적과 규칙을 알려주는 시스템 명령어입니다. 이 경우에는 통화 관련 질문에만 답변해 주세요 . 둘째, MCP 도구 세트를 보실 수 있습니다. 이는 에이전트를 이전 단계에서 배포한 MCP 서버에 연결하여 환율 가져오기 도구에 액세스할 수 있도록 하는 핵심 요소입니다 . ADK에는 테스트를 위한 간단한 웹 인터페이스가 함께 제공됩니다. 시작해 볼까요? 이전 단계에서 생성한 Cloud Run 프록시를 별도의 탭에서 계속 실행 상태로 유지하는 것을 잊지 마세요. 새 터미널 탭에서 ADK 웹 명령을 실행합니다 . 이렇게 하면 8000번 포트에서 새 서버가 시작됩니다. 해당 서버에 접속하려면 클라우드 셸 도구 모음에서 웹 미리 보기 버튼을 클릭하세요. 미리보기 탭을 실행하기 전에 포트를 8000으로 변경해야 할 수도 있습니다. 열리는 웹 페이지에서 왼쪽 상단 드롭다운 메뉴에서 환전 대리점이 선택되어 있는지 확인하십시오. 자, 이제 "캐나다 달러 250달러는 미국 달러로 얼마인가요?"와 같은 질문을 해보세요. 효과가 있습니다. ADK 에이전트는 배포된 MCP 서버의 도구를 올바르게 사용하여 질문에 답변했습니다. 자 , 이제 이 에이전트를 다른 에이전트들이 사용할 수 있도록 하는 방법을 살펴보겠습니다. 이제 우리 에이전트는 우리와 대화할 수 있지만, AI 에이전트의 진정한 힘은 에이전트끼리 대화할 수 있을 때 발휘됩니다. 이를 위해 에이전트 간 프로토콜(A2A)을 사용하겠습니다. A2A는 다양한 프레임워크와 벤더의 에이전트 간 협업 방식을 표준화하는 개방형 프로토콜입니다. 이 서비스는 HTTP, SSE, JSON-RPC와 같은 표준을 기반으로 구축되었으며 , 엔터프라이즈급 보안을 보장합니다 . A2A는 모달리티에 구애받지 않도록 설계되어 에이전트가 텍스트, 오디오, 비디오 및 기타 비정형 형식 전반에 걸쳐 협업할 수 있도록 합니다.
