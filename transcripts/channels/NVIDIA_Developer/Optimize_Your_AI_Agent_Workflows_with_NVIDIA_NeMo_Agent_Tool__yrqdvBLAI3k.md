## 스크립트

안녕하세요, 저는 NVIDIA의 솔루션 아키텍트인 Dro입니다. 오늘은 NVIDIA Agent IQ 프로파일러를 사용하여 에이전트 워크플로의 성능 및 동작 특성을 심층적으로 분석하는 방법을 보여드리겠습니다. 이번 데모에서는 AI 에이전트인 Morpheus를 예시로 분석해 보겠습니다. 에이전트 IQ 프로파일러를 실행한 후 에이전트 자체의 구성 가능성을 살펴보겠습니다. NVIDIA에서 개발한 Morpheus 에이전트 시스템은 취약점, 소프트웨어 컨테이너 및 코드를 신속하게 분류할 수 있습니다. 소프트웨어 취약점 분석은 개발 과정 에서 중요하지만 시간이 많이 소요되는 단계이므로 이 기능은 매우 유용합니다. 에이전트 입력은 분류가 필요한 취약점이며, 여기에는 문서 정보와 코드 위치 정보도 포함됩니다. 대규모 언어 모델은 취약점 분류를 위해 조사해야 할 항목 목록을 생성합니다. 이 목록은 다른 에이전트에서 병렬로 처리됩니다. 에이전트는 컨테이너 문서와 코드에 대한 검색, 증강 및 생성 작업을 수행하여 특정 취약점이 존재하는지 확인합니다. 모든 체크리스트 항목이 병렬로 실행되면 해당 에이전트가 이를 분석합니다. 모델에는 두 가지 단계가 더 있습니다. 먼저 모든 결과를 요약한 다음 컨테이너에 취약점이 존재하는지 여부에 대한 근거를 담은 Vex 근거를 생성하여 사용자에게 전달합니다. 이 프로세스는 에이전트 Morphus를 사용하면 처음부터 끝까지 시간을 크게 절약할 수 있습니다. 일반적으로 보안 분석가와 운영자가 몇 시간에서 며칠씩 걸리는 작업을 에이전트 Morphus는 단 1분 만에 완료합니다. 오른쪽에서 에이전트의 사고 과정과 관찰 내용을 확인해 보세요. 이제 에이전트 IQ에서 에이전트가 어떻게 구성되는지 살펴보겠습니다. 다양한 작업을 수행하는 도구 및 에이전트 자체인 함수가 있습니다. 예를 들어 벡터 데이터베이스를 검색하는 함수, 인터넷에서 소프트웨어 빌드 및 자료를 검색하는 함수 등이 있습니다. 또한 실행에 사용되는 LM도 있습니다. 예를 들어 벡터 데이터베이스 체크리스트용 LM, 리트리버 실행용 LM 등이 있습니다. 워크플로에서 프로파일러를 생성하고 실행하는 첫 번째 단계는 프로파일 러가 에이전트 IQ 에 내장된 평가 도구의 일부인지 확인하는 것입니다. 이를 위해 구성 하단에 구성 항목을 추가해야 합니다. 먼저 Agent IQ에게 프로파일러 사용 방법을 알려주는 파일을 생성하고, 데이터 저장 위치와 프로파일러에서 사용할 입력 데이터의 위치를 ​​Agent IQ에 지정합니다. 또한 어떤 메트릭을 분석할지 지정해야 합니다. 예를 들어 각 메트릭에 대한 하이퍼파라미터가 있다면 여기에 추가해야 합니다. 워크플로 실행 시간 예측을 위해 워크플로 실행의 각 단계에서 에이전트와 LLM이 생성하는 고유 토큰 수를 예측할 수 있으며, 워크플로의 병목 현상도 파악할 수 있습니다. 프로파일러 출력 결과를 살펴보면서 이러한 모든 내용을 확인해 보겠습니다. 오른쪽에 프로파일러가 성공적으로 완료되었음을 알 수 있습니다. 이제 출력 결과를 자세히 살펴보겠습니다. 프로파일러의 주요 출력 중 하나는 에이전트 실행 추적입니다. 에이전트의 모든 중간 단계, 생각, 행동, 도구 사용 내역을 확인할 수 있으며, 에이전트의 출처, 함수 계보, 실행 시간, 심지어 어떤 프레임워크에서 구현되었는지까지 알 수 있습니다. 예를 들어 에이전트 시스템이 Langchain과 Llama에서 구현된 경우를 확인할 수 있습니다. 인덱스를 사용하면 여전히 모든 정보를 단일 보기에서 추적할 수 있지만, 가독성이 다소 떨어질 수 있습니다. 따라서 모든 정보를 열 형식으로 정리한 데이터 프레임을 사용하여 데이터를 표준화했습니다. 이렇게 하면 해석이 훨씬 쉬워집니다. 더 중요한 것은 Phoenix와 같은 UI에서 이 데이터를 볼 수 있도록 개방형 텔레메트리 통합 기능을 제공한다는 점입니다. 각 에이전트 도구 호출 및 실행, LLMS의 지연 시간, 도구에 입력된 내용 및 출력 결과를 확인할 수 있습니다. LLMS 도구, 리트리버 등 모든 도구에 대해 기본적으로 투명하게 데이터를 확인할 수 있습니다. 따라서 사용자가 LangChain, Llama 인덱스 또는 다른 프레임워크를 구현하든 관계없이 중간 단계를 종합적으로 관찰할 수 있습니다. 또한 추론 최적화와 같은 지표도 살펴볼 수 있습니다. 이는 엔지니어링 팀과 협업하여 워크플로 실행 시간을 최적화하는 데 유용합니다. 예를 들어, 자주 사용되는 프롬프트 접두사를 식별하여 NVIDIA Nim의 키-값 캐시를 미리 채워 처리량을 높이고 지연 시간을 줄일 수 있습니다. 워크플로 실행 방식이나 고유 토큰 수 등을 더 잘 이해할 수도 있습니다. 모든 에이전트가 LLM을 호출하는 동안 발생하는 지연 시간을 분석하여 LLM 자체의 서비스 제공 방식에 대한 더 나은 결정을 내릴 수 있습니다. 또한 개발자 관점에서 워크플로 실행 시간과 지연 시간 신뢰 구간을 확인할 수 있습니다. 추가 메타데이터를 제공하여 워크플로가 실시간으로 어떻게 실행되는지 이해할 수 있도록 지원합니다. 프로파일링 보고서를 통해 개발자는 병목 현상이 발생하는 지점을 파악하고, LLM 자체의 문제인지 특정 도구의 문제인지 확인할 수 있습니다. 마지막으로 다양한 동시 실행 환경에서 워크플로 실행 방식을 살펴보겠습니다. 여러 동시 실행 환경에서 LLM의 지연 시간을 분석하여 워크플로 배포 방식을 더욱 효율적으로 결정할 수 있습니다. 예를 들어, 높은 동시 실행 환경에서 지연 시간이 낮다면 좋은 결과이지만, 높은 동시 실행 환경에서 지연 시간을 더욱 줄이려면 워크플로가 실행되는 클러스터에 대한 배포 방식을 최적화해야 할 수도 있습니다. 이 모든 기능은 개발자가 병목 현상을 정확히 파악하고 워크플로를 최적화하여 다음 실행 시 속도를 향상시킬 수 있도록 지원하기 위한 것입니다.
