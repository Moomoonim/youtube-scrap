## 스크립트

Memory mapping and streaming. In this video we'll&nbsp; take a look at two core features of the Datasets&nbsp;&nbsp; library that allow you to load and process huge&nbsp; datasets without blowing up your laptop's CPU. Nowadays it is not uncommon to find yourself&nbsp; working with multi-GB sized datasets,&nbsp;&nbsp; especially if you’re planning to pretrain a&nbsp; transformer like BERT or GPT-2 from scratch.&nbsp;&nbsp; In these cases, even *loading*&nbsp; the data can be a challenge.&nbsp;&nbsp; For example, the C4 corpus used to pretrain T5 consists of over 2 terabytes of data! To handle these large datasets, the Datasets&nbsp; library is built on two core features:&nbsp;&nbsp; the Apache Arrow format and a streaming API.&nbsp;&nbsp; Arrow is designed for high-performance data&nbsp; processing and represents each table-like dataset&nbsp;&nbsp; with an in-memory columnar format. As you can&nbsp; see in this example, columnar formats group&nbsp;&nbsp; the elements of a table in consecutive blocks of&nbsp; RAM and this unlocks fast access and processing.&nbsp;&nbsp; Arrow is great at processing data at any scale,&nbsp; but some datasets are so large that you can't even&nbsp;&nbsp; fit them on your hard disk. For these cases,&nbsp; the Datasets library provides a streaming API&nbsp;&nbsp; that allows you to progressively download the&nbsp; raw data one element at a time. The result is&nbsp;&nbsp; a special object called an IterableDataset&nbsp; that we'll see in more detail soon.&nbsp;&nbsp; Let's start by looking at why Arrow is so&nbsp; powerful. The first feature is that it treat every&nbsp;&nbsp; dataset as a memory-mapped file. Memory mapping&nbsp; is a mechanism that maps a portion of a file or&nbsp;&nbsp; an entire file on disk to a chunk of virtual&nbsp; memory. This allows applications to access can&nbsp;&nbsp; access segments in an extremely large file without&nbsp; having to read the entire file into memory first.&nbsp;&nbsp; Another cool feature of Arrow's memory&nbsp; mapping capability is that it allows multiple&nbsp;&nbsp; processes to work with the same large dataset&nbsp; without moving it or copying it in any way.&nbsp;&nbsp; This "zero-copy" feature of Arrow makes it&nbsp; extremely fast for iterating over a dataset.&nbsp;&nbsp; In this example you can see that we iterate over&nbsp; 15 million rows in about a minute using a standard&nbsp;&nbsp; laptop - that's not too bad at all! Let's now&nbsp; take a look at how we can stream a large dataset.&nbsp;&nbsp; The only change you need to make is to set the&nbsp; streaming=True argument in the load_dataset()&nbsp;&nbsp; function. This will return a special&nbsp; IterableDataset object, which is a bit different&nbsp;&nbsp; to the Dataset objects we've seen in other&nbsp; videos. This object is an iterable, which means&nbsp;&nbsp; we can't index it to access elements, but instead&nbsp; iterate on it using the iter and next methods.&nbsp;&nbsp; This will download and access a single&nbsp; example from the dataset, which means&nbsp;&nbsp; you can progressively iterate through a huge&nbsp; dataset without having to download it first.&nbsp;&nbsp; Tokenizing text with the map() method also works&nbsp; in a similar way. We first stream the dataset and&nbsp;&nbsp; then apply the map() method with the tokenizer. To&nbsp; get the first tokenized example we apply iter and&nbsp;&nbsp; next. The main difference with an IterableDataset&nbsp; is that instead of using the select() method to&nbsp;&nbsp; return example, we use the take() and skip()&nbsp; methods because we can't index into the dataset.&nbsp;&nbsp; The take() method returns the first N examples&nbsp; in the dataset, while skip() skips the first N&nbsp;&nbsp; and returns the rest. You can see examples&nbsp; of both in action here, where we create&nbsp;&nbsp; a validation set from the first 1000 examples&nbsp; and then skip those to create the training set.
