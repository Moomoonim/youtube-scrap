## 스크립트

Hello, and welcome to this tutorial for using AMD Vitis™ subsystems for AI Engine and programmable logic co-simulation with the AMD Vivado™ XSIM simulator. We will begin by briefly explaining what a Vitis Subsystem (VSS) is and how it can improve your design flow We will then demonstrate step-by-step how to use the VSS flow to simulate AI Engine and programmable logic (PL) components in tandem. The AMD Vitis™&nbsp;subsystem is simply a self-contained package of interconnected AI Engine and PL components. This package is platform independent and reusable, allowing it to be linked to any hardware platform that targets the same part. It can contain HLS and RTL PL components in the form of “.xo” files and packaged IP repositories. AI Engine components are similarly linked using “libadf.a” files. There is also support for adding metadata, simulation models, and other generated design sources. Example VSS components can be found in the L2 directory of the Vitis DSP library. AMD Vitis Model Composer v2025.1 also added support for exporting AI Engine and PL functions as a VSS component. The utility of a subsystem consisting of AI Engine and PL components rather than only AI Engine components may not be clear at first. This diagram of a polyphase channelizer offers an explanation: some functions are best implemented in the PL, whereas others are a better fit for AI Engine tiles. Having an ensemble of PL and AI Engine functions results in a more efficient design in this case. Furthermore, the AMD Vitis™ subsystem allows the entire polyphase channelizer to be modeled and tested as a single entity, instead of being limited to only testing these functions in their individual domains. The VSS flow simplifies development, testing, and delivery of heterogeneous designs. A top-level HDL testbench can be used for simulation without a platform or CIPS. This allows for more flexible development and testing of interconnected graphs and kernels. Migrating functions from the PL region to AI Engine tiles is also faster since existing RTL verification environments can now be reused. Faster migration allows for deeper exploration of AI Engine tiles for functions, potentially resulting in more efficient designs. Support for VSS hierarchy also allows for intuitive, RTL-like modular design. The resulting VSS component can be deployed like traditional IP. Let’s move on to a demonstration of AI Engine and PL cosimulation using VSS. This video will be centered around the XSIM simulator, but third-party simulators will be supported in future releases of the AMD Vivado™ Design Suite. The example files used during this demo can be found in the “Versal™ Vitis™ Subsystem Flow” design tutorial in the Vitis-Tutorials GitHub repo. Begin by ensuring that all required AI Engine, HLS, and RTL kernels have been compiled and verified in their own domains. Refer to UG1701 for specific details on compiling kernels. AMD Vitis™ subsystems are configured using a config file. Specify the clock frequency for every PL component using the “freqhz” parameter. Set the “vss” parameter according to the specific PL kernels and AI Engine graphs to be included. Make interface connections just as you would when generating an extensible platform. Use the “v++ --link” command with arguments for setting mode to “vss”, part name, vss config path, list of kernels, and path to destination build folder.&nbsp; With the Vitis subsystem configured, generate C_RTS for the target simulator. C_RTS Makefiles are created during AI Engine compilation and can be found in the systemC directory inside the AI Engine work folder. I will use the “make” command on the “.xsim” Makefile. Set these environment variables to allow XSIM to connect to AI Engine Sim. AIE_WORK_DIR points to the “Work” directory paths for each AI Engine kernel. The “AIESIM_OPTIONS” variable points to the aiesim config file’s path. For this demo, the config file is simply a text file with AIE_DUMP_VCD set to enable VCD dump from the AI Engine Sim. Create a Vivado design suite project targeting the same part as the generated VSS. In the Tcl console, use the “vitis::import_vss” command with the path to the VSS. This will import the VSS into the Vivado tool as a block design file. In the sources tab, right-click on the VSS block design and generate an RTL wrapper. Use this RTL wrapper to instantiate the VSS as the DUT of a top-level HDL testbench. Add testbench driver and monitor modules as needed to verify the VSS. Import the testbench, driver, and monitor source files into the Vivado design suite. Click “Run Simulation” in the Flow Navigator and the “Run Behavioral Simulation” option. Note that the example testbench designates the output signals of the AI Engine graph with the “AI_ENGINE_0” prefix. Run the simulation for 5 microseconds. The simulation results for the VSS are now visible!&nbsp; Thank you for watching.
