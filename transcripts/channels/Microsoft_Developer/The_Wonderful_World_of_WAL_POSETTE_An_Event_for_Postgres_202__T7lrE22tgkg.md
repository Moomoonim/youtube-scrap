이 백엔드 들은 공유 버퍼 캐시(이 경우 빨간색)에 쓸 때마다 쓰기 선행 로그에 쓰기 작업을 수행합니다. 상단의 세 개의 빨간색 화살표는 모두 WAL 버퍼라는 곳에 쓰기를 하고 있습니다. 모든 트랜잭션이 끝나면 WAL 버퍼의 데이터는 커널뿐만 아니라 영구 저장소 (RAID 컨트롤러, SSD, 자기 디스크 드라이브 등)에도 동기화됩니다. 데이터가 영구적으로 저장되는 곳이죠. 아시다시피 관계형 시스템은 ACID 속성을 따라야 하며, ACID에서 D는 내구성을 의미합니다. 따라서 실제로 그런 일이 발생합니다. 쓰기 전 로그(Write-Ahead Log)는 기본적으로 모든 커밋 시에 플러시됩니다. 변경할 수는 없지만 기본적으로 내구성이 있는 저장소에 플러시됩니다. 쓰기 전 로그는 데이터베이스에 대한 변경 사항 목록을 집계한 것입니다. 쓰기 전 로그의 내용을 더 잘 보여주기 위해 pg_walinspect라는 도구를 사용하겠습니다. 슬라이드에서 빨간색으로 표시된 부분은 가장 중요한 부분이므로 주의 깊게 살펴보시기 바랍니다. 또한 이 프레젠테이션을 직접 실행해 보고 싶다면 여기에 있는 URL을 참조하세요. 지금 보고 계신 SQL 코드를 다운로드하여 직접 실행해 볼 수도 있습니다. 다음은 쓰기 전 로그 내부 구조의 일부를 재레이블링하는 데 사용할 헬퍼 함수입니다 . 그리고 다음은 공통 테이블 표현식(CTE) 쿼리입니다. 이 코드는 `pg_get_wal_records_info`라는 함수를 호출하여 쓰기 전 로그(write-ahead log)의 내용을 출력합니다. 예를 들어, PostgreSQL을 처음부터 설치하고 `initdb`를 실행하면 다음과 같은 쓰기 전 로그 레코드가 생성됩니다. 왼쪽에는 리소스 관리자, 쓰기 전 로그에 포함된 다양한 리소스 유형, 각 리소스 관리자별 레코드 수, 레코드 비율, 크기 비율이 표시됩니다. 이는 전반적인 구조를 보여줍니다. 특정 레코드 유형을 살펴보면 , 예를 들어 B-트리 리소스 관리자의 경우 8개의 서로 다른 레코드 유형이 있는 것을 볼 수 있습니다. 여기에는 B-트리에서 수행할 수 있는 다양한 작업(삭제, 리프 페이지 삽입, 상위 페이지 삽입, 새 루트 생성, 페이지 분할 등)이 포함됩니다. 이러한 작업들은 쓰기 전 로그에서 일반적으로 볼 수 있는 내용입니다. 데이터베이스 리소스 관리자를 사용하면 기본적으로 새 데이터베이스를 생성할 때 수행하는 작업들을 볼 수 있습니다. 힙 테이블은 데이터 저장 테이블로, 삭제, 핫 업데이트, 삽입과 같은 레코드 유형 을 확인할 수 있습니다 . Heap2는 다른 유형의 힙 레코드 입니다. pg_wal은 쓰기 전 로그(Write-Ahead Log, WAR) 레코드로, 체크포인트, 전체 페이지 이미지(FPI) 등이 포함됩니다. 여기에서도 이러한 레코드 유형을 확인할 수 있습니다. 트랜잭션 상태 파일의 페이지를 0으로 초기화하는 것은 pg_xact입니다. 관계형 맵을 생성할 때는 업데이트 유형이 사용됩니다. 스탠바이 데이터베이스의 경우, 쿼리, 레코드 유형, 또는 데이터 생성을 위한 저장소가 있습니다. 이것은 트랜잭션을 커밋할 때 사용되는 레코드 유형입니다. 이것은 쓰기 전 로그에 나타나는 레코드 유형입니다. 이제 실제로 몇 가지 명령어를 실행하여 특정 명령어 유형에 의해 생성되는 쓰기 전 로그를 살펴보겠습니다. 이 경우 `CREATE TABLE` 문은 이 쿼리를 실행하여 이러한 레코드 유형을 생성합니다. `CREATE TABLE`은 B-트리에 데이터를 삽입합니다.
