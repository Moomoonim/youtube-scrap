EXPLAIN ANALYZE 출력에는 쿼리 실행 계획 시각화 도구가 포함되어 있습니다. 이 도구를 통해 실행 계획을 읽고, 쿼리의 비용이 많이 드는 부분을 파악하고, 성능이 저하되는 부분을 확인하고, 노드별 세부 정보를 확인할 수 있도록 다양한 시각화 옵션을 제공 합니다. 또한 테이블, 관계, 열, 데이터 유형 등을 시각적으로 보여주는 ERD 스타일의 스키마 다이어그램도 제공합니다 . 스키마별로 필터링하여 대규모 데이터베이스에서 필요한 정보만 볼 수 있습니다. 또한 성능 대시보드를 통해 실시간 및 과거 메트릭을 확인할 수 있어 느린 쿼리 간의 상관관계를 파악하고 서버 및 데이터베이스 작동 방식을 디버깅하고 조사할 수 있습니다. 그리고 물론, Copilot AI는 모든 곳에서 사용할 수 있습니다. 거의 모든 영역에서 AI Copilot과 상호 작용할 수 있는 방법을 제공하며 , 단순히 새 채팅을 시작하는 것뿐만 아니라 사용자가 보고 있는 내용에 대한 컨텍스트를 에이전트에 제공하여 디버깅, 조사 및 애플리케이션 개발에 있어 든든한 파트너가 되어줍니다. 이 도구는 항상 플랫폼에 구애받지 않도록 설계되었으며 , 이는 프로젝트의 핵심 원칙이자 목표입니다. 하지만 Azure Database 사용자를 위해 몇 가지 편의 통합 기능을 제공합니다. 가장 대표적인 기능은 Entra ID를 사용하여 데이터베이스에 인증하는 기능으로, 애플리케이션 내에서 자연스럽게 이루어집니다. 또한 지난 몇 달 동안 서버 관리 도구 모음을 구축하는 데 집중해 왔습니다 . 그리고 이것들은 일반적으로 포털로 보내거나 사용하는 것들입니다. 이전에는 별도의 CLI를 사용하여 관리해야 했지만 , 이제는 VS Code 편집기 내에서 직접 관리할 수 있습니다. 그럼 이러한 도구들이 실제로 어떻게 작동하는지 간단히 살펴보겠습니다. 좋습니다. 확장 프로그램에 추가된 Azure 관리 기능 몇 가지를 간단히 보여드리겠습니다 . 여기 Azure 서버가 있습니다. 유연한 서버입니다. 이 서버에 연결해 보겠습니다. 연결되면 대시보드를 열겠습니다. Azure 서버이기 때문에 Azure Monitor에서 가져올 수 있는 추가 메트릭이 있습니다 . 다른 클라우드나 로컬 또는 온프레미스에 있는 Azure 서버가 아닌 경우 에도 메트릭을 가져올 수 있습니다. 모든 메트릭은 데이터베이스 서버에서 직접 제공됩니다. 여기에서 여러 기능과 구성을 살펴볼 수 있습니다. 네트워크 설정을 열어 보겠습니다. 방화벽과 공용 액세스를 관리할 수 있습니다. 개체 탐색기 트리로 돌아가서 두 곳 모두에서 관리할 수 있는지 확인해 보겠습니다. 서버 매개변수를 보고, 목록을 확인하고, 필터링할 수도 있어서 포털에서처럼 변경할 수 있습니다. 여기서는 변경 가능한 백업 설정을 나열하고 있습니다. 백업 이 자동인지 온디맨드인지 확인하고 관리하거나, 필요에 따라 삭제하거나, 새로운 온디맨드 백업을 즉시 생성하거나, 새 서버를 복원하거나, 특정 백업에서 새로운 플렉서블 서버를 복원 할 수 있습니다. 또한, 서버 로그가 구성되어 있는 경우 로그를 확인할 수 있고 , 서버를 시작, 중지, 다시 시작하는 등의 제어 기능도 제공합니다. 서버 복제 페이지를 통해 백업에서 직접 복제할 수도 있습니다. 이처럼 확장 프로그램에서 다양한 Azure 서버 관리 기능을 사용할 수 있습니다 . 좋습니다. 앞서 말씀드렸듯이, 이러한 도구를 원하는 사용자를 파악하기 위한 중요한 설계 기준 중 하나는 Cursor IDE를 지원하는 것이었습니다. Cursor IDE는 VS Code의 포크 버전이므로 동일한 확장 프로그램 모델을 사용합니다. 따라서 여러 면에서 확장 프로그램은 이미 어느 정도 지원되고 있었고, 일부 사용자는 이미 이를 활용하는 방법을 찾아냈습니다. 저희는 Cursor 내에서 공식적으로 지원되는 배포 가능한 확장 프로그램을 개발해 왔으며, 여기에는 모든 Azure 및 Entra 통합 지점과 Cursor 내에서 Copilot이 아닌 에이전트 환경과의 통합이 포함됩니다. Cursor가 최근 v3을 출시했는데, 여기에는 에이전트 중심 앱이 포함되어 있습니다. 이 앱은 완전히 다른 에이전트, 아니, 완전히 다른 확장 프로그램 모델을 사용합니다. 따라서 저희는 아직 어떤 통합 방식을 사용할지 검토 중입니다. 다음 데모에서는 Cursor를 살펴보겠습니다. IDE 내에서 확장 프로그램이 실행되는 모습과 사용 가능한 모든 기능을 보여드리겠습니다. 여기 Cursor Classic이 있고, 익숙한 사이드바에 객체 탐색기가 있어 모든 연결 목록을 볼 수 있습니다. 연결을 탐색하고, 데이터베이스 트리를 탐색하고, 검색 기능을 사용하여 대규모 스키마 또는 여러 스키마가 있는 데이터베이스 에서 데이터베이스 객체를 찾을 수 있습니다 . 여기서는 제가 준비한 작은 쇼핑몰 데모에서 주문 테이블을 불러와서 객체 속성이라는 새로운 기능을 열어보겠습니다. 이 기능은 데이터베이스에 있는 모든 유형의 데이터베이스 객체에서 작동합니다. 위쪽 헤더 행에는 강조 표시된 정보가 있는데, 이를 통해 추정치나 통계를 업데이트하려는 경우 테이블을 직접 다시 분석할 수 있습니다 . 전체 SQL 정의가 제공되므로 객체가 어떻게 생성되었는지 확인할 수 있고, 다양한 제약 조건과 인덱스를 분석하여 세부 정보를 여러 관점에서 살펴볼 수 있습니다. 또한 모든 보안 정보도 표시됩니다. 특정 권한이 있는 경우 수혜자 와 부여자, 그리고 해당 SQL이 나열됩니다. 쿼리 편집기에서 열어볼 수 있고, 해당 객체의 종속 항목과 종속성을 탐색할 수 있습니다. 행 수준 보안과 같은 정보도 여기에 표시됩니다. 다른 데이터베이스 객체와 연결하여 필요한 모든 정보를 가져올 수도 있습니다. 이 기능은 VS Code와 Cursor에서 모두 작동합니다. 당연히 쿼리를 실행할 수 있어야 합니다. Cursor는 VS Code와 동일한 쿼리 편집기와 쿼리 결과 인터페이스를 제공합니다 . 두 제품 모두에서 최신 기능 중 하나인 쿼리 실행 계획 시각화 도구를 지원합니다. 쿼리를 실행한 후 쿼리 실행 계획 생성을 선택하고 몇 가지 매개변수를 지정하면 쿼리 실행 계획에서 비용이 많이 드는 부분을 색상으로 강조 표시 한 보기 좋은 그래프를 얻을 수 있습니다 . UI를 보여주기 위해 일부러 복잡한 쿼리를 만들어 봤습니다 . 레이아웃과 렌더링 방식을 다양하게 조정하여 특정 문제를 집중적으로 살펴볼 수 있습니다. 여기서는 쿼리에서 가장 비용이 많이 드는 부분을 강조 표시하도록 렌더링 방식을 선택할 수 있습니다 . 이제 일반 렌더링으로 돌아가서 몇 가지 다른 보기 방식을 보여드리겠습니다. 저희는 '아이스클 차트'라는 것을 제공하는데, 이는 불꽃 그래프와 유사하게 구성 가능한 속성 및 매개변수 세트를 기반으로 가장 비용이 많이 드는 노드를 보여주는 데 도움이 됩니다 . 테이블 보기로도 표시할 수 있습니다. 이는 일종의 상향식 보기이지만, 정렬할 수 있도록 몇 가지 열을 강조 표시합니다. 따라서 비용이나 행 수만 확인하고 싶을 때 매우 쉽게 접근할 수 있습니다. 또한 모든 기능에서 공통적으로 제공되는 기능은 쿼리 계획이든 다른 것이든 상호 작용하고 싶은 부분에 항상 'Copilot' 버튼이 있다는 것입니다. 이 버튼을 클릭하면 쿼리를 포함할지 여부를 묻습니다. 쿼리를 AI 서비스로 전송 할지 여부를 결정하는 것입니다. 이제 Cursor의 내장 모델 관리 및 AI 채팅 기능을 사용하여 Cursor에 포함된 MCP 서버( VS Code 확장 프로그램에도 포함된 것과 동일한 서버)를 활용 하고 있습니다. 이 도구는 쿼리 계획 컨텍스트와 노드 컨텍스트를 가져오는 데 필요한 몇 가지 도구를 사용하고 , 실제로 데이터베이스에 접속하여 테이블 통계를 확인합니다. 예를 들어, 최근에 테이블에서 vacuum과 같은 작업을 수행했다면 이 쿼리 계획 분석에서 해당 작업을 다시 수행 하라고 권장하지 않습니다 . 즉, 실제 테이블을 분석하여 쿼리 계획이 알려주는 정보 와 개선 할 수 있는 부분에 대한 유용한 권장 사항을 제공하는 지능적인 기능을 갖추고 있습니다. 이제 Cursor와 VS Code 모두에서 작동하는 다른 기능들을 보여드리겠습니다 . 개체 탐색기로 돌아가서 이전에는 로컬 Docker 데이터베이스에 연결했지만, 이제 Azure Flexible Server에 연결해 보겠습니다. Entra 인증을 사용하여 Azure에 연결하고 정보를 가져오는 MCP 도구를 통해 데이터베이스 의 특정 메트릭 또는 여러 메트릭에 대해 채팅할 수 있습니다 . 이제 다음 아키텍처 구성 요소로 넘어가겠습니다 . 모델 컨텍스트 프로토콜 서버(MCP). 아마 최근에 많은 분들이 들어보셨을 겁니다. MCP는 AI 에이전트에 도구, 도구 호출 및 도구 컨텍스트를 제공하는 개방형 프로토콜입니다 . 이전에는 VS Code 확장 프로그램에 VS Code 전용 도구를 포함시켰지만, 이는 특정 호스트에만 종속되는 단점이 있었습니다. 그래서 이제는 모든 데이터베이스 통합 기능을 다양한 호스트 플랫폼에서 사용할 수 있는 독립형 MCP 서버에 통합했습니다 . 모든 기능이 모든 플랫폼에 적합한 것은 아니므로, 그래픽 요소를 갖춘 고급 도구는 에디터에 적합하고, 구조화된 데이터에만 의존하는 터미널이나 에이전트 중심 애플리케이션에는 더 적은 기능이 포함됩니다. 하지만 이 모든 플랫폼에서 동일한 프로젝트를 사용하고 있습니다 . 그리고 이러한 기능을 손쉽게 사용할 수 있도록 도와주는 것이 바로 새로운 도구인 pgsql-tools입니다. pgsql-tools는 독립형 MCP 서버와 다양한 유틸리티 기능을 제공합니다. 예를 들어 연결 프로필 생성 및 관리, 연결 자격 증명을 구성 파일에서 분리하여 안전한 OS 키링 지원 형식으로 저장하는 기능, MCP 서버 등록 및 에이전트 하네스와의 연동 실행 등이 있습니다. 이를 통해 CLI 기반 에이전트 앱에도 동일한 기능을 제공할 수 있게 됩니다. 다음 데모에서는 Copilot CLI를 사용하여 pgsql- tools를 설정하고 실행하는 방법을 보여드리겠습니다 . 먼저 pgsqltools CLI가 설치되어 있는지 확인해 보겠습니다. 여기서 버전을 확인하겠지만, 실제 사용 시에는 다른 버전이 표시될 것입니다. 가장 먼저 연결 프로필에 연결을 추가해 보겠습니다 . 이 연결 프로필은 Cursor나 VS Code 확장 프로그램에 추가했던 프로필과는 다르다는 점을 기억해 주세요 . 표준 PostgreSQL 연결 문자열만 입력하면 됩니다. 처음에 연결할 때 암호를 입력 하지 않았기 때문에 `set-password` 명령을 실행하라는 메시지가 표시되는 것을 볼 수 있습니다 . CLI에 암호가 표시되지 않도록 하기 위해서죠. 그래서 TTY를 실행하고 암호를 안전하게 입력할 수 있도록 한 다음, OS 키링에 암호를 저장합니다. 이제 연결을 추가하고 암호를 설정했으니 모든 연결 목록을 표시해 보겠습니다. 보시다시피 암호가 설정되었습니다. 다음으로 Copilot에 MCP 서버를 등록해 보겠습니다. Copilot의 구성을 수정하여 이 MCP 서버가 존재함을 알리고 연결 프로필과 지금 살펴볼 도구에 접근할 수 있도록 하는 것입니다 . Copilot을 실행해 보겠습니다. MCP 서버가 로드되고, 간단한 질문만 하면 됩니다. "서버에는 무엇이 있나요?" 프로그램은 몇 가지 도구를 더 사용하여 데이터베이스와 스키마가 몇 개 있다는 것을 확인합니다 . 하지만 이것만으로는 전체적인 구조를 파악하기 어렵습니다. 그래서 이번에는 서버 스키마의 ERD(엔티티 관계 다이어그램)를 생성해 달라고 요청합니다. 프로그램은 몇 가지 도구를 더 실행하고, 스키마에 어떤 테이블이 있고, 각 테이블에는 어떤 열과 제약 조건이 있는지 보여주는 깔끔한 개요를 제공합니다 . 정말 유용한 기능입니다. 다음으로는 데이터를 좀 더 자세히 살펴보기 위해 몇 가지 쿼리를 작성해 볼 수도 있겠습니다. 예를 들어, "지출액 기준으로 상위 5개 고객은 누구인가?" 와 같은 쿼리를 말이죠. 이처럼 도구 덕분에 데이터베이스 스키마에 대한 맥락을 파악할 수 있습니다. 그리고 SQL 쿼리를 작성하는 방법도 알고 있습니다. 자, 이제 쿼리를 하나 작성해 보겠습니다. 상위 5개 지출 기업을 보여줍니다. 이 데이터가 데모용 시드 데이터라는 것을 정확하게 파악했네요. 조금 의심스럽긴 하지만, 통찰력이 뛰어납니다. 조금 더 복잡한 쿼리를 입력해 보겠습니다.
