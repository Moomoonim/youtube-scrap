안녕하세요, 오늘은 Quadrant를 시작하는 방법에 대한 튜토리얼을 진행해 보겠습니다. Quadrant 클라이언트(파이썬 클라이언트)를 사용할 것이고, Docker를 통해 Quadrant를 실행할 것입니다. 벡터 데이터베이스가 무엇인지, 그리고 Quadrant에 대해 어느 정도 알고 있지만, 어떻게 시작해야 할지, 무엇을 해야 할지, 벡터를 어떻게 넣고 Quadrant가 제공하는 유용한 기능들을 어떻게 활용해야 할지 잘 모르시는 분들을 위해 설명드리겠습니다. 자, 그럼 이제 Quadrant 공식 웹사이트에 접속했습니다. 시작하기 전에 가상 환경을 설정해야 합니다. 저는 Mamba를 사용하겠지만, 여러분에게 가장 편리한 다른 환경을 사용하셔도 됩니다. Mamba create bash 명령어를 입력하고, 이름을 Q tutorial로 지정하고, Python 3.10을 사용하겠습니다. NumPy와 Faker 패키지를 설치하고, 설치가 진행되는 동안 Quadrant를 실행해 보겠습니다. Quadrant는 벡터 데이터베이스입니다. 차세대 AI 애플리케이션에 강력한 기능을 제공 하는 고급 고성능 벡터 유사성 검색 기술을 소개합니다. 이 기술은 쿼리와 의미적으로 유사한 벡터를 통해 검색할 수 있을 뿐만 아니라, 매우 강력한 추천 API를 기반으로 추천 시스템을 구축할 수 있도록 지원합니다. 퀀텀에 대한 자세한 정보는 여기에서 확인하실 수 있습니다. 퀀텀이 제공하는 다양한 기능에 대해 더 자세히 알아보시기를 권장합니다. 오늘은 퀀텀에서 할 수 있는 몇 가지 기능만 살펴보겠습니다. 빠른 시작 섹션으로 이동하여 시작하는 데 필요한 정보를 확인하겠습니다. 먼저 쿼드런트 이미지를 다운로드해야 합니다. 환경을 활성화한 다음, ' quadrant tutorial'이라는 디렉토리를 생성하고 해당 디렉토리로 이동합니다. 최신 이미지를 다운로드합니다(저는 이미 최신 이미지를 가지고 있습니다). 그런 다음 Jupiter Lab을 실행하고 Jupiter Lab의 URL을 복사합니다. 새 탭을 열고 Jupiter Lab에 접속합니다. 쿼드런트에 연결하려면 이 명령어를 실행해야 합니다. 하지만 그 전에 쿼드런트 클라이언트를 설치해야 하므로, 다시 환경을 활성화하고 새 Jupyter Notebook을 생성하겠습니다. 이름은 ' Quadrant Tutorial'로 하겠습니다. 좋습니다. 이제 필요한 모든 것을 설치했으니, 이 창을 닫고 Docker 명령어를 붙여넣은 다음 제품에 연결하겠습니다. 좋습니다. 보시다시피 최신 버전인 B 1.2.x가 설치되었고, 이제 시작할 준비가 되었습니다. 이번 사용 사례에서는 수천 개의 영역으로 구성된 데이터베이스가 있다고 가정해 보겠습니다. 사용자가 특정 노래를 선택하면 가장 유사한 노래를 추천하거나, 사용자가 좋아했던 노래 와 좋아하지 않았던 노래를 기반으로 새로운 노래나 아직 들어보지 못한 노래를 추천하고 싶습니다. 따라서 추천 기능이 최대한 정확하도록 만들겠습니다. 사람들이 좋아하지 않는 곡들과는 최대한 멀리, 좋아하는 곡들과는 최대한 가깝게 만들기 위해, 우리의 노래를 나타내는 가짜 데이터를 생성하기 위해 NumPy를 사용할 것입니다. 또한 방금 다운로드한 Quadrant 클라이언트를 통해 Quadrant가 실행 중인 컨테이너에 연결할 것입니다. 필요한 라이브러리를 모두 가져오겠습니다. 모델 모듈에는 유용한 기능이 많으므로 먼저 NumPy를 `NP`로 가져오고, 필요한 라이브러리인 `Faker`도 가져 옵니다. 자, 이제 필요한 라이브러리를 모두 가져왔으니, 먼저 Quadrant에 연결할 클라이언트를 생성해야 합니다. 클라이언트 이름은 `client`로 하고, 호스트는 컴퓨터에서 실행 중이므로 `localhost`로, 포트는 Docker 명령에서 사용하는 `6333`으로 설정합니다. 이제 클라이언트를 생성하고 다음으로 할 일은... 컬렉션을 생성해 보겠습니다. 컬렉션은 트랜잭션 데이터베이스나 분석 데이터베이스에서 테이블이라고 부르는 것과 유사합니다. 이러한 데이터베이스에서는 SQL 쿼리 등을 통해 검색합니다. 벡터 데이터베이스의 컬렉션은 비슷해 보이지만 약간 다릅니다. 컬렉션에는 포인트가 있고, 이 포인트들은 ID, 벡터, 페이로드를 가지고 있습니다. ID는 각 벡터의 고유 식별자입니다. 예를 들어 이미지, 오디오 파일, 노래, 비디오 또는 문서를 나타낼 수 있습니다. 벡터는 해당 데이터의 고차원 표현입니다. 페이로드는 데이터에 대한 메타데이터와 같습니다. 예를 들어 벡터로 표현되는 노래를 만든 아티스트, 노래가 녹음된 국가, 발매 연도, 해당 지역에 접속하는 데 사용할 수 있는 URL 등 생각할 수 있는 모든 정보를 포함할 수 있습니다. 자, 이제 컬렉션을 어떻게 생성하는지 알아볼까요? 클라이언트를 사용하여 생성하겠습니다. 컬렉션을 생성하려면 이름을 지정해야 합니다. 저는 ' my collection' 또는 ' first collection'이라고 하겠습니다. 다음으로 벡터를 구성해야 합니다. 벡터에 대한 구성 파일을 제공해야 하는데, 여기에는 두 가지가 있습니다. 먼저 품질(quality)을 지정해야 합니다. 이는 벡터의 차원(dimension) 크기입니다. 데이터베이스에 저장될 열의 개수라고 생각하시면 됩니다. 그런 다음 데이터베이스를 쿼리할 때 사용할 거리 측정 방법을 지정해야 합니다. 모델(models) 벡터, 부모(parents) 벡터, 매개변수(parameters)의 크기는 100으로 설정하고, 거리 측정 방법은 코사인 유사도( cosine similarity)로 지정합니다. 이렇게 데이터베이스를 생성했으니 이제 컬렉션에 데이터를 채워 넣는 방법을 알아보겠습니다. 먼저 넘파이( numpy)를 사용하여 가짜 데이터를 생성합니다. 여기서 우리 의 데이터는 실제 데이터라고 생각하면 됩니다. 이 사용 사례는 많은 노래가 있고, 각 노래를 100차원의 고차원 벡터로 표현하는 것입니다. 각 차원은 예를 들어 노래의 템포, 가수의 음높이, 장르, 길이 등을 나타낼 수 있습니다. 즉, 각 벡터는 노래에 명시적으로 나타나지 않는 특징을 나타냅니다. 이러한 고차원 벡터는 일반적으로 딥러닝 모델의 내부 레이어에서 생성됩니다. 다양한 방법으로 생성할 수 있지만, 이 방법이 가장 유용해 보이며, 임베딩이라고도 합니다. 자, 이제 노래를 나타내는 가상의 데이터 세트를 만들기 위해 non-pride를 사용할 것입니다. 이를 위해 낮은 값(예: 1.0)과 높은 값(예: 1.0)을 부여해야 합니다. 즉, 낮은 값은 -1.0, 높은 값은 1.0입니다. 그리고 나서 크기를 지정해야 하는데, 크기는 각각 100차원의 벡터 1,000개가 될 것입니다. 그런 다음 인덱스 또는 컬렉션의 ID 인덱스를 생성할 것입니다. 이 인덱스는 해당 자산의 길이만큼의 범위를 가진 목록이 될 것입니다. 1,000이라는 값을 알고 있으므로 바로 1,000으로 입력할 수 있습니다. 아, 여기에 오류가 있네요. 크기가 같다는 오류입니다. 이제 수정했습니다. 자, 이제 데이터가 준비되었으니 컬렉션을 채울 수 있습니다. 클라이언트를 사용하여 observe 메서드를 통해 컬렉션에 데이터를 채울 것입니다. Quadrant의 batch 메서드를 사용하여 포인트를 일괄적으로 업로드할 것입니다. ID는 여기에 있는 인덱스와 같다고 지정하겠습니다. 데이터가 어떻게 생겼는지 궁금하시다면, 첫 번째 두 벡터는 n차원의 요소이고, 두 번째 벡터는 인덱스 입니다. 마지막 10개입니다. 이제 벡터 데이터를 리스트로 변환해야 합니다. 쿼드런트는 파이썬 변수를 사용하므로, 데이터의 데이터 유형인 넘파이 배열을 리스트로 변경해야 합니다. 인덱스는 이미 리스트이므로 업로드할 수 있습니다. 이제 컬렉션이 채워졌으니 어떻게 확인하고 평가할 수 있을까요? 가장 먼저 할 수 있는 일은 컬렉션 에서 요소를 가져오는 것입니다. ` retrieve` 명령어를 사용하면 됩니다. 컬렉션 이름 과 ID를 함께 전달해야 하며, 가져올 ID 목록을 지정할 수도 있습니다. 예를 들어 500개까지 지정할 수 있습니다. 이제 레코드가 반환되는 것을 볼 수 있습니다. 쿼드런트는 이 레코드를 반환하지만, 벡터를 가져오려면 이 정보 자체만으로는 그다지 유용하지 않습니다. 벡터를 2차원으로 압축하여 차트로 시각화할 것이기 때문입니다. 따라서 쿼드런트에 벡터를 가져오도록 명시적으로 알려야 합니다. 즉, 해당 옵션을 ` true`로 설정해야 합니다. 화면 에 많은 정보가 표시되는데, 이 중 일부는 그다지 유용하지 않을 수도 있습니다. 하지만 이 기능의 진정한 힘은 사용자에게 유용한 정보를 제공하는 데 있습니다. 사용자의 검색어에 의미 있는 검색 결과를 제공하거나 추천을 해주는 것이 목표이기 때문입니다. 그렇다면 어떻게 해야 할까요? 먼저 페이로드를 생성해야 하는데, Faker를 이용하면 됩니다. Faker 객체를 생성하고 어떤 작업을 할 수 있는지 살펴보겠습니다. Faker는 무작위 이름, 성, 주소, 단어, 국가, 연도, URL 등을 생성합니다. 예를 들어 노래 데이터베이스를 다룰 때, 앱에 업로드한 노래와 가장 유사한 노래를 찾거나 노래를 기반으로 추천을 받고 싶다면, 노래 제목, 아티스트, 발매 연도, 발매 국가와 같은 정보를 반환받는 것이 유용할 수 있습니다. 등등, 이 모든 정보를 담을 페이로드를 만들어 보겠습니다. 페이로드의 이름을 payload라고 하겠습니다. 리스트를 만들 건데, payload는 JSON 객체이고, 파이썬에서는 딕셔너리가 됩니다. 원하는 어떤 데이터든 넣을 수 있지만, 몇 가지 제약 조건이 있습니다. 예를 들어 벡터 자체는 넣지 않고, 이미 벡터에 저장된 데이터를 사용해야 합니다. 또는 정확한 데이터 조각 대신 데이터가 있는 위치의 URL( 예: S3 버킷)을 넣을 수도 있습니다. 그래서 payload@at, artist( 아티스트)(이름을 선택)와 노래 제목을 각각 입력하겠습니다. 노래 제목은 세 단어로 이루어져 있으므로 join 메서드를 사용하여 결합하겠습니다. 아티스트는 이미 있으므로 URL을 입력하고, 연도를 입력한 다음... 국가, 연도, URL 객체를 가져와서 어떤 결과가 나오는지 확인해 보겠습니다. 먼저 세 개의 데이터 객체를 출력해 보면, 첫 번째 노래의 경우 아티스트는 Michael Chang, 노래 제목은 Bed One Style, URL은 노래를 들을 수 있는 주소, 발매 연도, 녹음 국가가 표시됩니다. 자, 이제 다시 오프셋 메서드를 사용해 보겠습니다. 컬렉션 이름을 지정하고, 배치( batch)를 사용하여 ID를 설정하고, 커넥터에는 인덱스를, 데이터에는 데이터를, 페이로드에는 방금 생성한 페이로드를 사용합니다. 좋습니다. 성공적으로 완료되었습니다. 이제 무엇을 해 볼까요? 벡터 데이터베이스를 활용하여 의미 검색을 해볼 수 있습니다. 예를 들어, Ricky Martin의 노래 "Living a Vida"를 검색해 보겠습니다.
