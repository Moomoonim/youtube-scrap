## 스크립트

[음악] Azure Migrate 시리즈의 또 다른 비디오에 오신 것을 환영합니다. 이번 비디오에서는 해당 도구와 그 기능에 대한 데모를 다룹니다. 이 시리즈에서는 기존 환경을 파악하는 것부터 준비 상태를 평가하고 워크로드를 Azure로 마이그레이션하는 전체 마이그레이션 과정을 살펴봅니다. 이 비디오에서는 결정 단계, 특히 지속적인 Azure 연결 없이도 검색을 빠르게 시작할 수 있는 경량 도구인 Azure Migrate Collector에 대해 집중적으로 살펴보겠습니다 . Azure Migrate는 환경 및 제약 조건에 따라 다양한 검색 방법을 지원합니다. 어플라이언스 기반 검색을 통해 VMware, Hyper-V, 물리적 환경 및 멀티 클라우드 환경 전반에 걸쳐 종속성 매핑을 포함한 지속적인 검색이 가능합니다. 여기서 강조된 컬렉터 기반 검색은 VMware 및 물리적 환경을 위한 경량의 에이전트리스 옵션입니다. 이 기능은 지속적인 Azure 연결이 필요 없는 단일 스냅샷으로 작동합니다 . 이미 인벤토리 데이터가 있는 환경의 경우 CSV 가져오기 및 RVTools 가져오기를 통해 서버 세부 정보를 직접 가져와 구성 기반 평가를 생성할 수 있습니다. 두 방법 모두 동일한 결과, 즉 계획을 세울 수 있도록 자산 현황을 명확하게 파악할 수 있게 해줍니다 . 필수 조건 중 하나로, 포털에서 Azure Migrate 프로젝트를 생성했는지 확인해야 합니다. 프로젝트를 엽니다. 탐색을 시작할 수 있는 옵션이 표시됩니다 . 그것을 클릭하면 세 가지 옵션이 나타납니다. 수집기 사용을 선택 하고 다운로드를 클릭하여 Azure Migrate 수집기 도구를 받으세요. Azure Migrate 수집기를 설정하려면 자격 증명도 구성해야 합니다 . 사용 환경에 따라 수집기는 다음과 같은 계정을 필요로 합니다 . VMware 환경의 경우 서버 구성 및 성능 데이터를 수집하려면 읽기 전용 및 게스트 작업 권한이 있는 vCenter 계정이 필요합니다 . Windows 서버의 경우, 설치된 소프트웨어, SQL 및 PostgreSQL SQL 데이터베이스 인스턴스, 웹 애플리케이션 데이터를 수집하려면 도메인 계정 또는 관리자 계정이 필요합니다. 리눅스 서버의 경우, 해당 데이터를 수집하려면 루트 계정이 필요합니다. 설치된 소프트웨어, SQL, PostgreSQL 인스턴스 및 웹 애플리케이션 데이터. SQL 사용을 위해서는 SQL 권한이 있는 도메인 계정이 필요합니다. 참고로, 최소 권한 계정도 지원되므로 높은 권한의 자격 증명을 공유할 필요가 없습니다 . 자격 증명이 준비되면 수집기를 실행하고 검색을 수행할 수 있습니다. 수집기 설정 단계를 간단히 살펴보겠습니다 . 온프레미스 머신에서 PowerShell 스크립트를 실행하세요. 이렇게 하면 Azure Migrate 수집기가 실행됩니다. 실행이 완료되면 서버 자격 증명을 추가하세요. 사용 환경에 따라 vCenter 자격 증명 또는 물리적 서버 자격 증명이 될 수 있습니다 . 수집 담당자는 게스트 자격 증명을 확인합니다. 문제가 발생하면 분석 요약 섹션으로 이동하여 문제 를 해결하고 수정한 후 다음 단계로 진행할 수 있습니다. 검증이 성공적으로 완료되면 수집기가 환경을 전체적으로 스캔하고 압축 파일을 생성합니다. 귀사의 모든 현장 재고 목록이 포장되어 준비 완료되었습니다. 해당 압축 파일을 포털의 Azure Migrate 프로젝트에 다시 업로드하면 인벤토리 평가를 위한 준비가 완료됩니다 . 이제 Azure Migrate 컬렉터 데모로 넘어가겠습니다. 먼저 Azure 포털에서 Azure Migrate를 검색하세요 . 랜딩 페이지에는 새 프로젝트를 생성하거나 기존 프로젝트를 볼 수 있는 두 가지 옵션이 있습니다. 이미 프로젝트가 설정되어 있으므로 ' 모든 프로젝트 보기'를 클릭하세요. 본인이 만든 프로젝트를 이름으로 검색하여 열어보세요. 프로젝트 랜딩 페이지에 접속하면 ' 조사 시작' 옵션이 표시됩니다. 클릭하세요. 세 가지 옵션이 표시됩니다. 수집기 검색 흐름을 진행하려면 수집기 사용을 선택하십시오. 다운로드 페이지로 이동합니다. 수집기 zip 파일을 다운로드하고 온프레미스 머신에서 압축을 해제한 다음 PowerShell 스크립트를 실행하십시오. 이 스크립트는 새 설치인지 기존 수집기를 업데이트하는 것인지 확인하는 메시지를 표시합니다. 확인이 완료되면 스크립트가 실행되고 수집기 구성 관리자가 자동으로 열립니다. 구성 관리자에서 먼저 vCenter 서버 세부 정보를 추가합니다. 추가하는 vCenter에 친숙한 이름을 지정할 수 있습니다. 다음으로, 검색 소스 서버의 IP 주소 또는 FQDN, 포트 번호, 그리고 이 서버를 매핑할 vCenter를 추가합니다. vCenter 서버 세부 정보를 추가할 수 있으며, 최대 10,000대의 서버를 추가할 수 있습니다. 다음으로, 데이터베이스, 웹 애플리케이션 및 설치된 소프트웨어를 포함하는 심층적인 검색을 위해 게스트 자격 증명을 추가하십시오. 자격 증명 유형을 선택하고, 사용자 이름을 추가하고, 사용자 이름과 암호를 입력한 다음, 대상에 대해 유효성을 검사하십시오 . 최대 5개의 가상 머신(VM)을 선택하여 유효성 검사를 실행하고 자격 증명이 제대로 작동하는지 확인할 수 있습니다. 저장하고 진행하세요. 데이터 수집 시작을 클릭하세요. 데이터 수집기는 시스템 구성 데이터, 성능 데이터, 소프트웨어 인벤토리 및 워크로드 검색 데이터 수집을 시작합니다. 수집 시간은 환경 규모와 추가된 자격 증명 수에 따라 달라집니다. 완료되면 수집된 모든 데이터의 요약을 볼 수 있습니다. 구성 관리자에서 수집된 데이터를 ZIP 파일로 내보냅니다 . 압축 파일을 Azure 포털에 액세스할 수 있는 컴퓨터로 복사하세요 . Azure 마이그레이션 프로젝트로 돌아가세요 . 검색 시작을 클릭하고, 수집기 사용을 선택한 다음 3단계로 진행하세요. 수집기가 생성한 zip 파일을 가져옵니다 . 압축 파일을 찾아 선택 하고 가져오기를 클릭하세요. 가져오기 완료 시간은 파일 크기에 따라 다르며 일반적으로 최대 30분이 소요됩니다. 가져오기가 완료되면 프로젝트 개요로 이동하세요. 한눈에 전체 재고 목록을 확인할 수 있습니다 . 모든 서버, 데이터베이스, 웹 애플리케이션 및 설치된 소프트웨어를 한 곳에서 관리할 수 있습니다. 여기에서 개별 페이지를 자세히 살펴보면 더 많은 정보를 확인할 수 있습니다. 서버는 인프라 워크로드, Windows, Linux, SQL 서버를 모니터링하고, 각 서버를 인라인으로 확장하여 하드웨어 구성, 스토리지, 네트워크 및 운영 체제 세부 정보를 확인할 수 있습니다. 데이터베이스( SQL 및 기타 데이터베이스), 서버 인스턴스, 인스턴스 별로 호스팅되는 추가 버전 데이터베이스, 웹 애플리케이션, IIS, Java 프레임워크, 애플리케이션 풀 구성, 소프트웨어, 설치된 애플리케이션, 머신별 역할 기능. 각 페이지는 워크로드의 계층적 구조를 보여줍니다. 사전 조사가 완료되면 이제 사업 계획서를 작성하여 투자 수익률(ROI)을 분석하거나 평가서를 작성하여 마이그레이션 옵션을 살펴볼 수 있습니다.
