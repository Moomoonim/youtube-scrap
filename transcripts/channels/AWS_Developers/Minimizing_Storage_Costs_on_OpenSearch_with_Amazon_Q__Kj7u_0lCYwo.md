좋은 질문인 것 같네요. 아마존 QBE에서 제공하는 가이드와 방향을 살펴보겠습니다. 아마존 QBE에서 제시한 계획은 다음과 같습니다. 먼저 Terraform AWS 메인 Terraform 파일로 이동하여 데이터 스트림 플래그를 True로 설정해야 합니다. 좋은 시작입니다. 다음으로 scripts 폴더의 DS policy Json 파일을 수정합니다. 인덱스 관리자 템플릿인 것 같은데, 이 폴더가 맞네요. scripts data policy 폴더입니다. 좋습니다. 그리고 스크립트 생성 데이터 스트림 스크립트 필드를 업데이트합니다. 보시 다시피, 시작하기에 아주 좋은 방법입니다. 물론 실제 지침을 다시 한번 확인해야겠지만, 적어도 제 코드베이스에서 어떤 특정 폴더와 파일을 수정해야 하는지는 알게 되었습니다. 그래서 오픈서치의 데이터 문자열 기능을 구현하는 첫 번째 예제를 제 프로젝트에 구현해 보았습니다. 하지만 이게 올바른 방법인지 확신이 서지 않습니다. 그래서 어떻게 해야 할지 고민 중입니다. 실제로 Amazon Q를 사용하여 이 구현을 검증하고 있습니다. 전체 Jon 코드를 프롬프트로 보내고 아래 Jon 문서가 OpenSearch의 데이터 스트림 기능에 대한 적절한 예제를 제공하는지 확인하도록 요청할 것입니다. 이러한 유형의 검증은 개발자에게 매우 흔한데, 때로는 정확한 방법을 찾는 것보다 올바른 접근 방식인지, 그리고 해당 벤더의 모범 사례 및 아키텍처 권장 사항을 적절히 제공하는지 확인하는 것이 더 중요하기 때문입니다. 검증된 모든 항목은 다음과 같습니다. 세션 인덱스 패턴( OpenSearch에서 매우 중요함), 데이터 스트림 사용, 우선순위, 템플릿 등이 검증되었으며, 데이터 스트림 객체의 존재에 대한 간단한 의견도 제공되었습니다. 이는 L 스탠드 구현에서 올바른 방향으로 가고 있음을 나타냅니다. OpenSearch 도메인에 UltraWar 기능을 구현해야 합니다. 여기서는 Terraform을 사용하여 인프라 코드를 통해 OpenSearch 도메인을 생성하고 있습니다. 그런데 이 UltraWar 기능을 Terraform 코드로 어떻게 표현해야 할지 잘 모르겠습니다. 그래서 Amazon Q를 사용하여 또 다른 기능 개발을 생성하고 다음과 같이 요청할 것입니다. 현재 파일을 수정하려면 파일 이름이 무엇인가요? op search를 입력하세요. TensorFlow 에서 오픈서치의 울트라 웜 기능을 지원하도록 수정해 주세요. 이 변경 사항을 구현한 후에는 다른 모든 부분을 그대로 유지해야 합니다. 아마존 Q 개발자가 이 특정 변경 요청을 반영하기 위해 현재 코드를 어떻게 수정할지 살펴보겠습니다. 아마존 Q 개발자가 제시한 권장 사항은 기본적으로 코드에 ` warm enable` 플래그를 추가하는 것입니다. 이미 권장 사항을 코드에 적용했고, 모든 것이 테스트 준비가 완료된 것 같습니다. 이는 아마존 Q 개발자가 개발자 및 IT 전문가에게 제공할 수 있는 기술 향상의 좋은 예입니다. 특정 기술 분야의 전문가가 아니더라도 아마존 Q를 통해 부족한 부분을 보완할 수 있습니다.
