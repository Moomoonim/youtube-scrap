## 스크립트

오늘은 GitHub Actions를 시작하는 데 필요한 모든 것을 알려드리겠습니다. [음악] 이 영상이 끝나면 GitHub Actions를 사용하는 방법과 첫 번째 자동화 워크플로를 만드는 방법을 알게 될 것입니다. 안녕하세요, 저는 케다샤입니다. 오늘 이렇게 함께해 주셔서 정말 기쁩니다 . GitHub Actions를 사용하여 취약점 검사, 테스트 실행, 릴리스 생성, 심지어 팀에 중요한 음악 업데이트 알림 보내기 등 개발자 워크플로에서 흔히 수행하는 작업을 자동화하는 방법에 대해 이야기해 보겠습니다. GitHub Actions는 GitHub에 내장된 지속적 통합, 지속적 배포( CI/CD) 및 자동화 플랫폼입니다 . 사람들은 이러한 것들을 액션 워크플로 또는 단순히 워크플로라고 부르는 경우가 많습니다. 이 기능을 사용하면 저장소에 저장된 YAML 파일을 이용하여 반복적인 작업과 배포 프로세스를 자동화할 수 있습니다. 액션 워크플로는 푸시, 풀 리퀘스트 또는 스케줄과 같은 GitHub 이벤트에 의해 트리거되며 가상 환경에서 실행됩니다 . GitHub Actions를 사용할 때 보게 될 몇 가지 용어를 살펴보겠습니다. 모든 용어를 다 설명하지는 않겠지만, 핵심적인 내용은 이벤트, 초청 참가자, 그리고 일자리입니다. 이벤트는 워크플로를 시작하는 특정 활동입니다. 예를 들어 코드 푸시, 풀 리퀘스트 열기 또는 이슈 생성 등이 있습니다. 러너는 워크플로우 에서 작업을 실행하는 가상 머신입니다 . GitHub는 호스팅된 실행 도구를 제공하며, 사용자가 직접 호스팅 실행 도구를 설정할 수도 있습니다. 작업은 동일한 실행기 내에서 실행되는 일련의 단계입니다 . 각 단계는 셸 명령이거나 GitHub Marketplace에서 미리 빌드된 액션입니다 . 이제 워크플로는 저장소의 이벤트에 의해 트리거됩니다. 이는 풀 리퀘스트를 보내거나, 브랜치를 병합하거나, 심지어 이슈를 제기하는 것일 수도 있습니다. 이벤트가 발생하고 해당 이벤트에 응답하는 워크플로가 있는 경우 GitHub는 러너에서 실행되는 하나 이상의 작업을 생성합니다. 이것이 바로 GitHub Actions 워크플로의 기본 작동 방식입니다. 처음에 작업 탭으로 이동하여 새 워크플로 버튼을 클릭하면 사용할 수 있는 몇 가지 기본 워크플로가 제안됩니다 . 제안된 작업 중 하나를 클릭하면 작업 워크플로를 구축할 때 알아야 할 세 가지 주요 섹션이 표시됩니다. 워크플로의 기능을 설명하는 이름 섹션, 워크플로를 트리거하는 조건을 정의하는 시작 조건 섹션, 그리고 실제 작업이 이루어지는 작업 섹션으로 구성됩니다. GitHub Actions에 대해 더 자세히 알아보려면 GitHub Skills로 이동하여 Hello GitHub Actions 챌린지를 완료하세요. 이 에피소드와 관련된 블로그 게시물은 gh.io/gfb-actions에서 읽으실 수 있습니다. 자 , 이제 재밌는 부분입니다. 이제 실제로 워크플로우를 구축하는 방법을 살펴보겠습니다. 따라 하려면 이 저장소 링크로 이동하여 컴퓨터에 복제하세요 . 그다음 작업 시작 분기로 이동합니다 . 글렌다를 영입하여 이 워크플로우를 단계별로 함께 구축할 예정입니다. GitHub Actions는 YAML 구문을 사용하여 [음악] 워크플로를 정의합니다. 각 워크플로는 저장소의 특수 .github/workflows 디렉터리에 .yml 파일로 저장됩니다. 자, 이제 저장소의 루트에 있는 .github 폴더를 클릭하고, 그 안에 있는 workflows 폴더로 들어가겠습니다. 우리 저장소에 새로 생성되는 이슈에 자동으로 레이블을 지정하는 워크플로를 만들어 봅시다. 워크플로 파일을 만들 때는 build.yml 및 test.yml 또는 security-scanner.yml처럼 한눈에 어떤 기능을 하는지 알 수 있도록 설명적인 이름을 사용하세요. 자 , 그럼 우리 워크플로에 이름을 붙여봅시다. 파일 이름을 label-new-issue.yml로 지정하고, YAML 파일의 시작 부분에 이름 섹션을 추가하겠습니다. 이제 우리는 어떤 사건이 그것을 촉발할지 결정해야 합니다. GitHub에는 문서에 자세히 나와 있는 수많은 트리거 옵션이 있으므로, 개발 중인 내용에 따라 선택하세요. 풀 리퀘스트가 제출될 때 테스트를 실행하거나, 브랜치가 병합될 때 보안 문제를 검사하고 싶을 수도 있습니다 . 저희의 경우, 이슈 트리거를 사용한 다음 활동 유형을 열기로 추가하겠습니다. 이렇게 하면 새로운 GitHub 이슈가 생성될 때마다 레이블이 추가됩니다 . 자, 이제 본격적인 업무가 이루어지는 채용 부분으로 넘어가 보겠습니다 . 우선 우리 업무에 제목을 붙이고 어떤 종류의 기계로 업무를 처리할지 정하겠습니다. GitHub는 Ubuntu, Windows 및 macOS의 다양한 버전을 지원하는 호스팅 실행 도구를 제공합니다. 이 작업의 이름을 label-issues로 지정 하고 최신 Ubuntu에서 실행해 보겠습니다. 이는 GitHub에게 최신 버전의 Ubuntu를 사용하는 머신을 풀에서 선택하도록 지시하는 것입니다 . 레이블을 추가할 수 있도록 여기에 쓰기 권한도 추가해야 합니다. 그럼, 권한 문제도 추가해 봅시다. 작업 내에서 권한 키를 사용하면 작업 내의 모든 작업 및 실행 명령이 지정된 액세스 권한을 얻게 됩니다. 이제 단계를 추가해 보겠습니다. 여기서 우리는 업무에서 실제로 일어나는 일을 정의합니다 . 여기에는 '사용'과 '실행'이라는 두 가지 주요 키워드가 있습니다. '사용'이라는 항목이 보이면, GitHub 마켓플레이스에서 미리 만들어진 액션을 가져오는 것을 의미합니다. 예를 들어 코드를 체크아웃하거나 Node.js를 설정하는 것과 같은 작업입니다. 이것들은 오픈 소스이며 재사용 가능한 액션으로, 일반적인 작업을 처리하므로 모든 것을 처음부터 작성할 필요가 없습니다 . '실행'이라는 단어가 보이면, 그것은 명령이나 스크립트를 실행하는 것을 의미합니다. 이처럼 간단한 한 줄짜리 코드일 수도 있고, 여러 줄로 된 스크립트일 수도 있습니다. 다음 단계는 환경 변수를 설정하는 것입니다. 자동으로 설정되는 gh_token, gh_repo 및 number 변수를 사용하겠습니다 . 즉, GitHub Actions는 이러한 비밀 키와 GitHub 컨텍스트를 기반으로 해당 변수에 사용할 값을 자동으로 파악합니다. gh_token, secrets.github_token을 추가하고 , issue_number, github.event.issue.number를 추가한 다음, 마지막으로 추가할 레이블 목록인 label을 추가해 보겠습니다. 이 기능이 제대로 작동하려면 해당 레이블이 저장소에 존재해야 합니다. 우리는 환자 분류 라벨을 추가할 것입니다. 이것으로 첫 번째 워크플로우가 완료되었습니다. 이 모든 것을 종합하면, 이 워크플로는 GitHub Actions에게 새 이슈가 열리면 최신 Ubuntu 버전에서 실행하고 이슈에 분류 레이블을 추가하도록 지시합니다. GitHub Actions 워크플로 구문은 많은 유연성을 제공하지만, 처음 시작할 때는 최대한 간단하게 유지하는 것이 좋습니다. 이제 방금 만든 워크플로를 GitHub에 푸시하고, PR을 생성하고, 메인 브랜치에 병합하고, 저장소에 새 이슈를 생성하는 단계로 추가해 보겠습니다. 새로운 이슈를 열어봅시다. 이것을 테스트 워크플로라고 부르고 만들기를 클릭합니다. 몇 초 안에 GitHub Actions 팝업창이 뜨면서 'triage'라는 레이블이 추가되는 것을 볼 수 있습니다. 워크플로가 실제로 어떻게 실행되는지 보려면 작업 탭으로 이동해 보겠습니다. 왼쪽의 작업 탭을 보면 ' 레이블 새 이슈 워크플로'가 있습니다. 클릭하면 작업 레이블 문제를 볼 수 있습니다. 그리고 해당 작업을 클릭하면 작업을 완료하는 데 사용된 단계를 확인할 수 있습니다 . 이 탭에서 Actions 워크플로를 실행하고 다시 실행할 수 있습니다. 그리고 일시적으로 중지해야 하는 경우 파일을 삭제하는 대신 작업 탭에서 직접 비활성화할 수 있습니다. ' 작업' 탭에서는 모든 워크플로를 확인하고 관리할 수 있습니다. 이 화면에서 배포, 실행기, 메트릭, 성능 및 캐시를 확인할 수 있습니다. 이 탭에서 워크플로 파일을 보고 편집할 수도 있습니다. 축하합니다! 첫 번째 GitHub Actions 워크플로를 성공적으로 구축하셨습니다. 글렌다, GitHub Actions 워크플로우를 처음 구축하고 GitHub에서 테스트하는 방법을 알려주셔서 정말 감사합니다 . 이제 GitHub Actions는 이슈에 라벨을 붙이는 것 이상의 훨씬 더 많은 작업을 수행할 수 있습니다. 패키지를 게시하고, 새로운 기여자를 환영하고, 코드를 빌드 및 테스트하고 , 심지어 보안 검사를 실행하는 등의 작업을 생성할 수 있습니다.
