## 스크립트

참조 데이터를 최신 상태로 유지하면서 동시에 데이터 스트림을 빠르게 보강하는 데 어려움을 겪었을 수 있습니다. 참조 데이터를 캐시에 저장 하지 않고는 데이터를 빠르게 보강하기 어렵고, 데이터가 캐시되면 오래된 값이 남게 됩니다. 반대로 매번 데이터베이스에서 직접 조회하는 방식은 실시간 분석에 너무 느립니다. 이번 시리즈 2부에서는 APF 링크를 사용하여 실시간 게임 리더보드 애플리케이션을 구축하는 방법을 5개의 에피소드를 통해 배우게 됩니다. 데이터 수집, 보강, 시각화에 이르기까지 스트리밍 아키텍처의 모든 부분을 살펴보고, A/B 테스트를 위한 제어 채널, 지연 도착 데이터 처리, 정확한 한 번 아카이빙, 온디맨드 데이터 재생과 같은 고급 분석 기법도 배우게 됩니다. 지난 영상에서는 구축 중인 스트리밍 아키텍처의 개요 와 데이터 수집 부분을 설명했습니다. 1부를 아직 시청하지 않으셨다면 시청을 권장합니다. 스트리밍 개념과 전체 아키텍처에 대한 이해도를 높일 수 있습니다. 이번 영상에서는 SQL 데이터베이스 체인을 사용하여 데이터 스트림을 빠르게 보강하는 방법을 보여드리겠습니다. 데이터 캡처와 데이터 최신성에 대해서도 이야기해 보겠습니다. 필요한 모든 것이 포함된 GitHub 저장소는 아래 설명에서 찾을 수 있습니다. 자, 시작해 볼까요? 먼저 CDC(데이터 캡처)가 무엇이고, 이 CDC 방식을 사용하여 Flink에 캐시된 상태를 업데이트하는 방법을 이해해 보겠습니다. 데이터베이스에 ID와 구독 유형 두 필드를 가진 테이블이 있다고 가정해 보겠습니다. 플레이어 1의 구독 유형은 무료입니다. 이를 초기 설정이라고 합니다. 이 초기 설정이 완료되면 CDC 커넥터는 이벤트를 통해 이 데이터를 Flink 상태로 가져옵니다. 이 경우 이벤트는 삽입(INSERT)입니다. 이제 미래 시점(T2)에 새로운 행이 추가되어 플레이어가 목표 멤버십에 가입했다고 가정해 보겠습니다. 다시 삽입 이벤트가 Flink로 전파됩니다. 다음으로 플레이어 1이 구독 유형을 무료에서 7일 체험판으로 업그레이드하면 업데이트 이벤트가 생성됩니다. 이번에는 삽입 이벤트가 아니라 삭제 이벤트가 생성됩니다. 마지막으로 플레이어 2의 데이터가 삭제되면 삭제 이벤트가 생성됩니다. 이러한 이벤트는 데이터베이스와 동기화되어 Flink 상태를 업데이트하고 유지하는 데 도움이 됩니다. 데이터베이스에 있는 값을 정확하게 반영하는 최신 업데이트 값을 사용합니다. 이 Flink 상태의 반영된 데이터를 가입 프로세스에 어떻게 활용할지 설명하겠습니다. 예를 들어, 시간 T1에 플레이어 1이 무료 멤버십을 가지고 있다고 가정해 보겠습니다. 같은 플레이어의 탈퇴 이벤트( PED 280)를 수신하면, 가입 및 도달 데이터는 플레이어 1의 구독 유형이 무료이고 속도는 280으로 표시됩니다. 하지만 나중에 시간 T3에 같은 데이터가 수신되면 플레이어 1의 속도는 300이 됩니다. Flink는 데이터베이스에서 최신 데이터를 이미 받아 캐시에 저장했기 때문입니다. Flink는 "플레이어 1에 대한 데이터를 다시 생성해야 하는데, 이번에는 구독 유형이 7일 무료 체험으로 업데이트되었으므로 속도는 300이 됩니다."라고 판단합니다. 지금까지 구축한 것은 아키텍처 의 데이터 수집 부분입니다. 이제 두 가지 구성 요소를 더 추가하겠습니다. 하나는 데이터베이스에 업데이트, 삭제, 삽입 이벤트를 지속적으로 생성하는 데이터 생성기인 Lambda 함수이고, 다른 하나는 이 데이터베이스를 Flink에 연결하는 것입니다. 이제 코드 변경 사항에 대한 개요를 설명하겠습니다. CDK 변경 사항을 설정에 배포하는 방법을 안내해 드리겠습니다. 보시다시피 이미 데이터 주입 부분은 완료되었습니다. 이 경우 두 번째 분기인 CDC 강화 설정부터 시작합니다. 이 설정은 기본적으로 두 가지 서브넷 유형을 가진 VPC(VPC) 네트워크를 생성합니다. 첫 번째는 양방향 인터넷 연결을 허용하는 퍼블릭 서브넷이고, 두 번째는 AWS 리소스가 인터넷에 접속할 수 있도록 허용하지만 역방향 트래픽은 차단하는 프라이빗 서브넷입니다. 다음으로 서버리스 데이터베이스를 설정하는데, 두 가지 옵션이 있습니다. 첫 번째는 Aurora MySQL을 사용하는 것입니다. 데모에서는 EC2 기반 MySQL 설정을 사용하겠습니다. 이 설정은 데이터베이스 자격 증명을 관리하는 시크릿 관리자와 MySQL 데이터베이스를 실행하는 인스턴스로 구성됩니다. 세 번째는 플레이어용 데이터 생성기로, 삽입, 업데이트 및 삭제 이벤트 측면에서 변경 사항을 데이터베이스에 반영합니다. 이제 배포를 진행해 보겠습니다. 다시 터미널로 돌아가서 두 번째 분기의 infra 폴더에서 ` cdk deploy`를 입력합니다. 변경 사항을 배포하라는 메시지가 나타나면 '예'를 선택하여 확인합니다. 변경 사항이 배포될 때까지 기다리겠습니다. 이 아키텍처에 대해 궁금한 점이 있으면 댓글을 남겨주시면 답변해 드리겠습니다. WEA CDC 커넥터를 빌드하는 코드가 어디에 있는지 보여드리겠습니다. jar 폴더에 있습니다. 이미 컴파일된 jar 파일 하나가 있을 겁니다. pom.xml 파일인데, 이 파일이 빌드를 담당합니다. pom.xml은 모든 종속성을 포함하는 fat jar를 빌드하는 Java 방식입니다. 이 pom.xml에는 두 개의 라이브러리가 포함되어 있습니다. 첫 번째는 MySQL용 Vevera 커넥터이고, 두 번째는 MySQL 커넥터 Java입니다. 그리고 모든 종속성을 통합하고 fat jar를 빌드하는 Shar 플러그인이 있습니다. 우리가 가지고 있는 CDK를 사용하면 이 fat jar가 이미 AWS에 배포됩니다. 노트북에서 이 파일을 참조하면 됩니다. 이런 식으로 jar를 사용하므로 이전에 설명했던 테이블에 대해 Mascu CDC를 커넥터 유형으로 사용할 수 있습니다. Apache Link용 CDC 커넥터를 사용하여 MySQL에서 CDC 변경 사항을 스트리밍하는 방법도 이미 설명했습니다. 이제 이 커넥터를 빌드하고 사용하는 방법을 알아보겠습니다. 보시다시피 노트북에서 CloudFormation 콘솔 스택에 두 개의 새로운 출력이 나타납니다. 첫 번째는 MySQL 자격 증명 링크이고 두 번째는 MySQL 데이터베이스의 호스트 이름입니다. 이제 K's 분석 서비스와 스튜디오 노트북으로 이동하면 이전 단계에서 생성했던 것과 매우 유사한 새 스튜디오 노트북이 나타납니다. 이제 실행을 클릭하여 노트북을 시작하고 Zeppelin 열기를 클릭하여 Zeppelin을 로드합니다. 가져오기를 클릭하고 동일한 노트북 폴더에서 Challenges 노트북을 선택한 다음 열기를 클릭하면 새 Challenges 노트북이 로드됩니다. 이제 이 노트북을 열어 보겠습니다. 이미 생성한 이벤트 테이블이 있습니다. 만약 생성하지 않았다면 지역을 변경하고 다시 실행하세요. 이 명령은 테이블을 삭제하고 이미 존재하는 경우 다시 생성하므로 여러 번 실행할 수 있습니다. 제 경우에는 US East1 지역이므로 다시 실행합니다. 이제 플레이어 테이블로 이동하면 MySQL CDC 커넥터를 사용하는 것을 볼 수 있습니다. CloudFormation에서 호스트 이름과 암호를 가져오세요. 플레이어 테이블 스키마를 이미 여기에서 볼 수 있습니다. 이 스키마에는 작업 시간 스탬프, 플레이어 ID, elas 등 다양한 필드가 포함되어 있습니다. 작업 시간 스탬프는 삽입, 업데이트, 삭제와 같은 특정 작업의 시간 스탬프입니다. 나머지 스키마는 여기에 있습니다. 이제 테이블이 생성된 것을 볼 수 있습니다. 플레이어 ID 열을 사용하여 두 테이블을 조인할 것입니다. 이벤트 테이블에는 이벤트 시간과 이벤트 시간(TZ) 필드도 있습니다. 주요 차이점은 이벤트 시간(TZ)이 시간대를 나타낸다는 것입니다. 여기서 여러분의 과제는 플레이어 테이블에서 데이터를 선택하는 것입니다. 다음 두 명령어를 사용하여 스키마를 설명할 수 있습니다. 다음 과제는 플레이어 테이블에서 데이터를 선택하여 국가별 플레이어 분포를 보여주는 원형 차트를 그리는 것입니다. 세 번째 과제는 시스템 시간을 기준으로 플레이어 테이블과 이벤트 테이블을 조인하는 것입니다. 이벤트 시간대를 사용하세요. Apache Flink에서 시간 조인이 어떻게 작동하는지에 대한 자세한 내용은 이 링크를 참조하세요. 이 비디오에서는 실시간 스트리밍 보강을 통해 데이터를 최신 상태로 유지하는 방법을 배웠습니다. 이 시리즈가 마음에 드셨다면 이 비디오에 좋아요를 누르고 구독을 고려해 주세요. 다음 비디오에서는 데이터를 처리하고 계산하는 방법을 보여드리겠습니다. 순위표를 만들고 이해하기 쉬운 시각 자료를 제작할 예정이니 기대해 주세요.
