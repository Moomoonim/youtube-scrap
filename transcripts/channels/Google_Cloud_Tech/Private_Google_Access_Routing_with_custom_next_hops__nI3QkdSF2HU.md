[음악] 이 영상에서는 사용자 지정 방화벽이나 프록시를 우회하여 Google API에 대한 지원되는 라우팅 경로를 구성하는 방법을 배우게 됩니다 . 이전에는 Comput Engine 인스턴스가 비공개 Google 액세스를 사용하여 Google API 및 서비스에 액세스하는 매우 간단한 경로를 살펴보았습니다 . 하지만 현실 세계에서 기업 네트워크는 그렇게 단순한 경우가 드뭅니다. 일반적인 보안 패턴은 모든 아웃바운드 트래픽을 방화벽이나 프록시 서버 역할을 하는 자체 관리형 VM과 같은 사용자 지정 넥스트 홉을 통해 라우팅하는 것입니다 . 이렇게 하면 인터넷 트래픽은 안전해지지만 , Google API와 통신할 때는 큰 문제가 발생합니다. 방화벽 VM을 통해 컴퓨팅 엔진 트래픽을 GCS 또는 파일 저장소와 같은 서비스로 라우팅하면 방화벽이 성능 병목 현상이 됩니다. 이러한 설정은 종종 네트워크 혼잡을 초래하여 처리량 감소, 지연 시간 급증 또는 최악의 경우 연결 끊김을 야기합니다. 이 문제에 대한 해결책은 Google APIs.com 및 기타 Google 클라우드 도메인 이름으로 향하는 트래픽이 프록시 서버를 우회할 수 있도록 정적 경로를 구성하는 것입니다 . 클라우드 스토리지, 컴퓨팅, 파일 저장소, 비트쿼리 등과 같은 클라우드 서비스의 대부분의 API 엔드포인트는 모두 Google APIs.com의 하위 도메인입니다. 하지만 한 가지 큰 단점이 있습니다. 네트워크 경로는 도메인 이름이 아닌 IP 주소를 사용하여 구성됩니다 . 이 웹 페이지는 공용 인터넷 공간에서 접속 가능한 모든 IP 주소 및 서브넷의 목록을 제공합니다 . 보시는 바와 같이, Google Cloud 리소스는 단일 IP 주소를 가진 단일 서버에 호스팅되지 않습니다. 수백 개의 계속 바뀌는 IP 주소에 대해 허용 목록이나 고정 경로를 유지하는 것은 현실적으로 불가능하며 , 이는 사실상 해당 IP 주소를 이동 표적처럼 취급하게 만듭니다. 먼저, 이 시나리오가 여러분의 환경에도 적용되는지 확인해 보겠습니다. 네트워크 인텔리전스 센터로 이동하여 연결 테스트를 생성하십시오. 해당 경로 에 'Google API 경로'와 같은 레이블을 지정하세요 . 네트워크 트래픽이 시작될 VM을 선택하십시오. 다음으로 Google APIs.com 도메인 이름에 대한 대상 IP 주소 예시로 199.36.153.8을 사용하겠습니다 . 테스트가 완료되면 이름을 클릭하여 결과를 확인하세요. 네트워크 트래픽이 구글 API 서버로 성공적으로 전달되는 것을 확인할 수 있습니다 . 하지만 여기에 표시된 경로는 트래픽이 다른 VM으로 전달될 것임을 나타냅니다. 연결 테스트 결과 패킷의 다음 홉이 인터넷 게이트웨이 이외의 다른 곳으로 표시되면 API 트래픽이 Google API 서버에 도달하는 데 잘못된 경로를 사용하고 있다는 의미입니다 . 이 문제를 해결하려면 두 가지를 해야 합니다. 한 가지 방법은 클라우드 DNS 서버를 구성하여 Google APIs.com의 모든 하위 도메인을 private.googleapis.com이라는 Google 개인 액세스 전용 단일 도메인 이름으로 해석하도록 하는 것입니다 . 다음으로, 이 도메인 이름이 고정된 네 개의 IP 주소 집합을 통해 접근 가능하도록 구성하겠습니다 . VPC 서비스 제어가 필요한 경우 restricted.googleapis.com을 대신 사용할 수도 있지만 구성 로직은 동일합니다. 실제 방법은 다음과 같습니다 . 네트워크 서비스에서 클라우드 DNS로 이동하세요. 개인 DNS 영역을 생성합니다. ' 개인 Google 액세스'와 같은 이름을 지정 하고 DNS 이름으로 Google APIs.com을 사용하세요 . 이 영역을 적용할 VPC 네트워크를 하나 이상 선택한 다음 만들기를 클릭합니다. 다음으로 표준 레코드를 생성합니다. DNS 이름으로 사용하려면 별표(*)를 추가하기만 하면 됩니다. 레코드 유형으로 CNAME을 선택하고 정규 이름으로 private.googleapis.com을 선택합니다. 별표는 와일드카드 역할을 하여 googleis.com의 모든 하위 도메인을 포함하고 private.googleapis.com으로 리디렉션합니다. 마지막으로, 추가 레코드 세트를 하나 생성합니다 . 이번에는 A형으로 설정하겠습니다. DNS 이름 필드에는 ' private'라고 입력하세요. 그다음 1 199.36.153.8.9와 같은 네 개의 IP 주소를 추가하세요 . 8.910.11. DNS 설정이 완료되면 Google apis.com 또는 하위 도메인에 대한 모든 요청은 항상 private.googleapis.com으로 연결되며, 이 도메인은 이 레코드 세트에 나열된 네 개의 고정 IP 주소를 통해 접속할 수 있습니다 . 이처럼 간소화된 DNS 구성을 통해 새로운 정적 경로를 생성할 수 있습니다. VPC 네트워크 페이지에서 '라우트'로 이동한 다음 '라우트 관리'를 클릭합니다. 경로 생성 버튼을 클릭하세요 . ' 개인 Google 액세스'와 같은 이름을 입력한 다음 이 경로가 적용될 네트워크를 입력하세요. 대상 IP 범위로 서브넷 마스크 199.36.153.8/30을 사용하십시오. 네트워크 트래픽 흐름을 방해할 수 있는 다른 경로보다 우선 순위를 갖도록 적절한 우선순위를 설정하십시오 . 값이 낮을수록 우선순위가 높습니다. 마지막으로, 다음 홉이 기본 인터넷 게이트웨이로 설정되어 있는지 확인하십시오. 이 설정은 VPC에게 이러한 Google IP 주소로 향하는 트래픽을 제외한 모든 트래픽을 방화벽으로 보내도록 지시합니다. 그것들을 구글에 직접 보내세요. 연결 테스트 도구로 돌아가서 테스트를 다시 실행하세요. 클라이언트 VM에서 Google API 서버로의 네트워크 트래픽이 여전히 도달 가능한 것을 확인할 수 있습니다. 하지만 이번에는 다음 단계가 인터넷 게이트웨이입니다. 축하해요. 이를 통해 새 DNS 설정과 네트워크 경로가 트래픽을 Google API 서버로 직접 전송하는지 확인할 수 있습니다 .
