## 스크립트

안녕하세요, 다시 오신 것을 환영합니다. 다음으로 자동화 디자인 패턴에 대해 이야기해 보겠습니다. 웹훅과 런치라는 두 가지 자동화 유형을 배웠는데, 어떤 경우에 어떤 것을 사용해야 할지 궁금하실 수 있습니다. 이 슬라이드에서는 웹훅과 런치를 비교하여 기본적인 개념을 설명해 드리겠습니다. 웹훅 과 런치는 모두 이벤트에 의해 트리거될 수 있으며, 이 이벤트는 모델 레지스트리에서 태그를 추가하거나 아티팩트를 추가하는 등의 작업일 수 있습니다. 웹훅에서 이벤트가 발생하면 페이로드가 전송됩니다. 페이로드는 일종의 정보 패키지로, 레지스트리의 아티팩트에 있는 가중치, 편향, 메타데이터 등의 정보를 담고 있습니다. 웹 서버는 이 웹훅을 수신하는데, 이 웹 서버를 컨슈머라고 부릅니다. 항상 소비자인 것은 아니지만, 웹 서버라고 부르는 이유는 웹훅이 개발자 도구에서 매우 흔하게 사용되기 때문입니다. 웹훅을 수신할 수 있는 도구는 웹 서버일 필요는 없으며, GitHub Actions가 그 예입니다. Weights and Bias는 GitHub Actions로 이벤트를 보낼 수 있습니다. 웹훅을 사용하면 큐(Q) 관리가 필수적입니다. 큐는 실행하려는 모든 작업을 저장하는 공간입니다. Weights and Bias가 웹훅을 실행하면 페이로드를 수신하게 되고, 여러 페이로드를 수신할 경우 어떤 순서로 처리하고 추적할지 등을 직접 구현해야 합니다. 웹훅의 핵심 아이디어는 자체 웹 서버를 구축하고 모든 것을 직접 관리하는 것이 아니라, GitHub Actions와 같은 타사 소프트웨어와 통합하는 것입니다. 웹훅을 통해 할 수 있는 또 다른 작업은 다음과 같습니다. Hooks는 Weights and Bias 위에 도구를 구축할 수 있도록 해줍니다. WebBooks는 범용적이고 유연한 패러다임으로, 원하는 모든 작업을 수행할 수 있도록 해줍니다. 매우 유연하며, 페이 로드를 포착하고 그 페이 로드에 따라 수행할 작업을 결정할 수 있습니다. 아티팩트를 다운로드하거나 필요한 모든 작업을 수행할 수 있습니다. Launch는 이와는 조금 다릅니다. Weights and Bias에서는 이벤트에 대한 응답으로 코드를 실행해야 하는 경우가 많습니다. 특히 학습 코드나 평가 코드를 실행하고 싶을 수 있습니다. 예를 들어, 학습 실행을 위해 웹 서버를 구축하고, 페이로드를 포착하고, 자체 큐를 관리하고, 최종적으로 코드를 실행하는 등의 과정을 직접 구현하는 대신, Launch는 이러한 모든 과정을 매우 간편하게 처리해 줍니다. 학습 실행이나 평가 실행을 위해 Launch는 이벤트가 발생하면 해당 이벤트를 포착하여 코드를 실행합니다. 큐(Quee)와 가중치 및 편향(Weights and Bias)은 큐를 사용합니다. 기본적으로 사용자는 가상 머신, 로컬 머신, Kubernetes 등 원하는 컴퓨팅 환경에서 에이전트를 실행합니다. 에이전트는 큐에서 데이터를 소비하므로, 큐를 지속적으로 관리하고 필요한 데이터를 가져옵니다. 큐에 데이터가 추가되면 에이전트가 큐에서 데이터를 가져오는 방식이라 매우 편리합니다. Launch는 학습 및 평가 실행을 위해 설계되었으며, 에이전트는 사용자가 선택한 컴퓨팅 환경에서 Docker 또는 Python 코드를 실행하도록 되어 있습니다. 학습 또는 평가 실행이 필요한 경우 Launch를 사용하는 것이 좋습니다. 하지만 가중치 및 편향을 기반으로 다양한 기능을 갖춘 도구를 개발하거나, 웹훅을 제공하는 타사 서비스와 통합하려는 경우에는 다른 방법을 사용할 수 있습니다. 웹훅에 대해 다시 한번 요약해 드리겠습니다. 웹훅은 타사 애플리케이션과의 통합을 위한 것이며, 바로 그러한 목적으로 설계되었습니다. 큐 관리는 직접 해야 하지만, 웹훅을 사용하여 가중치 및 편향(Weights and Bias) 기반의 맞춤형 도구와 애플리케이션을 구축할 수도 있습니다. 웹훅은 가장 유연하고 범용적인 통신 패턴이라고 할 수 있습니다. 여러 애플리케이션이 서로 통신할 때, 인프라에 대한 가정이 거의 또는 전혀 없이 필요한 방식으로 직접 구축할 수 있습니다. Launch는 이러한 부분에서 약간의 도움을 줍니다. Launch를 사용하면 가중치 및 편향 큐를 관리할 수 있으며, 이벤트에 대한 응답으로 원하는 컴퓨팅 환경에서 Python 및 Docker 코드를 실행할 수 있는 경로가 마련되어 있습니다. 여기서 ' 원하는 컴퓨팅 환경'은 매우 일반적이며, Kubernetes를 포함한 어디에서든 실행할 수 있습니다. AWS용 SageMaker나 GCP용 Vertex와 같은 환경에서도 사용 가능합니다. 웹훅은 주로 학습 또는 평가 실행에 사용됩니다. 이 설명이 여러분의 이해를 돕는 데 도움이 되었기를 바랍니다. 웹훅과 런치 기능을 언제 사용해야 할까요?
