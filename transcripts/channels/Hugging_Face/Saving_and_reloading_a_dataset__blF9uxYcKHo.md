## 스크립트

이 비디오에서는 데이터 세트를 다양한 형식으로 저장하고 저장된 데이터를 다시 불러오는 방법을 살펴보겠습니다. 데이터 세트를 다운로드하면 처리 스크립트와 데이터가 컴퓨터의 로컬에 저장됩니다. 캐시를 통해 데이터 세트 라이브러리는 데이터 세트를 사용할 때마다 전체 데이터 세트를 다시 다운로드하거나 처리하지 않아도 됩니다. 하위 데이터는 Arrow 테이블에 저장되며, 해당 위치는 데이터 세트의 캐시 파일 속성을 통해 확인할 수 있습니다. 이 예에서는 Huggy Face Hub에서 Alisin 데이터 세트를 다운로드했으며, 캐시 에 각 분할에 대한 Arrow 파일 3개가 저장된 것을 볼 수 있습니다. 하지만 대부분의 경우 표에 나와 있는 것처럼 데이터 세트를 다른 위치나 형식으로 저장해야 합니다. 데이터 세트 라이브러리는 이를 위해 네 가지 주요 기능을 제공합니다. CSV 및 JSON 형식은 이미 익숙하실 텐데, 이 두 형식은 작 거나 중간 크기의 데이터 세트를 빠르게 저장하는 데 적합합니다. 하지만 데이터 세트가 매우 큰 경우에는 Arrow 또는 Parket 형식으로 저장하는 것이 좋습니다. Arrow 파일은 데이터를 다시 불러오거나 처리할 계획이 있는 경우에 유용합니다. 가까운 미래에 paret 파일은 장기 저장을 위해 설계되었으며 공간 효율성이 매우 뛰어납니다. 각 형식을 자세히 살펴보겠습니다. Arrow 형식으로 데이터 세트 또는 데이터 세트 딕셔너리 객체를 저장하려면 ` save to disk` 함수를 사용합니다. 이 예제에서 볼 수 있듯이 데이터를 저장할 경로만 제공하면 데이터 세트 라이브러리가 Arrow 테이블과 메타데이터를 저장할 각 분할에 대한 디렉터리를 자동으로 생성합니다. 여러 분할을 가진 데이터 세트 딕셔너리 객체를 다루는 경우 이 정보는 데이터 세트 딕셔너리 JSON 파일에도 저장됩니다. 이제 Arrow 데이터 세트를 다시 로드하려면 `load from disk` 함수를 사용합니다. 데이터 세트 디렉터리의 경로만 전달하면 원래 데이터 세트가 복구됩니다. 데이터 세트를 CSV 형식으로 저장하려면 `two CSV` 함수를 사용합니다. 이 경우 데이터 세트 딕셔너리 객체의 분할을 반복하면서 각 데이터 세트를 개별 CSV 파일로 저장해야 합니다. `two CSV` 함수는 pandas의 함수를 기반으로 하므로 키워드 인수를 전달하여 출력을 구성할 수 있습니다. 이 예제에서는 인덱스 인수를 `None`으로 설정하여 오류가 발생하지 않도록 했습니다. CSV 파일에 데이터 세트의 인덱스 열이 포함되지 않도록 하려면, CSV 파일을 다시 로드하기 위해 익숙한 `load data set` 함수 와 CSV 로딩 스크립트, 그리고 각 분할 과 관련된 파일 이름을 지정하는 `data files` 인수를 함께 사용합니다. 이 예제에서 볼 수 있듯이 모든 분할과 해당 파일 이름을 제공함으로써 원래 데이터 세트 딕셔너리 객체를 복구할 수 있습니다. 이제 데이터 세트를 JSON 또는 PART 형식으로 저장하는 방법은 CSV의 경우와 매우 유사합니다. JSON 파일의 경우 `two Json` 함수를, PART 파일의 경우 `two pet` 함수를 사용합니다. CSV의 경우와 마찬가지로 각 분할을 개별 파일로 저장하기 위해 반복문을 사용해야 합니다. 데이터 세트가 JSON 또는 PART 파일로 저장되면 `load data set` 함수 에서 해당 스크립트를 사용하여 다시 로드할 수 있습니다. 이전과 마찬가지로 `data files` 인수를 제공하기만 하면 됩니다. 이 예제는 두 가지 형식 모두 에서 저장된 데이터 세트를 다시 로드하는 방법을 보여줍니다. 이제 다양한 형식으로 데이터 세트를 저장하는 방법을 알게 되었습니다.
