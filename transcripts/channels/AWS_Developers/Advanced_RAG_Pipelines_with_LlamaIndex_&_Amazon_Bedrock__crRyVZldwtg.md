## 스크립트

오늘날 데이터 중심 세상에서 필요한 정보를 빠르게 찾는 것은 매우 중요합니다. 그렇다면 인공지능 비서가 단순히 검색만 하는 것이 아니라 이해하고 추론까지 할 수 있다면 어떨까요? 안녕하세요, 저는 스튜어트입니다. 첨단 증강 현실(Advanced Augmented Generation, 줄여서 RAG)의 세계에 오신 것을 환영합니다. 여기서는 Llama Index와 Amazon Bedrock이 협력하여 복잡한 질문을 분석하고, 여러 문서를 분석하여 추론하고, 포괄적인 답변을 제공할 수 있는 지능형 시스템을 개발했습니다. 그럼 먼저 하위 질문 쿼리부터 살펴보겠습니다. 예를 들어, "2020년과 2021년 Uber와 Lyft의 매출 성장률을 비교해 보세요"라고 질문한다고 가정해 보겠습니다. 간단해 보이지만, 분석해야 할 부분이 많습니다. Llama Index의 하위 질문 쿼리 엔진을 사용하면 이 질문을 관리하기 쉬운 부분으로 나눌 수 있습니다. 예를 들어, "Uber의 2020년 매출은 얼마였나요?", "Uber의 2021년 매출은 얼마였나요?", "Lyft의 2020년 매출은 얼마였나요?", "Lyft의 2021년 매출은 얼마였나요?"와 같이 세분화할 수 있습니다. 2021년, 이러한 간단한 질문에 답함으로써 결과를 종합하여 더욱 정확하고 포괄적인 답변을 얻을 수 있습니다. 코드를 통해 이를 구현하는 방법을 살펴보겠습니다. 먼저 Llama 인덱스에서 필요한 클래스를 가져옵니다. Uber 인덱스와 LT 언더스코어 인덱스는 이전에 생성되었다고 가정하고, 해당 부분은 넘어가겠습니다. 다음으로, 이들을 쿼리 엔진으로 변환합니다. 이를 위해 쿼리 엔진 도구 객체 목록을 생성합니다. 각 도구는 쿼리 엔진을 래핑하고, 어떤 정보에 접근할 수 있는지에 대한 메타데이터를 제공합니다. 그 후, ` from uncore defaults` 메서드를 사용하여 하위 질문 쿼리 엔진을 생성합니다. 이 메서드는 도구 목록을 전달합니다. 마지막으로 복잡한 질문을 엔진에 쿼리합니다. 엔진은 자동으로 질문을 하위 질문으로 분해하고, 적절한 도구를 사용하여 쿼리한 후, 답변을 생성합니다. 하지만 질문에 더 많은 추론이 필요한 경우는 어떨까요? React Agent가 탑재된 Genetic Rack을 사용해 보겠습니다. 저희 인공지능은 단순히 질문에 답하는 것이 아니라, 어떻게 답해야 할지까지 생각합니다. 정말 멋진 기능이죠. 예를 들어, Lift의 매출 성장률에 대해 질문하면, 에이전트는 " 먼저 찾아야 할 것이 있다"라고 판단할 수 있습니다. 먼저 재무 보고서를 살펴보고 관련 연도의 매출액을 추출한 다음 성장률을 계산합니다. 에이전트는 다양한 도구를 사용하여 여러 데이터 소스를 쿼리하고 복잡한 작업을 분해하여 가장 정확한 답변을 제공할 수 있습니다. 작동 방식 과 설정 방법을 보여드리겠습니다. 예를 들어 다음 코드를 살펴보겠습니다. 먼저 React 에이전트를 포함한 필요한 클래스를 가져옵니다. ltor 인덱스는 이전에 생성되었다고 가정하고 이를 쿼리 엔진으로 변환합니다. 재무 계산기 클래스도 존재한다고 가정해야 하지만, 이 모든 내용은 예제 코드에 포함되어 있습니다. 도구 목록을 정의합니다. 첫 번째는 재무 데이터에 접근하는 쿼리 엔진 도구이고, 두 번째는 재무 계산기를 사용하는 사용자 지정 도구입니다. `from uncore tools` 메서드를 사용하여 React 에이전트를 생성하고 도구 목록과 이전에 정의한 대형 언어 모델( llm)을 전달합니다. `chat` 메서드를 사용하여 에이전트와 상호 작용할 수 있습니다. 생성형 AI에 질문하는 것처럼 질문을 전달하면 에이전트는 추론 능력을 사용하여 어떤 도구를 사용할지 결정합니다. 질문에 답하는 순서와 사용법을 알아보겠습니다. 이제 Amazon Bedrock과 Llama Index를 사용하여 이 모든 것을 통합해 보겠습니다. 먼저 Llama Pass를 사용하여 문서를 전달합니다. 다음 코드를 보면 어떻게 하는지 알 수 있습니다. 여기서는 Llama Pass와 Simple Directory Reader를 가져옵니다. 모든 PDF 파일을 전달하는 데 사용할 Llama Pass 객체를 생성합니다. 여기에 API 키를 지정해야 합니다. 출력 형식은 이 섹션에서만 생략했습니다. 병렬 작업자 수와 Vose 출력도 지정할 수 있습니다. 다음으로, PDF 파일 확장자를 전달하는 데 사용할 딕셔너리를 생성합니다. 이 딕셔너리의 이름은 File Under Extractor입니다. 그런 다음 입력 디렉터리와 File Extractor를 지정하여 Simple Directory Reader 객체를 생성합니다. 이 리더를 사용하여 지정된 디렉터리 에 있는 모든 PDF 파일을 로드합니다. 다음으로 Llama Index에서 Bedrock 관련 클래스를 가져와야 합니다. 여기서는 언어 모델용 Bedrock 객체를 생성하고 모델로 Clase V2를 지정합니다. 그런 다음 Bedrock 객체를 생성합니다. 임베딩 모델에 사용할 임베딩 객체를 생성할 때 Titan EMB 임베딩 모델을 지정할 수 있습니다. 다음으로 필요한 클래스를 가져와야 하는데, 여기에는 하위 질문 쿼리 엔진과 Amazon KnowledgeBase Retriever가 포함됩니다. Amazon KnowledgeBase Retriever 객체를 생성하고, 여기에서 KnowledgeBase ID, AWS 리전, 샘플링할 최대 토큰 수를 지정합니다. ` from defaults` 메서드를 사용하여 하위 질문 쿼리 엔진을 생성하고, Bedrock Retriever와 언어 모델을 전달합니다. 마지막 단계로, ` acquired` 메서드를 사용하여 디지털 가구 트렌드에 대한 질문을 전달하고 비동기적으로 엔진을 쿼리합니다. 이 전체 설정은 Llama Index의 고급 쿼리 기능 과 Amazon Bedrock의 강력한 모델 및 지식 기반을 결합합니다. Llama Index의 고급 쿼리 및 기술과 Amazon Bedrock의 강력한 모델 및 지식 기반을 결합하여 대규모 데이터 세트에 대한 복잡한 쿼리를 처리할 수 있는 매우 정교한 RAG 파이프라인을 구축합니다. 이 시스템은 단순히 정보를 찾는 데 그치지 않고 정보를 이해하고 추론합니다. 아래 설명에서 이러한 단계를 직접 시도해 볼 수 있는 예제 노트북 과 모든 예제를 찾을 수 있습니다. 이 내용이 도움이 되었다면 좋겠습니다. 이 비디오가 마음에 드셨다면, 더 많은 실습 위주의 기술 콘텐츠를 보시려면 이 비디오에 좋아요를 누르고 AWS Developers YouTube 채널을 구독해주세요. 시청해주셔서 감사합니다.
