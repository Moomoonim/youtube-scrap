## 스크립트

[음악] 구글 서비스에 안전하게 비공개로 접속해야 하는데 , PSC를 써야 할까요, 아니면 PSA를 써야 할까요? 이 문제를 스스로 해결하려고 하면 막막하게 느껴질 수 있습니다. 제 이름은 로렌 프라이스이고, 네트워크 전문 고객 엔지니어입니다. 이 영상에서는 사설 연결의 모든 방법 과 네트워크 연결 센터 기반 아키텍처에서 이러한 방법을 적용하는 방법을 살펴보겠습니다. 그렇다면 개인 연결에는 어떤 방법들이 있을까요 ? 첫 번째 종류의 비공개 네트워킹 방식은 API 기반 서비스에 사용됩니다. Gemini 클라우드 스토리지 및 BigQuery와 같은 API 기반 서비스는 비공개 연결을 위해 Google API용 PSC(Private Service Connect)를 사용합니다. 이 방법을 사용하려면 API 액세스가 필요한 모든 VPC 스포크에 글로벌 PSC 엔드포인트를 생성하고 모든 서브넷에서 비공개 Google 액세스 플래그를 활성화해야 합니다 . PSC 엔드포인트는 VPC 피어를 통해 접근할 수 없습니다. 그래서 VPC당 하나씩 필요한 것입니다. Google API 엔드포인트용 PSC마다 star.p.googleapis.com에 대한 프라이빗 클라우드 DNS 영역이 자동으로 생성됩니다 . 이 특수 도메인을 사용하려면 애플리케이션 측에서 API 엔드포인트를 리디렉션해야 합니다. star.googleapis.com 및 googleis.com 에 대한 DNS 영역을 수동으로 생성할 수도 있습니다 . 하이브리드 사용 사례에 PSC에서 제공하는 특수 도메인을 사용하지 않으려면 DNS 확인을 원하는 위치에 따라 인바운드 또는 아웃바운드 포워딩으로 DNS 포워딩을 구성해야 합니다. PSC for Google APIs는 글로벌 엔드포인트를 사용하므로 지역 서브넷의 IP 주소를 사용하지 않습니다. 이는 해당 엔드포인트가 하이브리드 연결을 통해 자동으로 광고되지 않음을 의미합니다 . 이러한 연결을 위해서는 하이브리드 링크 에 사용자 지정 경로 광고를 생성해야 합니다 . 비공개 Google 액세스는 API 기반 비공개 연결의 또 다른 방법입니다. 하지만 VPC 내부에 엔드포인트를 생성하는 대신 Google에서 제공하는 VIP를 사용해야 하며, VIP에 대한 올바른 경로가 구성되어 있는지 확인해야 하고 star.google API 도메인만 사용할 수 있습니다. 두 번째 유형의 사설 네트워킹 방식은 인프라 기반 서비스를 다룹니다. 이러한 서비스에는 클라우드 SQL, Apogee 및 Cloud Composer 등이 있습니다. 인프라 기반 서비스는 주로 엔드포인트, 백엔드 및 인터페이스의 세 가지 형태로 제공되는 사설 서비스 연결(PSC)을 사용합니다. PSC 엔드포인트와 백엔드는 소비자와 생산자 환경 간의 IP 중복 문제를 걱정하지 않고 소비자가 시작하는 단방향 연결을 가능하게 합니다 . PSC 엔드포인트는 소비자 VPC 내의 단일 IP 주소로, 생산자 VPC 내의 서비스 연결에 연결됩니다. PSC 백엔드는 Google Cloud의 프록시 기반 로드 밸런서와 함께 사용되는 특수한 유형의 네트워크 엔드포인트 그룹입니다 . PSC 백엔드는 프로듀서 서비스 연결에도 연결되지만 , 소비자 측을 로드 밸런서로 구성하면 NCC 허브에서 PSC 전파를 활성화하여 추가적인 트래픽 라우팅 기능을 활용할 수 있습니다 . 이렇게 하면 모든 PSC 엔드포인트가 모든 VPC 스포크와 하이브리드 라우팅을 통해 완벽하게 라우팅 가능해집니다 . PSC 백엔드를 사용하는 경우 PSC 전파는 적용되지 않습니다. 로드 밸런서는 어차피 완전히 라우팅 가능하기 때문입니다. PSC 인터페이스는 소비자와 생산자 간의 양방향 트래픽을 가능하게 합니다 . 프로듀서 서비스는 컨슈머 VPC 내 지정된 네트워크 연결 에서 IP 주소를 사용하는 PSC 인터페이스를 생성합니다 . 특정 서비스에서 달리 명시하지 않는 한 IP 주소 중복은 문제가 되지 않습니다 . PSC 인터페이스는 소비자 VPC에서 nyx로 표시되므로 기본적으로 NCC 허브를 통한 라우팅은 물론 하이브리드 환경에서도 완벽하게 라우팅 가능합니다. 일부 Google 서비스는 VPC 피어링을 기반으로 하는 PSA(프라이빗 서비스 액세스)라는 연결 방식을 사용한다는 점에 유의할 필요가 있습니다. NCC에는 프로듀서 스포크라는 기능이 있는데, 이 기능을 사용하면 PSA VPC를 NCC 허브에 스포크로 연결하여 NCC 환경에서 PSA 서비스를 완벽하게 라우팅할 수 있습니다 . 서비스가 PSC를 지원하지 않거나 PSA와 PSC 사이에 특정 기능상의 차이가 있는 경우에만 PSA를 사용하는 것이 좋습니다. 아래 링크된 문서를 참조하여 어떤 서비스가 어떤 유형의 개인 서비스 연결 또는 개인 서비스 액세스를 지원하는지 이해하십시오. 서버리스 제품은 어떻습니까? 클라우드 런, 바로 너를 두고 하는 말이야. 이 내용은 다른 영상에서 자세히 다루겠습니다 . 자, 그럼 마무리해 볼까요? 마지막 으로 핵심 요점들을 말씀드리겠습니다. 서비스 이용에 필요한 연결 방식을 항상 확인하세요. Google API용 PSC 와 표준 PSC는 동작 방식 이 다르며, 잘못된 PSC를 사용하면 접근이 차단될 수 있습니다. 서비스는 API 기반, 인프라 기반 또는 서버리스 방식으로 제공되며, 각각 고유한 연결 방식을 가지고 있습니다. 서비스 설명서에는 연결 요구 사항이 항상 명시되어 있습니다. 그러니 꼭 확인해 보세요 . 앞으로 공개될 구글 클라우드 네트워킹 관련 영상들을 기대해 주세요. 댓글로 의견을 남겨주시고, 이 영상이 도움이 되었다면 좋아요를 눌러주세요. 시청해 주셔서 감사합니다.
