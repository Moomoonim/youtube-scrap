## 스크립트

저희는 언제나 개발자들을 위한 공간이었고, 앞으로도 변하지 않을 것입니다. 이제 개발자와 에이전트가 에이전트 본부에서 함께 협업할 수 있도록 에이전트 기능을 추가하고 있습니다. GitHub Copilot은 이제 단순한 자동 완성 기능을 훨씬 뛰어넘는 완벽한 코딩 도우미입니다. 이제 더 심층적인 맥락, 더 강력한 추론, 그리고 개발자 워크플로 전반에 걸쳐 작업을 실행하고 조정하는 능력을 갖추고 작동합니다 . 클로드와 코덱스도 요원 본부에 배치하는 건 어때요 ? 구글 코그니션이나 XAI의 코딩 에이전트는 어떻습니까? 맞습니다, 에이전트 본부는 모든 코딩 에이전트 여러분의 GitHub 참여를 환영합니다. 그래서 이 코딩 에이전트를 시작으로 올해 말에는 프론티어 랩 및 여러 스타트업과 협력하여 그들의 코딩 에이전트를 깃허브 플랫폼에 도입할 예정입니다. Agent HQ는 웹, IDE, CLI, 심지어 모바일에 이르기까지 모든 환경에서 세션을 시작, 관리 및 제어할 수 있는 단일 플랫폼을 제공합니다. 여러분이 가장 좋아하는 코딩 에이전트가 선호하는 플랫폼이며, 유료 구독을 통해 모든 기능을 이용할 수 있습니다 . 올해 말 출시 예정인 Agent HQ 코딩 에이전트를 사용하여 이러한 모든 코딩 에이전트를 관리하고 활용하세요. 저희는 코파일럿의 코딩 에이전트에서 핵심 기능을 추출하여 새로운 분기 제어 기능을 기반으로 구축할 수 있는 새로운 플랫폼을 제공함으로써 에이전트가 생성한 코드가 실행되는 시점을 사용자가 제어할 수 있도록 했습니다. 각 에이전트는 GitHub에서 완전한 실제 ID를 가지고 있으므로 원하는 항목에 대한 액세스 권한만 부여하고, 이슈와 풀 리퀘스트를 할당하고, 댓글에서 멘션할 수도 있습니다 . 각 에이전트는 GitHub Actions를 사용하여 기존 컴퓨팅 계층 위에 기능을 구축할 수 있습니다 . 또한 엔터프라이즈급 AI 제어 기능을 통해 GitHub에 대한 액세스 관리, 보안 정책 설정 및 에이전트 활동 감사를 수행할 수 있습니다 . Agent HQ는 사용 중인 모든 코딩 에이전트를 아우르는 단일 명령 센터입니다 . 새로운 통합 관리 화면에서 프로젝트 전반에 걸쳐 에이전트의 모든 세션을 확인할 수 있습니다. 새로운 작업을 할당하고, 진행 상황을 추적하고, 코드가 작성되는 동안 코드를 검토할 수 있습니다 . 원하는 작업 장소에서 새로운 세션을 시작할 수도 있습니다. CLI에서 웹으로, 웹에서 IDE로 자유롭게 이동하며 자신에게 가장 적합한 환경에서 작업할 수 있습니다. 저희는 코딩 에이전트와 협업하는 단일화된 방식을 구축하여, 에이전트에게 여러분과 여러분의 작업에 대한 올바른 맥락을 제공하고, 가장 중요한 것은 여러분에게 제어권을 부여하는 것입니다. Figma, Sentry, Atlassian Jira와 같은 핵심 서비스는 해당 MCP 서버와 GitHub MCP 레지스트리를 통해 연결할 수 있습니다. 코파일럿 코딩 에이전트는 GitHub Actions에서 바로 실행되므로 , 에이전트가 자체 호스팅 개발 환경에서 변경 사항을 빌드하고 테스트한 후 검토를 요청할 수 있습니다. 하지만 여러분 중 일부는 그것만으로는 충분하지 않다고 분명히 말씀해 주셨습니다. 오늘부터 Copilot 코딩 에이전트는 CI/CD에 사용하는 자체 호스팅 러너에서 실행될 수 있습니다. GitHub Copilot에는 GitHub의 가장 강력한 기능들이 모두 포함되어 있어야 합니다. 따라서 C-Pilot은 모든 작업에서 실행할 수 있는 도구로 CodeQL, 종속성 검사 및 비밀 보호 기능을 통합하여 코드 보안을 강화했습니다 . 작업에 대해 말씀드리자면, 문서 작성이나 테스트 주도 개발과 같은 특정 시나리오에 맞게 Copilot을 맞춤 설정할 수 있도록 사용자 지정 에이전트도 도입할 예정입니다. 하지만 당신을 위한 또 다른 сюрприз가 있습니다. 편집기에서 가장 많은 시간을 보내는 곳에 가장 강력한 에이전트를 사용하는 것이 합리적이지 않을까요 ? Codex는 오늘부터 VS Code Insiders에서 Copilot Pro Plus 사용자에게 미리 보기로 제공되며, 이러한 모든 파트너의 에이전트는 올해 말 Agent HQ에서 사용할 수 있게 될 예정 이며 자세한 내용은 곧 공개될 예정입니다. 이제 GitHub Copilot용 대표 에디터인 VS Code에 대해 알아보겠습니다. 지난 6개월 동안 저희는 지역 사회와 함께 협력해 왔습니다. VS Code용 Cop-lot에 거의 200가지의 개선 사항을 적용했습니다. Copilot이 전체 스택을 이해하고 현재 파일만 파악하는 것이 아니라, MCP를 완벽하게 지원합니다 . 사용자 지정 규칙은 C-Pilot이 코드를 생성할 때 따라야 할 표준을 정의하는 기능입니다. 슬래시 명령어를 사용하여 팀 전체에서 공통 프롬프트와 반복 가능한 워크플로를 공유하세요. 또한 향상된 의미론적 코드 모델을 통해 C-Pilot은 GitHub 에 저장된 코드에 대한 더 깊은 맥락과 더 스마트한 이해력을 제공합니다 . 현재 저희는 프론티어 랩에서 신제품을 출시하는 즉시 C-Pilot 고객에게 신제품을 배송하고 있습니다 . Claud Sonnet 45 및 GPT5 코덱과 같은 모델은 같은 날 출시되었습니다. HuggingFace 및 Azure AI Foundry와 같은 VS Code 확장 프로그램을 사용하면 선택의 폭이 더욱 넓어져 코파일럿 플랜 외의 다른 모델 공급자를 사용할 수 있습니다. Open Router와 같은 호스팅 모델 제공업체에 연결하거나 LM Studio와 같은 도구를 통해 로컬 모델을 실행할 수 있습니다. 때로는 너무 많은 선택지가 오히려 부담스러울 수 있습니다. 이제 Copilot이 사용자의 작업에 가장 적합하다고 판단되는 모델을 자동으로 선택하는 자동 모드가 있습니다 . 이 모델들은 단순히 기능적인 측면만 고려한 것이 아닙니다. 그것들은 개발이 어떤 느낌인지에 관한 것입니다. 오늘 VS Code와 GitHub Copilot의 새로운 버전을 출시합니다. 제가 가장 좋아하는 새로운 기능 중 하나인 계획 모드에 대해 이야기하면서 시작하고 싶습니다. 가장 성공적인 팀들은 C-pilot을 사용하여 프로젝트 시작 전에 요구사항 문서와 유사한 것을 작성합니다. 하지만 이제 계획 모드를 사용하면 C-Pilot을 활용하여 작업에 대한 단계별 접근 방식을 구축할 수 있습니다 . 진행 과정에서 명확한 설명을 위해 질문을 드릴 것입니다 . 이 기능은 코드를 작성하기 전에 프로세스 초기에 누락된 부분, 결정되지 않은 사항 또는 프로젝트 결함을 찾아내는 데 도움을 줌으로써 C-pilot의 기능을 빠르게 향상시킵니다 . 승인이 완료되면 계획을 가져와 코파일럿에게 전달하여 VS Code에서 로컬로 구현하거나 에이전트 본부의 에이전트 중 하나를 사용하여 구현을 시작할 수 있습니다. 이번 주부터 Slack에서 @mention GitHub를 사용하여 에이전트 작업을 시작할 수 있습니다. 동료들과 함께하는 스레드에서 GitHub를 태그하고 버그 수정을 요청하거나 작업 중인 아이디어를 구체화해 달라고 요청하면 Co-Pilot이 작업을 시작합니다. 슬랙뿐만이 아닙니다. 이제 Teams에서 C-pilot과 협업하거나 Azure Boards, Raycast에서 작업을 시작할 수 있으며, 오늘부터는 linear에서도 사용할 수 있습니다. 저희는 첫 단계로 코파일럿 코드 리뷰 기능을 출시하여 풀 리퀘스트에 대한 의미 있는 리뷰를 제공했지만, 그것만으로는 충분하지 않았습니다. 이제 새로운 에이전트형 보조 조종사 코드 검토 기능을 바로 사용하실 수 있습니다. 그리고 이 자리에 계신 기업 관리자 여러분 , 미리 보기 기능에서 해당 기능을 활성화하시면 오늘 바로 기업 환경에서 사용하실 수 있습니다. 우리는 소프트웨어 개발의 모든 문제를 해결할 수 있습니다. 아직 그렇게 하지는 않았지만, 회사 개발자들이 GitHub의 핵심 기능을 활용하지 못한다고 해도 큰 문제는 되지 않을 겁니다. 이는 상사 또는 상사의 상사와 관리팀이 C-Pilot을 회사에 도입하는 데 필요한 도구와 통제 장치를 갖추도록 지원하는 동시에 투자 수익률(ROI)을 입증해야 함을 의미합니다. 그리고 우리는 세 가지 아주 큰 방식으로 그것을 해냈습니다 . 첫 번째는 코드 품질입니다. 코드가 훌륭하지 않다면 더 많은 코드를 배포하는 것은 아무 소용이 없습니다. 품질은 단순히 통과 심사 이상의 의미를 지닙니다. 왜냐하면 겉보기에 좋아 보인다고 해서 건강한 상태를 의미하는 것은 아니기 때문입니다 . 그렇지 않으면 실제 운영 환경 에서 버그가 발견되거나 문제가 발생하는 일이 절대 없을 겁니다. 바로 이 부분에서 GitHub 코드 품질 기능이 빛을 발합니다. C-Pilot을 확장하여 풀 리퀘스트 내부에서 변경된 코드의 유지 관리성과 안정성에 미치는 영향을 분석할 수 있도록 해줍니다 . 저희는 여러 고객사와 협력하여 엔지니어링 리더에게 유용한 정보와 개발자들이 실제로 좋아할 만한 정보를 제공하고 있는지 확인하고 있습니다. 그래서 저희 팀은 이 기능을 공개 미리보기로 제공하고 여러분의 피드백을 듣고, 대규모 환경에서도 코드 품질을 높게 유지할 수 있도록 돕게 되어 매우 기쁩니다. 다음으로, 고객 여러분께서 많은 피드백을 주셨던 부조종사 관련 지표에 대해 말씀드리겠습니다. 오늘, C-Pilot 메트릭 대시보드의 공개 프리뷰를 발표하게 되어 기쁩니다. 이 대시보드는 C-Pilot 및 모든 코딩 에이전트를 조직 전체에 사용할 때의 영향을 보여주며, 회사가 C-Pilot을 어떻게 활용하고 있는지에 대한 정보를 제공합니다. 이를 통해 실질적인 영향력을 발휘하기 위해 무엇을 측정해야 하는지에 대한 필수적인 지침과 조언을 얻을 수 있을 뿐 아니라, 대시보드를 쉽게 시작하고 API 액세스를 통해 심층 분석을 수행할 수 있는 방법도 안내받을 수 있습니다. 기존 Copilot 비즈니스 또는 Copilot 엔터프라이즈 구독을 통해 지금 바로 공개 미리보기로 C-pilot 메트릭 대시보드를 사용해 보실 수 있습니다. 마지막으로, 귀사에서 C-pilot 배포를 관리하고 오늘 공유한 모든 내용 , 새로운 모델 및 향후 개발될 기능을 활용하는 데 필요한 AI 제어 기능을 갖추었는지 확인해야 합니다. AI 제어 기능을 통해 부조종사에게 명확한 제어 영역을 제공합니다. 그리고 앞으로 에이전트 본부 전체에 걸쳐 적용될 것입니다. 이 모든 기능은 관리자와 새로운 사용자 지정 역할을 통해 신뢰받는 대리인이 사용할 수 있는 단일 전사적 관리 인터페이스에서 제공됩니다. 오늘은 많은 분들이 요청하셨던 상담원 중앙 관리 기능 과 사용자 지정 상담원 프로필을 저장할 공유 위치를 정의하는 기능부터 시작하겠습니다. 에이전트 감사 로그를 확인하여 어떤 사용자가 에이전트를 시작했는지, 해당 에이전트가 어떤 작업을 수행했는지 파악하고, GitHub의 다른 이벤트처럼 추적할 수 있습니다. 또한 에이전트가 코드베이스의 어떤 부분에 접근할 수 있는지, 어떤 기능을 팀에서 사용할 수 있는지 제어할 수 있습니다. 이러한 새로운 AI 제어 기능은 기업들이 원하는 기능을 더욱 세밀하게 제어하여 한 곳에서 모두 사용할 수 있도록 지원하겠다는 당사의 새로운 의지를 보여줍니다.
