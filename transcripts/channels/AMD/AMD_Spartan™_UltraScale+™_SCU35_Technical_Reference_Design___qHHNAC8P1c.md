Welcome to the Spartan UltraScale Plus SCU35 Technical Reference Design Demonstration. In this walkthrough, you will explore the AMD Spartan UltraScale Plus SCU35 Evaluation Kit and build the SCU35-IO Technical Reference Design, TRD. You will generate the hardware platform in the AMD Vivado Design Suite, develop and build the standalone software application in the AMD Vitis Unified IDE, create the device image, and finally run and validate the design on the target hardware. This demo requires the Spartan UltraScale Plus SCU35 Evaluation Kit. The demo also requires the following additional hardware, a power supply, and a USB to micro-USB cable. In addition to the required hardware, the demonstration also requires the following software tools. The Vivado Design Suite, the Vitis Unified software platform, Google Chrome, a serial terminal. AMD Spartan UltraScale Plus FPGAs deliver industry-leading IO density, providing 3.5 times more IO per logic cell than previous Spartan generations, alongside low power consumption and robust security features. Built on a 16 nanometer process node, these devices include hardened IP for DDR and PCIe on larger configurations, significantly improving interface efficiency. The SCU35 Evaluation Board serves as a comprehensive hardware platform for implementing and validating these advanced capabilities in real-world scenarios. Specifically engineered for the Spartan UltraScale Plus XCSU35P device, the board leverages high IO counts and low power operation, making it ideal for industrial, medical, and other high-reliability sectors. To streamline development, the SCU35 platform integrates seamlessly with the AMD Vivado Design Suite and the AMD Vitis Unified software platform. This integrated ecosystem allows for efficient hardware and software design, implementation, and debugging within a unified toolchain. The SCU35 IO Technical Reference Design demonstrates the creation of a streamlined human-machine interface, HMI, using the AMD Spartan UltraScale Plus SCU35 Evaluation Board and the AMD MicroBlaze 5 processor. While the Spartan UltraScale Plus device is a stand-alone FPGA, this reference design specifically targets the SCU35 Evaluation Board by implementing a MicroBlaze 5 soft processor within the programmable logic, PL. The processor is configured to monitor and interact with the board's integrated I2C and GPIO peripherals. By utilizing a soft processor in the PL, the design can deploy a stand-alone software application to poll and update peripheral states in real time. Connectivity is handled via a UART interface, allowing the processor to communicate with a host-based web application. The TRD is comprised of three core components, an AMD Vivado hardware design, an AMD Vitus stand-alone application, and a web application interface. Once inside the directory, use the git checkout command, followed by your specific release tag to ensure you are working with the correct version. The repository is organized for a seamless build process. The hardware and software folders contain the source files for hardware and software development, respectively. For rapid testing, the pre-built folder offers ready-to-use binaries. Finally, the webapp folder hosts the scripts and styles for the browser-based interface. To begin, source the Vivado setting script from your installation path to set up your environment variables. Now, navigate to the root of the cloned repository and run make XSA. This command automates the synthesis and implementation process, generating the hardware platform file required for software development. Upon completion, the exported hardware platform will be the following XSA file. With the hardware built, launch the Vivado IDE and open the newly created project file. Open the block design to visualize how the Microblaze 5 processor connects to the various IO peripherals and IP blocks. Take a moment to analyze the block design. Here, you can verify the address mapping and peripheral configurations that the standalone software will eventually interact with. Next, we will build the software. Source the VITAS setting script to initialize the toolchain, ensuring your environment is ready to compile the application. Navigate to the TRD root and run make elf. This command triggers the VITAS build flow, compiling the C source files into an executable file for the Microblaze 5 processor. The resulting executable file will be the following elf file. Once the build is complete, launch the VITAS unified IDE and point your workspace to the software folder. Here, you can see how the IO platform component abstracts the hardware for the software. Take a moment to look through the IO app source files to see how the code interacts with the board's peripherals. With both the hardware and software successfully built, we now need to merge them. Ensure your Vivado environment is sourced and ready for the final implementation step. Run make pdi. This command tells the Vivado design suite to associate the software executable with the processor and generate the final device image. This process may take a few minutes as it runs through the implementation and bitstream generation stages. Once the process finishes, a success message will appear in your terminal. Your integrated device image is now ready in the following pdi file. This single file contains everything needed to configure the Spartan UltraScale Plus FPGA and launch your application. Now let's look at how to make the necessary connections to the SCU-35 evaluation board. Ensure that the power connector is not plugged in. Connect the micro USB JTAG or UART cable between the board and the host. Locate J35 on the board. This header configures the Spartan UltraScale Plus device's boot mode, which should be set to JTAG. Plug in the power connector and power on the board. The power LEDs should illuminate. With the board powered on and connected to your computer via JTAG, open the Vivado GUI. Navigate to the flow navigator and click Open Hardware Manager. Select Auto Connect to allow the Vivado Design Suite to identify the Spartan UltraScale Plus FPGA. Click Program and wait for the status bar to complete, which indicates the hardware and software are now running on the board. Now, let's launch the controller.
