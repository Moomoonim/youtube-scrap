## 스크립트

안녕하세요, 네이버 클라우드입니다. 오늘은 네이버 클라우드 플랫폼의 컴퓨팅 제품군에 대해 알아보겠습니다. 네이버 클라우드 플랫폼의 컴퓨팅 제품군은 서버 및 서버 관련 리소스를 제공합니다. 네이버 클라우드 플랫폼에서는 서버 사용 목적 과 서비스 규모에 따라 다양한 서버 유형을 선택하여 사용할 수 있습니다. 예를 들어, 메모리 집약적인 워크로드에 적합한 고용량 메모리 서버 와 높은 vCPU/메모리 비율로 컴퓨팅 집약적인 워크로드에 적합한 고용량 CPU 서버 등이 있습니다. 서버 요금은 컴퓨팅 리소스, 네트워크, 스토리지 요금을 합산하여 계산됩니다. 서버 정지 시에는 일부 서버 유형의 경우 운영체제 설치에 필요한 기본 디스크 요금만 부과되지만, GPU 서버 및 베어 메탈 서버는 서버 종료 후에도 일반 요금이 부과됩니다. 따라서 서버 운영 시 이 점에 유의하시기 바랍니다. 할인 요금이 적용되는 서버의 경우, 서버 정지 기간은 한 번에 90일, 12개월 누적 180일을 초과할 수 없습니다. 정지 기간을 초과한 서버는 고객에게 통지 후 종료되며, 종료된 서버는 블록 스토리지로 복원할 수 없습니다. ( SSD 유형) HDD 유형과 SSD 유형이 제공되며, SSD 유형은 최대 IOPS를 보장하는 특징이 있습니다. 앞서 언급했듯이 네이버 클라우드 플랫폼은 다양한 워크로드를 지원할 수 있는 다양한 서버 유형을 제공합니다. 여기에는 가장 범용적으로 사용할 수 있는 표준 서버, 과학 모델링 및 게임 서버에 사용할 수 있는 고성능 CPU 서버, 고성능 데이터베이스 서버 및 대규모 게임 서비스에 사용할 수 있는 고용량 메모리 서버, 머신 러닝 처리 서버 및 고성능 웹 서비스에 사용할 수 있는 CPU 집약적 서버가 포함됩니다. 이제 베어 메탈 서버에 대해 자세히 살펴보겠습니다. 베어메탈 서버는 클라우드에서 독립적으로 사용할 수 있는 고성능 물리적 서버를 의미합니다. 클라우드에서 물리적 서버를 사용하는 것이 다소 생소하게 느껴질 수 있습니다. 일반적인 서버는 물리적 하드웨어 장치 위에 하이퍼바이저가 마운트되는 구조를 가지고 있지만, 베어 메탈 서버는 하이퍼바이저 없이 운영 체제가 하드웨어에 직접 설치되는 구조를 가지고 있습니다. 따라서 클라우드에서 사용되는 고성능 물리적 서버라고 설명할 수 있습니다. 베어메탈 서버의 RAID 구성은 인프라 운영 방식에 적합한 방식으로 선택할 수 있으며, 현재 RAID 1/1 및 RAID 5 구성을 사용할 수 있습니다. Oracle Linux와 Windows는 베어메탈 서버 운영 체제로 제공되며, 일반 클라우드 서버와 마찬가지로 인접 클라우드 플랫폼 의 다양한 서비스와 연결할 수 있습니다. 하지만 가상화 서버가 아니므로 서버 이미지 스냅샷 및 추가 스토리지 기능은 연결할 수 없으며, 라이브 마이그레이션 기능도 제공되지 않습니다. 다음으로 살펴볼 서버 유형은 GPU 서버입니다. GPU 서버는 여러 고성능 연산을 동시에 처리할 수 있는 서버 유형으로, 딥러닝, 인공 지능, 자율 주행과 같은 고성능 컴퓨팅에 적합합니다. 2022년 7월 현재, 네이버 클라우드 플랫폼은 싱가포르 리전의 VPC 환경에서 T4 모델의 GPU 서버를 제공하고 있습니다. 싱가포르 리전의 인접 클라우드 플랫폼 GPU 서버는 Linux와 Ubuntu 운영 체제를 지원합니다. 네이버 클라우드 플랫폼은 한국, 싱가포르, 일본, 미국, 독일, 홍콩 리전을 제공하며, 각 리전별로 제공되는 서비스가 다릅니다. 네이버 클라우드 플랫폼을 기반으로 글로벌 리전을 구축할 때는 각 리전에서 제공되는 서비스를 사전에 확인하는 것이 좋습니다. 지금까지 컴퓨팅 제품 그룹에서 제공되는 서버 유형과 사양을 살펴보았습니다. 이제 서버를 생성하는 방법에 대해 알아보겠습니다. 콘솔을 통한 생성, CLI를 통한 생성, API를 통한 생성의 세 가지 방법이 있습니다. 여기서 콘솔은 관리 콘솔을 의미합니다. 클라우드닷컴 포털에 접속하여 웹 콘솔에 로그인하면 네이버 클라우드 플랫폼 리소스를 관리할 수 있습니다. 웹 페이지를 통해 네이버 클라우드 플랫폼에서 제공하는 기능을 관리할 수 있으며, 네이버 클라우드 플랫폼 전용 CLI를 설치하여 CLI를 사용할 수도 있습니다. 네이버 클라우드 플랫폼의 객체 스토리지는 AWS CLI를 통해서도 관리할 수 있습니다. 마지막으로 API를 사용하여 관리할 수 있으며, 이 API는 RESTful API 방식으로 제공되고 XML 및 JSON 형식으로 응답합니다. 이제 서버 생성 후 네이버 클라우드 플랫폼에서 제공하는 서버 운영 기능을 살펴보겠습니다. 먼저 ' 내 서버 이미지', '스냅샷', ' 서버 복제' 기능을 알아보겠습니다. '내 서버 이미지'는 서버의 현재 상태를 이미지로 저장하는 기능입니다. 서버가 실행 중이거나 중지된 상태일 때 모두 생성할 수 있으며, 추가된 스토리지 도 이미지로 저장되므로 추가 디스크 용량이 크고 저장된 데이터가 많을수록 생성 시간이 오래 걸릴 수 있습니다. '내 서버 이미지' 생성 시간을 단축하려면 추가 디스크 연결을 해제한 후 추가 디스크의 스냅샷을 생성하면 됩니다. 다음으로 스냅샷 기능을 살펴보겠습니다. 스냅샷은 서버의 현재 상태를 저장하는 기능입니다. 블록 스토리지의 상태를 살펴보겠습니다. 앞서 설명한 서버 이미지의 대상이 서버 OS 추가 볼륨인 반면, 스냅샷의 대상은 볼륨으로 제한됩니다. 그렇다면 복제 서버는 언제 사용할까요? 이 기능은 동일한 사양의 서버를 생성할 때 사용할 수 있습니다. 원본 서버의 기본 서버 이미지, 서버 유형, 요금제, 영역 인증 키, ACG와 같은 정보를 가져와 동일한 정보를 사용하여 서버를 생성할 수 있습니다. 하지만 이 경우 원본 서버의 데이터가 아닌 서버 사양과 관련된 정보만 가져옵니다. 이 섹션에서는 스크립트에 대해 살펴보겠습니다. 스크립트는 이름에서 알 수 있듯이 서버 생성 시 처음 한 번만 실행되는 스크립트를 의미합니다. Linux 에서는 Python, Girl, Shell과 같은 스크립트를 사용할 수 있으며, Windows에서는 Visual Basic 스크립트만 사용할 수 있습니다. 스크립트는 동일한 패키지를 설치해야 하는 여러 서버를 생성하거나 초기 설정을 해야 하는 경우 등 다양한 용도로 사용할 수 있습니다. 서버를 생성할 때 적용할 초기화 스크립트를 선택하기만 하면 됩니다. 스크립트를 통해 서버를 빠르고 효율적으로 관리할 수 있습니다. 이제 서버 측 방화벽 역할을 하는 ACG에 대해 살펴보겠습니다. HCG는 액세스 제어를 의미합니다. 컨트롤 그룹 ACG는 기본 ACG와 사용자 지정 ACG로 분류할 수 있습니다. 기본 ACG는 네이버 클라우드 플랫폼에서 예시로 설정되어 있으므로, 서버 목적에 따라 직접 정의한 사용자 지정 ACG를 사용하는 것이 좋습니다. ACG는 허용할 프로토콜, IP 범위 및 포트를 지정하며, 네이버 클라우드 플랫폼에서 서버의 네트워크 인터페이스당 최대 3개의 ACG를 적용할 수 있습니다. ACG 규칙은 인바운드 및 아웃바운드 각각 최대 50개까지 설정할 수 있습니다. ACG는 서버 생성 시 필수적으로 지정해야 하는 부분이므로, 서버 생성 전에 목적에 맞는 ACG를 생성하는 것이 좋습니다. 다음으로 안티바이러스에 대해 살펴보겠습니다. Windows 안티바이러스는 클래식 플랫폼에서 무료로 제공되며, 다른 안티바이러스는 보안 모니터링 서비스를 통해 요청할 수 있습니다. IDS, IPS, WAFP, DOS 등의 기타 보안 서비스 도 Linux 서버에서 적용할 수 있습니다. OS 영역에는 기본적으로 50GB의 블록 스토리지가 할당됩니다. 더 많은 용량이 필요한 경우 최소 10GB에서 최대 2TB(최대 15GB)까지 추가 스토리지를 생성할 수 있습니다. 단일 볼륨에 2테라바이트 이상이 필요한 경우 서버별로 추가할 수 있습니다. Linux에서는 LVM을 통해, Windows에서는 동적 디스크 할당을 통해 여러 볼륨을 바인딩하여 단일 볼륨으로 인식하도록 할 수 있습니다. 예를 들어 Linux 서버에서 6테라바이트 디스크를 단일 볼륨으로 사용하려면 3~2테라바이트 크기의 블록 스토리지를 생성하고 LVM으로 바인딩하여 6테라바이트로 인식하도록 할 수 있습니다. 블록 스토리지에 대한 분리/연결 기능은 운영 체제 영역에서는 제공되지 않고 추가 블록 스토리지 측면에서만 제공됩니다. 분리 기능을 사용하면 서버의 추가 블록 스토리지를 분리할 수 있고, 연결 기능을 사용하면 할당 가능한 블록 스토리지를 다른 서버에 연결하여 사용할 수 있습니다. 추가 블록 스토리지는 크기 조정 기능을 제공하여 최대 2테라바이트까지 확장할 수 있습니다. 이 경우 콘솔에서 블록 스토리지 용량을 늘린 후 서버 시스템에 맞게 파티션과 파일 시스템을 변경할 수 있습니다. 이제 지금까지 살펴본 서버 작업 외에 다른 서버 작업에 대해 알아보겠습니다. 먼저 종료 보호 설정부터 살펴보겠습니다. 서버가 실수로 종료되는 것을 방지하기 위해 종료 보호 기능을 설정할 수 있습니다. 서버 생성 시 지정한 이름을 변경하려면 서버 이름을 변경할 수 있습니다. 단, 서버 이름 변경은 콘솔에 표시되는 서버 이름만 변경하며 실제 서버의 호스트 이름은 변경되지 않습니다. 서버 생성 시 설정한 인증 키도 변경할 수 있습니다. 인증 키는 인증 절차를 거친 후에만 변경할 수 있습니다. 서버 인증 키 변경을 위한 이메일이 발송되며, 이메일을 통한 인증 절차가 완료되어야 합니다. 인증 키를 변경한 후에는 초기 비밀번호가 더 이상 작동하지 않으므로, 사용자가 서버에 접속하여 루트 비밀번호를 변경한 경우에는 주의해야 합니다. 마지막으로 살펴볼 서버 작업은 공용 IP입니다. 외부에서 네이버 클라우드 플랫폼의 서버에 접속할 때는 공용 IP를 사용할 수 있습니다. 서버에 할당된 공용 IP는 서버에 종속되지 않으므로, 서버에 공용 IP를 할당하거나 제거할 수 있습니다. 다음으로 살펴볼 컴퓨팅 제품군 서비스는 클라우드 함수입니다. 클라우드 함수는 네이버 클라우드 플랫폼의 서버리스 서비스로, 별도의 서버 관리 또는 프로비저닝 부담 없이 간단한 비즈니스 로직을 작성할 수 있도록 지원합니다. 이를 통해 클라우드 환경에서 로직을 쉽게 구현할 수 있습니다. 클라우드 함수는 다양한 분야에서 활용될 수 있습니다. API 게이트웨이, 데이터베이스, 객체 스토리지, CLA와 같은 네이버 클라우드 플랫폼 서비스와의 연동 외에도, 컴퓨팅 제품군의 마지막 서비스는 자동 스케일링입니다. 자동 스케일링은 유연한 인프라 확장 및 축소를 가능하게 하는 서비스입니다. 네이버 클라우드 플랫폼의 자동 스케일링 기능은 다음과 같이 작동합니다. 1. 스케줄링 기반, 2. 모니터링 기반, 3. 온디맨드 기반. 예를 들어, 스케줄링 기반은 설정된 일정에 따라 서버를 확장 및 축소하는 방식이며, 모니터링 기반은 사용자가 설정한 임계값을 기준으로 작동합니다. CPU 사용률이 1분 이상 70%를 초과할 경우 세 대의 서버를 추가하는 방식이 모니터링 기반 방식의 예입니다. 마지막으로 온디맨드 방식은 사용자의 요청 즉시 자동 스케일링 기능을 활성화합니다. 아래 그림은 앞에서 설명한 자동 스케일링 작동 기능을 보여줍니다. 이 그림은 온디맨드 방식을 제외한 스케줄링 및 모니터링 방식을 설명합니다. 이상으로 네이버 클라우드 플랫폼에서 제공하는 컴퓨팅 제품군 서비스의 주요 특징에 대한 설명을 마치겠습니다. 감사합니다.
