## 스크립트

[음악] 안녕하세요, 네이버 클라우드입니다. 오늘은 네이버 클라우드 플랫폼의 컴퓨팅 제품군에 대해 알아보겠습니다. 네이버 클라우드 플랫폼의 컴퓨팅 제품군은 서버 및 서버 관련 리소스를 제공합니다. 네이버 클라우드 플랫폼에서는 서버 사용 목적과 서비스 규모에 따라 다양한 서버 유형을 선택하여 사용할 수 있습니다. 예를 들어, 메모리 집약적인 워크로드에 적합한 고용량 메모리 서버와 높은 vCPU/메모리 비율로 컴퓨팅 집약적인 워크로드에 적합한 고용량 CPU 서버 등이 있습니다. 서버 요금은 컴퓨팅 리소스, 네트워크, 스토리지 요금을 합산하여 계산됩니다. 서버 정지 시에는 일부 서버 유형의 경우 운영체제 설치에 필요한 기본 디스크 비용만 부과되지만, GPU 서버와 베어메탈 서버는 정지 후에도 일반 요금이 부과됩니다. 따라서 서버 운영 시 이 점에 유의하시기 바랍니다. 할인 요금이 적용되는 서버의 경우, 서버 정지 기간은 한 번에 90일, 12개월 누적 180일을 초과할 수 없습니다. 정지 기간을 초과한 서버는 고객에게 통지 후 자동으로 종료되며, 종료된 서버는 블록 스토리지로 복원하여 서버에 연결할 수 없습니다. SSD와 HDD 유형이 제공되며, SSD 유형은 최대 IOPS를 보장하는 특징이 있습니다. 앞서 언급 했듯이 네이버 클라우드 플랫폼에서는 다양한 서버 유형을 제공하며, 가장 범용적으로 사용할 수 있는 표준 서버, 과학 모델링 및 게임 서버에 사용할 수 있는 고성능 CPU 서버, 고성능 데이터베이스 서버 및 대규모 게임 서비스에 사용할 수 있는 고용량 메모리 서버, 머신 딥러닝 처리 서버 및 고성능 웹 서비스에 사용할 수 있는 CPU 집약형 서버 등 다양한 워크로드를 지원하는 서버가 제공됩니다. 이제 베어 메탈 서버에 대해 자세히 살펴보겠습니다. 베어메탈 서버는 클라우드에서 독립적으로 사용할 수 있는 고성능 물리 서버를 의미합니다. 클라우드에서 물리 서버를 사용한다는 것이 다소 생소하게 느껴질 수 있는데, 일반적인 서버는 물리적 하드웨어 장치 위에 하이퍼바이저가 마운트되는 구조를 가지고 있지만, 베어 메탈 서버는 하이퍼바이저 없이 운영체제가 하드웨어에 직접 설치되는 구조를 가지고 있기 때문입니다. 따라서 클라우드에서 사용되는 고성능 물리 서버라고 할 수 있습니다. 베어메탈 서버의 RAID 구성은 인프라 운영 방식에 적합한 방식으로 선택할 수 있습니다. RAID 1L 및 RAID 5 구성이 현재 제공되며, OS로는 Oracle Linux와 Windows가 선택 가능합니다. 베어메탈 서버는 일반 클라우드 서버와 마찬가지로 네이버 클라우드 플랫폼의 다양한 서비스와 연동할 수 있습니다. 하지만 가상화 서버가 아니므로 내 서버 이미지 스냅샷 및 추가 스토리지 기능은 연동할 수 없으며, 라이브 마이그레이션 기능도 제공되지 않습니다. 다음으로 살펴볼 서버 유형은 GPU 서버입니다. GPU 서버는 여러 고성능 연산을 동시에 처리할 수 있는 서버 유형으로, 딥 러닝, 인공지능, 자율 주행과 같은 고성능 컴퓨팅에 적합합니다. 2022년 7월 현재, 네이버 클라우드 플랫폼은 싱가포르 리전 의 VPC 환경에서 T4 모델 GPU 서버를 제공하고 있습니다. 싱가포르 리전에서 네이버 클라우드 플랫폼의 GPU 서버는 Scent OS 와 Ubuntu OS를 지원합니다. 네이버 클라우드 플랫폼은 한국, 싱가포르, 일본, 미국, 독일, 홍콩 리전을 제공하며, 각 리전별로 제공되는 서비스가 다릅니다. 네이버 클라우드 플랫폼을 기반으로 글로벌 리전을 구축할 때는 각 리전에서 제공되는 서비스를 사전에 확인하는 것이 좋습니다. 지금까지 살펴본 내용은 다음과 같습니다. 이제 컴퓨팅 제품군에서 제공하는 서버 유형 및 사양을 살펴보고 서버를 생성하는 방법을 알아보겠습니다. 콘솔을 통한 생성, CLI를 통한 생성, API를 통한 생성, 이렇게 세 가지 방법이 있습니다. 콘솔은 관리 콘솔을 의미하며, 클라우드닷컴 포털에 로그인한 후 네이버 클라우드 플랫폼 리소스를 관리할 수 있습니다. 웹 콘솔에서 네이버 클라우드 플랫폼이 제공하는 기능을 관리할 수 있습니다. CLI는 네이버 클라우드 플랫폼 전용 CLI를 설치하여 사용할 수 있으며, AWS CLI를 통해 네이버 클라우드 플랫폼의 객체 스토리지를 관리할 수도 있습니다. 마지막으로 API를 사용하여 관리할 수 있습니다. API는 RESTful API 방식으로 제공되며 XML 및 JSON 형식으로 응답합니다. 이제 서버 생성 후 서버 운영을 위해 제공되는 네이버 클라우드 플랫폼의 기능을 살펴보겠습니다. 먼저 '내 서버 이미지' 스냅샷과 '서버 복제' 기능에 대해 알아보겠습니다. '내 서버 이미지'는 서버의 현재 상태를 이미지로 생성할 수 있는 기능입니다. 서버가 실행 중이거나 중지된 상태일 때 모두 생성할 수 있으며, 추가된 스토리지도 이미지화되므로 생성하는 데 시간이 더 오래 걸릴 수 있습니다. 서버 이미지 생성 시 추가 디스크 용량이 클수록, 그리고 데이터가 많을수록 생성 시간을 단축할 수 있습니다. 추가 디스크 연결을 해제한 후 서버 이미지를 생성하고, 그 다음 추가 디스크의 스냅샷을 생성합니다. 이제 스냅샷에 대해 알아보겠습니다. 스냅 샷은 블록 스토리지의 현재 상태를 저장하는 기능입니다. 앞서 설명한 서버 이미지의 대상이 서버 OS 추가 볼륨이었다면, 스냅샷의 대상은 볼륨으로 제한됩니다. 그렇다면 복제 서버는 언제 사용할까요? 이 기능은 동일한 사양의 서버를 생성할 때 사용할 수 있습니다. 원본 서버의 기본 서버 이미지, 서버 유형, 요금제, 영역 인증 키, ACG와 같은 정보를 가져와 동일한 정보를 사용하여 서버를 생성할 수 있습니다. 하지만 이 경우 원본 서버의 데이터가 아닌 서버 사양과 관련된 정보만 가져옵니다. 이 시간에는 서버 스크립트에 대해 살펴보겠습니다. 스크립트는 이름에서 알 수 있듯이 서버 생성 시 처음 한 번만 실행되는 스크립트를 말합니다. Linux에서는 Python, Perl, Shell 스크립트를 사용할 수 있으며, Windows에서는 Visual Basic 스크립트만 사용할 수 있습니다. 초기화 스크립트는 여러 서버를 생성해야 하는 경우를 포함하여 다양한 용도로 사용할 수 있습니다. 동일한 패키지를 설치하고 초기 설정이 필요할 때 서버를 생성할 때 적용할 초기화 스크립트를 선택하기만 하면 됩니다. 스크립트를 통해 서버를 빠르고 효율적으로 관리할 수 있습니다. 이제 서버 측 방화벽 역할을 하는 ACG( 액세스 제어 그룹)에 대해 살펴보겠습니다. ACG는 기본 ACG와 사용자 지정 ACG로 분류할 수 있습니다. 기본 ACG는 네이버 클라우드 플랫폼에서 예시로 설정되어 있으므로, 서버 목적에 따라 직접 정의한 사용자 지정 ACG를 사용하는 것이 좋습니다. ACG는 허용할 프로토콜, AP 범위 및 포트를 지정하며, 네이버 클라우드 플랫폼에서 서버의 네트워크 인터페이스당 최대 3개의 ACG를 적용할 수 있습니다. ACG 규칙은 인바운드 및 아웃바운드 각각 최대 50개까지 설정할 수 있습니다. ACG는 서버 생성 시 반드시 지정해야 하는 부분이므로, 서버 생성 전에 목적에 맞는 ACG를 생성하는 것이 좋습니다. 다음으로 바이러스 백신에 대해 살펴보겠습니다. Windows 바이러스 백신은 무료로 제공되지만 기존 플랫폼에 한정됩니다. 다른 바이러스 백신은 보안 모니터링 서비스를 통해 요청할 수 있습니다. IDS, IPS, WAFF OS와 같은 기타 보안 서비스도 제공됩니다. Linux 서버에서도 사용할 수 있으며, OS 영역에 기본적으로 50GB의 블록 스토리지가 할당됩니다. 더 많은 용량이 필요한 경우 최소 10GB에서 최대 2TB까지 추가 스토리지를 생성할 수 있습니다. 서버당 최대 15개의 추가 블록 스토리지를 추가할 수 있습니다. 단일 볼륨에 2TB 이상의 용량이 필요한 경우, Linux 에서는 LVM을, Windows에서는 동적 디스크 할당을 통해 여러 볼륨을 바인딩하여 단일 볼륨으로 인식하도록 할 수 있습니다. 예를 들어, Linux 서버에서 6TB 디스크를 단일 볼륨으로 사용하려면 3TB에서 2TB까지의 블록 스토리지를 생성하고 LVM을 사용하여 바인딩하면 6TB로 인식됩니다. 블록 스토리지에 대한 분리/연결 기능이 제공됩니다. OS 영역의 블록 스토리지에는 분리/연결 기능이 제공되지 않으며, 추가 블록 스토리지에만 제공됩니다. 분리 기능을 사용하면 서버의 추가 블록 스토리지를 분리할 수 있고, 연결 기능을 사용하면 할당 가능한 블록 스토리지를 다른 서버에 연결하여 사용할 수 있습니다. 블록 저장 용량을 최대 2테라바이트까지 확장할 수 있는 크기 조정 기능이 있습니다. 이 경우 콘솔에서 블록 저장 용량을 늘린 후 서버 시스템에 따라 파티션과 파일 시스템을 변경할 수 있습니다. 이제 지금까지 살펴본 서버 작업 외에 다른 서버 작업들을 살펴보겠습니다. 먼저 종료 보호 설정이 있습니다. 서버가 실수로 종료되는 것을 방지하기 위해 종료 보호 기능을 설정할 수 있습니다. 서버 생성 시 지정한 이름을 변경하려면 서버 이름을 변경할 수 있습니다. 단, 서버 이름 변경은 콘솔에 표시되는 서버 이름만 변경하며 실제 서버의 호스트 이름은 변경되지 않습니다. 서버 생성 시 설정한 인증 키도 변경할 수 있습니다. 인증 키는 변경을 위한 인증 이메일이 발송된 후에만 변경할 수 있으며, 이메일을 통한 인증 절차가 완료되어야 합니다. 인증 키를 변경하면 기존 비밀번호는 더 이상 사용할 수 없다는 점에 유의하십시오. 사용자가 서버에 접속한 후 루트 비밀번호를 변경한 경우에는 더욱 그렇습니다. 마지막으로 살펴볼 서버 작업은 공용 IP입니다. 외부에서 네이버 클라우드 플랫폼의 서버에 접속할 때 공용 IP를 사용합니다. 서버에 할당된 공용 IP는 서버의 IP 주소가 아닙니다. 서버에 공용 IP를 할당하고 제거할 수 있도록 종속성을 설정할 수 있습니다. 다음으로 살펴볼 컴퓨팅 제품군 서비스는 클라우드 함수입니다. 클라우드 함수는 네이버 클라우드 플랫폼의 서버리스 서비스로, 별도의 서버 관리나 프로비저닝 부담 없이 간단한 비즈니스 로직을 작성할 수 있도록 지원합니다. 이를 통해 클라우드 환경에서 로직을 쉽게 구현할 수 있습니다. 클라우드 함수는 API 게이트웨이, 데이터베이스, 객체 스토리지, CLA 등 네이버 클라우드 플랫폼 서비스와 연동하여 사용할 수 있습니다. 컴퓨팅 제품군의 마지막 서비스는 자동 스케일링입니다. 자동 스케일링은 유연한 인프라 확장 및 축소를 지원하는 서비스입니다. 네이버 클라우드 플랫폼의 자동 스케일링 기능은 다음과 같이 작동합니다. 1. 스케줄링 기반, 2. 모니터링 기반, 3. 온디맨드 기반. 예를 들어 스케줄링 기반은 설정된 일정에 따라 서버를 확장 및 축소하는 방식이며, 모니터링 기반은 사용자가 설정한 임계값을 기준으로 작동합니다.
