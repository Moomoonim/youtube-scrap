## 스크립트

개발자들은 작업을 완료하기 위해 가끔씩 아주 빠르게 새로운 것을 배워야 할 때가 있습니다 . 저에게 그런 일이 일어났을 때의 이야기와 아마존 Q 개발자가 어떻게 문제를 해결했는지에 대한 이야기를 들려드리겠습니다 . 갑시다. 모든 것은 제가 아마존에서 스프링 부트를 사용한 마이크로서비스에 관한 책을 구입하면서 시작되었습니다 . 새로 맡게 된 업무를 수행하기 위해 이것을 배워야 했습니다. 그 일은 꽤 간단했다. 시스템 의 '주문'이라는 엔티티에 대한 새로운 영구 저장 계층을 구현하세요 . 제가 해야 할 일은 새로운 엔티티 클래스를 만들고, JPA 어노테이션을 추가하고 , 스프링 부트의 지원 기능을 활용하여 리펄서 패턴을 구현하는 것뿐이었습니다 . 그 입장들은 모든 것이 예상대로 진행되고 있음을 보여주었다. 내가 제대로 가고 있는지 확인하기 위해 아마존 Q 개발자 도구를 사용하여 코드의 유효성을 검사했습니다. 모든 것은 잘 알려진 코딩 모범 사례를 기반으로 구현되었습니다. 저는 제 코드를 포함한 PR을 제출하고 개발팀이 테스트를 검토하기를 기다렸습니다. 하지만 제 영주권 신청은 거절당했습니다. 검토자들은 제 코드가 기술적으로는 정확하지만 회사의 구현 지침을 일부 따르지 않았다고 지적했습니다. 올바른 기본 클래스를 상속받는 방법이나 올바른 로그인 프레임워크를 사용하는 방법과 같은 세부 사항이 누락되어 있었습니다. 그들은 Springpad Clinic 샘플 애플리케이션을 연구해 볼 것을 권장했는데 , 이는 회사의 구현 지침이 나온 출처입니다. 그때 아마존 Q 개발자 맞춤 설정 기능을 사용해 보자는 아이디어가 떠올랐습니다. 제가 어떻게 했는지 보여드리겠습니다. 안녕하세요, 저는 AWS에서 개발자 옹호 담당자로 일하고 있는 리카르도 페레르입니다. 아마존 Q 개발자 맞춤 설정 기능을 여러분께 보여드리게 되어 정말 기쁩니다. 이 기능은 특정 코드베이스를 학습 목적으로 사용할 수 있도록 해줍니다. 따라서 다음에 아마존 G 개발자 추천이나 코드 생성을 요청할 때는 학습 코드를 기반으로 추천이 제공될 것입니다. 이는 여러 상황에서 흥미로운 점입니다. 예를 들어, 오픈 소스 프로젝트에 기여하기 시작 하고 구현 지침을 준수해야 한다고 가정해 봅시다. 따라서 코드베이스를 연구하는 데 몇 주 또는 몇 달을 소비하는 대신 , 해당 코드베이스를 아마존 Q 개발자에게 보내 몇 시간 동안 교육을 받은 후, 샘플 코드 의 구체적인 구현 방식에 대해 질문할 수 있습니다 . 또 다른 상황은 당신이 독점 API를 사용하는 회사의 팀에 새로 합류한 개발자이고 , 당연히 그 독점 API는 다른 곳에서는 사용할 수 없으며, 아마존 Q 개발자는 그것을 어떻게 다뤄야 할지 전혀 모를 수도 있다는 것입니다. 그러니 팀 리더에게 아마존의 유능한 개발자에게 특정 샘플 코드를 보내달라고 요청하세요. 그 개발자는 해당 API의 모든 특징과 구현 방식을 배우게 될 겁니다. 그러고 나서 다음에 어떤 일을 어떻게 끝내야 할지 조언을 구할 때, 어떻게 될까요? 귀하께 맞는 맞춤형 추천을 제공해 드리겠습니다. 이 비디오에서는 Amazon Q 개발자 사용자 지정 기능을 처음부터 설정하는 방법과 해당 사용자 지정 기능을 IDE에서 사용하여 코드 추천을 요청하는 방법을 보여드리겠습니다. 그럼 더 이상 기다리지 않고 바로 시작하겠습니다 . 첫 번째 단계는 학습 목적으로 사용할 코드 샘플을 준비하는 것입니다. 이것은 두 가지 방법으로 달성할 수 있습니다. 첫 번째 방법은 Amazon Q 개발자가 GitHub와 같은 저장소에서 코드를 직접 가져오도록 하는 것이고, 두 번째 방법은 코드 샘플을 Amazon S3에 업로드하는 것입니다. 저는 지금부터 이 두 번째 방법을 사용할 것입니다. 보시다시피 저는 ' springpad cleaning code'라는 버킷을 만들었고, 그 폴더 안에 'code content'라는 하위 폴더를 만들어 교육용으로 사용할 모든 코드 샘플을 업로드했습니다. 이 시나리오에서는 유명한 스프링팻 클리닉의 샘플을 사용했지만, 보시다시피 동일한 샘플의 다양한 변형을 제공했습니다. 첫 번째 방법은 Angular를 프런트엔드 프레임워크로 사용하는 것입니다 . 백엔드는 동일하지만 프런트엔드가 다른 코드, 백엔드는 동일 하지만 프런트엔드로 React DS를 사용하는 코드, 그리고 계층 간 통신에 REST API를 사용하는 동일한 코드의 100% 완벽한 샘플도 포함되어 있습니다 . 이는 아마존 Q 개발자가 코딩 스타일을 어떻게 활용하고 여러 시나리오에서 어떻게 재사용할 수 있는지 보다 구체적으로 이해하는 데 중요합니다 . 질문을 시작하고 코드 생성 방식이나 코드 제안에 대한 프롬프트를 만들 때, 아마존 Q 개발자가 "아, 네 의도를 제가 학습한 내용과 어떻게 연결해야 할까요?"라고 판단하는 것이 매우 중요합니다. 코드 샘플을 모두 업로드했으면 Amazon Q 개발자 페이지로 이동하여 사용자 정의를 시작할 수 있습니다. 이 기능을 사용하려면 여기 있는 메뉴를 이용하시면 됩니다. 현재는 미리 보기 버전이지만, 아마 이 영상을 시청하실 때쯤에는 정식으로 사용 가능해질 사용자 지정 기능을 활용하시면 됩니다. 하지만 작업 흐름은 사실상 동일할 것입니다. 여기 있는 '사용자 지정 만들기' 버튼을 사용해서 사용자 지정을 만들고 이름을 지정하면 됩니다. 이 경우 저는 스프링 펫 클리닉에 전화해서 이 모든 교육 목적이 유명한 스프링패드 클리닉의 코드 샘플을 기반으로 한다는 것을 상기시켜 드리겠습니다. 그런 다음 다양한 연결 공급자를 사용할 수 있는데, 이 경우에는 코드스토어를 사용하여 GitHub와 같은 다양한 저장소에 연결하거나, 이 데모에서는 Amazon S3를 선택할 것입니다. 여기서는 S3 버킷의 URI를 입력해야 합니다. 여기를 클릭하여 S3를 찾아본 다음 사용하려는 URI를 선택하면 됩니다. 그래서 이 경우에는 코드 내용에 있는 이 URI를 사용하겠습니다. S3 URI 복사를 클릭한 다음 다시 S3 URI를 입력하러 돌아가겠습니다. 내용을 여기에 바로 전달해 드리겠습니다. 이 작업을 완료했으면 아래로 스크롤하여 '사용자 지정 생성'을 클릭하기만 하면 됩니다. 시작하기 전에, 한 가지 알려드릴 점이 있습니다. 로그 전달이라는 기능을 사용하면 교육 과정을 추적하고 문제를 해결하는 데 도움이 될 수 있습니다.
