## 스크립트

안녕하세요, 오늘은 자동화라는 기능에 대한 몇 가지 핵심 개념을 설명하려고 합니다. Haml님이 잘 설명해주셨듯이, 자동화는 가중치와 편향에서 수행하는 다양한 동작들을 연결하고, 자동으로 트리거되도록 하고 싶은 다운스트림 이벤트와 연결하는 일종의 접착제와 같은 역할을 합니다. 이번 자동화 발표의 핵심은 바로 이러한 이벤트-액션 쌍을 설정하는 것입니다. 다시 말해, 자동화는 이벤트-액션 쌍입니다. 이벤트는 모델 레지스트리에서 특정 변경 사항이 발생하는 것을 말합니다. 예를 들어 새 모델 버전이 추가되는 경우처럼요. 그리고 이 이벤트는 액션에 연결됩니다. 액션은 이벤트 발생에 대한 응답으로 트리거되는 다운스트림 액션입니다. 다시 말하지만, 복잡한 개념은 아니고, 그저 이벤트-액션 쌍일 뿐입니다. 여기 다이어그램에서 볼 수 있듯이, 설정할 수 있는 이벤트 유형은 두 가지입니다. 예를 들어, 특정 이벤트를 추가하거나, 또는... 새 버전이 추가되면 자동화 시스템은 이전에 살펴본 등록된 모델의 변경 사항을 감지합니다. 예를 들어, 새 모델이 추가될 때 모델 평가 파이프라인을 시작하도록 설정할 수 있습니다. 이 이벤트는 새 버전을 레지스트리에 연결하는 역할을 합니다. 두 번째 이벤트는 새 별칭을 추가하는 것입니다. 이는 특정 별칭을 사용하여 모델 버전을 추가하는 것을 의미합니다. 예를 들어, 모델 수명 주기의 특정 단계에 있을 때만 실행되어야 하는 작업을 시작하도록 설정할 수 있습니다. ' quantized'라는 별칭을 추가하면 모델 양자화와 같은 하위 프로세스를 트리거하는 데 유용한 이벤트가 될 수 있습니다. 또 다른 예로 'prod'라는 별칭을 추가하면 모델을 프로덕션 환경에 배포하는 하위 작업을 시작할 수 있습니다. 오른쪽에는 자동화 시스템이 응답으로 트리거할 하위 작업이 표시됩니다. 이벤트가 발생한 후 하위 작업이 실행됩니다. Weights and Bias에서는 현재 두 가지 작업 옵션이 있습니다. 첫 번째는 웹훅입니다. 소프트웨어에서 익숙한 용어일 수 있는데, Hamill이 웹훅 설정 방법과 로컬에서 웹훅을 설정하는 방법, 클라우드로 이동하는 방법 등 좋은 예시를 통해 자세히 설명할 예정입니다. Weights and Bias에서 웹훅을 실행한다는 것은 외부 애플리케이션에서 하위 프로세스를 시작할 수 있도록 해줍니다. 예를 들어 워크플로 오케스트레이터 에서 모델 평가 파이프라인을 시작할 수 있습니다. 기본적으로 다른 애플리케이션이나 서버의 외부 엔드포인트에 POST 요청을 보내는 것이며, Weights and Bias 이벤트를 다른 도구( 예: 모델 CI/CD 프로세스 관리 도구)에 연결할 수 있도록 해줍니다. 두 번째 유형의 작업은 런치 작업입니다. Job은 컨테이너화되고 재사용 가능하며 구성 가능한 작업으로, 다양한 컴퓨팅 환경에서 실행할 수 있습니다. 일반적으로 평가나 모델 재학습과 같이 컴퓨팅 요구량이 많은 작업을 처리할 때 이러한 방식을 권장합니다. 반면 WebHook은 GitHub Actions와 같은 CICD 도구 또는 사용 중인 워크플로 오케스트레이터와 같은 외부 시스템에 모델을 전달하는 데 더 유용합니다. Haml이 제공할 데모의 주요 초점이 될 WebHook에 대해서는 나중에 자세히 설명하겠습니다. Launch는 Weights and Bias 제품군의 또 다른 제품입니다. 제가 자동화의 구조에 대해 설명했던 이벤트-액션 쌍을 보여주는 다이어그램을 만들었습니다. 여러분은 이것이 CICD 워크플로와 어떤 관련이 있는지, 그리고 자동화가 Weights and Bias를 CICD 워크플로에 연결하는 데 어떻게 유용한지 이해할 수 있을 것입니다. 그래서 제가 다이어그램을 만들었습니다. 여기 몇 가지 예시가 있습니다. 왼쪽 맨 왼쪽 열에 자동화하려는 여러 워크플로가 표시되어 있는데, 여기서 중요한 점은 모델 레지스트리나 아티팩트의 변경 사항을 감지하여 이러한 프로세스를 자동화할 수 있다는 것입니다. 좋은 예시로 모델 평가 워크플로를 보여드리겠습니다. 새 모델이 스테이징 후보로 등록되고 모델 레지스트리에 연결되면 반드시 평가 테스트 시스템을 거쳐야 합니다. 자동화는 변경 사항을 감지하여 " 새 모델이 추가되었으니 모델 평가 프로세스를 시작해야겠다"라고 판단하고, 모든 평가 결과를 수집하여 팀에서 분석할 수 있도록 자동화된 보고서를 생성할 수도 있습니다. 데이터 세트 아티팩트에도 자동화를 적용할 수 있는데, 이 부분은 좀 더 간략하게 다루겠습니다. 데이터 세트 아티팩트에도 자동화를 설정하여 자동화를 적용할 수 있습니다. 새로운 데이터 세트나 버전이 추가될 때마다 이를 감지하고, 새로운 버전이 추가될 때마다 모델 재학습 파이프라인을 시작합니다. 이는 매달 정기적으로 새로운 데이터를 수집하는 고객들에게서 많이 볼 수 있는 사용 사례입니다. 고객들은 데이터가 가중치 및 편향 모델에 입력될 때마다 자동화된 기능을 통해 새로운 데이터 세트를 감지하고 재학습 프로세스를 자동으로 수행하기를 원합니다. 즉, 누군가가 " 새로운 주석이 달린 데이터가 있습니다. 모델을 재학습시켜 주시겠습니까?"라고 요청하는 대신 자동화된 기능을 활용하는 것입니다. 마지막으로 웹훅에 대해 말씀드리겠습니다. 이 부분은 나중에 자세히 데모를 통해 보여드리겠습니다. 외부 시스템과 통신할 때 인증 정보나 비밀 키, 액세스 토큰 등이 필요할 수 있는데, 이러한 정보를 가중치 및 편향 모델에 저장하는 것이 안전한지 궁금하실 수 있습니다. 네, 안전합니다. 저희는 이러한 정보를 안전하게 저장할 수 있는 비밀 키 저장소를 제공합니다. Weights and Bias and Beyond의 웹훅을 인증하기 위해 사용자 또는 수신 서버에서 필요한 비밀 키 또는 액세스 토큰입니다. 클라우드 배포 환경은 물론, 온 프레미스 배포 환경을 사용하는 모든 고객을 위해 주요 3대 클라우드 제공업체의 비밀 관리자와의 통합을 제공합니다.
