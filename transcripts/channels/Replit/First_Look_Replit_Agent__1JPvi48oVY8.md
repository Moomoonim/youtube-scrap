Riplet 홈페이지에 접속하시면, 핵심 구독자이신 경우 가장 먼저 Repet Agent 얼리 액세스 버튼을 보실 수 있습니다. 얼리 액세스는 중요한 주의사항입니다. 이 소프트웨어는 매우 새롭기 때문에 모든 기능이 완벽하게 작동하지 않을 수 있습니다. 하지만 내부 테스트와 트위터 및 인터넷에서 확인한 바에 따르면, 지금까지 매우 인상적인 성능을 보여주었습니다. 그리고 오늘 제가 생각하기에 아주 멋진 기능을 하나 보여드리겠습니다. Repet은 예전과 똑같습니다. 걱정하지 마세요. Repet은 항상 접근 가능한 Repet 앱을 계속 만들 수 있고, 당분간 사라지지 않을 겁니다. 하지만 Repet 에이전트를 사용하면 훨씬 빠르게 시작할 수 있게 되었습니다. 이번 데모에서는 방명록을 만들어 보겠습니다. 제 블로그에 방명록이 있는데, 만드는 데 시간이 좀 걸렸습니다. 사실 만드는 방법을 알려주는 튜토리얼도 만들었죠. 하지만 설정이 복잡하고 데이터베이스도 만들어야 해서 어려웠습니다. Repet 에이전트가 이런 것도 쉽게 처리해 줄 수 있는지 한번 보겠습니다. 제 블로그에 사용자들이 이름과 메시지를 남길 수 있는 방명록을 만들어 보겠습니다. 방명록은 메시지가 세션이나 사용자 간에 저장되지 않으면 의미가 없죠. 그냥 일시적인 React 앱처럼 아무 기능도 하지 않는 건 원하지 않습니다. 그러니까 사용자의 이름과 메시지가 영구적으로 저장되도록 해야 합니다. 제가 '입력' 버튼을 클릭하면 어떻게 될까요? 음, 다른 AI 도구들을 아시는 분이라면, 그런 도구들은 일회성 AI 도구라고 생각하실 거예요. 프롬프트를 입력하면 애플리케이션을 만들어주고, 단일 페이지짜리 React 앱을 반환하는 식으로요. 그게 전부죠. 하지만 제 에이전트는 다릅니다. 에이전트는 무엇을 만들어야 할지 고민하고, 애플리케이션과 그 구현 단계를 계획하는 데 시간을 투자합니다. 그리고 그 계획을 저에게 제시해 주는 거죠. 저는 Flask, Vanilla JS, Posttest를 사용해서 방명록 앱을 만들었어요. 이 앱은 사용자들이 기존 게시물을 보고 새 게시물을 작성할 수 있게 해주고, 데이터는 데이터베이스에 저장됩니다. 에이전트가 데이터베이스를 설정하고 애플리케이션에 연결해 주는 거죠. 그리고 현재 기능은 제가 제안한 기존 앱에 추가할 수 있는 개선 사항이나 다음 단계 목록을 제안해 주는 겁니다. 저는 그중에서 원하는 것을 선택할 수 있어요. 예를 들어 페이지네이션이나 관리자 기능 같은 걸 제안해 보죠. 저는 이런 건 필요 없고, 그냥 기본적인 제안만 받고 싶어요. 제가 선택할 수 있는 항목들이 있고, 에이전트가 완료되면 해당 단계로 넘어갑니다. 음, 이제 '앱 승인 계획'을 누르고 시작하겠습니다. 그러면 에이전트가 반복 작업을 시작할 겁니다. 에이전트는 MVP를 만들어 제가 원하는 대로 되는지 확인하도록 설계되었습니다. 지금 보시는 것은 에이전트가 이 파일 시스템에서 파일을 편집하기 시작하는 것입니다. 여기서 강조하고 싶은 것은 이것이 리플, 즉 가상 컨테이너이자 가상 머신이라는 점입니다. 에이전트는 지금 이 모든 파일을 생성, 편집, 업데이트하고 있습니다. 그런 다음 제가 만들고 있는 방명록에 연결할 데이터베이스를 생성할 것입니다. 왼쪽에서 보시다시피 CSS, JavaScript 파일, 웹 페이지를 표시하는 HTML 파일이 생성되었고, 지금은 main.py 파일을 작업 중입니다. 이 모든 것을 진행률 창에서 볼 수 있습니다. 이제 에이전트가 패키지를 설치하고 있습니다. Python 환경을 관리하는 방법인 p 프로젝트 파일(poetry.py)을 생성했고, Python 패키지 설치를 시작했습니다. 단순히 코드를 생성하는 것 이상으로, 필요한 실행 환경을 보여주고 실제로 구축해 줍니다. 그래서 최종적으로 이 과정이 완료되면 모든 코드와 작동하는 애플리케이션에 접근할 수 있게 됩니다. 에이전트가 배포 과정을 안내해 주겠지만, 만약 main.py 파일을 수정하고 싶다면, 예를 들어 Repeti-AI 도구를 사용해서 수정할 수 있습니다. 익숙한 인터페이스에서 AI 패널을 열고 애플리케이션에 대해 더 자세한 질문을 할 수도 있죠. 아니면 AI가 제가 만들고자 하는 것에 대한 맥락을 이해하지 못하는 경우, 제가 원하는 도메인별 기능을 추가해서 직접 코드를 작성하여 개선할 수도 있습니다. 에이전트가 블로그 방명록을 보여준 것 같은데, 모든 게 괜찮아 보이면 메시지를 남기라는 메시지가 뜹니다. 하지만 저는 참을성이 없으니, "앗!", "안녕하세요!" 같은 메시지를 남겨보겠습니다. 작동하는지 확인해 볼게요. 잘 작동하네요. 방명록에 글을 남길 수 있고, 보시다시피 애플리케이션 화면을 캡처했어요. 이미 작동하는 걸 알고 있었던 거죠. 그런 다음 배포 창이 나타났어요. 초기 프로토타입을 구축한 거죠. 여기서 다른 기능을 추가하거나 다른 작업을 하고 싶으면 에이전트를 통해 계속해서 수정하고, 변경하려는 디렉터리의 파일을 계속해서 편집할 수 있어요. 하지만 지금은 배포 과정이 얼마나 원활한지 보여드리고 싶었어요. 에이전트가 이 애플리케이션을 구축했고, 어떤 배포 방식이 가장 적합한지 알고 있어서 VM 예약을 제안할 거예요. '배포 설정'을 클릭할게요. 이름을 ' 맷의 방명록'으로 지정할게요. 아마 사용 가능할 거예요. 이제 머신을 구성할 수 있어요. 원한다면 더 강력하게 만들 수도 있고요. 파이썬 실행 명령도 이미 설정되어 있어요. 그리고 정말 놀라운 점은, 새 게시물 주소(PAN)로 이동하면 데이터베이스가 있다는 거예요. PostgreSQL 데이터베이스가 있는데, 제가 이걸 클릭하면 각 사용자에 대한 항목이 표시됩니다. 초기 계획에서 명시했던 대로 에이전트는 PostgreSQL 데이터베이스를 생성한 모든 사용자를 추적하고 해당 데이터를 영구적으로 보관합니다. 여러 사용자가 동시에 방명록을 편집할 수 있으며, 모든 데이터가 보존됩니다. 또한 방명록에 참여한 다른 사용자를 볼 수도 있습니다. 이것은 데이터베이스, 프런트엔드, 백엔드를 갖춘 풀 스택 애플리케이션이며, 에이전트가 모든 것을 구축하고 연결해 주었습니다. 이제 배포할 차례입니다. 배포 패널로 이동하면 에이전트가 데이터베이스를 연결하고 필요한 모든 정보를 제안해 주었습니다. 이제 배포 버튼을 클릭하면 배포 프로세스가 진행됩니다. 이것이 Repet 에이전트입니다. 배포가 진행되는 동안 Repet 에이전트와 다른 도구들의 차이점에 대해 간단히 설명하거나, 여기서 무슨 일이 일어나고 있는지 설명하겠습니다. 에이전트는 추론을 진행하고 있습니다. 사용자 입력을 받아들이고 반복적으로 작업을 수행하며, 전체 repet 환경에 접근할 수 있습니다. 즉, 에이전트는 페어 프로그래머와 유사하다고 생각할 수 있습니다. 환경을 설정하고, 패키지를 설치하고, 파일을 생성하고, repet이 에이전트에 노출한 서비스를 생성할 수 있기 때문입니다. repet 인터페이스의 모든 기능을 에이전트에 노출했으므로, 에이전트가 애플리케이션에 데이터베이스가 필요하다고 판단하면 데이터베이스를 생성할 수 있고, 스크립트를 예약된 배포로 실행해야 한다고 판단하면 "이 인터페이스를 사용하여 예약된 배포를 구성하는 방법은 다음과 같습니다."라고 안내할 수 있습니다. repet의 놀라운 점은 소프트웨어 빌드 및 배포에 최적화된 가상 머신 환경을 구축하기 위한 다양한 도구를 개발했다는 ​​것입니다. 덕분에 파이썬과 Node.js를 한 줄 명령으로 설치할 수 있고, 에이전트도 마찬가지로 한 파일로 파이썬 환경을 빠르게 구성할 수 있습니다. 이는 애플리케이션 개발에 있어 무궁무진한 가능성을 열어줍니다. AI를 활용하면 정말 흥미로운 도구와 프로젝트를 만들 수 있을 거라고 생각합니다. 이미 많은 사용자들이 그렇게 하고 있는 것을 볼 수 있습니다. 이제 애플리케이션으로 돌아가서 배포 프로세스가 완료되었음을 확인해 보겠습니다. 3분 만에 에이전트가 생성한 전체 환경을 프로비저닝하고 코드 스냅샷을 찍었습니다. 이는 기존 리플 배포 방식과 동일하게 작동하며, 해당 URL로 푸시됩니다. URL에 접속하면 제 방명록과 제가 남긴 메시지를 볼 수 있습니다. 예를 들어, 제가 "맷"이라고 입력하고 메시지를 남기고 제출 버튼을 누르면 다른 메시지가 표시됩니다. 제가 기대했던 모습 그대로입니다. 이것으로 리플 에이전트에 대한 소개를 마치겠습니다. 여러분이 무엇을 만들어낼지 정말 기대됩니다. 놀라운 기회들이 많이 있을 거라고 생각합니다. 이 에이전트는 이전에는 이러한 기술 도구를 사용해 볼 기회가 없었던 사람들에게도 잠재력을 열어줄 것입니다. 그뿐만 아니라, 에이전트가 워낙 강력하기 때문에 더욱 기대가 큽니다. 이 도구는 생각하는 방식과 편집 중인 파일을 보여주기 때문에 설명적입니다. 이 도구를 사용하면 이러한 구성 요소들이 서로 어떻게 연결되는지 이해할 수 있을 거라고 생각합니다. 제가 개인적으로 AI를 개발하면서 느낀 점은 처음에는 개념이 생소하게 느껴질 수 있지만, 개발할수록 이러한 요소들이 어떻게 결합되고 왜 결합되는지 더 잘 이해하게 된다는 것입니다. 궁금한 점이 있으면 Repid AI 탭을 열어서 " 이 프로젝트에서 왜 바닐라 자바스크립트를 사용하나요? 프런트엔드에 자바스크립트, 백엔드에 파이썬을 사용하는 목적은 무엇인가요? 플래시와 AI는 어떻게 작동하나요?"라고 질문할 수 있습니다. Repid AI는 Sonet과 GBT 40으로 구동되며, 이러한 질문에 답하고 구성 요소들이 어떻게 연결되는지 이해하는 데 도움을 줄 것입니다. 이를 통해 더 나은 애플리케이션과 더 구체적인 도구를 만들 수 있게 될 것입니다. 에이전트에게 더 많은 맥락을 제공하여 Repid AI에 질문을 던질 수 있기 때문입니다. 네, 맞습니다. Repet Agent는 AI를 활용한 개발의 다음 단계입니다. 처음에는 원핫 프롬프트를 사용하여 단일 페이지 애플리케이션을 생성하는 시스템이 있었고, 그 다음에는 코드 편집기로 넘어갔는데, 이것이 두 번째 단계였습니다. 그리고 이제는 자체 개발 환경을 갖추고 반복 작업을 수행하며 피드백을 수용하고, 풀 스택 애플리케이션에 필요한 모든 세부 사항과 서비스를 구성하고 웹에 배포할 수 있는 자율 시스템이 있습니다. 이것이 바로 Repet Agent입니다. 오늘부터 모든 Repet Corp 구독자에게 얼리 액세스로 제공됩니다. rep.com에 접속하여 로그인하고 살펴보시고 개발을 시작해 보세요. 여러분이 무엇을 만들어낼지 정말 기대됩니다. 저는 Repet의 개발자 관계 담당자 Matt이고, 지금 까지 Repet Agent에 대한 첫 번째 소개였습니다. 다음에 또 뵙겠습니다.
