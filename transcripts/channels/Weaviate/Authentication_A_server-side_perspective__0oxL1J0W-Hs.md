API 키가 정의되면 세 가지 작업을 모두 문제없이 수행할 수 있는 것을 확인할 수 있습니다. 다음으로 사용자 별로 다른 액세스 수준을 정의하는 방법을 보여드리겠습니다. 이를 위해서는 여기에 표시된 권한 변수를 정의해야 합니다. 먼저 다음 변수를 설정해야 합니다. 관리자 목록을 활성화하고 관리자 목록에 포함될 사용자 와 읽기 전용 사용자 목록에 포함될 사용자를 정의해 보겠습니다. IDC 설정은 API 키 액세스 설정과 매우 유사합니다. 토큰 발급자의 설정과 일치하도록 이러한 변수를 설정해야 합니다. 먼저 IDC를 활성화해 보겠습니다. 나머지 설정은 토큰마다 고유합니다. 저희의 경우 토큰 발급자로 WCS를 사용하겠습니다. 해당 설정은 문서의 인증 페이지에서 찾을 수 있습니다. 아래로 스크롤하면 Weaviate를 리소스로 구성하는 방법에 대한 지침이 있습니다. 여기에 사용할 OIDC 설정이 있으므로, OIDC 발급자, 클라이언트 ID, 사용자 이름 클레임부터 시작하여 구성 파일에 복사해 넣으면 됩니다. 마지막으로, 이전과 마찬가지로 사용자에게 특정 수준의 권한을 부여해야 합니다. 이를 위해 제 사용자 이름을 관리자 사용자 목록에 추가합니다. 이제 Weaviate를 다시 시작하고 자격 증명으로 Weaviate에 액세스할 수 있는지 확인해 보겠습니다. OIDC 자격 증명을 사용하는 사용자를 읽기 전용 사용자로 지정하는 것은 이전과 마찬가지로 잘 작동합니다. 사용자 이름을 가져와 관리자 사용자 목록에 추가하는 대신 읽기 전용 사용자 목록에 추가하면 됩니다. 따라서 동일한 셀을 실행하면 이전과 마찬가지로 처음 두 명령은 제대로 실행되지만 자격 증명이 부족하여 객체를 생성할 수 없습니다. 이 비디오를 통해 Webiate 인스턴스의 인증 및 권한 부여를 설정하는 데 필요한 단계를 잘 이해하셨기를 바랍니다. 설정해야 하는 변수는 다음과 같이 authentication 및 authorization으로 시작하는 변수입니다.
