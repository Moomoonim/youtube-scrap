## 스크립트

안녕하세요, Damo KV Manager 비디오 데모에 오신 것을 환영합니다. Damo KV Manager는 경량 KV 오프 플로팅 프레임워크로, WeLland와 같은 인기 있는 추론 엔진에서 쉽게 사용할 수 있습니다. 예를 들어, 복잡한 멀티코드, CLI, 멀티 언 대화 시나리오에서 Damo KV Manager 솔루션은 제거된 캐시를 CPU 호스트 메모리와 SSD로 오프로드하여 KV 재작성 계산을 최소화합니다. 첫 번째 섹션은 설치입니다. 보시다시피 KV Manager 개발 컨테이너에 이미 설치되어 있습니다. Dynamo KV Manager 설치는 간단합니다. Dynamo Adapted WeLland와 파이핑 스톨만 다운로드하면 됩니다. 전역 KV 목록과 같은 다른 모듈은 Damo 설치 시 이미 포함되어 있습니다. 자, 그럼 두 번째 섹션으로 넘어가서 Dynamo KV Manager를 활성화하는 방법을 설명하겠습니다. Damo WeLland 서버를 초기화할 때 KV 전송 구성을 추가하기만 하면 됩니다. Dynamo 캐시 커넥터와 KV Manager가 활성화됩니다. 나머지 구성은 동일합니다. 예를 들어, 공정한 비교를 위해 GPU PR 접두사 캐싱을 활성화합니다. 또한 Chun 프로필을 비활성화했습니다. 서버 초기화 프로세스는 할당하는 CPU 메모리 블록 수에 따라 몇 분까지 걸릴 수 있습니다. 예를 들어, 여기서는 200k 블록을 할당했는데, 약 600GB의 CPU 호스트 메모리가 필요합니다. 좋습니다. 이제 서버가 실행되었습니다. 보시다시피 아래쪽에 두 개의 터미널이 있습니다. 왼쪽에는 서버가 있고 오른쪽에는 클라이언트가 있습니다. 벤치마킹을 위해 멀티 클라이언트 멀티유저 워크로드를 구성했는데, 이는 multiusertest라는 파이썬 스크립트로 구현되었습니다. 시간 제약으로 인해 구현 의 모든 세부 사항을 설명할 수는 없지만, 몇 가지 구성 세부 사항에 주의를 기울이도록 하겠습니다. 먼저 사용자 수를 50명으로 설정했습니다. 즉, 50명의 사용자가 동시에 시스템과 통신할 수 있습니다. 각 사용자는 서버와 10번의 라운드를 통신하게 됩니다. 시스템 프롬프트 렌즈를 1K로 설정했습니다. 즉, 각 실행, 각 반복에서 ISL이 더 긴 시퀀스에 추가됩니다. 물론 각 클라이언트는 각 R에서 메시지를 전송합니다. 서버에 새로운 ISL을 추가하고 새 출력을 128로 설정했습니다. 좋습니다. 이제 클라이언트를 시작하고 결과를 확인해 보겠습니다. 보시다시피 새로운 ISL이 몇 개 추가되었고 많은 로그가 표시됩니다. 일부는 VM 관련 로그이고 일부는 DynamoDB 관리자 관련 로그입니다. 시간을 절약하기 위해 메트릭 클립을 보여드리겠습니다. llm에서 GPU KV 캐시 사용량을 볼 수 있는데 거의 100%에 가깝습니다. 즉, 많은 KV 캐시가 영향을 받을 것입니다. 바로 이 부분에서 저희 솔루션이 작동합니다. DynamoDB KV 관리자 잠금을 보면 KV 관리자 CPU 캐시에서 약 2만 개의 토큰을 수신한 것을 볼 수 있습니다. 이는 PCIe를 통해 이루어집니다. 이것이 시간 비용입니다. 또한 접두사 캐시에서 약 3천 개의 토큰을 수신했지만 CPU 캐시에 비해 매우 제한적입니다. 이것이 바로 이러한 이유입니다. 물론 직접적인 TTFT(총 응답 시간) 향상이 있지만, 비교를 위해 순수 GPU 접두사 캐싱의 성능 수치도 확인하고 싶으실 겁니다. 간단하게 할 수 있는데, 엔진 초기화에서 KV 전송 설정을 삭제하면 됩니다. 그런 다음 오른쪽에 있는 동일한 클라이언트를 실행하면 TTFT와 처리량 성능 수치를 얻을 수 있습니다. 마지막으로, 성능 데이터를 요약해 드렸듯이 Dam KV 관리자는 사용자 수나 라운드 수, 또는 둘 다를 늘릴 경우 TTFT 측면에서 순수 TPU 접두사 캐싱보다 훨씬 뛰어난 성능을 보여줍니다. SSD 로딩도 이미 지원되지만 시간 관계상 자세히 다루지는 않았습니다. 자세한 내용은 언제든지 문의해 주세요. 이것으로 이번 비디오 데모를 마치겠습니다. 시청해 주셔서 감사합니다.
