## 스크립트

안녕하세요, 이번 영상에서는 Weaviate에서 제공하는 인증 옵션, 특히 익명 액세스, API 키, OpenID Connect(ODC) 인증의 차이점을 자세히 살펴보겠습니다. 인증은 복잡할 수 있으며 많은 사용자가 문의하는 부분이기도 합니다. Weaviate는 다양한 사용자 요구 사항을 충족하고 보안을 최우선으로 고려하여 이러한 옵션을 제공합니다. 하지만 인증은 다소 복잡한 주제이므로 각 방식의 작동 방식을 좀 더 자세히 알아보겠습니다. 먼저 익명 액세스부터 살펴보겠습니다. 이 방식은 가장 간단하지만 보안이 가장 취약합니다. 익명 액세스는 상호 작용에 대한 제약이 없으므로 Weaviate 인스턴스에 접근 권한이 있는 경우 모든 작업을 수행할 수 있습니다. API 키 또는 OID Connect 인증의 경우, 인증 정보는 각 요청의 추가 헤더로 Eva에 전달됩니다. API 키 방식은 Weaviate가 내부적으로 검증하여 해당 권한을 부여하는 문자열 키를 사용합니다. OID Connect 인증은 사용자 이름과 비밀번호와 같은 자격 증명을 사용하여 Microsoft OCTA 또는 WCS와 같은 외부 토큰 발급 기관에서 서명된 토큰을 발급받아 Weaviate에 전달합니다. 이 토큰은 암호화 방식으로 서명되어 Weaviate가 토큰 발급 기관의 정보를 사용하여 소유자를 확인할 수 있도록 합니다. 이러한 ID 토큰은 시간 제한이 있어 비공개 인스턴스에서 토큰이 유출되거나 가로채이는 것을 방지하여 시스템을 더욱 강력하게 만듭니다. Eva는 인증된 ID를 기반으로 권한을 부여할 수 있으며, 이 단계를 권한 부여라고 합니다. 이는 기술적으로 인증과는 다르지만 전체 프로세스에서 매우 중요한 부분입니다. 대부분의 경우 공개 인스턴스를 사용하는 것은 너무 불안정할 수 있으므로 API 키 인증을 사용하는 것이 좋습니다. 시각적 보안이 필요한 경우 YDC가 좋은 옵션일 수 있지만, 앞서 언급했듯이 복잡성이 상당히 증가합니다. 모든 IDC 토큰은 만료되므로 가로채이더라도 위협이 최소화됩니다. 단점은 이러한 토큰을 주기적으로(일반적으로 약 15분마다) 갱신해야 한다는 것입니다. Waviate 클라이언트를 사용하는 경우 이 동작이 자동화되어 눈에 띄지 않지만 수동으로 수행할 경우 매우 복잡한 프로세스가 될 것입니다. 또한 OIDC에는 리소스인 Waviate, 토큰 발급자( Microsoft OCTA 또는 WCS와 같은 ID 공급자)인 Waviate, 그리고 클라이언트의 세 주체가 관여합니다. 각 ID 공급자는 종종 서로 다른 구성을 사용하므로 Waviate와 클라이언트가 설정을 적절하게 일치시켜야 합니다. OIDC에 필요한 복잡성은 다음과 같습니다. API 키는 일반적으로 보안과 사용 편의성 사이에서 좋은 균형을 이루지만, 만료되지 않으므로 유출되거나 가로채질 경우 수동으로 취소될 때 까지 리소스에 접근하는 데 사용될 수 있습니다. 이러한 이유로 특정 상황에서는 OIDC 솔루션이 더 적합할 수 있습니다. 지금까지 Weaviate에서 사용할 수 있는 세 가지 인증 방법 비교에 대해 살펴보았습니다. 이 영상이 다양한 인증 방법의 차이점을 잘 이해하고 사용 사례에 맞는 최적의 옵션을 선택하는 데 도움이 되었기를 바랍니다. 시청해 주셔서 감사합니다. 다음에 또 뵙겠습니다.
