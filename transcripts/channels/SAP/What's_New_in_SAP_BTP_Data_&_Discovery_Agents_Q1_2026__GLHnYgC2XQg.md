## 스크립트

여러분, 안녕하세요. 2026년 첫 번째 SAP BDP Insights에 오신 것을 환영합니다. 오늘날 SAP BDP 기반 SAP HANA Cloud에서 데이터를 다루려면 데이터가 어디에 있는지, 테이블이 어떻게 연결되어 있는지, 그리고 데이터를 어떻게 쿼리하는지 알아야 합니다. 이는 단지 해답을 원하는 개발자와 데이터 사용자에게 큰 장벽이 됩니다. 이것이 바로 디스커버리 에이전트 와 데이터 에이전트가 해결하고자 하는 문제입니다. 그럼 한번 살펴볼까요? 먼저 SAP HANA 클라우드에 몇 가지 BDC 데이터 제품을 설치해 보세요. 설치가 완료되면 해당 시스템에 쿼리를 실행하여 판매 내역 및 판매 문의 테이블을 자세히 살펴봅니다. 저는 영업 문의 테이블과 유사하지만, 추가적으로 판매 전환 확률 열을 포함하는 판매 예측 테이블을 만듭니다. SAP RPT1 모델의 예측 기능을 활용하면 이제 각 고객의 판매 전환 확률을 손쉽게 계산할 수 있습니다. 모든 데이터베이스 객체가 준비되었으므로, 이제 데이터 제품이나 데이터베이스 객체가 무엇인지 모르는 사용자라도 데이터 및 검색 에이전트가 이러한 데이터와 상호 작용하는 방법을 살펴보겠습니다. SAP HANA Cloud Central에서 ' 지식 그래프 생성'을 클릭하면 SAP HANA Cloud의 모든 데이터베이스 객체에 대한 의미론적 보기가 구축됩니다 . 사용자 지정 지식 그래프가 준비되면 Jewel을 사용하여 데이터베이스와 통신할 수 있습니다 . 예를 들어, 저는 " 모든 고객에 대한 판매 전환 확률을 예측하고 모든 세부 정보를 보여주세요."라고 요청합니다. 검색 에이전트는 관련 데이터 제품 및 데이터베이스 객체를 찾은 다음, 이를 실행 가능한 SQL로 변환하여 HANA 클라우드에서 실행하여 결과를 가져옵니다. 이러한 새로운 에이전트를 사용하면 기본 아티팩트에 대한 깊은 지식 없이도 데이터를 더 쉽게 탐색, 분석 및 활용할 수 있습니다 . 이러한 데이터 및 검색 에이전트는 조만간 SAP HANA 클라우드와 함께 베타 버전으로 제공될 예정입니다 . 더 자세한 내용을 알고 싶으시면 영상 설명란에 있는 링크를 확인해 주세요 . 현대 기업에게 연결성은 매우 중요합니다 . SAP BTP용 SAP Integration Suite 어댑터는 데이터 사일로를 해소하고 운영을 간소화하며 새로운 기능을 신속하게 도입하여 혁신 속도를 높임으로써 통합 환경을 혁신하는 데 도움을 줍니다. 최신 릴리스에서는 직원 생애주기 데이터를 효율적으로 수신 및 처리할 수 있는 BambooHR 어댑터, 캘린더, 메일, 첨부 파일 및 메시지를 핵심 업무 워크플로에 원활하게 통합할 수 있는 Microsoft Outlook 송수신 어댑터 등 뛰어난 연결 옵션이 제공됩니다. 특히 엣지 통합 셀(Edge Integration Cell)의 경우, NFS 시스템과의 안전한 데이터 교환을 가능하게 하는 파일 어댑터와 , 비즈니스 파트너와의 안전한 메시지 교환을 위한 OFTP 2 규격 준수 B2B 연결 어댑터를 출시했습니다 . SAP Business Accelerator Hub(api.sap.com)에서 사용 가능한 모든 통합 콘텐츠, 어댑터, iFlow, AI 통합용 API 패키지 등을 살펴볼 수 있습니다. 실제 자동화 시스템에서는 오류가 불가피합니다. 견고한 시스템을 구별하는 것은 시스템이 얼마나 자주 실패하느냐가 아니라, 실패했을 때 얼마나 의도적으로 대응하는가입니다. SAP BTP의 SAP 빌드 프로세스 자동화에서 RPA 오류 처리에 정확성과 예측 가능성을 어떻게 구현하는지 보여드리겠습니다. 여기서는 API 기반 액션 단계를 구성하고 있습니다. 먼저, 액션 단계에 대한 오류 처리 이벤트를 정의합니다 . 인증 실패를 정확하게 처리하기 위해 401과 같은 특정 오류를 정의할 수 있습니다 . 오류가 발생했을 때 실행되어야 하는 하위 프로세스를 추가할 수 있습니다. 또한 4XX, 5XX와 같은 일반적인 범주를 정의하여 보다 광범위한 클라이언트 또는 서버 문제를 처리할 수 있습니다. 보시 다시피 저는 어떤 범주도 겹치도록 정의할 수 없습니다. 예를 들어, 401과 4XX를 결합할 수는 없습니다. 이를 통해 모호성을 제거하고 확정적인 런타임 동작을 보장합니다. 오류가 발생할 경우 우선순위는 엄격하게 적용됩니다. 구체적인 오류를 먼저 표시하고, 그다음 일반적인 범주를 표시하고, 마지막으로 정의 되지 않은 대체값을 표시합니다. 마지막으로, 다음 단계로 진행할지 아니면 프로세스를 종료할지 결정함으로써 결과를 제어합니다. 실행 단계에서 재시도 횟수와 재시도 간 지연 시간을 설정하여 재시도 설정을 구성할 수 있습니다 . 재시도 횟수가 모두 소진된 후에야 오류 처리 로직이 실행됩니다. 재시도부터 문제 해결까지 모든 단계가 모니터링 시스템에 완벽하게 기록되어 추적성이 보장됩니다. 이를 통해 오류 처리는 블랙 박스가 아닌 제어 가능하고 관찰 가능한 워크플로 결정으로 전환됩니다. 더 자세한 내용을 알아보려면 영상 설명란의 링크를 확인하세요 . 오늘은 SAP BTP에서 SAP Build Work Zone을 활용하는 강력한 새로운 방법을 여러분께 소개해 드리게 되어 매우 기쁩니다. 여러 페이지를 클릭하는 대신 , 필요한 것을 직접 요청하기만 하면 필요한 작업을 처리해 줍니다 . 새로운 프로젝트 작업 공간을 설정해야 하는 상황이라고 상상해 보세요. 여러 부서가 참여하는 프로젝트를 위한 작업 공간을 만들어야 합니다 . Joe를 열고 ' 2분기 고객 참여를 위한 작업 공간 만들기'라고 입력하기만 하면 됩니다 . 조는 사용 가능한 템플릿에 대해 안내해 드립니다 . 템플릿을 하나 선택하세요. 창조는 계속된다. 몇 초 만에 작업 공간이 생성됩니다. 다음으로, Mo를 작업 공간에 참여시켜야 한다는 것을 깨닫고 Joe에게 작업 공간 세부 정보를 확인하도록 요청합니다. 그러자 조는 당신이 알려준 이름과 일치하는 사람을 찾았습니다 . 이름과 이메일, 맞습니다. 초대장이 발송되었습니다. Mo가 시스템에 로그인하면 초대를 수락하고 워크스페이스 멤버가 됩니다. 마지막으로, 시작 문서를 추가해야 합니다 . 그러니까, 파일을 작업 공간에 업로드하기만 하면 됩니다 . 조는 작업 공간에서 사용 가능한 폴더 목록을 작성했습니다 . 하나를 선택하세요. 이제 파일 업로드를 완료할 수 있습니다 . 복잡한 탐색도, 화면 전환도, 기술적인 단계도 필요 없습니다. Joe가 개발한 자연어 처리 기술 덕분에 SAP Build Zone은 더욱 대화형이고 직관적이며 사람들이 실제로 일하는 방식에 더욱 부합하게 되었습니다. 오늘은 SAP Automation Pilot과 J를 사용하여 반복적인 운영 작업을 에이전트 기반 기능으로 전환하는 방법을 보여드리겠습니다. 먼저 SAP Automation Pilot 인터페이스를 사용하여 S/4HANA 상태 점검이나 SAP HANA 클라우드 문제 해결 작업과 같은 실제 운영 프로세스부터 시작합니다. 필요한 자동화를 수집하고 MCP 서버로 그룹화한 다음, 이 서버를 J Studio에 연결하여 J 운영 에이전트를 구축합니다. 이러한 방식으로 운영팀은 여러 화면과 절차를 오가는 대신 J에 있는 운영 담당자에게 간단히 문의할 수 있으며, MCP 서버를 사용하는 담당자가 요청된 작업을 즉시 실행합니다. 자세한 내용은 아래 링크를 확인하세요.
