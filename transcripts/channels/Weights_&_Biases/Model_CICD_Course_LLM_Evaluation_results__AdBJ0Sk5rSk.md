## 스크립트

최대 단계 매개변수를 수정했으니 이제 학습 라운드가 완료되었습니다. 학습 CLA가 1,000단계가 조금 넘는 기간 동안 수렴한 것을 확인할 수 있습니다. 또한 평가에서 확정한 모델의 생성 결과도 볼 수 있습니다. 프롬프트와 생성 결과를 모두 확인할 수 있죠. 이제 기준선과 비교하여 어떻게 보이는지 살펴보겠습니다. 수동으로 평가를 실행하는 대신, 아티팩트로 이동하여 이 학습 CLA에 저장한 모델을 선택하고 레지스트리에 연결하겠습니다. 우리는 작은 명령어 llm을 사용하고 있다는 점을 기억하세요. 이제 후보 ALA를 이 모델 버전에 추가하고 연결하면 레지스트리에서 이 모델을 확인할 수 있을 겁니다. 평가 작업이 트리거되었기를 바랍니다. 큐를 확인해 보면 새 실행 상태가 에이전트를 기다리는 중이고 현재 실행 중인 것을 볼 수 있습니다. 에이전트가 이 특정 평가 실행을 선택했으니, 해당 위치로 이동하여 다시 한번 확인할 수 있을 것입니다. 설정 화면에서 후보 모델이 이제 작은 명령어 LM V3인 것을 확인할 수 있습니다. 이 모델은 기준 모델인 버전 0과 비교 평가되고 있습니다. 실행이 완료되면 결과를 볼 수 있을 텐데, 아직 진행 중인 것 같습니다. 잠시 기다리면 결과를 확인할 수 있겠네요. 후보 모델의 선호도 점수는 0.53입니다. 이 결과는 기준 모델보다 훨씬 좋습니다. 이 점수를 바탕으로 후보 모델을 더 발전시킬 수 있을 것 같습니다. 다음 단계로 넘어갈 수도 있고, 프로덕션 단계로, 또는 양자화 단계로 넘어갈 수도 있습니다. 기준 모델과 후보 모델의 비교 결과를 볼 수 있을 겁니다. 예를 들어 선택 항목별로 필터링하거나 그룹화할 수 있습니다. 기준 모델이 후보 모델보다 좋은 예는 단 12개뿐입니다. 어, LLM 평가자가 두 모델을 동등하게 판단한 경우가 23건이고, 후보 모델이 더 나은 경우가 65건입니다. 즉, 후보 모델이 기준 모델보다 확실히 더 우수하다는 뜻입니다. 더 자세히 분석하여 회귀가 발생하는 부분이나 후보 모델이 기준 모델보다 성능이 떨어지는 부분을 파악하고 싶다면 이 표를 활용할 수 있습니다. 예를 들어, 특정 그룹을 제거하고 오류 분석에만 집중하고 싶다면, 이 표를 기준으로 정렬하면 후보 모델이 기준 모델보다 성능이 떨어지는 모든 사례를 확인할 수 있습니다. LLM 평가자의 판단 근거를 살펴보고 이를 바탕으로 다음 실행에서 모델을 개선할 수 있습니다. 예를 들어, 더 많은 데이터를 제공해야 할 수도 있고, 하이퍼파라미터를 변경해야 할 수도 있습니다. 이러한 과정을 통해 장기적으로 모델을 개선할 수 있습니다. 따라서 모델 레지스트리 의 작업을 기반으로 자동화된 방식으로 평가 및 분석을 설정하는 것의 가치를 이해하셨기를 바랍니다. 여러분이 프로젝트와 소속 조직에서 이 방법을 실제로 적용해 보시기를 기대합니다.
