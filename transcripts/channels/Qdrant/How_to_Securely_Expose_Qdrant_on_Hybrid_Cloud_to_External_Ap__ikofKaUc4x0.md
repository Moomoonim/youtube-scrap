API 키를 직접 입력할 필요는 없고, Kubernetes 클러스터 에 있는 시크릿을 참조하기만 하면 됩니다. 그럼 먼저 ccj 명령어를 사용하여 시크릿을 생성해 보겠습니다. API 키라는 이름의 필드를 가진 'my API key'라는 시크릿을 생성하고, 이 필드의 값은 ' Top Secret'이라고 지정합니다. 이 경우 쿼드런트 이름에 'Top Secret'을 사용합니다. Kubernetes 시크릿은 CLI뿐만 아니라 원하는 Gitops 도구나 HashiCoP World와 같이 Kubernetes 연결을 지원하는 다른 시크릿 관리 도구를 사용하여 생성할 수 있습니다. 이제 이 시크릿이 생성되었으므로 쿼드런트 클러스터 구성에서 이를 참조할 수 있습니다. 시크릿 이름과 나중에 로그인할 때 입력할 실제 값이 구성된 필드 이름을 복사합니다. 저장하면 몇 초 후에 새 구성으로 데이터베이스가 다시 시작되는 것을 볼 수 있습니다. 다시 시작되었는지 확인해 보겠습니다. 너무 빨리 다시 시작되었네요. 보시 다시피 16초 전에 다시 시작되었습니다. UI에서 확인하기에는 너무 빨랐습니다. 이제 대시보드를 새로고침하면 API 키를 입력하라는 메시지가 나타납니다. ' Top Secret'이라는 이름의 API 키를 입력하면 됩니다. 데이터베이스에 로그인한 다음 TLS 인증서를 구성해 보겠습니다. API 키를 구성하는 것과 같은 방식으로 인증서와 인증서 키가 저장된 시크릿을 참조하여 TLS 인증서를 구성할 수 있습니다. 여기서는 인증서를 직접 입력하는 것이 아니라 시크릿을 참조하기만 하면 됩니다. 먼저 시크릿을 생성해 보겠습니다. 이 명령어를 사용하면 ' quarantine s test'라는 시크릿이 생성됩니다. 시크릿에는 TLS 인증서가 포함된 'CT' 필드와 인증서 키가 포함된 'key' 필드, 이렇게 두 개의 필드가 있습니다. 파일 시스템 도구를 사용하여 큐번 시크릿을 생성하는 다른 방법도 여러 가지가 있습니다. 이제 시크릿의 내용을 살펴보겠습니다. 여기에서 'quarantine s test' 시크릿 의 실제 Yama 사양을 볼 수 있으며, TLS CRT와 ts라는 두 필드를 확인할 수 있습니다. 각각의 인증 키와 함께 키를 사용하므로, 이 정보를 quent UI에 입력하여 비밀 키를 가져오고 TLS를 구성합니다. 인증서와 키 모두에 대한 비밀 키 이름은 TLS 테스트에서 SC이며, 그러면 인증서가 ts에 저장됩니다. CRT 필드와 키는 다시 TLs dokey에 저장됩니다. 모든 변경 사항을 저장하면 쿼드런트 데이터베이스가 몇 초 안에 새 구성으로 다시 시작됩니다. 이제 종료되는 것을 볼 수 있으며 새 구성의 새 컨테이너가 생성되고 몇 초 후에 실행됩니다. 이제 상태 검사가 완료될 때까지 기다리면 됩니다. 완료되었습니다. 이제 페이지를 새로 고침하면 잘못된 응답이 표시됩니다. 대시 보드에 접근하려면 HTTPS를 사용해야 하고, 링크도 변경되었기 때문입니다. 이제 브라우저에서 인증서 경고가 표시됩니다. 이는 브라우저에서 허용하는 CA에서 생성되지 않은 자체 서명 인증서를 사용했기 때문입니다. 이는 데모 목적으로만 사용됩니다. 이제 다시 로그인할 수 있습니다. 참고로, API 키와 TLS를 구성했으므로 데이터베이스 에서 더 세분화된 JW 토큰을 생성할 수도 있습니다. 이를 보여주기 위해 데이터를 생성해 보겠습니다. 빠른 시작으로 이동하여 ' star'라는 컬렉션을 하나 생성해 보겠습니다. 샤드가 여러 개 있는데, 그중 하나가 'te'라고 되어 있습니다. 제가 설정한 관리자 키로 모든 컬렉션에 접근할 수 있는 것을 확인할 수 있습니다. 이제 UI의 액세스 토큰 섹션으로 이동하여 사용자에게 전체 액세스 권한을 부여하거나 특정 컬렉션에만 접근 권한을 부여하는 등 더욱 세분화된 토큰을 생성할 수 있습니다. 예를 들어, ' 스타 차트' 컬렉션을 선택하고 접근 권한을 허용해 보겠습니다. 또한, 권한 있는 작업도 허용하고 저장을 클릭하면 JWT 토큰에 어떤 내용이 구성되었는지 확인할 수 있습니다. 생성된 토큰을 복사해서 관리자로 로그인한 상태로 컬렉션 목록으로 돌아가면, 이 JWT 토큰으로 로그인했을 때 ' 스타 샤드'에만 접근 권한이 있고 'te' 컬렉션에는 접근할 수 없는 것을 볼 수 있습니다. 또한, 새 샤드를 생성할 권한도 없습니다. 이 외에도 페이 로드 필터, 읽기 전용 토큰, 세분화된 액세스 제어 시스템 등 다양한 옵션을 설정할 수 있습니다. 이렇게 저희는 하이브리드 환경을 위한 로드 밸런서를 만들었습니다. 클라우드 데이터베이스 클러스터에서 로드 밸런싱을 구성하여 내부 접근을 제한하고, 예를 들어 관리자 API 키를 생성하여 구성 의 비밀 키를 통해 참조하는 방법을 살펴보았습니다. 또한 데이터베이스에 TLS 인증서를 구성하고 JWT 토큰을 사용하여 세분화된 접근 제어를 지원하는 방법도 알아보았습니다. 감사합니다.
