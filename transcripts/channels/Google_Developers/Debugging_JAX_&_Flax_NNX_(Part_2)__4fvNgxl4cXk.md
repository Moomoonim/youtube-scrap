JAX 도구가 충분하지 않거나, PDB의 익숙함을 원한다면 어떻게 해야 할까요? JAX는 탈출구를 제공합니다. ` jax.disable_jit`는 JAX에게 PyTorch처럼 코드를 즉시 실행하도록 지시합니다 . JIT 비활성화 블록 내부에서는 일반 print 문과 PDB set_trace 호출이 예상대로 정확하게 작동합니다. 또한 VS Code 디버거와 같은 IDE 디버거를 사용할 수도 있습니다. JIT를 비활성화하는 방법은 세 가지가 있습니다. 컨텍스트 관리자를 사용하거나, 전역적으로 또는 환경 변수를 사용하여 설정할 수 있습니다. 하지만 주의하세요. 이렇게 하면 JIT 최적화가 비활성화되므로 코드 실행 속도가 훨씬 느려집니다. 강력한 디버깅 도구이지만, 성능 향상을 위해 일시적으로만 사용하고 사용 후에는 반드시 제거하세요. 이 코드 예제는 with 블록 내에서 PDB가 어떻게 효과적으로 작동하는지 보여줍니다 . jax.disable_jit을 사용하더라도 변환 함수를 얼마나 깊이 있게 다룰 수 있는지에는 몇 가지 제한이 있습니다. jax.vmap이나 jax.scan과 같은 변환을 사용하는 경우 벡터화된 스캔 실행까지 완전히 진행할 수는 없습니다. 하지만 NNX와 같은 도구를 사용하여 중간 단계를 캡처할 수는 있습니다 . 복잡한 JIT 컴파일 함수 내에서 '숫자가 아님' 또는 'NaN' 값이 발생하는 원인을 추적하는 것은 흔히 발생하는 골칫거리입니다. JAX는 jax_debug_nans라는 유용한 플래그를 제공합니다 . jax.config.update 또는 환경 변수를 통해 활성화할 수 있습니다. jax_debug_nans가 활성화되면 JAX는 jit 내부 작업의 출력을 감시합니다. NaN 값을 발견하면 해당 코드 부분을 단계별로 자동으로 다시 실행하여 NaN을 발생시킨 정확한 기본 연산을 찾은 다음, 해당 연산을 가리키는 오류를 발생시킵니다 . 이렇게 하면 수동 검색 시간을 크게 줄일 수 있습니다 . 하지만 이로 인해 오버헤드가 발생하여 속도가 느려진다는 점에 유의하십시오. NaN 값이 의심될 때 사용하고, 의심이 사라지면 기능을 끄세요 . 이제 Flax와 NNX가 제공하는 도구 중 하나인 NNX.display를 살펴보겠습니다. Flax와 NNX는 모델을 더 쉽게 이해할 수 있도록 하는 것을 목표로 하며, 핵심 도구는 NNX.display입니다. NNX 모델, 레이어 또는 옵티마이저에 사용하세요 . 이 기능은 매개변수와 상태 변수를 포함하여 객체의 구조에 대한 스냅샷을 제공하며, 해당 매개변수, 상태 변수의 이름, 유형, 형태 및 현재 값을 보여줍니다. 노트북에서 작업하면 멋진 인터랙티브 트리 구조를 볼 수 있습니다. 이는 모델 아키텍처를 검증하거나 옵티마이저 상태를 검사하는 데 매우 유용합니다. NNX 모듈이 이제 네이티브 JAX PyTree이므로 NNX.display는 기본적으로 해당 PyTree 구조를 풍부하고 탐색 가능한 형태로 보여줍니다 . 단순한 출력물이 아니라, JAX 변환이 작동하는 기본 데이터 구조를 보여주는 것입니다. 자, 이제 NNX가 제공하는 또 다른 도구인 NNX.sow를 살펴보겠습니다. 이는 Flax의 NNX 모듈 시스템인 NNX.sow 내의 또 다른 유용한 기능입니다. 그렇다면 module.sow는 정확히 무엇일까요? 본질적으로 이는 Flax NNX 모듈에 내장된 메서드로 , 모델이 순방향 계산을 실행하는 동안 계산되는 중간 값을 캡처하고 저장할 수 있도록 특별히 설계되었습니다 . 특정 레이어의 출력 이나 기타 내부 계산과 같은 것들을 생각해 보세요. 이것이 왜 유용한가요? 네, 이는 이러한 내부 계산을 추적하는 과정을 상당히 간소화합니다. 모델의 전체 호출 스택을 통해 딕셔너리나 다른 데이터 구조를 수동으로 생성하고 전달하여 중간 어딘가에서 값을 가져오는 대신 , 이 방법을 사용하면 값이 생성된 바로 그 위치에 값을 직접 전달할 수 있습니다. 이 덕분에 여러 작업에 매우 편리하게 사용할 수 있습니다 . 모델의 동작을 디버깅하려면 내부 상태를 검사하고, 중간 레이어의 출력을 시각화하여 모델이 무엇을 학습하는지 이해 하거나, 이러한 내부 활성화 값에 의존하는 더욱 복잡한 사용자 지정 손실 함수를 구현할 수도 있습니다 . 자, 이제 실제로 어떻게 사용하는지 살펴보겠습니다 . 기본 서명에는 몇 가지 핵심 인수가 포함됩니다. 첫째, 변수 유형입니다. 이는 저장하는 값을 어떻게 분류할지 알려주는 것으로 , 종종 x.intermediate와 같은 것을 사용합니다. 이렇게 입력하는 방식은 나중에 저장된 값 중에서 특정 유형을 필터링하거나 검색할 때 도움이 됩니다 . 둘째, 이름입니다. 이는 단순히 모듈 인스턴스에 값이 저장될 속성 이름을 정의하는 문자열입니다 . 셋째, 가치입니다. 이것은 저장하려는 실제 데이터이며, 일반적으로 Jax 배열이지만 다른 Python 객체일 수도 있습니다. 또한 선택적 인수로 reduce 함수와 knit 함수가 있으며, 이를 통해 동일한 이름의 값을 여러 번 호출할 때 더욱 사용자 정의된 동작을 구현할 수 있습니다. 좋습니다, 그럼 간단한 예시를 통해 실제로 어떻게 작동하는지 살펴보겠습니다. 여기에는 단일 밀집 레이어를 가진 기본적이고 간단한 모델이 있습니다 . dunder 호출 메서드 내부에서, 밀집 레이어를 적용한 후 self.so를 사용합니다. 우리는 유형을 NNX 중간으로 지정하고, 이름을 밀집 출력으로 지정하고, 레이어의 출력 X를 값으로 전달합니다. 모델을 인스턴스화하고 입력값을 넣어 실행한 후, 어떻게 그 값을 다시 얻을 수 있나요? 앞서 언급했듯이, 해당 값은 우리가 제공한 이름을 사용하여 모델 인스턴스 자체의 속성으로 저장됩니다. 그래서 우리는 우리가 붙인 이름인 model.dense_output을 통해 직접 접근할 수 있습니다 . 중요한 것은 실제 데이터가 이 속성의 점 값 속성 내에 저장된다는 점입니다 . 즉, model.dense_output.value는 저장된 중간 값을 제공한다는 의미입니다. 예시의 출력 결과는 배열을 포함하는 튜플임을 알 수 있습니다. 이는 기본 동작을 강조합니다. 같은 순방향 전달 과정에서 동일한 이름을 사용하여 여러 번 호출하더라도 값이 덮어쓰여지지 않습니다. 대신, 각 새 값을 dot 값에 저장된 튜플에 추가합니다. 이 방식은 유연 하지만, 루프 내부나 현재 레이어처럼 자주 바느질하는 경우 이 튜플이 커져서 상당한 메모리를 소비할 수 있다는 점에 유의하세요. 추가가 바람직하지 않은 상황을 위해 고급 사용자 지정 옵션을 제공합니다. 초기화 함수 또는 축소 함수를 제공할 수 있으며, 이를 통해 동일한 이름으로 묶인 여러 값을 결합하는 방법에 대한 사용자 지정 로직을 정의할 수 있습니다. 예를 들어, 합계를 내거나 평균을 내거나 다른 축소 작업을 수행하여 튜플이 무한히 커지는 것을 방지할 수 있습니다. 마지막으로, 변수 유형 으로 식별되는 이러한 변수들은 NNX의 상태 관리 유틸리티와 잘 연동된다는 점을 알아두는 것이 중요합니다. NNX split, NNX state, NNX pop과 같은 함수를 사용하면 이러한 중간 값이나 매개변수 또는 배치 통계와 같은 다른 변수 유형을 전체 모듈 상태에서 쉽게 분리, 확인 또는 제거할 수 있으므로 세밀한 제어가 가능합니다. 결론적으로, JAX와 Flax NNX를 위한 세 가지 핵심 디버깅 기법을 살펴보았습니다. 첫째, 표준 파이썬 디버깅 도구를 사용하지 않고 문제를 해결하기 위한 방법으로 jax.disable_jit을 언제 어떻게 사용해야 하는지 알아야 합니다. 둘째, jax.debug_nans 플래그를 활용하여 NaN 값을 자동으로 감지하고 추적합니다. 마지막으로 NNX 디스플레이를 통해 NNX 모델의 구조와 상태를 이해해 보겠습니다 . 이 코딩 연습 문제와 빠른 참조 문서 및 슬라이드를 통해 JAX 및 전체 JAX AI 스택에 대해 자세히 알아볼 수 있습니다.
