## 스크립트

고성능 머신러닝 시스템을 구축하는 데 있어 가장 큰 과제 중 하나는 데이터 요구량이 많은 이러한 가속기에 지속적으로 데이터를 공급하는 것입니다. 우리는 모두 그러한 가속기가 얼마나 강력 하고 엄청난 양의 연산을 수행할 수 있는지 알고 있습니다 . 하지만 데이터 세트를 지속적으로 빠르고 효율적으로 제공할 수 없다면, 그러한 가속기는 그냥 놀고만 있을 것입니다. 오늘은 머신러닝 학습을 위한 데이터를 빠르게 읽고 처리하도록 설계된 파이썬 라이브러리인 Grain에 대해 이야기해 보겠습니다. 이 도구는 주로 Jack에 최적화되어 있지만, 유연한 설계 덕분에 다른 머신 러닝 프레임워크와도 함께 사용할 수 있습니다. Grain은 데이터 처리 단계를 정의하고 연결하는 선언적 방식을 제공하여 복잡한 입력 파이프라인 생성을 간소화하고, 모든 것을 작동시키는 데 필요한 복잡한 병렬 컴퓨팅 로직을 추상화합니다 . 곡물이 돋보이는 데에는 몇 가지 핵심 원칙과 특징이 있습니다 . 첫째는 데이터 파이프라인 내에서 임의의 파이썬 변환을 구현할 수 있는 유연성으로, 이를 통해 고도로 맞춤화된 데이터 준비가 가능하다는 점입니다. 둘째, 잭슨빌 생태계의 많은 부분과 마찬가지로, 이는 결정론적입니다. 그레인 설계는 동일한 데이터 파이프라인을 여러 번 실행하더라도 항상 동일한 출력을 생성하도록 보장합니다. 이는 재현성, 디버깅 및 일관된 실험 결과를 위해 매우 중요합니다. 세 번째이자 제가 개인적으로 가장 좋아하는 점은 선제 공격에 강하다는 것입니다. Grain은 간편한 체크포인트 설정 과 중단 후 데이터 처리의 원활한 재개를 위해 설계되었으므로 , 선점형 인스턴스를 사용하는 클라우드 환경에서 장기간 실행되는 학습 작업에 적합합니다. 제가 마지막으로 확인했을 때, 선점형 인스턴스를 사용하면 여전히 큰 할인이 적용되었습니다. 때때로 스팟 인스턴스라고도 합니다. 따라서 이는 동일한 비용으로 더 나은 성능을 얻을 수 있는 좋은 방법이 될 수 있습니다 . 이제 그레인에 대해 더 자세히 알아보기 전에, 알아두면 좋은 점은 그레인이 기본적으로 GPU나 TPU를 직접 활용하는 대신 CPU에서 데이터 처리를 수행한다는 것입니다 . 이 기본 설정은 CPU에서 데이터를 효율적으로 준비한 다음 가속기로 전송할 수 있음을 의미합니다. 하지만 모든 작업 부하가 이러한 특정 설정에 적합한 것은 아닙니다. 물론 설정을 변경할 수도 있지만, 이것이 기본 설정이라는 것을 알아두면 좋습니다. Grain은 데이터 처리 파이프라인을 정의하는 두 가지 주요 방식을 사용합니다. 데이터 로더 및 데이터 세트 클래스. 이번 영상에서는 데이터 로더 API만 살펴보고, 다음 영상에서는 체크포인트 기능과 함께 데이터 세트 API를 살펴보겠습니다. 데이터 로더는 원시 출력을 읽는 데이터 소스, 데이터 순서를 정의하는 샘플러, 그리고 사용자가 선택할 수 있는 일련의 변환이라는 세 가지 추상화를 통합하는 고수준 API입니다 . 데이터 로더는 입력 데이터 처리를 병렬화하기 위해 하위 프로세스를 시작하고 관리합니다. 여기에는 샤딩 및 셔플링과 같은 작업이 포함되며, 이러한 프로세스에서 출력 요소를 수집하고 모델이 사용할 최종 배치 데이터를 제공합니다. 데이터 로더가 사용하는 세 가지 추상화 개념 각각에 대해 간략하게 설명하여 사용 예시를 이해하는 데 도움을 드리겠습니다. 먼저 데이터 소스 클래스부터 살펴보겠습니다. Grain에서 지원하는 주요 내장 데이터 소스는 경로 또는 파일 명령 객체의 단일 목록을 허용하는 배열 레코드, PI arrow에서 지원하는 모든 파일 시스템 내의 경로를 허용하는 paret, 그리고 많은 일반적인 데이터 세트를 쉽게 로드할 수 있는 방법을 제공하는 TensorFlow 데이터 세트(TFDS)입니다. 마지막으로, 사용자 지정 데이터 소스를 생성하는 옵션도 있습니다. 하지만 이 길은 마음이 약한 사람에게는 적합하지 않습니다. 데이터 소스가 직렬화되어 하위 프로세스로 전송되므로 데이터가 선택 가능한 형식인지 확인해야 합니다 . 또한, 사용 후에는 열려 있는 파일 핸들이 닫히도록 해야 합니다. 개인적으로는 파일 시스템이나 데이터 프로토콜에 정말 관심이 있는 경우가 아니라면 내장 옵션 중 하나를 사용하는 것이 좋다고 생각합니다. 이러한 옵션에 대해 더 자세히 알고 싶으시면 아래 설명란에 링크를 넣어두었습니다. 네, 데이터 소스가 있습니다. 이제 다음에 읽을 레코드를 결정하는 샘플러가 필요합니다 . 간단해 보일지 몰라도, 요구사항이 높아질수록 이 작업의 복잡성은 점점 더 커 집니다. 이러한 고려 사항에는 방대한 데이터 세트 전체에 걸쳐 레코드를 섞는 것, 여러 에포크에 걸쳐 데이터 세트를 반복하는 것, 그리고 여러 머신에 걸쳐 샤딩하는 것 등이 포함됩니다. 다행히 Grain은 이러한 작업의 대부분을 처리하는 데 사용할 수 있는 인덱스 샘플러 클래스를 제공합니다 . 그리고 우리는 원하는 섞기, 반복, 분할 방식을 간단하게 명시적으로 지정할 수 있습니다. 따라서 대규모 머신러닝에 있어서는 이 기능이 매우 유용합니다. 개인적으로 저는 여러 대의 머신에 걸쳐 일관되고 재현 가능한 샤딩 및 셔플링을 구현하는 책임을 맡고 싶지 않습니다 . 마지막으로, 변화에 대해 이야기해 볼 시간입니다. 아마도 지도, 플랫맵, 필터 및 일괄 변환 기능에 가장 관심이 많을 것입니다. 맵 변환은 표준 파이썬 맵이 하는 것과 정확히 같은 작업을 수행합니다. 이 기능은 사용자 지정 함수를 데이터 세트의 모든 요소에 매핑합니다 . 반면, 플랫 맵은 데이터 세트의 개별 요소를 더 작은 조각으로 나누고 싶을 때 사용합니다. 예를 들어, 쌍으로 이루어진 리스트가 있고 각 쌍을 서로 다른 두 요소로 만들고 싶 거나, 딕셔너리 리스트가 있고 해당 딕셔너리 의 모든 값만 있는 리스트로 변환해야 하는 경우 , flatmap을 사용하여 각 요소를 모델이 사용할 수 있는 토플 데이터 요소로 생성할 수 있습니다. 필터는 표준 파이썬 필터와 마찬가지로 데이터 세트에서 요소를 유지할지 여부에 따라 true 또는 false를 반환해야 합니다 . 마지막으로, 그다지 놀랍지 않겠지만, batch 명령어를 사용하면 데이터 세트를 배치로 만들어 모델이 보기 좋게 덩어리째 사용할 수 있도록 할 수 있습니다. 데이터 소스, 변환 및 샘플러 설정이 완료되면 이 모든 것을 그레인에 전달하는 것은 간단합니다. 그런 다음 데이터 로더가 모든 데이터를 하나로 모아줍니다 . 이것이 바로 데이터 로더 API의 핵심입니다. 약속드린 대로, 다음 영상에서 해당 데이터 세트 API에 대해 자세히 살펴보겠습니다. 비록 하위 레벨 API일지라도, 당신은 오히려 그것이 더 마음에 들 수도 있습니다. 제 생각에는 관리해야 할 요소가 더 적고, 데이터 로더보다 사용하기가 훨씬 직관적일 것 같습니다. 그러니 꼭 확인하셔서 직접 비교해 보세요 . 그렇다면 여러분이 가장 좋아하는 데이터 로딩 및 처리 라이브러리는 무엇인가요? 아래 댓글에 여러분의 생각을 공유해 주세요. 이 영상이 마음에 드셨다면 좋아요 버튼을 눌러 알려주세요. 오늘은 여기까지입니다 . 다음 영상에서 뵙겠습니다.
