## 스크립트

Hello and welcome to the final video of&nbsp; our inaugural USD for Developers series.&nbsp;&nbsp; We've saved the best for last - Hydra, a&nbsp; generalized pipeline for custom renderers,&nbsp;&nbsp; that can now extend to dynamic&nbsp; data science pipelines. Originally created to bridge input&nbsp; scene graphs and output renderers,&nbsp;&nbsp; Hydra has since evolved into a versatile&nbsp; framework for custom pipelining of composed data. While data for virtual worlds is modeled using&nbsp; USD, Hydra provides interfaces for implementing&nbsp;&nbsp; the business logic to process that data as a&nbsp; customizable chain of runtime scene indexes.&nbsp; With classical Hydra 1.0, scene delegates are&nbsp; responsible for populating a flattened render&nbsp;&nbsp; index which is then used by render delegates.&nbsp; This completely decouples USD from renderers,&nbsp;&nbsp; allowing any scene graph that can answer&nbsp; queries served by scene delegates to&nbsp;&nbsp; be used. The USD distribution on GitHub&nbsp; comes with the USD imaging scene delegate,&nbsp;&nbsp; which has been optimized for cached&nbsp; animation playback and load times. The render delegate abstraction enables&nbsp; the render index data from USD imaging&nbsp;&nbsp; to be shared between different renderers,&nbsp; whether they be rasterized or path-traced.&nbsp; At NVIDIA, we’ve focused on optimizing Hydra&nbsp; pipelines for large-scale scene updates such as&nbsp;&nbsp; rigid body simulations. One of the key advantages&nbsp; of Hydra is that it’s not tightly coupled to any&nbsp;&nbsp; single runtime data layout, which allows us&nbsp; to compile the composed USD into a deeply&nbsp;&nbsp; vectorized data layout that we call Fabric. Fabric has been formalized into its own scene&nbsp;&nbsp; delegate, which can service all scene graph&nbsp; queries. This means that the extensibility and&nbsp;&nbsp; generality of Hydra can be used to power a fully&nbsp; Fabric runtime for Omniverse, enabling behaviors&nbsp;&nbsp; driven by the data models in USD schemas. Hydra 2.0 offers even more flexibility for&nbsp;&nbsp; post-composition runtimes. Rather than having&nbsp; scene delegates populate a single render index&nbsp;&nbsp; for render delegates to consume, chains of scene&nbsp; indexes can now be processed procedurally through&nbsp;&nbsp; multiple pipeline steps on the way to the&nbsp; renderer or other runtimes. This allows&nbsp;&nbsp; for more complex and customizable workflows,&nbsp; making it easier for artists and developers&nbsp;&nbsp; to iterate on and optimize their pipelines.
