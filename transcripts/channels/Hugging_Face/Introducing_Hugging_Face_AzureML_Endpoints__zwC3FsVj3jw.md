## 스크립트

안녕하세요 여러분, 저는 Target Faith의 기술 리더인 Philip입니다. 오늘은 Hiding Face Transformers를 Azure에 배포하는 방법을 보여드리겠습니다. 먼저 Azure 파트너 페이지에서 Hiding Face Azure ML 엔드포인트를 검색해야 합니다. "Hugging"으로 검색하면 마켓플레이스 섹션에서 Hiding Face Azure ML 엔드포인트를 찾을 수 있습니다. 그러면 마켓플레이스 오퍼링 페이지로 이동합니다. "만들기"를 클릭하면 Azure에 Hiding Face 관리형 애플리케이션을 리소스 그룹으로 생성할 수 있습니다. 저는 "Test 리소스 그룹"을 선택하겠습니다. 여기에서 관리형 앱을 배포할 리소스 그룹을 선택할 수 있습니다. 지역은 미국 동부 지역을 선택하겠습니다. 이름은 Hiding Face Video로, 애플리케이션 이름은 Hiding Face Video로 지정합니다. 관리형 리소스 그룹은 중요하지 않습니다. 나중에 모든 관리형 리소스가 저장되는 위치입니다. 필요에 따라 변경할 수 있지만 그대로 두어도 됩니다. 다음 단계는 텍스트 입력입니다. 지금은 텍스트가 필요하지 않습니다. 마지막으로 " 검토"를 클릭하고 "만들기"를 클릭하면 됩니다. 입력값을 검증한 다음 조건을 확인해야 합니다. 기본적으로 이는 사용자가 하이킹 2단계 배포 또는 리소스 생성을 허용해야 한다는 의미입니다. 이제 만들기를 클릭하면 관리형 애플리케이션과 몇 가지 기본 Azure 리소스가 생성됩니다. 배포에는 약 1분이 소요됩니다. 배포가 완료되면 관리형 애플리케이션 배포가 완료됩니다. 이제 HTML 엔드포인트를 생성할 수 있습니다. 리소스로 이동하면 하이킹 단계 관리형 애플리케이션으로 이동합니다. 왼쪽의 리소스 미리 보기에서 하이킹 단계 엔드포인트를 찾을 수 있습니다. 이곳은 모든 하이킹 단계 엔드포인트를 관리하는 중앙 위치입니다. 생성된 모든 엔드포인트를 한눈에 볼 수 있으며, 추가, 삭제 또는 편집할 수 있습니다. 관리형 애플리케이션을 생성했으므로 아직 사용 가능한 엔드포인트가 없으므로 하나 추가하겠습니다. 새 하이킹 단계 엔드포인트를 생성하려면 하이킹 페이스 모델 ID와 모델 인스턴스 시간만 제공하면 됩니다. 하이킹 단계 허브로 이동하여 모델을 선택합니다. 이 경우 Digital Bird Base Uncased Fine-Tune 모델을 사용하겠습니다. 텍스트 분류에 최적화된 분산 모델인 SSD2를 사용하기 위해 Azure 리소스로 돌아가서 High Infest 모델 ID를 붙여넣습니다. 그런 다음 컴퓨팅 인스턴스를 선택할 수 있습니다. 여기서 인스턴스에 사용 가능한 SRML 컴퓨팅 용량이 있는지 확인해야 합니다. 드롭다운 메뉴에는 사용 가능한 모든 Azure ML 인스턴스가 표시되지만, 용량이 충분한지 여부는 UI에서 확인하지 않습니다. 예를 들어 T4 인스턴스를 배포하려면 용량이 충분한지 확인해야 합니다. 용량이 부족하면 생성이 실패합니다. 하지만 이 경우에는 GPU가 필요하지 않으므로 CPU에 최적화된 F2 시리즈 인스턴스를 선택하겠습니다. 검토 및 제출을 클릭하고 모델 ID 와 인스턴스 유형이 올바른지 확인합니다. 그런 다음 제출을 클릭하면 리소스가 생성됩니다. 오른쪽 상단에 리소스 생성 중이라는 메시지가 표시됩니다. 이는 백엔드에서 제공된 모든 정보를 검증하고 있다는 의미입니다. 즉, 제공된 모델 ID가 High Infest Hub에서 유효한 모델인지 확인하고, 용량이 충분한지 확인합니다. 용량이 부족하면 생성이 실패합니다. F2 인스턴스 시리즈의 용량 부족으로 오류가 발생할 수 있습니다. 여기서 오류가 발생하면 세부 정보로 이동하여 화살표를 확인하면 용량 부족 메시지가 표시될 것입니다. 몇 초 후 녹색 체크박스가 나타나고, 엔드포인트 생성 상태와 함께 첫 번째 엔드포인트가 표시될 것입니다. Hiking Face SRML 엔드포인트의 멋진 기능 중 하나는 모델에 대한 작업을 자동으로 파생한다는 것입니다. 모델 ID만 제공하고 사용할 작업을 지정하지 않았는데도 모델 정보에서 작업이 자동으로 파생됩니다. 따라서 모델이 텍스트 분류 모델이라고 지정할 필요가 없었습니다. 이 작업은 자동으로 수행되었습니다. 제가 말씀드리는 동안 유효성 검사 또는 사용자 지정 리소스가 성공적으로 생성되었고 대시 보드가 ​​현재 로드 중입니다. 좋습니다. 새 엔드포인트가 생성 중 상태로 표시되고 있으며, 5~10분 이내에 엔드포인트가 생성될 것입니다. 배포도 생성되고 나면 다시 돌아와서 엔드포인트 배포가 성공했음을 보여드리겠습니다. 이제 관리형 애플리케이션에서 작업을 파생한 것을 확인할 수 있으며, 애플리케이션에 직접 복사하여 붙여넣을 수 있는 엔드포인트 URI도 볼 수 있습니다. 마지막으로 인스턴스도 확인할 수 있습니다. 이제 엔드포인트를 테스트하는 데 사용할 Azure 리소스 링크를 복사하여 브라우저에 붙여넣으면 Azure Machine Learning Studio에서 생성된 엔드포인트로 이동합니다. 여기에서 테스트를 클릭하여 엔드포인트를 테스트할 수 있습니다. 이 엔드포인트는 Hiking Phase 추론 API 와 동일한 API 스키마를 사용하므로 입력 키와 " 이 모델은 Azure에서 실행됩니다"라는 문장이 포함된 JSON을 제공해야 합니다. 이제 테스트를 클릭하면 모델에서 긍정적인 결과를 얻을 수 있습니다. 또한 애플리케이션에 통합하려면 HTML에서 Python, C#, R용 코드 스니펫을 제공하므로 애플리케이션 에 직접 복사하여 붙여넣을 수 있습니다. 보안 지침에 따라 키를 다시 생성할 수도 있습니다. 이제 관리형 애플리케이션 개요로 돌아가서 Hiking Phase 애플리케이션에 엔드포인트를 더 생성하거나 엔드포인트를 삭제할 수 있습니다. Hiking Face SRML 엔드포인트에 대한 질문이 있으면 언제든지 이메일로 문의해 주세요. 관리형 애플리케이션을 배포하면 지원 이메일 주소가 제공됩니다. 또는 다른 방법으로도 문의할 수 있습니다. 이 비디오의 목적은 사용자 정의 리소스를 생성하는 방법을 보여드리는 것이었으므로, 저희 포럼의 전용 섹션에서 이 내용을 다룹니다. 또한, 엔드포인트를 안전한 리소스로 삭제하여 사용자 정의 리소스를 삭제해도 잠시 후 다시 로드되도록 조치했습니다. 마지막으로 백그라운드에서 모든 인프라를 정리하겠습니다. 감사합니다. 안녕히 계세요.
