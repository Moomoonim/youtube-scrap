## 스크립트

[음악] 외국어 [음악] USD 개발자 시리즈 세 번째 영상에 오신 것을 환영합니다. 오늘은 오픈 USD의 두 번째 핵심 요소인 사용자 정의 스키마에 대해 알아보겠습니다. 사용자 정의 스키마는 USD 개발의 기본 요소이자, 데이터를 확장하여 더욱 복잡 하고 정교한 가상 세계를 구현할 수 있도록 하는 강력한 도구입니다. 이전 영상에서는 희소한 비파괴 장면 구성을 위한 합성(composition)에 대해 배웠습니다. 사용자 정의 스키마는 이러한 데이터 모델을 더욱 확장하여 시스템 동작을 구현할 수 있도록 합니다. 장면 합성을 넘어, 이전 영상 에서 보았던 화분 예시로 돌아가 보겠습니다. 이 USDA 코드 조각은 플라워봇 에이스(Flowerbot Ace) 지오메트리 메시를 나타내며, 메시의 점들이 정의되어 있습니다. 이 정보는 USD 지오메트리 라이브러리의 메시 스키마에 형식화되어 있습니다. 각 스키마는 USD 스키마 레지스트리에 프리미티브(Prim) 정의를 채우는데, 이 레지스트리에는 USD의 모든 스키마에 대한 이름, 유형 및 대체 값이 포함되어 있습니다. 스테이지는 프리미티브( Primitive)의 계층 구조로 이루어져 있으며, 프리미티브는 장면 그래프에서 개별 노드를 나타내는 데이터 컨테이너입니다. 각 프리미티브는 속성과 관계를 포함한 속성으로 구성되며, 이러한 속성은 스키마에 형식화될 수 있습니다. 예를 들어, 메시 스키마는 메시의 토폴로지와 점들을 정의합니다. 특정 데이터 모델을 통해 프리미티브에 의미를 부여하여 콘텐츠에 대한 쿼리에 응답할 수 있도록 합니다. 스키마는 표준화된 스키마를 통해 프리미티브에 유형화된 구조 정의를 부여합니다. 모든 UST 호환 런타임은 원시 데이터를 의미 있는 방식으로 해석할 수 있습니다. USDA에서 데이터 모델링과 런타임 동작을 구분하는 것이 중요합니다. 스키마는 프리미티브의 데이터 구조를 정의하지만, 런타임이 해당 데이터를 기능적 목적에 맞게 해석하는 것은 런타임의 몫입니다. 즉, 스키마는 데이터 구조를 규정하는 계약을 제공 하지만 런타임이 해당 데이터를 어떻게 처리하는지는 규정하지 않습니다. USDA는 현재 ISA 또는 화분 예제에서 보았듯이 메쉬와 같은 유형 스키마를 포함하여 다양한 유형의 스키마를 지원합니다. ISA 스키마는 인스턴스화 가능 여부에 따라 추상 스키마 또는 구체 스키마로 구분됩니다. 추상 스키마는 경계가 있는 스키마와 같이 관련 구체 스키마 집합의 기반 역할을 하며 인스턴스화할 수 없습니다. 반면 구체 스키마는 메쉬와 같이 장면 계층 구조에서 인스턴스화할 수 있습니다. 이러한 스키마는 객체 지향 프로그래밍의 클래스 상속과 유사합니다. 반면에 API 스키마는 클래스 구성과 유사합니다. 이미 타입이 지정된 Prim에 추가 속성을 부여하는 것을 예로 들어 보겠습니다. 물리 스키마는 API 스키마의 좋은 실제 사례입니다. 다음은 물리 시뮬레이션을 위한 강체 API 스키마입니다. 부엌 세트에 있는 화분에 강체 API를 적용하면, 해당 Prim의 API 스키마 목록에 추가 값만 기록하는 것입니다. 다시 말해, 희소하고 직관적이지 않은 오버라이드 방식을 통해 화분에 강체 API에 정의된 모든 속성을 부여할 수 있으며, 이러한 속성은 다른 Prim의 속성처럼 쿼리하고 편집할 수 있습니다. 이 예에서 물리 스키마는 강체의 실시간 시뮬레이션을 위해 PhysX 런타임에 필요한 정보를 제공하는 데 사용됩니다. USD 데이터 모델은 데이터 교환의 기반을 제공하며, RTX 렌더러는 동일한 정보를 사용하여 시뮬레이션을 시각화할 수 있습니다. 중요한 점은 NVIDIA, Pixar, Apple 간의 USD 물리 스키마 협업에는 물리 엔진이나 렌더러가 포함되어 있지 않다는 것입니다. 대신, 이 스키마는 누구나 호환되는 물리 엔진과 렌더러를 구현할 수 있는 강체에 대한 표준 데이터 모델 역할을 합니다. 이는 데이터 모델과 물리 엔진의 분리를 보여줍니다. 앞서 언급했듯이 데이터 모델링과 런타임 동작 간의 관계를 표준화하는 과정은 다섯 단계로 구성됩니다. 첫째, UST에서 사용자 정의 속성을 사용하여 새로운 스키마를 프로토타입으로 만들고 데이터 모델 과 런타임 동작이 안정될 때까지 반복적으로 개선합니다. 둘째, 스키마 정의를 공식화하고 타입 스키마 또는 API 스키마로 표현하는 방식 과 기타 고려 사항 간의 장단점을 평가합니다. 셋째, 스키마는 데이터 모델을 시연하고 동작 구현에 대한 자동화된 테스트를 시작하는 데 사용할 수 있는 표준 자산과 함께 내부 검토를 거칩니다. 넷째, 후보 스키마는 백서로 발표되어 다양한 산업 분야에서 광범위한 검토 과정을 거치며 합의에 도달할 때까지 반복적으로 개선됩니다. 마지막으로, 새로운 스키마는 모든 USD 호환 구현에서 지원될 수 있는 표준으로 채택됩니다. 보시다시피 USD를 사용한 사용자 정의 스키마는 더욱 복잡하고 정교한 가상 세계를 구현할 수 있는 무수한 가능성을 열어줍니다. UST 자체에는 지오메트리 및 셰이딩과 같은 핵심 스키마가 포함되어 있으며, 디지털 트윈 등을 위한 생태계를 더욱 확장하기 위해 새로운 스키마가 지속적으로 개발되고 있습니다. 이 영상이 사용자 정의 스키마를 이해하는 데 도움이 되었기를 바랍니다. 구독하시고 USD 개발자 시리즈의 나머지 영상도 기대해 주세요.
