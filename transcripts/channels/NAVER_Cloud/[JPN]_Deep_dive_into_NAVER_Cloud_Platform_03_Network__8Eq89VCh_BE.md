## 스크립트

[음악] 감사합니다 [음악] 안녕하세요, 네이버 클라우드입니다. 오늘은 네이버 클라우드 플랫폼의 네트워킹 제품들을 살펴보겠습니다. 먼저 VPC 서비스를 알아보겠습니다. VPC는 Virtual Private Cloud의 약자로, 클라우드 상에서 논리적으로 격리된 고객 맞춤형 네트워크 공간을 생성할 수 있도록 지원하는 서비스입니다. 현재 VPCR을 사용하여 생성할 수 있는 AP 대역은 10.0 0 0 8 170부터 0.16 0 0 12, 그리고 190부터 0.168 0 0 16까지입니다. 각 대역의 서브넷 마스크는 최소 28비트에서 최대 16비트까지 지원됩니다. 계정당 최대 3개의 VPC를 생성할 수 있으며, VPC 피어링 기능을 통해 서로 다른 VPC 간의 프라이빗 통신이 가능합니다. VPC 피어링은 단방향 통신이므로, 요청하는 VPC와 수락하는 VPC를 지정하여 두 네트워크를 연결합니다. VPC 피어링을 통해 다른 계정 에서 관리하는 VPC 간, 그리고 본인이 관리하는 VPC 간에도 프라이빗 통신을 설정할 수 있습니다. 다음으로 VPC의 핵심 구성 요소인 네트워크 액세스 제어 목록(ACL)에 대해 살펴보겠습니다. ACL은 VPC의 보안을 강화하는 중요한 요소이며, 서브넷에 적용되어 외부에서 서브넷에 접근할 때 작동합니다. ACL에서는 인바운드 및 아웃바운드 트래픽에 대한 허용 및 차단 규칙을 설정할 수 있으며, 규칙은 우선순위에 따라 처리되어 트래픽 허용 여부를 결정합니다. 또한, 네이버 클라우드 플랫폼은 VPC 수준의 보안 강화를 위해 ACG(액세스 제어 그룹)라는 기능을 제공합니다. ACG는 각 서버에 적용되며 서브넷 내 서버 간 통신 보안을 담당합니다. ACG는 허용 규칙만 지원하며, 모든 규칙은 트래픽 허용 여부를 결정하기 전에 평가됩니다. 이번에는 서브넷에 대해 살펴보겠습니다. 서브넷의 주소 범위는 VPC 생성 시 지정된 CIDR 형식으로 지정됩니다. 서브넷 생성 시 영역을 지정할 수 있으며, 동일한 영역에 여러 개의 서브넷을 생성할 수도 있습니다. 서브넷은 크게 외부 통신이 가능한 퍼블릭 서브넷과 내부 통신만 가능한 프라이빗 서브넷으로 나뉩니다. 퍼블릭 IP는 퍼블릭 서브넷의 서버에만 할당할 수 있습니다. 현재 최대 기본적으로 각 VPC에는 최대 200개의 서브넷을 생성할 수 있으며, 프라이빗 서브넷은 외부 통신이 불가능합니다. 하지만 외부 통신이 필요한 경우, NAT 게이트웨이를 통해 프라이빗 서브넷 내 서버의 외부 인터넷 통신을 활성화할 수 있습니다. NAT 게이트웨이를 생성한 후에는 루트 테이블에서 프라이빗 서브넷으로 연결되는 경로를 설정해야 합니다. 이 경로는 외부 통신을 위해 NAT 게이트웨이로 연결되어야 합니다. 다음으로 네트워킹 제품 의 대표적인 서비스 중 하나인 로드 밸런싱에 대해 살펴보겠습니다. 로드 밸런싱은 수신된 트래픽을 여러 서버로 분산하는 서비스로, 가용성을 높이고 시스템 사용률을 조정하는 역할을 합니다. 네이버 클라우드 플랫폼에서 로드 밸런싱을 생성할 때는 대상 그룹을 설정해야 합니다. 대상 그룹은 로드 밸런싱이 수신하는 트래픽을 실제로 처리할 서버 그룹을 의미합니다. 동일한 VPC 내의 서버로 대상 그룹을 생성할 수 있으며, 대상 그룹 A에 속한 서버는 대상 그룹 B에도 속할 수 있습니다. 하지만 대상 그룹 A는 여러 로드 밸런싱에 연결될 수 없습니다. 로드 밸런싱은 연결된 서버의 상태를 모니터링하기 위해 주기적으로 상태 점검을 수행합니다. 사용자는 상태 점검 주기를 5초에서 300초 사이로 설정할 수 있습니다. 사이클 설정 외에도 임계값을 설정할 수 있습니다. 정상 임계값과 실패 임계값을 설정할 수 있는데, 정상 임계값은 비정상 상태가 된 타겟이 서비스에 복귀하기 위해 필요한 성공적인 상태 확인 횟수를 나타냅니다. 실패 임계값은 정상 서버가 비정상 상태로 전환되어 로드 밸런싱 타겟에서 제외되기 위해 필요한 실패한 상태 확인 횟수를 나타냅니다. 로드 밸런싱 알고리즘은 기본적으로 라운드 로빈 방식을 사용합니다. 로드 밸런싱 알고리즘 변경, 스티키 세션 프록시, 프로토콜 설정 등은 로드 밸런서 생성 후 구성할 수 있습니다. 현재 네이버 클라우드 플랫폼의 로드 밸런서는 TCP, 프록시, TCP, HTTP, HTTPS 프로토콜을 지원합니다. 지원되는 프로토콜에 따라 로드 밸런서는 네트워크 로드 밸런서, 네트워크 프록시 로드 밸런서, 애플리케이션 로드 밸런서로 분류됩니다. 각 로드 밸런서 유형은 다음 슬라이드에서 자세히 설명합니다. 네이버 클라우드 플랫폼의 로드 밸런서는 로드 밸런싱 성능에 따라 소형, 중형, 대형으로 선택할 수 있습니다. 지원되는 CPS 값은 로드 밸런서 유형별로 다르며, 로드 밸런싱 알고리즘은 클라이언트 요청 시 서버에 트래픽을 순차적으로 분산하는 기본 라운드 로빈 방식 외에도 최소 연결 방식을 사용하여 가장 적은 연결을 가진 서버에 분산하는 방식을 지원합니다. 클라이언트 연결과 소스 EP 해시 방식( 클라이언트 AP용 해시 테이블을 사용하여 클라이언트 IP 에 매핑된 서버로 새 연결을 분산하는 방식)이 지원됩니다. 이제 각 로드 밸런서 의 특징을 자세히 살펴보겠습니다. 애플리케이션 로드 밸런서는 HTTP 및 HTTPS 프로토콜을 지원하며 호스트 헤더 기반 분기 처리와 URL 기반 분기 처리가 가능합니다. L7 계층에서 작동할 수 있으므로 라운드 로빈 임대 연결 및 소스 EP 해시를 포함한 모든 분기 처리 방식을 지원합니다. 다음으로 네트워크 로드 밸런서를 살펴보면 TCP 고성능 처리를 지원하고 클라이언트 IP를 그대로 로깅합니다. 네트워크 로드 밸런서는 소스 EP 해시와 라운드 로빈 방식을 지원합니다. 마지막으로 살펴볼 로드 밸런서 유형은 네트워크 프록시 로드 밸런서입니다. 네트워크 프록시 로드 밸런서는 프록시 기반 통신을 제공하므로 세션 유지 관리가 필요한 TCP 기반 애플리케이션에서 사용할 수 있습니다. 또한 애플리케이션 로드 밸런서와 동일한 로드 밸런싱 알고리즘을 적용할 수 있습니다. 이제 각 로드 밸런서의 기능을 자세히 살펴보겠습니다. 시스템에 TCP 수준의 고성능 로드 밸런싱 기능이 필요한 경우 어떤 유형의 로드 밸런서를 선택해야 할까요? 네트워크 로드 밸런서가 적합할 것입니다. 네트워크 로드 밸런서는 초당 최소 10만 개에서 최대 40만 개의 연결을 지원하며, 고객 서버에 직접 응답하는 직접 서버 응답(DSR) 기능을 통해 더 빠르고 효율적인 서비스를 제공합니다. TCP 세션 관리가 필요한 경우 네트워크 프록시 로드 밸런서가 적합하고, SSL 인증 및 암호화 처리가 필요한 경우 애플리케이션 로드 밸런서 또는 네트워크 프록시 로드 밸런서를 사용할 수 있습니다. SSL 인증서를 사용하려면 사전에 인증서 관리자에 등록해야 합니다. 다양한 로드 밸런싱 알고리즘을 적용하려면 애플리케이션 로드 밸런서와 네트워크 프록시 로드 밸런서를 사용할 수 있습니다. 두 로드 밸런서 모두 라운드 로빈, 임대 연결, 소스 EP 해시 등 모든 로드 밸런싱 알고리즘을 지원하며, HTTP 및 HTTPS 트래픽에 대한 패킷 헤더를 확인하여 애플리케이션 레벨에서 분기 처리를 수행합니다. 호스트 헤더 기반 분기 처리, URL 경로 패턴 기반 분기 처리, 가중치 분기 처리 및 리디렉션 응답 처리 등이 로드 밸런서에서 지원됩니다. 리스너를 사용하면 애플리케이션 로드 밸런서를 선택할 수 있습니다. 더 자세한 구성이 필요한 경우, 이 리스너는 사용자가 생성한 로드 밸런서에 대한 기본 모니터링 기능을 제공합니다. 네트워크 로드 밸런서 모니터링은 동시 연결, 초당 연결 수, 트래픽, 사용 가능한 호스트 등 5가지 항목에 대한 정보를 제공합니다. 애플리케이션 로드 밸런서 모니터링은 트래픽 출력을 포함하여 6가지 항목에 대한 정보를 제공합니다. 마지막으로 로드 밸런싱 지원 설정을 살펴보겠습니다. 로드 밸런서 규칙을 설정할 때 로드 밸런싱 지원 포트는 다른 로드 밸런싱 규칙의 포트와 다르게 설정해야 합니다. 서버 포트는 다른 로드 밸런싱 규칙의 서버 포트와 동일하게 설정할 수 있습니다. 네트워킹 서비스는 로드 밸런서 이후를 확인합니다. 로드 밸런서는 글로벌 DNS 서비스입니다. 글로벌 DNS 서비스를 통해 도메인에 대한 다양한 레코드를 등록하고 사용할 수 있으며, 글로벌 DNS 에 구성된 도메인에 별칭 레코드를 매핑할 수 있습니다. 또한 구성된 도메인에 대한 요청 수를 확인할 수 있는 모니터링 기능도 제공합니다. 이것으로 네이버 클라우드 플랫폼에서 제공하는 주요 네트워킹 제품에 대한 설명을 마치겠습니다. 다음 시간에 더 흥미로운 콘텐츠로 돌아오겠습니다. 감사합니다.
