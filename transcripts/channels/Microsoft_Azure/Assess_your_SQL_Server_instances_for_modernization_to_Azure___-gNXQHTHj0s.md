## 스크립트

[음악] 안녕하세요 여러분, 환영합니다. 이 비디오에서는 Azure Migrate를 사용하여 Microsoft SQL Server 배포를 Azure로 마이그레이션하는 계획을 세우는 방법을 살펴보겠습니다. Azure Migrate를 사용하면 독립형 또는 고 가용성 대규모 SQL Server 인스턴스 및 데이터베이스를 검색하고 평가할 수 있습니다. 구체적으로 말하자면, SQL 워크로드 의 마이그레이션 및 현대화를 가능하게 한다는 측면에서 이야기하는 것입니다 . 새로운 Azure SQL 평가 기능을 사용하면 마이그레이션 준비 상태 및 장애 요인, 권장 대상 Azure 서비스, 적정 규모의 분산 정도, 그리고 권장 사항의 근거를 파악할 수 있습니다. Azure에서 SQL Server 배포를 실행하는 데 드는 비용 추정치와 마이그레이션 지침도 확인할 수 있습니다. 즉, 권장되는 방식을 사용하여 마이그레이션을 수행하기 위해 필요한 단계입니다. Microsoft SQL Server 배포를 Azure로 마이그레이션하기 전에 SQL Server를 성공적으로 검색하는 데 필요한 모든 전제 조건이 충족되었는지, 그리고 모든 검색 관련 문제가 해결되었는지 확인해야 합니다. 필수 조건에 대한 자세한 내용은 aka.ms/azuremigrate/sqldiscovery를 참조하세요. SQL Server 인스턴스 및 데이터베이스를 검색하기 위한 최소 권한 자격 증명을 생성하려면 aka.ms/azuremigrate/sqldiscovery 스크립트를 참조하십시오. 검색이 성공적으로 완료되면 데이터베이스 블레이드로 이동하여 SQL 평가를 시작할 수 있습니다. 평가할 SQL 서버를 선택하고 ' 평가 생성'을 클릭하면 됩니다. 평가를 생성하는 동안 마이그레이션 대상 지역, 소스 워크로드의 기본 환경 유형, ID(개발, 테스트 또는 프로덕션)와 같은 대상 속성을 지정하여 적절한 가격을 적용할 수 있습니다. 또한 통화, 종량제, 1년 또는 3년 예약 인스턴스, Azure 절약 플랜과 같은 절약 옵션 및 평가 기준을 지정할 수 있습니다. Azure 하이브리드 혜택을 이용하면 자체 Windows Server 또는 SQL Server 라이선스를 Azure로 가져올지 여부를 지정할 수도 있습니다 . ' 기본값 편집'을 클릭하면 대상 서비스 계층과 인스턴스 SKU를 지정하여 활용할 Azure SQL 제품을 선택할 수 있습니다. 또는 기본값을 그대로 두면 Azure Migrate가 어떤 설정이 가장 적합한지 스스로 결정하도록 할 수 있습니다. 모든 세부 정보를 지정한 후 ' 검토 및 평가 생성'을 클릭할 수 있습니다 . 모든 것이 괜찮아 보이면 ' 만들기'를 클릭하세요. 평가 결과는 몇 분 안에 검토 가능합니다. 보시는 바와 같이, 저희는 92개의 서버, 188개의 인스턴스, 13,000개의 데이터베이스를 평가했으며, 8개의 장애 조치 클러스터 인스턴스와 21개의 가용성 그룹을 보유하고 있습니다. 또한, 저희가 제공하는 여러 서비스들이 지원이 종료되었거나 종료가 임박했음을 확인할 수 있습니다. 또한, 문제 발견 성공률은 보통 수준이며, ' 문제 보기'를 클릭하여 수정해야 할 사항을 확인할 수 있습니다. SQL Server 인스턴스 및 데이터베이스에 대한 다양한 마이그레이션 방식의 준비 상태 와 Azure에서 이러한 워크로드를 실행하는 데 필요한 예상 비용을 확인할 수 있습니다. Azure SQL MI와 같이 Azure의 각 SQL 배포 대상에 맞춘 보고서를 자세히 살펴보거나 요약된 권장 보고서를 참조할 수 있습니다. 권장 보고서는 선택한 마이그레이션 기본 설정(이 경우 '현대화')을 기반으로 SQL Server 배포를 Azure로 마이그레이션하는 가장 효율적인 방법을 제시합니다. Azure Migrate는 마이그레이션 준비 상태와 예상 비용을 모두 고려하여 SQL 배포가 누락되지 않도록 합니다. 아직 완전히 밝혀지지 않은 것들까지도 포함해서 말입니다. 이 경우, 현대화하려는 의도에 따라 126개의 동일한 서버 인스턴스를 재플랫폼화하여 그중 62개를 IS에 인계하고 재호스팅하는 것을 권장합니다. 더 자세히 살펴보면, 권장되는 패스 서비스는 Azure SQL Managed Instance이고, IaaS 서비스는 Azure VM임을 알 수 있습니다. 이제 장애 조치 클러스터 인스턴스인 fc3 sequel2k19.fpl.com에 있는 MS SQL Server에 대한 평가 세부 정보를 살펴보겠습니다. 이 인스턴스는 제가 현대화하려는 애플리케이션의 데이터 계층을 나타냅니다 . Azure SQL 및 Azure VM의 SQL Server로 마이그레이션할 준비가 되었으며, 앞서 언급한 현대화 목표를 고려할 때 권장 대상은 Azure SQL MI임을 알 수 있습니다 . 권장 구성에는 컴퓨팅 관점에서 범용으로 제공되는 Gen5 4V 코어와 32GB 스토리지가 포함되며, 비용은 215달러입니다. 또한 할당된 코어, CPU 사용률, 사용 중인 메모리 등과 같은 집계된 성능 통계를 더 자세히 볼 수 있습니다. 준비 상태 탭에서는 Azure의 모든 SQL 대상에 대한 준비 상태를 파악할 수 있습니다. Azure SQL Database로의 현대화와 관련된 문제점을 이해하기 위해 몇 가지 문제를 해결해야 하지만, 이러한 문제들은 Azure 로의 마이그레이션 자체에는 큰 지장을 주지 않는 변경 사항임을 알 수 있습니다 . 이 경우, 애플리케이션에 서비스 브로커가 필요하지 않다면 Azure SQL DB로의 마이그레이션을 준비하거나 다른 대상을 고려하기 위해 서비스 브로커를 비활성화할 수 있습니다. 목표 추천 탭에서는 이상적인 목표가 어떻게 결정되었는지 설명합니다. 이 경우 SQL Server는 Azure SQL MI를 사용할 준비가 되어 있었지만, Azure SQL DB의 경우 몇 가지 마이그레이션 문제가 발견되었습니다 . 또한 Azure SQL MI에서 이 인스턴스를 실행하는 비용이 두 가지 옵션 중 가장 낮을 것으로 예상됩니다. 이 보고서는 또한 Azure SQL MI로 마이그레이션하는 것도 간단하다고 설명합니다. 모든 사용자 데이터베이스를 권장 관리형 인스턴스 구성으로 마이그레이션하기만 하면 되며, Azure VM의 SQL Server로 마이그레이션했을 때처럼 고가용성을 위해 여러 노드로 구성된 클러스터를 설정할 필요가 없습니다. 해당 작업에 권장되는 도구는 Azure Data Studio임을 알 수 있습니다. Azure Migrate의 권장 사항 덕분에 SQL 배포를 정확하게 검색하는 데 필요한 자격 증명이나 권한이 없었을 때도 문제를 해결할 수 있었습니다. SQL 배포를 하나도 빠뜨리지 않도록 하기 위함입니다 . 이제 각 목표에 대한 방향성 보고서를 살펴보겠습니다 . 특히 패스형 패스는 운영 및 유지 관리 측면에서 비용 효율성이 높기 때문에 더욱 그렇습니다. Azure SQL MI 전용 준비 상태 보고서를 살펴보면 186개 인스턴스 중 133개 인스턴스가 Azure SQL MI로 마이그레이션할 준비가 되었거나 마이그레이션 조건을 충족하는 상태임을 확인할 수 있습니다. HR SQL VM 05의 MS SQL 서버는 해당 서버의 데이터베이스 중 하나에서 파일 스트림 기능이 활성화되어 있으므로 Azure SQL MI에 대한 조건을 충족하는 준비 상태로 표시되어 있음을 확인할 수 있습니다. 이 인스턴스를 Azure SQL MI로 마이그레이션하는 데 관심이 있다면 채택할 수 있는 해결 방법이 있음을 알 수 있습니다 . 권장 구성은 차세대 범용 프로비저닝 방식의 5세대 스큐(skew) 프로세서로, 4개의 V 코어와 96GB 의 스토리지를 갖추고 있으며 가격은 약 215달러입니다. 보시다시피 Azure Migrate는 Azure VM의 SQL에 대해 두 가지 전용 평가 보고서를 제공합니다 . " Azure VM의 SQL 서버 인스턴스로 마이그레이션"이라는 제목의 문서에서는 성능 저하 없이 각 SQL 서버 배포를 스트라이프 디스크가 있는 별도의 Azure VM으로 마이그레이션하는 이상적인 접근 방식을 다룹니다 . FC3 SQL 2K19.fpl.com에서 실행되는 MS SQL 서버를 살펴보겠습니다. 이는 고가용성 배포 환경입니다. 더 자세히 살펴보면, 원천 데이터 에서 확인된 성능 통계를 확인 하고 마이그레이션 지침을 이해할 수 있습니다. 이 경우 활성 노드의 데이터를 Azure VM의 SQL 서버로 복사해야 합니다. 이때 임시 자산은 VM의 임시 드라이브로 이동하고, 로그 및 데이터 자산은 각각의 스토리지 풀로 복사해야 합니다. 데이터 이동이 완료되면 공유 디스크를 사용하는 Azure VM을 기반으로 2노드 클러스터를 구성하여 감시 서버로 활용할 수 있습니다. "Azure VM 의 SQL Server로 서버 마이그레이션"이라는 제목의 다른 보고서는 최소한의 노력으로 Azure VM으로 마이그레이션하기 위한 리프트 앤 시프트 또는 복제 기반 접근 방식을 목표로 합니다 . Azure SQL DB 준비 상태 보고서를 활용하면 성공적으로 검색된 각 데이터베이스를 Azure SQL DB로 마이그레이션하는 데 필요한 준비 상태, 예상 비용 및 편차를 파악할 수 있습니다. Azure VM 또는 Azure SQL DB의 SQL Server 또는 Azure SQL MI로 마이그레이션할 때 컴퓨팅 및 스토리지 비용 분포를 검토할 수 있습니다 . 언제든지 설정으로 이동하여 예약 용량, 마이그레이션 전략, Azure 하이브리드 혜택 등의 선택 사항을 변경하여 평가를 사용자 지정하고 비용 변화를 확인한 후 최적의 조합을 선택할 수 있습니다 . 또한, 평가 보고서를 내보내어 공유하거나 오프라인에서 활용할 수 있습니다 . 이 데모에서는 Azure Migrate에서 제공하는 모든 기능을 활용하여 대규모 SQL Server 인스턴스 및 데이터베이스를 검색하고 평가하는 방법을 설명합니다 . Azure Migrate를 사용하여 데이터 마이그레이션 우선순위를 쉽게 정할 수 있도록 Azure SQL 평가 생성 및 다양한 옵션, Azure SQL 배포 대상 및 적정 규모 편향 권장 사항과 관련 근거 및 마이그레이션 지침 , 비용 세부 정보 등을 포함했습니다 . 시작하실 때 이 화면에 있는 Azure Migrate 설명서와 같은 자료를 활용하시면 됩니다. 탐색 및 평가가 완료 되고 신뢰도 높은 마이그레이션 계획을 수립한 후에는 Azure Data Studio, Azure Database Migration Service 또는 Azure Migrate의 기본 리프트 앤 시프트 기능을 활용하여 SQL Server 배포를 마이그레이션할 수 있습니다. Azure Data Studio와 Azure Database Migration Service를 사용하면 데이터베이스 및 서버 개체를 Azure SQL MI, Azure VM의 SQL Server 또는 Azure SQL DB로 마이그레이션할 수 있습니다. Azure Migrate의 서버 마이그레이션 기능을 사용하면 서버를 Azure 가상 머신으로 옮길 수 있습니다. 실제 마이그레이션을 진행하기 전에 프로덕션 워크로드에 영향을 주지 않고 테스트 마이그레이션을 수행할 수도 있습니다. 이 영상을 시청해 주셔서 감사합니다. [음악]
