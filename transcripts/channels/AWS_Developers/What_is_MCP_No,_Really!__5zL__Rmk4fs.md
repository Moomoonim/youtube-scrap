## 스크립트

MCP. 이 영상에서는 모델 컨텍스트 프로토콜이 무엇인지, 어떻게 사용하는지, 그리고 앞으로 어떻게 발전할지에 대해 이야기해 보겠습니다 . 이는 Anthropic Games에서 개발한 오픈소스 프로토콜로, 대규모 언어 모델을 갖춘 유전 시스템을 구축하는 데 도움이 되기 때문입니다 . 대부분의 경우 , 이는 노트북에 해당 프로그램이 설치되어 있고, 거기에 에이전트가 있다는 것을 의미합니다. 그러니까 이건 클로 데스크톱일 수도 있고, 아니면 우리 컴퓨터에 있는 아주 작은 MCP 서버를 사용하는 아마존 Q CLI일 수도 있어요. 이 MCP 서버는 에이전트 기능이 더 많은 작업을 수행하고 외부 세계와 연결할 수 있도록 해줍니다. 실제로 어떻게 작동하는지 살펴보겠습니다 . 제 노트북에는 QCLI와 MCP 서버가 설치되어 있습니다. 물론, 자연어로 질문을 입력하여 컴퓨터 에서 다양한 작업을 수행하는 데 이 기능을 활용할 수 있습니다 . AWS 문서에서 Amazon Bedrock에 대해 뭐라고 설명하는지 여쭤보겠습니다. 아마존 베드락은 새롭고 계속 발전하는 기술입니다. 그래서 우리는 최신 정보를 원합니다. 그럼, 엔터 키를 누르겠습니다. QCLI는 생각하기 시작하고 문서 내부의 정보를 찾아보기 위해 MCP 기능을 사용하기로 결정합니다. 여기서는 아마존 베드락 관련 문서 내에서 검색을 하려고 한다는 내용이 나옵니다. 네, 그러겠습니다 . 저는 해당 프로그램이 제 컴퓨터 외부의 서비스에 연결하는 것을 허용합니다. 무언가를 발견했다는 뜻이에요. 해당 정보를 읽고 나면 아마존 베드락에 대한 최신 정보를 담은 응답을 보내줄 것으로 기대됩니다. 이것은 제 컴퓨터에서 QCLI라는 에이전트를 사용하여 MCP 서버를 통해 데이터 소스에 연결하는 예시입니다. 저희는 다양한 MCP 서버를 보유하고 있습니다. 여기 GitHub 저장소에 AWS Labs MCP가 있는 것을 보여드리겠습니다. 물론 링크는 아래 설명란에 있습니다. 저희는 다양한 MCP 서버 목록을 보유하고 있으며 , 대부분은 이러한 워크플로우를 수행할 수 있도록 사용자의 컴퓨터에서 실행되도록 설계되었습니다. 이 파일들을 다운로드한 후, QCLI와 연동하도록 구성하려면 제가 여기에서 한 것처럼 MCP JSON 파일을 열고 QCLI가 MCP와 연동하여 이 리소스에 연결하는 방법에 대한 세부 정보를 입력하면 됩니다. 지금 우리 중 많은 사람들이 하고 있는 일이 바로 이런 종류입니다 . 저희는 MCP를 기본적으로 저희 시스템에서 실행되는 소프트웨어를 위한 플러그인 아키텍처로 사용하고 있습니다. MCP에 대해 좀 더 자세히 알아보기 위해 이러한 구성 요소들을 하나씩 살펴보겠습니다. 저희 담당자가 여기 계십니다. 이것은 저희 MCP 클라이언트이고, 반대편에는 MCP 서버가 있습니다. 이제 제가 왜 이 일에 그토록 흥분하는지, 그리고 이것이 우리가 기존에 에이전트를 양성하는 방식과 어떻게 다른지 설명해 드리겠습니다. 불과 몇 주 전만 해도 상황이 이렇게 빨리 변할 줄은 몰랐어요. 예전에는 에이전트가 여러 도구와 통신하도록 설정하고, 해당 도구에 대한 구성은 에이전트 자체 내에 저장했습니다 . 이제 이러한 구성, 이름, 설명, 인수 또는 이러한 도구와 통신하는 방법에 대한 스키마는 자연어로 저장됩니다. 에이전트 내부에 있는 대규모 언어 모델이 도구 설명을 읽고 에이전트 워크플로에서 어떤 도구를 언제 사용해야 하는지 파악할 수 있도록 자연어를 사용합니다. 하지만 에이전트에서 이 설명과 구성이 여기에 있다는 것은 이러한 구성 요소들을 매우 긴밀하게 연결시켜 줍니다. 그리고 많은 경우, 에이전트와 도구는 동일한 코드베이스의 일부일 가능성이 높습니다. 하지만 MCP를 사용하면 상황이 달라집니다. 이 설정은 MCP 서버 자체로 전달됩니다. 따라서 이 구성은 이제 기능과 함께 작동하며 MCP는 이를 에이전트에 노출하는 역할을 합니다. 따라서 실행 중인 에이전트는 " 도구 목록을 보여주세요"라고 말할 수 있습니다. 사용 가능한 도구가 무엇인지 알려주시면, 해당 데이터가 다시 전송되어 상담원이 특정 도구를 언제 사용할지 결정할 수 있습니다 . 그러면 모든 정보를 갖게 되므로 실행 방법을 알고 MCP 서버에 호출을 보낼 수 있습니다 . 이러한 구성 요소들의 분리가 바로 우리가 에이전트 시스템을 위한 아키텍처를 구축할 수 있는 매우 흥미로운 방식입니다. 또한 이것이 단순히 도구에 관한 문제만은 아니라는 점을 지적해야 합니다. 또한 프로토콜 내부에 리소스를 보유할 수 있는 기능도 있습니다. 이것들은 파일 또는 데이터입니다. 프롬프트도 있습니다. 따라서 MCP 서버의 일부로 프롬프트 템플릿을 사용할 수 있습니다 . 따라서 MCP 서버는 에이전트에게 어떤 방식으로 상호 작용하기를 원하는지 알려줄 수 있습니다 . MCP 서버 내부에서는 저장 가능한 데이터와 수행할 수 있는 작업에 있어 매우 다양한 유연성을 제공합니다 . 컴퓨터에서 실행되는 에이전트용 플러그인 시스템을 만드는 데 이렇게 복잡한 과정을 거치는 건 좀 과한 것 같네요. 하지만 그것은 MCP의 미래 비전이 아닙니다. MCP의 미래 비전은 그보다 훨씬 더 큽니다 . 이는 MCP 클라이언트를 다른 곳에 두고 MCP 서버는 인터넷상의 어딘가 , 가장 흔하게는 클라우드에 두는 것을 의미합니다. 해당 프로토콜 자체는 두 가지 서로 다른 전송 표준에 대해 특정 입장을 취하고 있습니다. 표준 IO이기 때문에 결국 우리 컴퓨터에 MCP 서버가 많이 설치되는 것이지만, 스트리밍 가능한 HTTP도 포함됩니다. 이것이 바로 서버를 노트북 하드웨어에서 분리하여 클라우드 어딘가에 설치할 수 있게 해주는 기술입니다. 이것이 MCP의 미래 비전이며, 현재 사람들이 함께 만들어가고 있는 결과물입니다. 이러한 단절된 특성으로 인해 우리는 신원 확인 및 보안과 관련하여 몇 가지 해결해야 할 과제가 있습니다. 하지만 이 프로토콜은 그러한 문제에 대처할 수 있는 방법을 제공하여 궁극적으로 다음과 같은 미래 상태에 도달할 수 있도록 해줍니다 . 챗봇이든 데이터 처리 파이프라인이든, 당사의 에이전트 시스템은 원격으로 호스팅되는 MCP 서버에 연결될 수 있습니다. 다른 에이전트와 연결될 수 있습니다. MCP 프로토콜은 MCP 기반의 뛰어난 에이전트 시스템을 통해 사용자와 이 모든 것을 연결합니다 . 이 MCP 소개가 유용했기를 바라며, 이 영상이 마음에 드셨기를 바랍니다. 이 영상이 마음에 드셨다면 좋아요를 눌러주세요. 다른 사람들이 이와 비슷한 영상을 찾는 데 도움이 됩니다. 이런 영상을 더 보고 싶으시다면, 이 채널을 구독하고 새 영상이 올라올 때 알림을 받으시려면 종 모양 아이콘도 눌러주세요 . MCP 여정에 함께해 주셔서 감사합니다. 곧 다른 영상에서 다시 뵙겠습니다.
