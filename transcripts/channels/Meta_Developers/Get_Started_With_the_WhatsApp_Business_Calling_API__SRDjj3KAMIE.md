API 호출을 위한 요구 사항과 초기 설정 방법에 대해 이야기해 보겠습니다. 먼저 Meta 에서 호스팅하는 클라우드 API와의 기존 통합이 필요합니다 . 개발자 계정, 애플리케이션, 웹훅 및 권한과 같은 개념에 익숙해야 합니다. 이러한 개념이 익숙하지 않다면, 이 영상을 잠시 멈추고 개발자를 위한 메타 웹사이트의 무료 자료를 확인해 보세요. 둘째, WhatsApp 비즈니스 메시징 권한과 WhatsApp 비즈니스 관리 권한이 있는 액세스 토큰이 필요합니다. 클라우드 API 온보딩 과정에서 제공받은 메시징용 기존 토큰을 활용할 수 있습니다. 셋째, 시그널링에 HTTPS 프로토콜을 선택하는 경우, 메타 개발자 계정이 새로운 호출 웹훅 필드를 구독해야 합니다. 앱 대시 보드의 설정 페이지에 있는 WhatsApp 섹션에서 해당 설정을 변경할 수 있습니다. SIP 프로토콜을 선택하는 경우에는 이 단계가 필요하지 않습니다. 넷째, 메타 개발자 계정은 통화 기능을 활성화할 비즈니스 전화번호가 있는 WhatsApp 비즈니스 계정에 가입되어 있어야 합니다 . 이는 클라우드 API 온 보딩 프로세스 중에도 수행되므로 이를 활용할 수 있습니다. 마지막으로 통화 기능을 활성화해야 합니다. 이 기능은 기본적으로 비활성화되어 있습니다. 이 기능을 활성화하려면 SL 전화번호 ID SL 설정 엔드포인트로 POST 요청을 보내야 하며, 해당 기업은 모든 전화번호에 대해 24시간 동안 기업에서 시작한 대화 수를 1,000건으로 제한해야 합니다. 요청 본문에는 ' calling'이라는 이름의 객체를 보내야 합니다. 이 이미지에서 이 객체가 다음과 같은 매개변수를 가지고 있음을 확인할 수 있습니다. 우리가 먼저 살펴볼 첫 번째 매개변수는 상태 관련 매개 변수입니다. 이 기능을 활성화하면 WhatsApp 클라이언트 앱의 비즈니스 대화 및 비즈니스 채팅 프로필에 통화 아이콘이 표시됩니다. 두 번째 매개변수는 통화 아이콘 표시 여부입니다. 통화 상태가 활성화로 설정되면 이 매개변수를 통해 통화 아이콘 표시를 추가로 제어할 수 있습니다. 이 매개변수를 기본값으로 설정하면 첫 번째 이미지와 같이 채팅 메뉴에, 그리고 두 번째 이미지와 같이 비즈니스 정보 화면에 통화 아이콘이 표시됩니다 . 통화 기능을 모두 비활성화하면 통화 아이콘이 숨겨 지고 사용자는 해당 업체에 원치 않는 전화를 걸 수 없습니다 . 기업은 여전히 ​​사용자가 전화를 걸 수 있도록 행동 유도 버튼이 포함된 대화형 메시지 또는 템플릿 메시지를 보낼 수 있습니다 . 또 다른 매개변수는 통화 가능 시간입니다. 이 기능을 사용하여 사용자가 회사에 전화할 수 있는 이용 가능한 시간대를 정의할 수 있습니다 . 해당 시간 외에 걸려오는 전화는 모두 차단됩니다. 또한 이 기능을 사용하여 휴일과 같이 비즈니스가 일시적으로 운영되지 않는 시간대를 지정할 수도 있습니다. 이 시간대에 걸려오는 모든 전화는 차단됩니다. 호출 객체의 마지막 매개변수는 콜백 권한 상태입니다. 사용자에게 전화를 걸기 전에 기업은 사용자로부터 명시적인 허가를 받아야 합니다. 콜백 권한 상태 매개변수를 활성화로 설정하면 사용자가 비즈니스에 전화를 건 후 비즈니스는 자동으로 사용자에게 다시 전화를 걸 수 있는 권한을 받게 됩니다. 이는 사용자가 업체에 전화를 걸었지만 응답을 받지 못한 경우의 사용자 경험입니다. 세 번째 이미지에서 볼 수 있듯이, WhatsApp 소비자 앱에 권한이 승인 되었다는 알림 메시지가 표시됩니다. 사용자가 메시지를 클릭하면 마지막 이미지에 표시된 것처럼 권한을 취소할 수 있습니다. 다음 섹션에서는 기업이 고객으로부터 전화를 받는 방법에 대해 자세히 살펴보겠습니다 . 우리는 이러한 사용 사례를 사용자 주도 . 사용자가 전화를 거는 경우와 마찬가지로, 고객 서비스 상담 창이 열려 있는 경우 기업은 대화형 메시지를 통해 통화 권한 요청을 보낼 수 있습니다 . 고객 서비스 상담 창이 열려 있지 않은 경우, 기업은 템플릿 메시지를 보낼 수 있습니다 . 이미지에서 볼 수 있듯이, 통화 권한 요청이 대화형 메시지 형태로 전송되는 몇 가지 예시가 있습니다. 이 메시지를 보내려면 기업은 메시징에 사용되는 것과 동일한 클라우드 API 엔드포인트를 사용해야 합니다 . 그들은 type 매개변수를 새로운 값인 ` _underscore` 권한 요청으로 설정해야 합니다. 사용자가 통화 권한 요청에 응답하면 기업은 응답이 포함된 웹훅을 수신하게 됩니다. 웹훅의 구조는 클라우드 API에서 메시징에 사용되는 웹훅 사용자 구조와 유사합니다. 제공된 코드 샘플에서 볼 수 있듯이 웹훅에는 값 객체가 포함된 changes 배열과 대화형 객체가 포함된 messages 배열이 포함됩니다. 이 마지막 객체에는 사용자가 통화 권한 요청에 대해 응답한 내용이 포함되어 있습니다 . 해당 type 매개변수는 call_mission reply로 설정됩니다 . 응답 매개변수는 사용자의 선택을 나타내며, 수락 또는 거부일 수 있습니다. 만료 시간 매개변수에는 권한이 만료되는 시간(초)이 포함됩니다 . 비즈니스 담당자가 사용자에게 전화를 걸 수 있도록 승인을 받으면, `/ phone number ID/calls` 엔드포인트로 POST 요청을 보내 통화를 시작할 수 있습니다. 이때 ` action` 매개변수를 `connect`로 설정하고, ` two` 매개변수에는 사용자의 전화번호를, ` session` 매개변수에는 WebTC 통화 제안을 제공해야 합니다. SDP 유형 매개변수는 '제공'으로 설정해야 하며, SDP 매개변수는 RFC 4566을 준수해야 합니다. 그러면 비즈니스 측에서는 이 요청에 대한 응답으로 발신자 번호(Call ID)를 수신하게 됩니다 . 다른 필수 API 호출을 수행하려면 이 호출 ID를 저장해야 합니다 . 그러면 해당 기업은 통화 연결 웹훅을 수신하게 됩니다. 웹훅의 구조는 이전에 설명한 사용자 시작 호출용 통화 연결 웹훅과 유사합니다 . 제공된 코드 예제에서 볼 수 있듯이, 통화 관련 정보는 값 객체 내의 호출 배열에 담겨 전송됩니다. calls 배열에는 ID 매개변수에 통화 ID가 포함되어 있으며 event 매개변수는 connect로 설정됩니다. 또한 RFC 4566을 따르는 SDP 매개변수 와 비즈니스에서 시작된 호출 사례의 경우 제안 대신 응답으로 설정되는 SDP 유형 매개변수도 포함되어 있습니다. 통화가 시작되면 기업은 통화 상태와 관련된 웹훅을 수신하게 됩니다 . 통화가 연결 중인지, 수신되었는지, 거절되었는지를 나타냅니다. 이러한 웹훅의 구조는 클라우드 API에서 전송하는 메시지 상태 웹훅의 구조와 유사합니다 . 코드 예제에서 볼 수 있듯이, 값 객체 내의 statuses 배열에는 원인 상태 정보가 포함되어 있습니다. 상태 매개변수는 사용자가 전화를 받기 시작하면 'ringing' , 사용자가 전화를 받으면 'accepted', 사용자가 전화를 거부하면 'rejected' 중 하나일 수 있습니다. 그러면 기업은 이전에 사용자가 시작한 통화를 종료하기 위해 논의했던 것과 동일한 API 요청을 통해 통화를 종료할 수 있습니다. 코드 예시에서 볼 수 있듯이, 그들은 슬래시(/) 전화번호 ID가 호출되는 엔드포인트로 POST 요청만 보내면 됩니다. ID 매개변수에 통화 ID를 제공 하고 action 매개변수를 종료로 설정하십시오. 마지막으로, 사용자 또는 기업 측에서 통화를 종료하면 기업은 사용자 시작 통화에 대해 수신하는 것과 유사한 통화 종료 웹훅을 수신하게 됩니다 . 이 샘플 코드를 웹훅 전체 구조에 대한 참조 자료로 사용할 수 있습니다 . 원인 객체에는 통화 ID가 포함되고 이벤트는 종료로 설정됩니다. 이 단계는 기업이 고객에게 전화를 걸기 위해 따라야 하는 절차를 완료합니다. 이것으로 WhatsApp 비즈니스 통화 API에 대한 기술적 개요를 마무리합니다. 이 프레젠테이션을 통해 WhatsApp 비즈니스 클라우드 API 호출에 대한 포괄적인 기술적 개요를 제공해 드렸기를 바랍니다. 이 모든 것을 배우고 나면 이제 실행에 옮길 준비가 된 것입니다. 딥 링크 생성, DTM 적합음 생성, SIP 프로토콜을 이용한 신호 전송 등 다른 기능에 대해 더 자세히 알아보려면, developers.mmeta.com 웹사이트 에서 이 QR 코드를 스캔하여 모든 정보를 확인하세요 . 시청해 주셔서 감사합니다.
