## 스크립트

모든 개발자는 팀 간에 일관된 코드 문서를 유지하는 것이 얼마나 어려운 일인지 잘 알고 있습니다. 개발 시간의 최대 25%를 소모할 수 있는데, 여기에는 서로 다른 스타일, 누락된 세부 정보, 오래된 문서 등이 포함됩니다. 안녕하세요, STW입니다. 오늘은 Amazon Bedrock의 프롬프트 관리 기능을 사용하여 코드 스니펫에 대한 포괄적인 문서를 생성하는 프롬프트를 만들어 보겠습니다. Amazon Bedrock 프롬프트 관리는 생성형 AI 애플리케이션 구축 과정을 간소화하는 다양한 기능을 제공합니다. 구조화된 프롬프트에는 시스템 지침, 도구, 추가 메시지 정의 기능이 있습니다. 모든 프롬프트를 구축할 때 API 통합을 위해 Converse 및 Invoke 모델을 사용할 수 있습니다. Invoke는 프롬프트를 카탈로그화하는 기능을 Amazon Bedrock에서 직접 수행합니다. Converse 및 Invoke API 호출을 통해 이 작업을 수행할 수 있습니다. 어떻게 하는지 간단히 살펴보겠습니다. 먼저 Bedrock 콘솔로 이동합니다. 왼쪽의 빌더 도구 아래에서 프롬프트 관리를 선택합니다. 프롬프트 생성을 클릭합니다. 몇 가지 입력 필드가 있는데, 이름을 지정해야 합니다. 저는 코드 문서 생성기라고 하겠습니다. 여러 단어를 사용할 경우 하이픈(-)을 사용해야 합니다. 설명은 선택 사항이지만, 저는 좋은 시민으로서 여기에 추가하겠습니다. 코드 스니펫에 대한 자세한 문서를 생성하도록 하겠습니다. 이 부분도 선택 사항이므로 원하지 않으면 건너뛰셔도 됩니다. 다음으로 '생성'을 클릭하세요. 이제 1 단계로 넘어가겠습니다. 1단계에서는 시스템 지침 입력을 구축하고 모델의 역할을 정의합니다. 이 예에서는 다음과 같이 입력하겠습니다. 코드 개발 및 문서화 전문가라고 알려주고, AI에게 코드 의 목적과 기능을 설명하고 모든 매개변수를 문서화하고 값을 반환하도록 요청할 것입니다. 또한 사용 예시를 제공하고 요구 사항에 대한 종속성을 파악하며 모범 사례 와 잠재적 문제를 강조할 수 있습니다. 문서화를 위한 런북을 만든다면 바로 이러한 내용을 가이드라인 문서에 포함할 것입니다. 2단계에서는 변수를 생성할 수 있으며, 이중 중괄호를 사용하여 변수를 묶습니다. 나중에 이러한 변수에 값을 전달할 수 있으며, 혁신 시점에 이 값은 프롬프트 템플릿에 삽입됩니다. 이 예에서는 다음을 사용합니다. 다음은 세 가지 변수(언어, 코드 스니펫)를 포함하는 프롬프트입니다. 그런 다음 형식을 사용합니다. 다음 코드에 대한 문서를 생성하려면 언어가 중괄호 안에 있고 코드 스니펫도 중괄호 안에 있으므로 약간의 작업이 필요합니다. 함수, 클래스, 목적, 매개변수, 설명 및 유형, 반환 값 및 세부 정보, 예제 사용법, 예외 상황 또는 제한 사항을 포함하도록 요청하고 고려 사항을 수행합니다. 그런 다음 특정 스타일로 출력하도록 요청합니다. 다음으로 모델을 선택합니다. 여기서는 CLA 3을 선택하겠습니다. 선택할 수 있는 모델은 많으며 사용 사례에 따라 다를 수 있지만, 이 경우에는 CLA 3을 사용하겠습니다. 이것을 선택하고 나머지는 기본값으로 둡니다. 마지막으로 3단계에서는 함수 C1의 도구 설정 섹션에서 도구를 구성합니다. 모델이 외부 함수와 상호 작용하고 모든 기능을 확장할 수 있도록 이름, 설명 및 입력 스키마를 사용하여 도구를 정의할 수 있습니다. 여기서는 도구 정보가 포함된 JSON 스키마를 제공합니다. 이를 자세히 살펴보겠습니다. 이 단계별 설명에서 우리는 투어 선택 항목을 살펴보고, 이를 '자동'으로 설정하겠습니다. 이렇게 하면 시스템이 이 도구를 사용할 시기를 자동으로 선택하게 됩니다. 다음으로 '도구'가 있는데, 이는 배열 이며 각 배열에는 하나의 도구 사양이 포함되어 있습니다. 도구 세부 정보, 이름('문서 생성'), 설명(' 주어진 코드 스니펫에 대한 문서 생성'), 입력 스키마( 필수 입력 및 언어 정의), 프로그래밍 언어(코드의 언어), 코드 스니펫( 문서화할 실제 코드), 형식( 원하는 문서 출력 형식)이 있습니다. 마크다운이나 HTML 등 여러 형식을 지정할 수 있습니다. 이 구조는 AI 시스템이 코드 스니펫을 제공하고 언어를 지정한 후 출력 형식을 선택하여 자동으로 문서를 생성할 수 있도록 설계되었습니다. 보시다시피 인접 스키마를 따르므로 이 도구를 사용할 때 필요한 모든 정보가 제공됩니다. 함수 호출이나 LLM 호출이 도구를 직접 사용하지 않는 경우에도 대신 도구를 참조합니다. 도구를 사용하려면 도구 매개변수가 필요하므로 사용자는 모델의 요청에 따라 도구를 호출하고 결과를 다시 모델에 전달하는 로직을 구현해야 합니다. 이 모든 작업을 완료한 후 개요 페이지로 돌아가 저장을 클릭할 수 있습니다. Amazon Bedrock에서 프롬프트 리소스의 고유 식별자인 프롬프트 리소스 이름을 복사해야 합니다. 나중에 이 식별자를 사용할 것이므로, 따라오고 있다면 애플리케이션에서 프롬프트를 호출할 수 있도록 안전한 곳에 저장해 두세요. 이제 프롬프트 식별자와 버전을 포함할 수 있으며, 이는 Amazon Bedrock Converse API 코어의 일부가 될 것입니다. 다양한 모델에서 여러 문서 스타일을 평가한 다음 Bedrock API를 사용하여 통합할 수 있습니다. 이제 AWS SDK를 사용하여 다음 코드를 예시로 작성해 보겠습니다. Python과 boto 3를 사용하여 Jupyter Notebook에서 작성하겠습니다. 먼저 boto 3 와 Json을 가져와야 합니다. 그런 다음 Amazon Bedrock과 상호 작용하는 데 필요한 구성 요소를 설정할 수 있습니다. 먼저 boto 3 세션을 생성해야 합니다. boto 3는 Python용 AWS SDK입니다. 특정 AWS 프로필을 사용하는 세션을 생성합니다. 여기서 제 프로필에는 AWS 자격 증명과 구성 설정이 포함되어 있습니다. 두 번째로 Amazon Bedrock 런타임용 특정 클라이언트를 생성해야 합니다. Bedrock Docent를 사용하여 Amazon 런타임과 연동되는 저수준 클라이언트를 생성합니다. 이 과정에서 Bedrock 런타임 서비스와 상호 작용하도록 지정합니다. Amazon Bedrock 기본 모델에 비용을 지불하기 전에 이 설정이 필수적입니다. 마치 특정 프로그램을 실행하기 전에 컴퓨터에 로그인해야 하는 것과 유사하다고 생각하면 됩니다. 저는 Amazon 리소스 이름(ARN)을 모델 ID 매개변수에 복사했습니다. 그러면 Amazon Bedrock이 프롬프트 관리 라이브러리에서 프롬프트 버전을 직접 로드하여 지연 시간 오버헤드를 발생시키지 않고 프롬프트를 호출할 수 있습니다. 이렇게 하면 워크플로가 간소화되고, 모델 호출 API를 통해 PR 프롬프트를 직접 호출할 수 있습니다. 이는 수동으로 프롬프트를 검색하고 형식을 지정하는 작업을 없애주므로 매우 유용합니다. 또한 팀 구성원들이 프롬프트를 재사용하고 공유하며, 다양한 버전을 추적할 수 있도록 해줍니다. 따라서 많은 이점이 있습니다. 좀 더 자세히 살펴보겠습니다. 이제 Bedrock 기능에 대해 더 자세히 살펴보겠습니다. 이는 Amazon Bedrock과 상호 작용하도록 특별히 설계된 AWS K4 Python의 핵심 구성 요소입니다. Bedrock 런타임에서 `invoke model` 함수를 호출하면 Bedrock에게 " 이 작업이 있는데, AI 모델을 사용하여 처리해 줄 수 있나요?"라고 묻는 것과 같습니다. 다음으로 `ID` 매개변수가 있습니다. 이는 Amazon Bedrock 툴박스 에서 선택할 수 있는 특정 도구와 같은 역할을 합니다. 이 매개변수는 작업 에 사용할 정확한 AI 모델을 식별하는 데 사용됩니다. 이 경우 앞서 복사한 ID를 가진 모델을 사용합니다. 그 아래에 있는 `ARN`은 `body` 매개변수입니다. 여기에서 작업에 대한 모든 세부 정보를 제공합니다. 마치 AI에게 일련의 지침을 제공하는 것과 같습니다. `body`에는 ` prompt` 변수가 있습니다. 이는 사용자 지정 설정으로 생각할 수 있습니다. 프로그래밍 언어를 지정하거나, 분석할 코드 스니펫을 제공하거나, 원하는 출력 형식을 지정할 수도 있습니다. 앞서 HTML과 마크다운 형식에 대해 이야기할 때 질문했던 것을 기억하세요. 마지막으로 ` Content Type`과 `Accept` 헤더가 있습니다. 이는 AI가 요청 형식과 응답에서 기대하는 형식을 이해하도록 합니다. 이 경우 JSON을 사용합니다. 이제 컴퓨터에서 흔히 사용되는 데이터 형식을 사용해 보겠습니다. 마지막으로 모든 세부 정보를 출력하려고 합니다. 보기 좋게 출력하는 기능을 사용하고 있는데, 이렇게 하면 읽기가 훨씬 쉬워집니다. 만약 이 기능을 애플리케이션으로 사용한다면 응답을 바로 출력할 수 있을 것입니다. 이제 실행이 완료되었고, 결과를 세 부분으로 나누어 볼 수 있습니다. 최상위 스크립트, 콘텐츠 섹션, 그리고 사용 통계가 있는데, 모두 아주 좋습니다. 응답을 보면 입력은 파이썬 "Hello World" 함수였고, 이 프로세스는 560개의 입력 토큰을 소비하고 228개의 출력 토큰을 생성했습니다. 이후 응답이 중지된 것은 도구 사용 작업이 완료되었기 때문입니다. 이 구조화된 응답 형식을 통해 모델 출력의 프로그래밍 방식 처리, 리소스 사용량 추적 및 관리가 가능합니다. Amazon Bedrock Promp Management는 모든 생성형 AI 개발을 간소화합니다. 시스템 지침 및 정의, 도구 구성, 프롬프트 변형 비교와 같은 기능을 갖춘 맞춤형 관리 프롬프트를 생성할 수 있는 중앙 집중식 플랫폼을 제공합니다. 개발자는 이제 더욱 관련성 높은 출력을 생성하는 AI 솔루션을 쉽게 구축하고 배포할 수 있습니다. Amazon Bedrock Promp Management를 사용하여 모든 코드 문서화를 자동화할 수도 있습니다. 이 영상이 마음에 드셨다면, 이 외에도 구현할 수 있는 다양한 기능들이 많이 있습니다. 더 많은 실습 위주의 기술 콘텐츠를 보고 싶으시다면, 영상에 좋아요를 누르고 awest Developers 유튜브 채널을 구독해주세요. 시청해주셔서 감사합니다!
