## 스크립트

오늘은 Amazon Bedrock에 대해 알아보겠습니다. Amazon Bedrock 은 강력한 기본 모델에 접근할 수 있도록 해주는 완전 관리형 서비스입니다. 간단한 API를 통해 이러한 모델을 학습하고 배포할 수 있지만, 처음부터 직접 구축하려면 상당한 리소스와 전문 지식이 필요합니다. 안녕하세요, 저는 STW입니다. 오늘 Amazon Bedrock이 어떻게 사전 학습된 모델을 제공하고, 이를 간단한 API를 통해 사용자 정의하고 배포할 수 있도록 하여 이러한 복잡성을 제거하는지 보여드리겠습니다. Amazon Bedrock은 고급 자연어 처리 기능을 모든 애플리케이션에 통합하는 과정을 간소화합니다. 따라서 광범위한 모델 학습 대신 언어 이해, 텍스트 생성, 질문 답변과 같은 기능에 직접 접근할 수 있습니다. 이 모든 것을 간단한 API 상호 작용을 통해 수행할 수 있습니다. 통합 프로세스는 명확한 구조를 따릅니다. 먼저 개발 환경을 설정하고 Amazon Bedrock 클라이언트를 생성합니다. 이것이 모든 모델 상호 작용의 진입점이 될 것입니다. 다음으로 모델이 처리할 프롬프트를 정의하고, 이러한 프롬프트를 사용하여 모델을 호출한 다음, 생성된 출력을 애플리케이션에서 사용할 수 있도록 처리합니다. 시작하기 전에 이 작업을 수행하기 위한 필수 조건과 필요한 사항을 살펴보겠습니다. 데모에서 보여드리겠습니다. 먼저 AWS 계정이 필요합니다. 둘째, 개발 환경이 필요합니다. 저는 Python이 실행되는 Jupyter Notebook이 있는 Virtual Studio Code를 사용하고 있지만, Python을 지원하는 어떤 IDE든 사용 가능합니다. 셋째, 환경 에 AWS 자격 증명이 구성되어 있어야 합니다. 이 자격 증명은 AWS 서비스에 대한 요청을 인증하는 역할을 합니다. 이제 설정이 완료되었으니 통합을 구축해 보겠습니다. 단계별로 진행하겠습니다. 개발 환경에는 두 가지 필수 패키지가 필요하므로 먼저 임포트하겠습니다. 스크립트에 boo3와 Jason을 임포트합니다. 이제 Amazon Bedrock 클라이언트를 생성합니다. 이 클라이언트는 모든 기본 모델 상호 작용을 위한 주요 인터페이스 역할을 합니다. Amazon Bedrock 런타임을 사용하는데, 이는 Amazon Bedrock 런타임 서비스에 대한 하위 수준 클라이언트를 생성합니다. 제 이름과 자격 증명을 사용하고, 여기서는 미국 동부 1 지역을 사용합니다. 다음으로 런타임 클라이언트가 모델 상호 작용을 처리합니다. 이 클라이언트는 모든 요청과 응답을 처리합니다. 클라이언트가 준비되었으므로 기본 모델을 사용하여 프롬프트를 준비하겠습니다. 프롬프트에는 자연어 명령, 코드 스니펫, 모델이 처리할 특정 작업 등이 포함될 수 있습니다. 간단한 예제부터 시작해 보겠습니다. " 안녕하세요, 누구세요?"라는 메시지를 API 엔드포인트로 보내려면 특정 인자 키워드가 필요합니다. 이러한 키워드는 Amazon Bedrock 콘솔에서 얻을 수 있습니다. Amazon Bedrock 콘솔에서 어떻게 작동하는지 살펴보겠습니다. 먼저 기본 모델로 이동합니다. 탐색 페이지에서 Titan Text G1 Express를 검색하여 선택합니다. 하단에 있는 API 요청 섹션에 액세스합니다. 이제 코드를 추가했으니 각 매개변수를 살펴보겠습니다. 모델 ID는 특정 기본 모델을 식별하고, Conta 유형과 예외는 데이터 형식을 정의합니다. 본문에는 프롬프트와 구성 설정이 포함됩니다. 구성 설정에는 최대 토큰 수( 응답 길이 제어), 온도(출력에 영향), 무작위성( 응답 다양성에 영향)이 있습니다. 모든 매개변수를 확인하려면 다음을 수행하면 됩니다. 쿼드를 사용한 다음 출력합니다. 여기서 입력 본문을 질문으로 변경해야 하므로 간단히 " 당신은 누구입니까?"라고 질문합니다. 그런 다음 실행할 수 있습니다. 실행이 완료되면 모델 ID, 콘텐츠 유형, 실행 중인 본문, 구성 파일에 추가한 입력 텍스트 등 다음과 같은 출력을 볼 수 있습니다. 이제 핵심 상호 작용으로 넘어갑니다. 모델을 호출할 것입니다. 이 작업은 프롬프트를 Amazon Bedrock으로 보내고 생성된 응답을 수신합니다. 더 진행하기 전에 응답 구조를 분석해 보겠습니다. 입력 텍스트 토큰 수는 프롬프트 토큰 사용량을 보여줍니다. 또한 실제 출력 텍스트에 포함된 결과 와 완료 세부 정보도 표시됩니다. 완료 이유는 응답이 완료된 이유를 나타냅니다. 이는 모든 출력을 애플리케이션에 쉽게 통합할 수 있도록 매우 엄격한 응답 형식입니다. Amazon Bedrock은 다양한 FMS( 기본 모델)를 제공하며 각 모델은 고유한 강점과 기능을 가지고 있습니다. Amazon Bedrock 클라이언트를 생성할 때 모델 이름 매개변수를 전달하여 사용할 모델을 지정할 수 있습니다. 이제 Amazon에 대해 알아보았습니다. Bedrock 과 이를 통해 애플리케이션 에 기본 모델을 통합하는 과정이 얼마나 간소화되는지 살펴보겠습니다. 지금까지 다룬 내용을 간단히 요약해 보겠습니다. 완벽한 개발 환경을 구축하고, Bedrock 클라이언트를 생성 및 구성하고, 프롬프트를 구성하고 전송하는 방법을 알아보았습니다. 또한 프로세스 모델 응답도 사용해 보았습니다. 이제 이러한 기본 모델의 강력한 기능을 매우 간단한 API 호출을 통해 이용할 수 있습니다. 즉, 복잡한 모델 학습 이나 리소스 관리 없이도 이러한 작업을 수행할 수 있다는 의미입니다. 여기서는 매우 간단한 코드 예제로 시작했지만, AWS 문서와 추가 모델 및 구성을 살펴보시기를 권장합니다.
