API 탭에서 실행 중인 작업을 보려면 필터링을 비활성화하세요. 이 예시에서는 현재 실행 중인 작업이 없습니다. API 클라이언트로 전환하여 데이터 추출 작업을 실행합니다. 여기서는 예측 버전을 기준으로 필터링한 모델의 사실 데이터를 내보냅니다 . 참고로 페이지 크기별로 10,000개의 레코드를 추출합니다 . 작업을 새로 고침하면 작업이 대기 중인 것을 확인할 수 있습니다. 그리고 이 작업에 대한 자세한 내용을 열어볼 수 있는데, 여기에는 API 클라이언트 에 구성된 동일한 추출 작업 과 레코드 수가 포함됩니다. 이제 다시 본론으로 돌아갑니다. 추출할 나머지 레코드를 생성하기 위해 OData 다음 링크를 실행할 수 있습니다. 이제 나머지 기록이 담긴 두 번째 페이지를 볼 수 있습니다 . 다음으로, 공용 차원, 보안 테이블 및 표준 단위 테이블을 포함한 추가 아티팩트에 대한 데이터 추출 작업을 생성해 보겠습니다. 작업 모니터를 새로 고치면 해당 작업들이 성공적으로 완료된 것을 확인할 수 있습니다. 해당 작업을 선택하면 작업 기간 및 추출된 레코드 수와 같은 자세한 정보를 확인할 수 있습니다. 작업 모니터에 새 소스 열이 추가되어 소스 개체로 다시 이동할 수 있습니다 . 데이터 추출 작업의 보존 기간은 7일입니다. 다음으로, 작업 모니터에서 델타 계산 작업 도입에 대해 살펴보겠습니다 . 따라서 델타 구독이 모델에서 활성화되면 델타 계산 작업이 생성됩니다. 이러한 작업은 사실 데이터의 델타 변화를 포착하기 위해 모델 큐브 이벤트를 생성합니다. 작업 모니터에서 이것이 어떻게 나타나는지 예를 통해 살펴보겠습니다. 탐색 메뉴의 시스템 폴더에서 작업 모니터를 열고 데이터 내보내기 API 탭에서 델타 계산 옵션을 선택합니다. 이제 모델에 델타 변경 사항을 수집하는 구독 기능을 만들어 보겠습니다. 이 작업을 처음 실행하면 모든 팩트 데이터 내용이 포함된 초기 로드가 생성됩니다. 다음은 추출 예시입니다. 이제 모델로 이동하여 사실 데이터를 업데이트하고 변경 사항을 저장하기 위해 게시해 보겠습니다. 이 작업은 델타 계산 작업을 활성화하여 이전 사실 데이터 값과 새 사실 데이터 값 간의 차이를 계산합니다. 이제 작업 모니터에서 해당 작업을 확인할 수 있습니다. 이 작업이 이미 성공적으로 완료되었음을 알 수 있습니다. 자세한 정보를 얻으려면 해당 직무를 선택할 수 있습니다 .
