Flutter 서비스, ADK 피팅룸 서비스 및 ADK 스타일링 서비스는 모두 동일한 3단계 패턴을 따릅니다. 첫 번째 단계는 세션입니다. 세션은 백엔드에서 대화 기록과 여러 차례에 걸쳐 공유되는 상태를 추적하는 방식입니다. 탈의실은 매번 새로운 세션을 만들어냅니다 . 하지만 스타일링 서비스는 다릅니다. 동일한 세션 ID를 재사용합니다. 이 기능 덕분에 상담원은 고객의 피드백을 기억하고 처음부터 다시 시작하는 대신 제안을 다듬을 수 있습니다 . 두 번째 단계는 에이전트를 실행하는 것입니다. 바로 이곳에서 마법이 일어납니다. 두 서비스 모두 실행 엔드포인트로 POST 요청을 보냅니다 . 요청 내용에는 앱 이름, 세션 ID, 새 메시지가 포함됩니다. 해당 메시지에는 부품 배열이 포함되어 있습니다. 각 부분은 서로 다른 유형의 데이터를 저장할 수 있습니다 . 지침이나 맥락을 나타내는 텍스트와, Base64로 인코딩된 이미지용 인라인 데이터가 포함됩니다. 예를 들어, 탈의실에서는 사용자 사진과 제품 이미지를 모두 전송합니다. 스타일링 서비스는 행사 및 장소와 같은 텍스트와 선택적으로 사용자 사진을 전송합니다. 세 번째 단계는 생성된 이미지를 불러오는 것입니다. 대용량 이미지를 응답에 직접 전송하는 대신 , 아티팩트를 사용합니다. 이미지가 생성되면 Google 클라우드 스토리지에 저장됩니다. 에이전트는 참조 이름만 반환합니다. 그러면 프런트엔드는 이미지를 가져오기 위해 별도의 GET 요청을 보냅니다. 이렇게 하면 응답이 가볍고 빠르며 예측 가능해집니다. REST API 세션과 아티팩트 저장소는 ADK에 내장된 몇 가지 편의 기능입니다. 다음으로, ADK가 실제로 어떻게 작동하는지 좀 더 자세히 알아보겠습니다. 자, 이제 ADK 자체에 대해 이야기해 보겠습니다. ADK(Agent Development Kit)는 AI 에이전트를 구축, 오케스트레이션 및 배포하기 위한 Google의 오픈 소스 프레임워크입니다 . 이것은 제미니 모델을 실제로 작업을 수행할 수 있는 에이전트로 변환할 수 있는 도구 모음이라고 생각하면 됩니다. 단순히 질문에 답하는 것뿐만 아니라, 행동을 취하고, 도구를 사용하고, 맥락을 기억하고, 다른 상담원들과 협력해야 합니다 . 저희의 경우, ADK Go를 사용하고 있습니다. 그래서 모든 것은 클라우드 런 백엔드에서 Go 언어로 실행됩니다. 그렇다면 왜 그냥 모델에게 전화하지 않느냐고 궁금해하실 수도 있습니다. 네 , 제미니 API를 직접 호출할 수도 있지만, 앱에서 제품을 조회하고, 이미지를 생성하고, 의상을 추천해야 하는 경우 구조화된 방식이 필요합니다.
