## 스크립트

안녕하세요 여러분, 저는 MEL AI의 선임 응용 엔지니어인 AI Surchi입니다. 오늘은 여러분의 애플리케이션 개발에 MEL AI 모델을 사용해야 하는 세 가지 주요 이유에 대해 이야기하고자 합니다. 첫 번째는 대규모 언어 모델의 경우 투명성이 매우 중요하다는 점입니다. 특히 개발자 입장에서는 모델의 구조를 이해할 수 있어야 성능 향상 및 비용 효율성 개선과 같은 작업을 수행할 수 있습니다. 다행히 MEL AI 모델은 가중치가 공개되어 있습니다. 상업용 라이선스 가중치든 패치 2.0 가중치든 관계 없이 저희 웹사이트에서 다운로드하여 상태 사전을 검토하고 레이어 구조를 이해할 수 있습니다. 그런 다음 SageMaker 또는 Bedrock에서 제공하는 서비스를 사용하여 모델을 추가로 최적화하여 애플리케이션에 더욱 적합하게 만들 수 있습니다. 두 번째는 개발자가 다양한 작업을 위한 애플리케이션을 구축할 때 모델을 선택하고 맞춤 설정할 수 있는 기능이 매우 중요하다는 점입니다. 예를 들어 특정 Java 또는 SQL 언어에 대한 코딩 코파일럿을 구축하는 경우 동일한 모델을 여러 개 사용할 필요는 없습니다. 대규모 모델의 추론 비용을 매번 추론 호출마다 지불하는 것보다 코드에 맞게 커스터마이징된 소규모 모델을 사용하는 것이 훨씬 효율적입니다. 이상적으로는 Mistol을 사용하면 프로덕션 환경에서 모델이 접하게 될 특정 구문 스타일에 맞는 유닛을 찾을 수 있습니다. 프로토 타이핑 단계에서는 대규모 모델을 사용할 수 있지만, 프로덕션 최적화를 고려할 때는 소규모 모델, 심지어는 F 유닛을 사용할 수도 있습니다. Mistol의 가장 큰 장점 중 하나는 바로 이러한 최적화 기능이며, AWS에서 이를 지원합니다. 세 번째 요점을 예로 들어 설명하자면, 여러분의 애플리케이션이 매우 성공적이어서 수천 명의 사용자가 이 앱을 사용하게 되고, 결과적으로 모델을 수억 번 호출하게 된다고 가정해 보겠습니다. 이는 분명 매우 긍정적인 결과이지만, 엄청난 비용이 수반됩니다. 개발자로서 사람들이 반복해서 사용하고 싶어하는 훌륭한 앱을 만들었다면, 좋은 사용자 경험을 제공하면서도 비용을 절감하고 싶을 것입니다. Mistol은 다양한 크기의 모델을 제공하며, 가장 큰 모델에도 Frontier를 지원합니다. 모델 성능은 훨씬 작은 용량으로 구현되므로, Bedrock이나 Sage Maker에서 사용할 때 추론 비용이 다른 모델과 비교했을 때 훨씬 낮습니다. 동일한 기능을 제공하는 다른 모델을 직접 배포하든 API로 사용하든 마찬가지입니다. 따라서 애플리케이션 수명 주기 전반에 걸쳐 Mel에서 적절한 모델을 선택하고 현명하게 사용함으로써 비용을 크게 절감할 수 있습니다. A의 프레젠테이션이 도움이 되었기를 바랍니다. 이 영상이 마음에 드셨다면 좋아요 버튼을 눌러주시고, 더 많은 영상을 보고 싶으시다면 구독 버튼을 눌러주세요. 시청해 주셔서 감사합니다. 다음 영상에서 뵙겠습니다.
