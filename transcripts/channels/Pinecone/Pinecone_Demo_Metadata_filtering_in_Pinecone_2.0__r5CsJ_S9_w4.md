## 스크립트

안녕하세요, 저는 Pinecone의 제품 디렉터인 Dave Bergstein입니다. 오늘은 시맨틱 검색을 활용한 예제를 보여드리겠습니다. Pinecone 2.0 버전의 새로운 기능인 메타데이터 필터링을 사용해 보겠습니다. 먼저 클라이언트 코드를 위해 Python 클라이언트를 가져오겠습니다. 텍스트 임베딩 생성을 위해 문장 변환기 모델을 사용하고, 몇 가지 Python 라이브러리 도 불러오겠습니다. 이 경우 사용할 데이터 세트는 20만 개의 기사 제목으로 구성되어 있으며, 18개의 서로 다른 뉴스 기사 및 잡지에서 가져온 것입니다. 데이터를 불러와서 어떻게 생겼는지 살펴보겠습니다. 제목만 있고, 기사가 게재된 매체, 연도, 그리고 0부터 20만까지 카운트하는 인덱스가 있습니다 . 문장 변환기를 사용할 건데요, 이건 제가 앞서 가져온 패키지에 있는 건데, 거의 기본 설정 그대로 사용할 겁니다. 각 제목을 벡터로 변환할 건데요, model.encode를 사용해서 변환하고 다시 데이터 테이블에 넣을 겁니다. 잠시 기다렸다가 데이터가 어떻게 변했는지 살펴볼까요? 제목, 출판사, 연도, 그리고 각 제목을 인코딩한 벡터의 시작 부분이 보이시죠? 이제 Pinecone을 설정해 보겠습니다. 이 코드를 실행해서 초기화하면 이미 생성된 인덱스가 보이네요. 새 인덱스를 만들 수도 있지만, 시간을 절약하기 위해 기존 인덱스에 연결할 겁니다. 다음으로 방금 생성한 벡터들을 upsert하는 방법을 보여드리겠습니다. 그리고 이건 버전 2.0의 새로운 기능인데요, 메타데이터를 추가해 보겠습니다. 여기 인덱스 번호, 0이 있습니다. 하나, 둘, 셋, 넷. 이걸 문자열로 저장할 거예요. 벡터를 가져올 건데, 이 경우에는 각 제목마다 300개의 부동 소수점 숫자로 이루어져 있어요. 메타데이터를 사용할 건데, 연도, 출판사, 제목을 넣을 거예요. 이걸 딕셔너리에 담고, 각 벡터에 대해 ID, 벡터 자체, 그리고 메타데이터를 업서트할 거예요. 처음 10개까지는 이렇게 할 수 있어요. 보시다시피 비교적 빠르지만, 20만 개 전부 다 할 시간은 없어요. 제가 이미 전에 처리했으니 믿으셔도 돼요. 요약을 보면 각각 300차원의 벡터이고, 총 20만 개의 항목이 있어요. 자, 이제 쿼리를 해볼게요. 예를 들어 " 화성에서 온 우주선"과 비슷한 제목을 찾고 싶다고 가정해 볼게요. 먼저 " 화성에서 온 우주선"이라는 문구를 가져와서 다시 모델에 입력할 거예요. 그러면 벡터 임베딩을 얻게 되겠죠. 이제 이 벡터 임베딩을 기준으로 쿼리할 수 있어요. 상위 5개를 찾아보겠습니다. 결과를 확인해 볼까요? 여기 결과가 있습니다. 유사도 점수를 볼 수 있는데, 코사인 유사도를 사용한 결과입니다. 즉, 코사인 유사도로 계산된 유사도입니다. 그리고 여기에 ID가 있습니다. 이 ID 들을 모두 ID 목록으로 가져와서 데이터 구조에서 추출해 보겠습니다. 어떤 내용인지 살펴볼까요? 여기 있습니다. 유사한 제목들의 제목은 모두 화성과 우주 여행과 관련된 내용입니다. 어떤 출판물에서 나온 것인지, 그리고 벡터도 확인할 수 있습니다. 좋습니다. 이제 필터링을 추가해 보겠습니다. 특정 출판물만 보고 싶다고 가정해 보겠습니다. 예를 들어, 그 출판물이 'New Investigation'이라고 해봅시다. 저는 우주 여행에는 관심이 없고, 공상 과학 소설에 더 관심이 있다고 가정해 보겠습니다. 'New Investigation'은 문학 전문 저널입니다. 다시 한번, 원하는 문구를 입력하고 필터를 적용하여 ' New Investigation'이라는 제목의 출판물만 가져오도록 하겠습니다. 그래서 이 코드를 실행하면 또 다른 ID 집합을 얻을 수 있고, 결과를 살펴보면 우주와 관련된 공상 과학 소설이라는 것을 알 수 있습니다. 더 중요한 것은 이 모든 결과가 새로운 연구 논문에서 나온 것이라는 점입니다. 즉, 우리는 데이터 세트에 있는 모든 벡터 중 메타데이터가 새로운 연구 논문과 일치하는 벡터의 부분 집합에 대해 근사 최근접 이웃 검색을 수행했습니다. 특히 흥미로운 점은 이 작업이 단일 단계에서, 즉 벡터 검색을 수행하는 동시에 완료되었다는 것입니다. 또한 매우 효율적입니다. 시간을 측정해 보면 이전 쿼리에 비해 지연 시간이 훨씬 짧다는 것을 알 수 있습니다. 훨씬 적은 수의 논문을 검색하기 때문입니다. 그러니 버전 2.0을 사용해 보시고 의견을 주시면 감사하겠습니다.
