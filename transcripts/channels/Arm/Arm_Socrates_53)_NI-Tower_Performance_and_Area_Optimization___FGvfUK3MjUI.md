## 스크립트

ASIC에서 동시에 처리하는 올바른 데이터 비트의 수가 많을수록 다운스트림 링크의 활용 효율이 높아져 성능이 향상됩니다. I Tower 구성 요소는 워홀 라우팅을 사용하는데, 워홀 라우팅에서 구성 요소가 패킷의 헤더 FL을 수신하면 해당 패킷의 플릿을 위해 전체 플러드 버퍼를 할당합니다. 처리되지 않은 패킷의 마지막 스플릿을 처리한 후에만 다음 패킷에 FL 버퍼를 사용할 수 있도록 합니다. ASNE 올바른 데이터 FIFO는 AXI 요청자로부터 들어오는 올바른 데이터 비트를 수집합니다. ASNE는 트랜잭션에 대한 올바른 데이터 비트를 수집하여 짧은 시간 내에 가능한 한 많은 플릿을 전송합니다. 따라서 다운스트림 링크를 더욱 효율적으로 사용하고, 처리되지 않은 플릿에 대해 다운스트림 플릿 버퍼에 할당되는 사이클 수를 줄입니다. ASNE 올바른 데이터 F의 크기는 AI를 통과하는 데이터 트래픽 밀도와 올바른 요청 스플릿 크기( 즉, 플릿을 생성하는 데 필요한 데이터 비트 수)라는 두 가지 속성을 기반으로 설정하는 것이 좋습니다. 성능 도구를 사용하면 올바른 데이터 F가 가득 차서 발생한 지연이 있는지 확인할 수 있으며, 이는 결과 통계에서 확인할 수 있습니다. PMU 범주의 성능 테스트 사례에서 별표가 없는 경우, 다른 트래픽 사례에서는 별표가 0이 아닌 값을 보였습니다. 이는 깊이에 대한 오른쪽 데이터 F4 값을 높이면 STS를 방지하고 대역폭을 개선할 수 있음을 시사합니다. 점유율에 대한 평균 오른쪽 데이터 F4 값은 점유율 범주에서 확인할 수 있습니다. 캔버스에서 컴퓨터 인터페이스를 선택하고 속성 편집기 아래의 매개변수를 클릭하여 오른쪽 데이터 F4의 깊이를 수정할 수 있습니다. 오른쪽 데이터 F4 깊이 구성 매개변수는 트래픽을 기반으로 추적기 깊이에서 찾을 수 있습니다. 모든 ASNE에 대해 이 값을 1로 설정하겠습니다. 영역 보고서를 살펴보면 이 구성의 총 영역이 29,990으로 줄어들었습니다. 구성 수정 후에도 성능 요구 사항을 충족하는지 확인하기 위해 동일한 성능 테스트 사례를 실행해 보겠습니다. 성능 요구 사항을 여전히 충족하는 것을 확인할 수 있습니다. 즉, 트래픽을 기반으로 야간 시간 구성 매개변수를 올바르게 조정함으로써 영역 계정을 38,000,587에서 29,990으로 줄일 수 있었습니다. 이는 아무런 손실 없이 영역을 22% 이상 줄인 것입니다. 성능
