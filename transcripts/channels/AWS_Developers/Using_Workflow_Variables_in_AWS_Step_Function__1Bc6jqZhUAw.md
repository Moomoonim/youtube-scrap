## 스크립트

Step Functions 전환 간 데이터 관리를 더 쉽게 하고 싶으신가요? 안녕하세요, 저는 AWS 수석 개발자 겸 옹호자인 Eric Johnson입니다. 개발자들은 AWS Step Functions를 사용할 때, 최상위 작업에서 최하위 작업으로 데이터를 전달할 때, 각 전환마다 데이터를 유지 관리할 필요 없이 더 쉽게 데이터를 전달하고 싶어 한다는 의견을 주셨습니다. 이제 Step Functions 워크플로우 변수를 통해 이러한 요구 사항을 충족할 수 있게 되었습니다. 워크플로우 변수는 Amazon State Language(ASL) 에서 변수를 할당하고 참조할 수 있는 기능을 제공하며, JSON Path와 JSON을 모두 지원합니다. 혹시 Jonata나 Step Functions의 Jonata 지원에 익숙하지 않으시다면, 아래 댓글에 링크된 영상을 참고해 주세요. 이 영상에서는 Jonata를 Step Functions에서 실제로 사용하는 방법을 자세히 설명합니다. 이 영상에서는 Jonata를 사용하여 데모를 보여드리겠습니다. 그럼 데모를 시작해 볼까요? 변수를 할당하려면 Amazon State Language에서 'assign'이라는 새로운 객체를 사용합니다. 여기에서 제가 필요한 변수를 할당하는 예시를 보실 수 있습니다. 이전 소유자에게 권한을 할당하고 있으며 JSON을 사용하여 상태를 관리하고 있습니다. 입력. 이전 소유자에게 새 소유자에게도 동일하게 적용 하고 테이블을 할당합니다. 이제 이전 소유자, 새 소유자, 테이블이 있습니다. 이 테이블을 참조하려면 특정 구문을 사용합니다. 구문은 달러 기호($)와 변수 이름입니다. 추가 문자나 공백은 사용하지 않습니다. 이전과 달리 달러 기호와 점(.) 같은 복잡한 구문을 사용하지 않고 그냥 달러 기호와 변수 이름만 사용합니다. 여기 예시를 보면 테이블 이름이 필요할 때 JSON 자동 래퍼를 사용하여 달러 기호와 테이블이라고 입력합니다. 아래에는 달러 기호와 이전 소유자가 있습니다. 이렇게 하면 테이블이 할당됩니다. 여기서 이해해야 할 점은 실제 워크플로 평가 순서, 즉 변수를 언제 할당하고 어떤 데이터를 할당하는지, 그리고 그 시점에서 데이터의 컨텍스트는 무엇인지입니다. 가장 중요한 것은 변수는 작업이나 하위 워크플로가 실행된 후에도 할당할 수 있다는 것입니다. 즉, 달러 기호로 표시되는 루트 데이터는 실제 작업의 출력이 됩니다. 따라서 한 작업에서 변수를 할당하면 해당 변수는 같은 작업에서는 사용할 수 없지만 다른 작업 에서는 사용할 수 있습니다. 더 아래쪽 작업에 대해 이야기해 보겠습니다. 다음으로 스코핑에 대해 알아보겠습니다. 변수와 관련하여 스코핑이 어떻게 작동하는지 살펴보죠. Step Functions에는 스코프라는 개념이 있습니다. 루트 워크플로인 외부 스코프가 있고, 그 아래에 인라인 맵, 분산 맵, 병렬, 선택 등의 하위 스코프가 있습니다. 외부 스코프에서 변수를 할당하면 대부분의 하위 스코프에서 사용할 수 있습니다. 선택, 병렬, 인라인에서 사용할 수 있지만, 분산 맵에서는 사용할 수 없습니다. 분산 맵은 스코프 외부에 있는 다른 하위 Step Function으로 연결되기 때문입니다. 두 번째 개념은 형제 스코프입니다. 선택, 병렬, 인라인 맵처럼 분기가 있는 경우, 왼쪽 분기에서 변수를 할당하면 오른쪽 분기 나 두 번째 분기에서는 사용할 수 없습니다. 하지만 해당 하위 분기의 후속 작업에서는 사용할 수 있습니다. 두 번째로 이해해야 할 점은 해당 변수가 사용할 수 없게 된다는 것입니다. 외부 스코프에서 자식 스코프는 외부 스코프에 변수를 전달할 수 없지만, 외부 스코프는 자식 스코프에 변수를 전달할 수 있습니다. 이것이 바로 변수 사용에 대한 제한 사항입니다. 지금까지 Step Functions 워크플로 변수에 대한 간략한 개요를 살펴보았습니다. 변수 할당, 변수 참조, 그리고 스코프와 그 작동 방식에 대해 이야기했습니다. 아직 Step Functions의 JSON 관련 영상을 보지 않으셨다면 아래 링크에서 확인해 보시길 권장합니다. 이와 같은 영상을 더 보고 싶으시다면 구독 버튼을 눌러주세요. 저는 AWS의 수석 개발자 Eric Johnson입니다. 다음에 또 뵙겠습니다.
