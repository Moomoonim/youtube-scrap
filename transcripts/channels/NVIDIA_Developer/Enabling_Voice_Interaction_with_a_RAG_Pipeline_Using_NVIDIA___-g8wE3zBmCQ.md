## 스크립트

이 녹화 영상을 보실 때쯤이면 엔비디아가 Reva 음성 인식, 기계 번역 및 음성 합성 서비스를 위한 세 가지 추론 모듈(NIM)에 대한 일반 액세스 권한을 최근에 부여했을 것입니다. NIM은 AI 모델, 애플리케이션 및 서비스를 최적화된 컨테이너로 패키징하여 사용자가 클라우드, 데이터 센터 또는 워크스테이션에서 실행할 수 있도록 합니다. 빌드에서 각 Reva NIM을 사용해 볼 수 있습니다. nvidia.com에서 다운로드하세요. 이 비디오에서는 먼저 NIMS의 가장 기본적인 기능을 살펴보고, 다음으로 자체 시스템에서 NIMS를 실행하고, 마지막으로 RAG 파이프라인에 통합하여 데이터 와 음성 상호 작용할 수 있도록 하는 방법을 알아보겠습니다. 시작해 볼까요? 각 Reva NIMS에는 사용자가 버튼 클릭 한 번으로 기본적인 추론을 수행할 수 있는 랜딩 페이지가 있습니다. 영어 음성을 텍스트로 변환하고, 30개 이상의 언어 중에서 선택하여 텍스트를 한 언어에서 다른 언어로 번역하거나, 텍스트를 자연스러운 음성으로 변환할 수 있습니다. 실제로 어떻게 작동하는지 살펴보겠습니다. NVIDIA Reva Parakeet NIMS의 음성 인식 기능을 시연하고 있습니다. 대문자 사용은 약간 개선이 필요하지만 전반적으로 매우 훌륭하다고 생각합니다. 저는 힌디어를 못하지만 스웨덴어는 제 모국어 중 하나이며, 다행히 지원되는 언어 중 하나입니다. 샘플 텍스트를 영어에서 스웨덴어로 번역해 보겠습니다. 번역이 충분히 정확한 것을 확인할 수 있습니다. 밝은 목소리를 선택하고 샘플 텍스트를 합성해 보겠습니다. Reva 번역은 Megatron 모델을 사용하여 원어에서 대상 언어로 텍스트를 번역합니다. 랜딩 페이지는 Nim의 기본 기능을 탐색할 수 있는 편리한 도구를 제공합니다. Nim의 진정한 강점은 API 호출을 통해 호스팅된 Nim 엔드포인트를 사용하는 고급 NVIDIA GPU 인터페이스에서 실행할 수 있다는 점입니다. 어떤 경우든 NS를 애플리케이션에 통합할 수 있습니다. ren Nim의 API를 사용해 보려면 'API 사용해 보기' 탭의 지침을 따르세요. API 키가 없는 경우 ' 이 Nim으로 빌드' 버튼을 클릭하여 생성할 수 있습니다. 팝업 상자가 자동으로 관리형 API 탭으로 열리고 여기에 API 키가 표시됩니다. 이 데모의 핵심은 시스템에서 ASR 및 TTS Nim을 시작한 다음 NVIDIA의 생성형 AI 예제 GitHub 저장소에 있는 기본 rag 파이프라인에 연결하는 것입니다. 이를 통해 지식 기반에 문서를 업로드하고 해당 문서에 대한 질문을 음성으로 하고 합성된 자연스러운 음성으로 답변을 얻을 수 있습니다. 정식 출시 후에는 docs에서 각 ren Nim의 문서에 액세스할 수 있습니다. nvidia.com의 Nim 문서에 나와 있듯이, 시스템 에서 각 Nim 컨테이너를 실행하기 위한 주요 전제 조건은 Docker 로그인 명령과 API 키를 사용하여 NVIDIA 컨테이너 레지스트리에 로그인하는 것입니다. 로그인 후에는 적절한 환경 변수를 설정하고 제공된 Docker 실행 명령을 실행합니다. 한 번에 하나의 Reva 서비스만 실행하려는 경우, 하나의 Nim 컨테이너를 중지하고 다른 Nim 컨테이너를 시작하기 전에 로컬 nimc 디렉터리를 비우거나 각 Reva Nim에 대해 다른 로컬 Nim 캐시 디렉터리를 지정해야 합니다. 또한 GPU 유형에 따라 Nim 매니페스트 프로필 매개변수를 변경하는 것이 좋습니다. 기본적으로 Nim 컨테이너는 충분히 고급 NVIDIA GPU 에서 실행되는 모델 파일을 다운로드합니다. 그러나 ASR 또는 TTS Nim을 시작할 때 이 매개변수를 적절히 변경하면 h100, a100 또는 l40 GPU에 최적화된 모델 파일을 다운로드하게 됩니다. 이렇게 하면 지원되는 GPU 중 하나에서 더 빠른 추론이 가능합니다. 추가 GPU 유형에 대한 최적화된 Nim 지원은 곧 제공될 예정입니다. 저는 곧 한 시스템에서 ASR 및 TTS Nim을 모두 실행해 볼 예정입니다. H100 GPU를 사용하기 때문에 Nim 매니페스트 프로필 값을 해당 아키텍처에 최적화된 모델을 다운로드하도록 설정했습니다. 두 서비스를 동시에 실행하기 위해 로컬 nimc 값은 각 Nim에 대해 동일합니다. 이제 ASR Nim을 시작해 보겠습니다. 약 20분 정도 소요됩니다. ASR Nim이 준비되었습니다. 문서 의 추론 실행 섹션에 제공된 명령어를 사용하여 컨테이너가 정상적으로 실행 중인지 확인했습니다. Reva Python 클라이언트 저장소의 로컬 복사본 이름을 문서에서 권장하는 이름과 약간 다르게 지정했습니다. 방금 실행한 Python 스크립트는 한 남성이 자연어 처리가 무엇인지 묻는 녹음을 텍스트로 변환합니다. 이제 ASR Nim을 중지 하고 TTS Nim을 시작해 보겠습니다. 구성 모델이 차지하는 전체 공간이 훨씬 적기 때문에 ASR Nim을 시작하는 것보다 훨씬 빠를 것입니다. 하지만 ASR Nim과 TTS Nim 모두 동일한 로컬 Nim 캐시 디렉토리를 사용하기 때문에 TTS Nim은 ASR 및 TTS 모델을 모두 실행합니다. Reva Nim에 연결할 Rag 웹 앱은 NVIDIA의 생성형 AI 예제 저장소의 일부입니다. 이 녹화 영상을 보실 시점에는 공개 GitHub 저장소의 구성이 현재와는 매우 다를 것입니다. 따라서 파일 및 디렉토리 경로를 참조할 때 내부 GitLab 마스터 저장소를 사용하겠습니다. 생성형 AI 예제 저장소를 클론한 후 이 영상을 보실 때쯤에는 두 저장소의 구성이 일치해야 합니다. 가장 중요한 작업은 ` rag SL examplesbasic rag Lang chain docker-compose.yml` 파일을 편집하는 것입니다. RAG 플레이 그라운드 서비스의 플레이그라운드 모드를 음성으로 설정하고, Reva 환경 변수, 특히 Reva API URI를 추가합니다. Reva API URI는 Reva Nims가 실행되는 노드의 IP 주소와 50051 포트로 설정해야 합니다. Reva API URI 값을 정의할 때 따옴표를 사용하지 않도록 주의하세요. 따옴표를 사용하면 Python OS 모듈이 Reva URI를 정의하는 문자열에 따옴표를 포함하여 문제를 일으킬 수 있습니다. Docker Compose 파일을 적절히 편집한 후에는 같은 디렉토리에서 다음 Docker Compose 명령어를 실행하여 컨테이너 네트워크를 시작합니다. 마지막으로, 다음 명령어를 사용하여 네트워크 내의 각 컨테이너가 제대로 작동하는지 확인합니다. 앱을 사용하려면 브라우저에서 로컬 호스트 포트 8090으로 접속해야 합니다. 여기에서 텍스트 또는 음성으로 LLM에 쿼리를 보내고, 사용 가능한 모델이 있으면 해당 버튼을 클릭하여 음성 응답을 활성화할 수 있습니다. Reva ASR 및 TTS 언어는 해당 메뉴에서 선택하여 변경할 수 있습니다. TTS 음성 메뉴도 있습니다. 페이지 오른쪽 상단에 있는 '지식 기반' 탭을 클릭해 보겠습니다. 이 탭을 통해 PDF, 일반 텍스트 또는 마크다운 문서를 업로드할 수 있습니다. 업로드된 문서의 내용은 다차원 벡터에 포함된 후 벡터 데이터베이스에 색인화됩니다. 이 데이터베이스는 LLM에 이전에 학습되지 않았던 지식을 제공합니다. NVIDIA Blackwell GPU 아키텍처 관련 보도 자료 PDF를 업로드해 보겠습니다. 이 녹화 영상이 나오기 4개월 전에 발표되었음에도 불구하고, 이 샘플 웹 앱의 기본 LLM은 이 내용을 알지 못합니다. 이제 PDF를 업로드했으니 '대화' 탭으로 돌아가 보겠습니다. 전체 페이지를 볼 수 있도록 제 영상은 삭제했습니다. 이제 Blackwell에 대해 앱에 질문해 보겠습니다. 엔비디아 블랙웰 GPU에는 트랜지스터가 몇 개나 들어 있나요? 보시다시피 Reva ASR이 제 음성을 정확하고 실시간으로 받아쓰기했습니다. 도와드릴 수 있어서 기쁩니다만, 한 가지 정정해 드려야 할 점이 있습니다. 엔비디아 블랙웰 GPU라는 것은 없습니다. 엔비디아는 수년 동안 여러 GPU를 출시했지만, 블랙웰은 엔비디아에서 공식적으로 발표하거나 알려진 GPU 모델이 아닙니다. 좋습니다. 지식 기반을 사용하지 않으므로 TTS 출력을 중지했습니다. LLM은 블랙웰 GPU에 트랜지스터가 몇 개나 들어 있는지 분명히 모르고 있으며, 엔비디아가 블랙웰 GPU 아키텍처를 발표했다는 사실조차 인지하지 못하고 있습니다. 지식 기반을 사용하여 다시 질문해 보겠습니다. 엔비디아 블랙웰 GPU에는 트랜지스터가 몇 개나 들어 있나요? 텍스트에 따르면 엔비디아 블랙웰 GPU에는 2080억 개의 트랜지스터가 들어 있습니다. 이번에는 전체 RAG 파이프라인을 사용했고, LLM은 정확하게 답변할 수 있었습니다. 이 영상에서는 ASR, TTS, NMT용 새로운 Reva Nims의 랜딩 페이지에 대한 기본 추론을 수행했습니다. 그런 다음 자체 시스템에서 ASR 및 TTS Nims를 시작 하고 간단한 장치에 연결했습니다. 음성 간 상호 작용을 가능하게 하는 Rag 파이프라인을 통해 Reva Nims를 어떻게 활용할 수 있을지 생각해 봅시다. 즐거운 딥 러닝 되세요!
