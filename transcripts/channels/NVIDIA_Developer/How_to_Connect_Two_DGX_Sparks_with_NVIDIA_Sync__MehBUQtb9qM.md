DGX Sparks using the NVIDIA Sync application.&nbsp; The first step is downloading and installing&nbsp;&nbsp; NVIDIA Sync on your Windows, Mac, or&nbsp; Ubuntu laptop. Getting started just&nbsp;&nbsp; requires the licensing agreement, selecting&nbsp; applications for launch, and connecting to a&nbsp;&nbsp; device on the network. Here, the user has a&nbsp; DGX Spark on their home network that NVIDIA&nbsp;&nbsp; Sync discovers through MDNS. Sync requires&nbsp; the device username and password to add it. Adding a device to NVIDIA Sync configures&nbsp; key-based SSH access and lets the user launch&nbsp;&nbsp; applications directly on the remote DGX Spark.&nbsp; Here they launch a terminal on the Spark and run&nbsp;&nbsp; NVIDIA SMI to verify the GP10 system. A terminal&nbsp; isn't the only application that they can launch.&nbsp;&nbsp; They can launch things like VS Code or here the&nbsp; DGX dashboard with a click. Now let's look at the&nbsp;&nbsp; cluster assistant feature of NVIDIA Sync. The&nbsp; cluster assistant is available from the NVIDIA&nbsp;&nbsp; Sync settings window and it requires at least&nbsp; two physically connected GB10 devices to be&nbsp;&nbsp; available on the network. In this case, the two&nbsp; devices to be clustered are not on the user's&nbsp;&nbsp; home network. They're available over a VPN and so&nbsp; the user needs to use the actual IP addresses to&nbsp;&nbsp; add the devices. Once the two Spark devices are&nbsp; added to NVIDIA Sync, the clustering process can&nbsp;&nbsp; start. Selecting add new cluster opens the cluster&nbsp; assistant window and asks you to name the cluster. The next step is to select the devices to be&nbsp; clustered. In this case, the Home Spark should&nbsp;&nbsp; not be selected because it is not physically&nbsp; connected to the other two devices. NVIDIA Sync&nbsp;&nbsp; verifies the devices are physically connected and&nbsp; checks if there's an existing ConnectX-7 network.&nbsp;&nbsp; In this case, the devices are connected and there&nbsp; is no existing network. So, NVIDIA Sync creates&nbsp;&nbsp; one. Once the network is created, NVIDIA Sync&nbsp; tests bandwidth and latency to make sure it's&nbsp;&nbsp; within limits. If it isn't, sync warns you. In&nbsp; this case, things are performing as expected.&nbsp;&nbsp; The cluster requires inter-device communication&nbsp; for process management. NVIDIA Sync automatically&nbsp;&nbsp; configures device-to-device SSH on the connect&nbsp; 7 network with a key pair. The SSH configuration&nbsp;&nbsp; is separate from the SSH configuration used to&nbsp; access each device individually from your laptop.&nbsp;&nbsp; Once the cluster is created, you will need to set&nbsp; up whatever distributed workload you want to run.&nbsp;&nbsp; NVIDIA Sync doesn't yet set up such workloads,&nbsp; but you can use NVIDIA playbooks to learn how&nbsp;&nbsp; to get different things set up and running. The&nbsp; NVIDIA Sync documentation has some suggestions.&nbsp;&nbsp; For example, running NIXL and vLLM on two DGX&nbsp; Spark devices. Overall, we can see that Nvidia&nbsp;&nbsp; Sync makes it straightforward to connect DGX&nbsp; Spark units into a high bandwidth cluster with&nbsp;&nbsp; network setup, performance validation, and SSH&nbsp; configuration all handled automatically.
