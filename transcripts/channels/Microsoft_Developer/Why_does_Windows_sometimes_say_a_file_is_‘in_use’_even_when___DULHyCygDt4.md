## 스크립트

때때로 사람들은 파일이 사용 중인 것을 보고 어떤 애플리케이션이 해당 파일을 사용하고 있는지 궁금해하며, 해당 핸들을 닫아 그 핸들이 가리키는 파일을 삭제하는 방법을 알고 싶어합니다. 믿기 ​​어려우시겠지만, 저는 실제로 1990년대에 이 문제를 겪었고, 그 계기로 handle이라는 도구를 만들게 되었습니다. 그리고 나서 Process Explorer라는 또 다른 도구를 만들었는데, 이 도구들을 사용하면 특정 핸들을 검색하고 해당 핸들을 실행 중인 애플리케이션에서 직접 종료하거나, 적어도 어떤 애플리케이션이나 프로세스가 해당 핸들을 열고 있는지 파악한 후 해당 프로세스를 종료할 수 있었습니다. 그래서 어떤 사람들은 파일이 열려 있다고 생각되는 애플리케이션을 종료해도 파일이 여전히 열려 있는 경우가 있습니다. 이러한 현상이 발생하는 일반적인 이유로는, 예를 들어 안티바이러스 프로그램이 파일을 검사하는 과정에서 시스템 컨텍스트 내에서 해당 파일을 열어 놓은 경우 등이 있습니다. 또는 사용자가 어떤 작업을 수행했고 다른 시스템의 어떤 프로세스가 해당 파일을 열어놓았기 때문에 네트워크를 통해 참조되고 있는 것일 수도 있습니다. 다시 말해, Sysinternals의 Process Explorer와 같은 도구를 사용하면 해당 핸들을 검색하여 왜 열려 있는지, 시스템 컨텍스트에서 실행 중인지 여부를 정확히 파악할 수 있습니다. 윈도우의 또 다른 특징은 파일이 DLL로 프로세스에 로드되면 파일 핸들로 표시되지 않는다는 점입니다. 그것은 메모리 내 [음악] 참조로 나타나는데, 그것은 다른 것입니다. 따라서 열려 있는 핸들은 보이지 않지만, DLL이거나 파일의 주소 공간에 매핑된 경우라면 파일을 삭제할 수 없고, 해당 파일이 주소 공간에 매핑된 애플리케이션을 종료해야만 파일을 삭제할 수 있습니다. 참고로 제가 알고 있는 해결 방법 중 하나는 파일 이름을 바꾸는 것입니다. 그러면 새 버전의 파일을 만들어서 다른 프로세스에서 불러올 수 있습니다 . 자, 여기까지가 파일 핸들과 매핑된 파일, 그리고 윈도우에서 '파일이 잠겨 있습니다'라는 오류가 발생하는 이유입니다.
