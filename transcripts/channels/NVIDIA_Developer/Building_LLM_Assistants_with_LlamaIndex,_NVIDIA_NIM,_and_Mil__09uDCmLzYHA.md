NVIDIA는 대규모 언어 모델을 위한 풀 스택 생태계를 제공하며, 이는 널리 사용되는 오픈 소스 도구와 원활하게 통합됩니다. 이 생태계는 유연성과 성능을 제공하여 개발자가 필요에 따라 다양한 구성 요소 간에 전환할 수 있도록 합니다. NVIDIA는 자체 도구뿐만 아니라 오픈 소스 커뮤니티에도 크게 기여하고 있습니다. 대규모 언어 모델 구축 및 학습을 위한 Nemo와 추론 서비스를 위한 Triton은 NVIDIA의 오픈 소스 기여의 대표적인 예입니다. 이러한 도구는 광범위한 AI 생태계와 잘 통합되어 개발자에게 강력한 GPU 가속 옵션을 제공합니다. LLM 애플리케이션 구축을 위해 Nemo는 단순한 학습 프레임워크를 넘어 개발자의 기능을 향상시키는 여러 오픈소스 구성 요소를 포함하고 있습니다. 주목할 만한 Nemo 구성 요소 두 가지는 Nemo 데이터 큐레이터와 Nemo 가드레일입니다. Nemo 데이터 큐레이터는 데이터 큐레이션 프로세스를 간소화하고, 대량의 비정형 데이터 에서 중복 정보를 추출하고 필터링하여 학습에 필요한 고품질의 관련성 높은 데이터 세트를 확보하는 데 도움을 줍니다. Nemo 가드레일은 모델 출력에 대한 안전 장치 및 제어 기능을 구현하는 데 유용하며, 개발자가 부적절한 응답을 방지하는 가드레일을 추가하여 AI 애플리케이션의 신뢰성과 안전성을 향상시킬 수 있도록 합니다. 자세한 내용은 github.com/envidianemo에서 확인할 수 있습니다. 이제 핵심 기술인 RAG(Retrieval Augmented Generation)에 대해 간략히 살펴보겠습니다. RAG는 LLM에 외부의 최신 지식에 대한 접근 권한을 제공하여 LLM의 성능을 향상시킵니다. 간단히 설명하자면, 먼저 기업 데이터 또는 독점 데이터를 가져옵니다. 이 데이터는 벡터 데이터베이스로 처리됩니다. 작동 방식은 데이터를 청크로 분할한 다음, 이를 벡터 임베딩으로 변환하는 것입니다. 빠른 검색을 위해 벡터 데이터베이스에 저장되어 있으므로 사용자가 추론 시점에 쿼리를 제출하면 임베딩으로 변환됩니다. 그런 다음 엔터프라이즈 데이터를 사용하여 생성된 벡터 데이터베이스를 검색하는 데 사용됩니다. 가장 관련성이 높은 정보가 검색되고 순위가 매겨집니다. 쿼리 와 검색된 정보는 모두 대규모 언어 모델에 입력되어 사전 학습된 지식과 데이터베이스의 특정 관련 정보를 기반으로 응답을 생성합니다. 이 프로세스를 통해 챗봇은 일반적인 응답과 기존 데이터 또는 엔터프라이즈 데이터에 특화된 응답을 모두 제공할 수 있으며, 검색과 생성을 결합하여 더욱 정확하고 맥락에 맞는 답변을 제공합니다. 이제 NVIDIA 도구 및 기타 오픈 소스 구성 요소를 사용하여 이러한 파이프라인을 구현하는 방법을 살펴보겠습니다. 먼저 아카이브에서 최신 LLM 기술에 대한 연구 자료를 가져왔습니다. 이 연구 자료는 챗봇 지식 기반의 기반이 됩니다. GPU 가속 도구를 사용하여 대규모 데이터 세트를 더 빠르고 효율적으로 처리할 것입니다. 특히, NVIDIA 추론 마이크로서비스(NYSS)는 호스팅된 LLM 및 임베딩 모델에, MILIS는 GPU 가속 벡터 검색에 사용됩니다. 임베딩 모델에는 NVIDIA의 GPU 가속을 활용하여 텍스트를 고차원 벡터로 빠르게 변환하는 NVEmbed를 사용합니다. 벡터 저장 및 유사도 검색에는 대규모 유사도 검색을 놀라운 속도로 처리할 수 있는 GPU 가속 벡터 데이터베이스인 MILIS를 사용합니다. GPU 인덱싱 및 쿼리를 사용하려면 CPU 인덱싱에 비해 최대 처리량과 지연 시간 감소를 위해 수많은 쿼리 벡터 또는 매우 높은 요청 압력이 필요하다는 점에 유의해야 합니다. 따라서 NVEmbed와 MILIS의 GPU 가속은 채팅 부트의 성능을 크게 향상시켜 아카이브 문서의 인덱싱 및 쿼리 속도를 높여줍니다. 실제 질문 답변에는 NVIDIA의 NiM API를 통해 액세스되는 대규모 언어 모델, 특히 Lama 3 70b 명령어 모델을 사용합니다. 이를 통해 최첨단 언어 모델의 강력한 기능과 GPU 가속의 속도를 결합하여 실시간 응답을 제공할 수 있습니다. 사용자 경험을 개선하기 위해 마지막으로 Llama Index를 사용하여 쿼리 처리부터 관련 정보 검색 및 응답 생성에 이르기까지 전체 프로세스를 관리합니다. Nim API 키가 환경 변수로 설정되어 있는지 확인하고, 인덱스와 쿼리 엔진을 저장할 전역 변수를 설정합니다. 이 변수들은 문서가 로드될 때 초기화됩니다. 이제 문서 로딩을 처리하는 함수를 만들어 보겠습니다. ` get files from input` 함수는 파일 객체에서 파일 이름을 추출하고, `load document` 함수는 파일을 읽고, 밀리초 벡터 저장소를 사용하여 인덱스를 생성하고, 쿼리 엔진을 설정합니다. 다음으로 채팅 기능을 구현합니다. `chat` 함수는 기본적인 질문과 답변 기능을 담당하고, ` stream response` 함수는 응답을 처리합니다. 이 기능은 응답 스트리밍을 가능하게 하여 더욱 상호작용적인 경험을 제공합니다. 이제 Gradio 인터페이스를 설정해 보겠습니다. 문서 업로드를 위한 파일 입력란과 문서 로딩 버튼, 질문을 위한 채팅 인터페이스, 그리고 채팅 기록을 지우는 버튼을 만들겠습니다. 이제 인터페이스 구성 요소를 각각의 기능에 연결하겠습니다. 로딩 버튼은 문서 로딩을 실행하고, 메시지 입력란은 스트리밍 응답을 시작하며, 지우기 버튼은 채팅 기록을 초기화합니다. 마지막으로 스크립트가 실행될 때 Gradio 애플리케이션이 실행되도록 코드를 추가하겠습니다. 이제 터미널에서 이 앱을 실행해 보겠습니다. 앱을 실행하려면 간단히 ` python`을 입력하면 됩니다. 터미널에서 이 명령을 실행하면 웹 서버가 시작되고, 이 서버를 통해 앱에 접속할 수 있습니다. 보시다시피 이 웹 앱은 로컬 URL 인 Local Host에서 포트 번호 78760으로 실행되고 있습니다. 이제 이 URL로 접속해 보겠습니다. 이제 Rag Q&amp;A 차트 애플리케이션이 실행되었으니 어떻게 작동하는지 보여드리겠습니다. 먼저 데모를 위해 몇 가지 문서를 가져오겠습니다. 저는 NVIDIA의 연구 논문을 준비했습니다. 이 영역에서 파일을 선택하려면 아무 곳이나 클릭하면 됩니다. 보시다시피 여러 파일을 한 번에 선택할 수 있습니다. 이 경우에는 PES 파일 두 개를 모두 선택하겠습니다. 파일을 선택한 후 " 문서 로드" 버튼을 클릭합니다. 그러면 문서 로드 프로세스가 시작되어 파일을 읽고 내용을 처리한 다음 빠른 검색을 위한 인덱스를 생성합니다. 새 데이터를 추가하려는 경우가 아니라면 모든 애플리케이션 로드 시 인덱스를 생성할 필요는 없습니다. 좋습니다. 문서가 성공적으로 로드되었다는 확인 메시지가 표시됩니다. 이제 이 논문의 내용에 대한 질문을 시작할 준비가 되었습니다.
