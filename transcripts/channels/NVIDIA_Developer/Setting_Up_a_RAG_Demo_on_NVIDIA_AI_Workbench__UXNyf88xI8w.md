## 스크립트

안녕하세요, NVIDIA AI Workbench에서 RAG 데모를 설정하는 방법에 대한 비디오에 오신 것을 환영합니다. 이 비디오는 대규모 언어 모델(LLM)과 RAG를 실험해보고 싶지만, GPU 가속 컨테이너 환경을 완벽하게 구축할 기술이 항상 있는 것은 아닌 분들을 위해 제작되었습니다. NVIDIA AI Workbench란 무엇일까요? 바로 노트북의 가상화된 Linux 컨테이너 환경에서 AI 프로젝트 전체를 실행할 수 있도록 해주는 매우 간편한 도구입니다. 복잡한 명령어를 입력하거나 소프트웨어를 설치하고 웹에서 수많은 사용 설명서를 찾아볼 필요 없이, 초보자가 AI 세계에 쉽게 입문할 수 있도록 도와주고, 숙련된 데이터 과학자에게도 작업 환경을 빠르게 구축하고 공유할 수 있는 편리한 방법입니다. 그럼 이 LLM 및 RAG 데모를 실행하는 데 필요한 것은 무엇일까요? 시스템 요구 사항은 비교적 낮습니다. PC에 16GB RAM, Windows 10 또는 Windows 11이 필요하며, Linux와 Mac에서도 실행됩니다. 또한 약 40GB의 disbase 공간이 필요합니다. 솔직히 말해서 마지막 부분은 좀 의심스럽습니다. Workbench를 설치하기 전과 후에 disbase 공간을 확인해 봤는데, RAG 데모를 실행하기 전에는 160GB의 여유 공간이 있었고, 이후에는 80GB가 남았습니다. 따라서 시작하기 전에 최소 80GB의 여유 공간을 확보해 두는 것이 좋습니다. AI Workbench의 가장 큰 장점 중 하나는 GPU 가속 워크플로우를 GPU 리소스가 있는 곳이라면 어디에서든 실행할 수 있다는 것입니다. 좋은 GPU가 있다면 워크스테이션에서 llm 프로젝트를 로컬로 실행할 수 있고, 네트워크의 GPU 가속 서버에서 실행할 수도 있으며, NGC(Nvidia GPU Cloud)와 같은 클라우드 기반 API 엔드포인트를 사용할 수도 있습니다. 저희 데모에서는 NGC를 사용할 예정이므로 노트북에 GPU가 없어도 데모를 실행할 수 있습니다. 자, 그럼 시작해 볼까요? Workbench를 실행하기 전에 github.com에 접속하여 계정을 만들어야 합니다. 사용자 ID와 비밀번호를 입력하기만 하면 되는 아주 간단한 과정입니다. GitHub 시스템에서 사용자 이름을 생성하세요. 이 계정을 통해 데모 진행 중에 GitHub에서 프로젝트를 저장하고 검색할 수 있습니다. 데모를 시작하기 전에 몇 가지 지루한 검증 테스트를 거쳐야 합니다. 이 과정을 시작하면 곧 포털에 접속할 수 있습니다. 인증 코드가 포함된 이메일도 발송될 예정이니, 실제 사용자임을 확인하기 위해 해당 코드를 입력해 주세요. 처음 몇 화면은 GitHub 환영 화면일 뿐이며, 그 외에는 거의 모든 준비가 완료되었습니다. 다음으로 ngc.com 또는 nc로 이동해야 합니다. nvidia.com에 접속하여 계정을 만드세요. 개인 이메일 주소와 회사 이메일 주소를 입력하고 비밀번호를 설정한 후, 본인 인증을 해야 합니다. 몇 가지 테스트를 거쳐야 하는데, 요즘 AI 때문에 사람인지 확인하는 게 점점 어려워지는 것 같네요. 이메일 주소 인증도 해야 하고요. 인증이 완료되면 몇 가지 화면만 더 거치면 됩니다. 프로필을 설정하고 본인에 대한 정보를 입력하면 몇 초 안에 NGC에 로그인할 수 있습니다. 자, 이제 워크벤치에서 NGC에 접속할 수 있도록 개인 키를 설정해 보겠습니다. 이 키는 사용자 ID와 비밀번호를 대신하는 역할을 합니다. 키 이름은 '워크벤치'로 하고, 만료 기간은 이 경우 12개월로 설정합니다. NGC의 모든 서비스를 이용할 수 있도록 모든 서비스 에 접근 권한을 부여합니다. 설정이 완료되면 키를 복사할 수 있는 옵션이 나타나는데, 꼭 복사해 두세요. 키를 바로 저장하세요. 나중에 다시 사용할 수 없으니, 여기에 저장해 두세요. 워드 문서나 이메일 등 안전한 곳에 저장해 두면 나중에 필요할 때 다시 사용할 수 있습니다. 이제 NGC를 사용할 건데, 이 추론 작업을 하려면 NGC에 크레딧이 얼마나 있는지 확인해야 합니다. NGC에서는 크레딧을 확인할 수 없지만, 빌드 메뉴로 이동하면 확인할 수 있습니다. nvidia.com은 AI 모델 호스팅 분야에서 NGC를 점차 대체하고 있는 또 다른 웹사이트입니다. 여기 프로필 섹션으로 이동하면 크레딧 수를 확인할 수 있습니다. 이 데모에서 추론 요청을 보내거나 LLM에 질문을 할 때마다 크레딧이 1씩 차감됩니다. 즉, 추론 요청 하나당 1크레딧이 소모됩니다. 그럼 가입 ​​시에는 몇 크레딧을 받게 될까요? 보시 다시피 회사 이메일 주소를 사용하면 NGC와 nvidia.com에서 모델을 사용해 볼 수 있는 5,000크레딧을 받게 됩니다. nvidia.com에서 개인 이메일 주소를 사용하면 1,000 크레딧만 받을 수 있습니다. 원하시면 더 요청하실 수 있으며, 전혀 문제없습니다. 자, 이제 AI Workbench를 설치해 보겠습니다. 화면 하단에 있는 URL로 이동하여 다운로드 버튼을 클릭하세요. 그러면 설치 프로그램이 워크스테이션에 다운로드됩니다. 다운로드된 디렉토리로 이동하여 파일을 두 번 클릭하세요. 관리자 권한이 필요 하므로 설치 과정에서 관리자 권한을 몇 번 요청할 것입니다. 여기에서 설치 시작 아이콘을 클릭하면 Windows Subsystem for Linux(Windows Subsystem for Linux)에 대한 안내가 나옵니다. 이것은 Windows 워크스테이션에서 컨테이너와 애플리케이션을 실행할 수 있는 가상 Linux 환경입니다. 따라서 Windows Subsystem for Linux를 설치해야 합니다. 기본 운영 체제에 대한 액세스 권한을 몇 번 요청할 것입니다. 워크스테이션에서는 문제없이 설치될 것입니다. 설치 후에는 재부팅이 필요합니다. 이렇게 하면 몇 초 후에 워크스테이션이 재부팅됩니다. 재부팅이 완료되면 다시 시작되므로 워크스테이션을 재부팅해 보겠습니다. 워크스테이션이 다시 시작되면 Workbench 설치에 필요한 Linux 배포판 다운로드가 자동으로 진행됩니다. 만약 설치가 제대로 되지 않으면 명령줄에서 ` WSL - 설치`를 입력하고 Workbench를 다시 실행하여 문제를 해결할 수 있습니다. 설치가 완료되면 다음과 같은 애플리케이션 오류가 발생할 수 있습니다. 가상화 지원과 관련된 문제일 가능성이 높으므로 워크스테이션 BIOS에서 가상화가 설치되어 있고 활성화되어 있는지 확인하십시오. 이 작업은 5분에서 10분 정도 소요될 수 있습니다. 완료되면 다음 질문이 나타납니다. 이제 사용할 컨테이너 런타임 환경을 선택해야 합니다. Docker를 사용할 수 있지만, Docker를 직접 설치해야 합니다. 이 데모에서는 Docker의 경량 버전인 Podman을 사용하는 것을 권장합니다. 계속 진행하기 전에, 아까 만들어 둔 GitHub 계정에 로그인해서 설치를 준비해 두겠습니다. 잠시 후 워크벤치 환경과 GitHub 간의 연결 및 로그인을 활성화하기 위해 코드를 입력해야 합니다. 자, 이제 Podman을 선택하고 다음 버튼을 클릭합니다. 관리자 권한이 필요하니, 이 과정을 다시 진행하겠습니다. 몇 분 정도 소요될 수 있으니, 지루한 과정은 빨리 감기로 처리하겠습니다. 이제 GitHub에 로그인해서 워크벤치에서 프로젝트를 저장하고 검색할 수 있도록 GitHub와의 연결을 설정해야 합니다. 그러면 인증 코드가 생성되는데, 이 코드를 GitHub에 입력해야 합니다. 이 페이지를 옆에 두고 인증 코드를 입력하겠습니다. 제가 추천하는 방법은 이 작업을 비교적 짧은 시간 안에, 빠르게 진행하는 것입니다. 그렇지 않으면 시간 초과가 발생하여 다시 여기에 들어가서 NVIDIA가 GitHub Pages에 액세스할 수 있도록 승인하고 비밀번호를 다시 확인해야 하기 때문입니다. 그러면 모든 준비가 완료되고 자동으로 응답이 올 것입니다. 자, 이제 Workbench 프로젝트를 시작해 볼까요? 여기로 들어가면 먼저 " Workbench에 오신 것을 환영합니다"라는 메시지가 표시되고 기본 위치가 설정됩니다. 이 경우 기본 위치는 로컬 워크스테이션입니다. 원격 워크스테이션, 원격 서버 또는 클라우드 엔드포인트 등 원하는 대로 설정할 수 있지만, 이 경우에는 로컬 워크스테이션에 연결하여 프로젝트를 시작할 것입니다. 여기에서 프로젝트를 시작할 수도 있지만, 이번에는 GitHub에서 이미 있는 프로젝트를 복제할 것입니다. 자, 이제 GitHub에 접속해야 합니다. 이미 로그인되어 있습니다. 문제가 발생했고, 우리는 거기서 프로젝트를 복제할 겁니다. 여기 URL이 있는데, github.com 사용자 프로젝트를 예상하고 있습니다. 제가 아래쪽에 강조 표시한 페이지로 이동하면 이것이 우리의 RAG, 즉 하이브리드 RAG 프로젝트임을 알 수 있습니다. 아래로 스크롤하면 이 프로젝트에 포함된 내용, 실행 방법 등 자세한 정보를 볼 수 있습니다. 먼저 이 프로젝트를 포크해야 합니다. 즉, 원본 프로젝트에 영향을 주지 않고 다른 사람들과 작업, 공유, 동기화할 수 있도록 이 프로젝트를 우리 저장소로 복제해야 합니다. 자, 몇 초 후에 이 프로젝트의 포크를 만들겠습니다. 워크벤치에서 이 프로젝트를 로컬 PC로 복제하는 데 사용할 사용자 지정 URL을 만들 겁니다. 복사를 누르겠습니다. 이제 워크벤치로 돌아가서 Ctrl+V로 여기에 붙여넣고 복제를 누릅니다. 이 단계에서 모든 하위 디렉터리 구조와 모든 정보가 복제됩니다. GitHub 페이지에서 제 로컬 워크스테이션으로 다운로드했습니다. Workbench 하단을 보시면 '빌드'라는 섹션이 있는데, 현재 34개 중 1번째입니다. 이 프로젝트를 완전히 빌드하는 데 약 30분 정도 걸릴 것 같습니다. Workbench의 가장 큰 장점은 바로 이것입니다. 필요한 모든 구성 요소와 종속성을 스크립트 기반으로 자동으로 설치해 줍니다. 덕분에 반복해서 사용하기가 매우 편리합니다. 빌드 과정은 약 분 정도 소요되는데, 대부분의 과정은 빨리 감기로 처리하겠습니다. 기다리는 동안 Windows Subsystem for Linux(WSL)에 대해 간단히 설명드리겠습니다. Windows 시작 메뉴에서 WSL을 입력하면 링크를 클릭할 수 있습니다. 클릭하면 Windows 워크스테이션에 Linux 환경이 생성되고, 여기에서 일반적인 Linux 작업( 예: CD 명령, 디렉터리 변경 명령)을 수행할 수 있습니다. 이 경우 ` CD slome SL workbench` 명령어를 실행하면 실제로 이 디렉토리로 이동하여 Workbench가 생성한 하위 디렉토리 구조의 내용을 보여줍니다. 이 하위 디렉토리 구조 안으로 더 들어가면 복제된 프로젝트를 볼 수 있습니다.
