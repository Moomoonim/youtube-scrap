## 스크립트

[음악] 이제 가중치 및 편향 사용자가 봇에게 질문할 수 있는 간단한 웹 애플리케이션을 구축할 준비가 되었습니다. 설정 P에서 시작해 보겠습니다. 가중치 및 편향 프로젝트를 포함한 구성을 정의합니다. 팀에서 작업하는 경우 작업 유형을 설정하고 팀을 설정하여 가중치 및 편향 엔티티를 지정합니다. 또한 벡터 저장소와 PROM 템플릿을 어디에서 가져올지 정의합니다. 이 경우 이전 비디오에서 생성한 가중치 Andis 아티팩트를 사용합니다. 애플리케이션 실행에 사용할 모델도 설정할 수 있습니다. 또한 체인에 정의된 여러 함수를 사용할 것입니다. 특히, pi 파일에서 벡터 저장소를 로드하려고 합니다. 벡터 저장소는 이전에 문서를 수집한 후 업로드한 Weight Andes 아티팩트에서 가져옵니다. 또한 체인도 로드해야 하는데, 여기서는 LongChain 의 대화형 QA 체인을 사용합니다. OpenAI의 Chat 모델을 사용할 것이며, 3.5 Turbo 또는 GPT 4 중에서 선택할 수 있습니다. 이 경우 설정에서 GP Chat GPT( 3.5 Turbo 모델)를 정의하고, 구성 파일 에서 가져온 매개변수를 정의합니다. 그런 다음 LongChain에 정의된 유틸리티인 대화형 검색 체인을 반환하고, 이 체인을 애플리케이션에 전달하여 사용자의 질문에 응답할 수 있도록 합니다. 마지막으로, 체인과 사용자 질문을 사용하여 응답을 제공하는 GetAnswer 함수가 있습니다. 이제 애플리케이션으로 돌아가서, 간단한 Gradio 사용자 인터페이스를 웹 애플리케이션으로 노출할 것입니다. 벡터 저장소와 체인을 저장하는 Chat 클래스를 정의하고, 이 클래스가 인터페이스 H가 되도록 합니다. 사용자 호출 사이에는 구성과 가중치 실행이 필요합니다. 가중치 실행은 벡터 스토어와 체인(채팅 인터페이스라고 부르는 것)을 포함한 아티팩트를 가져오는 데 사용됩니다. 백그라운드에서 벡터 스토어나 체인이 로드되지 않은 경우, 해당 데이터를 로드하여 채팅 객체에 저장합니다. 그런 다음 '답변 가져오기' 함수를 사용하여 응답을 생성하고 기록에 추가합니다. Gradio 블록을 사용하여 사용자 인터페이스를 정의합니다. 구체적으로, 사용자 질문을 입력하는 텍스트 상자와 OpenAI API 키를 지정하는 텍스트 상자가 있습니다. 사용자에게 API 키를 공개하고 싶지만 공유하고 싶지 않은 경우, 이 경우에는 환경 변수로 설정했으므로 제공할 필요가 없습니다. 하지만 웹에 애플리케이션을 공개하고 OpenAI API 호출을 후원하지 않으려면 사용자에게 자체 키를 제공하도록 요청할 수 있습니다. 또한 챗봇 객체의 상태도 저장하고 있으며, 사용자가 질문을 제출할 때마다 해당 객체를 호출합니다. 채팅 객체는 기본 설정과 함께 제공되며, 질문과 상태를 전달하면 사용자 인터페이스에 표시할 수 있는 답변을 받습니다. 이제 이 애플리케이션을 실행하고 브라우저에서 어떻게 보이는지 확인해 보겠습니다. 다시 말하지만, 우리는 가중치와 편향을 사용하여 벡터 저장소와 문서를 가져오고 있으며, 애플리케이션은 로컬 URL에서 실행됩니다. 이 링크를 클릭하면 브라우저를 통해 Q&amp;A가 표시되는 것을 볼 수 있습니다. 이 애플리케이션을 배포할 수도 있습니다. 예를 들어, 페이스북이나 리플릿에 배포하는 등 여러 가지 방법이 있지만, 이 과정에서는 배포에 대한 자세한 내용은 다루지 않겠습니다. 하지만 이 비디오 아래에 제공되는 추가 링크를 확인하여 다양한 배포 옵션을 살펴보시기 바랍니다. 이제 챗봇에게 질문을 해서 제대로 작동하는지 확인해 보겠습니다. 답변이 표시됩니다. 팀원과 보고서를 공유하려면 보고서를 저장하고 공유 버튼을 클릭하는 등의 단계를 따라야 합니다. 이 부분이 맞을 수도 있지만, 보기에는 그렇지 않습니다. 사실 이전 영상에서 비슷한 쿼리를 살펴보고 검색 체인을 구현했을 때와는 조금 다릅니다. 이 체인이 실제로 어떻게 실행되었는지, 벡터 저장소에서 어떤 데이터가 검색되었는지, 어떤 문서가 프롬프트에 입력되었는지 살펴보는 것도 흥미로울 것입니다. 이를 위해 Weights and Bias 트레이서를 사용할 수 있습니다. 자, 한번 살펴보겠습니다. Weights and Bias에 들어가면 환경 변수 `LchainWbetracing`을 ` true`로 설정해야 합니다. 즉, 모든 쿼리와 응답이 Weights and Bias로 스트리밍되어 분석됩니다. 이를 통해 무엇이 잘 되었는지, 무엇이 잘못되었는지 확인할 수 있습니다. 이 경우 웹 인터페이스에서 질문했던 내용("팀원들과 보고서를 공유하는 방법")과 사용자 인터페이스에서 보았던 답변을 확인할 수 있습니다. 또한 추적 타임라인, 즉 최종적으로 결과물을 생성하기까지의 함수 호출 순서를 볼 수 있습니다. 마지막으로 대화형 검색 체인을 확인할 수 있습니다. L 체인에서 정의한 다음, L 체인에서 가져온 여러 입력 문서로 구성된 문서 체인을 호출합니다. 그런 다음 LLM 체인으로 드릴다운하고 최종적으로 OpenAI에 도달하면 템플릿에 포함된 모든 문서를 포함하는 프롬프트를 볼 수 있습니다. 이 문서 목록을 스크롤하면 템플릿의 시스템 부분과 같은 것을 볼 수 있습니다. 벡터 스토어에서 가져온 다양한 문서를 볼 수 있습니다. 이 목록을 스크롤하면 협업 및 Q&amp;A 보고서 공유에 대한 문서를 찾을 수 있습니다. 이 문서에는 보고서를 저장한 후 공유 버튼을 선택하여 협업할 수 있으며, 편집 버튼을 선택하면 보고서 초안 사본이 생성되어 저장된다는 내용이 나와 있습니다. 이것이 실제로 LLM 체인의 답변에 영향을 미친 요소입니다. Weight Invis Tracer를 사용하면 디버깅을 통해 백그라운드에서 어떤 일이 발생했는지, 답변을 생성하기 위해 어떤 API 호출 순서가 수행되었는지 이해할 수 있습니다. 이 경우, 프롬프트에서 이 출력을 생성하는 데 사용된 문서를 찾았습니다. 이런 식으로 오류 분석을 할 수 있습니다. 사용자가 일부 응답을 도움이 되지 않는다고 생각할 경우, 어떤 문제가 발생했는지 확인 하고 자세히 살펴볼 수 있습니다. 예 를 들어 특정 쿼리에 대해 올바른 문서가 검색되지 않았을 수 있으며, 문서 검색 및 검색 사이트를 개선해야 할 수도 있습니다. 또는 모델의 성능이 좋지 않아 프롬프트 내에서 올바른 답을 찾지 못했을 수도 있습니다. 이 경우 프롬프트 설계를 개선하거나 더 강력한 모델로 변경하는 등의 방법으로 문제를 해결할 수 있습니다. GPT 3.5에서 GPT 4, Anthropology Clo 또는 Coher Command 모델로 전환하는 것도 고려해 볼 수 있습니다. 다양한 옵션이 있으며, 이러한 실험을 통해 애플리케이션을 개선할 수 있습니다. 다음 모듈에서는 애플리케이션 개선 및 결과 평가를 위한 체계적인 실험 프로세스를 개발하는 방법을 살펴보겠습니다. 그때 뵙겠습니다.
