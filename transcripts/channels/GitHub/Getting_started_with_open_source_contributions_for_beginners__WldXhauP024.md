## 스크립트

오픈 소스 프로젝트에 기여하고 싶지만 어떻게 시작해야 할지 모르시나요? 자, 오늘은 그 방법을 알려드리겠습니다. 이 영상을 끝까지 보시면 오픈 소스가 무엇인지, 참여할 음악 프로젝트를 찾는 방법 , 오픈 소스 저장소를 읽는 방법 등을 알게 될 것입니다. 안녕하세요, [음악] 저는 카니샤이고 오늘 이렇게 함께해 주셔서 정말 기쁩니다 . 제 친구 앤젤라가 오픈 소스의 세계를 탐구하고 여러분이 처음으로 오픈 소스 프로젝트에 기여하는 방법을 알려줄 거예요. 고마워, 카니샤. [음악] 오픈 소스 소프트웨어(Open source software, 줄여서 OSS)는 소스 코드를 자유롭게 이용할 수 있는 소프트웨어를 말합니다. 클로즈드 소스 소프트웨어와는 대조적으로 오픈 소스 소프트웨어는 누구나 자유롭게 사용하고 개발할 수 있도록 공개되어 있습니다 . 이는 코드 기반과 사용자 간의 소통을 포함한 모든 작업 내용이 누구나 볼 수 있도록 공개되어 있음을 의미합니다. 소프트웨어 개발의 세계에 이제 막 발을 들여놓았다면, 오픈 소스 프로젝트를 살펴보고 기여하는 것은 전 세계 수많은 사용자가 이용하는 영향력 있는 대규모 프로젝트에 참여할 수 있는 좋은 방법입니다. GitHub는 오픈 소스 소프트웨어의 본거지입니다. 그럼, 여러분이 참여할 수 있는 프로젝트를 찾는 방법을 알려드리겠습니다 . 오픈 소스 프로젝트 (음악)에 처음으로 참여하는 것은 부담스러울 수 있습니다. 제게는 효과가 있었어요. 기여할 프로젝트를 찾기 위해 가장 먼저 할 수 있는 일은 자신이 아는 언어로 만들어진 프로젝트를 찾아보는 것입니다. GitHub Copilot Chat을 사용하면 특정 프로그래밍 언어로 작성되었고 새로운 기여자를 받고 있는 오픈 소스 프로젝트를 찾을 수 있습니다. GitHub에서 Copilot 아이콘을 클릭하여 새 대화를 시작하세요 . 그런 다음 " TypeScript로 작성되었고 새로운 기여자를 받고 있는 오픈 소스 프로젝트 목록을 찾고 있습니다."라는 메시지를 입력하세요. GitHub에서 검색하고, ' good first issue' 레이블을 사용하며 GitHub에서 별 100개 이상을 받은 저장소로 목록을 좁히세요 . Copilot은 ' 첫 번째 이슈가 괜찮았음'이라는 레이블로 필터링된 탐색 가능한 프로젝트 목록을 반환합니다. '좋은 첫 이슈'라는 표시는 해당 이슈가 초보자에게 친숙하고 새로운 기여자에게 훌륭한 출발점임을 나타냅니다. 이는 프로젝트에서 개선할 수 있는 문제점을 찾아내는 훌륭한 방법입니다 . 예를 들어, VS Code 저장소에 기여하는 데 관심이 있고 처음 시작하기 좋은 이슈를 찾고 싶다고 가정해 보겠습니다. GitHub에서 VS Code 리포지토리로 이동하여 이슈를 클릭하세요. 그런 다음 레이블을 클릭하고 첫 번째 발행 상태가 좋은 것으로 필터링합니다. 작업할 수 있는 미해결 문제 목록이 표시됩니다. 이슈 작업을 시작하려면 프로젝트 저장소에 있는 기여자 가이드를 읽어야 합니다 . 그럼 오픈 소스 프로젝트에서 찾아야 할 핵심적인 요소들을 살펴보겠습니다 . 잘 관리되는 오픈 소스 프로젝트에는 몇 가지 공통점이 있습니다. 해당 프로젝트는 설치 지침이 포함된 잘 정리된 README 파일, 기여 방법을 설명하는 기여자 가이드, 오픈 소스 라이선스를 통해 누구나 자유롭게 사용할 수 있는 프로젝트임을 알 수 있고, GitHub에서 최소 100개 이상의 스타를 획득하여 커뮤니티에서 널리 사용되고 있음을 보여주며, 활발한 개발을 통해 오픈 소스 소프트웨어 관리자가 기여 내용을 검토할 수 있음을 보장하고, 새로운 기여자를 환영한다는 것을 나타내는 적절한 첫 번째 이슈 레이블을 가지고 있습니다 . 프로젝트에 기여하고 싶을 때, 저장소에서 다음과 같은 사항들을 확인해야 합니다 . 이 프로젝트, Gitfolio가 [음악] 우리에게 잘 맞는지 한번 살펴볼까요? 이 저장소는 제가 기여하고 싶어할 만한 것 같고, 프로그래밍 언어 면에서도 제 적성에 딱 맞습니다. 또한 문서화가 잘 되어 있는 것 같고, 코드 기여 방법을 알려주는 contributing.md 파일도 있습니다. 해당 저장소는 최근에 업데이트되었으므로 활발하게 유지 관리되고 있다고 생각합니다. 자, 그럼 오픈 소스 저장소에 처음으로 기여하는 방법을 보여드리겠습니다. 좋은 오픈 소스 프로젝트를 찾는 방법에 대한 자세한 내용은 gh.io/gfiboss를 참조하세요. [음악] 프로젝트 홈페이지로 이동하여 포크 버튼을 클릭하고 새 포크를 생성하세요. 포크는 저장소의 복사본입니다 . 우리는 일반적으로 오픈 소스 저장소에 기여할 때 포크를 사용합니다. 포크를 사용하면 원본 프로젝트에 영향을 주지 않고 자유롭게 변경 사항을 실험해 볼 수 있기 때문입니다. 소유자를 저로 설정하고 저장소 이름과 설명은 그대로 유지하겠습니다. 엄청난. 이제 우리는 저장소의 자체 복사본을 갖게 되었습니다 . 포크된 저장소에서 문서 부분을 간단히 수정하겠습니다. 이는 저장소에 처음으로 제기된 중요한 문제 중 하나였습니다. GitHub UI를 통해 변경 작업을 진행하겠지만, 저장소를 복제하거나 코드 스페이스를 사용하셔도 됩니다. 여기서 변경 사항을 적용하고, 이 변경 사항을 제가 포크한 저장소의 브랜치에 커밋하겠습니다. 이제 변경 사항이 포함된 제 브랜치를 사용하여 원본 프로젝트에 풀 리퀘스트를 열겠습니다 . 포크 간 비교를 클릭하여 내 포크의 변경 사항과 원본 저장소의 변경 사항을 비교해 보겠습니다. 자, 이제 풀 리퀘스트에 간단한 제목과 설명을 추가해 봅시다 ! 이제 관리자의 검토를 거쳐 승인을 받을 준비가 되었습니다. 승인 및 병합이 완료되면 GitHub는 자동으로 내 포크의 변경 사항을 원본 저장소( 코드베이스의 공식 소스)의 메인 브랜치에 적용합니다. 앤젤라, 출연해 주시고 첫 오픈 소스 기여 방법을 알려주셔서 정말 감사합니다. 오픈 소스 소프트웨어의 정의부터 좋은 오픈 소스 프로젝트를 찾는 방법, 포크를 통해 오픈 소스 프로젝트에 기여하는 방법까지 많은 내용을 다뤘습니다. 이것이 여러분이 좋아하는 음악 프로젝트에 기여하는 데 영감을 주기를 바랍니다. 자세한 내용은 방송 노트에 있는 링크를 확인하세요. 이 영상이 도움이 되었기를 바랍니다. GitHub의 YouTube 채널을 구독하시면 앞으로 업로드될 영상을 놓치지 않고 시청하실 수 있으며, 이 정보가 필요한 개발자 친구와도 공유해 주세요 . 즐거운 코딩 되세요.
