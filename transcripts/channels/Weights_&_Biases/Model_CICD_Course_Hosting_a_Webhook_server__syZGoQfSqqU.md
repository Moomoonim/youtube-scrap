## 스크립트

지난 섹션에서 로컬에 웹훅을 생성했으므로 이제 웹훅의 기본 개념을 이해했을 것입니다. 웹훅은 웹 서버가 요청을 수신하고, 이에 대한 응답으로 함수를 실행하거나 다른 작업을 수행하는 것입니다. 이제 좀 더 현실적인 프로덕션 수준으로 웹훅 서버를 클라우드에 호스팅하는 단계로 넘어가겠습니다. 제 생각에 가장 쉬운 방법은 Modal과 같은 도구를 사용하는 것입니다. Modal은 머신러닝 엔지니어를 위한 서버리스 파이썬 환경입니다. 기본적으로 Google Cloud 제품인 Cloud Functions와 비슷하지만, 특히 머신 러닝 엔지니어를 위해 서버리스 방식으로 코드를 배포하도록 설계되었습니다. Modal에 대해 자세히 설명하지는 않겠지만, 매우 가볍고 시작하기 쉽고 누구나 접근할 수 있다는 점을 말씀드리고 싶습니다. 가입 후 첫 30달러 크레딧은 무료입니다. 따라서 시작하는 것은 매우 간단할 것입니다. 그럼 시작해 보겠습니다. 먼저 코드를 살펴볼 건데요, GitHub 저장소를 확인해 보겠습니다. 아직 이 저장소를 클론하지 않으셨다면, 제 GitHub 사용자 이름인 haml SMU로 클론해 주세요. 저장소 이름은 WDB 모달 웹훅입니다. 클론하시면 이 저장소에 이번 강의에서 사용할 모든 코드가 들어 있습니다. 이제 VS Code 에디터에서 README 파일을 열어서 더 큰 글씨로 볼 수 있도록 하겠습니다. 음, 가중치(weights)에 대한 내용인데요, 이 저장소는 웹훅을 이용해 가중치와 편향(bias)을 통합하는 예시를 보여줍니다. 특히 모달과의 통합에 초점을 맞추고 있죠. 하지만 웹훅을 사용하기 때문에, 가중치와 편향을 다른 어떤 것과도 연결하는 최소한의 예시일 뿐입니다. 웹훅은 매우 범용적이기 때문에, 앞서 설명했듯이 다양한 인프라에서 외부와의 통신 채널을 제공하는 데 사용됩니다. 세계 와 그리고 이것이 바로 Weights and Bias에 웹훅 트리거가 있는 이유입니다. 하지만 Weights and Bias에 대해 자세히 알아보기 전에, Weights and Bias가 접근할 수 있는 곳에 웹훅 서버를 호스팅해야 합니다. 그러려면 클라우드에 서버를 구축해야 하므로, 먼저 ` pip install modal` 명령어를 실행해야 합니다. 저는 먼저 가상 환경을 생성하는 것을 추천합니다. ` pip install modal` 명령어를 사용하거나, 제가 선호하는 `cond` 명령어를 사용하면 됩니다. 그런 다음 ` modal` 클라이언트도 설치합니다. Modal에 로그인하면 계정을 생성하게 됩니다. 다음으로 해야 할 일은 시크릿을 생성하는 것입니다. 이전에 시크릿 랜덤 토큰을 생성했던 것을 기억하시죠? 이제 "시크릿 생성"을 클릭해 보겠습니다. 시크릿 영역으로 이동하고, "새 시크릿 생성"을 클릭한 다음 "사용자 지정"으로 이동합니다. 여기에서 Weights and Bias 시크릿을 찾을 수 있습니다. 지금은 그 부분은 논의하지 않고, 사용자 지정 시크릿을 생성해 보겠습니다. 사용자 지정 시크릿은 매우 유연하기 때문입니다. 자, 여기 있는 O 토큰을 여기에 붙여넣고, 여기에 무작위 시크릿 토큰을 붙여넣겠습니다. 그런 다음 ' 다음'을 클릭하고 시크릿 이름을 'myrandomSecret'으로 지정하겠습니다. 코드가 제대로 작동하려면 이름을 정확하게 입력해야 합니다. 실수하기 쉬우니 주의하세요. ' Seeker가 생성되었습니다'라는 메시지가 표시될 겁니다. 이 코드는 시크릿을 가져오는 최소한의 예시를 보여줍니다. 코드는 곧 자세히 살펴보겠지만, 이 내부 코드, 즉 'myrandomSecret'이 환경 변수에 저장되는 것을 볼 수 있을 겁니다. 자, 이제 지난 연습에서 만들었던 웹 서버를 열어 보겠습니다. 모달 에 표시하려면 약간의 리팩토링이 필요합니다. 모달에 대해 자세히 설명하지는 않겠지만, Fast API 서버와 모달의 차이점을 보여드리겠습니다. 이전에 만들었던 코드와 이번 코드의 차이점을 보여드리겠습니다. 여기서 보시는 것처럼 변경된 부분은 다음과 같습니다. 가장 중요한 변경 사항은 Modal 라이브러리와 이미지 생성에 필요한 Secret 같은 Modal 유틸리티를 가져온 것입니다. Docker 이미지를 빌드하기 위해 Fast API와 Pantic이 포함된 Docker 이미지를 생성하고, 애플리케이션 이름을 지정하는 데 사용하는 '스텁'이라는 것을 추가했습니다. 그리고 Fast API 데코레이터 대신 Modal에서 제공하는 데코레이터를 사용하는데, 기능은 거의 동일합니다. Secret과 웹 엔드포인트를 가져올 수 있는 특별한 데코레이터를 추가한 것입니다. 나머지 코드는 완전히 동일합니다. 이 코드가 정확히 무엇을 하는지는 너무 신경 쓰지 않으셔도 됩니다. 대부분은 기본 코드라고 생각하시면 됩니다. 이 변경 사항은 클라우드에 배포할 수 있도록 최소한의 기능만 추가한 것이며, 환경 변수를 하드코딩하는 대신(하드코딩은 바람직하지 않으니까요) Modal에서 제공하는 데코레이터를 사용하는 것입니다. 실제로는 이 값이 환경 변수, 특히 Modal 에서 설정한 토큰 환경 변수에서 가져옵니다. 다시 README 파일로 돌아가서 미리 보기를 해보겠습니다. 다시 여기에 놓으면 잘 보입니다. 다음으로 Modal 웹훅을 배포해야 합니다. 배포하려면 여기로 가서 ` modal deploy`를 클릭하면 server.py 파일이 생성됩니다. 빠르네요. 제가 이전에 배포해 본 적이 있기 때문에 Modal은 데이터를 지능적으로 캐싱합니다. 배포가 완료되면 두 개의 링크가 표시됩니다. 첫 번째 링크는 웹훅의 엔드포인트입니다. 로컬 호스트 대신 여기에 페이로드를 보낼 수 있습니다. 두 번째 링크는 로그를 확인할 수 있는 곳입니다. 배포 현황을 보려면 여기를 클릭하세요. 배포가 완료된 것을 볼 수 있습니다. 이제 로그를 보려면 여기를 클릭하세요. 로그 수신 대기 중이며 다음과 같습니다. 현재 로그가 없습니다. 음, 다음으로 할 일은 해당 웹 엔드포인트로 페이로드를 보내는 것입니다. 이를 위해 이 URL을 사용할 수 있으며, 동일한 curl 스크립트를 사용할 수 있습니다. curl 스크립트에 무엇이 있는지 다시 한번 알려드리겠습니다. curl 스크립트는 단순히 URL로 curl 명령을 보내는 것입니다.
