GitHub 초보자를 위한 코스에 다시 오신 것을 환영합니다. 지난 시즌에는 GitHub Copilot을 살펴보았고, 이번 시즌에는 기본으로 돌아가 GitHub의 핵심 기능을 살펴보겠습니다. 그 시작은 GitHub의 가장 강력한 협업 도구 두 가지인 GitHub Issues와 Projects입니다. 이 비디오를 끝까지 시청하시면 이슈를 생성하는 방법, 이슈를 GitHub 프로젝트 보드에 동기화하는 방법, 그리고 GitHub 프로젝트를 사용하여 작업을 추적하는 방법을 알게 될 것입니다 . [음악] 안녕하세요, 저는 카데샤입니다. 오늘 이렇게 함께해 주셔서 정말 기쁩니다 . GitHub 이슈 와 프로젝트를 활용하여 체계적으로 정리 하고 효율적으로 협업하는 방법에 대해 이야기해 보겠습니다. [음악] 자, 그럼 시작해 볼까요? GitHub 이슈와 프로젝트는 체계적인 관리를 원하는 모든 팀에게 필수적인 도구입니다 . 이슈 기능을 사용하면 작업, 버그 및 아이디어를 명확하고 공유된 공간에서 추적할 수 있습니다. 프로젝트를 통해 업무를 시각화하고, 우선순위를 정하고, 계획할 수 있으며, 개별적인 문제를 모든 사람이 따를 수 있는 실행 가능한 워크플로로 전환할 수 있습니다 . 이슈와 프로젝트를 결합함으로써 팀은 업무를 조율하고, 진행 상황을 소통하며, 모든 구성원이 동일한 목표를 향해 나아가도록 할 수 있습니다. 오늘 제 친구 리즈가 이슈와 프로젝트를 결합하여 더욱 협업적인 방식으로 작업하는 방법을 보여줄 거예요. GitHub 이슈를 사용하면 새로운 아이디어, 버그 또는 작업 등 프로젝트에서 주의가 필요한 모든 것을 간단하게 기록할 수 있습니다. 그들은 팀이 협력적으로 일하고, 체계적으로 업무를 처리하며, 모든 사항이 처리되도록 돕습니다. GitHub 이슈를 생성하는 방법을 살펴보겠습니다. 저희는 gh.io/ghb-issues 저장소를 사용할 예정입니다. 그러니 부담 없이 따라오세요. 저장소의 메인 페이지에서 ' 이슈' 탭을 클릭한 다음 '새 이슈' 버튼을 클릭하고 명확한 제목을 지정하세요. 이 기능의 이름을 '다크 모드 토글 추가'라고 하겠습니다. 설명란에 필요한 작업에 대한 자세한 내용을 추가하세요. 이 예시에서는 다크 모드 토글 버튼의 ​​용도를 설명할 수 있습니다. 이제 이 업무를 팀원이나 저 자신에게 할당할 수 있습니다. ' 개선 사항' 또는 '좋은 첫 번째 이슈'와 같은 레이블을 추가하세요. 버그나 작업과 같은 유형을 추가하고, 더 큰 릴리스의 일부인 경우 마일스톤에 연결할 수도 있습니다 . 이슈는 GitHub에서 소통과 프로젝트 관리의 핵심입니다. 그들은 당신의 업무를 체계적으로 정리하고, 아무것도 분실되거나 잊히지 않도록 해줍니다. 이슈가 생성되면 팀의 누구든 참여하여 댓글을 달 수 있습니다. 간단한 업데이트 내용을 추가하겠습니다. 작업이 완료되면 해당 이슈를 닫으면 됩니다. 해시 태그와 이슈 번호를 입력하여 여러 이슈를 연결할 수도 있습니다. 그래서 댓글에 해시태그 33을 입력하면 해당 이슈 해시태그 33으로 연결되는 클릭 가능한 링크가 생성되는데, 이는 관련 작업을 추적하는 데 매우 유용합니다 . 이 기능은 풀 리퀘스트를 관련 이슈에 연결하는 데에도 사용할 수 있습니다 . 자, 그럼 GitHub 프로젝트에 대해 이야기해 봅시다. 프로젝트는 음악 관련 문제를 시각적 대시보드에서 그룹화할 수 있는 방법을 제공하여 계획, 구성 및 작업 추적에 매우 유용합니다. 이는 큰 목표를 관리 가능한 작업으로 나누어 한 곳에서 모두 추적할 수 있도록 도와주는 도구입니다. 프로젝트 보드를 만들려면 저장소의 메인 페이지에서 프로젝트 탭으로 이동하세요 . 그다음은 새로운 프로젝트입니다. GitHub에서 몇 가지 템플릿 옵션을 제공하므로 처음부터 모든 것을 만들 필요가 없다는 것을 알 수 있을 것입니다 . 칸반 보드 템플릿을 선택하고 제목을 지정해 보겠습니다. 저는 이것을 포트폴리오 사이트 개발이라고 부르겠습니다. 저장소에서 열린 이슈를 프로젝트 보드로 가져오는 옵션을 선택 해제한 다음, 프로젝트 생성 버튼을 클릭하겠습니다. 이 템플릿 옵션을 사용하면 GitHub에서 자동으로 열을 설정해 주지만, 원하는 대로 사용자 지정할 수도 있습니다. 프로젝트 보드에 대한 다양한 관점이 있다는 것도 알게 되실 겁니다. 백로그 보기, 우선순위 보드 보기, 팀 항목 보기, 로드맵 보기, 내 항목 보기. GitHub 프로젝트 및 이슈에 대한 자세한 내용은 문서를 참조하세요. 이 에피소드와 관련된 블로그 게시물은 gh.io/ghfb-issues에서 읽으실 수 있습니다. 프로젝트 보드를 관리하려면 점 세 개를 클릭하고 설정을 클릭하세요. 이 페이지에서는 프로젝트 보드에 대한 접근 권한을 관리하고, 필드를 생성하고, 기존 필드를 업데이트하고, 프로젝트 이름과 설명을 수정하고, 프로젝트 보드용 README 파일을 생성할 수도 있습니다. 이곳에서 프로젝트 보드를 복사하거나 프로젝트의 공개 여부를 변경할 수도 있습니다. 인사이트 탭을 클릭하면 차트를 보고, 만들고, 맞춤 설정할 수 있습니다. 차트의 레이아웃은 옵션 버튼을 클릭 하고 드롭다운 메뉴에서 옵션을 선택하면 변경할 수 있습니다. 워크플로 탭을 클릭하면 특정 이벤트에 따라 항목 상태를 업데이트하는 데 사용할 수 있는 내장 워크플로를 볼 수 있습니다. 예를 들어, 프로젝트에 항목이 추가될 때 상태를 자동으로 '수행 중'으로 설정할 수 있습니다 . 프로젝트에서 이슈의 상태가 변경되면 이슈를 닫거나, 이슈가 닫히면 상태를 완료로 설정하세요. GitHub 프로젝트에서 '상태 업데이트 추가' 버튼을 클릭하면 프로젝트 상태 및 진행 상황에 대한 보고서를 추가할 수 있습니다. 자, 이제 이슈와 프로젝트가 어떻게 서로 연관되어 여러분의 업무를 전체적으로 조망할 수 있도록 하는지 살펴보겠습니다. 문제를 개별적인 작업으로, 프로젝트를 이러한 작업을 정리하는 대시보드로 생각하십시오 . 이슈를 프로젝트 보드에 연결하면 모든 진행 상황을 한눈에 시각화할 수 있습니다. 프로젝트 보드가 열리면 열 하단의 더하기 버튼을 클릭하여 새 항목을 추가합니다. 여기서 새 이슈를 생성하거나 기존 이슈를 검색할 수 있습니다. 이전에 제기 했던 다크 모드 토글 추가 문제를 추가하겠습니다 . 저장소에서 항목 추가를 클릭하겠습니다 . 저장소를 선택한 다음 추가하려는 이슈를 선택하세요 . 모든 이슈를 선택하여 프로젝트 보드에 한 번에 추가할 수도 있습니다. 제 프로젝트에서 해당 문제가 카드 형태로 나타나는 것을 확인해 보세요. 작업 진행 상황에 따라 백로그에서 진행 중, 완료 순으로 열 사이를 드래그하여 이동할 수 있습니다. 해당 문제를 클릭하면 자세한 내용을 볼 수 있습니다. 그리고 여기서부터가 멋진 부분입니다. 여기서 이슈 상태를 업데이트하면 모든 곳에 업데이트됩니다 . 내 프로젝트 보드와 이슈 페이지는 자동으로 동기화됩니다. 여러 이슈를 한 번에 이동하고, 워크플로에 맞춰 열로 정리하고, 카드를 완료 위치로 끌어당길 때의 만족감을 느낄 수 있습니다. 이제 이 모든 것을 팀 프로젝트에서 실제로 사용할 수 있는 워크플로에 적용해 보겠습니다 . 먼저, 저희 사이트에 내비게이션 메뉴를 추가하는 것에 대한 새로운 이슈를 생성하겠습니다 . 명확한 제목을 붙이고, 설명에 구현 세부 정보를 추가하고 , 개선 사항으로 표시하겠습니다 . 다음으로, 그것을 제 프로젝트 보드에 추가합니다 . 그건 내 백로그 항목에 추가돼요 . 이제 팀원에게 이 업무를 배정하겠습니다 . 그들은 이 문제가 이제 자신들의 책임이라는 알림을 받게 될 것입니다. 작업이 진행됨에 따라 팀원은 업데이트 내용을 댓글로 남길 수 있고, 저는 보드에서 카드를 이동시킬 수 있습니다 . 연락처 양식을 구현하기 위한 풀 리퀘스트를 열 때, 풀 리퀘스트 설명에 "closes hash 34"라고 입력하여 이 이슈를 참조할 수 있습니다. GitHub는 자동으로 이들을 연결해 줍니다. 해당 풀 리퀘스트가 병합되면 이슈는 자동으로 닫힙니다. 이 워크플로는 지속적인 회의 없이도 모든 구성원의 업무 진행 상황을 파악할 수 있도록 해줍니다 . 알아야 할 모든 정보는 이슈와 프로젝트 보드에 있습니다. 이제 GitHub에서 이슈와 프로젝트를 사용하여 작업을 정리하는 방법을 알게 되었습니다 . 몇 가지 간단한 문제부터 시작해서 프로젝트 보드를 차근차근 구축해 나가면 팀 규모에 맞춰 확장 가능한 시스템을 갖추게 될 겁니다. 이 영상이 도움이 되었기를 바랍니다.
