## 스크립트

안녕하세요! 시계열 데이터를 많이 다루시거나 InfluxDB를 사용하여 시계열 데이터를 저장하고 쿼리하는 것을 좋아하시나요? InfluxDB를 AWS에서 실행할 수 있다는 사실을 알고 계셨나요? 저는 AWS 개발자 옹호자(Developer Advocate)인 데릭 빙햄(Dererk Bingham)입니다. 이번 영상 에서는 AWS에서 InfluxDB용 TimeStream을 사용하여 InfluxDB 인스턴스를 생성하는 방법을 보여드리겠습니다. 인스턴스는 관리되므로 서버 관리와 같은 복잡한 작업은 신경 쓸 필요가 없습니다. 그럼 바로 시작해서 얼마나 쉽고 빠르게 할 수 있는지 알아보겠습니다. 여기 AWS 콘솔이 있습니다. Amazon TimeStream을 검색해서 클릭해 보겠습니다. 여기 있네요. Amazon TimeStream 서비스를 열면 실시간 분석용 TimeStream과 InfluxDB용 TimeStream이 표시됩니다. 이번에는 InfluxDB용 TimeStream을 생성할 것입니다. 여기를 클릭하면 DB 인스턴스 이름과 같은 몇 가지 정보를 입력해야 합니다. 이 인스턴스를 '데릭 데모 인플럭스'라고 이름 짓고, 사용자 이름, 조직 이름, 초기 버킷 이름을 지정합니다. 인플럭스 데이터베이스를 사용해 보신 적이 있다면 모두 익숙하실 테지만, 처음 사용하시는 분들을 위해 설명드리자면, 인스턴스에 로그인하려면 사용자 이름이 필요하고, 기본 조직 이름과 버킷 이름도 필요합니다. 로그인하려면 사용자 이름과 함께 비밀번호도 입력해야 합니다. 자, 여기 제 비밀 비밀번호가 있습니다. 다음으로 인스턴스 구성을 시작해 보겠습니다. 인스턴스 크기, 실행 영역(Zone) 등을 설정할 수 있는데, 이 모든 설정은 인플 럭스 워크로드에 최적화되어 있습니다. 16x Large(64 CPU)부터 1 CPU( 이 데모에서는 1 CPU를 선택하겠습니다)까지 다양한 옵션이 있습니다. 스토리지 유형도 최대 16,000 IOPS부터 최소 3,000 IOPS까지 변경할 수 있는데, 저는 3,000 IOPS로 실행하겠습니다. 스토리지 용량도 20GB부터 그 이상까지 선택할 수 있습니다. 프로덕션 환경에서 사용하는 다중 AZ 배포 또는 단일 AZ 배포 중에서 선택할 수 있는데, 저는 단일 AZ를 사용하겠습니다. 데모에서는 VPC도 변경할 수 있습니다. 즉, 인스턴스가 실행되는 VPC의 위치와 서브넷을 지정할 수 있습니다. 서브넷과 보안 그룹을 통해 인스턴스에 대한 액세스를 엄격하게 제한할 수 있으며, 공용 IP 주소 할당 여부도 정의할 수 있습니다. 이 데모에서는 공용 IP 주소를 할당하도록 설정하겠습니다. 인스턴스에 전달할 파라미터 그룹과 S3 버킷에 저장할 로그 위치도 정의할 수 있습니다. S3 버킷에 대해 알아야 할 몇 가지 사항이 있으므로 S3 서비스에서 간단히 살펴보겠습니다. 새 탭을 열고 S3 서비스로 이동하면 됩니다. 먼저 버킷을 생성해야 합니다. 가장 먼저 확인해야 할 것은 AWS 리전입니다. S3 버킷의 AWS 리전은 InfluxDB 인스턴스와 동일한 리전이어야 합니다. 다음으로 버킷 이름을 지정합니다. 예를 들어 " 데릭 데모 인플루언스 DB"와 같이 지정합니다. 나머지 설정은 기본값으로 두고 " 생성"을 클릭하면 버킷이 생성됩니다. 버킷이 생성되면 액세스 권한을 추가해야 합니다. 포트 설정은 S3 권한에서 아래로 스크롤하여 버킷 정책을 찾고 추가를 클릭하면 됩니다. 저는 이미 정책을 생성했으므로 해당 정책을 붙여넣고 설명해 드리겠습니다. 이 정책에서는 특정 서비스 주체인 TimStream InfluxDB를 허용합니다. Amazon aws.com은 InfluxDB용 타임스트림 서비스 주체입니다. 또한 특정 버킷인 리소스에 대한 액세스 권한을 제한해야 하므로 이를 지정합니다. 이렇게 하면 권한 설정이 완료됩니다. 이제 InfluxDB용 타임스트림으로 돌아가면 S3 버킷이 표시되고 로그 위치로 선택할 수 있습니다. 좋습니다. 이제 InfluxDB 데이터베이스를 생성해 보겠습니다. 이 창이 사라지고 InfluxDB 데이터베이스가 생성되면 목록에 나타나고 상태는 '생성 중'으로 표시됩니다. 데이터베이스를 클릭하여 자세한 정보를 확인할 수 있습니다. 상태를 확인하려면 엔드포인트가 표시되면 '생성 완료'입니다. 엔드포인트는 InfluxDB UI에 액세스하는 방법입니다. 프라이빗 VPC를 사용하는 경우 프라이빗 VPC 내의 다른 서버를 통해 SSH로 접속해야 하지만, 퍼블릭 VPC를 사용하므로 InfluxDB UI에 바로 액세스할 수 있습니다. UI가 초기화될 때까지 기다린 후, 이전에 생성한 자격 증명으로 로그인합니다. 이전에 InfluxDB를 사용해 본 적이 있다면 이 UI가 익숙할 것입니다. InfluxDB UI는 매우 익숙해야 합니다. 시작하는 데 도움이 되는 편리한 마법사가 몇 가지 있는데, 그중 하나가 CLI 설정입니다. 저는 이미 CLI를 설정했고, 이제 CLI로 넘어가 보겠습니다. 제가 설정한 CLI에는 인증 토큰이 이미 설정되어 있어서 제가 가진 InfluxDB 인스턴스에 접근할 수 있습니다. 테스트해 보면, ` influx org list` 명령어를 실행했을 때 제 Derek 조직에 접근 가능한 것을 확인할 수 있습니다. 다음으로, 제 버킷이 해당 조직 안에 있는지 확인하기 위해 `bucket list` 명령어를 실행하면, 맨 아래에 Derek InfluxDB 버킷이 있고 사용 가능한 것을 볼 수 있습니다. 이제 다음 단계는 시계열 데이터를 해당 버킷으로 전송하는 것입니다. 이 작업도 InfluxDB CLI를 사용하여 수행합니다. 물론 CLI를 사용하지 않고 다양한 API와 오픈 소스 라이브러리를 활용하여 시계열 데이터를 InfluxDB로 전송할 수도 있습니다. 이러한 라이브러리들은 모두 Amazon TimeStream과 호환됩니다. 인플럭스 DB를 예로 들자면, 이 예시는 인플럭스 DB 웹사이트에서 바로 가져온 것입니다. 지정된 버킷에 시계열 데이터를 전송하는 예시인데, 데이터가 버킷에 들어가면 인플럭스 DVI로 돌아가서 어떻게 표시되는지 확인할 수 있습니다. 데이터 탐색기에서 이 작업을 수행하므로 데이터 탐색기로 이동해 보겠습니다. 여기에는 두 개의 핀이 있는데, 하나는 플럭스 스크립트를 사용하여 쿼리를 편집하는 쿼리 편집기이고, 다른 하나는 상단에 있는 그래프 영역입니다. 먼저 스크립트 편집기로 이동해 보겠습니다. 인플럭스 DB를 사용해 본 경험이 있다면 플럭스 스크립트에 익숙하실 텐데, 이는 인플럭스 DB에 수집된 시계열 데이터를 쿼리하는 방법입니다. 저는 특히 제 버킷 안에 있는 데이터를 살펴볼 것입니다. 여기서 ' 인플럭스 DB'는 지정된 버킷을 가리키고, 해당 버킷 안에서 저는 특정 데이터에 관심이 있다고 가정합니다. 특정 시간 또는 시간 범위를 지정하려면 ` range` 키워드를 사용해야 합니다. ` range`를 입력하면 자동 완성 기능이 있어 Flux 스크립트를 정확하게 작성하는 데 도움이 됩니다. ` range` 키워드 또는 함수를 사용하려면 두 개의 시간대와 두 개의 타임 스탬프(아, 죄송합니다. 두 개의 타임스탬프입니다.)를 지정해야 합니다. 타임 스탬프는 모두 줄루어로 작성되며 시작 시간과 종료 시간이 있습니다. 제가 관심 있는 시간 범위 내의 모든 시계열 데이터를 찾고 있으므로 시작 및 종료 타임 스탬프를 지정합니다. Flux 쿼리를 작성했으면 실행하면 여기에 결과가 표시됩니다. 여기에서 지정한 시간 범위 내의 모든 데이터가 반환된 것을 볼 수 있습니다. 하지만 이것이 데이터를 시각화하는 가장 좋은 방법은 아닐 수 있습니다. 데이터 탐색기를 사용하면 사용되는 그래프를 변경할 수도 있습니다. 여기 위의 드롭다운 메뉴에서 그래프 와 단일 통계(그다지 유용하지 않음) 또는 다른 그래프로 변경할 수 있습니다. 히스토그램이 바로 이것입니다. Amazon TimeStream을 사용하여 InfluxDB를 설정했습니다. 보시다시피 시계열 데이터를 인스턴스에 수집하고 데이터 탐색기를 사용하여 처리할 수 있었습니다.
