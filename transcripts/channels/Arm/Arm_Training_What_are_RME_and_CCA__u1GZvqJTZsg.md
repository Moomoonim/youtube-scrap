## 스크립트

안녕하세요 여러분, 이 영상은 RCCA와 RME에 대한 개요 영상입니다. 이 영상에서는 RME와 그 이점, 보안 모델, MCCA, RME, 그리고 동적 데이터 영역(Dynamic Data Zone) 간의 관계에 대해 다룹니다. 또한, 4대 영역 개념을 사용하여 RME 아키텍처를 살펴보고 RCCA의 잠재적 사용 사례에 대해서도 논의해 보겠습니다. 먼저 RCCA에 대해 알아보겠습니다. 기밀 컴퓨팅(Confidential Computing, RME)에는 여러 가지 보안 문제가 있습니다. 타사 하이퍼바이저 또는 클라우드 컴퓨팅 제공업체가 신뢰할 수 있는 실행 환경(Trusted Execution Environment, TEE)의 데이터를 오용하지 않을 것이라는 신뢰, 모든 시스템 구성 요소가 취약점 및 공급망 공격으로부터 안전한지 확인하는 것, 시스템 내 다른 소프트웨어로부터 애플리케이션 데이터를 격리하는 것, 메모리 암호화 침해 및 운영 서버에 대한 물리적 접근을 차단하는 것, 그리고 하이퍼바이저 또는 다른 시스템 구성 요소가 애플리케이션에 사용되는 주변 장치의 데이터를 엿볼 수 없도록 하는 것 등이 있습니다. 그렇다면 MCCA는 이러한 문제를 어떻게 해결할까요? RME 데이터는 시스템 내 다른 소프트웨어 구성 요소와 격리되어 작고 검증 가능한 신뢰할 수 있는 컨티뉴어티드 기반 소프트웨어, 펌웨어 및 하드웨어를 갖춘 새로운 보안 상태로 이동됩니다. 시스템 보안을 보장하기 위해 모든 시스템 부팅 시 소프트웨어와 하드웨어가 검증됩니다. 이제 각 구성 요소는 4대 영역으로 동적으로 할당된 메모리를 갖게 됩니다. 하드웨어 수준에서 다른 시스템 엔티티와 격리된 킬로바이트 단위의 세분성을 갖는 메모리 암호화 컨텍스트(RME)를 통해, 서로 다른 시스템 엔티티를 다른 시스템 엔티티와 독립적으로 암호화할 수 있으므로 공격자의 공격 표면을 줄일 수 있습니다. 장치는 신뢰할 수 있는 실행 환경(TEE)에 동적으로 할당될 수 있으며, TEE는 시스템의 다른 엔티티가 데이터를 보거나 액세스할 수 없도록 하면서 장치와 해당 데이터를 독점적으로 사용할 수 있습니다. 그렇다면 RME란 무엇일까요? ARMv 93a의 RAM 관리 확장(RME)은 Realm이라는 새로운 유형의 검증 가능한 격리 환경을 지원합니다. RME는 CCA와 함께 사용되는 하드웨어 기능으로, CCA의 보안 및 격리 기능을 향상시킵니다. 이 교육을 진행하면서 프로젝트에서 Realm을 활용하여 보안 및 격리를 개선하는 방법을 생각해 보세요. 이 기술을 통해 업무에서 어떤 잠재적인 응용 프로그램을 구상할 수 있을까요? RME, RCCA, 동적 트리 영역(DTE)의 경계는 무엇일까요? RME는 RCCA의 하드웨어 구성 요소이며, 이를 통해 풍부한 가상 머신과 하드웨어로 강화된 인 클레이브인 Realm을 사용할 수 있습니다. RME를 사용한다고 해서 반드시 Realm을 사용해야 하는 것은 아닙니다. 장치 할당을 통해 장치를 하나 이상의 Realm에서 사용하도록 특정 할당할 수 있으며, 이 경우 해당 데이터는 다른 곳에서 볼 수 없습니다. 시스템 내의 다른 소프트웨어 엔티티가 접근할 수 있는 장치를 증명하고 필요한 RAM에 직접 할당하여 다른 소프트웨어 엔티티의 접근을 차단합니다. 장치가 손상된 경우 시스템에서 아예 사용할 수 없도록 합니다. 메모리 암호화 컨텍스트(RCCA)는 시스템 내의 다양한 소프트웨어 엔티티를 개별적으로 암호화하여 메모리 암호화를 효과적으로 구획화합니다. RME는 또한 보안이 접근할 수 있는 물리적 메모리 범위를 정의하는 새로운 세분화된 보호 테이블을 도입하여 보안 리소스의 동적 할당을 가능하게 합니다. 동적 트러스트 영역 또는 ARM CCA를 사용하려면 RME가 필요합니다. ARM CCA 또는 ARM 기밀 컴퓨팅 아키텍처는 기밀 컴퓨팅을 강화하기 위해 도입되었습니다. CCA는 RME와 RMM, RMI, RSI와 같은 기밀 컴퓨팅 실행에 필요한 소프트웨어로 구성됩니다. RCCA는 펌웨어 파티셔닝과 EL3 모니터의 격리를 도입하여 더욱 강력한 신뢰 경로 및 증명 서비스를 제공합니다. 또한 메모리 보호 엔진을 통해 안전하게 할당된 DAM의 모든 데이터를 암호화합니다. 동적 트러스트 영역은 일반 트러스트 영역과 유사하게 작동합니다. 동적 트러스트 영역에서는 영역이 사용되지 않고 대신 RME가 사용되어 신뢰할 수 있는 가상 머신을 사용할 수 있도록 합니다. 일반적인 신뢰 영역 영역은 동적 신뢰 영역에서 사용되지 않고, 대신 RME(실질 관리 확장)가 사용됩니다. RME는 신뢰 영역을 사용하는 신뢰할 수 있는 가상 머신을 활성화하여 보안 영역과 비보안 영역 간에 4킬로바이트 페이지의 메모리를 동적으로 할당함으로써 가상 머신의 메모리를 동적으로 할당 및 할당 해제할 수 있도록 합니다. 요약하자면, RME의 기능은 신뢰 실행 환경(RS)을 활성화합니다. RME는 호스트 운영 체제 또는 하이퍼바이저로부터 RAM 데이터와 메모리를 보호하여 리소스에 대한 권한 있는 액세스를 방지하는 동시에 하이퍼바이저가 리소스를 관리할 권한을 유지하도록 합니다. 또한 RME 데이터는 일반 또는 보안 영역 애플리케이션, 운영 체제 및 기타 영역과 같은 시스템 내의 다른 소프트웨어 요소로부터 보호됩니다. RME는 하드웨어, 소프트웨어 및 플랫폼 구성에 대한 증명을 지원하여 RME 또는 CCA 시스템에서 사용되는 모든 요소가 시스템 보안을 손상시키지 않도록 합니다. 또한 RME는 4킬로바이트 단위 로 RS에 대한 세밀한 동적 메모리 보호를 제공합니다. 승인되지 않은 액세스 시도는 새로운 CCA 세분 보호 테이블을 사용하여 세분 보호 오류로 등록되어 프로세스 또는 액세스 시도를 차단합니다. G GPT는 이제 루트 영역 모니터로 이동되었습니다. 월드 간 영역(Between Worlds Realms)은 기존의 비보안 VMS와 매우 유사한 프로그래밍 환경을 제공하여 영역 사용에 필요한 초기 학습 시간을 줄이고 도입을 용이하게 합니다. 따라서 애플리케이션 이나 운영 체제가 있고 하이퍼바이저 또는 시스템 내의 다른 엔티티가 데이터에 접근할 수 없도록 하고, 하드웨어로 메모리 보안이 강화된 신뢰할 수 있는 실행 환경에서 실행하려는 경우 RME와 CCA가 적합합니다. 이제 RME 아키텍처 구조에 대해 살펴보겠습니다. RME는 V9A 아키텍처를 확장하여 영역 월드와 루트 월드라는 두 개의 월드를 추가하고 각 월드에 물리적 주소 공간을 추가합니다. RME는 일반 모니터 월드 및 트론과 동일한 시스템에서 사용할 수 있습니다. 각 월드는 물리적 주소 공간을 가지며, 메모리와 같은 물리적 리소스는 물리적 주소 공간 간에 이동하여 메모리 보안을 보장합니다. CCA 시스템에서 메모리가 할당 해제될 때마다 루트 월드 의 이전 데이터에 접근하지 못하도록 메모리를 먼저 초기화합니다. 모니터는 자체 보안 상태와 개인 주소 공간을 가지며, GPT에 쓰기를 통해 보안 상태 간 처리 요소 실행의 컨텍스트 스위칭과 처리 요소에 메모리를 할당하는 기능을 제공합니다. 보안되지 않은 영역에서 RAM 영역으로의 모든 접근은 보안 모니터(Realm)를 통해 이루어져야 합니다. 보안 모니터는 Realm 영역을 구성하며, 여기에는 신뢰할 수 있는 실행 환경(Trusted Execution Environments, TEE)과 Realm 관리 소프트웨어(RMM, RSI, RMI)가 포함됩니다. RMM은 Realm 관리 모니터, Realm 서비스 인터페이스, Realm 관리 인터페이스라고도 합니다. RMM은 Realm 간의 보호 경계를 적용합니다. Realm 메모리는 하드웨어 기반 격리를 제공하며, 루트 레벨에서 모니터에 의해 제어되는 세분화된 보호 테이블에 의해 관리됩니다. 잘못된 접근은 페이지 폴트를 발생시킵니다. Realm 관리는 Realm 관리 모니터에 의해 감독됩니다. 일반 가상 머신과 마찬가지로 Realm은 vCPU를 가지며 여러 vCPU를 실행할 수 있습니다. 일반 가상 머신 하이퍼바이저는 Realm 생성 또는 삭제, Realm 에 메모리 할당 또는 할당 해제, BCPS 실행 스케줄링, 장치 할당 시 사용됩니다. 이는 시스템 내 소프트웨어 요소의 중복을 줄이고 RMM의 크기를 축소하기 위한 것입니다. 하이퍼바이저는 이러한 작업을 언제든지 수행할 수 있으므로 RMM은 완전히 동적입니다. ROM 하이퍼바이저 인터페이스를 통해 ROM 소프트웨어는 호스트 하이퍼바이저에 특정 서비스 및 데이터를 요청할 수 있습니다. 이러한 특정 서비스 중 일부는 다음과 같습니다. 호스트 플랫폼의 상태와 관련된 데이터에 접근하고, 호스트가 제어하는 ​​특정 상태 또는 리소스를 특정 영역에서 접근할 수 있도록 매핑하는 서비스에 접근하는 경우를 생각해 보겠습니다. CCA 의 잠재적 사용 사례를 몇 가지 살펴보겠습니다. 예를 들어, 클라우드 서버에서 출시되지 않은 게임의 3D 모델을 제작한다고 가정해 보겠습니다. 서버는 사용할 수 있는 GPU를 제공하지만, 클라우드 서버의 다른 어떤 엔티티도 앱이나 GPU에서 생성된 데이터를 볼 수 없도록 하고 싶습니다. CCA를 사용하면 3D 모델을 제작하는 데 사용하는 앱을 자체 영역으로 만들 수 있으므로 데이터가 보호됩니다. 장치 할당을 통해 GPU를 해당 영역에 독점적으로 할당하여 시스템의 다른 부분이 GPU 데이터에 접근할 수 없도록 할 수 있습니다. CCA를 사용하면 다른 공급업체의 소프트웨어를 신뢰할 필요성이 줄어듭니다. 아키텍처 자체가 보안을 제공하기 때문입니다. 모바일 장치에는 일반적으로 은행 정보, 의료 정보, 업무 이메일과 같은 많은 개인 데이터가 있습니다. 악성 앱이나 소프트웨어가 장치에 설치되면 이러한 취약한 앱 중 하나에 접근하여 시스템 전체로 확산될 수 있습니다. 하지만 CCA를 사용하면 어떻게 될까요? 각 앱은 자체 영역을 가질 수 있습니다. 자체 ROM의 데이터가 개별적으로 암호화되어 있으므로 공격 표면이 줄어들어 앱 하나가 공격을 받더라도 공격자가 다른 앱들을 개별적으로 복호화하지 않고는 시스템의 나머지 부분으로 공격을 확산할 수 없습니다.
