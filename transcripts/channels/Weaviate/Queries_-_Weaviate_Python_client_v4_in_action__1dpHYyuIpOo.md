## 스크립트

안녕하세요. 이번 영상에서는 Windows 8에서 쿼리를 수행하기 위해 새롭게 출시된 Python 클라이언트 V4 버전을 사용하는 방법을 보여드리겠습니다. 새 클라이언트는 내부적으로 gRPC를 실행하여 쿼리 속도를 향상시켰을 뿐만 아니라, API도 개선하여 쿼리를 작성하고 응답을 처리하는 과정을 더욱 간편하게 만들었습니다. 몇 가지 예제를 살펴보겠습니다. 저는 이미 Windows 8 클라우드 인스턴스를 설정해 두었고, 영화 컬렉션 과 리뷰 컬렉션 두 개를 링크로 연결해 두었습니다. 먼저 이 컬렉션들을 가져와서 작업해 보겠습니다. `clientcollections` 명령어를 실행하면 ` movies`라는 Python 객체가 생성되고, 이 객체를 사용하여 쿼리를 보낼 수 있습니다. 같은 방식으로 ` reviews` 컬렉션에도 동일한 작업을 반복해 보겠습니다. 먼저 간단한 텍스트 쿼리부터 시작해 보겠습니다. 쿼리 네임 스페이스 또는 서브모듈을 살펴보면 ` M25`, `Hybrid` 등 다양한 메서드가 있는 것을 볼 수 있습니다. 이 메서드들은 모두 쿼리 또는 검색 기능을 제공합니다. 하이브리드 검색, 키워드 검색, 그리고 기타 검색 유형에 따라 결과가 달라지는 경우가 많습니다. 우선 휴일 영화 관련 텍스트 검색을 해보겠습니다. 검색어는 ' 휴가 시즌'이고, 검색 결과는 두 개로 제한하겠습니다. 이제 응답 결과를 변수에 저장해 보겠습니다. 응답 객체를 보면 타입이 지정되어 있으므로 검사할 수 있습니다. 객체 속성이 있는데, 예를 들어 ' objects CU'라고 하면 리스트라는 것을 알 수 있습니다. 모든 속성을 출력해 보겠습니다. 보시다시피 속성이 상당히 많습니다. 속성부터 살펴보고, UID도 확인해 보겠습니다. 출력해 보면 각 응답에 대한 많은 데이터와 UID가 출력된 것을 볼 수 있습니다. 참고로, 쿼리 에서 어떤 속성을 반환할지 지정하지 않았는데, 새 클라이언트에서는 기본적으로 모든 속성을 반환하기 때문입니다. 음, 객체의 속성과 UID를 반환합니다. 물론 BLOB처럼 용량이 큰 객체는 제외하고요. 기본적으로 제외되는 유일한 IPlot 속성 데이터 유형입니다. 이제 연결된 리뷰를 가져오도록 쿼리를 확장해 보겠습니다. 이를 위해 ` return references` 매개변수를 사용할 수 있습니다. 그런 다음 참조 세트를 제공해야 합니다. 이를 위해 헬퍼 클래스를 사용해야 하므로 ` classes do query` 하위 모듈 전체를 `WQ`로 가져오겠습니다. 물론 개별 클래스를 가져올 수도 있지만, 저는 몇 가지만 사용할 것이므로 이 모듈을 사용하겠습니다. ` query reference link on`을 지정하고 ` has review`라는 속성이 있다는 것을 알고 있습니다. 반환 속성으로 사용자 이름( 리뷰 작성자)을 가져오겠습니다. 속성처럼 이 값도 리스트로 묶겠습니다. 하나만 반환하겠지만, 리스트로 묶어 두겠습니다. 일부 속성만 반환하려면 비슷한 방식으로 하면 됩니다. 일단 제목과 슬로건(슬로건은 재밌죠)만 가져오고, 이제 응답을 살펴보려면 응답 또는 참조, 아니, 속성에 있는 내용을 확인해야 합니다. 각 참조는 이제 속성과 비슷하죠. 참조 속성이기 때문에 먼저 참조 속성 이름을 제공해야 합니다. 이 속성은 'review'이고, 그 안에는 객체가 있습니다. 구조를 보면 응답 자체의 구조를 반영하기 시작하는 것을 알 수 있습니다. 다른 객체 집합에 대한 링크된 참조이기 때문에 그럴 만도 합니다. 첫 번째 'review' 객체를 살펴보겠습니다. 응답 객체처럼 속성을 가지고 있습니다. 어떻게 생겼는지 살펴볼까요? 여기 속성이 있습니다. 첫 번째 출력문은 UU ID이고, 이것은 출력되는 참조 라인입니다. 사용자 이름과 실제 사용자 이름입니다. 이것은 ' review' 컬렉션의 속성이고, 이것은 해당 속성의 값입니다. 꽤 간단하죠? 그리고 여기서 제가 이전에 언급하지 않았던 부분을 주목하세요. 속성 이름이나 매개변수 이름을 기억하기 위해, 아니, 쿼리에 매개변수 이름이 있어야 한다는 걸 잊지 않으려고 노력했습니다. 왜냐하면 원시 JSON을 제공하는 대신, 초기화 함수에 매개변수가 내장된 헬퍼 매개변수와 클래스를 사용했기 때문입니다. 정말 편리하죠. 자, 이제 이 쿼리에 필터를 추가해 보겠습니다. 필터 매개변수를 사용할 건데, 따로 찾아볼 필요가 없어서 좋네요. 필터 클래스가 있다는 걸 알고 있으니 그걸 사용해 보겠습니다. 필터링 기준은 여러 가지가 있지만, 지금은 속성별로 필터링하고 싶습니다. 영화를 러닝타임별로 필터링해 보겠습니다. 러닝타임이 100분 미만인 짧은 영화를 찾고 싶다고 가정해 봅시다. 이렇게 하면 될 것 같습니다. 다시 실행해 보겠습니다. 아, 잠깐만요. 이제 모든 속성을 가져오도록 하겠습니다. 그냥 실행해 보겠습니다. 제목과 실행 시간을 확인해 보겠습니다. 좋습니다. 결과가 바뀌었네요. ' 나이트메어 비포 크리스마스'는 76분, ' 징글 올 더 웨이'는 89분입니다. 보시다시피 100분 미만이라는 조건을 충족합니다. 만약 더 엄격한 조건을 추가하거나 다른 조건을 넣고 싶다면, 여기에 조건을 추가하고 앰퍼샌드(&amp;) 또는 파이프(|)로 연결할 수 있습니다. 앰퍼샌드를 추가하면 AND 조건이 됩니다. 이제 100분 미만 이면서 85분 이상인 영화를 찾고 싶다면, 어떤 결과가 나오는지 확인해 보겠습니다. 보시다시피 '징글 올 더 웨이'가 모든 조건을 충족하고, '테이크'도 있습니다. '테이크'가 휴일 영화인지는 확실하지 않지만, 조건을 충족합니다. 바로 우리가 찾던 결과입니다. 만약 이 결과를 생성형 쿼리로 변환하려면 하위 모듈을 '생성'으로 변경하고 나머지는 그대로 두면 됩니다. 구문은 그대로 유지됩니다. 이제 제가 해야 할 일은 언어 모델에 대한 프롬프트를 제공하는 것뿐입니다. 매개변수를 살펴보면서 단일 프롬프트를 사용해 보겠습니다. "언어 모델 아, 이것을 프랑스어로 번역해 줘."라고 말하겠습니다. 제목부터 시작해 보겠습니다. 단일 프롬프트는 기억하시겠지만, 각 개별 객체에 대해 작동합니다. 즉, 생성된 결과처럼 결과가 각 개별 객체에 연결되어 있다는 뜻입니다. 따라서 개별 객체를 보고 생성된 속성을 볼 수 있습니다. 이 코드를 실행하면 타사 API와 언어 모델을 거치는 데 몇 초 정도 걸립니다. 보시다시피, 이것은 프랑스어로 Tak이고, 이것은 프랑스어로 Jingle입니다. 아주 좋습니다. 마찬가지로, 반환된 모든 결과에 대해 그룹화된 작업을 수행하려면 " 이 영화들의 공통점은 무엇일까?"라고 묻고, 제한된 필터를 제거하고 결과를 4개로 줄이겠습니다. 이 그룹화 작업은 전체 집합에 대해 작동하기 때문입니다. 결과 또는 생성된 출력을 찾을 수 있는 결과는 응답 자체에 다음과 같이 표시됩니다. 이 쿼리를 다시 실행하면 추가적인 생성 쿼리가 수행되어 결과가 반환됩니다. 한번 살펴보겠습니다. 보시다시피 꽤 잘 작동했습니다. 이 영화들은 크리스마스라는 공통 주제를 가지고 있습니다. 자, 여기서 마치겠습니다. 모든 메서드를 하나하나 설명하지는 않겠습니다. 조금 지루할 수 있으니까요. 하지만 집계 네임스페이스 또는 하위 모듈도 있으므로 movies Aggregate를 살펴보고 이러한 함수나 메서드를 직접 사용해 볼 수 있습니다. 또 다른 좋은 점은 쿼리 하위 모듈에서 near text를 살펴보면 사용 가능한 다양한 매개변수가 표시되고 그중 하나가 Group by라는 것입니다. 인터페이스가 꽤 편리합니다. 이전에 Group by를 사용해 본 적이 있다면 구문 작성이 꽤 까다로웠겠지만 이제 훨씬 쉬워졌습니다. 재순위 지정 등도 마찬가지입니다. 물론 항상 그렇듯이 이러한 모든 것에 대한 구체적인 예제는 공식 문서를 참조하시기를 권장합니다.
