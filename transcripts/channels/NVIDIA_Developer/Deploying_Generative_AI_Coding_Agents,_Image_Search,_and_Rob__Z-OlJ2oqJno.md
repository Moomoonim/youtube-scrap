LLM은 로봇과 상호 작용하여 다양한 작업을 수행하는 자연스러운 인터페이스가 되고 있습니다. 앞서 말씀드린 것처럼 다족 로봇 애플리케이션은 이미지 검색에도 활용될 수 있습니다. 이전 튜토리얼에서는 이미지에 있는 정보를 텍스트로 변환하는 멀티모달 CAG(컴퓨터 지원 아키텍처)를 활용하는 방법을 살펴보았습니다. 이 변환된 텍스트는 하위 단계에서 사용자에게 응답을 생성하는 데 사용됩니다. 동일한 아키텍처를 넘어 이미지를 벡터 데이터베이스에 텍스트로 저장하고 이를 검색에 활용할 수도 있습니다. 예를 들어 사용자가 참조 이미지와 질문을 제공하면 시스템은 벡터 데이터베이스에서 유사한 이미지를 검색하고 사용자에게 응답을 제공합니다. 이것이 이미지 검색 워크플로의 모습입니다. 이전 튜토리얼을 보셨다면 워크플로가 매우 유사하다는 것을 알 수 있을 것입니다. 워크플로는 오프라인 단계와 온라인 단계의 두 단계로 나뉩니다. 오른쪽은 벡터 데이터베이스를 생성하는 오프라인 단계이고, 왼쪽은 데이터베이스가 생성되면 사용자가 데이터를 검색할 수 있는 온라인 단계입니다. 사용자는 텍스트와 이미지를 쿼리로 전달할 수 있으며, 이 텍스트와 이미지를 사용하여 가장 관련성이 높은 이미지를 검색한 다음 해당 정보를 기반으로 사용자에게 응답을 생성합니다. 따라서 단계는 매우 유사하지만, 유일한 차이점은 프레임워크에 제공하는 이미지에서 임베딩을 생성하고 벡터 데이터베이스를 만들기 위해 이미지 에믹 모델을 사용한다는 것입니다. 다음은 L-인덱스 문서에서 발췌한 예시입니다. 매우 간단한 이미지 검색 애플리케이션으로, 따라하기 쉽습니다. 왼쪽에는 이미지와 텍스트 데이터 세트를 사용하여 벡터 데이터베이스를 생성합니다. 벡터 데이터베이스를 생성한 후 오른쪽에는 사용자의 쿼리와 참조 이미지를 전달하여 벡터 데이터베이스에서 관련 이미지 검색을 수행하고 사용자의 질문에 기반한 응답을 생성하는 방법을 보여줍니다. 직접 실행해 보세요. 정말 좋은 예시이고 구현하기도 매우 쉽습니다. Colab에서 이 예시를 바로 실행할 수 있는 링크도 제공합니다. 제가 보여드리고 싶은 다른 애플리케이션은 다음과 같습니다. 코딩 어시스턴트와 개발 환경에서 자신이 선호하는 코딩 어시스턴트를 사용하는 방법에 대해 알아보겠습니다. 시중에는 코딩 작업에 사용할 수 있는 다양한 코딩 어시스턴트 모델이 있지만, 사용하기 전에 개발 환경에서 구성해야 합니다. 저는 VS Code를 사용하여 코딩 어시스턴트를 구성하는 방법을 보여드리겠습니다. 자, 시작해 볼까요? 시작하기 전에 몇 가지 사항을 결정해야 합니다. 첫째, 사용할 모델과 호스팅 위치, 그리고 호스팅 서비스에서 사용하는 API 프로토콜입니다. 저는 Nedia Inference Microservice(NIB)에서 호스팅하는 코딩 도구 모델을 사용하겠습니다. NIB 마이크로 서비스는 OpenAI 프로토콜을 사용하므로 세 가지 정보가 필요합니다. 첫째, 모델 이름, 둘째, 모델 엔드포인트 링크, 셋째, API 정보, 즉 AP 키 정보입니다. 이 세 가지 정보를 사용하여 VS Code에서 구성하겠습니다. 앞서 말씀드린 것처럼 저는 Nedia Inference Microservice(NIB) 에서 호스팅하는 NIB 마이크로서비스를 사용하겠습니다. 엔비디아 모델을 얻으려면 b로 이동해야 합니다. nvidia.com에 접속해서 모델을 검색하세요. 저는 Codol을 사용할 거라서 Codol을 검색합니다. 보시다시피 bu.com에는 다양한 코딩 어시스턴트 모델이 호스팅되어 있습니다. 검색창에 들어가면 BS URL을 복사하세요. 이 URL이 API 기반이 됩니다. 모델 이름에는 스트림이 연결되어 있습니다. VS Code를 실행하고 마켓플레이스로 이동합니다. 마켓플레이스에서 앱을 검색하고 설치를 계속합니다. 저는 이미 설치했으므로 추가 단계는 필요 없습니다. 설치가 완료되면 왼쪽 패널에 로고가 표시됩니다. 로고를 클릭 하고 설정으로 이동합니다. 설정에서 복사한 모델 이름과 모델 URL(엔드포인트)을 API 기반에 입력하고, HB API로 시작하는 API 키를 입력합니다. 공급자 이름은 OpenAI로 설정되어 있어야 합니다. 이름에서 알 수 있듯이 OpenI API 프로토콜을 따르므로 이 세 가지 정보를 입력하면 코딩 도우미와 상호 작용하면서 다양한 애플리케이션을 코딩할 수 있습니다. 마지막으로 로봇 공학 및 임베디드 분야에 대해 이야기해 보겠습니다. Elms는 임베디드 로봇 공학 및 V 러닝 분야에서도 활용되고 있습니다. 이미지 캡셔닝이나 시각적 질문 답변 대신, VA 모델(Vision Language Action Model)은 카메라 이미지와 자연어 명령에서 액션 토큰을 생성하여 로봇의 움직임을 제어합니다. 이 비디오에서 볼 수 있듯이, 그리퍼와 매니퓰레이터의 움직임을 제어하여 다양한 작업을 수행하는 방법을 보여줍니다. 이 또한 카메라로 캡처한 이미지와 자연어 상호 작용을 사용합니다. 제가 소개하고 싶은 VA 모델의 예로는 스탠포드, UC 블레이, 토탈 연구소의 연구원들이 개발한 Copen Villa 모델을 보여드리겠습니다.
