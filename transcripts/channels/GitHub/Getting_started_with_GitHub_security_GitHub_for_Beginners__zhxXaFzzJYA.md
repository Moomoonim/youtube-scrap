## 스크립트

오늘은 GitHub 보안을 시작하는 데 필요한 모든 것을 알려드리겠습니다. [음악] 이 비디오를 끝까지 시청하시면 시크릿 스캐닝, Dependabot, [음악] 코드 스캐닝, Copilot Autofix와 같은 내장 도구를 사용하여 GitHub 저장소의 보안 취약점을 수정하는 방법을 이해하게 될 것입니다. 안녕하세요, 저는 카데샤입니다. 오늘 이렇게 함께해 주셔서 정말 기뻐요. 보안이 왜 중요한지, 그리고 GitHub 도구를 사용하여 저장소를 안전하게 보호하는 방법에 대해 이야기해 보겠습니다 . 보안이 중요한 이유는 취약점이란 공격자가 악용할 수 있는 코드 또는 사용하는 라이브러리의 약점을 의미하기 때문입니다 . 취약한 코드를 직접 작성하지 않았더라도 해당 라이브러리를 프로젝트에 가져오는 순간 위험을 감수해야 할 수 있습니다. 그렇기 때문에 규모가 작거나 완전히 새로운 프로젝트조차도 취약점을 가질 수 있습니다. 거의 모든 소프트웨어는 타사 패키지에 의존합니다 . GitHub Advanced Security를 ​​사용하면 이러한 문제를 찾고 해결하는 것이 그 어느 때보다 쉬워집니다. 오늘은 제 친구 아리를 모시고 GitHub 고급 보안 기능과 저장소를 안전하게 보호하는 방법에 대해 자세히 알아보겠습니다. GitHub Advanced Security는 코드 품질을 향상하고 유지하는 데 도움이 되는 제품군입니다. 공개 저장소에서는 Dependabot, 코드 스캔, 비밀 키 스캔, Copilot Autofix와 같은 도구를 사용할 수 있습니다. 먼저 GitHub 고급 보안 기능이 켜져 있는지 확인해 보겠습니다. 리포지토리에서 설정 &gt; 고급 보안으로 이동하여 Dependabot 알림 및 보안 업데이트를 활성화하세요 . 코드 스캔 섹션으로 스크롤하여 기본 설정으로 코드 QL 분석을 활성화하세요. 마지막으로, 비밀 보호 기능을 활성화하세요. 공개 저장소는 기본적으로 이러한 정보를 갖습니다. 비공개 저장소에는 GAS 라이선스가 필요합니다. 이제 보안 탭으로 이동하여 노출된 비밀 정보, 취약한 종속성 및 위험한 코드 경로에 대한 경고를 확인할 수 있습니다. GitHub는 비밀 스캔 기능을 통해 민감한 정보를 보호하는 데 도움을 줄 수 있습니다 . 만약 실수로 API 키나 토큰을 공유했다면 , 비밀 정보 스캔 기능이 보안 탭에서 바로 해당 사실을 알려줍니다. 어떤 비밀이 감지되었고 어디에서 발견되었는지 확인하려면 알림 제목을 클릭하세요 . GitHub는 사용자를 대신하여 비밀 키를 취소할 수 없습니다. 비밀 키를 취소한다는 것은 기존 키를 더 이상 사용할 수 없도록 비활성화하는 것을 의미하며, 일반적으로 Azure 또는 Stripe와 같이 비밀 키가 생성된 플랫폼에서 새 키를 생성하는 방식으로 이루어집니다 . 그 부분은 직접 하셔야 할 겁니다. 하지만 비밀 정보 스캔은 유출된 비밀 정보가 악용되는 것을 막기 위해 조기에 경고를 해줍니다 . 비밀번호를 취소한 후에는 '취소됨'을 클릭하여 비밀번호 스캔 알림을 닫을 수 있습니다 . Dependabot은 코드 스캔 도구로, 종속성을 최신 상태로 유지하는 데 도움을 줍니다 . Dependabot 알림은 이러한 취약점에 대해 알려줍니다. Dependabot 알림을 받으면 Dependabot이 취약한 라이브러리를 발견 하고 업데이트하기 위한 풀 리퀘스트를 열었다는 것을 알 수 있습니다. 알림 페이지를 아래로 스크롤하면 알림을 발생시킨 특정 GitHub 보안 권고 사항을 확인할 수 있습니다. PR을 열고 버전 업데이트를 검토한 후, 모든 것이 괜찮아 보이면 PR을 병합합시다. Dependabot은 종속성에 대한 GitHub 보안 권고를 풀 리퀘스트로 자동 변환하므로 일반적인 취약점과 노출을 수동으로 추적할 필요가 없습니다. 제 눈에는 괜찮아 보여요. 병합합시다. GitHub 고급 보안에 대해 자세히 알아보려면 GitHub 스킬 페이지로 이동하여 취약한 노드 챌린지를 완료하세요 . 보안에 대해 배우는 재미있고 상호작용적인 방법입니다. 이 에피소드와 관련된 블로그 게시물은 gh.io/gfbsecurity에서 읽어보실 수 있습니다. 이제 CodeQL 알림을 살펴보겠습니다. 이 경고는 사용자 입력이 위험한 함수에 도달할 수 있음을 나타냅니다 . CodeQL은 린터가 아닙니다. 훨씬 더 강력합니다. 데이터 흐름을 이해하여 입력이 어디에서 시작하고 어디에서 끝나는지 보여줍니다. 이 취약점과 그 위험성을 이해 하고 몇 가지 해결 방법을 살펴보기 위해 규칙 도움말 텍스트를 읽어보겠습니다. 이제 경고에 대해 더 잘 이해했으니 Copilot Autofix를 사용하여 해결해 보겠습니다. 경고창에서 '수정 사항 생성'을 클릭하세요 . Copilot은 입력 유효성 검사 또는 명령 매개변수화와 같은 패치를 제안할 것입니다. 변경 사항을 검토하고 ' 새 분기에 커밋'을 클릭하세요. 풀 리퀘스트 열기를 선택한 다음 모달 창에서 풀 리퀘스트 열기를 클릭하여 기본 브랜치에 병합하기 전에 코드를 검토할 수 있도록 해주세요. Copilot은 보안 수정 속도를 높여주지만, 제어권은 여전히 ​​사용자에게 있다는 점을 기억하세요. 체크 표시가 모두 초록색이니 병합하겠습니다. 그러면 보안 탭에서 알림이 사라집니다 . GitHub 고급 보안을 사용하여 취약점을 안전하게 탐지하고 수정하는 방법을 알려주셔서 정말 감사합니다, Ari. [음악] 보안 수칙을 재미있고 흥미로운 방식으로 배우려면 취약한 노드 저장소를 꼭 확인해 보세요. 이 영상이 도움이 되었기를 바랍니다. [음악] GitHub의 YouTube 채널을 구독하시면 앞으로 업로드될 영상들을 놓치지 않고 시청하실 수 있습니다. 또한 이 정보가 필요한 개발자 친구와도 공유해 주세요 . 즐거운 코딩 되세요.
