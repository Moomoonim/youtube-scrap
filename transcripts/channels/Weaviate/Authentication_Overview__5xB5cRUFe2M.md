## 스크립트

안녕하세요. 이 짧은 비디오에서는 Weaviate의 인증 기본 사항을 소개하고, 인증이란 무엇이며 어떤 옵션이 있는지, 그리고 각 옵션에 대한 간략한 비교를 제공합니다. 인증은 사용자가 Weaviate와 같은 시스템과 상호 작용할 때 사용자의 신원을 확인하는 프로세스입니다. 사용자를 식별하면 시스템은 시스템 리소스에 대한 적절한 수준의 액세스 권한( 권한 부여)을 제공할 수 있습니다. 보안은 인증에서 중요한 요소입니다. 악의적인 사용자가 다른 사람인 척 가장하여 접근 권한이 없는 리소스에 접근하는 것을 막아야 합니다. 하지만 때로는 보안을 강화하면 사용성이 떨어질 수 있습니다. 자물쇠가 15개 달린 문을 생각해 보세요. 더 안전하겠지만 사용하기가 매우 불편할 것입니다. 따라서 인증의 핵심은 보안과 사용성 사이에서 적절한 균형을 찾는 것입니다. Weaviate는 다양한 사용 사례와 요구 사항에 맞춰 세 가지 인증 구성을 제공합니다. 하나씩 살펴보겠습니다. 첫 번째는 익명 액세스입니다. 이 옵션을 사용하면 누구나 자격 증명 없이 Weaviate 인스턴스에 액세스할 수 있습니다. 두 번째는 API 키입니다. API 키 구성에서는 사용자가 인증을 위해 키를 제공해야 합니다. Weaviate가 사용자를 인식하면 인증이 완료됩니다. 사용자는 API 키를 통해 Weviate에 대한 읽기 전용 또는 읽기/쓰기 권한과 같은 해당 수준의 액세스 권한을 얻게 됩니다. 마지막으로 OIDC(Open ID Connect)는 사용자가 단일 자격 증명 세트를 사용하여 여러 곳에 로그인할 수 있도록 설계된 인증 프로토콜입니다. 이는 상당히 안전한 옵션이지만, 대부분의 경우 여러 관계자와 백그라운드 프로세스가 관련되어 설정 및 사용이 복잡할 수 있습니다. 대부분의 사용 사례에서 API 키 기반 인증이 사용 편의성과 보안 사이의 균형을 제공하기 때문에 최선의 선택이라고 생각합니다. API 키는 설정 및 관리가 간단하며 대부분의 애플리케이션에 높은 수준의 보안을 제공합니다. 하지만 API 키는 Weviate 인스턴스에 대한 액세스 권한을 부여하므로 안전하게 보관하는 것이 중요합니다. 이것으로 Weviate 인증에 대한 소개를 마치겠습니다. 이제 세 가지 인증 구성 과 API 키가 많은 애플리케이션에서 최선의 선택인 이유를 기본적으로 이해하셨을 것입니다. 다음 시간에 다시 뵙겠습니다.
