## 스크립트

이제 런치 작업을 테스트했고, 기준 모델과 후보 모델에서 두 개의 예측값을 가져와 비교 및 ​​평가한다는 것을 확인했으므로, 새 모델이 모델 레지스트리에 추가되거나 특정 후보 모델이 모델 버전에 추가될 때마다 동일한 작업을 자동으로 수행하는 자동화를 설정할 수 있습니다. 이미 잘 알고 있는 모델 레지스트리로 이동하여 이 작업을 시도해 보겠습니다. 작은 명령어 llm이 보이고, 버전도 확인할 수 있습니다. 지금은 이 후보 태그를 제거하고 나중에 자동화를 트리거하기 위해 추가하겠습니다. 다시 이 모델로 돌아가 보면 아직 추가된 자동화가 없으므로 새 자동화를 추가해 보겠습니다. 이 자동화는 등록된 모델에 새 버전이 추가될 때 또는 모델 버전에 후보 모델이 추가될 때마다 실행되도록 설정할 수 있습니다. 이 경우에는 특정 후보 모델을 기준으로 자동화를 실행하도록 하겠습니다. 아쉽게도 이번에도 후보 Alas를 사용할 것이고, 작업은 작업( Weight Job)이 될 것입니다. 다음 단계에서 작업을 선택하는데, 이것은 방금 실행한 평가 작업입니다. 여기서 설정을 변경하고 재정의할 수 있습니다. 예를 들어 모든 샘플을 실행하는 대신 100개의 샘플만 실행하도록 할 수 있습니다. 동일한 OpenAI 모델을 사용하고, 모델 레지스트리에서 기준 Alas를 가져오고, Alas Val은 후보로 설정합니다. 하지만 이 자동화는 Alas를 기반으로 트리거되므로 나중에 Alas를 변경해야 할 수도 있습니다. 따라서 후보를 하드코딩하는 대신, Alas 업데이트를 참조하여 자동화를 트리거하는 동적 설정을 복사하고, 이 Alas 변수를 재정의 설정에 넣을 수 있습니다. 대상 프로젝트는 Tiny Name입니다. 이는 동일하며, 제 Q는 Docker 큐를 평가하는 작업이 될 것이고 자동화 이름은 그냥 evaluate라고 하겠습니다. GPT 4 Judge를 사용하여 후보 모델과 기준 모델을 비교할 것입니다. 이제 자동화를 생성해 보겠습니다. 자동화가 생성되었으니 이제 후보 모델 T Bas를 이 모델에 다시 추가하고 어떤 일이 발생하는지 확인해 보겠습니다. 모델로 돌아가서 큐를 보면 새 작업이 대기열에 추가된 것을 볼 수 있습니다. 제 컴퓨터에서 실행 중인 에이전트를 확인해 보면 이 작업이 시작되어 데이터를 가져왔고 현재 평가를 실행 중인 것 같습니다. 후보 모델 선호도 점수는 -0.07로, 후보 모델이 기준 모델보다 약간 나쁘다는 것을 의미합니다. 동일한 모델을 비교하는 것이지만, 100개의 샘플을 가져왔기 때문에 점수가 약간 다르게 나타나는 것입니다. 아마도 처음에는 이렇게 보였을 겁니다. 100개의 샘플을 분석해 보니 기준 모델이 더 나아 보이지만 여전히 비슷한 범위 내에 있는 것 같습니다. 후보 모델과 기준 모델이 매우 유사한 것 같네요. 결과를 좀 더 자세히 살펴보겠습니다. 이제 작업이 완료되었으니 가중치와 바이어스를 통해 결과를 확인할 수 있습니다. 후보 모델 선호도 점수 외에도, 프롬프트에 대한 비교 표도 기록되어 있습니다. 기준 모델의 응답과 후보 모델의 응답을 비교해 볼 수 있는데, 동점일 경우 0, 기준 모델은 -1, 후보 모델은 1의 선택지가 있습니다. 또한, LLM이 특정 답변을 선택한 이유도 확인할 수 있습니다. 동점이 아닌 경우를 살펴보겠지만, 이 경우에는 기준 모델이 선호됩니다. 디지털 보안에 대한 잠재적 위협 5가지 목록을 생성하라는 지시문을 살펴보겠습니다. 기준 모델 의 응답을 볼 수 있는데, 크로스 사이트 스크립팅(XSS)과 크로스 사이트 요청 위조(CSRF)가 세 번 반복됩니다. 이제 후보 모델의 응답을 살펴보겠습니다. 이것은 설명과 함께 크로스사이드 스크립팅입니다. LLM의 추론을 살펴보겠습니다. 두 모델 모두 문제가 있습니다. 모델 A는 설명에서 동일한 위협을 여러 번 반복하여 5개의 서로 다른 위협을 제시하라는 지침을 충족하지 못합니다. 모델 B는 하나의 위협에 대해 동일한 설명을 여러 번 반복하여 중복되고 추가적인 위협을 제공하지 않습니다. 하지만 모델 A는 반복되더라도 최소한 두 개의 서로 다른 위협을 제공하는 반면, 모델 B는 하나만 제공합니다. 이는 상당히 타당한 추론이므로 이 경우에는 동의합니다. 이렇게 해석해 보면 두 세대 모두 상당히 좋지 않다는 것을 알 수 있습니다. 다시 한번 살펴보겠습니다. 후보 모델로 제시된 모델을 다시 살펴보겠습니다. 개요로 돌아가서 계보를 기억하고, 구성에 기준선 및 평가 모델 경로를 저장하고 있다는 것을 알 수 있습니다. 이것은 작은 지침 LLM V3입니다. 여기 V3를 살펴보면... 이 모델을 생성한 실행 과정으로 돌아가서 구성과 설정을 확인해 보겠습니다. 음, 몇 가지 설정을 살펴보고 이런 좋지 않은 결과의 원인이 되는 부분이 있는지 확인해 보겠습니다. 다시 말씀드리지만, 이 모델을 AAC 모드에서 최대 스텝 수 20으로 실행했는데, 이는 모델이 지시를 따르는 방법을 제대로 학습할 기회를 충분히 주지 못하는 것입니다. 다음 단계에서는 모델 학습으로 돌아가서 이번에는 좀 더 오래 학습시키고 다시 평가를 실행하여 결과를 확인해 보겠습니다. 이번에는 결과가 훨씬 좋아지기를 바랍니다.
