## 스크립트

dpy는 인공지능 분야에서 획기적인 발전으로, 대규모 언어 모델 호출에서 체인 방식을 도입한 Lang Chain의 등장에 비견될 만합니다. LLM API는 매우 흥미로운 기술이며, 앱에 통합하거나 복잡한 프로그램을 구축하는 데 사용할 수 있습니다. 한 언어 모델 호출의 출력을 다음 호출의 입력으로 활용할 수 있습니다. 입력 요청 작성이나 블로그 게시물 작성과 같은 복잡한 작업을 연구, 작성, 편집 작업으로 분해하여 병렬화함으로써 간소화할 수 있습니다. 또한 다양한 제어 메커니즘을 활용할 수 있습니다. Spy는 pyos와 유사한 새로운 구문을 도입하여 LLM 프로그램에 대한 제어력과 유연성을 향상시켰습니다. thepi의 가장 흥미로운 점은 새로운 구문 과 OP 최적화를 결합했다는 것입니다. 즉, LLM 프롬프트에 작업에 대한 최적화된 명령어를 포함할 수 있습니다. 예를 들어, 문서 순위를 재조정하는 작업이 있고 재조정 에이전트가 있다고 가정해 보겠습니다. 이 경우 특정 표현을 사용하면 다른 표현보다 성능이 향상됩니다. 또한 JSON 출력을 요청해야 하는 경우, "JSON을 출력해 주세요" 또는 "JSON을 주세요"라고 명시하는 대신 최적화된 표현을 사용하여 더 효율적인 결과를 얻을 수 있습니다. 이것이 바로 Spy의 핵심 아이디어입니다. 프롬프트에서 사용되는 명령어와 예제를 자동으로 최적화하는 것이 목표입니다. 이는 DSP 프로그램 모델을 사용할 때 원하는 동작을 유도하기 위해 수행됩니다. 이 과정을 통해 많은 흥미로운 것들을 달성할 수 있습니다. DSP 프로그램 모델은 스토어의 시작점이며, P 에이전트 구문과 LLM 프로그램의 조합으로 설명할 수 있습니다. 이제 이 과정이 무엇을 포함하는지 자세히 살펴보겠습니다. 먼저 LLM 프로그램에 필요한 구성 요소를 정의합니다. 쿼드런트와 같은 HRI 시스템에서 시작하여 쿼 생성기 및 입력 메커니즘에 연결합니다. 특정 작업을 수행하는 두 개의 서로 다른 NLM 구성 요소가 있습니다. 이들은 전체 LLM 프로그램에서의 역할에 특화된 모델일 수 있으며, 이를 순방향 전달의 논리라고 부릅니다. 첫 번째 구성 요소는 쿼 생성기이며, 시작하기 전에 몇 가지 사항을 염두에 두어야 합니다. 우선 구성 요소에 이름을 지정해야 하는데, 이를 'gen quir'라고 하겠습니다. 다음으로, 나중에 설명할 DSPI Do 사고의 사슬이 있습니다. 먼저 시그니처에 대해 이야기해 보겠습니다. 이 강의를 진행하면서 시그니처가 있다는 것을 알게 될 것입니다. 문서 문자열에 더 긴 초기 프롬프트를 작성한 다음 입력/출력 필드를 추가하는 방식으로 시그니처를 확장하는 또 다른 방법이 있습니다. SP 스파이의 기능은 시그니처 구문을 사용하여 FM 프로그램 코드의 모양을 개선할 수 있도록 합니다. 간략한 구문은 컨텍스트, 질문 및 쿼리 필드를 정의하는 것입니다. 컨텍스트와 질문을 입력하면 스파이가 이를 구문 분석하고 쿼리를 출력합니다. LLM 또는 LAR 언어 모델은 변수 이름만으로 변수 의 의미를 추론하는 놀라운 능력을 가지고 있습니다. 예를 들어 컨텍스트 질문에서 GP4 또는 G Mini Ultra와 같은 강력한 모델은 이름만으로 컨텍스트를 정확하게 이해할 수 있습니다. 따라서 프로그램의 두 번째 구성 요소는 답변을 생성하는 또 다른 언어 모델을 포함합니다. 이 프로그램은 컨텍스트와 질문을 입력으로 받아 답변을 반환합니다. 흥미로운 점은 LLM 에이전트를 구축하고 입력 데이터와 상호 작용하여 출력을 생성하는 방법을 정의할 수 있다는 것입니다. 먼저 크기가 조정되지 않은 빈 컨텍스트를 정의합니다. 이는 또한 로컬 메모리를 순방향 전달에 통합하는 방법과 프로그램의 순방향 전달에서 비매개변수 함수를 사용하는 방법을 고려하는 것입니다. 빈 컨텍스트 목록으로 시작하여 반복합니다. 프로그램에서 하이퍼 파라미터로 설정하여 필요한 홉 수를 결정할 수 있는 다중 홉 질문-답변 방식은 복잡한 질문을 더 작은 하위 질문으로 나누어 효과적으로 답변하는 것을 의미합니다. 이 접근 방식은 처음 소개되었을 때 큰 주목을 받았던 AutoG GPT의 개념과 유사합니다. 에이전트는 각 하위 질문을 평가하여 결과를 통합하는 데 필요한 정보가 충분히 수집되었는지 판단할 수 있습니다. 이 과정을 다중 홉 질문이라고 합니다. 우리의 초점은 쿼리를 생성하는 TPT 프로그램 모델에 맞춰집니다. 우리는 컨텍스트와 입력 질문을 입력으로 받습니다. 이 과정을 통해 쿼리를 생성하고, 생성된 쿼리를 헤리 사분면을 통과시켜 필요한 컨텍스트를 얻습니다. 질문에 답하는 데 필요한 모든 컨텍스트를 얻을 때까지 이 과정을 반복합니다. 반복 횟수는 컨텍스트에 따라 달라집니다. 응답 생성 후, 생성된 응답을 대화에 입력하여 처리할 수 있습니다. ChatPT는 유창하게 대화하고 질문에 답하며 좋아하는 책이나 채팅에서 영감을 받은 YouTube 스크립트를 만드는 능력으로 모두를 놀라게 했습니다. 우리는 이러한 대규모 언어 모델(예: ChatTPT)을 체인으로 연결하여 더 복잡한 언어 모델(예: L-Chain)을 만들 수 있다는 것을 발견했습니다. 드라마 인덱스(Drama Index) 프로젝트는 대규모 언어 모델을 활용한 새로운 애플리케이션 구축 방식을 전파해 왔으며, 이것이 바로 미래입니다. 그들이 제안하는 접근 방식은 입력 길이 제한을 극복하는 체인(Chain)을 사용하는 것입니다. 전통적으로 체인은 복잡한 입력을 더 작은 덩어리로 분할하고, 각 덩어리를 개별적으로 처리한 다음, 출력을 결합하여 긴 문서를 처리하는 데 사용되었습니다. 특히 최대 32KB 크기의 모델을 감독하는 데 어려움이 있는 상황에서, 이러한 모델이 모든 입력에 어떻게 집중해야 하는지 파악하는 것은 어렵기 때문에 입력 길이를 분할하는 방식은 여전히 유효합니다. 두 번째 과제는 복잡한 작업을 해결하는 것입니다. 예를 들어, 채팅 GPT에게 쿠버네티스에서 애플리케이션을 실행하고 코드를 속성화하는 방법에 대한 블로그 게시물을 작성해 달라고 요청하는 것은 매우 어려울 수 있습니다. 이러한 복잡한 작업을 더 작은 하위 작업으로 나누고 언어 모델이 요청을 완료하기 위해 따라야 할 워크플로를 정의하는 것이 좋습니다. 체인은 검색 기능을 크게 향상시켰습니다. 예를 들어, 멀티홉 질의응답(Multihop Question Answering)을 들 수 있습니다. 이 과정에서 우리는 쿼리를 구성하고, 정보를 검색하고, 더 많은 컨텍스트를 얻기 위해 이전 정보를 참조한 다음, 해당 정보를 사용하여 질문에 답합니다. 이 과정을 개선하는 한 가지 방법은 언어 모델을 사용하여 필터를 만드는 것입니다. 언어 모델을 활용한 검색 문서 재구성은 검색에 있어서도 중요한 역할을 해왔습니다. 언어 모델이 발전함에 따라 그래프 형태 로 표현하는 것이 더 효과적이라는 것이 분명해졌습니다. 예를 들어, 현재 우리는 LEN 그래프를 가지고 있으며, 이를 텍스트 변환 그래프로 생각할 수 있습니다. LEN 그래프는 계산 그래프로, 엣지를 통해 텍스트 입력 과 출력의 변환이 전달되고, 변환된 텍스트는 엣지를 따라 다음 노드로 전달되어 추가 변환이 이루어집니다. 예를 들어, 기사 작성 및 편집 과정을 세 번에 걸쳐 병렬로 실행한 다음, 이러한 메모들을 LLM 프로그램의 게시된 기사 구성 요소에 동기화할 수 있습니다. 이를 통해 특정 주간의 뉴스를 기반으로 뉴스레터를 제작할 수 있습니다. 예를 들어, 지난주 야후 파이널에서 일어난 일과 같은 뉴스를 다룰 수 있습니다. 기사 작성 및 편집 과정을 병렬화한 다음 프로그램의 다른 부분에 동기화할 수 있습니다. 이러한 기사들을 종합하고 모든 정보를 결합하여 일관성 있는 내러티브를 만들어야 합니다. 더 자세히 알아보기 전에 LMA Index와 L Chain에서 제공하는 LLM 프로그램 갤러리를 살펴보시기를 강력히 추천합니다. 프레임워크는 LLM 체인, 그래프, 에이전트 및 프로그램을 구축하는 데 유용하지만 유연성이 제한적입니다. 바로 이 부분에서 Aspy 프로그램이 완벽한 솔루션으로 빛을 발합니다. LLM 프로그래밍 언어는 프레임워크와 대조적으로 프롬프트 없이 LLM 프로그래밍에 더욱 흥미로운 가능성을 제공합니다. LLM 프로그래밍 언어를 사용하는 데에는 두 가지 주요 이점이 있습니다. 첫째, 생성자 입력 및 출력 프롬프트를 통해 프로그램 내에서 아이디어를 일관되게 표현할 수 있습니다. 둘째, LLM 모델 간의 상호 작용 방식을 프로그래밍 방식으로 제어할 수 있어 LLM API를 사용하면서 필요와 상상력에 맞게 LLM 프로그램을 유연하게 사용자 정의할 수 있습니다. 자, 이제 프롬프트와 생성자 입력 및 출력을 정리하는 방법을 살펴보겠습니다. 이를 위해 시그니처를 사용합니다. 이 예제에서는 시그니처를 상속받는 '답변 생성' 함수를 사용합니다. 또한 특정 컨텍스트 에서 작업 프롬프트를 설명하는 도크 문자열을 작성합니다. 이 작업은 질문에 간결한 답변을 제공하는 것입니다. 이 비디오 후반부에서는 Spy가 이러한 프롬프트를 최적화하는 데 어떻게 도움이 되는지 설명하겠습니다. 작업에 대한 일반적인 개요만 제공하면 Spy가 나머지를 처리합니다. 미묘한 변경이라도 성능에 큰 영향을 미칠 수 있으므로 언어를 수정할 필요가 없습니다. Spy가 명령어를 최적화해 줍니다. 이에 대해서는 나중에 자세히 설명하겠습니다. 나중에 입력 및 출력 필드를 정의하는 방법이 있는데, 이 방법은 LLM 프로그램의 구성 요소에 대한 프롬프트와 구조화된 출력에 일관된 구문을 제공합니다. 이는 LLM 프로그램의 일관성을 보장하는 한 가지 방법입니다. 또 다른 흥미로운 기능은 LLM 모델이 서로 상호 작용하는 방식을 프로그래밍 방식으로 제어할 수 있다는 것입니다. 자, 이제 LLM 프로그래밍의 제어에 대해 이야기해 보겠습니다. 예를 들어, 특정 구문을 사용하여 프로그램에서 for 루프를 만들 수 있습니다. 이 예제에 없는 홉에도 접근할 수 있습니다. 이러한 루프를 연결하고 iflc 문을 사용하여 더 복잡한 코드를 작성할 수 있습니다. 간단한 예제를 살펴보겠습니다. 주식 티커를 입력하면 특정 회사에 대한 정보인 경우 프로그램에서 재무 정보를 출력하도록 할 수 있습니다. 제 프로그램은 먼저 재무 데이터베이스를 처리하고 해당 티커와 관련이 있는지 확인합니다. 관련이 있다면 해당 회사의 실적 및 보고서를 조사하도록 프로그램에 요청할 수 있습니다. 또한 프로그램을 사용하여 웹 쿼리를 수행하고 시장 동향 및 최근 뉴스에 대한 자세한 정보를 얻을 수 있습니다. 그런 다음 프로그램은 쿼리를 생성하여 API로 전송합니다.
