## 스크립트

[음악] 안녕하세요 여러분, 쿼드런트에 오신 것을 환영합니다. 저는 선 팬 쿠시입니다. 오늘은 벡터 데이터베이스 및 검색 분야에서 가장 주목받는 주제 중 하나인 검색 증강 생성 (RG)에 대해 이야기해 보겠습니다. 쿼드런트와 오픈 AI SDK 만을 사용하여 R 파이프라인을 간소화하여 구현하는 방법을 보여드리겠습니다. 최근 R 솔루션이 폭발적으로 증가하면서, 벡터 데이터베이스는 이러한 LLMS(임상 학습 모델)의 장기 메모리 역할을 합니다. R은 사용자의 쿼리에 대한 정보를 외부 지식 기반에서 검색하는 방법입니다. 이를 통해 LLMS가 허구적인 답변(환상)을 제공하는 경우를 줄이고, LLMS가 사실에 근거한 정확한 답변을 제공하도록 도와줍니다. 그럼 쿼드런트를 사용한 R 데모를 살펴보겠습니다. 본격적인 설명에 앞서 중요한 용어와 데이터 흐름에 대해 알아보겠습니다. 가장 중요한 세 가지 용어는 쿼리, 컨텍스트, 그리고 프롬프트입니다. 쿼리는 사용자가 묻는 질문이고, 컨텍스트는 사용자의 쿼리와 관련된 정보입니다. 이것이 바로 데이터 흐름입니다. 사용자가 질문을 하면, 그 질문은 지식 기반에서 유사한 컨텍스트를 검색하는 데 사용됩니다. 그리고 이 컨텍스트는 나중에 배우게 될 메타 프롬프트와 함께 표시됩니다. 메타 프롬프트는 기본적으로 질문 컨텍스트와 프롬프트를 일정한 형식으로 구성합니다. 이것이 데이터 흐름입니다. 이제 데모를 진행해 보겠습니다. Windows를 사용하시는 경우, Docker 앱을 설치해야 합니다. 먼저 실행해 보겠습니다. [음악] 또한, 이전에 제가 만든 가상 환경(Env environment)에 필요한 모든 패키지를 설치했습니다. ` pip install quadrant client fast embedd`와 `OpenAI` 명령어를 실행했습니다. 이제 실행이 완료되었습니다. Docker 앱을 확인해 보면 Quadrant가 사용 중인 것을 알 수 있습니다. 보시다시피 Quadrant 클라이언트를 가져왔고, 사용 중인 포트 633을 지정했습니다. 또한 `get collection` 명령어를 실행했습니다. 클라이언트에 이미 컬렉션이 있는 경우, 컬렉션 이름을 출력합니다. 현재 컬렉션이 없는 것 같습니다. 리스트가 비어 있으니 이제 컬렉션에 추가할 문서를 몇 개 추가해 보겠습니다. 이것은 벡터 데이터베이스용 웹 서비스를 만드는 데 사용할 수 있는 도구 목록입니다. 먼저 R을 추가해 보겠습니다. 자, 이제 이것을 컬렉션에 추가해 보겠습니다. 클라이언트를 추가해 봅시다. 컬렉션을 추가했습니다. 컬렉션 이름은 '지식 기반'인 것 같습니다. 이렇게 여러 개의 컬렉션이 생성되었으니 확인해 보겠습니다. 네, '지식'이라는 컬렉션이 있습니다. 일반 채팅 자동 완성 기능을 위한 것입니다. 중요한 파일은 모두 가져왔고, 어떤 도구를 사용할지 묻는 프롬프트도 표시했습니다. 웹 서비스를 구축하기 위해 벡터 임베딩을 사용했습니다. 문서를 기억하신다면, 기본적으로 사용 가능한 다양한 도구와 관련된 내용입니다. 하지만 이 예제에서는 R을 사용하지 않습니다. 단지 이 도구가 어떤 답변을 제공하는지, 그리고 나중에 RJ가 어떤 답변을 제공하는지 비교하기 위한 것입니다. 이제 실행해 보겠습니다. 네, 여기에서 API 키를 입력해야 합니다. 다음으로 넘어가기 전에 채팅 자동 완성 기능의 출력 결과를 간단히 설명하겠습니다. ID, 객체, 모델, 선택 항목이 포함된 Jason 출력이 표시됩니다. 이 출력에서 ​​내용을 추출하기만 하면 됩니다. 자동 완성의 경우, 선택 항목이 표시됩니다. 선택 항목은 리스트이므로 첫 번째 요소를 가져오면 됩니다. 메시지를 요청하고 완료 부분을 어시스턴트 역할에서 가져온 것으로 이해했으며 어시스턴트의 콘텐츠를 추출하려고 했습니다. 보시다시피 결과는 상당히 일반적입니다. 사용할 수 있는 다양한 프로그래밍 언어 웹 프레임워크가 제공되었지만 처음에 제공한 문서와는 아무런 관련이 없습니다. RG를 사용하여 채팅 완료를 테스트하고 차이점을 살펴보겠습니다. 이를 수행하려면 세 가지 메타데이터가 필요합니다. 프롬프트, 컨텍스트 및 질문입니다. 지식 기반에서 컨텍스트를 추출하려면 지식 기반 에서 최소 세 가지 관련 정보를 가져와야 합니다. 어떻게 하는지 살펴보겠습니다. 결과는 클라이언트 쿼리와 같습니다. 세 가지가 필요합니다. 컬렉션 이름(모두 알다시피 지식 기반입니다), 쿼리 텍스트, 음, 지식 기반의 이름은 실제로 밑줄이었습니다. 그래서 모든 컨텍스트를 결합하고 연결한 다음 메타 프롬프트를 만들었습니다. 답을 찾을 수 없으면 아는 척하지 마세요. 하지만 제가 몰랐던 답은 이것이 환각 현상을 방지하기 위한 것이라는 점입니다. 그래서 질문은 여전히 ​​웹 서비스를 구축하는 데 필요한 도구가 무엇인지 묻는 프롬프트입니다. 특히 검색을 위해 벡터 임베딩을 사용하는 경우, 이미 말씀드렸듯이 최소한 세 가지 요소, 즉 컨텍스트, 질문, 프롬프트가 필요합니다. 컨텍스트는 이미 여기에 제공되었으므로 이제 이 메타 프롬프트에 대한 채팅 완성 기능을 실행해 보겠습니다. 자, 이렇게 하면 지식 기반에서 정확한 컨텍스트를 얻을 수 있습니다. 파이프라인을 다시 진행하려면 컨텍스트를 가져와서 연결하면 됩니다. 메타 프롬프트에는 프롬프트, 질문, 컨텍스트를 제공했고, 이 메타 프롬프트를 사용하여 채팅 완성 기능을 실행하면 파이프 라인이 제대로 작동합니다. 오늘은 여기까지입니다. 이 중요한 주제에 함께해 주셔서 감사합니다. 앞으로 쿼드런트뿐만 아니라 AI 및 LLM과 관련된 다양한 중요 주제를 다룰 예정이니 기대해 주세요.
