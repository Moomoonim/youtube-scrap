JSON 파일을 이용해서 설정하기만 하면 됩니다. 방금 보여드린 레이아웃이 바로 저희가 하는 모든 일과 Data API Builder를 특별하게 만드는 이유를 요약한 것입니다 . 그러니까, 여러분이 제공하는 JSON 파일, 즉 맨 아래에 있는 설정 파일이 컨테이너로 전달되어 파일로 마운트되면, 런타임 엔진을 통해 동적으로 메모리 내에 추상화 객체를 생성하여 여러분이 노출하는 데이터베이스의 모든 데이터에 매핑합니다. 그러니까 그 JSON 파일에는 "여기에 제 연결 문자열이 있습니다. 연결 방식은 관리형 인스턴스든, 사용자 이름/암호 비활성화 방식이든, 패스스루 방식이든 상관없습니다."라고 적는 겁니다. 그런 다음 저희는 고객님의 데이터베이스에 연결할 것입니다. 그런 다음 해당 파일에서 Azure SQL, PostgreSQL, MySQL 또는 Cosmos에 노출하려는 테이블, 뷰 및 저장 프로시저를 명시합니다. 그런 다음 해당 데이터를 찾아 메타 메타데이터를 통해 유효성을 검사하고, 애플리케이션이 API와 상호 작용하기 시작하면 백엔드에서 쿼리를 생성하여 데이터베이스 와 신속하게 상호 작용할 수 있도록 하는 일종의 메모리 내 스키마를 만듭니다 . 안나, 그리고 이 기능의 가장 큰 장점은 엔지니어링 팀이 T-SQL을 완벽하게 이해하고 훌륭한 쿼리를 작성할 줄 아는 초고수 엔지니어 팀일 필요가 없다는 점입니다. 그 대신, JSON과 HTTP를 이해하고 다른 모든 것과 마찬가지로 엔드포인트와 상호 작용하는 개발팀만 있으면 됩니다. 그러면 저희가 API의 표면적인 부분을 활용하여 쿼리를 구성하는 방법을 알려드리겠습니다. 우리는 데이터베이스의 백엔드에서 쿼리를 실행합니다 . 그리고 좋은 점은 이러한 데이터베이스 중 어느 하나에든 연결할 수 있을 뿐만 아니라, 여러 데이터베이스에 동시에 연결할 수도 있다는 것입니다. 따라서 여러 데이터베이스를 보유하여 온프레미스 SQL 과 클라우드에 있는 SQL 모두에 연결할 수 있습니다. 이번 2.0 버전 출시로 그동안 정말 하고 싶었던 수많은 문제들을 해결했습니다 . 그리고 REST 엔드포인트 내부에 복합 경로와 같은 작은 기능들을 활용하면 원하는 API 표면을 구성하여 노출할 수 있습니다. 그래서 MCP 기능을 활성화하기 시작하면서 많은 부분이 중요한 기능이지만, 개발자 커뮤니티에 제공하고 싶었던 사소하지만 유용한 기능들도 포함되어 있습니다. 그리고 저희는 오픈 소스이기 때문에, 이러한 기능들은 대부분 커뮤니티의 기여와 저희 엔지니어링 팀의 노력 덕분에 가능했습니다. 마이크로소프트의 오픈 소스는 특별한데, 다른 곳의 오픈 소스와는 달리 유지보수 담당자가 여전히 활동 중인지 걱정할 필요가 없기 때문입니다. 마이크로소프트 입장에서는 오픈 소스가 하나의 제품으로 간주되어 정기적인 보안 검토를 거치기 때문입니다. 그래서 우리는 일반적인 오픈소스 저장소에서는 받을 수 없는 지속적인 내부 보안 감사를 받게 될 것입니다 . 따라서 이는 기업이 REST 엔드포인트를 사용하여 외부 고객이나 내부 애플리케이션에 데이터베이스를 AP에 노출하는 올바른 방법인지 결정할 때 또 다른 안정감을 제공합니다. 그래서 모든 면에서 상당히 강력합니다. 그리고 한 가지만 더 말씀드리자면, 가운데 있는 상자가 바로 데이터 API 빌더의 핵심 기능입니다. 그리고 거기 중간 아래쪽에 권한과 정책이 있었습니다. 그리고 저희가 할 수 있는 특별한 일 중 하나는 사용자 지정 조건자를 적용하는 것입니다.
