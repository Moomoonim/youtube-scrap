## 스크립트

Hi, I'm Paul Ramsey, a product manager here at Google. And today I'm excited to demonstrate a new capability in AlloyDB called Lakehouse Federation. To illustrate this feature, we'll use a fictional financial services organization called Simple Investments. They're a US-based global investment firm who recently modernized their legacy Oracle and SQL Server financial databases with AlloyDB. Imagine I'm an equity research analyst at Simple Financial, and I'm researching the impact of macroeconomic trends on equities in the S&amp;P 500. To accelerate this, I've stored 3.2 million text chunks and embeddings of the latest S&amp;P 500 10-Ks in AlloyDB. So now I can search through all of my 10-Ks using natural language, and AlloyDB will understand the semantic meaning behind my search. For example, I can search for 10-Ks that mention geopolitical instability and manufacturing relocation to help me better understand the impact of global trade policy and diplomatic tensions. But what if I want to filter my results by revenue, operating income, or some other dimension of my financial reference data that's stored in BigQuery? Or what if I want to compare my results to historical 10-K data that's already archived to my data lake in Parquet format? For that, I can use AlloyDB's new Lakehouse Federation feature. For example, let's say that I want to run the same vector query, but this time I want to focus on large companies with significant assets and operating income. I can instantly join my vector results with BigQuery reference data using Lakehouse Federation. And in this case, I was able to do it without moving any data. AlloyDB's Lakehouse Federation feature supports automatic pushdown of filters and aggregates to BigQuery, keeping performance fast and accurate. And for queries that require the lowest possible latency, we've introduced AlloyDB's one-click reverse ETL. This regularly syncs data from BigQuery into a local table in AlloyDB, giving us the insights we want from our BigQuery reference data with zero performance trade-offs. And what if I want to compare current 10-Ks of, let's say, this stock to previous 10-Ks that have already been archived to my data lake? With Lakehouse Federation, I can directly query my Parquet data in Iceberg to view historical data. I was able to do this without changing my connection string or managing another data source. Using AlloyDB as my unified access layer, my entire data platform, from live transactions to historical archives, is available through a single lens. And thanks for watching.
