## 스크립트

이 데모에서는 클라우드 전용 Entra 사용자를 위해 특별히 제작된 FSLogix를 사용한 Azure Virtual Desktop을 소개합니다 . 오늘은 Azure 파일 공유의 새롭고 흥미로운 기능을 소개해 드리겠습니다. 마이크로소프트 엔트라 ID부터 시작해 보겠습니다. 여기 테스트 사용자 코니 클라우드가 있습니다. 보시다시피 코니는 온프레미스 디렉터리에서 동기화되지 않았으며, 클라우드 전용 사용자이므로 클라우드 전용 사용자 보안 그룹의 구성원입니다. 다음으로 Azure Virtual Desktop 호스트 풀을 살펴보겠습니다. RDP 속성에서 이 호스트 풀이 Microsoft Entra 인증을 사용하도록 구성하여 원활한 단일 로그인 환경을 제공합니다 . 애플리케이션 그룹에서 이 데스크톱이 클라우드 전용 사용자 그룹에 직접 할당된 것을 확인할 수 있습니다. 자, 이제 저장 계정에 대해 자세히 살펴보겠습니다. 저희는 FSLogix 프로필을 저장하기 위해 특별히 설정된 Azure 파일 공유를 보유하고 있습니다. ID 기반 액세스 구성에서 클라우드 전용 ID를 지원하기 위해 Microsoft Entra Kerberos를 활성화했습니다. 이 구성을 완료하기 위해 인증된 사용자와 그룹이 SMB 공유 기여자 역할을 갖도록 기본 공유 권한을 활성화했습니다. 다음으로, '클라우드 전용 프로필'이라는 파일 공유 폴더를 만들었습니다 . 이 폴더로 이동하여 찾아보기를 선택하면 이제 Azure 포털에서 직접 파일 공유에 대한 액세스를 관리할 수 있습니다 . ' 액세스 관리'를 클릭하면 브라우저에서 바로 디렉터리 및 파일 수준의 권한을 정의할 수 있습니다 . 클라우드 전용 사용자 그룹에 해당 폴더에 대한 필요한 수정 권한이 부여되었음을 확인하실 수 있습니다. FSLogix의 권한 권장 사항에 따라 생성자 소유자는 하위 폴더 및 파일에 대한 모든 권한을 가지며, Azure 관리자 그룹은 모든 폴더 및 파일에 대한 모든 권한을 가집니다 . 이제 사용자 경험에 대해 이야기해 보겠습니다. 코니는 윈도우 앱을 실행 하고 엔트라 조인 데스크톱에 접속합니다. 싱글 사인온(SSO) 설정 덕분에 그녀는 끊김 없이 접속할 수 있습니다. 로그인하는 동안 FSLogix 앱과 사용자 프로필 서비스가 백그라운드에서 로드되는 것을 잠시 볼 수 있으며, 이는 사용자의 프로필이 동적으로 마운트되기 때문입니다. 접속 성공입니다. 코니가 윈도우 11 AVD 세션에 성공적으로 로그인했습니다. 그녀의 데스크톱은 준비되었고, 클라우드 전용 Entra 자격 증명을 사용하여 완벽하게 인증되었습니다. 마지막으로 프로필이 성공적으로 생성되었는지 확인해 보겠습니다. 포털에서 Azure 파일 공유로 다시 전환한 다음 디렉터리를 새로 고칩니다. Connie를 위한 새 폴더가 자동으로 생성되었으며, 그 안에 FSLogix VHD 프로필 컨테이너가 안전하게 저장되어 다음 세션에서 사용할 수 있도록 준비되었습니다.
