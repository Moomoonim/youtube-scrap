We begin understanding the core concepts behind FIR filtering and channelization. FIR filters are applied across multiple channels, with each channel processing its own data stream independently. This parallelism is key to leveraging&nbsp;AIE-DSPs&nbsp;effectively, enabling scalable and efficient signal processing. Let’s consider 8-tap channelized FIR filter, a common configuration that balances performance and complexity. FIR filters are applied across multiple channels, and each output is computed by multiplying 8 past complex input samples (each with 16-bit real and imaginary parts) by corresponding 16-bit integer coefficients, then summing the results. The example design that we have taken to for this video targets an AIE-ML implementation of our FIR filter. The system maintains a 256-bit AXI slave and master interface, ensuring direct compatibility with the existing DSP58-based design. Each channel requires sixteen multiply-accumulate operations for an eight-tap FIR at 200 mega-samples per second. Running the AIE-ML tile at 1.25 gigahertz provides six clock cycles per sample, meaning the filter must sustain roughly two-point-six-seven MACs per cycle per channel. Meeting this requirement ensures the AIE-ML implementation delivers equivalent throughput to the DSP58 reference while simplifying evaluation and integration into customer designs. Each channel requires&nbsp;16 MAC operations&nbsp;for 8 taps when processing&nbsp;16-bit complex integer data with&nbsp;16-bit integer coefficients. AIE-ML tiles operate at&nbsp;1.25 GHz, and at a sample rate of&nbsp;200 MSPS, only&nbsp;6 cycles&nbsp;are available to complete these operations. An optimized implementation uses 16×2 element-wise mul/mac operations&nbsp;to process 8 channels in just 4 cycles, leaving headroom for higher sample rates and additional processing. At&nbsp;200 MSPS, 8 channels generate a bandwidth demand of&nbsp;6,400 MB/s. This ensures smooth data flow and supports scalability as channel count or sample rate increases. This architecture uses ping-pong buffers and PLIO64s to manage data flow. When placing AI Engine kernels, keep these essential tips in mind to optimize performance, reduce routing delays, and ensure efficient resource use. Vertical routing is more efficient, and PLIO interfaces extend beyond the placement area, so aligning kernels vertically reduces routing complexity. Strategically skipping columns aligns vertical routes and PLIOs better within the placement area, which helps reduce latency variation across channels. Limiting the number of rows used in your kernel layout creates space above for additional kernels. This layout maintains vertical routing channels, which simplifies data movement to and from these upper kernels, improving overall system flexibility. Spreading kernels horizontally across the array is possible but less ideal. It can cause latency variations between channels, particularly at the array edges where horizontal routing becomes congested, impacting predictable performance.
