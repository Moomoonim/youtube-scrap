## 스크립트

Qdrant를 사용하여 빌드를 시작하기 전에, 먼저 Qdrant를 실제로 실행할 환경이 필요합니다. Qdrant는 오픈 소스이기 때문에 다양한 옵션을 활용할 수 있습니다. 로컬에서 실행하거나, 직접 배포하거나, 심지어 Qdrant 클라우드에서 실행할 수도 있습니다. 이 튜토리얼에서는 몇 가지 다른 옵션을 보여드리겠습니다. 다음으로, 저희는 자체적으로 무료 Qdrant 클러스터를 구축 하고 사용 가능한 도구들을 살펴보겠습니다. 이 과정을 마치면 첫 번째 프로젝트 에 사용할 수 있는 Qdrant 인스턴스를 갖게 될 것입니다 . 우선, 어떤 것을 만들려는지에 따라 적합한 옵션이 달라집니다. 그리고 Docker는 일반적으로 로컬 배포 및 테스트에 가장 쉽습니다 . Docker를 사용하여 Qdrant를 실행하려면 두 가지 명령이 필요합니다. 한 명은 이미지를 다운로드하고, 다른 한 명은 컨테이너를 시작하고 포트를 노출할 것입니다. 컨테이너가 실행되면 로컬 배포 환경을 테스트할 준비가 완료됩니다. 더 많은 유연성과 사용자 정의 기능을 원한다면 Docker Compose를 사용할 수도 있습니다. 이 예제는 재사용 가능한 compose 파일을 사용하여 단일 Qdrant 노드를 생성합니다 . Kubernetes를 사용하고 있다면 Helm 차트를 이용해 Qdrant를 배포할 수 있습니다. Qdrant를 Helm 저장소에 추가하고 차트를 설치하기만 하면 Qdrant가 Kubernetes 클러스터에 배포됩니다. 자, 그럼 이제 Qdrant 클라우드를 살펴보겠습니다. 이를 위해서는 qdrant.tech에 접속하여 "시작하기" 버튼을 클릭하기만 하면 됩니다. 제공되는 로그인 옵션 중 하나를 사용하여 계정을 만드세요 . 이미 구글 계정이 있으니 그냥 구글을 계속 쓸게요. 로그인하시면 클러스터 페이지로 이동합니다. 첫 번째 클러스터는 그냥 ' 첫 번째 클러스터'라고 이름을 붙이겠습니다. 사용 환경에 가장 적합한 클라우드 제공업체와 지역을 선택하세요. 학습 및 테스트에 아주 좋은 옵션이기 때문에 모든 항목을 자유 구성으로 선택하겠습니다 . 클러스터 준비가 완료되면 Qdrant는 API 키와 엔드포인트 두 가지를 표시합니다. 엔드포인트를 통해 클러스터의 실제 위치를 확인할 수 있습니다. API 키는 인증에 사용됩니다. 클러스터에 연결하려면 두 가지 모두 필요합니다. 자, 이제 Qdrant 웹 UI를 열어보겠습니다. 이것의 진짜 멋진 점은 웹 UI를 통해 클러스터를 탐색하고, 자신 만의 컬렉션을 관리하고, 요청을 실행하고, 대화형 튜토리얼을 따라할 수 있다는 것입니다. 왼쪽에는 콘솔, 컬렉션, 튜토리얼 및 데이터 세트가 있습니다. 콘솔을 사용하면 UI에서 Quadrant와 직접 상호 작용할 수 있습니다. 예를 들어, 컬렉션이 실제로 존재하는지 확인할 수 있습니다. 이 클러스터는 완전히 새로 만들어진 것이기 때문에, 여러분은 아직 그 존재를 인지하지 못할 것입니다. 컬렉션 페이지에는 클러스터에 저장된 모든 컬렉션이 표시됩니다 . 컬렉션은 Quadrant에서 벡터, 포인트 및 페이로드를 저장하는 곳입니다. 그리고 아직 만들지 않았으니 당연히 비어 있을 겁니다. 자, 이제 튜토리얼 과 데이터 세트로 넘어가겠습니다. 튜토리얼 선택 항목은 대화형이며 Quadrant 인스턴스에서 직접 실행할 수 있습니다. 빠른 시작 가이드를 따라하고, 샘플 데이터를 불러오고, 필터링을 시도하고, 하이브리드 검색을 사용해 볼 수 있습니다. 이 데이터 세트를 사용하면 실제로 샘플링 데이터를 얻을 수 있으므로 Quadrant에서 테스트할 수 있습니다 . 이렇게 하면 아무런 준비 없이도 빠르게 실험해 볼 수 있습니다. 자, 이제 쿼드런트 대시보드로 돌아가 보겠습니다. 웹 UI를 통해 Quadrant 내의 데이터를 활용할 수 있으며, 클라우드 대시보드는 클러스터 자체를 관리하는 데 도움이 될 것입니다. 여기에서 API 키를 관리하고, 성능을 모니터링하고, 로그를 확인하고, 구성을 업데이트할 수 있습니다. API 키 섹션으로 이동하면, 다른 API 키가 필요한 경우 대시보드에서 언제든지 새 API 키를 생성할 수 있습니다 . API 키 생성 옵션을 선택하고, 알아보기 쉬운 이름을 지정한 후 키를 생성하면 됩니다. 창을 닫기 전에 모든 키를 복사했는지 확인하세요. 자, 이제 측정 지표 페이지로 넘어가 보겠습니다. 메트릭 페이지에서는 클러스터의 실제 성능을 확인할 수 있습니다. 하지만 다시 말씀드리지만, 이 클러스터는 완전히 새것이고 아직 아무것도 표시하지 않았기 때문에 여기에는 아무런 활동도 없을 것입니다. 사용을 시작하면 요청, 메모리 사용량 및 기타 성능 정보를 모니터링할 수 있습니다. 자, 이제 로그 페이지로 넘어가 보겠습니다. 로그 페이지는 클러스터 의 활동 및 문제를 검사하는 데 도움이 됩니다 . 구성 섹션에서는 지원되는 쿼드런트 설정을 검토하고 조정할 수 있습니다. 하지만 첫 번째 프로젝트에서는 이러한 사항들을 변경할 필요가 없습니다. 애플리케이션이 본격적으로 성장함에 따라 이러한 기능들이 더욱 유용해집니다. 마지막으로 쿼드런트 클라우드 추론이 있습니다. Quadrant 에 텍스트, 이미지 또는 기타 콘텐츠를 저장하기 전에 일반적으로 이미지나 텍스트를 벡터로 변환하는 임베딩 모델이 필요합니다. 클라우드 추론은 이 부분을 해결하는 데 도움이 됩니다. 지원되는 모든 모델과 지원되는 외부 모델을 보여줍니다. 임베딩과 추론에 대해서는 다른 튜토리얼에서 자세히 살펴보겠습니다. 그게 다입니다 . 이제 여러분은 Quadrant를 다양한 방식으로 실행하는 방법을 알게 되었습니다. 이 영상이 도움이 되었기를 바랍니다. 시청해 주셔서 감사합니다.
