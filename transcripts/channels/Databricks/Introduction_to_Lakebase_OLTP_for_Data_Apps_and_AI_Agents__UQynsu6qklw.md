Next, let's talk a little bit deeper about the architecture behind Lakebase. It's not built on a new database management system. Instead, it's built on Postgress and more specifically a serverless Postgress architecture. So, let's see what that exactly means. If you're an application developer, you're already familiar with Postgress. It's a battle tested, open-source, and very popular OLTP database with a thriving community of contributors, users, and extensions. Take PG Vector for example. With PG vector you can add vector search capabilities to your Postgres database just by adding an extension and with that you can do semantic search over your data which is perfect for use cases like rag. Postgress is quickly becoming the most popular OLTP database just like git for version control. Postgress will be the default for building applications. But lakebase is not just Postgress it's serverless Postgress. One of the most fundamental principles of the lakehouse is the separation of storage and compute and serverless Postgress is bringing that to Postgress databases. With the separation of storage and compute and serverless Postgress, we can enable some really awesome features for an amazing developer experience like database branching, point in time recovery, and even time travel queries. We'll have more to share about these features very soon. All right, so when would you want to use lakebase?
