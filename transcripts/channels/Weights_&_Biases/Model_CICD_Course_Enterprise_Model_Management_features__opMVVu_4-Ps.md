## 스크립트

안녕하세요, 노아. 모델 레지스트리에 대한 개요와 그 핵심적인 내용들을 정리하는 데 도움을 주셔서 정말 감사합니다. 아시다시피, Weights and Bias 초기에는 제가 직접 엔터프라이즈급 도구들을 많이 만들고 여러 가지를 연결했었죠. 그런데 지금은 노아님께서 많은 기능을 개발하셔서 사람들이 직접 만들 필요 없이 한두 줄의 코드로 모든 것을 연결할 수 있게 되었다는 것을 알고 있습니다. 그런 엔터프라이즈급 기능들 중에서 특히 눈에 띄는 기능이나 인기 있는 기능, 그리고 앞으로 개발하실 기능에 대해 간략하게 말씀해 주시겠어요? 네, 물론이죠. 어디서부터 이야기해야 할까요? 좋은 기능들이 정말 많지만, 아티팩트를 이미 사용하고 계신 분들은 잘 알고 계실 만한 기능 하나를 먼저 말씀드리고 싶습니다. 모델 레지스트리에만 국한된 기능은 아니지만, 바로… 일반적으로 기업 팀들은 모든 모델과 데이터 세트를 다른 곳에 저장해 두고 작업합니다. 이 과정을 따라오면서 모델 레지스트리 데모를 보셨다면, " 좋은데, 우리는 이미 모든 모델 파일을 S3에 저장하고 있잖아요. 이게 나랑 무슨 상관이죠? 파일을 다운로드해서 로컬에 업로드하고 싶지도 않고요."라고 생각하실 수도 있습니다. 그래서 Weights and Bias가 아닌 외부 저장소에 있는 파일도 추적하는 방법을 설명하는 문서를 보여드리겠습니다. 고객들이 가장 흔하게 사용하는 방법은 모델을 S3나 Azure, GCS 같은 주요 클라우드 저장소에 저장하는 것입니다. 이 코드 스니펫을 보시면, 마치 아티팩트에 파일을 추가하는 것처럼 버킷 내의 특정 위치에 대한 참조를 아티팩트에 저장할 수 있습니다. 이렇게 하면 파일을 직접 이동하는 번거로움을 피할 수 있습니다. 가중치와 편향을 사용하여 버킷 안의 모든 것을 그대로 유지하면서 해당 버킷이 어디에 있는지에 대한 포인터를 추가하는 것입니다. 파일을 추가하거나 디렉터리를 추가하는 대신, 여기에 직접 참조를 추가하는 방식입니다. 사용하는 공급자 유형에 따라 다르겠지만, 저희는 NFS 드라이브도 지원합니다. 이 과정을 자세히 설명하는 훌륭한 가이드가 있으니 문서를 참조해 보세요. 문서에는 전반적인 내용이 나와 있습니다. 버킷에서 데이터를 옮길 필요는 없습니다. 가중치와 편향을 사용하여 모델을 표시하고 레지스트리에 연결하는 장점은 S3 위에 계층을 추가하는 것과 같습니다. 이를 통해 자동 버전 관리 및 계보와 같은 모든 기능을 API를 사용하여 구현할 수 있습니다. 즉, 기본 스토리지는 그대로 유지되지만, 가중치와 편향을 사용하는 것이 더 효율적입니다. 클라우드 제공업체에 대한 이야기도 좋고, 엔터프라이즈 고객을 위한 중요한 기능에 대해 말씀드리고 싶었던 또 다른 내용은 보호된 별칭에 관한 것입니다. 별칭에 대해서는 모델 레지스트리에서 모델 수명 주기를 추적하는 데 얼마나 중요한지, 즉 어떤 버전이 어떤 상태에 있는지 파악하는 데 얼마나 중요한지 이미 이야기했습니다. 보호된 별칭은 특정 별칭을 관리자 전용으로 표시하는 기능입니다. 즉, 모든 사람이 해당 별칭(예: 프로덕션 또는 평가판)을 추가할 수 있는 것이 아닙니다. 일반적으로 고객은 프로덕션과 같이 중요한 별칭을 사용하여 모든 사람이 모델을 해당 상태로 승격시킬 수 없도록 제한합니다. 왜 이것이 중요할까요? 예를 들어, 프로덕션과 같은 별칭이 자동화를 시작하는 데 사용될 수 있기 때문입니다. 별칭을 사용하여 자동화를 시작할 수 있으므로 팀의 모든 사람이 해당 기능을 사용할 수 없도록 해야 합니다. 아시다시피, 프로덕션 별칭을 추가하는 기능입니다. 사용자가 제어하거나 팀 관리자가 제어할 수 있도록 특정 별칭 세트를 저장하여 모델 레지스트리 관리자 역할만 가진 사용자만 추가할 수 있도록 하는 기능입니다. 위에서 볼 수 있듯이 이 기능은 모델 레지스트리 설정에서 관리됩니다. 관련 문서에 자세히 설명되어 있지만, 모델 레지스트리 설정에서 찾을 수 있습니다.
