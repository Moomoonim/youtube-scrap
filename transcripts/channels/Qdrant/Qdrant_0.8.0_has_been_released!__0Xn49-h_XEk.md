## 스크립트

드디어 Quadrant 0.8이 출시되었습니다! 성능 향상은 물론, 모두가 기다려온 새로운 기능들도 추가되었습니다. 이번 영상에서는 이러한 새로운 기능들을 자세히 살펴보겠습니다. Quadrant는 벡터 데이터베이스로, 최근접 이웃 검색 과 추가 필터링 기능을 손쉽게 사용할 수 있습니다. 지금까지는 단일 머신에서만 실행할 수 있었기 때문에, 대규모 컬렉션을 다룰 때는 머신에 상당한 양의 메모리를 할당해야 했습니다. 또한, 모든 검색 작업이 동일한 머신에서 실행되므로 여러 클라이언트의 동시 접속 트래픽 처리에 병목 현상이 발생할 수 있다는 단점도 있었습니다. 최신 버전의 Quadrant에는 실험적인 분산 모드가 포함되어 있어, 이제 데이터를 여러 머신에 분산하여 실행할 수 있습니다. 내부적으로는 수평 파티셔닝을 사용하여 컬렉션을 서로 겹치지 않는 여러 부분 또는 차트로 나눕니다. 즉, 각 머신이 데이터 포인트의 하위 집합만 처리하므로 쿼리가 모든 머신에서 동시에 병렬로 실행될 수 있습니다. 향후 릴리스에서는 복제 기능을 지원하고 기본 허용 오차 속성을 추가할 계획입니다. 이번 릴리스의 주요 변경 사항은 이것만이 아닙니다. 쿼드런트를 사용하면 벡터 유사도뿐만 아니라 기존 필터를 사용하여 검색할 수도 있습니다. 따라서 기준에 맞는 데이터 포인트만 반환됩니다. 이 필터링 기능을 사용하려면 벡터와 함께 JSON 페이로드를 제공해야 하며, 선택한 속성 값 또는 여러 속성을 동시에 기준으로 쿼리할 수 있습니다. 이전에는 모든 페이로드가 RAM에 로드되어 메모리 요구량이 다소 증가할 수 있었습니다. 이제 특정 컬렉션에서 페이로드에 자주 액세스하지 않을 것으로 예상되는 경우 모든 페이로드를 디스크에만 저장하도록 컬렉션을 생성하여 메모리 사용량을 줄일 수 있습니다. 하지만 필터를 광범위하게 사용하는 경우 검색 중에 일부 I/O 작업이 실행되므로 지연 시간이 증가할 수 있습니다. 그러나 데이터와 쿼리 방식을 잘 알고 있다면 동일한 시스템에 더 많은 벡터를 저장할 수 있다는 점이 반가울 것입니다. 신경망 검색을 수행하는 데 반드시 128GB의 RAM이 필요한 것은 아니므로 비용을 절감할 수 있습니다. 마지막으로, 가능성이 있습니다. 많은 분들이 요청하셨던 유사도 점수별 필터링 기능을 드디어 구현했습니다! 거리 함수와 특정 허용 임계값을 알고 있다면 검색 쿼리에 입력하여 해당 임계값 미만의 결과는 모두 제외할 수 있습니다. 쿼드런트 기능은 어떠셨나요? 아래 댓글로 의견을 남겨주시고, 마음에 드 셨다면 GitHub 페이지를 방문하여 별점을 주세요!
