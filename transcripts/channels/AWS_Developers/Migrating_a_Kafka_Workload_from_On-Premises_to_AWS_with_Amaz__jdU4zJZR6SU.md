## 스크립트

이번 데모에서는 Ache Copper를 사용하여 여러 시스템과 데이터를 공유하는 Java로 작성된 커넥터를 마이그레이션하는 방법을 보여드리겠습니다. 오늘 우리의 목표는 이 커넥터를 온 프레미스에서 AWS로 마이그레이션하여 이미 배포된 애플리케이션과 데이터를 공유할 수 있도록 하는 것입니다. 그럼 바로 시작해 보겠습니다. 먼저 Maven을 사용하여 Java 코드의 로컬 버전을 빌드해 보겠습니다. ` Maven package` 명령어를 실행하여 jar 파일을 생성하겠습니다. 보시 다시피 테스트에서 ER이 발생하고 있습니다. 빌드 중에 테스트를 건너뛸 수 있지만 정확한 명령어가 기억나지 않습니다. 이러한 경우에는 QAI를 사용하여 명령 줄에서 도움을 받을 수 있습니다. QAI에서는 테스트를 건너뛰고 Maven 빌드를 실행하는 방법을 묻습니다. 권장 사항은 `--` 매개변수를 사용하는 것입니다. `skip test`는 ` Simple execute`로 실행됩니다. 잘 되는지 확인해 보겠습니다. 네, 잘 됩니다! 빌드가 성공적으로 완료되었지만 실패한 테스트는 건너뛰었습니다. 이제 다음 단계로 넘어가겠습니다. 방금 구축한 커넥터를 AWS의 Amazon MSK Connect 서비스를 사용하여 배포하려고 하는데, Terraform을 사용하여 클러스터를 정의하는 코드의 일부만 가지고 있습니다. Terraform으로 Amazon MSK Connect와 동일한 기능을 구현하는 방법을 전혀 모르겠습니다. 그래서 Amazon Q Developer의 LASHD 기능을 사용하여 이 프로젝트에 로컬로 배포된 커넥터에 대한 Amazon MSK Connect 서비스를 정의하는 Terraform 코드를 생성하려고 합니다. 이 프롬프트가 표시되면 Amazon Developer가 프로젝트를 스캔하고 방금 구축한 jarard를 사용하여 적절한 참 코드를 생성합니다. 어떻게 되는지 지켜보겠습니다. Amazon Q Developer가 생성한 권장 사항인 ' 계획'이 표시됩니다. 이 계획은 요청 된 코드를 생성할 뿐만 아니라 다음에 수행할 작업에 대한 아키텍처 지침도 제공하는 매우 상세한 지침 모음입니다. 예를 들어, 커넥터가 시스템 과 통신하려면 정책이 필요하므로 정책 생성을 고려해야 한다는 점을 상기시켜 줍니다. 이는 코드 정의를 넘어선, 반드시 해야 할 작업입니다. 개발자들이 매일 어려움을 겪는 부분 중 하나가 바로 아키텍처 모범 사례입니다. 개발자들은 문제 해결을 위해 관련 자료를 읽고, 구글 검색을 하고, 연구하는 과정을 거쳐야 합니다. 이러한 과정이 없다면 문제가 발생할 수 있기 때문입니다. AWS는 개발자들이 코드뿐 아니라 AWS 및 클라우드에 대한 전문 지식을 바탕으로 목표를 달성할 수 있도록 완벽한 개발 환경을 조성하는 전략을 펼치고 있습니다. 이제 배포를 위한 TARMB 코드를 실행할 준비가 거의 다 되었는데, Amazon Q 개발자가 생성한 코드에서 한 가지 의문점이 있습니다. 바로 커넥터와 함께 사용하도록 권장된 특정 역할입니다. 왜 이 역할이 권장되었는지 완전히 이해가 되지 않습니다. Amazon Q 개발자에게 전송된 이 코드를 선택하여 추가 설명을 요청할 수 있습니다. 이 코드와 해당 역할이 필요한 이유에 대한 설명을 직접 작성할 수 있습니다. Amazon Q 개발자를 사용하면 직접 작성했거나 Amazon Q 개발자가 생성한 코드에 대한 추가 설명을 요청할 수 있습니다. 보시는 바와 같이, 이는 코딩과 관련된 특정 접근 방식에 대한 추론과 아키텍처적 결정 사항을 완전히 이해하는 데 도움이 됩니다.
