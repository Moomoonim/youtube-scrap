## 스크립트

작업 부하에 가장 적합한 데이터베이스를 선택하는 AI 에이전트를 구축해 봅시다 . SQLlight, duct DB, Level DB를 비교하는 데이터베이스 성능 평가 도구를 만들겠습니다. 각 프로젝트의 실제 GitHub 저장소에 연결하여 성능을 검증할 것입니다 . 에이전트는 스토리지 모델, 산성 보장, 쓰기 처리량, 쿼리 기능 및 Python API의 단순성을 평가합니다. 그리고 모든 응답은 코드로 분석할 수 있는 구조화된 권장 사항으로 마무리됩니다. 이를 위해 커넥터를 사용할 것입니다 . 커넥터는 등록된 MCP 서버로, MCP 전송을 로컬에서 관리할 필요 없이 Ristl SDK API에서 제공하는 도구, 대화 및 에이전트를 Studio와 Vibe에서 직접 사용할 수 있습니다 . 이 예시는 그저 시작점에 불과합니다. 이 코드를 수정하여 모든 라이브러리, 서비스 또는 프레임워크 세트를 비교할 수 있습니다. 이 과정을 마치면 커넥터에 대한 모든 프로그래밍 방식의 CRUD 단계를 알게 될 것입니다 . 새 커넥터를 생성하고, 기존 커넥터에 대한 세부 정보를 읽고 , 커넥터를 업데이트하고, 삭제할 수 있습니다. 우리는 Mistral Python SDK를 사용하여 Deep Wiki MCP 서버에 연결하기 위한 커넥터를 프로그래밍 방식으로 구성할 것입니다. Deep Wiki MCP 서버는 공개 GitHub 저장소를 인덱싱하고 에이전트가 호출할 수 있는 도구로 노출합니다. 따라하기 쉬운 노트와 문서 링크는 설명란에 있습니다. 자, 시작해 볼까요? 먼저 Mistl 계정과 API 키가 필요합니다. 스튜디오에서 커넥터 액세스 범위에 대한 API 키를 생성할 수 있습니다 . 여기서 사용하는 것이 개인용 및 공유용 커넥터이므로 반드시 표시해 두세요 . 저희가 만드는 비공개 커넥터입니다. 잠시 후 API 키를 환경에 추가할 예정이니 잘 보관해 주세요 . 하지만 먼저 mist 파이썬 SDK를 설치해 보겠습니다. 이제 임포트를 설정하고 클라이언트를 초기화해 보겠습니다 . 우리는 OS를 가져와 환경 변수에서 API Q를 읽고 SDK에서 MRO 클라이언트를 가져옵니다. 여기서 보시다시피 , 이 코드 블록을 실행하면 API 키를 추가하라는 메시지가 나타납니다. 이제 커넥터를 추가하겠습니다. 그렇다면 그것들은 정확히 무엇일까요? 커넥터는 Mistral 서비스(즉, 에이전트, 워크플로 및 Vibe)와 외부 데이터 소스 간의 명명되고 재사용 가능한 연결 고리입니다. 에이전트에 커넥터를 연결하면 에이전트는 해당 커넥터를 도구로 호출하여 커넥터가 제공하는 기능에 따라 지정된 작업을 수행할 수 있습니다. 딥위키가 좋은 예입니다. 이 프로그램은 GitHub 저장소 경로를 입력받아 소스 코드를 크롤링하고 쿼리 가능한 형태로 변환합니다. 따라서 인공지능에게 SQL 경량 스토리지 모델이 무엇이라고 생각하는지 묻는 대신 , 코드를 읽어보라고 요청할 수 있습니다 . 데이터베이스별로 커넥터를 하나씩 생성하고 , 모든 커넥터는 동일한 딥 위키 MCP 서버 URL을 가리키도록 하되, 저장소 경로는 서로 다르게 설정합니다. 이 주소는 딥 위키 MCP 서버의 URL입니다. 또한 각 데이터베이스에 대한 다양한 옵션을 구분하는 데 사용할 커넥터 제목 및 설명을 위한 배열을 추가할 것입니다 . 커넥터를 생성하기 위해 동기식 `connectors create`를 호출하고, 작업 공간에서 커넥터를 활성화하기 위해 빈 자격 증명을 전달하는 비동기식 `create or update user credentials`를 호출합니다. 나중에 커넥터 목록을 만들 때 쉽게 필터링할 수 있도록 세 커넥터 이름 모두에 "showdown"이라는 접두사를 붙였습니다. 이제 ` connectors list async` 명령어를 사용하여 커넥터가 올바르게 등록되었는지 확인해 보겠습니다. 계정에 연결된 모든 커넥터를 나열하고, 그중 ' showdown'으로 시작하는 커넥터만 필터링합니다. 또한 커넥터에서 사용할 수 있는 도구 목록을 제공하여 커넥터의 기능을 확인할 수 있도록 하겠습니다. 스튜디오에서 특정 도구를 활성화 또는 비활성화할 수 있으므로 사용자와 상담원은 원하는 도구에만 액세스할 수 있습니다 . 커넥터 등록이 완료되었으므로 이제 에이전트를 구축할 준비가 되었습니다 . 에이전트로부터 일관된 형식의 데이터를 반환하기 위해 JSON 응답 스키마를 생성합니다 . LLM은 결정론적이지 않기 때문에 응답 형식이 매우 다양할 수 있습니다. JSON 형식으로 출력을 반환하면 특정 필드의 데이터를 가져와 일관된 방식으로 처리할 수 있습니다. Mistro medium 최신 버전을 사용하여 에이전트를 생성 하고 커넥터 ID 목록에 있는 세 개의 커넥터 ID를 모두 전달합니다. 이제 상담원은 이 세 가지 모두를 호출 가능한 도구로 이용할 수 있습니다. 응답 형식을 에이전트에 알려주기 위해 JSON 스키마를 완료 인수로 추가합니다 . 이제 담당자에게 전화해서 지시사항을 전달합니다. 에이전트가 도구를 호출하는 시점을 추적하고 확인할 수 있도록 비동기 스트림 시작 기능을 사용하고 있습니다. 이 과정은 다소 시간이 걸릴 수 있으므로 데모 목적으로 활동을 모니터링할 수 있습니다 . 스트림이 완료되면 비동기 메시지 가져오기를 사용하고 마지막 메시지 출력을 가져와 JSON 형식의 최종 응답을 얻습니다. 그런 다음 JSON을 구문 분석하여 읽기 쉬운 형식으로 출력합니다. 각 커넥터에 대한 질문과 그에 대한 요약 , 차원별 비교, 근거 및 최종 권장 사항. 이 코드를 실행해 보면 에이전트가 여러 도구를 호출하고 소스 코드와 커밋 기록을 읽은 후 답변을 생성하는 것을 확인할 수 있습니다. 이제 우리는 답변을 얻었습니다. 각 데이터베이스에 대해 5가지 기준 모두를 포괄하는 구조화된 분석 결과를 확인할 수 있으며, 마지막에는 권장 사항이 제시됩니다. 커넥터 덕분에 여기서의 심층적인 분석은 소스 코드에서 직접 이루어집니다. 이제 두 가지 일을 하겠습니다. 우승한 커넥터의 설명을 업데이트하여 선택되었음을 표시하고 나머지 두 데이터베이스에 대한 커넥터를 삭제합니다 . 승자 이름을 알았으니, ' 결승전' 대신 '선정됨'으로 업데이트합니다. 그런 다음 반복 작업을 통해 나머지 항목들을 삭제합니다. 커넥터를 비동기적으로 업데이트하려면 커넥터 ID와 변경하려는 필드를 입력으로 받습니다. 여기서는 이름과 설명을 업데이트하고 있지만, URL이나 인수를 업데이트할 수도 있습니다 . 커넥터 삭제 비동기 작업은 커넥터 ID만 필요로 합니다 . 그게 다예요. 해당 커넥터가 계정에서 사라졌습니다. 마지막 단계로, 데모 목적으로만 사용되는 에이전트를 정리하겠습니다. 에이전트 ID를 에이전트 삭제 비동기 함수에 전달하여 에이전트를 삭제합니다 . 선택한 커넥터는 삭제하지 않는 한 그대로 유지됩니다. 선택된 커넥터를 삭제하려면 해당 단계의 주석 처리를 해제하면 됩니다 . 그게 다입니다. 저희는 실제 소스 코드를 읽고 증거 기반 추천을 제공한 다음, 승자를 업데이트하고 나머지를 삭제하여 자체적으로 정리하는 데이터베이스 대결 심사 에이전트를 개발했습니다. 우리는 커넥터의 전체 수명 주기를 활용합니다. 세 개의 MCPback 커넥터를 등록하기 위한 비동기 작업을 생성합니다. 목록을 비동기 방식으로 확인하여 검증하십시오. 에이전트에 연결하기 위한 커넥터 ID입니다. 승자를 표시하기 위해 비동기적으로 업데이트합니다 . 그리고 비동기 기능을 삭제하여 패배자들과 에이전트 자체를 제거하십시오. 그게 바로 완전한 순환 과정입니다. 계속해서 개발을 진행하려면 설명란에 링크된 커넥터 문서와 전체 노트북을 확인하세요 . 시청해 주셔서 감사합니다.
