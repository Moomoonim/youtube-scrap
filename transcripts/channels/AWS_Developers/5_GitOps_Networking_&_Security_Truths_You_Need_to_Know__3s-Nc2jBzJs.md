GIOps를 활용한 네트워크 보안 및 규정 준수를 위한 다섯 가지 팁을 살펴보기 전에, 먼저 GIOps가 무엇인지 알아보겠습니다. GIOps는 DevOps의 진화형으로, GIOps의 목표이자 기본 전제는 인프라 코드와 비즈니스 애플리케이션을 분리하는 것입니다. 이를 통해 개발자는 파이프라인을 구축하고 비즈니스 로직에 집중할 수 있으며, 인프라에 대해서는 걱정할 필요가 없습니다. 네트워크 팀과 운영 팀은 인프라를 G를 통해 코드로 배포할 수 있습니다. 이제 버전 관리 시스템을 갖추고 CICD 파이프라인을 통해 이 모든 것을 통합할 수 있습니다. 첫 번째로 네트워킹부터 시작해 보겠습니다. 네트워크 인프라의 모놀리식 구조를 분해하는 것이죠. 종종 매우 큰 규모의 배포 환경, 특히 라우팅 테이블이 엄청나게 큰 트랜짓 게이트웨이를 접하게 됩니다. th000 라우팅은 모든 VPC를 해당 Transit Gateway 라운딩 테이블과 연결된 Transit Gateway에 연결합니다. 따라서 라운딩 테이블을 변경하면 전체 네트워크에 영향을 미칩니다. 이러한 모놀리식 아키텍처는 분해하여 마이크로 아키텍처로 재구성할 수 있습니다. 이제 자체 VPC를 갖춘 개발 환경과 중앙 집중식 네트워크 계정을 통해 인프라를 분할할 수 있습니다. 이제 CICD와 GitOps를 활용하는 방법을 알아볼 수 있습니다. 두 번째로, GitOps와 관련하여 Git과 인프라를 코드로 관리해야 합니다. 인프라 코드란 현재 ClickOps를 사용하고 있는 네트워크 배포 환경을 CloudFormation이나 Terraform과 같은 도구를 활용하여 템플릿으로 만들고, 해당 템플릿을 Virgin Control에 추가한 다음 AWS CCommit과 같은 도구를 사용하여 Virgin Control 시스템에서 템플릿에 대한 풀 리퀘스트를 수행하는 방법을 의미합니다. 이제 인프라를 자동화하는 방법을 알아보겠습니다. 코드에 대해 이야기하고 나서 G Ops의 강력한 기능을 활용할 수 있습니다. CICD에 대해 이야기하기 전에 먼저 보안에 대해 생각해 봐야 합니다, 브랜든. 네, 세 번째로 알아야 할 사항은 파이프라인 보안입니다. 다난이 코드 커밋에 대해 언급했듯이 파이프라인은 코드 커밋, 코드 파이프라인, 코드 빌드와 같은 몇 가지 요소로 구성됩니다. 이 각 영역은 보안이 매우 중요합니다. 코드 커밋의 경우 권한과 저장소( HTTPS, SSH 등) 접근 권한을 고려해야 하며, 자격 증명이 IM에 연결되어 있는지 확인해야 합니다. 코드 파이프라인에는 서비스 RO가 사용되는데, 이 서비스는 활성화될 때 생성됩니다. 이 서비스가 우리가 원하는 서비스에만 접근하도록 제어해야 합니다. 민감한 정보는 코드에 직접 넣는 대신 파라미터 스토어를 사용하여 저장해야 합니다. 또한 모든 빌드 아티팩트는 암호화해야 하며, 이를 위해 KMS와 고객 관리 키를 사용할 것입니다. 또한 VPC 내에서도 실행할 수 있습니다. 기본적으로는 VPC 내에서 실행되지 않지만, 보안 그룹을 적용하여 파이프라인 전체의 트래픽 흐름을 제어할 수 있습니다. 즉, 파이프라인 보안을 강화하는 것이 중요합니다. 이제 네 번째로 살펴볼 부분은 파이프라인 전체의 보안입니다. 중요한 코드를 파이프라인을 통해 배포하는 만큼, 해당 코드가 안전하게 보호되어야 합니다. 이를 위한 두 가지 방법은 린팅과 CFN Guard를 이용한 가드레일 설정입니다. 린팅은 구문 뿐만 아니라, 공용 라우팅 테이블이 개인 라우팅 테이블과 연결되었는지, 또는 공용 서브넷이 개인 라우팅 테이블과 연결되었는지와 같은 오류를 검사합니다. 이러한 오류는 보안 문제로 이어질 수 있으므로 린팅은 매우 중요합니다. 다음으로 CFN Guard를 설정하여 가드레일을 구성하면, 특정 부분을 검사하고 보안 취약점을 파악할 수 있습니다. 제 Transit Gateway가 기본 라우팅 테이블을 사용하도록 하고 싶습니다. 따라서 여기에 코드를 푸시할 때마다, 해당 코드에 Transit Gateway 구성이 있든 없든, Transit Gateway 구성이 있는 경우 기본 라우팅 테이블을 사용하지 않도록 하고, 배포 전에 미리 적용할 수 있는 이러한 안전장치를 마련해 두었습니다. 파이프라인을 진행하면서 이를 확인하고, 실패하면 수정하고, 통과하면 테스트 페이지로 이동합니다. 이것이 네트워크, 보안 및 규정 준수를 위한 운영을 할 때 알아야 할 네 번째 사항입니다. 이제 다섯 번째 사항에 대해 이야기해 보겠습니다. 다섯 번째는 AWS의 CICD(AW Code Pipeline)를 사용하여 모든 것을 통합하는 것입니다. 이 파이프라인에서 앞서 언급했듯이 인프라는 코드입니다. 이제 여러분은 노트북이나 Cloud9에서 YAM 파일, JSON 파일, CloudFormation 파일 또는 Terraform 파일을 사용하여 템플릿을 구축하고, 소스와 상태를 파이프라인으로 보냅니다. 파이프라인의 첫 번째 단계는 다음과 같습니다. 소스 단계에서는 버전 관리를 하고 있습니다. 이제 파이프라인이 저장소의 변경 사항을 감지하면 전체 파이프라인이 빌드 단계로 이동하여 CFN(접근성 검사) 알림을 실행하고 사용자 승인 테스트 단계에서 필요한 모든 테스트를 실행합니다. 빌드 환경(예: Docker 컨테이너인 AWS CodeBild)에서 로컬 테스트를 통과하면 테스트 환경에 배포하여 접근성 분석 도구 와 네트워크 액세스 분석 도구를 사용하여 필요한 네트워크 액세스 및 경로가 제대로 설정되어 있는지 확인합니다. 그런 다음 승인 절차를 거치고 모든 테스트가 성공적으로 통과되면 프로덕션 단계의 체인 세트로 이동합니다. 체인 세트가 승인되면 모든 변경 사항이 프로덕션 환경에 적용되고, 프로덕션 환경에 배포할 수 있습니다. 이제 접근성 분석기, 네트워크 액세스 분석기, AWS Config Security Hub와 같은 도구를 사용하여 지속적 통합 및 지속적 평가를 수행할 수 있습니다. 이제 네트워크 인프라를 위한 완전 자동화된 파이프라인을 구축했습니다. 이 영상 재밌게 보셨나요?
