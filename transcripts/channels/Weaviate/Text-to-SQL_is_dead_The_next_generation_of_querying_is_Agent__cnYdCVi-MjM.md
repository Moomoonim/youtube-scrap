## 스크립트

대규모 언어 모델의 진정한 힘이 드러나기 시작했습니다. 자연어 입력을 받아 데이터베이스와 같은 외부 도구와 상호 작용하여 작업을 수행하는 방법을 결정하는 능력이 바로 그것입니다. 하지만 어떤 모델이 에이전트로서 가장 효과적인지는 아직 미지수입니다. 이 논문의 연구원들은 쿼리 함수 호출이라는 새로운 유형의 에이전트가 기존 방식을 뛰어넘는 방식을 탐구합니다. 그들은 다양한 모델에 대한 포괄적인 분석을 수행했으며, 심지어 모델 테스트를 위해 새로운 데이터 세트까지 만들었습니다. 결과는 잠시 후에 살펴보겠지만, 먼저 그들이 제안한 또 다른 아이디어에 대해 이야기해 보겠습니다. 기존에는 AI 모델을 사용하여 고급 데이터베이스 쿼리를 수행하려면 텍스트 -SQL 변환을 시도하는 경우가 많았습니다. 이 모델은 자연어 질문을 받아 SQL 쿼리로 변환합니다. 하지만 이 방식에는 몇 가지 문제가 있습니다. SQL 방언은 데이터베이스마다 다를 수 있으며, 모델은 필터링, 집계, 검색과 같은 실제적인 복잡성을 처리하는 데 어려움을 겪을 수 있습니다. 이 논문에서는 원시 SQL을 생성하는 대신 함수 호출이라는 다른 접근 방식을 제안합니다. LLM은 검색, 필터링, 집계 및 그룹화를 위한 선택적 인수를 사용하여 미리 정의된 함수 호출을 인접 형식으로 구성하여 쿼리를 생성합니다. 전체 시스템에서는 다음과 같은 형태가 됩니다. 쿼리가 들어오면… 사용자가 입력한 내용은 LLM(로컬 라이프 모델)에 전달됩니다. LLM은 사용자의 입력에 따라 데이터베이스를 쿼리하는 데 사용할 수 있는 JSON을 출력합니다. 어떤 텍스트를 사용할지, 집계 또는 검색 쿼리를 사용할지, 필터나 그룹화와 같은 추가 인수를 지정할 수 있습니다. LLM은 이 JSON을 검색 시스템에 전달하고, 검색 시스템은 검색을 수행하여 결과를 반환합니다. 예를 들어, 사용자가 함수 호출 설정에서 20달러 미만인 메뉴 항목이 몇 개인지 묻는다고 가정해 보겠습니다. 모델은 다음과 같은 JSON을 생성합니다. 이 방식은 텍스트를 Sequel로 변환하는 데 있어 주요 ISS(Instruction System Technology) 문제를 해결합니다. 이 JSON 구조를 사용하면 모델이 Sequel 구문이나 특정 데이터베이스 구조를 이해할 필요가 없으며 다른 쿼리 언어로 변환할 수 있습니다. 동일한 논리가 집계 또는 여러 속성에 걸친 필터링과 같은 더 복잡한 쿼리에도 적용됩니다. 모델은 다음과 같은 고급 쿼리도 생성할 수 있습니다. 예를 들어, 20달러 미만의 계절 특선 메뉴 항목의 평균 가격을 채식 여부에 따라 그룹화하는 쿼리는 계절 특선 메뉴에 대한 검색 쿼리, 평균 가격을 계산하는 가격 필터 집계 , 결과를 분류하는 그룹화 작업의 조합으로 구성됩니다. 연구진은 채식주의자 여부를 기준으로 모델이 이러한 유형의 고급 쿼리를 처리할 수 있는지 평가하기 위해 DB Gorilla 데이터 세트를 만들었습니다. 이 데이터 세트에는 레스토랑 메뉴 및 예약과 같은 세 가지 컬렉션으로 구성된 다섯 가지 고유한 사용 사례, 다양한 필터, 검색, 집계 및 그룹화 조합을 다루는 315개의 테스트 쿼리, 그리고 이 데이터 세트를 사용하여 실제 사용 사례를 테스트하도록 설계된 합성 데이터베이스 스키마가 포함됩니다. 이 연구는 다섯 가지 계열에서 나온 8개의 서로 다른 l 스템을 테스트했습니다. 가장 성능이 좋은 모델은 Claw 3.5, Sonic, GPT 40, Mini, GPT 40, Gemini 1.5 Pro였습니다. 이 모델들은 높은 정확도로 구조화된 쿼리를 성공적으로 생성하고 형식을 지정했습니다. Gemini 2.0 Flash 및 Llama 31억 8천만과 같은 성능이 낮은 모델은 쿼리의 모든 부분을 정확하게 처리하는 데 어려움을 겪었습니다. 또 다른 중요한 결과는 스키마 적응성이었습니다. GPT 40은 다양한 데이터베이스 스키마에서 가장 일관된 성능을 보인 반면, 더 작은 모델들은 상당한 편차를 보였습니다. 관찰된 주요 문제 중 하나는 일부 모델이 함수 호출을 건너뛰어야 할 때 완전히 건너뛴다는 것이었습니다. 예를 들어 Gemini 2.0 Flash는 54%의 경우 쿼리를 실행하지 못하여 성능을 크게 저하시켰습니다. 언어에 구애받지 않는 방식으로 데이터베이스를 쿼리할 수 있게 됨으로써 훨씬 더 발전된 에이전트 기반 앱을 개발할 수 있게 될 것입니다. 완전히 자율적인 지원 기능을 갖추기까지는 아직 갈 길이 멀지만, 이러한 목적에 맞게 설계된 에이전트들은 차세대 AI 애플리케이션의 도약을 이끌 것이며, 앞으로 어떤 일이 벌어질지 정말 기대됩니다. 언제나 처럼 모든 자료는 설명란에 링크되어 있습니다.
