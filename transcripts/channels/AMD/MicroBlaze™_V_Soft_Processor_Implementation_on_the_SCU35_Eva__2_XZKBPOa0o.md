Welcome to the MicroBlaze 5 soft processor implementation on the SCU35 evaluation board demonstration. This demonstration provides a guided, end-to-end walkthrough on how to implement an AMD MicroBlaze 5 soft processor design targeting the AMD Spartan UltraScale Plus FPGA SCU35 evaluation kit. This demonstration provides an overview of the MicroBlaze 5 soft processor, illustrates how to open, configure, and generate a device image, as well as how to export hardware for a MicroBlaze 5 preset example project in the AMD Vivado Design Suite. Additionally, the demo covers creating a simple application using an AMD Vitis Unified IDE template and running it on the SCU35 board. This demonstration requires the AMD Spartan UltraScale Plus FPGA SCU35 evaluation kit, which includes the SCU35 evaluation board and power supply cable to get started. In addition, the demonstration also requires a micro USB to USB-A cable to connect the board to the host PC. The MicroBlaze 5 processor is a 32-bit RISC-V soft processor core designed for implementation in AMD, adaptive SoCs, and FPGAs. This processor represents the evolution from the proprietary MicroBlaze architecture to the OpenRISC-V instruction set architecture, ISA, providing developers with an embedded processing solution based on open standards without licensing constraints. Implemented entirely within the programmable logic fabric, the MicroBlaze 5 processor offers flexibility through configurable RISC-V extensions, including multiply and divide M, atomic operations A, compressed instructions C, and bit manipulation B extensions. This configurability allows designers to optimize for specific requirements, whether prioritizing minimal area footprint, deterministic real-time performance, or computational throughput. The processor integrates with the AMD development ecosystem through the Vivado design suite and Vitis Unified IDE, enabling development with familiar tools. Key capabilities include the following. The MicroBlaze 5 processor is built on the open source RISC-V ISA and is supported by a broad industry ecosystem of software and solutions, enabling straightforward hardware migration from existing MicroBlaze designs and strong software portability across RISC-V platforms. It provides configurable ISA support, offering the RV32i and RV64i base instruction sets along with optional extensions including MAFC and bit manipulation, features such as ZBA, ZBB, ZBC, and ZBS. These options also provide code compression capabilities that significantly reduce code size and save memory. The architecture is designed for efficiency with multiple selectable preset configurations that scale from microcontroller class applications to full application processors and four pipeline choices that optimize either area or performance. Optional safety mechanisms such as dual-core lockstep and triple modular redundancy support deployment in safety-critical systems. The design also delivers a high degree of flexibility through its fully integrated workflow in the Vivado and Vitis tool chains, compatibility with all AMD, adaptive SoCs, and FPGAs, and support for both intuitive GUI and command-line interfaces, while optimized IP helps reduce overall system component count in MicroBlaze 5-based subsystems. The Welcome page handles key high-level configuration options. Under Predefined Configurations, you can choose from a set of presets that automatically apply multiple settings throughout the wizard. The default selection is the microcontroller preset. The available options include microcontroller preset designed for RV32IMC-based microcontroller applications. Real-time preset intended for real-time control using RV32IMAC with user mode and physical memory protection. Application preset built for high-performance workloads using RV32IMAFC with supervisor mode and virtual memory. RV32IMC providing the RV32I base instruction set with multiply and divide and compression. RV32IMAC adding atomic instructions alongside multiply and divide and compression. RV32IMAFC, which includes multiply and divide, atomic operations, single precision floating point, and compression. Next is Select Processor Implementation, where you choose the processor width. The default is 32 bits, which is commonly used in embedded RISC-VIE designs. A 64-bit option is also available. The implementation optimization parameter lets you select the pipeline depth and the balance between area and performance. The default for the microcontroller preset is area. The available options include area, which uses a three-stage pipeline and minimizes logic usage. Performance, which uses a five-stage pipeline to balance resources and speed. Frequency, which uses an eight-stage pipeline to achieve higher clock speeds at the cost of additional resources. Throughput, which uses a four-stage pipeline to maximize computational throughput. Keep the default settings and click Next to open the general page. The general page provides key architectural settings for defining the instruction set, execution behavior, and optional reliability features. Many options are pre-configured based on the selected preset. The instruction and ISA options allow you to enable or disable specific RISC-V extensions such as multiply and divide, atomic, floating point support, and compression. By default, the multiply or divide and compression extensions are enabled, while floating point support is disabled. This results in an RV32 configuration that is well-suited for microcontroller class designs. Privilege and addressing are set to machine mode with a 32-bit address space. This configuration is ideal for simple bare metal and embedded software environments. Optimization options control various execution efficiency features. These include branch optimizations and the branch target cache, while cache sizes continue to follow the selected preset. Fault tolerance features are also available, offering optional safety mechanisms. These are disabled by default to keep the design lightweight, unless the application specifically requires them. Available settings may vary depending on the selected processor preset. Keep the default settings and click next to open the exception page. The exception page configures how the processor detects and handles exception and trap events. These settings enable the processor to catch issues such as illegal instructions, misaligned access, arithmetic errors and bus faults, transferring control to software-defined handlers. Exception support enhances system robustness and aids debugging during software development. Keep the default settings and click next to advance to the debug page. The debug page configures hardware features used for debugging, tracing and performance analysis. These settings define how the processor interfaces with tools like XSDB and determine the level of visibility available during development. The debug module interface selection enables the MDM5JTAG-based debug module. It also provides options for configuring hardware breakpoints and watchpoints, allowing precise control and inspection of program execution. Debug resources can be scaled based on development needs. You can increase the number of breakpoints, watchpoints and related resources, keeping in mind that higher capability may impact on the maximum achievable clock frequency. Options for performance monitoring and tracing include features for execution profiling, latency measurement and program flow tracing. These capabilities use on-chip buffers or external trace interfaces and are especially useful for optimization and analysis in complex or timing-sensitive systems. Keep the default settings and click next to open the buses page. The buses page defines how the processor interfaces with memory, peripherals and optional accelerators. It controls local and system-level connections that affect data movement, latency and overall system integration. Local memory interfaces provide low latency access to on-chip memory, ensuring fast and efficient data retrieval for time-critical operations. AXI system interfaces allow the processor to communicate with external memory and peripherals through standard AXI-based buses, supporting flexible system design. Streaming and other specialized interfaces offer high throughput data paths and additional connectivity options. These interfaces support advanced use cases such as debug tracing, lockstep operation for safety-critical systems and monitored connections for enhanced system reliability.
