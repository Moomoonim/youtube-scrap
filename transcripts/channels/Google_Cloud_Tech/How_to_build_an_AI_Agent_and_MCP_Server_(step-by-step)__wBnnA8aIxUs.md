## 스크립트

[음악] 이 영상에서는 AI 에이전트를 MCP 서버에 연결하는 방법을 보여드리겠습니다. 이 과정에서는 MCP 서버가 무엇인지, 왜 중요한지, 그리고 ADK 에이전트에 어떻게 연결하는지 배우게 됩니다 . 결국에는 담당자가 단순히 작성 및 계획만 하는 것이 아니라 MCP를 통해 외부 도구의 정보도 활용하게 될 것입니다. 그렇다면 MCP는 정확히 무엇일까요? MCP는 모델 컨텍스트 프로토콜(Model Context Protocol)의 약자입니다. 복잡해 보이지만, 간단히 설명하자면 이렇습니다. 이는 상담원이 외부 도구와 통신하는 표준적인 방식입니다. 번역기라고 생각하면 됩니다. 한쪽에는 언어 모델을 기반으로 작동하는 에이전트가 있고, 다른 한쪽에는 구글 트렌드 조회, 데이터베이스 쿼리, 코드 실행과 같이 매우 구체적인 작업을 수행하는 도구가 있을 수 있습니다. 에이전트 자체는 이러한 작업을 직접 수행할 수 없으므로 MCP가 중간 역할을 합니다. 자, 작동 방식은 다음과 같습니다. 이 도구는 자체적인 프로세스에서 독립적인 프로그램으로 실행됩니다 . 에이전트는 표준 입력 및 출력을 통해 해당 장치에 연결합니다 . 그러자 담당자가 "어떤 도구를 가지고 계십니까?"라고 묻습니다. MCP 서버는 도구 이름, 해당 도구의 인수 및 반환 값 목록을 응답으로 보냅니다. 그러자 상담원이 "좋습니다. 이 인수를 사용하여 해당 도구에 전화해 보세요 ."라고 말합니다. 해당 도구가 실행 되고 결과는 JSON 형식으로 반환됩니다. 중요한 것은 이것이 얼마나 깔끔하게 분리되느냐입니다. 각 도구는 마치 자체 프로그램처럼 고유한 프로세스에서 실행됩니다 . 에이전트는 도구가 어떻게 만들어졌는지, 어떤 라이브러리를 사용하는지, 심지어 어떤 언어로 작성되었는지 알 필요가 없습니다. 도구가 MCP 프로토콜을 사용하기만 하면 에이전트는 해당 도구를 사용할 수 있습니다. 그렇다면 이것이 왜 그토록 강력한 것일까요? 우선, 격리부터 시작해야죠. 툴에 오류가 발생하더라도 에이전트는 함께 다운되지 않습니다. 둘째로, 상호 운용이 가능합니다. 파이썬, 고, 또는 노드로 도구를 작성해도 에이전트는 신경 쓰지 않습니다. 셋째, 발견 가능합니다. 에이전트가 런타임에 사용 방법을 파악할 수 있도록 스키마로 자체를 설명하는 도구입니다. 마지막으로, 확장성이 뛰어납니다. 에이전트 코드 전체를 다시 작성하지 않고도 도구를 추가하거나, 교체하거나, 버전을 관리할 수 있습니다 . 그러니까 에이전트를 두뇌라고 생각한다면, MCP는 에이전트를 현실 세계의 손과 눈에 연결하는 전선과 같은 역할을 합니다. 뇌는 무엇을 해야 할지 결정하고, MCP는 요청을 전달하며, 손은 작업을 수행합니다. 그 결과는 다시 뇌로 돌아옵니다. 바로 그 순환 구조가 상담원을 단순한 챗봇 이상으로 만들어주는 것입니다 . 지난 영상에서는 블로그 게시글을 작성하는 에이전트를 만들었습니다 . 주제를 입력했더니 전체 섹션을 계획하고 초안을 작성했으며 , 심지어 대체 제목까지 제안해 주었습니다 . 아직 못 보셨다면 첫 번째 영상을 확인하시거나 아래 설명란에 있는 링크에서 영상을 다운로드하세요 . 그 에이전트는 훌륭하지만, 현재로서는 모델에만 의존하고 있습니다. 그것은 현실 세계에서 무슨 일이 일어나고 있는지, 무엇이 유행하고 있는지, 뉴스에 무엇이 나오는지 알지 못합니다. 이번 영상에서는 구글 트렌드에서 실시간 데이터를 가져오는 MCP 서버에 연결하는 방법을 보여드리겠습니다 . 그렇게 하면 블로그 작성 담당자가 현재 실제로 유행하는 주제를 바탕으로 게시글을 작성할 수 있습니다. 프로젝트 디렉토리를 열고 server.py 파일을 생성해 보겠습니다. 우리는 한 가지 작업을 수행하는 파이썬 파일 하나를 살펴볼 것입니다. 이는 MCP를 통해 Trends라는 단일 도구를 제공하므로, 상담원이 이를 호출하여 Google Trends에서 어떤 트렌드가 있는지 확인할 수 있습니다. 이 파일을 아주 작은 웹 서비스라고 생각해보세요. 다만 HTTP 대신 모델 컨텍스트 프로토콜(MCP)을 사용하여 표준 입력과 출력을 통해 통신합니다. 이제 이 MCP 서버가 ADK 에이전트와 연동되도록 하는 네 가지 코드 부분을 자세히 살펴보겠습니다. 먼저, 일반 파이썬 함수인 Trends를 ADK 도구로 래핑합니다. 이 라인은 우리에게 많은 도움을 주고 있습니다. JSON 형식의 인수를 받아 JSON 형식의 딕셔너리를 반환하는 일반 파이썬 함수를 작성했습니다. 함수 도구는 해당 함수의 시그니처와 독스트링을 검사하고 스키마를 구축한 다음 도구에 이름을 지정합니다 . 이 시점부터 ADK는 해당 도구가 어떤 인수를 기대하고 어떤 인수를 반환하는지 알게 됩니다. 따라서 수동으로 스키마를 작성할 필요가 없습니다. 다음으로 MCP 서버 객체를 생성합니다. 이것을 상담원과 저희 도구 사이에 있는 아주 작은 프로그램이라고 생각하시면 됩니다. 표준 입력 및 출력을 통해 모델 컨텍스트 프로토콜을 사용합니다 . 이름은 클라이언트가 핸드셰이크 과정에서 보게 될 식별자일 뿐입니다 . 이제 중요한 두 가지 핸들러는 도구 목록을 표시하는 것과 도구를 호출하는 것입니다. 그러니까, 도구 목록을 보는 것이 에이전트가 이 서버가 할 수 있는 일을 파악하는 방법이고 , 에이전트가 서버에 연결할 때 "어떤 도구를 가지고 있나요?"라고 묻는 것입니다. 저희는 트렌드 도구를 MCP 도구 스키마로 변환한 목록을 제공하여 답변드립니다. 그런 다음 ADK에서 MCP 도구 유형으로 변환하는 도우미 함수는 ADK 함수 도구 메타데이터를 가져와 MCP 클라이언트가 예상하는 형식으로 정확하게 변환합니다. 즉, 담당자는 도구의 이름, 매개변수, 유형 및 설명을 볼 수 있습니다. 실행 시 유효한 호출을 구성하는 데 필요한 모든 것입니다. 에이전트는 도구 이름과 인자가 담긴 JSON 딕셔너리를 전송합니다. 우리는 이름의 유효성을 검사한 다음 함수 도구에서 `run {underscore} async`를 호출하여 해당 인수를 파이썬 함수로 바로 전달합니다. 함수가 반환하는 값이 무엇이든, 우리는 그것을 JSON 형식으로 변환한 다음 텍스트 콘텐츠 페이로드로 다시 보냅니다. 문제가 발생하면 간단한 JSON 오류 메시지를 반환하고 세부 정보를 표준 오류에 기록합니다. 여기서 중요한 점은 프로토콜이 매우 간단하다는 것입니다. 이름과 인수를 입력하면 JSON 결과가 출력됩니다. 마지막으로 서버를 표준 입력 및 출력에 연결하고 핸드셰이크를 실행합니다. 이 함수는 표준 입출력 전송을 열고 읽기 및 쓰기 스트림을 MCP 서버로 전달합니다. 초기화 옵션에는 메타데이터와 클라이언트가 볼 수 있는 기능이 포함됩니다 . 메인 블록에서는 서버 프로세스를 시작하는 async io.run을 호출합니다. 그 후 ADK는 스크립트를 실행하고, 필요한 도구를 요청하고, 다른 도구와 마찬가지로 트렌드를 호출할 수 있습니다 . 마지막으로, 메인 agent.py 파일에서 루트 에이전트의 도구 목록에 플래너와 라이터 바로 옆에 trends_mcp를 추가하기만 하면 됩니다. 에이전트 입장에서는 아무런 차이가 없습니다. 트렌드를 호출하는 것은 로컬 함수 도구를 호출하는 것과 정확히 같습니다. 하지만 이제는 에이전트가 임의로 내용을 만들어내는 대신, 블로그 게시물을 작성하기 전에 실제 인기 검색어를 가져올 수 있습니다 . 이제 다음 명령어를 사용하여 ADK 웹 UI를 열고 MCP 서버에 연결된 에이전트와 상호 작용해 보겠습니다. 이것이 바로 AI 에이전트를 MCP 서버에 연결하는 방법입니다. 지난 영상에서 보여드렸던 블로그 작성 에이전트를 기반으로, 트렌드 분석 도구를 제공하는 새로운 서버를 추가했습니다.
