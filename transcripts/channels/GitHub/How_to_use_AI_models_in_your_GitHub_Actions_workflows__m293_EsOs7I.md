## 스크립트

GitHub 모델은 자체 프로젝트 및 워크플로 내에서 AI 기능을 통합하고 반복 개발하는 데 도움이 됩니다. 이제 GitHub Actions에서 모델을 직접 사용할 수 있습니다. 몇 가지 사용 방법을 보여드리겠습니다. 이는 새로운 문제가 제기될 때마다 실행되는 워크플로로, 보고된 버그를 재현하는 데 필요한 충분한 정보가 있는지 확인하기 위한 것입니다. 보시다시피, 저희는 모델 접근 권한을 제공했으며, 이를 통해 이 워크플로는 이제 40개 이상의 주요 AI 모델을 호출할 수 있게 되었습니다. 이 워크플로를 트리거한 문제를 가져온 다음 AI 추론 작업을 사용하여 모델을 호출합니다. 시스템 프롬프트를 표시하고, 해당 프롬프트에 따라 충분한 세부 정보가 입력되면 문자열을 반환하고 , 그렇지 않으면 추가 정보를 요청하는 응답을 생성합니다. 카탈로그에서 다른 모델을 호출하려면 여기에서 모델 값을 변경하기만 하면 됩니다. 그런 다음 문제의 제목과 본문을 전달하고, 모델의 응답이 ' pass'가 아닌 경우에만 댓글을 답니다. 즉, 이는 인공지능 기반 분기 논리를 통해 결과를 결정할 수 있는 모델을 가지고 있음을 의미합니다. 그리고 이것이 바로 실제 모습입니다 . 여기서 우리는 이 버그를 재현하는 데 필요한 정보가 거의 제공되지 않은 버그 보고서를 볼 수 있습니다. 그래서 이 내용은 모델에게 전달되었고, 모델은 문제를 제기한 사람이 무엇을 해야 하는지에 대한 자세한 정보를 담은 답변을 작성했습니다 . 좀 더 세밀한 제어를 원한다면 모델 확장 기능을 사용하여 GitHub CLI를 직접 사용할 수 있습니다 . 이 워크플로는 병합된 풀 리퀘스트를 가져와 요약하고 릴리스 이슈 하단에 추가하여 릴리스 노트 작성에 도움을 줍니다. 보시는 바와 같이, GitHub CLI에 GH 모델 확장 프로그램을 설치하고 있으며 , 모델 사용 권한이 부여된 GitHub 토큰도 함께 설치하고 있습니다. 풀 리퀘스트의 제목, 본문, 댓글, 리뷰를 가져와서 Grock 모델에 전달하여 요약을 생성합니다. 그 작업이 완료되면 릴리스 이슈를 가져와 새 항목으로 업데이트합니다 . 다음은 이 워크플로의 출력 예시입니다. 두 개의 풀 리퀘스트가 병합되었으며, 이 변경 로그에는 두 개의 간단한 한 줄짜리 항목이 있습니다 . 다른 예시로 넘어가겠습니다. 이 워크플로는 매주 한 번 실행되어 해당 주에 접수되었거나 아직 해결되지 않은 모든 문제를 요약하고 우선순위를 지정합니다. 우리는 미해결 문제를 검색하고, 요약을 생성한 다음, 새로운 문제를 생성합니다. 워크플로 파일에서 직접 프롬프트를 설정할 수도 있지만, CLI를 사용하면 모델, 프롬프트 및 매개변수에 대한 모든 정보가 포함된 프롬프트 파일을 제공할 수도 있습니다. 물론, 이것이 바로 저희 주간 요약 보고서의 예시입니다. 새롭게 제기된 문제 목록 , 몇 가지 일반적인 주제, 그리고 제안된 우선순위를 확인할 수 있습니다. 마지막으로, GitHub 에서 모델과 액션을 활용하는 한 가지 방법을 보여드리겠습니다. 바로 제품 관리자가 문서 작업을 완료하고 작업의 효과를 극대화할 수 있도록 지원하는 도구인 Project Bloom입니다 . 진입점은 GitHub 토론 게시판이며, 새 토론 게시판이 생성될 때마다 워크플로가 실행됩니다 . Bloom은 요약 및 관련 증빙 서류를 자동으로 생성합니다 . 그러면 자동으로 사업 개요, 변경 내역 및 기타 추가 의견이 생성됩니다. 이 시스템은 컨텍스트 정보 수집을 중앙 집중화 하고 프로젝트 세부 정보가 변경됨에 따라 생성하는 모든 문서를 자동으로 업데이트합니다 . 물론 이것은 예시를 위한 가상의 프로젝트이지만, 이 도구 덕분에 우리 팀은 몇 시간씩 시간을 절약할 수 있습니다. 워크플로에 모델 권한을 추가하면 오늘부터 액션에서 모델을 사용할 수 있습니다. 재밌거나 흥미로운 것을 만드셨다면 저희에게 연락 주세요.
