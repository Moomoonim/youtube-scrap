## 스크립트

안녕하세요, 저는 VCH입니다. 저처럼 JetBrains IDE를 사용하는 팬이라면 Amazon Q Developer의 모든 기능을 어떻게 활용할 수 있을지 궁금하실 텐데요, 이 영상에서 Amazon Q Developer를 설치, 구성, 그리고 즐겨 사용하는 JetBrains IDE 와 함께 일상 업무에 활용하는 방법을 알려드리겠습니다. 저는 Intel Idea 커뮤니티 버전을 사용하고 있지만, 여러분은 원하는 IDE를 자유롭게 선택하셔도 됩니다. 현재 Amazon Q Developer 확장 기능은 JetBrains 제품군의 모든 IDE에서 지원되며, WebStorm, PyCharm, Intel Ultimate, Rust, Rover 등 다양한 IDE를 사용할 수 있습니다. 보시다시피, IDE에 프로젝트가 로드되어 있는데, 이는 CRUD(생성, 읽기, 업데이트, 삭제) 기반 API를 제공하는 간단한 Java 기반 애플리케이션입니다. 이 API는 Springwood 프레임워크를 사용하여 구축되었습니다. 저는 빌드 도구로 Maven을 사용하고 있으며, 전체 프로젝트는 Java 1.8로 개발되었습니다. 이 정보는 나중에 보여드릴 기능 중 하나인 Amazon Q Developer 코드 변환 기능과 관련하여 매우 중요합니다. 이 기능을 사용하면 Java 1.8 및 Java 11로 개발된 프로젝트를 최신 JDK 버전인 Java 17로 변환할 수 있습니다. 변환 과정에서 종속성이 업데이트되고, 최신이 아닌 코드 패턴을 감지하여 수정합니다. 또한 AI 기반 도구를 사용하여 몇 번의 클릭만으로 전체 환경을 현대화할 수 있습니다. 이제 Amazon Q Developer와 완벽하게 통합하기 위해 설치해야 하는 확장 프로그램을 살펴보겠습니다. 이미 이러한 확장 프로그램을 사용하고 계신 분들도 있겠지만, 설치해야 할 부분이 새롭게 표시될 것입니다. 플러그인 메뉴로 이동하면 현재 iws에서 제공하는 세 가지 확장 프로그램을 설치해야 합니다. 이 확장 프로그램들은 공식 GenBrains Marketplace 페이지에서 다운로드할 수 있습니다. 이전에는 AWS Toolkit에 Amazon Q와 Amazon Code Whisperer가 하나로 통합되어 있었습니다. 하나의 확장 프로그램이었지만, 이제 Amazon Q라는 이름의 독립형 확장 프로그램으로 분리했습니다. 이 확장 프로그램은 JetBrace Marketplace에서 설치하여 Amazon Q 개발자를 지원할 수 있으며, Amazon Toolkit 개발자의 기반이 되는 Amazon Code Whisperer도 지원합니다. AWS Core는 AWS Toolkit과 Amazon Q에서 분리된 세 번째 확장 프로그램으로, AWS Builder ID를 통한 인증 과 AWS Identity Center 싱글 사인온(SSO)을 제공합니다. 따라서 AWS Core는 두 확장 프로그램이 공유하는 공간 이며, 종속성으로 포함됩니다. 마지막으로, 이번 릴리스 이후 Amazon Code Whisperer 브랜드가 어떻게 되었는지 궁금하실 수 있는데, Amazon Q 개발자의 필요에 따라 두 가지 요금제를 도입했습니다. 하나는 Amazon Q Business이고 다른 하나는 Amazon Q Developer입니다. 두 요금제 모두 유사한 기능을 제공합니다. Q Business는 Amazon QuickSite를 사용하여 조직의 데이터 소스를 수집하고, 그래프를 그리고, 통계 및 시각화를 제공하고, Amazon Connect, Future, AWS Supply Chain과 통합하는 등 모든 비즈니스 기능을 포함합니다. 개발 측면에서는 Amazon Q Developer가 모든 기능을 제공합니다. 코드 위스퍼러 개인 및 전문가 플랜에서 사용 가능한 모든 기능을 한 곳에서 제공하는 개발자 경험을 제공합니다. 이제 IDE로 돌아가서 인증 방법을 살펴보고 Amazon Q Developer를 실제로 사용하는 방법을 알아보겠습니다. Amazon Q Developer를 실제로 사용하려면 먼저 제대로 인증해야 합니다. 이전에 로컬 머신에 배포된 AWS CLI 프로필과 액세스 키를 포함한 모든 자격 증명이 AWS 툴킷에 있었고, 지금도 여전히 사용할 수 있습니다. 현재 IDE에서 볼 수 있듯이 모든 프로필을 사용하여 모든 리소스를 나열할 수 있습니다. 하지만 AWS 툴킷은 이제 분리되었습니다. 따라서 Q Developer를 제대로 인증하고 활용하려면 오른쪽의 Amazon Q 페이지로 이동해야 합니다. 이제 두 가지 인증 옵션이 있습니다. 하나는 AWS 계정이 필요 없는 AWS Builder ID를 사용하는 것이고, 다른 하나는 조직의 관리자가 구축한 AWS Identity Center를 통해 제공되는 AWS Single Side On에 로그인할 때 전문가 라이선스를 사용하는 것입니다. 첫 번째 예시로 AWS Builder ID를 사용하겠습니다. 첫 번째 옵션(무료, AWS 계정 필요 없음)을 선택하고 계속을 클릭하면 바로 브라우저로 이동하여 확인 코드를 생성합니다. 브라우저에 표시되는 확인 코드와 일치하는지 확인해야 합니다. 브라우저로 이동하면 인증 요청에 동일한 코드가 표시되므로 확인하고 계속을 클릭합니다. 그러면 AWS 빌더 ID 로그인 페이지로 이동합니다. 저는 이미 빌더 ID를 가지고 있으므로 '이미 빌더 ID가 있습니다'를 선택하고 로그인합니다. 이메일 주소는 자동으로 입력되고, 이제 환경 에 제대로 인증하기 위한 비밀번호를 입력해야 합니다. 보안 캡처를 통과 하고 이 장치를 신뢰할 수 있는 장치로 표시해야 합니다. 로그인에 성공하면 JRA가 Code Whisperer에 액세스하기 위한 데이터 툴킷에 대한 액세스 권한을 허용할지 묻습니다. Code Whisperer와 관련된 모든 권한 목록이 표시되고 Amazon Q 개발자가 Code Whisperer를 사용할 수 있도록 허용합니다. 현재 액세스를 허용하고 있으며, 요청이 승인되면 Intellig로 이동하여 Amazon Q를 사용할 수 있습니다. 인증에 성공하면 Amazon Q와 상호 작용하고 도움을 요청할 수 있는 여러 가지 방법이 있습니다. 한 가지 방법은 오른쪽 사이드바에 있는 채팅 탭을 이용하는 것입니다. 새 탭을 열 때마다 새 세션이 열리고 해당 세션의 컨텍스트가 유지됩니다. 해당 세션 내에서 " Amazon Q는 어떻게 도움을 줄 수 있나요?"와 같이 대화형으로 질문하고 채팅에서 제공되는 답변을 읽을 수 있습니다. 또는 슬래시(/)를 입력하여 명령 팔레트를 열고 슬래시(/)를 선택하여 작업 공간의 여러 FES에 걸쳐 새 기능을 계획하고 구현할 수 있는 "def" 또는 Java 8 또는 11 애플리케이션을 Java 17로 포팅할 수 있는 "transfer form"을 선택할 수 있습니다. 현재는 이러한 실행 유형만 지원되며 mainen 기반 프로젝트만 지원된다는 점에 유의하십시오. 잠시 후 일반적인 팔레트와 차트 외에도 Amazon Q 상태 표시줄에서 일시 중지, 자동 완성, 질문 열기 등의 기능을 사용할 수 있습니다. 코드 참조 로그를 확인하고 채팅 패널에서 피드백을 보내거나 Amazon Q 설정을 열 수 있습니다. Amazon Q의 피드백 기능은 새로운 독립 실행형 확장 프로그램으로 직접 피드백을 전송합니다. AWS 툴킷(현재 별도 버전)에 피드백을 보내려면 AWS 툴킷 정식 버전을 찾아 ' 툴킷 피드백' 기능을 사용해야 합니다. 이제 AWS 툴킷을 닫고 Amazon Q를 실제로 사용하는 방법을 살펴보겠습니다. Amazon Q를 통합하고 일상 업무에 활용하는 한 가지 방법은 특정 코드 샘플을 Q에 보내 도움을 요청하는 것입니다. 예를 들어 코드 설명이나 최적화를 요청할 수 있습니다. 저는 Crow 컨트롤러 클래스에 있는 특정 코드를 예로 들어 ' 제품 이미지 가져오기' 메서드를 최적화하는 방법을 알고 싶습니다. 해당 메서드를 선택하고 Amazon Q에 보내 코드 최적화를 요청하겠습니다. 최적화 외에도 리팩토링, 코드 수정, 설명 등을 요청할 수 있습니다. 저는 코드 최적화 기능을 사용하여 답변을 받고 채팅창에 표시하겠습니다. 이미 열려 있던 탭에서 주어진 코드를 최적화하라는 메시지가 나타났고, 그에 대한 답변이 제공되었습니다. 어떤 최적화 방안이 제시되었는지 살펴보겠습니다. 불필요한 객체를 생성하지 않고 해당 객체를 tri 블록에서 직접 반환하는 것이 더 효율적이라는 것을 정확하게 지적해 주었습니다. 따라서 이는 매우 유용한 조언입니다. 이 답변을 선택하여 복사하여 붙여넣거나, 커서 위치에 삽입할 수도 있습니다. 모든 답변 하단에는 피드백 버튼이 있으니, 답변의 품질에 대한 의견을 남겨주세요. 저는 제공된 답변에 매우 만족하므로 긍정적인 평가를 선택하겠습니다. 또한, 이 부분에 대한 추가 질문을 제안하는 기능도 있습니다. 다른 최적화 방안에 대한 질문과 함께, 이러한 최적화가 성능 향상에 어떻게 도움이 되는지, 그리고 코드 변경 사항에 대한 설명도 요청할 수 있습니다. Amazon Q에 코드를 전송하는 것은 서비스와 상호 작용하는 한 가지 방법이지만, 실제 코드를 작성하는 데에도 사용할 수 있습니다. 방금 설명한 방법을 예시로 사용하여 실제 코드를 작성해 보겠습니다. 자, 이제 프로젝트의 테스트 정의로 이동하여 Crow 컨트롤러 테스트를 만들어 보겠습니다. 특정 테스트를 생성할 공간을 마련해 보죠. 이미 테스트 생성에 사용할 prop을 만들어 두었습니다. 이 prop은 제품 이미지를 가져오는 테스트를 정의하는 주석입니다. 이 테스트에서는 HTTP 응답 상태 코드와 바이트 값을 검증할 것입니다. 이미지 값은 하드코딩하고, 다른 테스트 에서처럼 제품을 모킹할 것입니다. 이제 Amazon Q가 어떻게 도움을 주는지 살펴보겠습니다. 프롬프트가 표시되자마자 코드에 테스트 어노테이션을 추가하여 테스트를 생성하라는 메시지가 나타납니다. 이 부분을 입력하고 테스트 제안을 기다리면, 제안 된 테스트 구현이 상당히 좋아 보입니다. 코드에 빨간색 오류 정보도 없고, 올바르게 작성된 것 같습니다. 이제 테스트가 컴파일되는지 확인해 보겠습니다. 이전에는 테스트 스위트에 6개의 테스트가 있었는데, 빌드가 성공적으로 완료되면 7개의 테스트가 추가된 것을 확인할 수 있을 것입니다. 오류 없이 실행되어 정말 놀랍습니다. 이 경우에도 큰 도움이 되었습니다. 마지막으로 두 가지 더 말씀드리고 싶은 것이 있는데, Amazon Q 개발자 인증 방법으로 AWS Identity Center와 Single Sign-On을 사용하는 방법이 있다는 것입니다. 이를 보여드리기 위해 여기에 있는 모든 창을 닫고 상태 표시줄을 통해 Amazon Q에서 로그아웃하겠습니다. 그런 다음 Amazon Q 탭을 열면 올바른 인증 방법을 선택하라는 메시지가 다시 나타납니다. " 전문가용 라이선스 사용"을 선택하고 "Single Sign-On으로 AWS에 로그인"을 클릭한 후 " 계속"을 클릭합니다. 다음 단계에서는 관리자 또는 헬프 데스크에서 제공한 시작 URL을 입력하라는 메시지가 나타납니다. 즉, AWS Identity Center에서 사용하는 Single Sign-On 시작 URL을 입력하는 것입니다. 그런 다음 Single Sign-On에 사용할 리전을 선택합니다.
