테이블을 생성하고 분산 하이퍼 테이블로 설정해 줍니다.이 분산 하이퍼 테이블은 호스트 네임 컬럼을 기준으로 데이터를 각 노드에 배치하고 해당 노드별로 타임 컬럼을 기준으로 여러 천크로 나눠서 저장되게 됩니다. 사용자는 데이터 노드에 직접 접근하지 않고 엑세스 노드를 통해 분산된 데이터를 조회할 수 있습니다. 분산 노드 구성은 비교적 최근에 추가된 기능으로 노드를 확장할 때 필요한 데이터 리밸런싱이나 특정 청크를 다른 노드로 이동하는 기능은 아직 구현이 되지 않았기 때문에이 부분은 유의하셔야 합니다. 일반적인 RDBMS로 시계열 데이터를 저장할 때 파티션 테이블을 많이 사용하실 텐데요.이 이 경우 특정 시간 단위로 파티션을 만들어 주고 보관 기간이 지난 파티션을 삭제해 주는 등의 작업을 배치로 처리해야 합니다. 타임스케일 리뷰는 하이퍼테이블이라는 객체를 사용해서 데이터를 특정 시간 단위에 묶음인 청크로 나눠서 관리합니다. 사용자는 데이터 보관 정책만 설정해 주면 새로운 데이터가 들어왔을 때 필요한 청크를 생성하고 보관 기간이 지난 데이터는 청크 단위로 삭제하는 작업을 자동으로 처리해 줍니다. 이런 복잡하고 귀찮은 처리를 타임스케일 DB가 처리해 주기 때문에 사용자는 하이퍼 테이블을 하나의 일반 테이블로 인식하고 편하게 사용할 수 있습니다. 시계열 데이터는 지속적으로 데이터가 삽입되므로 시간의 흐름에 따라 데이터의 사이즈가 매우 크게 증가합니다. 타임스케일 DB는 디스크 공간 절약을 위해 압축 정책에 의한 자동 압축 기능을 제공하며 90% 이상의 압축률을 보여줍니다. 압축을 하면 로우 개수를 줄이기 위해 예제와 같이 키 컬럼을 기준으로 해당 청구에서 여러 행의 값을 컬럼별로 배열로 변환하여 압축합니다. 이렇게 되면 특정 키의 값으로 조회를 할 때 다른 킥값의 압축을 풀 필요가 없이 필요한 킥 값의 데이터만 조회할 수 있어서 빠른 성능을 기대할 수 있습니다. 시계열 데이터베이스에서 최근 시간대의 데이터를 조회하는 거리는 여러 컬럼의 데이터를 종합적으로 조회하는 경우가 많습니다. 예를 들면 최근 하루 동안의 특정 서버에서 저장된 모든 매트릭을 조회하는 콜이라면 압축되지 않은 행기반의 데이터가 가장 유리한 성능을 나타낼 겁니다. 하지만 오래된 데이터는 긴 기간 동안 특정 매트릭을 조회하는 경우가 많습니다. 지난 1년간 월평균 디스크 사이즈 증가율을 구하는 콜이라면 특정 컬럼의 감만 필요하므로 컬럼 기반으로 압축된 데이터가 가장 빠른 성능을 보여줍니다. 이상으로 사이터스와 타임스케일 DB에 대해 설명드렸는데요. 사이터스와 타임스케일 DB 외에 저희 카카오에서 서버데수 기준으로 가장 많이 사용하는 익스텐션인 포스트 GIS가 있습니다. 포스트 GIS는 포스트레 SQL의 가장 유명한 익스텐션 중에 하나인 공간 데이터 관련 기능을 제공하는 익스텐션으로 카카오 지도와지 정보가 필요한 여러 서비스에서 널리 사용되고 있습니다. 이상으로 포스트 SQL 에코시스템의 핵심인 익스텐션에 대해 설명드렸습니다. 포스트 SQL에 대해 궁금하신 분들에게 조금이나마 도움이 되는 시간이 되었으면 좋겠습니다. 감사합니다.
