## 스크립트

자, 이제 웹훅을 생성했으니 코드 검토 화면에서 설정으로 이동했습니다. 보시다시피 웹훅에 비밀 키가 설정되어 있습니다. 다음으로 모델 레지스트리에서 자동화를 설정해야 합니다. 이를 위해 팀 페이지에서 모델 레지스트리로 이동합니다. 레지스트리에 이미 모델이 있으면 편리하지만, 없다면 모델 레지스트리에 모델을 추가하는 데 사용할 수 있는 스크립트를 알려드리겠습니다. 저는 특정 레지스트리를 선택할 건데요, 이 작은 라마 레지스트리를 선택하고 '세부 정보 보기'를 클릭합니다. '세부 정보 보기'에서 맨 아래로 스크롤하여 ' 새 자동화'를 클릭합니다. 새 자동화에서는 이벤트 유형을 선택해야 합니다. 처음 시작할 때는 이벤트 유형을 '별칭이 모델 버전에 추가됨'으로 설정하는 것이 좋습니다. 잠시 후 이것이 무엇을 의미하는지 보여드리겠습니다. 별칭( Rex)은 원하는 문자열 패턴을 일치시키는 것입니다. 어, 이 경우에는 제가 특정 문자열, 즉 ' candidate'라는 문자열을 찾을 거예요. 철자가 맞는지 꼭 확인하세요. 틀리면 나중에 헷갈릴 수 있거든요. 그리고 액션 유형은 웹훅으로 설정하고, 다음 단계로 넘어가서 웹훅을 선택할 거예요. 이미 이 프로젝트에 ' modal web hook test'라는 웹훅을 만들어 놨죠. 다음으로 페이로드를 지정할 거예요. 이 페이로드는 웹훅 서버 로 보낼 정보예요. 제가 curl 명령어를 실행했을 때 페이로드에 대해 설명했던 걸 기억하시죠? sh는 바로 이 부분, 즉 페이로드를 의미합니다. 가중치 와 편향(weights and biases)에게 이런 페이로드를 보내라고 지시하는 것이죠. 이제 'John Doe'나 '이벤트 유형' 같은 문자열을 하드코딩하는 대신, 가중치와 편향이 페이로드에 삽입할 변수를 지정할 수 있습니다. 잠시 후에 보여드리겠습니다. README 파일로 돌아가서 이 페이로드를 복사해서 붙여넣어 보겠습니다. 여기 복사해서 붙여넣으면 페이로드가 나옵니다. 이 구문을 보시면 문자열 치환(string substitution)을 의미합니다. 그리고 이 변수들은 가중치와 편향이 페이로드에 삽입할 변수들입니다. 이것은 추가할 수 있는 다양한 변수 와 그 의미를 보여주는 일종의 목차라고 할 수 있습니다. 예를 들어 '이벤트 유형'은 액션을 트리거하는 이벤트 유형을 의미하고, '작성자'는 액션을 트리거한 사용자를 의미합니다. 즉, 'John Doe'처럼 하드코딩하는 대신, 이 액션을 트리거하면 '이것이 Hamill'이 되고, '이것이 내 이름'이 되는 식입니다. 따라서 이 페이로드는 매우 의미 있고 유용한 정보를 담고 있습니다. 예를 들어 아티팩트 버전, 프로젝트 이름, 엔티티 이름이 있다면 웹훅에서 해당 아티팩트를 가져와 모델을 다운로드하거나, 후 처리를 수행하거나, 다양한 테스트를 진행하는 등 여러 가지 작업을 할 수 있습니다. 즉, 이러한 정보에 반응할 수 있다는 것입니다. 페이로드가 만족스러우면 다음 단계로 넘어가 자동화 이름을 지정할 수 있습니다. 저는 이 모델을 'WDB'라고 하겠습니다. 설명은 선택 사항이며, 실제 운영 환경에서는 용도를 잊어버릴 경우를 대비해 설명을 추가하는 것이 좋습니다. 그런 다음 ' 자동화 생성'을 클릭하면 새 자동화가 생성됩니다. 기본적으로 모델에 'candidate' 태그를 추가하면 이 웹훅이 트리거됩니다. 이제 특정 모델을 선택해 보겠습니다. 여기 있는 모델 중 하나인 ' 버전 1'을 선택하고 ' 보기'를 클릭한 다음 ' candidate' 태그를 추가하겠습니다. 자, 왜 '후보자'라고 했냐고요? 음, 제가 자동화를 설정할 때 설정한 트리거 때문입니다. 기억하시겠지만, 좀 더 일반적으로 말하자면, 이건 뭔가를 검토하고 싶거나, 테스트 같은 중간 작업을 하고 싶을 때 보내는 신호 같은 겁니다. 그래서 '후보자'라는 단어를 선택했지만, 원하는 어떤 단어든 사용할 수 있습니다. 자, ' 후보자' 태그를 추가하겠습니다. 태그가 추가된 게 보이시죠? 이제 모달 앱으로 돌아가서 로그를 확인하고 뭔가 변경된 게 있는지 보겠습니다. 오, 그렇군요. 자, 이건 우리가 John Doe와 같은 이름으로 weights and biases를 로컬에서 호출했을 때 받은 페이로드입니다. 하지만 이건 weights and biases에서 보낸 것입니다. 이벤트 작성자는 저, haml SMU입니다. 이건 제 weights and biases 사용자 이름이고요. 이건 weights and biases 아티팩트입니다. 이건 버전입니다. 이건 프로젝트 이름입니다. tiny llama입니다. 그리고 이건 프로젝트 또는 팀 이름입니다. 이 모든 정보는 자산, 가중치 및 편향과 상호 작용하는 데 사용할 수 있습니다. 이것이 바로 가중치, 편향 및 모달 간의 통합을 설정하는 방법입니다. 업데이트를 트리거하는 방법을 설정하면 여기에서 업데이트하는 태그가 외부 머신 러닝 시스템에서 특정 작업을 트리거할 수 있습니다. 이는 매우 강력한 기능입니다. 이것은 시작에 불과하며 매우 기본적인 설정이지만, 다양한 작업을 트리거하는 방법을 이해하는 데 도움이 되었기를 바랍니다. 다음 비디오에서는 학습을 더욱 발전시키는 데 사용할 수 있는 몇 가지 연습 문제를 살펴보겠습니다.
