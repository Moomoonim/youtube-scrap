## 스크립트

이번 간단한 안내에서는 Azure 방화벽이 Microsoft Sentinel 및 Defender XDR과 더욱 긴밀하게 통합되어 고화질 네트워크 신호를 보안 운영 워크플로에 직접 제공하는 방법을 살펴본 후 실제 데모를 진행하겠습니다. Azure Firewall은 Microsoft의 클라우드 네이티브 네트워크 보안 서비스로, 복잡한 인프라 관리 없이 대규모 워크로드를 보호하도록 설계되었습니다 . 이 제품은 상태 기반 네트워크 및 애플리케이션 계층 검사, 내장된 Microsoft 위협 인텔리전스, 그리고 수요에 맞춰 자동으로 확장되는 기능을 제공합니다 . Azure 방화벽은 Azure로 들어오거나 나가는 남북 트래픽과 워크로드 간에 이동하는 동서 트래픽을 모두 검사하여 환경 전체에서 일관된 방화벽 적용을 보장합니다. 또한 99.99% SLA를 보장하는 인바운드 DNAT, 아웃바운드 SNAT 및 다중 가용 영역 배포와 같은 실제 기업 요구 사항을 지원합니다 . 새로운 기능은 Azure 방화벽과 Microsoft Sentinel 및 Defender XDR 간의 더욱 심층적인 통합으로, 이를 통해 보안 운영 팀이 네트워크 보안 신호를 즉시 활용할 수 있게 되었습니다. 여기에는 새로운 침입 탐지 및 방지 시스템(IDPS) 기반 탐지 기능과 방화벽 로그에 대한 ASIM 기반 분석 기능이 포함됩니다 . Microsoft Sentinel 내에서 Azure Firewall은 이제 최고의 솔루션으로 자리매김했습니다 . 가시성을 위한 내장 워크북, 악성 IP 차단 또는 보안 팀 알림과 같은 대응을 위한 자동화된 플레이북, 그리고 의심스러운 행위를 지속적으로 분석하는 분석 규칙이 제공됩니다. 5가지 새로운 IDPS 기반 탐지 기능을 통해 풍부한 네트워크 원격 측정 데이터가 기존 SOC 워크플로에 자연스럽게 통합되는 경고 및 사건으로 변환됩니다. ASIM(고급 보안 정보 모델)은 방화벽 로그를 공통 스키마로 표준화합니다 . ASIM이 없으면 각 방화벽 공급업체가 서로 다른 필드 이름을 사용하므로 탐지 기능을 구축하고 유지 관리하기가 더 어려워집니다. ASIM을 사용하면 소스 IP 및 대상 포트와 같은 필드가 일관성을 유지하므로 탐지 기능을 재사용할 수 있고, 벤더에 구애받지 않으며, 다양한 환경에서 확장하기가 더 쉬워집니다. 이러한 배경 지식을 바탕으로 Microsoft Sentinel 및 Defender XDR 내에서 이러한 탐지 및 워크플로가 실제로 어떻게 작동하는지 간단한 데모를 통해 살펴보겠습니다. 이 데모에서는 Azure 방화벽, Microsoft Sentinel 및 자동화 기능이 함께 작동하여 악의적인 아웃바운드 활동을 감지하고 자동으로 차단하는 방법을 보여드리겠습니다 . 우리는 인터넷상의 웹 애플리케이션에 대한 공격을 시작하는 Azure 가상 머신으로 시작합니다. 이 VM에서 인터넷으로 향하는 모든 트래픽은 IDPS가 경고 및 차단 모드로 활성화된 Azure Firewall Premium을 통해 라우팅됩니다 . 보안 운영 측면에서 Microsoft Sentinel은 Azure 방화벽 IDPS 로그를 기반으로 하는 맬웨어 탐지 규칙으로 구성되어 있습니다 . 방화벽이 심각도가 높은 악성코드 활동을 감지하면 이 규칙에 따라 Sentinel에 자동으로 사건이 생성됩니다 . 이 탐지 규칙에는 대응 플레이북이 첨부되어 있습니다. 인시던트가 생성되면 플레이북이 실행되어 공격 VM의 소스 IP가 악성 IP 그룹에 추가됩니다. 이 IP 그룹은 알려진 악성 소스에서 나가는 모든 트래픽을 차단하는 Azure 방화벽 거부 규칙에 참조되어 있습니다 . 자, 이제 가상 머신에서 주스 가게 웹사이트를 대상으로 공격 스크립트를 실행해 보겠습니다. 자, 시작해 볼까요. 이제 Azure 방화벽 로그로 전환하면 IDPS가 악성 트래픽을 실시간으로 감지하고 차단하는 것을 확인할 수 있습니다 . Microsoft Sentinel로 이동하면 맬웨어 탐지 규칙이 활성화되어 있는 것을 확인할 수 있습니다. 사건이 발생했으며, 대응 계획표가 성공적으로 실행되었습니다 . 이제 악성 IP 그룹을 살펴보면 소스 IP인 10.0.100.20이 자동으로 여기에 추가된 것을 확인할 수 있습니다. 이 IP 그룹이 방화벽 차단 규칙에 사용되므로 공격자 VM에서 나가는 모든 액세스는 별도의 수동 조치 없이 차단됩니다. 다음으로, ASIM 파서가 조사를 어떻게 간소화하는지 살펴보겠습니다. Azure Firewall은 이제 ASIM 기반 정규화를 지원하므로 분석가는 일관되고 공급업체에 구애받지 않는 스키마를 사용하여 방화벽 데이터를 쿼리할 수 있습니다 . Azure 방화벽에는 네트워크 트래픽용 네트워크 세션, HTTP 및 HTTPS 트래픽용 웹 세션, DNS 활동용 DNS 등 세 가지 주요 ASIM 파서가 있습니다. 이러한 파서를 사용하면 분석가는 Azure 방화벽 트래픽을 신속하게 분리하고, 재사용 가능한 쿼리를 작성하고, 공급업체별 필드 이름에 대해 걱정할 필요 없이 방화벽 신호를 다른 보안 데이터와 연관시킬 수 있습니다 . 결론적으로, 이 데모는 Azure 방화벽 네트워크 신호가 Microsoft Sentinel로 직접 전달되어 정확한 탐지 및 자동화된 대응을 가능하게 하는 방식을 보여줍니다. IDPS 기반 탐지, SOAR 자동화 및 ASIM 정규화 로그를 통해 보안 팀은 위협을 더 빠르게 탐지하고 자동으로 대응하며 대규모로 조사하여 네트워크 원격 측정 데이터를 실행 가능한 XDR 결과로 전환할 수 있습니다.
