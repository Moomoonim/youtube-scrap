## 스크립트

오늘은 Cerebrus가 최첨단 세대 간 결과를 얻는 데 가장 적합한 플랫폼인 이유에 대해 이야기해 보겠습니다. 이는 Cerebrus의 뛰어난 확장성 덕분인데, 이는 대규모 모델을 실행하는 데뿐만 아니라 최상의 모델 품질을 달성하는 데에도 매우 중요합니다. 왜 그런지 설명해 드리겠습니다. 대규모 모델을 실행할 때, 손실 곡선이 매끄럽게 나타나 모델이 발표된 결과에 수렴하고 있음을 보여주기를 기대하지만, 실제로는 메모리 부족 문제, 모델 발산 문제, 그리고 설령 수렴에 성공하더라도 최첨단 정확도에 도달하지 못할 수도 있습니다. 이는 대규모 세대 모델의 본질적인 특성입니다. 대규모 모델은 본질적으로 다루기 어렵습니다. 모델을 실행하는 데 필요한 데이터 분포 문제 외에도, 실행 결과를 좋게 만들기 위해서는 상당한 노력과 복잡한 머신러닝 문제를 해결해야 합니다. 이러한 대규모 모델은 매개변수가 매우 많기 때문에 튜닝 방식에 극도로 민감합니다. 즉, 만약 여러분이 데이터 문제, 정밀도 문제, 또는 학습률 스케줄이 제대로 조정되지 않은 경우 등 사소한 수치적 문제가 발생할 수 있으며, 이러한 문제들이 대규모 모델에서 누적되면 모델 성능이 저하될 수 있습니다. 즉, 공개된 하이퍼파라미터를 그대로 사용해서는 자체 데이터에 대해 매우 높은 수준의 모델 품질을 얻기가 매우 어렵다는 뜻입니다. 이러한 문제는 반복 학습과 실험을 통해 해결할 수 있지만, 대규모 모델 실행에는 막대한 비용이 소요됩니다. 수십만 달러에서 수백만 달러에 이르는 비용이 들 수 있기 때문에, 이러한 대규모 모델 실행에 시간과 비용을 많이 투자해야 합니다. 물론 현재에도 훌륭한 모델들이 많이 존재합니다. 그렇다면 사람들은 어떻게 이 문제를 해결하고 있을까요? 머신러닝 전문가들은 먼저 소규모 모델을 설계하고 여러 실험을 실행하여 최적의 하이퍼파라미터를 찾습니다. 그런 다음 이를 대규모 모델로 확장하고 대규모 모델의 동적 특성에 맞게 튜닝을 개선합니다. 이러한 과정을 반복하면서 학습을 거듭하여 가장 큰 모델에 적합한 최적의 설정을 찾습니다. 이 과정을 이해하는 핵심은 절대 실패하지 않도록 하는 것입니다. 300억 개의 파라미터를 사용하는 대규모 시뮬레이션을 통해 얻는 통찰력을 10억 개 또는 수십억 개의 파라미터를 사용하는 시뮬레이션에서 얻을 수 있었을 것입니다. 따라서 점점 더 큰 모델로 테스트할수록 구성이 가장 큰 모델에 적합하다는 확신이 높아지지만, GPU 환경에서는 이러한 과정이 오히려 많은 작업을 요구합니다. 더 큰 모델로 이동할 때마다 코드를 리팩토링하고 점점 더 복잡해지는 병렬 처리를 처리해야 더 큰 클러스터에서 작동하도록 만들 수 있습니다. Megatron과 같은 최첨단 분산 프레임워크를 사용하더라도 분산 전략, 텐서 병렬 처리, 파이프라인 병렬 처리, 전문가 병렬 처리, 시퀀스 병렬 처리를 구성하고, 인터리브 파이프라인 스케줄을 설정하고, 메모리 절약을 위해 활성화 연산을 언제 제거하고 다시 계산해야 하는지 파악해야 합니다. 2만 줄에 달하는 코드를 다루는 법을 배워야 하는데, 여기에는 C++와 CUDA가 포함되어 있습니다. 확장성 실험을 실행하거나 모델 아키텍처를 튜닝할 때마다 이러한 작업을 반복해야 합니다. 이 설정을 다시 구성하고 코드를 다시 디버깅해 보세요. 이 프레임워크들은 정말 놀랍습니다. 뛰어난 엔지니어들이 개발했고, 다양한 유형의 병렬 처리를 배우거나 분산 문제를 처리할 팀을 고용할 수도 있지만, Cerebrus를 사용하면 분산 문제를 전혀 걱정할 필요가 없습니다. Cerebrus에서는 이 모든 문제가 해결됩니다. 750억 개의 파라미터를 가진 GPT 모델을 실행하려고 해도 P Torch 코드 565줄만 있으면 됩니다. CUDA는 필요 없습니다. 왼쪽의 10억 파라미터 모델에서 오른쪽의 700억 파라미터 모델로 확장할 때 변경하는 것은 레이어 크기, 레이어 수, 헤드 수뿐입니다. 기본 모델 코드는 전혀 변경할 필요가 없으므로 이 모든 것을 구성 파일 하나로 설정할 수 있습니다. 모델 크기가 70배 커져서 더 많은 컴퓨팅 자원이 필요해지면 실행 명령에서 숫자 하나만 변경하면 더 많은 Cerebrus 노드가 자동으로 온라인 상태가 되어 더 커진 클러스터를 계속 사용할 수 있습니다. 세레브러스 클러스터는 마치 단일 장치처럼 작동하므로, 큰 규모의 실행은 물론이고 소규모, 중규모, 대규모 실험까지 추가 작업 없이 모두 수행할 수 있습니다. 이것이 바로 세레브러스 플랫폼의 강력한 장점입니다. 추가 작업 없이 최고 품질의 모델 구성을 얻을 수 있습니다. GPU에서는 소규모 모델이 기본이므로 대규모 모델을 구현하려면 점점 더 많은 엔지니어링 노력이 필요하지만, 세레브러스에서는 대규모 모델이 기본이므로 소규모 모델은 무료로 구현할 수 있습니다. 마치 대규모 AI 개발에서 '쉬운 버튼'을 누르는 것과 같습니다. 이제 사람들이 세레브러스에서 어떤 성과를 거두었는지 살펴보고 몇 가지 모델 결과를 공유해 보겠습니다. 먼저 의료 분야의 사례를 살펴보겠습니다. 전 세계 450개 이상의 병원과 클리닉을 보유한 글로벌 헬스케어 기업인 M42에서 개발한 Med42 모델입니다. 엄선된 의료 데이터 세트로 Llama 70b 모델을 F 튜닝하여 단 일주일 만에 미국 의사 면허 시험을 통과했습니다. 이 모델은 훨씬 더 큰 규모의 GPT 3.5를 능가했으며, 대규모 실행 자체는 주말도 채 걸리지 않았습니다. 다음은 또 다른 사례입니다. 저희는 고객사인 바르셀로나 슈퍼컴퓨팅 센터(BC)와 함께 다국어 도메인 프로젝트를 진행하며 카탈루냐어에서 최첨단 성능을 자랑하는 다국어 모델 Flor를 개발했습니다. 실험이 매우 용이했기 때문에, 팀은 최신 언어 적응 기술을 모두 적용하여 리소스가 부족한 언어에 대한 전이 학습을 개선할 수 있었습니다. BC는 현재 이 모델을 사용하여 법률 분야와 같은 특정 도메인에 특화된 RAG 시스템을 개발하고 있으며, 이 작업 또한 단 며칠 만에 완료되었습니다. 또한 작년 말에는 전략적 파트너인 Core 42와 함께 300억 개의 파라미터를 가진 이중 언어 모델 JS를 개발했습니다. 이 모델은 처음부터 완전히 사전 학습되었으며, 아랍어에서 최첨단 성능을 자랑할 뿐만 아니라 영어에서도 유사한 규모의 모델들과 매우 경쟁력 있는 성능을 보여줍니다. JS 개발의 과제는 고품질 아랍어 학습 데이터가 부족했다는 점과, 오늘날 대부분의 토크나이저가 영어 코퍼스로 학습되어 아랍어에 잘 적용되지 않는다는 점이었습니다. 따라서 저희는 항상 최소한의 시간과 비용으로 고품질 모델을 개발하기 위해 노력해 왔으며, 이를 위해 기존에 사용하던 것과 동일한 반복 루프를 활용했습니다. 앞서 언급했듯이, 저희는 자체 다국어 데이터 세트를 개발하기 위해 5억 개의 파라미터 규모에서 실험을 시작했습니다. 아랍어, 영어, 코드 데이터의 정확한 비율을 찾기 위해 다양한 실험을 진행하여 다운스트림 아랍어 성능을 최상으로 끌어올렸습니다. 그런 다음 10억, 30억, 70억 개의 파라미터 규모에서 선택적으로 실험을 실행하여 130억 및 300억 파라미터 모델에 적합한 데이터 조합을 확신할 수 있도록 했습니다. 이후 교차 언어 정렬에 최적화된 새로운 어휘를 개발하고, 이에 맞춰 맞춤형 아랍어 토크나이저를 학습시켰습니다. 이 모든 것을 바탕으로 각 모델 규모에서 광범위한 하이퍼파라미터 스윕을 수행하여 최종 모델의 정확도를 확보했습니다. 이 프로젝트의 수석 과학자인 Nas Gupta는 핵심 42 팀이 Cerebrus 클러스터에서 모든 모델 규모와 스케일에서 실험을 진행하는 것이 매우 쉬웠다고 밝혔습니다. 최상의 결과를 얻기 위해 필요한 실험이었으며, 단일 시스템 에서 작업을 실행하는 것과 여러 시스템에서 실행하는 것 사이에 차이가 없었다고 합니다. 지난 몇 달 동안 더 많은 데이터로 학습을 지속해 왔으며, 최근 자체 기록을 경신 하고 아랍어 모델 성능에서 새로운 최고점을 달성했다는 소식을 전하게 되어 매우 기쁩니다. JS는 이제 1조 3천억 개의 토큰으로 학습되었으며, Core 42의 hugging face 저장소에서 오늘부터 이용할 수 있습니다. 이러한 언어 관련 작업은 매우 흥미롭지만, 이 분야는 매우 빠르게 발전하고 있으며, 현재 최첨단 기술은 멀티모달리티입니다. 이 분야에 대한 관심이 매우 높아 매주 새로운 아이디어와 모델이 등장하고 있으며, AI 커뮤니티의 진정한 정신에 따라 많은 부분이 오픈 소스로 공개되어 있어 직접 아이디어를 시도해 볼 수 있습니다. 다만, 각 아이디어는 별도의 GitHub 저장소에 있으며, 학습 설정 방식, 데이터 세트, 평가 실행 방식 등이 모두 다릅니다. 따라서 이러한 다양한 아이디어를 조합하여 시작하려면 여전히 상당한 노력이 필요합니다. 그래서 제가 매우 자랑스럽게 생각하는 것은 멀티모달리티를 매우 쉽게 사용할 수 있도록 만들었다는 것입니다. 세레브러스 플랫폼에서는 플러그 앤 플레이 프레임워크를 개발하여 Clip이나 Sight 같은 다양한 이미지 인코더를 쉽게 실험해 볼 수 있고, Mistr이나 Llama 같은 다양한 LLM 백본도 실험해 볼 수 있습니다. 시각적 질의응답 모델의 일반화된 개발을 지원하므로, Lava, Animal, Eyes Wide Shut과 같은 최신 구성 중 하나를 사용하거나 직접 개발하여 아주 짧은 시간 안에 설정할 수 있습니다. 최근 며칠 동안 개발한 모델을 보여드리겠습니다. 보시다시피, 이 모델은 이미지 속 각 동전이 무엇인지 식별하고 각 동전의 가치도 알려줄 수 있습니다. 이는 단순히 텍스트 기반 추론이 아니라 시각적 의미론적 추론을 활용한 것으로, 원본 이미지에 모든 정보가 없더라도 이러한 정보를 결합하여 질문에 답할 수 있습니다. 조금 더 복잡한 예를 들어보겠습니다. 여기에서 보시는 것처럼, 이 모델은 코끼리 모양으로 접힌 수건을 식별할 뿐만 아니라, 원본 이미지에 없는 정보까지도 식별해낼 수 있습니다. 코끼리의 위장을 간파하는 데 어려움을 겪는 것처럼, 저희의 유연한 프레임워크를 사용하면 지난 몇 주 동안 여러 가지 모델 구성을 학습시켜 최신 연구 결과를 손쉽게 재현할 수 있습니다. 주황색 ​​막대로 표시된 저희의 실행 결과가 Lava 1.5 및 SGPT 4V 모델의 원본 버전과 얼마나 유사한지 확인할 수 있습니다. 단순히 결과를 일치시킨 것이 아니라, 저희 플랫폼에서 대규모 모델 실험을 매우 쉽게 수행할 수 있기 때문에 성능을 향상시켰습니다. 저희 팀은 여러 가지 학습 레시피를 시도해 본 결과, 70억 개의 매개변수를 가진 모델을 구축했는데, 이는 130억 개의 매개변수를 가진 Lava 1.5 HD 모델과 경쟁할 만한 성능을 보였습니다. 이 모델은 크기가 두 배이고 해상도가 1.7배 더 높은 이미지 데이터로 학습되었습니다. 여러분도 이렇게 할 수 있습니다!
