## 스크립트

안녕하세요! AWS 인프라 전반에서 일관성과 보안을 유지하기 위해 수많은 설정 파일에 파묻혀 허우적거리는 기분을 느껴보신 적이 있으신가요? 오늘은 GitOps의 세계로 여러분을 안내해 드리겠습니다. GitOps는 클라우드 환경 관리 방식을 혁신적으로 바꿀 획기적인 솔루션입니다. 복잡한 네트워크 인프라를 관리하고, 여러 AWS 리전과 계정에 걸쳐 있는 모든 설정을 추적하고, 규정을 준수하며, 일관된 보안 상태를 유지해야 한다고 가정해 보세요. 이 모든 과정은 순식간에 악몽이 될 수 있습니다. 바로 이럴 때 GitOps가 등장하여 인프라 자동화 및 관리를 위한 간소화되고 안전한 솔루션을 제공합니다. 저는 클라우드 보안 전문가 브랜든 캐롤입니다. 이 영상에서는 GitOps의 작동 방식과 네트워크 보안 및 규정 준수에 미치는 강력한 영향에 대해 자세히 알아보겠습니다. Git과 코드형 인프라(IAC), 지속적 배포 파이프라인을 결합한 GitOps에 대해 심층적으로 살펴보겠습니다. GitOps를 통해 네트워크 설정을 자동화하고, 보안 정책을 시행하며, AWS 환경 전반에 걸쳐 일관되고 규정을 준수하는 인프라를 유지하는 방법을 알아보겠습니다. 자, 그럼 시작해 볼까요? 먼저 GiOps가 해결하는 주요 문제에 대해 이야기해 보겠습니다. 기존 인프라 관리는 종종 수동 프로세스, 복잡한 스크립트, 그리고 임의적인 변경을 수반하여 구성 불일치, 일관성 부족, 보안 취약점을 초래합니다. 반면 GiOps를 사용하면 인프라 프로비저닝을 자동화하고, 버전 관리를 적용하며, AWS 환경 전반에 걸쳐 일관된 보안 상태를 유지할 수 있습니다. 인프라 관리의 큰 과제 중 하나는 시간이 지남에 따라 리소스가 원하는 상태에서 벗어나는 구성 불일치입니다. 이는 보안 위험 및 규정 준수 문제로 이어질 수 있습니다. GiOps는 인프라를 Git으로 버전 관리되는 코드처럼 취급하고 모든 편차를 자동으로 조정하여 이 문제를 해결합니다. 규정 준수 및 감사는 특히 규제 산업에서 매우 중요한 문제입니다. GiOps는 모든 변경 사항에 대한 자세한 감사 추적을 제공하여 규정 준수 여부를 쉽게 확인 하고 예기치 않게 발생하는 문제를 조사할 수 있도록 합니다. 보안 스캔 및 정책 시행 또한 조직의 보안 상태를 유지하는 데 필수적입니다. GiOps를 사용하면 오픈 소스 보안 스캔 도구를 파이프라인에 통합할 수 있습니다. 이를 통해 배포 전에 인프라가 조직의 보안 정책을 준수하는지 확인할 수 있습니다. 다음은 자동화된 롤백에 대해 알아보겠습니다. GioOps의 또 다른 주요 이점은 백업 및 복구입니다. 배포가 실패 하거나 문제가 발생할 경우, GioOps를 사용하면 알려진 정상 상태로 신속하게 롤백하여 다운타임을 최소화하고 일관된 인프라를 유지할 수 있습니다. 마지막으로, GioOps는 리소스를 수정하는 대신 교체하는 불변 인프라 개념을 장려합니다. 이러한 접근 방식은 구성 변경 위험을 줄이고 인프라가 알려진 안전한 상태를 유지하도록 보장합니다. 이제 GioOps가 해결하는 주요 문제들을 모두 살펴보았으니, GioOps 방법론 자체에 대해 이야기해 보겠습니다. GioOps는 Git 원칙을 인프라 자동화 및 관리에 적용하는 일련의 원칙과 관행입니다. 개발자가 버전 관리 및 코드 공동 작업을 위해 Git을 사용하는 것처럼, GioOps를 사용하면 인프라를 코드로 취급 하고 Git 저장소를 사용하여 관리할 수 있습니다. GioOps의 핵심 아이디어는 인프라에 대한 단일 진실 소스를 구축하는 것이며, 이는 Git 저장소에 저장됩니다. 이 저장소는 원하는 인프라 상태에 대한 선언적 설명 역할을 합니다. 인프라에 대한 모든 변경 사항은 PLL 요청 프로세스를 거쳐야 하므로 변경 사항에 대한 가시성, 검토 시간 및 필요한 승인이 제공됩니다. 기존의 수동 인프라 관리 방식과는 대조적으로, GiOps는 개발자 중심 접근 방식을 지향합니다. 인프라 변경 사항을 소프트웨어 코드 변경 사항처럼 취급하는 것이죠. 이러한 사고 방식의 변화는 버전 관리, 협업, 자동화된 테스트와 같은 이점을 인프라 관리에도 가져다줍니다. GiOps를 인프라에 도입했을 때 얻을 수 있는 이점을 이해하기 시작하셨나요? 그렇다면 GiOps 스택의 핵심 구성 요소 와 그 작동 방식을 살펴보겠습니다. GiOps 스택의 중심에는 Git 저장소가 있습니다. AWS CodeCommit, Amazon CodeCatalyst, GitHub, GitLab 등 다양한 Git 저장소를 사용할 수 있습니다. 이러한 저장소는 인프라 구성에 대한 단일 정보 소스 역할을 합니다. 저장소에는 Terraform, CloudFormation과 같은 언어로 작성된 인프라 코드(I/I) 파일이 저장됩니다. 다음으로, AWS CodePipeline 및 CodeBuild와 같은 지속적 통합 및 지속적 배포(CI/CD) 플랫폼이 필요합니다. 이러한 플랫폼은 배포 프로세스를 자동화합니다. Git 저장소와 연동하여 변경 사항이 푸시될 때마다 인프라를 자동으로 빌드, 테스트, 배포합니다. 이제 보안 및 규정 준수를 위해 다양한 보안 스캔 도구와 정책 시행 메커니즘을 GiOps에 통합할 수 있습니다. 예를 들어 파이프라인을 사용하면 AWS ConfigRules를 통해 배포 전에 조직의 보안 정책에 따라 인프라 구성을 검증할 수 있습니다. 지금까지 많은 내용을 다뤘으니 이제 GiTops 파이프라인 아키텍처 예시를 살펴보겠습니다. 데모를 시작할 시간입니다. GiTops 파이프라인을 설정하여 인프라를 관리하는 과정을 보여드리겠습니다. GiTops가 실제로 어떻게 작동하는지 살펴보겠습니다. AWS 콘솔에서 진행할 예정입니다. 먼저 코드 파이프라인으로 이동하여 새 파이프라인을 생성합니다. 이름을 지정하면 서비스 규칙도 자동으로 생성됩니다. 고급 설정에서 아티팩트 저장소를 기본 설정으로 유지하면 아티팩트를 저장할 S3 버킷이 생성됩니다. 다음 페이지에서는 코드 소스를 선택합니다. 이 경우에는 GitHub를 선택합니다. GitHub에 연결하겠습니다. 저는 이전에 제 계정에서 한 번 연결한 적이 있지만, 이번에는 새 연결을 생성하려고 합니다. 연결 옵션이 제공됩니다. GitHub에 새 앱이나 커넥터를 설치하고 이름을 설정하려면, 액세스하고 인증할 계정을 선택할 수 있습니다. 아래로 스크롤하여 AWS 계정이 액세스할 리포지토리를 선택합니다. 이제 AWS 콘솔로 돌아가서 모니터링할 리포지토리와 브랜치를 선택하고, 필터를 사용하지 않도록 트리거를 변경합니다. 하지만 특정 필터를 기반으로 파이프라인을 시작하려면 이 설정을 조정할 수 있습니다. 다음으로 빌드 공급자로 CodeBuild를 선택합니다. 프로젝트가 없으므로 생성해야 합니다. CodeBuild 프로젝트에 이름을 지정하고, 환경은 기본 설정인 EC2 온 디맨드 인스턴스로 둡니다. 그러면 역할 도 자동으로 생성됩니다. 추가 구성에서 컴퓨팅 설정을 좀 더 강력한 것으로 변경하고, 조금 더 아래로 내려가서 프로젝트에서 빌드 사양 파일을 사용하도록 설정합니다. 빌드 사양 파일은 프로젝트 실행 시 작동 방식에 대한 지침이 포함된 YAML 파일입니다. 이 빌드 사양 파일도 제 리포지토리에 있습니다. 이제 이 코드는 아티팩트의 일부가 될 것입니다. 다시 구성으로 돌아가서 로깅이 활성화되어 있는지 확인합니다. 파이프라인 구성에서 프로젝트가 선택되어 있는 것을 볼 수 있습니다. 이제 아래로 스크롤하여 파이프라인을 생성하겠습니다. 하지만 아직 끝나지 않았습니다. 이제 IM AM으로 이동하여 권한을 조정해야 합니다. 현재 정책에 추가해 보겠습니다. 이제 올바른 권한이 설정되었으므로 코드를 리포지토리에 커밋해 보겠습니다. 커밋하면 파이프라인이 실행 중인 것을 볼 수 있습니다. 참고로 이전에도 실행되었지만 코드가 아직 없었기 때문에 실패했습니다. 하지만 이번에는 소스 코드가 완성되었고 코드 빌드 프로젝트가 실행 중인 것을 확인할 수 있습니다. 이 과정은 시간이 좀 걸립니다. 코드 파이프라인 과 코드 빌드 프로젝트 두 곳에서 실행 과정을 확인할 수 있습니다. 이제 속도를 조금 높여 프로젝트가 완료된 것을 볼 수 있습니다. 개발 계정으로 돌아가면 AWS 네트워크 방화벽과 지원 인프라가 성공적으로 구현된 클라우드포메이션 템플릿을 확인할 수 있습니다. 약간의 수정만으로 이제 코드에서 Cata 규칙을 업데이트하고 코드를 리포지토리에 커밋한 다음 테스트 결과를 확인해 보겠습니다. 배포가 자동으로 진행되는 모습이 정말 멋지죠? 이 데모는 GitOps의 실제 작동 방식을 잘 보여줬습니다. 이 영상에서는 GitOps 와 AWS 인프라 관리 방식을 어떻게 변화시킬 수 있는지 살펴보았습니다. 기존 구성 관리의 문제점 과 GitOps가 Git 원칙, 코드 기반 인프라, 지속적 배포 파이프라인을 결합하여 이러한 문제점을 어떻게 해결하는지 논의했습니다. 또한 구성 변경, 감사 문제, 자동 롤백 등 네트워크 보안 및 규정 준수와 관련된 GitOps의 주요 문제점에 대해서도 이야기했습니다. GitOps 스택의 구성 요소를 살펴보고 데모를 통해 코드 파이프라인 설정, 코드 빌드 프로젝트, 리포지토리 연결, 권한 조정, 자동화된 인프라 배포 등 다양한 기능을 보여드렸습니다. GitOps에 대해 더 자세히 알아보고 AWS 인프라 보안에 대해 더 배우고 싶다면, 저희 클라우드 보안 뉴스레터를 구독하고 제 TikTok 채널 '클라우드 보안 전문가'를 팔로우해주세요. 유용한 팁과 최신 정보를 제공해 드립니다. 커뮤니티의 기술 블로그도 확인해 보세요.
