## 스크립트

대부분의 AI 코드 검토자는 차이점만 볼 뿐입니다 . 그들은 당신 팀의 기준, 사용하는 도구, 또는 실제 업무 환경이 존재하는 시스템에 대해 알지 못합니다. Copilot 코드 리뷰가 Microsoft의 공식 문서를 활용하고, 팀 리뷰 체크리스트를 적용하며, 단일 풀 리퀘스트에서 차이점 비교를 넘어선 문제까지 잡아내는 방법을 살펴보겠습니다 . 이 저장소에는 Flask 백엔드와 Astro 프런트엔드를 사용하는 웹 애플리케이션이 포함되어 있습니다. Copilot 코드 리뷰가 코드 변경 사항뿐만 아니라 다른 정보에도 접근할 수 있을 때 어떻게 처리하는지 살펴보겠습니다 . 먼저 홍보부터 시작해 볼까요? Flask 백엔드에 새로운 입양 엔드포인트를 추가하고 Astro 프런트엔드에 입양 버튼을 추가했습니다. 사소하고 일상적인 변경처럼 보이지만, 출시 전에 확인해야 할 몇 가지 문제가 있습니다. 검토를 실행하기 전에 Copilot이 접근할 수 있는 컨텍스트를 살펴보겠습니다. 팀은 저장소 설정에서 Microsoft Docs MCP 서버를 구성했습니다. 마이크로소프트가 REST API 설계 가이드라인을 게시하는 바로 그 문서 사이트입니다. 코드 검토 설정에서 팀은 MCP 도구를 활성화하고 사용자 지정 지침을 추가했습니다. 이 부분에서 플랫폼 팀은 검토자가 사용할 수 있는 컨텍스트 소스를 제어합니다. 팀 자체 검토 체크리스트는 .github/skills 디렉토리 내의 일반 마크다운 파일 형태로 저장소에 있습니다. 이 파일은 두 가지 규칙을 가지고 있음을 보여줍니다. 새로운 엔드포인트에는 테스트가 필요합니다. 또한 오류 응답은 마이크로소프트에서 문서화한 오류 처리 절차를 따라야 합니다. 해당 스킬은 코드와 함께 버전 관리되므로 모든 PR에서 자동으로 반영됩니다. 즉, 체크리스트 변경 사항은 코드베이스의 나머지 부분과 동일한 검토 프로세스를 거칩니다. PR로 돌아가서, Copilot을 검토자로 지정합니다. 몇 초 후, 검토 결과가 도착하고 Copilot은 이미 차이점에서 문제를 발견했습니다. 하지만 더 흥미로운 점은 Copilot 세션 로그입니다. 여기서 우리는 Copilot이 팀에서 구성한 컨텍스트를 불러오는 것을 볼 수 있습니다 . Microsoft Docs MCP 서버가 로드되면 팀 검토 체크리스트 스킬이 로드됩니다. 그런 다음 Copilot이라는 도구가 코드에 대해 실행되면서 코드 검토 과정을 추론하는 것을 볼 수 있습니다. 이 지점에서 외부 환경은 단순한 설정값을 넘어 실제 검토 과정의 일부가 됩니다. 이제 변경된 파일을 살펴보겠습니다. Copilot은 여러 가지 조사 결과를 발표했습니다. 현재 이 댓글에는 출처 표시가 없지만, 내용으로 인해 어떤 맥락에서 나온 댓글인지 알 수 있습니다. 첫 번째는 오류 응답에 관한 것입니다. 해당 댓글은 마이크로소프트에서 문서화한 오류 봉투, 코드, 메시지 및 대상에 대한 내용을 참조합니다. 해당 문구는 차이점 비교에서 나온 것이 아니라, 이전에 구성했던 Microsoft Docs MCP 서버에서 나온 것입니다. 이제 테스트 없이도 엔드포인트를 여기서 확인할 수 있습니다. 이 댓글은 팀 리뷰 체크리스트 스킬의 규칙, 즉 해당 저장소에 커밋된 마크다운 파일과 직접적으로 연결됩니다 . 이제 배지가 없더라도 문구는 팀이 정의한 바와 일치합니다. Copilot은 한 번의 검토 과정으로 여러 출처에서 나온 다양한 결과를 도출해냈으며, 그 차이는 각 의견의 내용에서 확연히 드러납니다. 하나의 풀 리퀘스트로 여러 유용한 결과를 얻었습니다. 이러한 결과 중 일부는 마이크로소프트에서 공개한 문서를 기반으로 하지만, 일부는 리포지토리에 있는 팀 자체 체크리스트를 통해 도출되었고, 또 다른 일부는 Copilot에 내장된 분석 기능을 통해 얻어졌습니다. GitHub Copilot 코드 리뷰는 사용자의 표준, 도구 및 실제 컨텍스트가 존재하는 시스템을 활용할 수 있습니다. 플랫폼 팀이 이러한 요소들을 한 번만 연결하면 모든 PR에 해당 컨텍스트가 자동으로 반영되기 때문입니다. 문서 링크는 설명란에 있습니다.
