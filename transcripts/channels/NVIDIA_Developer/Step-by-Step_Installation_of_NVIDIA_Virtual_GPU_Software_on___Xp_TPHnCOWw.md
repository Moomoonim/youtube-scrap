## 스크립트

Proxmox 18 버전에 NVIDIA VGPU를 설치하는 방법에 대한 비디오에 오신 것을 환영합니다. 저희는 KVM 배포판인 Proxmox를 지원합니다. Proxmox와 NVIDIA 지원 모두에 대한 라이선스가 필요하지만, 라이선스가 있는 경우 NVIDIA에 문의하여 지원을 받을 수 있습니다. 이 경우에는 플랫폼 공급업체인 Proxmox에 먼저 문의하는 것을 권장합니다. 먼저 GPU 가상화에 익숙하지 않은 분들을 위해 VGPU의 전체 아키텍처 와 구성 요소를 살펴보겠습니다. 이 그림 하단에서 서버 하드웨어와 물리적 GPU를 볼 수 있습니다. 그 위에는 하이퍼바이저인 Proxmox가 있습니다. GPU 관리자 소프트웨어는 이 하이퍼바이저 위에 설치되며, 이를 통해 GPU를 여러 GPU 프로필로 분할할 수 있습니다. 가상 머신은 NVIDIA 게스트 드라이버가 설치된 상태에서 실행되며, 사용자 애플리케이션이 실행됩니다. 이 비디오에서는 하이퍼바이저, GPU 관리자 드라이버 및 가상 머신용 NVIDIA 게스트 드라이버 설치에 중점을 두고 설명합니다. Windows 및 Linux 설치의 세 번째 단계는 라이선스 서비스를 설치하고 VM 드라이버가 해당 서비스와 통신하도록 구성하는 것입니다. 무료 클라우드 기반 라이선스 서비스(CLS) 또는 온프레미스 위임 라이선스 서비스( DLS)를 사용할 수 있습니다. 라이선스 서버 설치에 대한 별도의 비디오가 있으므로 화면 상단에 링크를 제공했습니다. 한 가지 유의할 점은 이 비디오를 녹화할 당시에는 Proxmox를 온 프레미스 DLS 설치 플랫폼으로 지원하지 않았다는 것입니다. 향후 이 비디오를 시청할 경우(예: 올해 말 또는 2026년) DLS 관련 문서가 변경될 수 있으므로 다시 확인해 보시는 것을 강력히 권장합니다. 또 한 가지 알아두셔야 할 점은 이미 DLS 서비스를 사용하고 있는 경우 VGPU 18 자체에서 최소 DLS 버전 3.4가 설치되어 있어야 한다는 것입니다. 반면 CLS를 사용하는 경우에는 이미 최신 버전입니다. 이제 포털에서 어떤 내용이 있는지 간단히 살펴보겠습니다. 포털에 로그인하면 라이선스가 부여된 서버의 VGPU 사용 권한에 액세스할 수 있을 뿐만 아니라 소프트웨어도 다운로드할 수 있습니다. 가상 GPU를 설치해야 하는데, 여기 긴 목록이 보이시죠? 이 목록을 좀 더 간략하게 필터링해야 합니다. 예를 들어 DLS( 라이선스 서비스)를 설치하려면 DLS를 검색하면 필요한 DLS 버전인 3.4.1이 표시됩니다. 하지만 앞서 말씀드렸듯이 Proxmox에서는 아직 3.4.1 버전을 지원하지 않습니다. 이 경우에는 VGPU 18을 설치할 것이므로 'GP vgpu 18'을 입력하면 필요한 소프트웨어가 표시됩니다. 이제 Linux KVM 배포판을 선택하고 다운로드 버튼을 누릅니다. Proxmox에 필요한 버전을 다운로드하면 DLS 3.4 버전이 필요하다는 경고 메시지가 표시됩니다. 이 경고는 모든 VGPU에 공통적으로 적용됩니다. 18개의 배포가 진행 중이며, 이제 소프트웨어를 다운로드하겠습니다. 다운로드가 완료되면 파일을 살펴보고 내용을 확인해 보겠습니다. 보시다시피 파일이 다운로드되었습니다. 압축 파일을 열어보면 호스트 드라이버가 있습니다. 이 호스트 드라이버를 Proxmox 호스트에 설치할 것입니다. 게스트 드라이버 폴더를 보면 Linux 게스트 드라이버와 Windows 게스트 드라이버 소프트웨어가 있습니다. 한 가지 주의할 점은 NVIDIA 웹사이트( nvidia.com)에서 드라이버를 다운로드했다면, 해당 드라이버는 가상 GPU와 호환되지 않습니다. NVIDIA 포털에서 다운로드한 드라이버를 사용해야 합니다. 또한, 녹화 시점을 기준으로 Proxmox는 독립형 가상 GPU 제품을 지원하는 플랫폼입니다. 따라서 그래픽 작업 부하에는 주로 Virtual Workstation, Virtual PC 또는 Virtual Apps 라이선스를 사용해야 합니다. Proxmox는 독립형 가상 GPU 제품을 지원하지 않습니다. 이번 초기 릴리스에서는 NVIDIA AI Enterprise 제품이 포함되어 있지만, 나중에 이 비디오를 시청하실 경우 Proxmox 및 NVIDIA AI Enterprise 관련 문서를 확인해 보시기 바랍니다. 이제 서버로 이동하여 몇 가지 점검을 해보겠습니다. 먼저 BIOS 설정을 확인해 보겠습니다. 여기에서 Intel 가상화 기술이 활성화되어 있는지 확인합니다. 보시다시피 활성화되어 있습니다. 서버 제조업체에 따라 설정이 다를 수 있지만, 이 경우 Northbridge 아래에 있는 I/O 구성에서 Intel VTD라는 항목이 있습니다. Intel VTD는 활성화해야 합니다. AMD에서는 IMMU라고도 합니다. 또한, PCIe 설정으로 돌아가서 4GB 이상 디코딩이 활성화되어 있어야 합니다. 그리고 AMPE 세대 이상의 GPU를 사용하는 경우 SROV 지원( AED)도 활성화해야 합니다. 자, 서버에서 이러한 설정을 완료했으면 서버를 부팅하고 VGPU 드라이버를 설치하면 됩니다. 자, 이제 VGPU를 설치하기 전에 필요한 준비 작업을 해 보겠습니다. 하이퍼바이저를 부팅했으니, 여기에서 저장소(repositories)를 보면 현재 어떤 저장소에서 데이터를 가져오는지 확인할 수 있습니다. 보시다시피 현재 구독이 없습니다. Proxmox와 NVIDIA의 지원을 받으려면 구독이 필요합니다. 여기에는 ' 구독 없음(no subscription)'이라는 저장소가 있는데, 이를 통해 PO(구매 주문)를 사용하여 가상 GPU를 실행할 수 있습니다. 이 경우 작동은 되지만, 당연히 어떠한 지원도 받을 수 없습니다. 저는 이 시스템에 대한 구독 키가 있으므로, Proxmox 콘솔 하단에 구독 키를 추가하겠습니다. 추가 후 시스템에 구독 키가 등록되는 데 시간이 조금 걸리므로 업데이트를 실행하기 전에 몇 분 정도 기다려 주십시오. 등록이 완료되면 저장소가 준비된 것을 확인할 수 있습니다. 이제 다음 작업을 진행할 수 있습니다. 업데이트 탭을 클릭하고 VGPU를 설치하기 전에 필요한 모든 업데이트를 받으세요. 여기에서 새로 고침을 누르면 모든 저장소가 새로 고쳐집니다. 완료되면 업그레이드 버튼을 누르면 서버가 VGPU 설치에 적합한 상태로 업데이트됩니다. Proxmox에서 가상 GPU에 필요한 모든 필수 조건을 설정하는 데 도움이 되는 스크립트를 제공합니다. 이 스크립트는 Proxmox 8.3.4 이상 버전에 포함되어 있으며, Proxmox 웹사이트의 가상 GPU 관련 문서를 참조하여 다운로드할 수도 있습니다. 하지만 지원되는 버전의 Proxmox( 8.3.4 이상)를 사용하고 있다면 기본적으로 설치되어 있을 것입니다. 스크립트 실행이 완료되면 서버를 재부팅하고 다음 단계로 넘어갑니다. 재부팅 후 GPU 관리자 소프트웨어가 제대로 설치되었는지 다시 한번 확인합니다. 먼저 다음 단계를 진행해야 합니다. 먼저 해당 파일을 실행 가능하게 만들어 GPU 관리자를 설치할 수 있도록 해야 합니다. 이제 남은 작업은 해당 명령어를 실행하는 것뿐입니다. 그러면 GPU 관리자가 설치될 것입니다. 설치 과정에서 몇 가지 메시지가 나타날 수 있습니다. 예를 들어 DKMS 관련 메시지가 있다면 " 예"를 선택하여 설치 및 등록을 진행하세요. 설치 과정은 다소 빠르게 진행되지만 일반적으로 5분 정도 소요됩니다. 설치가 완료되면 " 설치가 완료되었습니다"라는 메시지가 표시됩니다. 이제 가상 GPU와 일반 GPU가 시스템에서 인식되었는지 확인하기 위해 서버를 재부팅하겠습니다. 다음 명령어를 실행하여 시스템에서 SROV를 활성화하고 재부팅 후에도 해당 설정을 유지하도록 하겠습니다. 재부팅 후에도 설정이 유지되는지 확인하기 위해 재부팅을 진행하겠습니다. 이제 서버가 재부팅되었으므로 lspci 명령어를 사용하여 SROV 가상 GPU가 인식되었는지 확인해 보겠습니다. 두 개의 GPU가 있으므로 총 64개의 가상 함수가 있어야 합니다. 이제 표준 명령어인 `Nvidia SMI`를 입력합니다. 보시다시피 두 개의 L4 GPU가 VGPU에 완전히 등록되어 정상적으로 작동하고 있습니다. 이제 Nvidia SMI 명령어를 좀 더 고급스럽게 사용할 수 있습니다. 예를 들어, 저는 GPU ID에서 `-I`를 빼고 ` -Q`를 사용했습니다. 이렇게 하면 GPU에 대한 자세한 정보를 얻을 수 있습니다. 보시다시피 GPU의 지원 기능, 작동 방식, 설정 등 다양한 정보가 표시됩니다. 이제 가상 GPU Prof 파일을 VMS에 할당하기 전에 Proxmox 콘솔의 데이터 센터 노드로 이동하여 리소스 매핑에서 모든 리소스(가상 함수)를 매핑해야 합니다. 미디어드 디바이스에서 사용하려면 이름을 지정해야 하는데, 저는 `l40 proxmox1`로 지정하겠습니다. 제 서버 이름인 ' 중재 장치'를 사용하면 GPU가 아닌 모든 장치가 필터링됩니다. 보시다시피 여기에 모든 가상 기능이 표시됩니다. 원하는 기능을 선택할 수 있지만, 일반적으로 가상 GPU에 대해 모든 기능을 선택하는 것이 좋습니다. 그러면 두 개의 GPU 모두 가상 GPU로 사용할 수 있게 됩니다. 완료되면 '생성'을 클릭합니다. 이제 가상 머신에 VGPU 프로필을 할당할 수 있는 단계에 이르렀습니다. 여기서는 가상 머신에 운영 체제가 이미 설치되고 패치되었다고 가정합니다. 다른 하이퍼바이저에서 익숙했던 것보다 몇 가지 단계가 더 있을 수 있으므로, 특히 Dis Network 및 메모리 벌루닝에 필요한 Vero 드라이버와 관련된 내용은 Proxmox 설명서를 참조하는 것이 좋습니다. Grid D를 검색하고 다음으로 검색하면 Grid D의 마지막 항목이 "라이선스 획득 성공"으로 표시됩니다. 이 경우 CLS 라이선스를 사용하고 있으므로 CLS 게이트웨이의 호스트 이름이 제공됩니다. 오류나 문제가 발생하여 라이선스가 제대로 인식되지 않는 경우 Vlog 또는 Cylog 파일을 확인해 보시면 됩니다. 이제 정상적으로 작동하므로 필요한 나머지 스택을 설치할 수 있습니다. 예를 들어 Docker, CUDA 툴킷, 또는 Linux 운영 체제 내의 다른 애플리케이션들을 설치하면 됩니다. 게스트 드라이버가 실행되고 라이선스도 올바르게 부여되었으므로 이제 VGPU 시스템이 정상적으로 작동합니다. 이 비디오가 도움이 되었기를 바라며, 여러분의 프로젝트에 행운을 빕니다.
