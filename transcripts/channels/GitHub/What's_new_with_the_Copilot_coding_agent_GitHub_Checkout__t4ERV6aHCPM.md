GitHub Copilot 코딩 에이전트의 새로운 기능을 보여주시길 기대하고 있습니다. 네, 코파일럿 코딩 에이전트가 무엇 인지에 대한 맥락을 먼저 설명하는 것이 좋을 것 같습니다. 그러니까, 코딩 작업을 수행할 수 있는 자율적인 개발자 에이전트인데, 여러분이 사용해봤을 다른 도구들과의 가장 큰 차이점은 클라우드에서 백그라운드로 실행된다는 점입니다. 그러니까, 작업을 맡기면 프로그램이 변경 사항을 적용하고, 작업 결과를 검증한 다음, 풀 리퀘스트를 생성하고, 검토를 위해 당신을 태그하는 방식입니다. 그리고 그 모든 것에는 컴퓨터가 필요하지 않아요. 그러니 당신은 노트북을 닫고 점심을 먹으러 가거나 커피를 타러 갈 수 있고, 부조종사는 백그라운드에서 작업을 계속할 수 있습니다. 지난주에 제가 특히 기대하고 있는 '에이전트 패널'이라는 것을 출시했습니다. 이것은 GitHub의 모든 화면에서 사용할 수 있는 새로운 오버레이로, Copilot에 새 작업을 쉽게 보내고 Copilot이 이미 수행하고 있는 작업의 진행 상황을 쉽게 추적할 수 있습니다 . 버튼을 눌러 이 패널을 열었습니다 . 자동으로 제가 현재 보고 있는 저장소를 선택합니다. 그런 다음 Copilot이 수행하길 원하는 작업을 설명하면 됩니다. 그러니까 예를 들어 " Node.js를 최신 버전으로 업그레이드하세요"라고 말한 다음 " 작업 시작"을 누르면 C-pilot이 해당 작업을 감지하고 백그라운드에서 PR 작업을 시작한 다음 완료되면 알림을 보내줍니다 . 그리고 최근에 추가한 정말 좋은 기능 중 하나는 그렇게 할 때 분기를 선택할 수 있다는 것입니다. 이 새로운 패널을 통해 부조종사의 작업을 훨씬 쉽게 추적하고 , 백그라운드에서 부조종사에게 새로운 작업을 훨씬 쉽게 전달할 수 있으며, 모든 것에 이슈 기능을 사용하지 않더라도 이슈 기능을 쉽게 시작할 수 있는 출발점을 제공합니다. 잠깐, 그럼 모바일 앱에서도 코딩 담당자에게 문제를 할당할 수 있는 건가요 ? 좋아요 . 네, 모바일 에서 부조종사에게 문제를 할당할 수 있는 기능이 있습니다 . 현재로서는 문제를 건너뛰고 바로 코파일럿이 특정 작업을 수행하도록 하는 작업 환경과 같은 기능은 제공하지 않습니다. 하지만 그건 저희가 해결하려고 노력 중인 문제입니다. 이러한 상담원 경험을 GitHub 모바일에도 더 많이 도입하게 되어 매우 기쁩니다. 최근에 출시한 또 다른 기능 중 제가 정말 기대하고 있는 것은 Copilot에 자체 웹 브라우저를 제공한 것입니다. 덕분에 웹 애플리케이션에서 훨씬 더 효율적으로 작동할 수 있게 되었습니다. 따라서 웹사이트나 웹 앱이 있다면 Copilot을 사용하여 해당 웹사이트나 앱의 작동 방식을 테스트하고 작동 원리를 이해하는 데 도움을 받을 수 있습니다 . 이건 제가 한 달 전쯤 Copilot에게 요청해서 생성한 PR인데, 웹사이트에 국제화 지원을 추가해달라고 했거든요. 그런데 스크롤을 내려보니 Copilot이 코드를 작성해줬을 뿐만 아니라 , 변경 사항 스크린샷까지 공유해줬네요 . 세부 사항을 살펴보거나 코드를 직접 확인하거나 브랜치를 체크아웃할 필요 없이, 작업 결과를 빠르게 검증할 수 있습니다. 이거 진짜 멋지네요. 사실 MCP로 구동됩니다. 저희는 Copilot 코딩 에이전트가 기본적으로 사용 가능하도록 설정된 MCP 서버를 여러 개 보유하고 있는데, 그중 하나가 Playright MCP 서버입니다. 이 서버를 통해 에이전트는 웹 브라우저를 사용할 수 있으며, 로컬 서버에서 실행 중인 웹사이트를 포함한 여러 웹사이트를 탐색하고 스크린샷을 찍어 저와 공유할 수 있습니다. 아마 로컬 환경에서 확인해보고 싶 거나, 미리 보기 환경에 배포해볼 수도 있겠지만, 풀 리퀘스트에서 즉각적인 피드백을 받는 건 정말 유용하고 모든 개발자가 그렇게 했으면 좋겠어요 . 그리고 저희는 이 제품을 개발하면서 바로 그 점을 염두에 두고 있습니다. 아시다시피, 모든 동료, 모든 협력자들이 해주길 바라는 일은 무엇이며, 부조종사가 그런 일들을 하도록 어떻게 도울 수 있을까요? 마치 LLM(법학 석사)처럼 들릴 수도 있겠지만, 이건 정말 획기적인 변화입니다. 이전에는 개선을 하려면 수동으로 작업을 진행해야 했거든요. 이 앱이 어떤 기술로 만들어졌는지는 모르겠지만, 말 그대로 서버를 로컬에서 실행하고, 추가된 요소들을 직접 조사하고 검사해야 했습니다 . 하지만 이제 Playright NCP 와 GitHub Copilot 코딩 에이전트 덕분에 그런 걱정을 할 필요가 없습니다. 네, 상당히 큰 PR이네요. 사실 이 작업을 하는 데 약 50분 정도 걸렸습니다 . 그건 꽤 큰 작업이지만, 결과물은 탄탄한 코드이고, 제 코딩 기준을 충족하고 , 테스트를 통과하는 등 모든 면에서 만족스럽습니다 . 우리는 이 에이전트가 항상 테스트를 실행하고, 린트를 실행하고, 빌드 프로세스를 실행하여 실제로 테스트를 통과하고 검토 및 승인을 받을 수 있는 코드를 생성하도록 해야 합니다. GitHub Copilot에 대해 활성화된 다른 MCP 서버는 무엇입니까? 네, 현재 저희는 기본적으로 활성화되어 있는 MCP 서버 두 대를 운영하고 있습니다 . 그래서 웹 브라우징이나 스크린샷 찍기 같은 용도로 Playright가 있고, GitHub MCP 서버도 기본적으로 설치되어 있습니다 . 그리고 그건 정말 유용한데, 왜냐하면 담당자가 저장소의 다른 문제들도 살펴볼 수 있다는 뜻이기 때문입니다. 이전 풀 리퀘스트를 참고하여 작업에 대한 영감을 얻을 수도 있습니다. 물론, 사용자 지정 MCP 서버를 추가할 수도 있습니다 . 그래서 우리는 사람들이 Notion MCP 서버를 사용하여 메모나 범위 설정 문서 등을 읽어들이는 것을 보았습니다. 그리고 접속할 수 있는 훌륭한 MCP 서버가 정말 많이 있으니, 이는 정말 좋은 점입니다. GitHub 엔지니어들이 Copilot Coding Agent를 가장 많이 사용하는 이유는 바로 기술 부채 문제 해결입니다. 대부분의 팀은 프로젝트도 많고 해야 할 일도 많아서 항상 따라잡기 힘들어하죠. 그렇기 때문에 리팩토링이나 테스트 커버리지 개선, 종속성 업그레이드와 같은 작업이 백로그의 맨 아래로 밀려나 거나 아예 수행할 수 없는 경우가 종종 발생합니다. 알고 보니 부조종사는 이런 종류의 업무를 정말 잘 해내는 경우가 많은데, 왜냐하면 이런 업무들은 엄청난 지능이나 심오한 사고를 요구하지 않기 때문입니다 . 코드 스타일을 개선하기 위한 작은 리팩토링을 하거나, 이미 출시되어 더 이상 필요하지 않은 기능 플래그를 제거하는 것 등이 있습니다. 그런 종류의 기능들이 Copilot 코딩 에이전트에서 정말 큰 성공을 거두고 있습니다. 많은 개발자들이 이것을 새로운 기능을 시작하는 방법으로 활용하고 있습니다 . 그러니 C조종사에게 모든 일을 맡길 필요는 없습니다 . 완벽할 필요는 없지만, 시작점을 마련해 주고 나머지는 당신이 마무리할 수 있도록 도와줄 수 있을 겁니다. 그러니 당연히 처음부터 완벽하게 작동하고 모든 작업을 알아서 해준다면 정말 좋겠죠. 정말 대단하네요. 그게 이상적이네요. 하지만 설령 모든 걸 다 해결해주지 못하더라도 , 처음 70~ 80% 정도는 해결해 줄 수 있고, 그 후에 나머지를 마무리해서 결국에는 학점을 받을 수 있다는 점에서 여전히 매우 유용할 수 있습니다. 코파일럿 코딩 에이전트에 작업을 할당하는 사람들이 부담해야 하는 비용에 대해 간략하게 설명해 주시겠습니까 ? 이제 Copilot 코딩 에이전트는 PR 생성 또는 PR 변경 요청을 할 때마다 프리미엄 요청 비용이 한 번만 발생합니다. 프리미엄 요청을 300개 받으면, 해당 프리미엄 요청을 모두 코딩 에이전트에 사용했을 경우 최대 300개의 풀 리퀘스트를 생성할 수 있다는 의미입니다. 사용량이 상당히 많네요. 그래서 그것은 매우 큰 효과를 가져올 수 있습니다. 또한 중요한 점은 이 기능이 내부적으로 GitHub Actions를 사용한다는 것입니다 . 그래서 GitHub Actions 시간도 사용될 예정입니다. 하지만 오픈 소스 저장소에 참여하고 있거나 조직에서 이미 GitHub Actions 사용 시간을 할당받은 경우처럼 무료로 사용 가능한 GitHub Actions 시간이 있다면, 해당 시간을 Copilot 코딩 에이전트에 사용할 수 있습니다. 그러니 꼭 비용이 드는 것은 아닙니다. 이 기능을 처음 출시했을 때는 최고급 플랜인 프로 플러스와 엔터프라이즈 플랜에서만 제공했지만, 이제 모든 유료 플랜에서 사용할 수 있게 되었습니다. 현재 어떤 계획이 있나요? 공유해 주실 수 있는 게 있으신가요? GitHub 내부는 물론 전 세계의 많은 개발자들이 " 왜 내 PR에서 Co-Pilot을 언급해서 테스트를 수정하거나 빌드를 통과시키거나 특정 변경 사항을 추가하도록 요청할 수 없나요?"라고 묻는 것을 듣고 있습니다. 그건 저희가 지금 열심히 작업 중인 부분이고, 곧 공개될 예정이라 정말 기대 하고 있습니다. 또 하나 정말 기대되는 점은 API 접근성이 향상된다는 것입니다. 그래서 저희는 곧 공개 API를 출시하여 여러분이 C-pilot에 작업을 쉽게 보낼 수 있도록 할 예정입니다. 그래서 지금은 불가능한 새로운 종류의 자동화가 가능해질 수 있습니다. 자동화를 통해 코드가 작성되는 것은 매우 흥미롭고 사람들에게 유용할 것이라고 생각합니다. 그리고 세 번째로, 제가 생각하기에 큰 변화를 가져올 것 같은 것은 Copilot이 GitHub Actions 빌드가 실패했을 때 더 쉽게 문제를 해결할 수 있도록 하는 것입니다 . 저희는 여러분이 업무를 효율적으로 처리하고, 통합하고, 다음 단계로 나아가면서 생산성을 높이고 더 즐겁게 일할 수 있기를 바랍니다 . 바라건대, 제가 이 영상을 보면서 ' 코딩 에이전트가 나를 위해 해줄 수 있는 정말 멋진 일은 무엇일까?'라고 생각하게 되기를 바랍니다. 사람들이 어떻게 이 피드백을 당신에게 전달할 수 있을까요? 네, 그렇게 하는 가장 좋은 방법은 깃허브 커뮤니티를 활용하는 것입니다. 저희는 그곳에서 활발하게 활동하고 있습니다. 저희는 사람들이 피드백을 공유할 수 있는 다양한 토론 게시판을 운영하고 있습니다 . 저희는 X, 레딧, 링크드인 등에서도 활발하게 활동하고 있습니다 . 저도 다른 분들의 의견을 꼭 들어보고 싶어요 . 제 이메일 주소는 GitHub 프로필에 있습니다. 그러니 언제든지 의견이나 질문이 있으시면 편하게 연락 주세요. 저는 항상 여러분의 의견을 듣고 싶습니다. 왜냐하면 궁극적으로 저희의 목표는 이 제품을 여러분에게 최대한 유용하게 만드는 것이기 때문입니다. 우리는 진정한 의미의 동료 프로그래머 시대에 살고 있습니다.
